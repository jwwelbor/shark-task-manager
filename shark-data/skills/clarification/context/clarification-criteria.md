# Clarification Criteria

A requirement is clarified when:

1. The actor is known.
2. The trigger or condition is known.
3. The expected outcome is observable.
4. Scope boundaries are explicit.
5. Key terms are defined or linked to a glossary.
6. Constraints are stated or explicitly marked out of scope.
7. Remaining assumptions are written down with confidence and blast radius.

## Severity Rubric

- **High:** Different interpretations produce different user-visible behavior, data behavior, security posture, or acceptance criteria.
- **Medium:** Different interpretations change implementation details or effort but not the main outcome.
- **Low:** Different interpretations affect wording, naming, or minor presentation only.
