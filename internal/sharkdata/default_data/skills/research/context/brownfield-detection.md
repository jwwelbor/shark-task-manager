# Brownfield Detection Rules

**Purpose**: Determine whether a project is brownfield (existing codebase) or greenfield (new/empty) to route `/shark-rider project bootstrap` to the correct estate.

## Detection Algorithm

Apply checks in priority order. First definitive hit wins.

### Priority 1: Build Manifests (Strongest Signal)

Glob for build manifests at depth ≤2:

```
package.json, package-lock.json, yarn.lock, pnpm-lock.yaml
go.mod, go.sum
pyproject.toml, setup.py, setup.cfg, Pipfile, requirements.txt
Cargo.toml, Cargo.lock
pom.xml, build.gradle, build.gradle.kts
Gemfile, Gemfile.lock
composer.json
mix.exs
pubspec.yaml
```

**Evaluation**:
- Manifest found AND contains actual dependencies (not just a name/version) → **brownfield** (confidence: HIGH)
- Manifest found but empty/no deps → continue to Priority 2

### Priority 2: Source File Count

Glob for source files excluding standard vendor directories:

```
Exclude: node_modules/, vendor/, .venv/, venv/, __pycache__/,
         dist/, build/, target/, .next/, .nuxt/, .output/,
         coverage/, .git/
```

Count files matching: `**/*.{ts,tsx,js,jsx,py,go,rs,java,rb,php,cs,swift,kt,ex,exs,dart}`

**Evaluation**:
- \>5 source files → **brownfield** (confidence: HIGH)
- 1–5 source files → **ambiguous** — ask user: "Found N source files. Is this an existing project you want analyzed, or a fresh start from a template?"
- 0 source files → continue to Priority 3

### Priority 3: Git History Depth

```bash
git rev-list --count HEAD 2>/dev/null
```

**Evaluation**:
- \>3 commits → **brownfield** (confidence: MEDIUM)
- 1–3 commits → check commit age (see Edge Cases: Cloned Template)
- 0 commits or not a git repo → **greenfield** (confidence: HIGH)

### Priority 4: Default

No signals detected → **greenfield** (confidence: HIGH)

## Confidence Scoring

| Signal | Confidence | Weight |
|--------|-----------|--------|
| Manifest with real deps | HIGH | Definitive |
| >5 source files | HIGH | Definitive |
| 1-5 source files | LOW | Ask user |
| >3 git commits | MEDIUM | Definitive |
| 1-3 git commits, old | MEDIUM | Likely brownfield |
| 1-3 git commits, <2 days | LOW | Likely template clone |
| No signals | HIGH | Greenfield |

## Edge Cases

### Monorepo

If multiple manifests found at depth 2 (e.g., `packages/*/package.json`), this is brownfield. Note monorepo structure for downstream analysis — brownfield-analysis should scan each workspace.

### Cloned Template

A single commit with message matching common template patterns (`initial commit`, `Initialize project`, `Create from template`, `Generated by`) AND commit date < 2 days ago → treat as **greenfield** with scaffolding.

Detection:
```bash
git log --oneline --format="%s" -1
git log --format="%ai" -1
```

If the commit message suggests a template AND is recent, ask user: "This looks like a freshly generated template. Treat as greenfield (recommended) or analyze as brownfield?"

### Already-Initialized Project

If `docs/architecture/bootstrap.md` marker file exists → bootstrap was already run. Defer to re-run policy (fill gaps, regenerate all, or cancel).

### Scaffolding Exception

A single entry point file (e.g., lone `main.py`, `index.ts`, `main.go`) with no other source files is ambiguous. Could be:
- Someone just started coding (greenfield with a file)
- A minimal project (brownfield)

Default to **greenfield** but mention: "Found a single source file. Treating as greenfield — if this is an existing project, re-run with `/shark-rider project bootstrap --force-brownfield`."

## Output

The detection step produces:

```yaml
estate: brownfield | greenfield
confidence: HIGH | MEDIUM | LOW
signals:
  - type: manifest | source_files | git_history | default
    detail: "package.json with 12 dependencies"
    confidence: HIGH
monorepo: true | false
template_clone: true | false
```

This output is consumed by the bootstrap orchestrator to route to the correct estate workflow.
