# Demo Script Scenario Template

Use one copy of this template for each demonstrable scenario. Keep unknown or
uncaptured information explicit; do not fill a field with assumed tooling,
access, URLs, credentials, deployments, or proof.

## Scenario: <short, observable outcome>

- **Stakeholder value:** <why this outcome matters>
- **Source requirement or acceptance criterion:** <committed source and locator>
- **Prerequisites and demo data:** <documented setup, state, and data; or gap>
- **Presenter actions:** <documented actions to take>
- **Expected observable result:** <what an observer can verify>
- **Evidence type and path:** <one permitted surface and committed artifact path>
- **Evidence environment and date:** <where and when the evidence was captured>
- **Acceptance/readiness classification:** <one of the three classifications>
- **Reset or recovery instructions:** <documented reset/recovery; or N/A with reason>
- **Known limitations:** <limits, gaps, pending integration, or accepted risk>

### Permitted evidence surfaces

Choose the documented surface that makes the expected result observable:

- UI capture or recording
- CLI transcript
- API request/response plus resulting state
- SDK runnable example
- Pipeline artifact or data
- Infrastructure health or metric evidence
- Background trigger/log/result evidence

### Classification notes

- **Demonstrated now:** source and existing observable evidence, including
  environment and date, are present.
- **Not demonstrated / pending integration:** a contract-only handoff, open
  activation, unavailable documented setup, or uncaptured evidence remains
  visible; draft mode labels the precise gap.
- **Accepted risks and overrides:** retain the independent assessor verdict,
  separate owner decision, open conditions, and risk without calling the claim
  demonstrated.
