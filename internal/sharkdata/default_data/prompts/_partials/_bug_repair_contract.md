{{define "_bug_repair_contract"}}Reference existing decisions; escalate conflicting authority to its owner. Keep all findings and route to the earliest invalidated stage. Diagnosis changes invalidate the plan and downstream evidence; material plan changes invalidate approval; candidate changes invalidate review and QA. Reuse unchanged valid evidence. Unavailable external evidence is blocked, not acceptance. For a structured success outcome, include exactly one outer `evidence` entry with `kind: bug_repair_plan`, `pointer` set to the project-relative plan file, and `summary` set to `sha256:<hex digest>` of the plan revision. During repair planning and plan review use the committed project document; downstream use the approved snapshot and its original path and digest supplied by the parent. A proposed material change requires a new plan revision and independent review. Also include exactly one `bug_review_baseline` evidence entry whose `pointer` is the full commit hash of the review baseline declared in that plan. Independently confirm the baseline at plan review and carry the same value through development, review and QA; do not infer or substitute a later baseline. The parent validates these identities; it does not establish evidence quality by itself.{{end}}
