## Codex Red-Team Verification (Step 5.7)

Codex verdict: **CONCERNS** (not FAIL)

Codex independently verified all 7 task acceptance criteria and confirmed them satisfied. Codex raised the following concerns:

1. **TC-018 timing** — Ready channel closes after DB init, integrity check, wiring, and listener setup, with no enforced timeout. Risk of exceeding 500ms in slow environments.
   - **QA Assessment:** Non-blocking. Test confirmed actual elapsed time is well under 10ms when a pre-bound DB is passed (as both the test and the `shark web` command do). For the `cmd/server` binary path (no pre-bound DB), dbinit is fast on a warm system. TC-018 verifies this at test time.

2. **REQ-NF-003 early server exit** — If `srv.Serve` returns an error before `ctx.Done()` fires, the code returns the error directly without calling `srv.Shutdown`. Codex flags this as contradicting the shutdown requirement.
   - **QA Assessment:** Non-blocking. If `srv.Serve` returns early, the server has already stopped accepting connections — there is nothing to shut down. The spec's 30-second shutdown timeout applies to graceful shutdown on context cancellation (the normal stop path), not to error paths where the server itself has already exited. The TechLead code review confirmed this select+channel pattern as correct.

3. **Spec deviations re: static asset routes and `statusCalc`** — Codex noted `RegisterStaticRoutes` is not called and `statusCalc` is `nil` in `WireServices`.
   - **QA Assessment:** Out of scope for this task. This task (T-E27-F05-004) is specifically scoped to the `StartServer` entry point and `WireServices` composition. Static asset serving via a single embedded `viewer.html` is intentional per F03 design. `statusCalc` is documented as optional in `NewViewerService` and reserved for future use.

None of the Codex concerns are blocking for the acceptance criteria of this task.
