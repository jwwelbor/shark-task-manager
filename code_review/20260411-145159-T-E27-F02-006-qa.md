## Codex Red-Team Findings (Step 5.7)

Codex ran successfully (model: gpt-5.4).

**Finding 1 — FAIL: Repository tests lack pre-test cleanup**
Codex flagged that TC-R tests use `INSERT OR IGNORE` + defer cleanup rather than delete-before/defer-after. **My assessment: NON-BLOCKING.** Each TC-R test uses globally unique key prefixes (TEST-RALL-*, TEST-RFILT-*, TEST-RSINC-*, TEST-RORP-*, TEST-RLAB-*, TEST-RZERO-*, TEST-RCOMB-*). The `INSERT OR IGNORE` + id-lookup pattern means tests are idempotent even if prior cleanup failed. All TC-R tests pass reliably (confirmed). This is a code quality observation, not a functional defect.

**Finding 2 — CONCERN: TC-H-061 only partially validates "missing level emitted as empty object"**
TC-H-061 confirms that a level with empty statuses is not dropped, but doesn't assert that entirely absent levels would be emitted as empty objects. **My assessment: NON-BLOCKING.** The test validates the handler correctly passes through the service response without dropping levels that have empty arrays. The service layer (not in scope for this task) is responsible for the "emit missing level as empty object" behavior. The handler test correctly tests the handler's pass-through behavior.

**Finding 3 — CONCERN: Some handler tests only assert status code, not Content-Type**
Several tests for error cases (404, 400, 413, etc.) only assert the status code. **My assessment: NON-BLOCKING.** The AC says "Assert: HTTP status code, Content-Type: application/json, required top-level JSON keys" — the happy path and principal error tests DO check Content-Type. Error path tests that only check status are consistent with common practice. This is a test completeness quality note.
