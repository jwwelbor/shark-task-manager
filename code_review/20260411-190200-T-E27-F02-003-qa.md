## Codex Red-Team Findings (Step 5.7)

Codex returned **CONCERNS** — all 8 specific checks PASS, with 2 non-blocking observations:

**Finding 1: DTO placement in service.go (non-blocking)**
The task spec described `FeatureTaskOptions` and `RecentActivityOptions` as being declared in `internal/api/viewer/service.go`. The implementation uses them from the `services` package directly. The code review explicitly assessed this as a reasonable architectural decision (single source of truth, no duplication). This was already reviewed and accepted. Not a blocker.

**Finding 2: Logging missing "entity" key on aggregate endpoints (non-blocking)**
`Summary`, `Hierarchy`, `RecentActivity`, `WorkflowMeta` log `"endpoint"` and `"error"` but not `"entity"`. The entity-specific endpoints (History, File, FeatureTasks) correctly log `"entity": key`. For aggregate endpoints with no entity key param, omitting `"entity"` is semantically correct behavior. The spec phrase "internal errors logged via slog.Error with entity, endpoint, error keys" is reasonably interpreted as "where an entity key is available." This does not affect functionality or security. Not a blocker.
