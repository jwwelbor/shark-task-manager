The implemented tests (`TestViewerService_Hierarchy_RelationshipsPopulated`, `TestViewerService_FeatureTasks_RelationshipsPopulated`) use task→task relationships only, not task→bug or task→feature. ## Red-Team Findings

### Finding 1: Cross-entity test coverage gap (non-blocking)

**Observation:** Test-plan §3.4 called for `TestViewerService_Hierarchy_TaskBugLinkVisible` and `TestViewerService_Hierarchy_IncludesCrossEntityRelationships` to cover TC-5.1 (task→bug) and TC-5.2 (task→feature). Neither test was written. The two tests that were written (`TestViewerService_Hierarchy_RelationshipsPopulated` and `TestViewerService_FeatureTasks_RelationshipsPopulated`) exercise task→task relationships only.

**Impact assessment:** The production code path for cross-entity resolution is verified correct by inspection (`entityRegistry` registers all five entity types in `wire.go`, `resolveTaskRelationships` uses the same branch for all `otherType` values). The missing tests would have provided explicit regression protection for the task→bug case, which was the original bug this feature was designed to fix.

**Classification:** Non-blocking. The mechanism works. The gap represents an incomplete test plan execution, not a functional failure.

**Recommendation:** Add `TestViewerService_Hierarchy_TaskBugLinkVisible` in a follow-up to close TC-5.1.

---

### Finding 2: Empty `entity_key` on orphaned relationship (edge case, non-blocking)

**Observation:** If `entityRegistry.GetRepository(otherType)` fails or `GetByID` returns an error (e.g., the related entity has been deleted), `resolveTaskRelationships` sets `EntityKey = ""` and still appends the entry to the result slice (viewer_service.go:720-733). The viewer will receive a `ViewerRelatedEntity` with an empty key.

**Impact assessment:** This is a data quality edge case, not a security or crash issue. The spec does not explicitly require filtering such entries. The behaviour is consistent with the graceful degradation pattern established for the entire `resolveTaskRelationships` function.

**Classification:** Non-blocking observation. A future iteration may choose to filter entries where `EntityKey == ""`.

---

### Finding 3: Minor panic message duplication (cosmetic, pre-existing)

**Observation:** Line 433 reads `"ViewerService requires a non-nil WorkflowService must not be nil"` — contains redundant phrasing ("requires a non-nil" and "must not be nil"). This was noted in both code reviews.

**Classification:** Non-blocking cosmetic. Pre-existing and known.
