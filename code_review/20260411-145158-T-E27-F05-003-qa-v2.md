## Bug Fix Verification

### BUG-001: Access-Control-Allow-Methods and Access-Control-Allow-Headers on non-OPTIONS local origin

**Fixed:** Yes.

`cors.go` lines 54-57 now set `Access-Control-Allow-Methods: GET, OPTIONS` and `Access-Control-Allow-Headers: Content-Type` for ALL local-origin requests (not just OPTIONS). Previously these were only set inside the `if r.Method == http.MethodOptions` block.

`cors_test.go` TC-006 (lines 38-43) and TC-007 (lines 67-72) now assert these headers on GET responses. Both tests pass.

### BUG-002: OPTIONS short-circuits regardless of Origin

**Fixed:** Yes.

`cors.go` line 28 checks `r.Method == http.MethodOptions` BEFORE the `origin == ""` early-return at line 43. All OPTIONS requests — with or without Origin — reach `w.WriteHeader(http.StatusNoContent)` and return without calling `next`.

`cors_test.go` `TestWithLocalCORS_OptionsNoOrigin` (TC-010b) explicitly tests OPTIONS with no Origin header, asserting 204 and no ACAO header. This test passes.
