## Open blocker B077-R32-01 — A successful configuration read can contradict the exact pin or explicit effort

The delivered Rider procedure at `c8a36d58:skills/shark-rider/verbs/run.md`, lines 235–244, requires both exact and mapped Codex callers to check the effective configuration before claim. For an exact model pin it sends the pin to the configuration reader and compares the returned model with that pin. For an explicit effort it also compares the returned effort with the request. A conflicting read stops the assignment. Owner instruction 4008 preserves user pins. Architect correction 4011 changes how the mapped route obtains its model. Neither authorizes dropping the exact-pin or explicit-effort preflight check. The provider reference also classifies a conflicting local read as unverified. [Codex provider reference](../../../../skills/shark-attack/providers/codex.md)

The successor edit at `45fe0e58` replaced the two-route preflight paragraph with mapped discovery. C01 now checks the effort in launch argv and in the producing turn. C02 checks the explicit model in launch argv and tests a failed read and a successful read returning the wrong **provider**. C04 tests an absent or empty mapped model. C05 changes model or effort **after** launch and refers a known local conflict back to C04. None of those fixtures makes a successful read return the correct provider and a conflicting exact pin or explicit effort. A supported value such as `low` can pass the capability check while the effective configuration reports `xhigh`. [Coverage index](../../../plan/bugs/B077.repair-plan.md#coverage-index) · [Rider preflight and launch](../../../../skills/shark-rider/verbs/run.md) · [Existing recording test](../../../../tests/contracts/b077_codex_route_attestation_test.go)

The following controls isolate the missing assertion. Keep the executable, input bytes, authentication, provider and observation channel fixed. Have the receiving worker honor the intended argv in every case it is called. A later matching observation can then hide the skipped preflight comparison.

| Keyed request | Effective local read before claim | Required behavior |
|---|---|---|
| Exact fixture pin P, effort `low`, profile default D distinct from P | The reader receives the P and `low` overrides and returns `openai/P/low` | One claim and one submission with the exact pin and effort |
| Same exact request and reader arguments | Change only the returned model to D | Bounded preflight rejection before any claim or submission |
| Same exact request and reader arguments | Change only the returned effort to `xhigh` | Same preflight rejection |
| Eligible mapped tuple requesting `low` | The selected CLI returns a concrete discovered model and the correct provider, but reports `xhigh` | Same preflight rejection. The matching-effort control launches with the discovered model |

**Required plan change.** Add the independent readback comparisons to the existing C01/C02/C04 index and identify the pre-claim caller. At the recording CLI inspect the effective read inputs and returned fields. At the parent count claims, submissions, inference, admissions and advances. Require zero on each conflicting read even when a hypothetical launch would yield a matching receipt. Keep omitted effort unforced. For an exact pin, a different profile default is legitimate before applying the pin. For a mapped request, the current read supplies the model. These are fixtures and require no provider spend.
