## Open blocker B077-R49-01 — the companion can replace the reason for fallback

The Runner 3 contract requires the successful review to retain why fallback occurred. The producer combines its capability decision, the failed attempt's reason and the eventual selection into `fallback_reason`. The companion takes an independent `--fallback-reason`, checks that it contains meaningful text, and puts it into the Markdown header and returned JSON. Its attempt sidecar can therefore contradict the explanation shown to the reader. [Runner 3 contract](../../../../skills/shark-rider/skills/deep-review/SKILL.md#runner-3-alternatecomparable-model-cli) · [Producer](../../../../skills/shark-rider/skills/deep-review/scripts/adaptive_review.py#L855) · [Companion metadata](../../../../skills/shark-rider/skills/deep-review/scripts/adaptive_review.py#L938) · [Companion validation](../../../../skills/shark-rider/skills/deep-review/scripts/adaptive_review.py#L971)

I ran the real producer and companion as separate processes with the repository's frozen-scope fixture. Two recording executables occupied the reviewer CLI slots. The preferred Codex executable exited 7. The Claude executable supplied a valid native-format recording. The producer returned PASS after the second attempt. I republished that same job to two fresh output paths with the same body, decisions, attempts bytes, original model request, scope and CLI. Only the fallback argument differed. Revision 36's packet comparison, original attempts checksum and original-request comparison receive identical inputs in both publications. Every new publication comparison can pass. The producer retry tests can also pass because the producer records the right reason. Testing the first failed attempt's sidecar alone misses the contradiction in the published header. A reason can also describe the initial runner choice when there was no failed attempt. The authoritative full string already exists in the successful producer result.

**Required revision.** Extend C12's existing producer-to-publication handoff to preserve the selected run's fallback explanation. Use it for the published field or reject a conflicting companion assertion. In C11/C12, hold every verified input fixed and vary only the companion reason. Read the saved header and returned JSON. A matched immediate or resumed publication must report the producer's reason, including the prior failure on retry. A conflicting argument must never produce a successful report carrying the replacement text. Exercise first-attempt success as well as success after retry. The producer and its receipts are sufficient for a recording-only check. This finding concerns an existing report field and requires no new routing or spend decision.
