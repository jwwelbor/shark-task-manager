## Open blocker B077-R47-01 — a valid producer result can lose the exact body required on resume

C12 hashes the full accepted report string before formatting and requires the caller to resume a matched publication from retained producer evidence. The parser returns that string intact. The persistence function writes a generated header followed by `body.rstrip() + "\n"`. The success JSON returns the report path and metadata. Neither it nor a listed sidecar supplies the original body. The planned execution reference preserves the attempt digest, which cannot reconstruct the text. [Packet parser](../../../../skills/shark-rider/skills/deep-review/scripts/adaptive_review.py#L695) · [Report persistence](../../../../skills/shark-rider/skills/deep-review/scripts/adaptive_review.py#L633) · [Producer return](../../../../skills/shark-rider/skills/deep-review/scripts/adaptive_review.py#L891)

I ran two additional valid producer packets. One report ended in a space, tab and two newlines. The other ended in one newline. Both producers exited 0. After removing the generated headers their saved bodies were byte-identical, while the required canonical packet digests differed. A caller that recovers the displayed text from the report can satisfy every crossed-receipt test and still reject a legitimate matched publication. Supplying the original fixture body to the companion masks this loss at the process boundary.

**Required change.** Specify how Runner 3 returns or retains the exact validated packet or body for later publication. Drive the resumed companion from the producer's durable outputs and saved job reference, discarding the fixture's input and in-memory packet before resuming. Each matched whitespace case must publish its own worker, usage and charge with exit 0. Switching only the two valid bodies must fail the packet check. Keep the intentionally formatted human-readable report.

## Open blocker B077-R47-02 — both proposed checks admit a false requested model

The producer records its original `--requested-model`. The companion independently takes that same option and copies it into the persisted header and stdout. The proposed packet digest covers the report and decisions. The attempt digest covers the retained receipts. In the fourth replay above, both digest inputs, the worker, verified effective route, charge and candidate stayed fixed. Only the companion's request argument changed from `opus` to `haiku`. The saved report and JSON both claimed `haiku`. This violates B077's original-request requirement at the publication caller. A matched-input assertion for the original request and the companion's effective-pair check can both pass on the ordinary fixture.
