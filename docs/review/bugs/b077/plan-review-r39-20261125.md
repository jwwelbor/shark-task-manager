The user-directed Architect consultation 5119 names descriptions and supported efforts as separate inputs. The plan requires the reader to reject conflicting rows for one selector. It checks descriptions across duplicate selectors, then keeps the first row’s efforts and default. [Selection rule and C01–C05/C11](../../../plan/bugs/B077.repair-plan.md#decision-and-repair) · [Reader called before acquisition](../../../../skills/shark-rider/verbs/run.md) · [Reader implementation boundary](../../../../skills/shark-rider/scripts/read-codex-route.py)

I compared those two rules with a small local decision table. All cases use two successfully returned pages for the same visible model B. Claude is unavailable. Both rows have the same qualifying coding description except in the description control. These are counterexamples to the assertion design. They do not claim a candidate execution.

| Case | Required keyed preflight | Reader comparing only duplicate descriptions |
|---|---|---|
| Identical B rows, explicit high supported | Select B once | Selects B once |
| Different capability descriptions, matching efforts | Unverified in either order | Unverified in either order |
| Both defaults low. One row supports low and high, the other only low. Request high. | Unverified in either order | Selects B with the high-capable page first. Reports unsupported in reverse order. |
| Both support low and high. One defaults to low, the other high. Request and profile omit effort. | Unverified in either order | Selects B using whichever default came first. |

In the third case a receiving process can honor the explicit high override and report B/high on its own producing turn. Claim, identity, receipt and charge can then all agree despite the unjustified submission. In the fourth case launch omits the override, so a producing turn matching the first default can also conceal the defect. Review 704’s first-row and last-row mutations ignore conflicting descriptions. Revision 39 catches those mutations. The surviving reader checks the descriptions correctly and loses only the independent effort evidence.

**Required revision.** Extend C04/C11’s existing keyed fixture with the two effort-only contradictions above. Reset the counters and run both page orders. Require the bounded unverified receipt to identify the two conflicting effort facts for B, retain only the established provider and show zero claim attempts, submissions and inference. Keep a matching readback and worker available. Include consistent controls for explicit high and for the omitted-effort row default, each permitting one verified dispatch. A comparison that ignores just supported efforts or just defaults must fail its own case. This implements the rule already proposed under 5038/5119 and requires no new owner policy.
