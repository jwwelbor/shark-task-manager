## Findings

### High: completed dispatches accept an unobserved claim session

`bench/runs/i07-schema.yaml:210-216` changes `claim.session_id` and the worker
identity fields to `nullable_string` for every dispatch. The conditional strict
check in `bench/scripts/verify-lifecycle-run.sh:269-272` restores non-null,
non-whitespace requirements for completed worker fields only; it never checks
`dispatch.claim.session_id`.

As a result, a publication-eligible completed record can erase or replace its
parent-owned claim session with whitespace and still pass I-07 validation. This
violates the intended contract that nullable observations are allowed only for
stop outcomes and weakens the session-authority evidence for completed runs.

The focused Go counterfactual at
`tests/contracts/e40_i07_lifecycle_run_contract_test.go:110-113` rejects a null
completed worker identity, but there is no equivalent completed-claim null or
whitespace case. The stop fixture at lines 120-133 therefore does not protect
the missing strictness.

Counterfactual evidence, using the committed valid completed fixture:

```text
jq -c '(.dispatches[0].claim.session_id)=null' \
  tests/contracts/testdata/e40_i07/valid/complete.jsonl > /tmp/null-claim.jsonl
bench/scripts/verify-lifecycle-run.sh /tmp/null-claim.jsonl \
  --schema bench/runs/i07-schema.yaml
# exit 0: {"dispatch_count":1,"publication_eligible":true,"result":"accepted",...}

jq -c '(.dispatches[0].claim.session_id)="   "' \
  tests/contracts/testdata/e40_i07/valid/complete.jsonl > /tmp/space-claim.jsonl
bench/scripts/verify-lifecycle-run.sh /tmp/space-claim.jsonl \
  --schema bench/runs/i07-schema.yaml
# exit 0: {"dispatch_count":1,"publication_eligible":true,"result":"accepted",...}
```

The verifier should require a non-whitespace `claim.session_id` whenever the
dispatch outcome is not in `stop_outcome`, alongside the worker checks. Direct
null and whitespace counterfactuals should cover this behavior.
