## 4. Codex Assessment (ChatGPT gpt-5.2-codex via Codex — Sole Assessor)

### Verdict: **REJECT** — blockers found.

### Blocking Issues

**BLOCKER 1: History recording not wired for tasks/bugs/change-cards.**
`shark status history` reads `entity_history` for all types (`status_group.go:552`), but task transitions write only to `task_history` via `TaskService.TransitionStatus` → `StatusUpdateRaw` and never to `entity_history` (`task_service.go:565`). Bug and change-card transitions never write history (`bug_service.go:317`, `change_card_service.go:309`). Result: new task/bug/change transitions won't appear in `shark status history`. This violates Story 2 and REQ-F-005.

**BLOCKER 2: Dead/unwired new APIs (no non-test call sites).**
- `EntityHistoryService.GetRecentHistory` — no call sites outside tests
- `EntityHistoryRepository.ListRecent` and `ListWithFilters` — no call sites outside tests
- `EntityHistoryFilters` — unused outside tests
- `models.EntityDocumentLink` — unused outside tests

### Non-Blocking Issues

- `--limit` truncation keeps the **oldest** N entries instead of the most recent (history ordered DESC, sliced from end at `status_group.go:582`).
- `changed_by` stores NULL for manual changes instead of `"user"` per spec (Story 4 AC).
- Not-found error path doesn't trigger friendly message.

## 5. Risks and Issues

### Blocking
- **History gap for tasks/bugs/change-cards** — TaskService, BugService, ChangeCardService bypass EntityService.TransitionStatus and write directly to their own tables/methods. entity_history records are never created for these entity types. This means `shark status history <task-key>` returns empty for new transitions.
- **Dead code** — Several newly introduced APIs have no runtime callers outside tests.

### Non-blocking
- `--limit` bug: returns oldest instead of most recent entries
- `changed_by` spec deviation: NULL instead of "user" for manual changes
- No CLI E2E tests for bug/change-card document linking (flags exist but untested end-to-end)

### Missing Evidence
- No pre/post migration output diff for backward compatibility verification
- No E2E test showing feature status transition → entity_history row → CLI output

---

## 6. UAT Decision

- **Verdict:** REJECT
- **Confidence:** High
- **Rationale:** The core promise of this feature — status change history for ALL entity types — is only partially delivered. Epic and feature history works, but task, bug, and change-card transitions do not write to `entity_history`, making `shark status history` incomplete for the most frequently used entity type (tasks). This is a wiring gap, not a design flaw — the infrastructure is correct but not connected to 3 of 5 entity types.

## 7. Required Follow-ups

1. **Wire task transitions to entity_history** — Add history recording call in `TaskService.TransitionStatus` after successful status update (recommended: call `historyRepo.Create()` directly, matching EntityService pattern)
