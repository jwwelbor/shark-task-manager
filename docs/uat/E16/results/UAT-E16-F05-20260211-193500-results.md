## Clarifications Discussed

**Q: How is backward movement determined?**
A: Via `getPhaseOrder()` in `config/workflow_schema.go`. Each status has a `phase` in its metadata. Phases map to numeric order. If target phase order < current phase order, it's backward.

**Q: Do same-phase transitions trigger backward detection?**
A: No. Same-phase transitions (e.g., `ready_for_refinement_tech` -> `in_refinement_ba`, both "refinement") are NOT backward. Only cross-phase transitions (e.g., development -> planning) trigger the guard. This matches spec REQ-F-003: "if target is earlier."
