### Cross-Cutting Findings

- **`shark next` contract is structurally present, but semantics are wrong.** `NextResponse` has the right shape (`next.go:114`), but `provider` is passed through unconditionally from workflow YAML (`next.go:451`), and **no shipped workflow YAML sets `provider:`**. The field is always empty.
- **`shark create task` is template-free** (`task.go:309` — calls `TaskService.CreateTask` directly). So the fresh-init template break is specific to epic and feature creation, not task.
- **Canonical workflow set is incomplete.** No `tech-debt.yaml` in `shark-data/workflow/` despite F04 scope.
- **F01's `_partials_inventory.md` is orphaned** from its intended `_extracted/` sidecars (which don't exist).
- **15 prompt files use path refs instead of inlining**: `epic/{ready_for_decomposition,ready_for_research,ready_for_refinement,ready_for_design}.md`, `bug/ready_for_development.md`, `task/ready_for_development.md`, `feature/{ready_for_specification,ready_for_assessment,ready_for_research,ready_for_task_generation,ready_for_test_planning,ready_for_qa,in_qa,ready_for_code_review,in_code_review}.md`.
- **Legacy `shark-templates/` references remain inside `shark-data/`'s own docs**: `specification-writing/README.md`, `quality/README.md`, `research/README.md`, `research/SKILL.md`, `research/workflows/consult-related-work.md`, `research/workflows/project-init.md`, `implementation/context/testing-requirements.md`, `implementation/workflows/implement-tests.md`.
- **`shark validate` on a fresh init is not clean** — uat SKILL.md YAML frontmatter warning.
- **F05 shipped the deletion half but not the deprecation half.** `/run` is functional as a redirect but lacks the required deprecation header; sibling slash commands are gone rather than deprecated for one release.

## 5. Risks and Issues

### Blocking (CRITICAL)

1. **Bootstrap broken on fresh project** — `shark create epic` / `shark create feature` fail in a freshly-init'd project (read from `shark-templates/entity/epic.md` rather than `shark-data/`). Epic's flagship "fresh project runs from `shark-data/` alone" promise broken. *(epic_helpers.go:712, feature_helpers.go:994)*
2. **Prompts not self-contained** — 15 shipped prompts use `Load skill: shark-data/skills/...` path refs; engine renderer does not inline. Epic's "cross-harness portable" promise broken.
3. **`tech-debt.yaml` missing** from `shark-data/workflow/` — bug/change-card flows can advance but tech-debt cannot via the new path.
4. **Pre/post prompt equivalence never proven** — no baseline captured, no golden-output diff suite exists.

### Blocking (HIGH)

5. **F01 `_extracted/` sidecars don't exist** anywhere under `shark-data/skills/`.

8. **F05 deprecation half missing** — `/run` has no deprecation header; sibling slash commands removed rather than deprecated.

## 6. UAT Decision

- **Verdict:** **REJECT**
- **Confidence:** High
- **Rationale:** Three flagship epic promises are broken (self-contained prompts, fresh-init bootstrap, complete canonical content). F05's deprecation contract was never shipped. F01's extraction artifacts (`_extracted/` sidecars) don't exist. The work is substantial — engine plumbing, embedded FS, content migration — but the integration between layers leaves the user with a project that can't actually be bootstrapped from `shark-data/` alone, which was the entire point.
