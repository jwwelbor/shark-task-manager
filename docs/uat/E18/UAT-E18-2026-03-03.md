## Feature Overview

Epic E18 introduces **bugs** and **change-cards** as first-class entity types in Shark Task Manager. Previously, bugs and small improvements had no dedicated home in Shark, forcing teams to either shoehorn them into the existing task system or track them in external tools.

### What Was Built

| Feature | Description | Tasks |
|---------|-------------|-------|
| **E18-F01** | Database schema and workflow engine extension — new `bugs` and `change_cards` tables, dedicated workflows (`bug_workflow`, `change_card_workflow`), `check_or_resume` orchestrator action type | 5 tasks |
| **E18-F02** | Bug entity core — `Bug` model, `BugRepository`, `BugService` with full CRUD and lifecycle operations | 10 tasks |
| **E18-F03** | Change-card entity core — `ChangeCard` model, `ChangeCardRepository`, `ChangeCardService` with full CRUD and lifecycle operations | 7 tasks |
| **E18-F04** | Bug CLI commands — `shark bug create/get/list/update/delete/triage/fix/verify/close` | 5 tasks |
| **E18-F05** | Change-card CLI commands — `shark change create/get/list/update/delete/implement/review/close` | 5 tasks |
| **E18-F06** | Unified CLI integration — key auto-detection for `B-###` and `CC-###` keys in `shark get`, `shark status`, `shark search` | 6 tasks |
| **E18-F07** | Dashboard and analytics integration — bug/change-card counts in `shark status`, type-based filtering, resolution metrics | 7 tasks |

### Scenario 3: Bug Workflow Lifecycle

**Tasks covered**: E18-F02-005 through E18-F02-008
**Objective**: Verify the bug workflow (open → triaged → in_progress → fixed → verified → closed) functions correctly.

**Steps**:

1. Start with bug `B-001` in `open` status. Triage it:
   ```bash
   ./bin/shark bug triage B-001 --assignee="dev-agent" --notes="Confirmed reproducible on v2.3.1"
   ```
   **Expected**: Bug moves to `triaged` status.

2. Begin the fix:
   ```bash
   ./bin/shark bug fix B-001
   ```
   **Expected**: Bug moves to `in_progress` status.

3. Mark as fixed:
   ```bash
   ./bin/shark status advance B-001
   ```
   **Expected**: Bug moves to `fixed` status.

4. Verify the fix:
   ```bash
   ./bin/shark bug verify B-001 --notes="Tested on Firefox 124 — no longer crashes"
   ```
   **Expected**: Bug moves to `verified` status.

5. Close the bug:
   ```bash
   ./bin/shark bug close B-001
   ```
   **Expected**: Bug moves to `closed` status.

6. Verify workflow completion:
   ```bash
   ./bin/shark bug get B-001 --field status
   ./bin/shark status history B-001
   ```
   **Expected**: Status is `closed`. History shows all 5 transitions.

**Success Criteria**:
- [ ] Bug workflow progresses through all states: `open → triaged → in_progress → fixed → verified → closed`
- [ ] `shark status advance` works on bug entities
- [ ] Status history correctly logs all transitions
- [ ] Invalid transitions are rejected (e.g., cannot go from `open` to `verified`)

### Scenario 9: Edge Cases and Error Handling

**Objective**: Verify graceful error handling for invalid inputs and edge cases.

**Steps**:

1. Get a non-existent bug:
   ```bash
   ./bin/shark bug get B-9999
   ```
   **Expected**: Error message "bug not found: B-9999", exit code 1.

2. Get a non-existent change-card:
   ```bash
   ./bin/shark change get CC-9999
   ```
   **Expected**: Error message "change-card not found: CC-9999", exit code 1.

3. Invalid status transition:
   ```bash
   ./bin/shark bug create "Test invalid transition" --severity=low
   ./bin/shark status set B-001 verified  # Cannot skip from open to verified
   ```
   **Expected**: Error about invalid status transition, exit code 3.

4. Create bug with invalid severity:
   ```bash
   ./bin/shark bug create "Bad severity" --severity=extreme
   ```
   **Expected**: Validation error about invalid severity value.

5. Case-insensitive key lookup:
   ```bash
   ./bin/shark get b-001   # lowercase
   ./bin/shark get B-001   # uppercase
   ```
   **Expected**: Both return the same bug.

**Success Criteria**:
- [ ] Not-found errors return exit code 1 with informative message
- [ ] Invalid transitions return exit code 3
- [ ] Input validation errors return clear error messages
- [ ] Keys are case-insensitive

All tasks should be returned to development for defect fixes before re-UAT.
