## Codex Findings

### HIGH — AC-03 / REQ-NF-012: missing mutation-route regression test
`RegisterRoutes` only mounts `GET /api/v1/viewer/tags` at `internal/api/viewer/handler.go:69`, so REQ-F-013 is implemented. But REQ-NF-012 explicitly requires an automated test asserting that POST/PUT/PATCH/DELETE produce 404 or 405. Grep over handler tests found only mock scaffolding (`TagsFunc`) at `internal/api/viewer/handler_test.go:27-40` and `:120-125`; no actual `/api/v1/viewer/tags` test cases and no non-GET coverage. This is a regression tripwire that does not exist.

### HIGH — AC-12 / REQ-F-017: UI filter does not apply to feature-task list
The active filter chips refetch hierarchy via `applyTagFilter()` calling `apiGetHierarchy()` (viewer.html:2044-2055; chip click at :4842-4855), but the feature-task fetch helper does NOT accept tags and always calls `/features/{key}/tasks` without query params (viewer.html:1928-1933). Spec REQ-F-017 mandates: "User-selected chips are appended to subsequent list fetches as `?tag=<name>` repeated params" on "every list view (hierarchy sidebar and any list-like surface that reads from `GET /api/v1/viewer/hierarchy` or `GET /api/v1/viewer/features/{key}/tasks`)."

### MEDIUM — Handler-layer tag/error-path tests are materially missing
Handlers implement tag parsing and unregistered-tag 400 handling at handler.go:94-107, :183-253, and :488-520. Handler tests at handler_test.go:251-352 and :668-819 contain no `?tag=` parsing assertions, no `unregistered_tags` assertions, and no 400-vs-404 ordering tests. Coverage gap; not a proven runtime bug.

### MEDIUM — REQ-F-015 / REQ-NF-011 debug-log invariant not implemented
Service degrades gracefully when `tagSvc == nil` (viewer_service.go:553-556, :1827-1844), but no one-time debug log at construction and no debug log when tag filters are ignored. The spec explicitly says "logged at debug" (REQ-F-015) and "A debug-level log is emitted once at ViewerService construction time noting that the tag decoration is disabled" (REQ-NF-011).

### Verified positives (cross-checks)
- Compile-time interface assertion present: `internal/api/viewer/service.go:31-32`
- AC-15 verified: NewViewerService has no MaintainerGate parameter; wire.go does not pass one

- AC-17 verified independently by Claude: `make fmt && make lint && make test` all pass cleanly
