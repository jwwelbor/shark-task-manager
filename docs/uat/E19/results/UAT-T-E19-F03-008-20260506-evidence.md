## Acceptance Criteria Evidence Map

### AC-12: Default carryover mode read from .sharkconfig.json

**Spec text (§1.2 REQ-F-006):** "Default carryover behavior is read from `.sharkconfig.json` key `sprint_defaults.carryover` (defaults to `"next"` if absent)."

**Evidence from code review:** Code review PASS — notes GetCarryoverBehavior() is nil-safe and returns "" when unconfigured.

**Evidence from QA:** QA PASS — four GetCarryoverBehavior decision-table rows pass using real Config struct.

**CRITICAL EVIDENCE FROM RED-TEAM CODE INSPECTION:**

The production config load path is:
```
CLI GetSprintService() -> GetConfig() -> config.NewManager(configPath).Load()
```

`Manager.Load()` in `internal/config/manager.go` manually parses JSON fields from rawData one by one. There is NO parsing block for `sprint_defaults`. It parses: observability, maintainer, tag_required_for, size_required_for, recent, color_enabled, json_output, workflow_config, console_width — but NOT sprint_defaults.

Therefore `Config.SprintDefaults` is ALWAYS nil when the config is loaded via `Manager.Load()` (the production path), even when `.sharkconfig.json` contains `sprint_defaults.carryover_behavior`.

**Config tests DO NOT test the production path.** The tests `TestSprintDefaultsConfig_CarryoverBehaviorRoundTrip` and `TestSprintDefaultsConfig_AbsentCarryoverDefaultsToEmpty` use `json.Unmarshal` directly on the `Config` struct — bypassing `Manager.Load()` entirely.

**AC-12 status: NOT MET — BLOCKER**
