## Findings

### Minor observations (non-blocking)

1. **`status_shared.go:45` uses `result.EntityKey` instead of `transResult.EntityKey`.**
   Both status_group.go and next_status_generic.go use the same pattern, but
   the variable is different. Here `result` is the `*EntityNextStatusResult`
   passed in as a parameter, and its `EntityKey` field is populated earlier by
   `buildNextStatusResult(info)`. Verified to be the correct, populated value.
   No bug, just a readability nit — the sibling line 38 uses `transResult.FromStatus`
   so readers may expect `transResult.EntityKey` here for consistency.

2. **`workflow show-action` debug command does not set `is_resume`.**
   `internal/cli/commands/workflow_show_action.go:97` calls
   `lookupEntityPlaceholders` which returns raw placeholders without setting
   `is_resume`. As a result, the resume preamble is suppressed in show-action
   output even though show-action is a "display-time preview" analogous to
   `shark get`. This is a pre-existing inconsistency that CC-029 neither
   created nor fixed. Not in scope for this task.

3. **`change/in_verification.tmpl` references old verification phase.**
   Per commit c2cd109, verification was renamed to code_review/qa/approval for
   tasks, but change cards still use `in_verification`. Pre-existing, not in
   scope.
