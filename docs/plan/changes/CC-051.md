# Bug provenance fields: found_by and defect class

## Description

Add found_by (live|rehearsal|unit|review) and class (environment|contract|content) to bugs so the share of bugs found live can be reported as a harness-gap signal. Source: WWGM S010 retro 2026-11-27 (wwgm PR #195, docs/plan/sprints/S010-rehearsal-harness-plan.md). Ten live attempts on one task, each failing at the next defect, never surfaced as drift.

## Justification

Without provenance, a project can't see how many defects escape to the most expensive stage. WWGM's B161–B182 were all found by paid live runs; about a third were environment/admission defects a $0 rehearsal would have caught.

## Impact Analysis

Two optional bug fields, plus reporting. Existing bugs default to unset; no workflow change.

Cheaper alternative to evaluate first: bugs already accept registered `--tag`s. Registering `found-by-*` and `class-*` tags gives the same data with no schema change; only the reporting (share of bugs found live) would need code. No provenance tags are registered in shark-task-manager or WWGM today (checked 2026-11-27).

## Rollback Plan

Fields are optional; stop populating them and hide them from reports. Drop the columns in a follow-up migration if abandoned.
