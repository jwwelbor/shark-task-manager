# Eliminate transitioner adapter boilerplate in run.go

## Description

`internal/cli/commands/run.go` has 5 transitioner adapter structs (`taskTransitionerAdapter`, `featureTransitionerAdapter`, `epicTransitionerAdapter`, `bugTransitionerAdapter`, `changeCardTransitionerAdapter`) that implement the `runner.EntityTransitioner` interface. After the E21 unification, all 5 are now trivial one-liner delegations:

```go
func (a *bugTransitionerAdapter) TransitionStatus(ctx, key, targetStatus, opts) (*TransitionResult, error) {
    return a.svc.TransitionStatus(ctx, key, targetStatus, opts)
}
func (a *bugTransitionerAdapter) GetNextStatus(ctx, key) (*NextStatusInfo, error) {
    return a.svc.GetNextStatus(ctx, key)
}
```

This is ~150 lines of boilerplate across 5 nearly identical structs.

### Options

1. **Have services implement `runner.EntityTransitioner` directly** — the method signatures already match. The adapters become unnecessary.
2. **Create a single generic adapter** that wraps any service with `TransitionStatus`/`GetNextStatus` methods.
3. **Define a shared interface** in the services package that all 5 services satisfy, then use that as the adapter target.

Option 1 is cleanest if `runner.EntityTransitioner` can be defined in a package that services can import without circular deps.

Note: The placeholder adapters (`taskPlaceholderAdapter`, `bugPlaceholderAdapter`, etc.) are entity-specific and would remain — they generate different placeholder maps per entity type.

## Justification

150 lines of copy-paste adapter code with zero behavioral variation. Each new entity type would require another copy.

## Impact Analysis

- **Files**: `run.go`, potentially `runner/` package for interface location
- **Risk**: Low — pure refactor, adapters are pass-throughs
- **Circular dep risk**: Need to verify `runner` package can import service types or vice versa

## Rollback Plan

Revert the commit.
