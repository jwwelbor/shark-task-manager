# Wire Embedded Workflow YAMLs as Zero-Config Fallback

## Problem

`defaultWorkflowDataLoader` (`internal/config/aliases.go`) resolves workflows in three passes:

1. Per-entity YAML from `shark-data/workflow/` (disk)
2. Inline `*_workflow` blocks in `.sharkconfig.json`
3. Hardcoded Go defaults via `emptyMLW.GetWorkflowForLevel()`

Pass 3 is a separate, static Go definition that duplicates the canonical workflow
YAMLs already embedded in the binary at `internal/sharkdata/default_data/workflow/`.
This means zero-config mode (no `shark-data/` on disk, no config blocks) gets the
hardcoded Go defaults — not the richer route-based `steps:` / `outcomes:` YAMLs
that ship in the embedded bundle.

## Desired Resolution Order

1. **Disk YAML** — `shark-data/workflow/<entity>.yaml` and its overrides directory
   (`shark-data/overrides/workflow/<entity>.yaml`). Unchanged from current Pass 1.
2. **`.sharkconfig.json` inline blocks** — `*_workflow` fields and legacy
   `status_flow`. Unchanged from current Pass 2.
3. **Embedded canonical YAMLs** — `internal/sharkdata/default_data/workflow/<entity>.yaml`
   loaded via `sharkdata.ReadEmbedded(...)`. Replaces the current hardcoded Go
   defaults (Pass 3).

Pass 3 should read from the embedded FS (same source that `shark install-shark-data`
extracts to disk) rather than a separate Go struct. The hardcoded Go workflow
definitions can then be removed.

## Acceptance Criteria

- [ ] `defaultWorkflowDataLoader` Pass 3 reads entity workflow YAMLs from the
      embedded FS (`sharkdata.ReadEmbedded("workflow/<entity>.yaml")`) instead of
      calling `emptyMLW.GetWorkflowForLevel()`.
- [ ] A project with no `shark-data/` dir and no `.sharkconfig.json` workflow blocks
      gets the same statuses/transitions/agent routing as one that ran
      `shark install-shark-data` (verified by a new test).
- [ ] The hardcoded Go workflow defaults (wherever `GetWorkflowForLevel` falls back
      to `defaultForType`) are removed or reduced to a last-resort guard that only
      fires if the embedded read also fails.
- [ ] All existing workflow tests continue to pass (`make test`).
- [ ] `make lint` passes.

## Out of Scope

- Changing the Pass 1 or Pass 2 logic.
- Changing the `workflow_config` field resolution.
- Altering the `shark install-shark-data` extraction path.
