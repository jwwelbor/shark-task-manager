# Remove bespoke status methods from BugService and ChangeCardService

## Description

BugService and ChangeCardService have bespoke status methods (`SetBugStatus`, `SetChangeCardStatus`, `AdvanceBugStatus`, `AdvanceChangeCardStatus`) that pre-date the E21 entity polymorphism work. These methods:

1. Destructure `TransitionOptions` into individual params (`force`, `reason`) only to reconstruct the struct internally
2. Call `EntityService.TransitionStatus` (same as the unified `TransitionStatus` method), then discard the `*TransitionResult` and re-fetch the entity to return a typed model
3. Duplicate the advance pattern that the generic path (`GetNextStatus` + `TransitionStatus`) already provides

Epic, Feature, and Task services do NOT have equivalent bespoke methods — they only have the unified `TransitionStatus` and `GetNextStatus`. Bug and change-card should match.

### What to remove

- `SetBugStatus(ctx, key, status, force, reason)` → callers use `TransitionStatus(ctx, key, status, opts)`
- `SetChangeCardStatus(ctx, key, status, force, reason)` → callers use `TransitionStatus(ctx, key, status, opts)`
- `AdvanceBugStatus(ctx, key)` → callers use `GetNextStatus` + `TransitionStatus` (generic advance path)
- `AdvanceChangeCardStatus(ctx, key)` → same
- `ApproveChangeCard` → can call `TransitionStatus` directly with target status "approved"
- `GetValidTransitions` on both services → identical implementations that delegate to `workflow.Service.GetValidTransitions`, which is already public

### Callers to update

- `changeCardServicer` interface in `change.go` — remove bespoke methods
- `MockChangeCardService` in `change_test.go` — remove mock fields
- `bug.go` command handlers that call `SetBugStatus` / `AdvanceBugStatus`
- `change.go` command handlers that call `SetChangeCardStatus` / `AdvanceChangeCardStatus` / `ApproveChangeCard`
- Internal callers within the services themselves

## Justification

E21 established a unified entity polymorphism pattern. Bug and change-card services still carry pre-E21 bespoke methods that create interface duplication, parameter sprawl, and were the direct cause of B007 (reason silently dropped). Removing them makes bug/change-card first-class entities with the same service contract as epic/feature/task.

## Impact Analysis

- **Files**: `bug_service.go`, `change_card_service.go`, `bug.go`, `change.go`, `change_test.go`, mock files
- **Risk**: Low — all bespoke methods are thin wrappers around `EntityService.TransitionStatus` which is already tested
- **Behavioral change**: None — same underlying logic, just fewer indirection layers

## Rollback Plan

Revert the commit. The bespoke methods can be restored from git history.
