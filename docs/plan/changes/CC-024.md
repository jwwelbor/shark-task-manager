# Add goroutine safety for tracer swap in tracing tests

## Description

`internal/repository/tracing_test.go`'s `setupTracingTest` function mutates 5 package-level tracer variables without holding any lock:
- `repoTracer` (root package)
- Plus 4 sub-package tracers via `SetTracerForTesting` calls (epic, feature, task, note)

The existing `testMu` mutex in `tracing_test.go` partially protects test seeding but does **not** protect the tracer swap in `setupTracingTest`. If tracing tests ever run with `t.Parallel()`, the global provider swap and tracer swaps will race.

**Proposed change:** Wrap `setupTracingTest` and its cleanup closure in a mutex that prevents concurrent tracer replacement. Alternatively, restructure the tests to use `t.Cleanup` with a shared lock, or document that tracing tests must never use `t.Parallel()`.

## Justification

This is a latent issue — currently tests do not call `t.Parallel()`, so no race exists today. However, as the test suite grows and developers are tempted to parallelize tests for speed, this will produce flaky, hard-to-debug failures. Fixing it proactively is cheap; debugging a race condition in OTel tracer setup is not.

## Impact Analysis

- **Files modified:** `internal/repository/tracing_test.go` (1 file), potentially `epic/tracing_test_helper.go`, `feature/tracing_test_helper.go`, `task/tracing_test_helper.go`, `note/tracing_test_helper.go`
- **Risk:** Very low — test-only changes, no production code affected
- **Tests:** The fix itself makes tests safer; no behavior change

## Rollback Plan

Revert the test file changes. Since this is test-only infrastructure with no production impact, rollback is trivial.
