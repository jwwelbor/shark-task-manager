# Batch tag name resolution in TagService.AttachMany

## Description

services/tag_service.go AttachMany resolves N tag names via N sequential GetByName calls, then N Attach calls (2N queries for N tags). Surfaced during /simplify review of E28-F04. Fix: add GetByNames(ctx, []string) to repository/tag.TagRepositoryInterface with a single WHERE name IN (?,?,?), compute missing names in-memory, then Attach — reduces to 1 SELECT + N INSERT-OR-IGNORE. Touches the repo interface, concrete repo, and all service-test mocks that stub tag lookups.

## Justification

Low-priority perf/structural cleanup on the tag-attachment path. Impact grows with tag count per entity; currently users typically attach 1-3 tags, so not user-visible today. Worth doing before entity create paths attach larger tag sets (e.g., bulk import flows).
