# Consolidate duplicate RecordSpanError implementations

## Description

Two independent implementations of span-error recording exist:

- `internal/services/tracing.go` (line 12): `func recordSpanError(span trace.Span, err error) error` — returns the error for chaining
- `internal/repository/repoutil/tracing.go` (line 21): `func RecordSpanError(span trace.Span, err error)` — void return

Both are functionally identical (nil check, `RecordError`, `SetStatus(codes.Error, ...)`). The only difference is the return signature.

**Proposed change:** Have `internal/services/tracing.go` import and delegate to `repoutil.RecordSpanError`, adding a thin return-value wrapper. This eliminates the duplicated nil-check and OTel API call logic.

## Justification

The `repoutil` package was established in E07-F36 as the shared tracing utility location. The services package predates this and rolled its own copy. Now that a canonical location exists, the duplication should be consolidated to prevent drift (e.g., if error recording behavior is enhanced in one place but not the other).

## Impact Analysis

- **Files modified:** `internal/services/tracing.go` (1 file)
- **Risk:** Low — the wrapper would still return `error` for service-layer chaining; only the internal implementation changes
- **Direction:** `services` → `repository/repoutil` is a valid import direction (services already import repository)
- **Tests:** Existing service tracing tests continue to work unchanged

## Rollback Plan

Revert the single file change to `internal/services/tracing.go` to restore the inline implementation.
