# Task: Note write orchestration and relationship service façade

## Goal
Implement the viewer mutation façade for note create and relationship create/delete so the HTTP layer stays thin and the normalized relationship store remains canonical.

## Scope
- Files to modify: `internal/api/viewer/mutation_service.go`, `internal/api/viewer/mutation_service_test.go`
- Files to review/update if needed: `internal/services/note_service_test.go`, `internal/services/entity_relationship_service_test.go`

## Acceptance Criteria
- See `spec.md` REQ-F02-001, REQ-F02-003, REQ-F02-004, REQ-F02-005, REQ-F02-006
- Note writes resolve source keys and delegate to the existing note service
- Relationship writes resolve source and target keys, reject duplicates/self-links/cycles, and persist only through `entity_relationships`

## Test Cases
- See `test-plan.md` TC-F02-001, TC-F02-003, TC-F02-004, TC-F02-005b, TC-F02-006
- Service tests cover happy-path delegation, validation, and canonical-write behavior

- See `spec.md` Section 2.4 for service-layer ownership
- See `spec.md` Section 2.7 for validation and error mapping
