# Task: Viewer mutation handler and façade

## Goal
Create the viewer mutation API and service façade for epics, features, and tasks so the UI can update fields and trigger workflow transitions through the existing entity services without bypassing validation or history.

## Scope
- Files to create: `internal/api/viewer/mutation_handler.go`, `internal/api/viewer/mutation_service.go`
- Files to modify: `internal/api/viewer/mutation_handler_test.go`, `internal/api/viewer/mutation_service_test.go`

## Acceptance Criteria
- See `spec.md` REQ-F-001, REQ-F-002, REQ-F-003, REQ-F-005, REQ-F-006
- Mutations validate entity type, allowed fields, and transition permissions before write
- Successful writes route through the shared entity/workflow services and preserve history

## Test Cases
- See `test-plan.md` TC-F01-001, TC-F01-003, TC-F01-004, TC-F01-005
- Handler tests cover request parsing, error mapping, and allowed route behavior
- Service tests cover field update and transition orchestration against mocked services

## Design Reference
- See `spec.md` Section 2.2 for component changes
- See `spec.md` Section 2.3 for API and interface contracts
- See `spec.md` Section 2.4 for the thin-facade approach
- See `spec.md` Section 2.7 for validation and error handling

## Dependencies
None.

## Notes
Keep the surface explicit and narrow so the viewer remains read-only except for the named mutation endpoints.
