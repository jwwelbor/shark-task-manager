### BUG-F04-002-A: `--link` flag silently ignored in `runBugList`

**Severity:** Medium
**Priority:** Medium

**Description:** The `--link` flag is registered for `bugListCmd` (line 229) but is never read or forwarded to `BugFilters` inside `runBugList`. Users running `shark bug list --link=E07-F01` will receive all bugs, not just those linked to that entity.

**Steps to Reproduce:**
1. Create a bug linked to E07-F01: `shark bug create "Test bug" --link=E07-F01`
2. Run: `shark bug list --link=E07-F01`
3. Observe: All bugs are returned, not just the linked one

**Root Cause:** `runBugList` (lines 311-343) reads `--status` and `--severity` flags but has no code to read `--link`. Additionally, `services.BugFilters` has no `LinkedEntityKey` field to accept it, and `repository.BugListFilters` has no linked-entity filter either.

**Expected:** Filter to bugs where `linked_entity_key` matches.
**Actual:** Flag value is parsed into the `bugLink` package-level var (which is shared with `bugCreateCmd`!) but never consumed in `runBugList`.

**Additional note:** The `bugLink` package-level variable is shared between `bugCreateCmd` and `bugListCmd` flags (registered on both), which means flag value from one command bleeds into the other. This is a flag registration smell.

**Fix Required:** Developer must add `LinkedEntityKey *string` to `services.BugFilters`, propagate it through `repository.BugListFilters`, and read/forward the `--link` flag in `runBugList`.

### BUG-F04-003-A: `--assign` flag value is silently dropped; no field on `Bug` model to persist it

**Severity:** High
**Priority:** High

**Description:** The `--assign` flag is correctly parsed in `runBugTriage` and placed in `input.Assign`. The `TriageBugInput.Assign` field exists. However, inside `TriageBug()` (lines 272-301 of `bug_service.go`), the `input.Assign` field is never read or applied to the bug. The `Bug` model has no `AssignedTo` or `AgentType` field. Therefore, assignment via triage is completely non-functional: it is accepted by the CLI, silently ignored by the service, and never persisted.

**Steps to Reproduce:**
1. Run: `shark bug create "Test bug" --severity=medium`
2. Run: `shark bug triage B001 --severity=high --assign=developer`
3. Run: `shark bug get B001 --json`
4. Observe: No `assigned_to` or `agent_type` field appears; assignment is lost

**Root Cause (multi-layer):**
- `Bug` model (`internal/models/bug.go`) has no `AssignedTo` or `AgentType` field
- `TriageBug()` service method does not use `input.Assign`
- No DB column for assignment in the bugs table (per the model)
- CLI accepts `--assign` flag, creating false expectation of functionality

**Expected:** Assigning via `--assign=developer` persists to the bug record and is visible in `get`.
**Actual:** Flag is silently ignored; no error returned to user.

**Fix Required:** Either (a) add `AssignedTo *string` field to `Bug` model + DB schema + repository, and apply it in `TriageBug()`, or (b) remove `--assign` flag and `Assign` from `TriageBugInput` if assignment is not yet in scope. Either way the current behavior is misleading.
