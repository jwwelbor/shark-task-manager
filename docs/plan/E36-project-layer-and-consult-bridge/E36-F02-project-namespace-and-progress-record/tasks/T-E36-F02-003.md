# Task: Create file_templates/progress.md template and progress record update logic

## Goal

Create the `file_templates/progress.md` template and add the progress record update step to `verbs/project.md` so that each activity completion appends a decision-log entry and regenerates the derived checklist at `docs/product/progress.md`.

## Requirements

### Functional Requirements

- [ ] `file_templates/progress.md` template exists with two sections: **Derived Checklist** and **Decision Log**
- [ ] `docs/product/progress.md` is seeded from the template on first activity completion (if not already present)
- [ ] After each project activity, the Derived Checklist section is regenerated from disk: check for `docs/architecture/` directory, `docs/architecture/D01-vision-statement.md`, `docs/architecture/D04-feasibility-report.md`, and other key artifacts
- [ ] After each project activity, a timestamped entry is appended to the Decision Log section (append-only — do not overwrite prior entries)
- [ ] The checklist is advisory — rendered as `[x]`, `[ ]` markers with no programmatic effect
- [ ] Writing the file is a skill `Write` operation (not a shark mutation)

### Non-Functional Requirements

- [ ] If `docs/product/` does not exist, the skill creates it before writing
- [ ] Progress record update failure does not abort the activity — best-effort
- [ ] Decision log entries are timestamped (ISO format or human-readable date)

## Implementation Plan

### Steps

1. [ ] **Create `file_templates/` directory** at repo root (new directory)

2. [ ] **Create `file_templates/progress.md`** with this structure:
   ```markdown
   ---
   type: progress-record
   ---
   # Project Progress Record

   ## Setup Checklist

   <!-- DERIVED — regenerated after each project activity. Do not edit manually. -->

   - [ ] Architecture docs (`docs/architecture/`) — not present
   - [ ] Vision statement (D01) — not present
   - [ ] Feasibility report (D04) — not present

   ## Decision Log

   <!-- APPEND-ONLY — human-written entries, one per activity. Do not overwrite. -->
   ```

3. [ ] **Add progress-record update step to `skills/shark/verbs/project.md`** (in T-E36-F02-001):
   - After activity completes, check if `docs/product/progress.md` exists
   - If not: seed from `file_templates/progress.md` template content (inline or Read)
   - Regenerate the checklist section by checking artifact paths on disk
   - Append a timestamped decision-log entry (activity name, date, brief outcome)
   - Write the updated file

### Technical Approach

- The checklist regeneration is a skill `Read` + `Write` craft operation
- Artifact presence is checked by trying to `Read` each path; if it fails, the item is `[ ]`
- The decision log is append-only: read current content, append new entry, write back

## Acceptance Criteria

- [ ] `file_templates/progress.md` exists and has the correct structure (checklist + decision log sections)
- [ ] After `/shark project bootstrap`, `docs/product/progress.md` is created if absent
- [ ] Checklist reflects actual artifact presence (e.g., `[x] Architecture docs` if `docs/architecture/` exists)
- [ ] Decision log has a new timestamped entry after each activity
- [ ] Running two activities in sequence appends two log entries (not overwriting the first)

## Files Changed

- `file_templates/progress.md` (new)
- `skills/shark/verbs/project.md` (updated — progress record step integrated)
