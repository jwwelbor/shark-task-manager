# Task: Create verbs/project.md dispatcher and update SKILL.md

## Goal

Create `skills/shark/verbs/project.md` — a namespace dispatcher for the three pre-epic activities (`bootstrap`, `brownfield-analysis`, `product-design`) — and update `skills/shark/SKILL.md` to expose the `project` verb and add the ops-as-entities convention section.

## Requirements

### Functional Requirements

- [ ] `/shark project` with no activity argument prints a usage menu listing the three activities with one-line descriptions
- [ ] `/shark project bootstrap` invokes the architecture-doc generation activity (delegates to same bundle content as `project-init` currently uses: `shark skill get research workflows/project-init.md`)
- [ ] `/shark project brownfield-analysis` runs the deep codebase analysis (delegates to `Read verbs/brownfield-analysis.md and follow it`)
- [ ] `/shark project product-design` runs the D01–D14 arc (delegates to `Read verbs/product-design.md and follow it`)
- [ ] Any unrecognized sub-verb prints "Unknown activity: <x>. Available: bootstrap, brownfield-analysis, product-design" and stops
- [ ] Each activity passes remaining args through to the delegated verb unchanged
- [ ] After any activity completes, the verb appends a decision-log entry to `docs/product/progress.md` (creating the file from template if absent) and regenerates the checklist section
- [ ] `SKILL.md` allowlist table adds a `project` row in the Getting started group
- [ ] `SKILL.md` includes the ops-as-entities convention (either as a guidance section or reference to docs/guides/ops-as-entities.md)

### Non-Functional Requirements

- [ ] Activities are independent — no activity assumes another has run first
- [ ] The progress record write is best-effort (skill `Write`); failure is logged, not fatal

## Implementation Plan

### Steps

1. [ ] **Create `skills/shark/verbs/project.md`**:
   - Header: `# /shark project — Pre-epic setup namespace`
   - Dispatch algorithm: read first arg token; match against `bootstrap`, `brownfield-analysis`, `product-design`
   - For `bootstrap`: `shark skill get research workflows/project-init.md` and follow it (same as current `project-init.md`); pass remaining args
   - For `brownfield-analysis`: `Read skills/shark/verbs/brownfield-analysis.md and follow it`; pass remaining args
   - For `product-design`: `Read skills/shark/verbs/product-design.md and follow it`; pass remaining args
   - For empty args: print menu (activity name + one-line description for each)
   - For unknown: print error + valid list
   - After activity completion: update progress record (see T-E36-F02-003 for record details, but call the update step inline)

2. [ ] **Update `skills/shark/SKILL.md`**:
   - Add `project` row to verb allowlist in Getting started group (after `project-init` which becomes deprecated in T-E36-F02-002)
   - Add reference or section for ops-as-entities convention (coordinate with F03 task; cross-ref to `docs/guides/ops-as-entities.md`)

3. [ ] **Add ops-as-entities guidance section** within `project.md` or as a block comment explaining what belongs in the namespace vs. as shark entities

### Technical Approach

- `project.md` is a pure skill verb (markdown procedure the agent follows)
- Delegation pattern: read first sub-token, dispatch to delegated verb via `Read` or `shark skill get`
- No Go code changes in this task
