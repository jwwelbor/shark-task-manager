# Task: Create inline and delegated Shark Rider consultation verbs

## Goal

Create `skills/shark-rider/verbs/consult.md` and `skills/shark-rider/verbs/consult-agent.md`. The first implements `/shark-rider consult <agent> [referent]` as a persona-driven inline consultation. The second implements `/shark-rider consult-agent <agent> [referent]` as a separate one-shot request to a bounded read-only host subagent.

## Implementation Plan

Create the file `skills/shark-rider/verbs/consult.md` with the following logic:

### 1. Argument resolution

- Parse `args`: first token is `<agent>` (optional), remaining tokens form `[referent]` (optional context/question to seed the conversation).
- If no `<agent>` is given, show the role-selection guide and stop. The guide
  points to `shark agent list --json` when none of its roles fit.

### 2. Agent lookup

- Run `shark agent list` to get all agent names + descriptions.
- Try **exact match** on name first (case-insensitive).
- If no exact match, try **fuzzy match**: agent whose name or description contains the token.
- If still no match, list agents and return: `Agent "<token>" not found. Available: ...`

### 3. Load persona

- Run `shark agent get <resolved-name>` to fetch the agent's content.
- Strip YAML frontmatter (the `---` block at the top) — the remainder is the raw persona prompt.

### 4. Adopt persona inline

- Do NOT spawn a subagent. Adopt the persona in the current conversation context.
- Announce briefly: `[Consulting <DisplayName>]` on its own line.
- Respond in-voice to any `[referent]` the user passed, or prompt them to ask their question if none was given.

### 5. Graceful degradation

- If `shark agent get` fails, report `Agent "<name>" was listed but its content could not be loaded.`, show `shark agent list --all`, and stop before adopting the persona.
- If the agent list itself is empty, suggest `shark admin install-shark-data`.

### 6. Delegated one-shot consultation

- Keep `consult-agent` in its own procedure file and preserve the inline `consult` behavior.
- Resolve the same agent persona and resolve the referent before preparing the handoff.
- Include the persona definition, the user's question and referent, and only relevant project context in one bounded read-only host-subagent request.
- Have the parent inspect the response and synthesize advice in its own voice. Do not mutate Shark state or workspace files, launch nested agents, or continue in the persona voice on later turns.
- If no suitable host subagent is available, report that and direct the user to inline `consult`.

## Acceptance Criteria

- [ ] `/shark-rider consult` and `/shark-rider consult help` show the role-selection guide and stop
- [ ] `/shark-rider consult architect` loads the architect agent and adopts the persona
- [ ] `/shark-rider consult arch` fuzzy-matches to `architect` (or whichever agent contains "arch")
- [ ] `/shark-rider consult architect "is this design sound?"` seeds the opening question
- [ ] Unknown agent name gives a helpful error listing available agents
- [ ] With `docs/design.md` unambiguous in context, `/shark-rider consult-agent architect review this design` loads the persona and referent, sends one bounded read-only host-subagent request, then has the parent review and synthesize the advice
- [ ] A delegated consultation does not mutate Shark state or workspace files and does not launch nested agents
- [ ] Inline procedure lives at `skills/shark-rider/verbs/consult.md`; delegated procedure lives at `skills/shark-rider/verbs/consult-agent.md`

## Post-completion clarification (2026-11-19)

`/shark-rider consult <agent> [referent]` remains inline and does not spawn a
subagent. Bare `consult` and `consult help` show the role-selection guide.
Delegated one-shot advice is available separately through
`/shark-rider consult-agent <agent> [referent]`; this command does not replace
the inline behavior or the natural-language route to `consult`.
