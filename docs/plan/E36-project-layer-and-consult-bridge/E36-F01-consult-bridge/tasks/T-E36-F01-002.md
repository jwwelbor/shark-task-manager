# Task: Create inline and delegated Shark Rider consultation verbs

## Goal

Create `skills/shark-rider/verbs/consult.md` and `skills/shark-rider/verbs/consult-agent.md`. The first implements `/shark-rider consult <agent> [referent]` as a persona-driven inline consultation. The second implements `/shark-rider consult-agent <agent> [referent]` as a separate one-shot request to a bounded host subagent when the host can enforce read-only permissions; otherwise it explains the limitation and directs the user to inline consult without launching a subagent.

## Implementation Plan

Create the two consultation verbs and their shared host-local context files:

- `skills/shark-rider/context/consult-role-guide.md` owns the shared role-selection wording.
- `skills/shark-rider/context/consult-request-resolution.md` owns argument parsing, agent lookup, empty-list recovery, persona loading, referent resolution, and relevant context retrieval. Both verbs follow this procedure before applying mode-specific behavior.

### 1. Inline consultation

- Keep `/shark-rider consult <agent> [referent]` in the current conversation.
- Adopt the loaded persona turn-by-turn and do not spawn a subagent.
- Keep Shark mutations read-only unless the user explicitly asks to make a change.

### 2. Delegated one-shot consultation

- Keep `/shark-rider consult-agent <agent> [referent]` in its own procedure file.
- Include the persona, resolved referent, user question, and only relevant project context in one bounded host-subagent request.
- Require an enforced host permission/tool profile that prevents workspace writes, Shark mutations, and nested dispatch. If the host cannot enforce all three, do not launch; explain the limitation and direct the user to inline `consult`.
- Have the parent inspect the result and synthesize the advice in its own voice. Do not continue in the persona voice on later turns.

### 3. Read-only and failure handling

- Stop before persona use or dispatch when lookup fails; show `shark agent list --all` after a `shark agent get` failure.
- If no agents are installed, suggest `shark admin install-shark-data` and stop in both modes.
- If a read-only permission profile is unavailable, delegated mode does not launch a subagent and directs the user to inline `consult`.

## Acceptance Criteria

- [ ] `/shark-rider consult` and `/shark-rider consult help` show the role-selection guide and stop
- [ ] `/shark-rider consult architect` loads the architect agent and adopts the persona
- [ ] `/shark-rider consult arch` fuzzy-matches to `architect` (or whichever agent contains "arch")
- [ ] `/shark-rider consult architect "is this design sound?"` seeds the opening question

- [ ] A delegated consultation does not mutate Shark state or workspace files and does not launch nested agents
- [ ] If the agent list is empty, either mode suggests `shark admin install-shark-data` and stops before persona loading
- [ ] If the host cannot enforce read-only permissions for workspace writes, Shark mutations, and nested dispatch, delegated mode does not launch and directs the user to inline `consult`
- [ ] Inline procedure lives at `skills/shark-rider/verbs/consult.md`; delegated procedure lives at `skills/shark-rider/verbs/consult-agent.md`

## Post-completion clarification (2026-11-19)

`/shark-rider consult <agent> [referent]` remains inline and does not spawn a
subagent. Bare `consult` and `consult help` show the role-selection guide.
Delegated one-shot advice is available separately through
`/shark-rider consult-agent <agent> [referent]` when the host can enforce the
read-only permission profile; without it, the procedure directs the user to
inline `consult` without launching a subagent. This command does not replace the
inline behavior or the natural-language route to `consult`.
