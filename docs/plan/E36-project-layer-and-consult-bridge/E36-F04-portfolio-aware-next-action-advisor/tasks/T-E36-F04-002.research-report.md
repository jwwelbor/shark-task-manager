# Research report

## Scope

T-E36-F04-002 adds one non-mutating claim-service query for portfolio advice.
It lists claim rows once and filters expired leases at a caller-supplied time.
It does not change claim persistence, TTL resolution, claim-management output,
session journaling, or the existing sweep-before-list behavior.

## Capability map

| Capability | Source | Decision | Application |
| --- | --- | --- | --- |
| Claim-management list | `ClaimService.List` | **REUSE** | Preserve the current reclaim-before-list behavior for `shark claims`; do not change its implementation or caller. |
| Set-oriented claim read | `claim.Repository.List` | **REUSE** | Call this read method exactly once and filter its returned rows in memory. |
| Expiry boundary | `EntityClaim.IsExpired` | **REUSE** | Apply the configured TTL with the existing strict `age > ttl` rule. Do not duplicate cutoff logic. |
| Configured service TTL | `NewClaimService`, `ClaimService.ttl`, and `GetClaimService` | **REUSE** | Use the TTL already resolved from project config, environment, or the default. Preserve `ttl <= 0` as expiry disabled. |
| Caller-supplied evaluation time | E36-F04 service contract | **NEW** | Add `ListActiveReadOnly(ctx, evaluatedAt)` so every row is evaluated against one stable time. |
| Expired-lease reclaim | `ClaimService.List` and `claim.Repository.ReclaimExpired` | **CONTRADICTS** | Reclaim is correct for claim-management paths but forbidden in the portfolio read path because it deletes rows and uses a separate current time. |
| Claim session journal | `ClaimService.openSession` and `closeSessions` | **REUSE** | Keep session writes attached only to claim and release operations. The read-only method must not invoke either hook. |
| Claim-service mock pattern | `internal/services/claim_service_test.go` | **EXTEND** | Reuse the function-field repository mock and add list, boundary, error, and zero-mutation assertions. |

## Ubiquitous vocabulary

- **Active claim**: a claim that `EntityClaim.IsExpired` does not classify as
  expired at the supplied evaluation time.
- **Evaluation time**: the single `time.Time` supplied by the portfolio service
  and reused for every claim in one list operation.
- **TTL**: the `ClaimService` lease duration. A non-positive TTL disables
  expiry.
- **Boundary claim**: a claim whose age equals the TTL exactly; it remains
  active because expiry uses a strict greater-than comparison.
- **Expired claim**: a claim whose age is greater than the TTL. The read-only
  method omits it but leaves its database row unchanged.
- **Sweep**: `ReclaimExpired`, which deletes stale claim rows. Sweep behavior
  remains part of `Claim` and `List`, not `ListActiveReadOnly`.
- **Mutation hook**: claim, reclaim, release, session release, renew, session
  open, or session close.

## Findings

1. `ClaimService.List` is intentionally mutating: for a positive TTL it calls
   `ReclaimExpired` before `repo.List`. `runClaims` depends on this behavior for
   the `shark claims` management view, and the existing
   `TestClaimService_List_ReclaimsFirst` locks it in.
2. `claim.Repository.List` is already the required read primitive. It runs one
   ordered `SELECT` and performs no write. No repository method or SQL query
   needs to change for this task.
3. `EntityClaim.IsExpired(evaluatedAt, ttl)` is the authoritative predicate. It
   returns false when `ttl <= 0` and expires only claims whose age is strictly
   greater than TTL. At a 60-minute TTL, ages of 59:59 and 60:00 are live;
   60:01 is expired.
4. The repository's `ReclaimExpired` cannot implement this read contract. It
   deletes rows and calculates its own `time.Now().UTC()` cutoff, so it would
   both mutate state and introduce a second evaluation time.
5. The additive method needs only this call graph:
   `repo.List(ctx)` → ordered in-memory filter using
   `claim.IsExpired(evaluatedAt, s.ttl)` → active slice. It must not call
   `ClaimService.List`, `ReclaimExpired`, `Get`, or any mutation or session
   method.
6. Filtering should preserve repository order and claim pointers. Allocate the
   result with length zero and capacity `len(claims)` so an empty successful
   read returns a non-nil empty slice without changing a claim object.
7. When `repo.List` fails, return no claims and wrap the error with operation
   context while preserving `errors.Is`. Do not retry through the sweeping
   `List` path or return partially filtered data.
8. Existing `mockClaimRepo` methods call function fields directly. Tests can
   define every unexpected method as a fail-on-call function and count the one
   expected repository list. Attach a session-log mock and assert zero opens
   and closes to cover indirect telemetry writes.
9. The focused tests do not need a database. The repository implementation and
   `EntityClaim.IsExpired` already have their own real-database and pure model
   coverage; this task verifies service composition with the real predicate.

## Decisions

1. Add
   `func (s *ClaimService) ListActiveReadOnly(ctx context.Context, evaluatedAt time.Time) ([]*models.EntityClaim, error)`
   beside `List` in `internal/services/claim_service.go`.
2. Call `s.repo.List(ctx)` exactly once. On success, preserve input order and
   include each claim for which
   `claim.IsExpired(evaluatedAt, s.ttl)` is false.
3. Treat `ttl <= 0` through `EntityClaim.IsExpired`; do not add a second TTL
   branch or bypass the repository read.
4. Return `nil` plus a wrapped repository error when listing fails. Make no
   mutation call before or after the failure.
5. Leave `ClaimService.List`, `Claim`, `ReclaimExpired`, `IsClaimable`, TTL
   resolution, and `runClaims` unchanged.
6. Add table-driven tests at one fixed UTC evaluation time for TTL disabled,
   TTL minus 1 second, exact TTL, and TTL plus 1 second. Assert one list call,
   stable result order, and a non-nil empty result when every claim is expired.
7. Add a repository-error test that verifies wrapped error identity, nil
   output, one list call, and zero claim, get, reclaim, release, session-release,
   renew, session-open, or session-close calls.
8. Keep output sanitization outside this method. It returns domain claims to
   T-E36-F04-006, which projects only the approved active-work fields.
