# Research plan

## Scope

Define the Go and JSON shape for the portfolio-advice read model. Cover the
envelope, epic evidence, relationship evidence, ordering, warnings, blockers,
and sanitized active work. Exclude graph analysis, service assembly,
repository access, CLI routing, and persistence changes.

## Recipe

Use the universal SIMPLE recipe with the backend and API modules. Establish the
shared vocabulary, compare the requested read model with existing JSON and
domain types, and resolve only the representation choices needed by
T-E36-F04-001.

## Source set

Read the task, feature contract, feature research, specification, and TC-019.
Inspect the existing epic, relationship, claim, completion-metadata, analytics,
and keyed-next response types for JSON tags, nullable-field behavior, slice
initialization, enum conventions, and sensitive-field boundaries.

## Steps

1. Extract every required object, field, JSON name, nullability rule, and
   collection rule from `spec.md` and TC-019.
2. Compare the contract with the existing epic, relationship, claim, and JSON
   response types.
3. Choose reusable scalar types and identify persistence structs that the new
   read model must not embed.
4. Define how constructors and callers keep every collection non-nil without
   adding graph or workflow logic to the model.
5. Record the exact DTO and test boundaries for the development task.
