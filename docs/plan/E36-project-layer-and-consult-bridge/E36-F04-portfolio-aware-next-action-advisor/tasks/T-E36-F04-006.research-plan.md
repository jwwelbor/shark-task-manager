# Research plan

## Scope

Define how `PortfolioAdviceService.Advise` assembles the completed T-001 through
T-005 contracts into one read-only evidence envelope. Cover dependency seams,
workflow-aware classification, partial evidence, eligibility, active-work
attachment, stable ordering, graph invocation, prompt construction, and tests.
Exclude CLI wiring, telemetry, Rider help, the scale fixture, and product-document
inspection.

## Recipe

Use the universal STANDARD recipe with the supported backend and
workflow-operations categories. Prefer the live DTO, repository, claim,
progress, graph, and workflow contracts over speculative abstractions.

## Source set

- Feature requirements and service contract in `spec.md`.
- Caller-path and decision-table cases TC-004 through TC-016 and TC-019 in
  `test-plan.md`.
- Completed foundation code and task research for T-001 through T-005.
- Existing workflow classification and service-constructor patterns.

## Steps

1. Inventory the exact production interfaces the service must consume.
2. Define one-call orchestration and fatal-versus-partial failure behavior.
3. Trace terminal, blocked, unknown, dependency, and descendant eligibility.
4. Specify progress, blocker, active-work, relationship, and warning assembly.
5. Specify deterministic sorting, graph invocation, and prompt boundaries.
6. Map mock seams and counter-factual tests to the test plan.
7. Verify the resulting design cannot reach mutation-capable dependencies.
