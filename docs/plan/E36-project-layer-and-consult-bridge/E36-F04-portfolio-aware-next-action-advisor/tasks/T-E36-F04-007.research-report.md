# Research report

## Scope

T-E36-F04-007 connects the completed advice service to the CLI. Bare
`shark next` returns one read-only portfolio envelope; `shark next <key>` keeps
the existing dispatch resolver, including its legitimate status normalization.
The task also owns production construction and portfolio-only tracing. It does
not change eligibility, graph rules, Rider behavior, or lifecycle preview flags.

## Capability map

| Capability | Source | Decision | Application |
| --- | --- | --- | --- |
| Keyed dispatch | `internal/cli/commands/next.go` | **REUSE** | Leave parse, adapter cache, `resolveNext`, prompt rendering, JSON shape, and existing span attributes intact for one argument. |
| Portfolio assembly | `PortfolioAdviceService.Advise` | **REUSE** | Call it only from the zero-argument branch and encode its envelope directly as JSON. |
| Global service construction | `internal/cli/services_global.go` | **EXTEND** | Add a lightweight accessor using the shared DB, epic repository, portfolio read repository, claim service, and configured workflow provider. |
| Cobra argument validation | Existing `nextCmd` | **EXTEND** | Change from exactly one argument to a zero-or-one contract. |
| Portfolio telemetry | Existing `shark.next` span | **EXTEND** | Add only mode, count, warning-count, and completeness attributes on bare success. |
| Inert `next --preview` | Removed flag and regression test | **CONTRADICTS** | Keep it absent; unknown-flag validation must occur before any advisor or keyed factory call. |
| Dispatch simulation | None | **CONTRADICTS** | Do not add a dry-run path or reinterpret bare advice as simulated dispatch. |
| Database-backed CLI tests | Existing unit-test boundaries | **CONTRADICTS** | Use injected factories and in-memory telemetry so routing tests remain database-free. |

## Ubiquitous vocabulary

- **Bare next**: `shark next` with zero positional arguments; a read-only
  portfolio advice query.
- **Keyed next**: `shark next <entity-key>`; the existing dispatch resolver,
  which may normalize workflow state while resolving a step.
- **Advisor factory**: the CLI seam that supplies an object with `Advise(ctx)`
  for bare-mode tests and production wiring.
- **Keyed factory**: any transitioner, placeholder, or action-service factory
  reachable only after a key is supplied.
- **Portfolio attributes**: bounded span facts about mode, candidate count,
  relationship count, graph-warning count, and evidence completeness.
- **Unknown flag rejection**: Cobra rejects `--preview` before RunE, so neither
  mode reads or mutates state.

## Findings

1. `runNext` currently parses `args[0]` and constructs the keyed adapter cache
   unconditionally. The bare branch must therefore occur immediately after the
   `shark.next` span starts and before `ParseGetArgs` or `newNextAdapterCache`.
2. `nextCmd.Args` is currently `cobra.ExactArgs(1)`. `cobra.MaximumNArgs(1)`
   expresses the required zero-or-one contract and rejects extra positional
   arguments before RunE.
3. The command package needs a narrow advisor interface and replaceable factory
   analogous to its existing keyed builder hooks. Tests can then fail on any
   keyed-factory call while returning a deterministic advice DTO.
4. The production accessor can create a new advice service per call because its
   dependencies are stateless or already shared. It must use the existing epic
   repository, new portfolio repository, `GetClaimService`, and
   `GetWorkflowService`; no action or transition service belongs in this path.
5. Bare success should use the same JSON encoder behavior as keyed output but
   must not pass through `NextResponse`, placeholder annotation, or keyed
   warning logic.
6. Bare fatal errors set the span to error and return a wrapped command error.
   They must not emit a partial JSON object. Partial evidence from `Advise` is a
   successful envelope and is represented by `evidence_complete=false`.
7. The exact bare success attributes are `mode=portfolio_advice`,
   `portfolio.candidate_count`, `portfolio.relationship_count`,
   `portfolio.graph_warning_count`, and `portfolio.evidence_complete`. Prompt
   text and claim identity must never enter telemetry.
8. Existing keyed span attributes remain unchanged. The portfolio branch must
   return before keyed response annotation so it cannot contaminate or rename
   the dispatch contract.
9. The already-removed `nextPreview` variable and flag registration must stay
   removed. Cobra unknown-flag behavior provides the required fail-before-state
   boundary; preview flags on other lifecycle commands are out of scope.
10. TC-001 through TC-003 and TC-018 require real command validation and JSON
    behavior, an advisor mock, fail-on-call keyed factories, and an in-memory
    span exporter. Global wiring tests should verify construction separately
    without making command tests database-aware.

## Decisions

1. Give `nextCmd` the usage `next [entity-key]` and `cobra.MaximumNArgs(1)`.
2. Start the existing span once, then dispatch `len(args)==0` to a dedicated
   bare-mode helper before parsing or constructing keyed adapters.
3. Add the smallest package-owned advisor interface/factory seam needed for
   database-free tests; production points it at `cli.GetPortfolioAdviceService`.
4. Encode the service-owned `PortfolioAdviceEnvelope` directly and return.
5. Emit exactly the five specified portfolio attributes on bare success and no
   prompt, claim-holder, session, note, or SQL content.
6. Preserve the keyed body below the new early branch except for structural
   movement needed by the shared span.
7. Prove excess arguments and `--preview` fail before both advisor and keyed
   factory access. Do not add any simulation code.
