# Research report

## Scope

T-E36-F04-001 defines the stable, sanitized Go structs serialized by bare
`shark next`. This report covers representation and JSON behavior only. The
service owns classification, validation, sorting, warning construction,
timestamp normalization, and collection population. Later tasks own graph,
repository, CLI, and workflow behavior.

## Capability map

| Capability | Source | Decision | Application |
| --- | --- | --- | --- |
| Portfolio-advice wire contract | E36-F04 `spec.md` Data model | **NEW** | Define dedicated envelope, epic, blocker, active-work, relationship, warning, and ordering structs in `internal/models/portfolio_advice.go`. |
| Keyed dispatch response | `internal/cli/commands/next.go` | **REUSE** | Keep `NextResponse` separate and unchanged. The portfolio envelope has `mode` and no dispatch `action`. |
| Epic scalar types | `internal/models/epic.go` | **EXTEND** | Project the stored status, priority, and business value into explicit read-model fields without embedding `Epic`. |
| Epic JSON representation | `internal/models/epic.go` | **CONTRADICTS** | `Epic.BusinessValue` uses `omitempty`, but portfolio JSON must include `business_value: null`; use a dedicated nullable field without `omitempty`. |
| Relationship vocabulary | `internal/models/entity_relationship.go` | **REUSE** | Reuse `EntityRelationshipType` for `depends_on`, `blocks`, and `follows`; expose endpoint keys and statuses instead of persistence IDs. |
| Persistent relationship model | `internal/models/entity_relationship.go` | **CONTRADICTS** | Do not embed `EntityRelationship`; it exposes database IDs and lacks the portfolio fields `hard` and nullable `satisfied`. |
| Claim time and progress scalars | `internal/models/entity_claim.go` | **EXTEND** | Reuse `time.Time` and `*float64`, normalize heartbeat values to UTC before assignment, and keep nullable progress present in JSON. |
| Persistent claim model | `internal/models/entity_claim.go` | **CONTRADICTS** | Do not embed `EntityClaim`; it would expose ID, session ID, claim time, and free-form note. |
| Required JSON nulls | `internal/services/sprint_analytics_dto.go` | **REUSE** | Follow the established pointer-without-`omitempty` pattern for `business_value`, `progress`, and `satisfied`. |
| Initialized collection constructor | `internal/models/completion_metadata.go` | **EXTEND** | Use a focused constructor to allocate envelope and nested ordering slices, but omit `omitempty` because empty portfolio collections must serialize as `[]`. |

## Ubiquitous vocabulary

- **Portfolio-advice envelope**: the top-level read model returned by bare
  `shark next`; it is distinct from keyed `NextResponse`.
- **Epic evidence**: the public, advisory projection of one non-terminal epic.
- **Eligibility**: `eligible`, `ineligible`, or `unknown`; the service computes
  it, while the model only carries it.
- **Blocked item**: a workflow-blocked descendant or unresolved hard
  predecessor attached to an epic.
- **Active work**: the sanitized projection of a live epic, feature, or task
  claim associated with an epic.
- **Relationship evidence**: a supported epic-to-epic relationship with
  resolved endpoints and hard-precedence satisfaction.
- **Ordering**: deterministic dependency and roadmap layers plus unlayered
  epic keys and graph warnings.
- **Warning**: a typed, actionable diagnostic with a stable code and sorted
  epic keys.
- **Allocated collection**: a non-nil Go slice that marshals to `[]`, not
  `null`.

## Findings

1. The specification defines seven required structs:
   `PortfolioAdviceEnvelope`, `PortfolioEpicEvidence`,
   `PortfolioBlockedItem`, `PortfolioActiveWork`,
   `PortfolioEpicRelationship`, `PortfolioWarning`, and
   `PortfolioOrdering`. All fields are JSON-visible; none needs a database tag.
2. Every collection requires an explicit JSON tag without `omitempty`:
   `epics`, `relationships`, top-level `warnings`, `eligibility_reasons`,
   `blocked_items`, `active_work`, `epic_keys`, `dependency_layers`,
   `roadmap_layers`, `unlayered_epics`, and ordering `warnings`. A nil slice
   marshals as `null`, so tags alone do not satisfy REQ-F-008.
3. `ordering` should be a value field rather than a pointer. This preserves a
   stable object shape in an empty response, but its four slices still require
   initialization.
4. Required nullable scalars must be pointers without `omitempty`:
   `business_value` is `*string`, `PortfolioActiveWork.progress` is
   `*float64`, and `PortfolioEpicRelationship.satisfied` is `*bool`. This
   makes nil encode as JSON `null` instead of deleting the field.
5. `PortfolioActiveWork` must be a projection, not an embedded claim. The exact
   public fields are `entity_type`, `entity_key`, `claimed_by`,
   `last_heartbeat`, and `progress`; this construction prevents session ID and
   note leakage by type design.
6. `time.Time` already marshals as an RFC 3339-compatible JSON string. The
   service must call `UTC()` before assigning `last_heartbeat`; the model does
   not need custom JSON marshaling or a stringly typed timestamp.
7. Existing typed-string conventions support small read-model enums for mode,
   eligibility, blocker kind, and warning code. Relationship type should reuse
   `EntityRelationshipType` instead of defining a second vocabulary. Stored
   workflow status remains `string` because workflows are configurable.
8. Model code must not sort, classify workflows, normalize relationships,
   clamp progress, or build messages. Those rules require service context and
   belong to T-E36-F04-005 and T-E36-F04-006.
9. A small `NewPortfolioAdviceEnvelope` constructor can set mode and allocate
   the top-level and ordering slices. Service assembly must also allocate every
   epic and warning child slice it creates. Custom `MarshalJSON` would hide
   incomplete assembly and add unnecessary transformation logic to the model.
10. The focused model test should marshal a constructor-produced empty envelope
    and an epic with allocated empty child collections, decode the result, and
    assert field presence and array types. It should also assert that nullable
    fields remain present as `null` and that the active-work type has no JSON
    path for `session_id` or `note`.

## Decisions

1. Add dedicated portfolio read-model structs. Do not embed `Epic`,
   `EntityRelationship`, `EntityClaim`, `NextResponse`, or service-layer DTOs.
2. Use explicit snake-case JSON tags and no `omitempty` tag on any field in the
   portfolio contract.
3. Use `string` for keys, titles, workflow statuses, priority, claim holder,
   prompt, and reason text. Use `*string`, `*float64`, and `*bool` for the three
   required nullable scalar fields.
4. Use `time.Time` for `last_heartbeat` and require the service to supply a UTC
   value. Use `EntityRelationshipType` for `relationship_type`.
5. Define typed constants for `portfolio_advice`, the three eligibility
   values, the three blocker kinds, and the warning codes named by `spec.md`.
   These constants are representation vocabulary only; they do not add model
   validation or workflow rules.
6. Provide `NewPortfolioAdviceEnvelope` to initialize mode, envelope slices,
   and every ordering slice. Initialize epic child slices and warning
   `epic_keys` at their service construction sites so the service-produced
   contract remains explicit.
7. Keep sorting and progress-range enforcement outside the model. Test only the
   DTO field names, required nulls, empty-array behavior, and sensitive-field
   exclusion in T-E36-F04-001.
