# Research plan

## Scope

Define the two query-only portfolio snapshot reads and their real-database test
boundary. Cover exact raw row shapes, hierarchy joins, supported relationship
filtering, deterministic ordering, parameterization, dangling relationship
evidence, and fixture cleanup. Exclude service classification, graph
normalization, writes, migrations, and the full target-scale service gate owned
by T-E36-F04-009.

## Recipe

Use the universal STANDARD recipe with the backend and data modules. Trace the
requested output fields to the live SQLite schema, compare the new cross-entity
read model with existing repository conventions, and convert the service error
contract into an explicit nullable-endpoint query design.

## Source set

Read the task, feature artifacts, specification, and test plan. Inspect the
current hierarchy and relationship DDL, model constants, database wrapper,
existing epic and relationship repositories, repository integration tests,
test-database helpers, and repository cleanup rules.

## Steps

1. Map every child-state field to the live epic, feature, and task columns and
   define direct-parent semantics for both entity types.
2. Map both stored relationship endpoints to epic rows without losing dangling
   relationship evidence required by the service warning contract.
3. Define one set-oriented, deterministically ordered SQL statement per method,
   with every filter value bound as a parameter.
4. Separate raw repository responsibilities from workflow, eligibility,
   progress, and graph decisions owned by the service.
5. Define focused real-database fixtures for ownership, supported filtering,
   nullability, repeatable ordering, read-only behavior, and reverse-order
   cleanup.
6. Identify the extension seam for T-E36-F04-009 without implementing its
   200/5,000/10,000 full-service performance fixture here.
