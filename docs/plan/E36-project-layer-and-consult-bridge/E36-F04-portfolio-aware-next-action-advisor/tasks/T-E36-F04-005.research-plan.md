# Research plan

## Scope

Define the pure portfolio graph analysis consumed by the advice service. Cover
stored-to-normalized relationship direction, hard-edge satisfaction, candidate
filtering, duplicate aggregation, deterministic Kahn layers, cycle and
contradiction diagnostics, reachability-based missing-order warnings, and
allocated output slices. Exclude repository reads, workflow classification,
eligibility calculation, recommendation scores, relationship repair, clocks,
and CLI behavior.

## Recipe

Use the universal STANDARD recipe with the backend module. Trace every graph
rule from the feature specification through TC-006 to TC-012, then compare it
with the live relationship semantics and E19-F07's stable, explainable ordering
precedent. Resolve output-shape ambiguities from the exact specification before
defining helper boundaries.

## Source set

Read the task and feature artifacts, T-E36-F04-001's DTO research and current
implementation, all graph acceptance tests, the relationship model and service,
and E19-F07's feature and production stable-order implementation.

## Steps

1. Define the graph's candidate and relationship inputs from the T001 read
   model, including the service-owned satisfaction precondition.
2. Normalize `depends_on`, `blocks`, and `follows` into explicit
   `before -> after` edges while preserving contributing relationship types.
3. Specify separate hard and combined-roadmap edge sets and deterministic Kahn
   traversal outputs.
4. Specify cycle classification, contradiction aggregation, and warning sort
   keys without repairing or choosing an edge.
5. Define reachability-based missing-order detection only among eligible hard
   first-layer roots.
6. Define focused pure tests for direction, satisfaction, permutations,
   duplicates, self and larger cycles, partial layers, contradictions, soft
   separation, and incomparable roots.
