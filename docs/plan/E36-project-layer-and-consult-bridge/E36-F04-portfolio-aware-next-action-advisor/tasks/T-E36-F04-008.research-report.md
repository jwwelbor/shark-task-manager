# Research report

## Scope

T-E36-F04-008 updates the host-side Rider contract and explanatory documents
after the CLI gained a second `next` mode. State-aware help consumes bare
portfolio advice inline and stops at one recommendation or evidence gap. Keyed
dispatch remains an explicit `/shark-rider run <key>` action. Static help stays
fully static.

## Ubiquitous vocabulary

- **Mode 1, portfolio advice**: bare `shark next`; a read-only evidence envelope
  and prompt for choosing one epic root.
- **Mode 2, keyed dispatch**: `shark next <key> --json`; the workflow-resolving
  dispatch API consumed by `/shark-rider run <key>`.
- **State-aware help**: bare `/shark-rider help`; the only help branch allowed
  to query live Shark state.
- **Static help**: `--fast`, `commands`, known-verb, or unknown-verb help; no
  Shark state calls.
- **Inline advice**: the current Rider reads relevant `docs/product/` artifacts
  named by the returned prompt and performs the recommendation itself.
- **Explicit handoff**: the operator separately invokes
  `/shark-rider run <recommended-key>` to cross from advice into dispatch.

## Findings

1. The live `help.md` already separates static and state-aware branches, so no
   new router or verb is needed. Only the state-aware procedure should gain the
   bare advice call.
2. Its current statement “Do not call `shark next` from state-aware help” is the
   exact stale contradiction created while removing the inert preview flag.
   It must be replaced, not merely supplemented.
3. State-aware help should run bare `shark next` exactly once and use the
   returned envelope prompt inline. The prompt already contains the authority,
   document-inspection, hard-precedence, recommendation, alternative, and gap
   rules; Rider should not duplicate or weaken them.
4. The help turn ends with either one eligible epic recommendation plus why-now
   and strongest-alternative evidence, or an evidence/relationship gap. It must
   not claim, advance, call keyed next, or spawn a worker.
5. Static help branch instructions occur before the state-aware section and
   already mandate zero state calls. The unknown-verb clause should explicitly
   remain a bounded static correction so it cannot fall through to advice.
6. The Rider skill's golden invariant currently needs narrower wording: only
   keyed `shark next <key> --json` yields the dispatch prompt that must be passed
   unchanged. Bare advice returns a different service-owned prompt for reasoning
   in the current turn.
7. The dispatch architecture document uses unqualified `shark next` in its
   contract bullets. It should identify its sequence diagram and wire shape as
   keyed dispatch, then state that bare mode neither assembles specialist
   prompts nor authorizes mutation.
8. The route guide says unqualified `shark next` hands out only unclaimed
   entities. That statement must become keyed `shark next <root>` so it cannot
   be misread as a side effect of portfolio advice.
9. TC-017 can be enforced by a Go contract test that reads production files,
   normalizes whitespace, slices the five help branches, and checks both
   required clauses and forbidden state/dispatch operations. Copied fixtures
   would not catch future documentation drift.
10. The existing query/workflow Rider verbs may continue to avoid keyed next
    for read-only entity inspection. This task changes only state-aware help;
    it does not make bare portfolio advice a substitute for an entity-specific
    status query.

## Decisions

1. Add a two-mode command boundary to Rider `SKILL.md`, keeping the golden
   unchanged-prompt rule explicitly keyed.
2. Make bare state-aware help call `shark next` once, follow its prompt inline,
   and stop at advice or a gap.
3. State explicitly that no subagent, keyed next, claim, transition, or automatic
   run occurs in help.
4. Keep all four static help forms at zero state calls and prevent unknown verbs
   from falling through.
5. Scope dispatch-assembly documentation to keyed mode and describe bare mode
   as a sibling read-only contract.
6. Qualify route-guide handout and lease statements with `<root>`.
7. Add only the production-Markdown TC-017 contract test; leave CLI and preview
   behavior to T-E36-F04-007.
