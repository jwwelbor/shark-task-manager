# Research report

## Scope

T-E36-F04-009 adds only the TC-020 integration/performance test. It wires the
real epic, portfolio snapshot, and claim repositories through
`PortfolioAdviceService.Advise`, observes their calls without replacing SQL,
and proves the exact target fixture is fast, deterministic, and read-only.

## Capability map

| Capability | Source | Decision | Application |
| --- | --- | --- | --- |
| Isolated SQLite fixture | `test.NewIsolatedTestDB` | **REUSE** | Give the non-parallel performance test a clean schema and automatic file cleanup. |
| Portfolio seed helpers | `repository_test.go` | **EXTEND** | Add transaction-oriented bulk helpers for the exact target scale. |
| Epic list | `EpicRepository.List` | **REUSE** | Delegate through a counting reader; do not replace results. |
| Descendant and relationship reads | Portfolio repository | **REUSE** | Delegate both set queries through one counting wrapper. |
| Active claim filtering | `ClaimService.ListActiveReadOnly` | **REUSE** | Delegate to the real claim repository; use expiry values well outside the measured current-time boundary. |
| Portfolio assembly and graph | `PortfolioAdviceService.Advise` | **REUSE** | Measure the production entry point and compare complete returned envelopes. |
| Per-epic repository calls | None required | **CONTRADICTS** | Fail when the four expected dependency methods are not called exactly once. |
| Production clock or schema changes | Task scope | **CONTRADICTS** | Do not add production seams solely for measurement or alter persisted data definitions. |

## Ubiquitous vocabulary

- **Target fixture**: exactly 200 epics, 5,000 feature/task descendants, and
  10,000 supported epic relationships.
- **Set read**: one call to epic list, child states, epic relationships, or
  active claims, regardless of returned row count.
- **Delegating counter**: a test wrapper that increments a call count and then
  invokes the real repository/service method without modifying its result.
- **Measured interval**: one production `Advise` call after schema creation and
  fixture seeding have completed.
- **Deterministic output**: two advice calls over the same snapshot yield deeply
  equal envelopes apart from no returned wall-clock field.
- **No-write evidence**: material table counts are unchanged across advice.

## Findings

1. The production service makes one epic-list call, one child-state call, one
   relationship call, and one active-claim call. Delegating wrappers around
   these exact interfaces can observe the four-call budget while preserving
   real SQLite SQL and real service/graph behavior.
2. The performance test belongs in `internal/repository/portfolio` because that
   is the permitted package for real database integration and already owns
   reverse-FK fixture helpers.
3. `test.NewIsolatedTestDB(t)` avoids contamination from the shared test DB and
   removes the database automatically. The test must not call `t.Parallel` so
   timing and local resource use remain controlled.
4. Setup must be outside the timer. A transaction with prepared statements is
   appropriate for 15,200 fixture rows and avoids measuring test-seeding
   overhead as product behavior.
5. An acyclic deterministic relationship pattern can be generated over ordered
   epic pairs with supported relationship types and no duplicate
   from/type/to tuple. All rows remain relevant because both endpoints are
   epics in the returned non-terminal set.
6. The descendant total should mix features and tasks while keeping every task
   attached to a seeded feature. For example, 20 features plus 5 tasks per epic
   yields exactly 5,000 descendants across 200 epics.
7. Claims are optional to the numeric scale but representative live and expired
   rows prove the real read-only filter. Seeding expiry/heartbeat values far
   from the current time avoids a new production clock hook and boundary
   flakiness.
8. Apply the one-second acceptance threshold to the first defined target-scale
   call. A second call is diagnostic and supports deep deterministic comparison;
   it must still retain the exact four-call-per-invocation shape.
9. Snapshot table counts before and after measured advice prove no lease cleanup,
   relationship repair, history insert, or other write occurred. Query counters
   prove there is no service-level per-epic read fan-out.
10. Empty and one-epic lower boundaries can be separate isolated subtests or
    calls before target seeding. They assert allocated collections, correct
    candidate counts, and the same four-method contract, but do not substitute
    for the exact scale threshold.
11. No network or document dependency is present in the production advice
    constructor. Keeping the test within repository/service packages prevents
    CLI observability or Rider artifacts from entering the measured path.

## Decisions

1. Add one non-parallel TC-020 test and narrowly scoped seed/count helpers to
   `internal/repository/portfolio/repository_test.go` only.
2. Use real repositories behind delegating counters and assert four total read
   calls, one per required method, for each `Advise` invocation.
3. Seed all exact-scale rows in a transaction, commit, then start a monotonic
   timer immediately before `Advise`.
4. Require elapsed time below one second, 200 returned epic candidates, complete
   evidence, deterministic repeated output, and unchanged table counts.
5. Include empty and one-epic lower-bound checks while keeping their timing
   informational rather than using them for AC-020.
6. Make no production, schema, migration, network, HTTP, or document changes.
