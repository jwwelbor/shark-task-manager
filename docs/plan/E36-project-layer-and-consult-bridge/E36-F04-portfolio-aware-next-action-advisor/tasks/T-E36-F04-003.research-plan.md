# Research plan

## Scope

Define a behavior-preserving extraction of the epic-progress calculation from
`EpicAnalyticsService.CalculateProgress`. Keep repository reads and errors in
the service method. Exclude a new scoring model, workflow redesign, portfolio
assembly, display-path cleanup, and persistence changes.

## Recipe

Use the universal STANDARD recipe with the backend and data modules. Trace the
existing formula, its input guarantees, its rounding caller, and adjacent
progress implementations before defining the pure helper boundary.

## Source set

Read the task, feature artifacts, specification, and test-plan infrastructure.
Inspect the analytics service and delegated `EpicService` tests, raw repository
rows, feature validation and schema constraints, workflow metadata, and the
other progress/status helpers that could appear reusable but have different
semantics.

## Steps

1. Separate repository access and error handling from arithmetic in
   `CalculateProgress`.
2. Record the exact cancelled, completed, archived, stored-progress, and empty
   behaviors.
3. Trace range enforcement and rounding to their actual layers.
4. Compare workflow-aware and display-data progress helpers for semantic
   compatibility.
5. Define the helper signature, callers, and focused regression matrix.
