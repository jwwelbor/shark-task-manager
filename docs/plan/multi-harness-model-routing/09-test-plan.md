# Test strategy and acceptance matrix

Run most coverage offline with fake dispatchers, fake executable helpers and frozen catalogs. Service tests use injected repositories and clocks. CLI tests mock service boundaries. Use isolated temporary databases for repository and explicit integration tests. Retain existing prompt, workflow and gate fixtures as regression controls. Run `make fmt`, `make lint` and `make test` during implementation along with the affected benchmark suites.

Exercise Rider's inline fallback as part of R09 and R13. With zero eligible external CLIs or with all external attempts exhausted on replay-safe failures, expect one inline attempt with a keyed prompt, a recorded mode and the existing lease and result checks. An accepted external result, including a valid negative workflow outcome, ends the fallback sequence. Permission denial, uncertain writes, unconfirmed retirement, exhausted budget and missing required independence or route evidence each prevent inline execution. An inline failure pauses without another launch.

## Real CLI qualification

Run a small authenticated qualification matrix after operator approval, using disposable repositories, approved test accounts, pinned model/environment/mode and bounded calls. One harmless read-only result per supported binding should prove model and effort selection, structured result extraction, worker-correlated evidence and absence of unapproved changes. Qualify one mutating fixture per supported writer mode, isolated to a disposable worktree. Use an intentionally denied action in the fixture to verify the claimed permission boundary. Treat isolation and entitlement evidence as specific to the tested versions and bindings.

| CLI | Minimum qualification evidence |
|---|---|
| Claude Code | Qualified model/effort pair, print-mode output, result contract and enforced allowed/denied tools. Verify the bug gate mode in the compatible adapter. |
| Codex CLI | Catalog and local config readback in launch context, then correlated execution identity and measured effort evidence where available. Verify bounded output and filesystem/approval behavior. |
| GitHub Copilot CLI | Qualified GitHub-managed model/effort pair, JSONL terminal output and correlated identity, approved permission profile and supported usage units. |
| Cross-harness workflow | Admit an independently verified review of the same immutable candidate. Exercise one prelaunch alternate with a deliberately absent executable. Verify resolution, lease, candidate and completion records. |

Reject certification where the worker cannot prove the required observed identity or permission contract. Record unsupported modes and the remaining evidence gap. Keep authenticated canaries separate from standard CI. Benchmark comparison eligibility additionally follows E40's calibration, evidence retention and workload requirements.

## Planning baseline verification

Offline checks passed for `internal/runner`, `internal/gaterun`, `internal/config/workflow`, `internal/config/action` and `internal/workercontrol`. The targeted B083 catalog, materializer and route-contract pytest set passed 62 cases. The Copilot routing identity wrapper passed 48 cases. The B083 production-route wrapper passed 40 cases using fixture workers. Executable/version/help checks supplemented source inspection. Authenticated canary qualification belongs to implementation.
