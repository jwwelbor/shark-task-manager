# Task: Add orchestrator action to task get output

## Goal

Wire `resolveTaskAction()` into `runTaskGet` in `task.go` so that both JSON and plain text output include the OrchestratorAction for the task's current status.

## Context

The infrastructure is already in place:
- `resolveTaskAction(task)` in `orchestrator_display.go` loads workflow config, looks up the task's status metadata, and returns a `*config.PopulatedAction` with template variables replaced.
- `displayOrchestratorAction(action)` renders the action in human-readable format.

This task wires these helpers into the task get command.

## Requirements

### Functional Requirements

- [ ] JSON output includes `"orchestrator_action"` field (null if no action configured)
- [ ] Plain text output appends "Next Action:" section when action exists
- [ ] Plain text output omits the section entirely when no action is configured
- [ ] Works for all task statuses (ready_for_*, in_*, blocked, completed, etc.)

## Implementation Plan

### Steps

1. [ ] Write tests verifying JSON output contains `orchestrator_action` field
2. [ ] Write tests verifying plain text output contains "Next Action:" section
3. [ ] Add `"orchestrator_action": resolveTaskAction(task)` to the JSON output map in `runTaskGet`
4. [ ] Add `displayOrchestratorAction(resolveTaskAction(task))` to plain text output in `runTaskGet`

### Files to Modify

- `internal/cli/commands/task.go` — `runTaskGet` function (~line 700 for JSON, ~line 857 for plain text)

### Files Already Modified (from earlier session)

- `internal/cli/commands/orchestrator_display.go` — `resolveTaskAction`, `displayOrchestratorAction` already exist
- `internal/services/display_service.go` — `OrchestratorAction` field already added to display structs

## Acceptance Criteria

- [ ] `shark task get <key> --json` includes `orchestrator_action` in JSON output
- [ ] `shark task get <key>` shows "Next Action:" section in plain text for statuses with actions
- [ ] No "Next Action:" section appears for statuses without actions (e.g., `in_development`)
- [ ] Tests pass with `make test`
- [ ] `make fmt && make lint` pass clean

## Testing Strategy

- Write unit tests using mocked workflow config (no DB needed)
- Test statuses WITH actions (e.g., `ready_for_development`) produce output
- Test statuses WITHOUT actions (e.g., `in_development`) produce no output
- Verify JSON structure includes the field

## Dependencies
- `orchestrator_display.go` helpers (already implemented)
- `config.PopulatedAction` struct (already exists)
