# Task: Add orchestrator action to feature get output

## Goal

Wire `resolveFeatureAction()` into `runFeatureGet` in `feature.go` so that both JSON and plain text output include the OrchestratorAction for the feature's current status. Must handle both planning mode and aggregation mode code paths.

## Context

The infrastructure is already in place:
- `resolveFeatureAction(feature)` in `orchestrator_display.go` loads workflow config and returns a `*config.PopulatedAction`
- `displayOrchestratorAction(action)` renders the action in human-readable format
- `FeatureDisplayInfo` struct already has `OrchestratorAction *config.PopulatedAction` field

Features have TWO display modes (same as epics):
1. **Planning mode** — uses `FeatureDisplayInfo` struct, rendered by `renderFeaturePlanning()`
2. **Aggregation mode** — uses `map[string]interface{}`, rendered by `renderFeatureDetails()`

Both modes need orchestrator action support.

## Requirements

### Functional Requirements

- [ ] Planning mode JSON: `FeatureDisplayInfo.OrchestratorAction` populated before JSON output
- [ ] Planning mode plain text: `renderFeaturePlanning()` displays action after workflow position
- [ ] Aggregation mode JSON: `"orchestrator_action"` added to output map
- [ ] Aggregation mode plain text: action displayed after `renderFeatureDetails()` call
- [ ] No action section when status has no configured action

## Implementation Plan

### Steps

1. [ ] Write tests for planning mode JSON output
2. [ ] Write tests for aggregation mode JSON output
3. [ ] Write tests for plain text output in both modes
4. [ ] Planning mode: set `info.OrchestratorAction = resolveFeatureAction(feature)` before JSON/render
5. [ ] Aggregation mode: add `"orchestrator_action": resolveFeatureAction(feature)` to JSON map
6. [ ] `renderFeaturePlanning()`: add `displayOrchestratorAction(info.OrchestratorAction)` after workflow position
7. [ ] Aggregation plain text: add `displayOrchestratorAction(resolveFeatureAction(feature))` after `renderFeatureDetails()` call
