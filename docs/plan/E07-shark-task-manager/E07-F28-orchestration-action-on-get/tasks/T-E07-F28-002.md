# Task: Add orchestrator action to epic get output

## Goal

Wire `resolveEpicAction()` into `runEpicGet` in `epic.go` so that both JSON and plain text output include the OrchestratorAction for the epic's current status. Must handle both planning mode and aggregation mode code paths.

## Context

The infrastructure is already in place:
- `resolveEpicAction(epic)` in `orchestrator_display.go` loads workflow config and returns a `*config.PopulatedAction`
- `displayOrchestratorAction(action)` renders the action in human-readable format
- `EpicDisplayInfo` struct already has `OrchestratorAction *config.PopulatedAction` field

Epics have TWO display modes:
1. **Planning mode** — uses `EpicDisplayInfo` struct, rendered by `renderEpicPlanning()`
2. **Aggregation mode** — uses `map[string]interface{}`, rendered by `renderEpicDetails()`

Both modes need orchestrator action support.

## Requirements

### Functional Requirements

- [ ] Planning mode JSON: `EpicDisplayInfo.OrchestratorAction` populated before JSON output
- [ ] Planning mode plain text: `renderEpicPlanning()` displays action after workflow position
- [ ] Aggregation mode JSON: `"orchestrator_action"` added to output map
- [ ] Aggregation mode plain text: action displayed after `renderEpicDetails()` call
- [ ] No action section when status has no configured action

## Implementation Plan

### Steps

1. [ ] Write tests for planning mode JSON output
2. [ ] Write tests for aggregation mode JSON output
3. [ ] Write tests for plain text output in both modes
4. [ ] Planning mode: set `info.OrchestratorAction = resolveEpicAction(epic)` before JSON/render
5. [ ] Aggregation mode: add `"orchestrator_action": resolveEpicAction(epic)` to JSON map
6. [ ] `renderEpicPlanning()`: add `displayOrchestratorAction(info.OrchestratorAction)` after workflow position
7. [ ] Aggregation plain text: add `displayOrchestratorAction(resolveEpicAction(epic))` after `renderEpicDetails()` call
