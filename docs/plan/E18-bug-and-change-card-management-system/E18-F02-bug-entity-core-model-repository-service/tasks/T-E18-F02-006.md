# Bug Service Status Transitions

## Goal

Implement `AdvanceBugStatus` and `SetBugStatus` on BugService for workflow-integrated status transitions via the workflow service.

## Rationale

Bug status transitions must use workflow.Service.ForLevel("bug") for configurability. No hardcoded status logic in the service. Follows the same pattern as task/feature/epic transitions.

## Scope

**Modified:** `internal/services/bug_service.go` -- Add 2 methods

**Methods:**
- `AdvanceBugStatus(ctx, key)` -- get next status from workflow, check terminal, update
- `SetBugStatus(ctx, key, targetStatus)` -- validate transition via workflow, update

## Success Criteria

- [ ] AdvanceBugStatus traverses: reported -> triaged -> in_fix -> in_verification -> resolved
- [ ] Terminal statuses (resolved, wont_fix, duplicate) return clear error on advance
- [ ] SetBugStatus validates transitions before applying
- [ ] SetBugStatus can reach terminal statuses from valid predecessors
- [ ] Invalid transitions return descriptive errors
- [ ] No hardcoded status values -- all via workflow service
