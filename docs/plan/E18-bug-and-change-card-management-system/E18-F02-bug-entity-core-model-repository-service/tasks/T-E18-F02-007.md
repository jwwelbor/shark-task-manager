# Bug Service Triage Operation

## Goal

Implement `TriageBug` method that atomically sets severity, assigns a person via context_data JSON, and advances status from "reported" to "triaged".

## Rationale

Triage is a domain-specific composite operation unique to bugs. It must be atomic -- if any step fails, all changes roll back. Encapsulating in a single method prevents multi-step CLI commands and partial updates.

## Scope

**Modified:** `internal/services/bug_service.go` -- Add TriageBug and context_data helpers

**What to Build:**
- `TriageBug(ctx, TriageBugInput)` per 04-backend-design.md Section 1.9
- Validate bug is in "reported" status
- Parse and merge context_data JSON for "assigned_to" per ADR-6
- Transaction wraps severity + context + status changes
- Rollback all on any failure

- TriageBug flow: [04-backend-design.md Section 1.9](../04-backend-design.md)

## Success Criteria

- [ ] Sets severity, assigned_to context, advances to "triaged"
- [ ] Only valid from "reported" status
- [ ] Error: "cannot triage bug B001: current status is 'triaged', must be 'reported'"
- [ ] Status advance failure rolls back severity and context changes
- [ ] assigned_to stored in context_data JSON, not as a column
- [ ] Triage with only Key still advances status
- [ ] `make fmt && make lint && make test` passes
