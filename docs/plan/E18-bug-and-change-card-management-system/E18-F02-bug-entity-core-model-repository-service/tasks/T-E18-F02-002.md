# Bug Repository Implementation

## Goal

Implement `BugRepository` in `internal/repository/bug_repository.go` with pure CRUD operations, filtering queries, key generation, and aggregate counts against the `bugs` table (delivered by F01).

## Rationale

The repository provides the data access layer that BugService depends on. It must be pure data access with zero business logic, following existing repository patterns.

## Scope

**New File:** `internal/repository/bug_repository.go`

**What to Build:**
- BugRepository struct with `*DB` dependency and constructor
- CRUD: Create, GetByKey (case-insensitive), GetByID, Update, Delete, UpdateStatus
- Key generation: GetNextKey using MAX query (never reuse deleted keys)
- Filtering: List with dynamic WHERE clause (status, severity, linked_entity_key)
- Aggregates: CountByStatus, CountBySeverity
- Private `scanBug` helper for column scanning

**Prerequisites:** F01 must have created the `bugs` table. T-E18-F02-001 must be complete.

## Success Criteria

- [ ] All CRUD methods use parameterized queries
- [ ] GetByKey is case-insensitive, returns NotFoundError when not found
- [ ] GetNextKey returns B001 on empty table, increments correctly, no key reuse
- [ ] List supports status, severity, linked_entity_key filters with AND logic
- [ ] List returns empty slice (not nil) when no results match
- [ ] CountByStatus and CountBySeverity return correct aggregations
- [ ] Delete returns NotFoundError for non-existent keys
- [ ] Update does not modify key or status
- [ ] `make fmt && make lint && make test` passes
