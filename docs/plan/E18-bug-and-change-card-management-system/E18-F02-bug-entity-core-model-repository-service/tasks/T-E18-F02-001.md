# Bug Model and Validation

## Goal

Create the Bug model struct, BugStatus type, BugSeverity type with constants, and structural validation methods in `internal/models/bug.go`. This is the foundational data type that all other F02 tasks depend on.

## Rationale

The Bug entity needs a strongly-typed model with severity constants and key format validation before the repository or service layers can be built. Follows existing model patterns (Task, Epic, Feature, Idea).

## Scope

**New File:** `internal/models/bug.go`

**What to Build:**
- BugStatus typed string (following the TaskStatus pattern)
- BugSeverity typed string with 4 constants: critical, high, medium, low
- ValidBugSeverities map for lookup validation
- Bug struct with all fields per [03-data-design.md Section 1.2](../03-data-design.md)
- Struct tags: json and db tags. Nullable fields use pointer types.
- `Validate()` method -- structural only. Must NOT check workflow status validity.
- `ValidateBugKey(key string) error` -- validates B### format (exactly 3 digits, uppercase B)

**Pattern Source:** `internal/models/task.go` and `internal/models/idea.go`

## Design References

- Struct definition and field types: [03-data-design.md Section 1.2](../03-data-design.md)
- Validation rules: [03-data-design.md Sections 1.4 and 1.5](../03-data-design.md)
- Key format: [feature.md F02-REQ-002, F02-REQ-003](../feature.md)

## Success Criteria

- [ ] Bug struct compiles with all fields from data design spec
- [ ] BugSeverity has exactly 4 constants
- [ ] `Validate()` errors on: empty title, invalid key, empty status, invalid severity
- [ ] `Validate()` accepts any non-empty status string
- [ ] `ValidateBugKey` accepts B001, B042, B999
- [ ] `ValidateBugKey` rejects B0001, B01, b001, bug001, empty string
- [ ] Error messages include the invalid value and expected format
- [ ] `make fmt && make lint && make test` passes
