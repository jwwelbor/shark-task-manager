# Bug Service DTOs and Repository Interface

## Goal

Define service-layer DTOs and the BugRepository interface in the services package, establishing the contract between BugService and BugRepository.

## Rationale

Defining DTOs and interfaces first enables parallel work on service and repository. The interface is in the services package (consumer-side pattern) per project architecture.

## Scope

**New File:** `internal/services/bug_dto.go`
**New/Modified:** `internal/services/bug_service.go` (interfaces at top, before service struct)

**DTOs (bug_dto.go):**
- CreateBugInput: Title (required), Description, Severity (optional), LinkedEntityKey (optional)
- TriageBugInput: Key (required), Severity (optional), AssignedTo (optional)
- BugUpdates: Title, Description, Severity -- pointer types for partial updates
- BugFilters: Status, Severity, LinkedEntityKey, ShowAll
- All with JSON tags

**Interfaces (bug_service.go):**
- BugRepository: CRUD, GetNextKey, List, CountByStatus, CountBySeverity
- BugListFilters struct for repository List method
- LinkValidatorEpicRepo, LinkValidatorFeatureRepo, LinkValidatorTaskRepo (GetByKey only)
