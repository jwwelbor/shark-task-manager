## Implementation Guidance

### Architecture Compliance Checklist

Verify each item from [Test Plan - Section 5.2](../09-test-plan.md#52-architecture-compliance-code-review-checklist):

- Model file imports only fmt, strings, time (no workflow/config packages)
- Repository contains zero business logic (no workflow checks, no validation beyond structural)
- Service uses workflowSvc for all status operations (zero hardcoded status strings)
- Service uses repository interface (not concrete type) for data access
- Constructor validates required dependencies (panics on nil)
- DTOs use pointer types for optional update fields
- Error messages match contract strings in backend design Section 6

### Pattern Parity Checks

Compare change-card implementation against existing entities for consistency:

- Constructor pattern matches TaskService/EpicService
- Error wrapping format matches existing services
- JSON tags follow snake_case convention
- Repository test cleanup pattern matches existing repo tests
- Service test mock pattern matches existing service tests
