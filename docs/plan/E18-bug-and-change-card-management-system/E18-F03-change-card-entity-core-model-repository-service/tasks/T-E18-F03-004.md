# Task: ChangeCard Service Implementation

## Goal

Implement the ChangeCardService with all business logic: create (with link validation and atomic file+DB), approve, advance status, set status, get, list with filters, update, delete, and count by status. The service delegates data access to the repository and workflow validation to workflowSvc.

## Success Criteria

- [ ] ChangeCardService struct and constructor in `internal/services/change_card_service.go`
- [ ] Repository interface defined consumer-side in the service file
- [ ] Constructor panics on nil required dependencies (db, repo, workflowSvc)
- [ ] Constructor accepts nil optional dependencies (epicRepo, featureRepo)
- [ ] All 9 service methods implemented per flows in backend design
- [ ] CreateChangeCard wraps DB insert + file write in a transaction (atomic)
- [ ] Link validation detects entity type from key format, rejects task keys
- [ ] All status transitions go through workflowSvc (zero hardcoded statuses)
- [ ] Service tests pass with mocked repositories using function-field pattern
- [ ] `make fmt && make lint && make test` passes with zero failures
