## Acceptance Criteria Verification

### 1. GetStatusService() wires bug/change-card repos via option functions

PASS.

```go
// service_accessors.go:231-242
func GetStatusService() *status.StatusService {
    db, err := GetDB(context.Background())
    if err != nil {
        panic(fmt.Sprintf("failed to get database: %v", err))
    }
    bugRepo := repository.NewBugRepository(db)
    ccRepo  := repository.NewChangeCardRepository(db)
    return status.NewStatusService(db,
        status.WithBugRepository(bugRepo),
        status.WithChangeCardRepository(ccRepo),
    )
}
```

- Both `BugRepository` and `ChangeCardRepository` are instantiated from the shared DB.
- They are injected using the functional-option pattern (`WithBugRepository`,
  `WithChangeCardRepository`) defined in `internal/status/status.go`.
- The option functions store the repos in `StatusService.bugRepo` / `StatusService.changeCardRepo`
  which are the `BugDashboardRepository` and `ChangeCardDashboardRepository` interface fields.
- Pattern is consistent with every other accessor in the file (panic on DB failure, no shared
  state, new instance per call).

### 2. Compile-time interface checks present and correct

PASS.

```go
// internal/services/interface_checks.go
var (
    _ status.BugDashboardRepository        = (*repository.BugRepository)(nil)
    _ status.ChangeCardDashboardRepository = (*repository.ChangeCardRepository)(nil)
)
```

- Placement in `package services` is architecturally correct: it allows `status` to remain
  ignorant of `repository` (avoiding a dependency cycle) while still enforcing the contract
  at compile time.
- Both interfaces are narrow, containing only the methods needed for dashboard aggregation:
  - `BugDashboardRepository`: `GetStatusSummary`, `GetFeatureBugSummary`
  - `ChangeCardDashboardRepository`: `GetStatusSummary`
- The godoc comment explains both the intent and the cycle-avoidance rationale clearly.

history (`git log -- internal/cli/commands/bug.go internal/services/bug_dto.go`) confirms
the last change to both files was from E18-F04 (`9695bd1`), before the T-E18-F07-007 commit
(`97b5fe1`).

Required fix: Add `Assign *string` to `TriageBugInput` in `internal/services/bug_dto.go`
(and handle it in `BugService.TriageBug`), or remove the `--assign` flag from `bugTriageCmd`
if the intent changed. This must be resolved before the branch can pass CI.
