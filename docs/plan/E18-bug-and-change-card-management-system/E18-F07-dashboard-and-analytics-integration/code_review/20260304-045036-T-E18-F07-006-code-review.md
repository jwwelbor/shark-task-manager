## Code Quality Assessment

### architecture.go — analytics.go

**Layering:** Correct. The command layer is a thin wrapper:
- `runAnalytics` parses flags and routes, delegates to helpers
- `runEntityAnalytics` / `runCombinedAnalytics` call `cli.GetDashboardAnalyticsService()` then pass to testable inner functions
- No repository calls in the command

**Interface definition at point of use:** `dashboardAnalyticsServicer` is defined at the top of `analytics.go` (the consumer). This correctly follows the Go interface pattern from the architecture rules.

**Routing logic:** Clean. Unknown `--type` values are rejected with a helpful error message. The "no flags, no type" path defaults to combined analytics without requiring an explicit `all` value — this is a sound UX decision.

**`formatDurationFromSecs`:** Well-implemented helper with intentional truncation rules (minutes omitted when days are shown, seconds omitted when hours are shown). The truncation approach is consistent and documented via comments. The helper is tested with a table-driven test covering the key cases.

**Minor observation (non-blocking):** The flag description string says `"Entity type analytics: bug, change"` while the acceptance criteria listed `bugs, changes, all`. The implementation uses singular forms throughout and is internally consistent. If the spec was intended to match `bugs`/`changes` as values, this would be a mismatch, but since the entire implementation (help text, error messages, routing, and tests) uses `bug`/`change`, this is coherent as-is. No change required.

### services_global.go — GetDashboardAnalyticsService

**Pattern compliance:** Follows the established pattern exactly — `GetDB` call, panic on error, repository construction, service construction. Consistent with `GetBugService` and `GetChangeCardService` directly above it.

**Godoc:** Present and correct, includes usage example.

### analytics_test.go

**Mock pattern:** Uses the function-field pattern consistent with the codebase (`mockDashboardAnalyticsService` with `GetBugAnalyticsFunc` / `GetChangeCardAnalyticsFunc`). Correctly implements the `dashboardAnalyticsServicer` interface.

**Coverage:**
- Human-readable output formatting (bug + change card)
- JSON output path (bug + change card)
- Isolation: `--type=bug` does not call change-card service
- Error propagation: both bug and change card service errors are tested
- Graceful degradation: combined output omits failing sections without returning an error
- Nil-safety: both formatters tested with nil pointer fields
- `formatDurationFromSecs` table-driven across 7 cases
- Invalid entity type rejection

**Output capture:** The `capturingOutput` helper uses `os.Pipe()` to redirect stdout. This is the correct approach for testing `fmt.Printf` output without refactoring the print functions.

**Global state cleanup:** `cli.GlobalConfig.JSON` is saved and restored with `defer` in JSON tests. This is correct and avoids cross-test pollution.
