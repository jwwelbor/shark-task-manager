## Acceptance Criteria Verification

### AC1: `--type` flag routes to bug or change analytics

**Status: PASS**

`analyticsCmd` registers `--type string` flag. `runAnalytics()` reads it and dispatches:
- `--type=bug` → `runEntityAnalytics(cmd, "bug")` → `runEntityAnalyticsWithSvc(..., "bug", svc)` → `svc.GetBugAnalytics()`
- `--type=change` → `runEntityAnalytics(cmd, "change")` → `runEntityAnalyticsWithSvc(..., "change", svc)` → `svc.GetChangeCardAnalytics()`
- Unknown value → `fmt.Errorf("unknown entity type...")` returned
- No `--type` + no session flags → `runCombinedAnalytics()` (combined output)

Verified by:
- `TestRunEntityAnalytics_Bug_DoesNotCallChangeCard` - routing isolation confirmed
- `TestRunEntityAnalytics_InvalidType` - unknown type returns error
- `./bin/shark analytics --help` shows `--type string Entity type analytics: bug, change`

## Architecture Review

The implementation follows project patterns correctly:

- **Interface at point of use**: `dashboardAnalyticsServicer` defined in `analytics.go` (not imported from services package), enabling lightweight test mocks
- **Testable core functions**: `runEntityAnalyticsWithSvc()` and `runCombinedAnalyticsWithSvc()` accept the interface, decoupling from the global accessor
- **Global accessor**: `cli.GetDashboardAnalyticsService()` wires the real service for production use
- **Thin CLI layer**: Command parses flags, calls service, formats output - no business logic
- **Graceful degradation**: Combined analytics skips unavailable sections instead of hard-failing
