# Task: Dashboard Model Extensions and StatusService Integration

## Goal

Extend the StatusDashboard model with optional bug and change-card summary fields, and extend the StatusService to conditionally populate these fields using the repository aggregate methods from task 001. This enables the dashboard to display bug/change-card data when available while maintaining backward compatibility.

## Success Criteria

- [ ] StatusDashboard struct has BugSummary and ChangeCardSummary optional pointer fields with omitempty JSON tags
- [ ] BugDashboardSummary and ChangeCardDashboardSummary types defined in status models
- [ ] StatusService accepts optional bug/change-card repositories via option function pattern
- [ ] GetDashboard() conditionally populates bug/cc sections (nil when repos absent or zero entities)
- [ ] Existing StatusService callers work without modification (backward compatibility)
- [ ] Graceful degradation: if bug repo returns error, dashboard still renders without bug section
- [ ] make fmt && make lint && make test passes

## Implementation Guidance

This task extends the status package models and StatusService using the option function pattern for backward-compatible dependency injection (ADR-F07-001 and ADR-F07-003).

- Dashboard model extensions: See [Architecture - Section 3.3](../02-architecture.md#33-dashboard-model-extensions)
- StatusService option pattern: See [Architecture - Section 4.1](../02-architecture.md#41-statusservice-extension-dashboard)
- Narrow interface definitions (BugDashboardRepository, ChangeCardDashboardRepository): See [Architecture - Section 4.1](../02-architecture.md#41-statusservice-extension-dashboard)
- Conditional population: query repo, check total > 0, populate or leave nil
- Graceful degradation: log warning on repo error, do not fail the dashboard
