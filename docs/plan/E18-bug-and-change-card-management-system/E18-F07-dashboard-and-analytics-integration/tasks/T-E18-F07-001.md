## Implementation Guidance

### Overview

Implement aggregate query methods on the bug and change-card repositories created by F02 and F03. Each method performs GROUP BY/COUNT/AVG operations and returns a typed DTO. The DTO definitions and method signatures are specified in the architecture doc.

### Key Requirements

- DTO structures: See [Architecture - Section 3.1](../02-architecture.md#31-new-repository-dtos) for BugStatusSummary, BugResolutionStats, BugFeatureSummary, ChangeCardStatusSummary, ChangeCardThroughputStats
- Repository interface contracts: See [Architecture - Section 3.2](../02-architecture.md#32-repository-interface-methods)
- SQL query specifications: See [Architecture - Section 7](../02-architecture.md#7-repository-aggregate-query-specifications)
- Resolution time uses created_at to terminal status timestamp from entity_status_history
- Terminal bug statuses: resolved, wont_fix, duplicate
- Approval rate: approved / (approved + declined), nil when no decided cards

### Files to Create/Modify

- BugRepository (created by F02) -- add GetStatusSummary, GetResolutionStats, GetFeatureBugSummary
- ChangeCardRepository (created by F03) -- add GetStatusSummary, GetThroughputStats
- Repository test files -- add tests for each aggregate method
