# Task: CLI Tests with Mocked ChangeCardService

## Goal

Create a comprehensive test suite in `internal/cli/commands/change_test.go` that validates all 11 change-card subcommands using mocked services. Zero real database access. Tests cover happy paths, error paths, JSON output, exit codes, and architectural compliance.

## Success Criteria

- [ ] Test file `internal/cli/commands/change_test.go` exists with tests for all 11 subcommands
- [ ] All tests use `MockChangeCardService` with function field pattern -- zero `test.GetTestDB()` calls
- [ ] Happy path tests for: create, get, list, update, delete, approve, note add, notes, context set/get/clear
- [ ] Error path tests: not found (exit 1), invalid state (exit 3), service error (exit 2)
- [ ] JSON output tests verify valid JSON on create, get, list, update, approve
- [ ] Approve tests cover: proposed (success), approved/completed/in_progress (exit 3), not found (exit 1)
- [ ] List tests cover: no filters, status filter, link filter, empty results, invalid status
- [ ] Architectural validation: no `repository.New` imports in `change.go`
- [ ] Note and context tests verify `entity_type="change"` is passed to NoteService/ContextService
- [ ] `make fmt && make lint && make test` passes with all tests green

## Implementation Guidance

### Overview

Define a `MockChangeCardService` struct with function fields for each service method. Write table-driven tests for each command covering the scenarios in the test plan. Use the function field mock pattern (not a mocking framework) to inline test data per test case. Verify mock call parameters with assertions to confirm correct service method invocation.

### Patterns to Follow
- Function field mock pattern: `CreateFunc`, `GetFunc`, `ListFunc`, etc.
- Table-driven tests with `t.Run()` for multiple scenarios per command
- `assert.NoError`, `assert.Equal`, `assert.Contains` from testify

### Integration Surface
- Tests must mock `ChangeCardService`, `NoteService`, and `ContextService`
- Tests must verify exact parameters passed to mock functions (key, entity_type, etc.)

### Scope Boundary
- DO NOT use real database (`test.GetTestDB()`) -- this is a CLI test, not a repository test
- DO NOT test service business logic -- only test that commands correctly parse args and call services
- DO NOT test view command in this file (view tests belong in view package tests)

## Validation Gates

- Zero `test.GetTestDB` or `repository.New` calls in test file
- Every exit code (0, 1, 2, 3) has at least one test
- Mock assertions verify correct parameters on every service call
- `make fmt && make lint && make test` passes

## Notes for Agent

- The mock must implement whatever interface or concrete type the commands use to call the service
- If commands call `cli.GetChangeCardService()` directly (not via interface), the test setup must override this accessor
- Consider using a `testChangeCardService` package-level var that tests can set, or use the existing CLI test override pattern
- For the delete confirmation test, you cannot fully test interactive stdin -- verify that `GetChangeCard` is called before the prompt
