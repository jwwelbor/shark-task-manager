# Task: Approve Command and Error-to-Exit-Code Mapping

## Goal

Implement the `shark change approve` domain-specific command and establish the error-to-exit-code mapping pattern for all change-card commands. The approve command calls `ChangeCardService.ApproveChangeCard` and maps typed service errors to exit codes 1 (not found) and 3 (invalid state).

## Success Criteria

- [ ] `shark change approve C001` advances status from `proposed` to `approved` with success message
- [ ] Approving a non-proposed card returns exit code 3 with message including current status
- [ ] Approving a non-existent key returns exit code 1 with "change-card not found: C999"
- [ ] `--json` flag outputs the approved change-card object
- [ ] Error-to-exit-code mapping is consistent with task/feature/epic commands
- [ ] Error mapping is reusable by CRUD commands from task 002 (shared helper or pattern)
- [ ] `make fmt && make lint && make test` passes

## Implementation Guidance

### Overview

The approve handler is a thin wrapper: parse the key, call `ChangeCardService.ApproveChangeCard`, format output or error. The critical addition is a reusable error mapping function that inspects `NotFoundError` (exit 1) and `WorkflowTransitionError` (exit 3) typed errors from the service layer and translates them to appropriate CLI exit codes and user-friendly messages.

### Key Requirements

- Approve handler pattern -- See [Architecture - Section 5, Approve example](../02-architecture.md#approve-domain-specific-command)
- Error handling strategy -- See [Architecture - Section 10](../02-architecture.md#10-error-handling)
- F05-REQ-007: Approve command -- See [PRD - F05-REQ-007](../feature.md#functional-requirements)
- Exit code mapping: 0=success, 1=not found, 2=service error, 3=invalid state -- See [Architecture - Section 9](../02-architecture.md#exit-code-coverage)
