# Task: Notes, Context, and View Command Integration

## Goal

Implement the `shark change note add`, `shark change notes`, `shark change context set/get/clear` subcommands by delegating to existing NoteService and ContextService with `entity_type="change"`. Also extend the `shark view` command to resolve C### keys to change-card markdown file paths.

## Success Criteria

- [ ] `shark change note add C001 --type=decision "content"` adds a note via NoteService
- [ ] `shark change notes C001` lists notes in chronological order
- [ ] `shark change context set C001 --field effort --value "small"` sets a context field via ContextService
- [ ] `shark change context get C001` returns all context fields as JSON
- [ ] `shark change context clear C001 --field effort` removes a specific context field
- [ ] All note and context calls pass `entity_type="change"` to the existing services
- [ ] `shark view C001` renders the change-card markdown file to the terminal
- [ ] `shark view C001` returns error if the markdown file does not exist on disk
- [ ] `make fmt && make lint && make test` passes

## Implementation Guidance

### Overview

Note and context handlers first resolve the change-card by key (via `ChangeCardService.GetChangeCard`) to get the database ID, then delegate to the existing NoteService/ContextService. The view command extension adds a `C###` key detection case to the view service's key routing logic, resolving the file path from the change_cards table.
