## T-E18-F05-003: Exit Code Fix

**Criteria:**
- `runChangeApprove` maps errors to exit codes: NotFoundError -> exit 1, workflow errors -> exit 3, other -> exit 2

**Evidence:**

`change.go` lines 438-450:
```go
errMsg := err.Error()
if strings.Contains(errMsg, "not found") {
    cli.Error(fmt.Sprintf("Change-card not found: %s", key))
    os.Exit(1)
}
if strings.Contains(errMsg, "cannot approve") || strings.Contains(errMsg, "invalid transition") ||
    strings.Contains(errMsg, "invalid status") || strings.Contains(errMsg, "cannot transition") {
    cli.Error(fmt.Sprintf("Cannot approve change-card %s: %s", key, errMsg))
    os.Exit(3)
}
cli.Error(fmt.Sprintf("Failed to approve change-card %s: %s", key, errMsg))
os.Exit(2)
```

**Note on approach:** The implementation uses `strings.Contains` on the error message rather than `errors.As` with typed errors. This is an accepted pragmatic approach for this codebase given that the change-card service layer does not currently expose typed error types. The error message strings checked ("not found", "cannot approve", "invalid transition", "invalid status", "cannot transition") are reasonable coverage.

**Known limitation:** `os.Exit()` in a Cobra command handler bypasses `PersistentPostRun` cleanup hooks and makes the function hard to unit test (tests for error paths are omitted in the test file for this reason, as documented with a comment). This is a pre-existing pattern in this codebase and is acceptable for this task scope.

**Result: APPROVED**

## T-E18-F05-004: Context Clear Fix

**Criteria:**
- `runChangeContextClear` respects `--field` flag: when set, clears only that field via `SetContextField(..., "")`, when absent clears all context

**Evidence:**

`change.go` lines 607-643:
```go
func runChangeContextClear(cmd *cobra.Command, args []string) error {
    key := args[0]
    field, _ := cmd.Flags().GetString("field")
    ...
    if field != "" {
        if err := ctxSvc.SetContextField(cmd.Context(), models.EntityTypeChange, key, field, ""); err != nil {
            return fmt.Errorf("failed to clear context field for change-card %s: %w", key, err)
        }
    } else {
        if err := ctxSvc.ClearContext(cmd.Context(), models.EntityTypeChange, key); err != nil {
            return fmt.Errorf("failed to clear context for change-card %s: %w", key, err)
        }
    }
    ...
}
```

The `--field` flag is registered on line 304 as optional (no `MarkFlagRequired`). The branching is correct: non-empty field value calls `SetContextField` with empty string value; absent field calls `ClearContext`.

The output messages at lines 637-641 also correctly differentiate between the two paths.

**Result: APPROVED**
