## Summary

The view service was correctly extended to handle CC-### key format. However, `shark change note add`, `shark change notes`, `shark change context set/get/clear` — the core deliverables of this task — were never created. Additionally, the existing unified `shark context CC-001` command fails at runtime because `toModelEntityType()` does not handle the `change_card` entity type. The entity model (`models.EntityTypeChange`) exists but is not wired into the context command dispatch.

**Verdict: FAIL**

---

## Acceptance Criteria Assessment

### AC1: `shark change note add CC-001 --type=decision "Note content"` works

**FAIL — BLOCKER**

`shark change note add` does not exist. `shark change` itself does not exist.

No note-add command for change-cards exists via any path. The `NoteService.AddNote()` supports `models.EntityTypeChange` (confirmed: `ValidEntityTypes` includes `"change"`), but no CLI command calls it with a CC-### key.

### AC2: `shark change notes CC-001` lists notes

**FAIL — BLOCKER**

`shark change notes` does not exist. No notes listing command for change-cards exists via any path.

### AC3: `shark change context set CC-001 --field=key --value=val` works

**FAIL — BLOCKER**

`shark change context set` does not exist under `shark change`.

Furthermore, the existing unified `shark context CC-001` command would also fail: `toModelEntityType()` in `internal/cli/commands/context.go` (line 234-243) only handles `"epic"`, `"feature"`, `"task"` — it returns `"unsupported entity type: change_card"` for CC-### keys. This is an additional bug in the existing code.

```go
// context.go line 234-243 - MISSING change_card case:
func toModelEntityType(entityType string) (models.EntityType, error) {
    switch entityType {
    case "epic":
        return models.EntityTypeEpic, nil
    case "feature":
        return models.EntityTypeFeature, nil
    case "task":
        return models.EntityTypeTask, nil
    // MISSING: case "change_card": return models.EntityTypeChange, nil
    // MISSING: case "bug": return models.EntityTypeBug, nil
    default:
        return "", fmt.Errorf("unsupported entity type: %s", entityType)
    }
}
```

### AC4: `shark change context get CC-001` and `shark change context clear CC-001` work

**FAIL — BLOCKER**

Same as AC3 — neither the `shark change context` subcommand nor the unified `shark context CC-001` path works correctly.

### AC5: `shark view CC-001` opens the change-card markdown file

**PASS**

The view service correctly handles CC-### keys. `internal/view/service.go` at line 107 has a `case scope.ScopeChangeCard:` branch that:
1. Fetches the card via `changeCardRepo.GetByKey()`
2. Returns `card.FilePath`

The `scope.NewInterpreter().ParseScope()` (line 91 of interpreter.go) recognizes CC-### keys via `keys.IsChangeCardKey()` and maps them to `ScopeChangeCard`. The `shark view CC-001` command should work correctly (assuming a card exists with a file path set).
