# Code Review: T-E18-F05-002 — CRUD Commands (create, get, list, update, delete)

**Reviewer:** TechLead Agent
**Date:** 2026-03-04
**Task:** T-E18-F05-002
**Status:** FAIL — Returned to ready_for_development

---

## Summary

The task required implementing `shark change create`, `shark change get`, `shark change list`, `shark change update`, and `shark change delete` as subcommands under the `shark change` parent group. Three of the five commands (create, get, delete) were partially implemented as helper functions dispatched through unified commands (`shark create change`, `shark get CC-###`, `shark delete CC-###`), but `shark change list` and `shark change update` are completely absent. The `--link` flag pattern was replaced with separate `--epic`/`--feature` flags contrary to spec. None of these exist under `shark change <subcommand>`.

**Verdict: FAIL**

---

## Acceptance Criteria Assessment

### AC1: `shark change create "<title>" [flags]` works

**FAIL — BLOCKER**

`shark change create` does not exist. `shark change` itself does not exist (`Error: unknown command "change" for "shark"`).

`shark create change "Title"` does work via unified dispatch, but that is not the specified interface.

The implementation in `runChangeCardCreate` uses `--epic` and `--feature` flags separately. The specification requires a single `--link=KEY` flag that accepts either an epic key (`E07`) or a feature key (`E07-F01`). This is a spec deviation.

**Spec requires:**
```
shark change create "Title" --link=E07
shark change create "Title" --link=E07-F01
```

**Implemented as:**
```
shark create change "Title" --epic=E07
shark create change "Title" --feature=E07-F01
```

### AC2: `shark change get CC-001 [--json]` works

**FAIL — BLOCKER**

`shark change get` does not exist under `shark change`. The unified `shark get CC-001` does work correctly via `runChangeCardGet` which calls `GetChangeCardService().GetChangeCard()`. The implementation is correct but exposed through the wrong command path.

### AC3: `shark change list [--status=proposed] [--json]` works

**FAIL — BLOCKER**

`shark change list` is completely absent. There is no list implementation for change-cards anywhere in the codebase — not under unified dispatch, not under any other command. The `ChangeCardService` has a `ListChangeCards` method (as required by T-E18-F05-002's service prerequisite), but no CLI command exposes it.

### AC4: `shark change update CC-001 [flags]` works

**FAIL — BLOCKER**

`shark change update` is completely absent. No update implementation for change-cards exists anywhere in the codebase or via any dispatch path.

### AC5: `shark change delete CC-001 [--force]` works

**FAIL — BLOCKER**

`shark change delete` does not exist under `shark change`. The unified `shark delete CC-001` works via `runChangeCardDelete`. The `--force` flag behavior needs verification — the implementation does not implement a confirmation prompt (task spec and ADR-F05-006 specify a confirmation prompt pattern).

### AC6: JSON output works for all CRUD commands

**PARTIAL**

`runChangeCardGet`, `runChangeCardCreate`, `runChangeCardDelete` all correctly check `cli.GlobalConfig.JSON` and call `cli.OutputJSON(card)`. But since three of these are only accessible via unified dispatch (wrong path) and two don't exist at all, this criterion is incomplete.
