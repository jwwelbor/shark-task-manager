# Task: Workflow Profile Integration

## Goal

Update the basic and advanced workflow profile JSON files to include `bug_workflow` and `change_workflow` sections so that `shark init update --workflow=advanced` and `--workflow=basic` generate complete workflow configurations for all entity types including bugs and change-cards.

## Success Criteria

- [ ] `internal/init/profiles/basic.json` contains `bug_workflow` and `change_workflow` keys
- [ ] `internal/init/profiles/advanced.json` contains `bug_workflow` and `change_workflow` keys
- [ ] Both profile files parse as valid JSON
- [ ] Existing epic/feature/task workflow sections in both profiles are unchanged
- [ ] New sections follow the same JSON structure as existing workflow sections (status_flow, status_metadata, special_statuses)
- [ ] After `shark init update --workflow=advanced`, config contains bug and change workflow sections
- [ ] A pre-E18 `.sharkconfig.json` (without bug/change sections) loads without error, falling back to defaults
- [ ] `make fmt && make lint && make test` passes

## Implementation Guidance

Add `bug_workflow` and `change_workflow` JSON sections to both profile files following the structure of existing `epic_workflow` and `feature_workflow` sections.

See [Architecture - Section 3.5 and 3.6](../02-architecture.md#35-internalinitprofilesbasicjson----basic-profile) for the profile modification specification. See [Implementation Phases - Phase 4](../08-implementation-phases.md#phase-4-workflow-profile-integration) for the JSON structure and the config deserialization path.

Verify that the config parser correctly maps `bug_workflow` JSON key to `MultiLevelWorkflow.Bug` field and `change_workflow` to `MultiLevelWorkflow.Change`. Check `internal/config/workflow_parser.go` if the mapping is not automatic.

- `internal/init/profiles/basic.json` -- Add bug_workflow and change_workflow sections
- `internal/init/profiles/advanced.json` -- Add bug_workflow and change_workflow sections
- `internal/init/profiles_test.go` or `internal/config/workflow_profiles_test.go` -- Add tests

## Brownfield Context

### Existing Files to Read Before Implementing

- `internal/init/profiles/advanced.json` -- Contains existing epic_workflow/feature_workflow/task_workflow sections; follow same structure
- `internal/init/profiles/basic.json` -- Simpler version of profile; add corresponding simplified sections
- `internal/config/workflow_parser.go` -- Verify how JSON keys map to MultiLevelWorkflow struct fields

### Patterns to Follow

- JSON section structure: status_flow_version, status_flow, status_metadata, special_statuses
- Advanced profile includes agent_type assignments; basic profile omits them

### Integration Surface

- Profile application goes through the config merger which copies all JSON keys to `.sharkconfig.json`
- `GetProfileMap()` loads the JSON into `map[string]interface{}` -- new keys are handled automatically

### Scope Boundary

- DO NOT modify the profile loading mechanism or config merger logic
- DO NOT modify existing epic/feature/task workflow sections in either profile

## Validation Gates

- JSON validity: both profile files parse without error
- Key presence: bug_workflow and change_workflow exist in both profiles
- Round-trip: apply profile, reload, verify GetWorkflowForLevel("bug") returns profile-defined (not default) workflow
- Preservation: diff existing sections before/after adding new sections

## Notes for Agent

- The advanced profile bug_workflow status metadata values should match DefaultBugWorkflow() specification
- The basic profile should have simplified workflows (fewer agent assignments)
