# Task: Database Schema Creation and entity_notes Migration

## Goal

Create the `bugs` and `change_cards` database tables with all columns, indexes, constraints, and triggers via the auto-migration system in `internal/db/db.go`. Migrate the `entity_notes` table to remove the CHECK constraint on `entity_type` so notes can be attached to bugs and change-cards. This task has no dependency on the workflow engine tasks and can run in parallel with Tasks 001/002.

## Success Criteria

- [ ] `bugs` table created with 12 columns including severity CHECK constraint and all 5 indexes
- [ ] `change_cards` table created with 11 columns and all 4 indexes
- [ ] Both tables have updated_at triggers
- [ ] `entity_notes` CHECK constraint on entity_type is removed
- [ ] After migration, inserting entity_notes with entity_type 'bug' or 'change' succeeds
- [ ] All existing entity_notes data preserved after migration (epic, feature, task notes intact)
- [ ] entity_notes indexes and cascade delete triggers recreated after migration
- [ ] Migration is idempotent -- running InitDB() twice causes no errors
- [ ] All changes use CREATE TABLE/INDEX IF NOT EXISTS (safe for fresh and existing databases)
- [ ] `make fmt && make lint && make test` passes

## Implementation Guidance

All database changes go in `internal/db/db.go`. Follow the `ideas` table creation pattern (lines ~337-370) for the new tables. The entity_notes migration uses a table-recreation approach since SQLite does not support ALTER TABLE DROP CONSTRAINT.

See [Data Design - Section 1](../03-data-design.md#1-new-tables) for complete table schemas, column details, indexes, and triggers. See [Data Design - Section 2](../03-data-design.md#2-entity_notes-table-migration) for the full migration strategy including idempotency check, table recreation steps, and indexes/triggers to recreate.

### Patterns to Follow

- `CREATE TABLE IF NOT EXISTS` for all new tables (idempotent)
- `CREATE INDEX IF NOT EXISTS` for all indexes
- `CREATE TRIGGER IF NOT EXISTS` for updated_at triggers
- Migration idempotency check via sqlite_master query before table recreation

### Integration Surface

- entity_notes migration must preserve existing cascade delete triggers for tasks, features, epics
- New tables are standalone (no foreign keys to existing tables)
