- A `bugCmd` parent Cobra command
- 10 subcommand stubs with proper `Use`, `Short`, `Args`, and `RunE` fields
- Package-level flag variable declarations

## Blockers

### B1 — Wrong file name

**Spec requires:** `internal/cli/commands/bug.go`
**Actual file:** `internal/cli/commands/bug_commands.go`

The spec (architecture doc `02-architecture.md`) explicitly states the file change is `internal/cli/commands/bug.go (NEW)`. The naming convention for all other entity command files in this package is consistent: `task.go`, `feature.go`, `epic.go`, `change_card.go`. The file must be renamed to `bug.go`.

### B2 — No Cobra command variables declared

The file contains zero Cobra command variable declarations. There is no `bugCmd`, no `bugCreateCmd`, no `bugGetCmd`, etc. Without these, the commands cannot be registered in Cobra and are inaccessible to the CLI user.

Expected (from spec and architecture doc):
```go
var bugCmd = &cobra.Command{
    Use:   "bug",
    Short: "Manage bugs",
    GroupID: "advanced",
}

var bugCreateCmd = &cobra.Command{
    Use:   "create",
    Short: "Create a new bug",
    Args:  cobra.NoArgs,
    RunE:  runBugCreate,
}
// ... plus 9 more subcommands
```

### B3 — No `init()` function; commands not registered

The file has no `init()` function. Without `init()`, no commands are added to `RootCmd` or to `bugCmd`. The three implemented handler functions (`runBugGet`, `runBugCreate`, `runBugDelete`) are unreachable dead code.

Expected:
```go
func init() {
    // Register flags on subcommands
    bugCreateCmd.Flags().StringVar(...)
    // ...

    // Add subcommands to parent
    bugCmd.AddCommand(bugCreateCmd, bugGetCmd, bugListCmd, ...)

    // Add parent to root
    cli.RootCmd.AddCommand(bugCmd)
}
```

### B4 — No package-level flag variable declarations

All flag variables must be declared at package scope so they are accessible from both `init()` (for registration) and handler functions (for reading). The implementation inlines all `cmd.Flags().GetString(...)` calls inside handlers with no pre-declared variables.

This violates the project convention visible in `task.go`, `feature.go`, and all other command files.

### B5 — `GetBugService()` missing from `internal/cli/service_accessors.go`

The task explicitly requires adding `GetBugService()` to `internal/cli/service_accessors.go`. This function is absent. Without it, all bug command handlers that need the service would have no standard way to obtain one.

Required addition:
```go
func GetBugService() *services.BugService {
    db, err := GetDB(context.Background())
    if err != nil {
        panic(fmt.Sprintf("failed to get database: %v", err))
    }
    bugRepo := repository.NewBugRepository(db)
    workflowSvc := GetWorkflowService()
    return services.NewBugService(bugRepo, workflowSvc, nil, nil, nil)
}
```

Note: The actual `NewBugService` constructor takes 5 params (repo, workflowSvc, epicRepo, featureRepo, taskRepo), so the accessor needs to reflect the actual signature. The optional repo params can be passed as nil for the CLI use case.

### B6 — Subcommand stubs missing (8 of 10)

The scaffolding task requires 10 subcommand stubs. Only partial handler functions exist for 3 (create, get, delete). The following are completely absent:
- `runBugList` / `bugListCmd`
- `runBugUpdate` / `bugUpdateCmd`
- `runBugTriage` / `bugTriageCmd`
- `runBugNoteAdd` / `bugNoteAddCmd`
- `runBugNotes` / `bugNotesCmd`
- `runBugContextSet` / `bugContextSetCmd`
- `runBugContextGet` / `bugContextGetCmd`
- `runBugContextClear` / `bugContextClearCmd`

## Principle of Least Surprise Violations

A developer looking at the `internal/cli/commands/` directory would expect `bug.go` (matching `task.go`, `feature.go`, etc.). Finding `bug_commands.go` is surprising and breaks the established naming convention.

A developer running `shark bug --help` would get "unknown command" because the command is never registered. This is the worst possible outcome for a scaffolding task — the feature is invisible to users.
