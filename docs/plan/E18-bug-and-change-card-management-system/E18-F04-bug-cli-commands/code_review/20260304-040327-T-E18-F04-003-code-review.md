## Blockers

### B1 — `runBugTriage` not implemented

The triage handler does not exist in `internal/cli/commands/bug_commands.go` (the current file) or anywhere else in the codebase.

Acceptance criteria from T-E18-F04-003:
- Handler calls `svc.TriageBug(ctx, key, TriageBugInput{Severity: severity, Assign: assign})`
- `--severity` flag is required
- `--assign` flag is optional
- Outputs: success message with new bug status, or error on failure

Status: NOT MET — zero implementation exists.

### B2 — `bugTriageCmd` Cobra command not declared

There is no `bugTriageCmd` variable in any file. Without this, `shark bug triage` is not a registered command.

### B3 — Service method mismatch

The task spec and API contracts reference `svc.TriageBug(ctx, key, TriageBugInput{...})`. The actual `BugService` in `internal/services/bug_service.go` does NOT have a `TriageBug` method. It has `AdvanceBugStatus` and `SetBugStatus` instead.

This is a service-layer gap that must be resolved before this task can be completed:

**Option A:** Add `TriageBug(ctx, key, TriageBugInput) (*models.Bug, error)` to `BugService` that sets severity and optionally assigns the bug before transitioning status to "triaged"

**Option B:** Revise the CLI handler to call `svc.SetBugStatus(ctx, key, "triaged")` and separately call a severity update via `svc.UpdateBug(ctx, key, BugUpdates{Severity: &severity})` — but this is a two-step operation that should be atomic at the service level

The developer must clarify with the architect/product owner which approach is correct, then implement accordingly.

### B4 — `TriageBugInput` DTO not defined in service layer

The API contracts define a `TriageBugInput` struct:
```go
type TriageBugInput struct {
    Severity string  // required
    Assign   *string // optional
}
```

This DTO does not exist in `internal/services/bug_dto.go`. It must be added as part of this task or as a prerequisite service-layer fix.
