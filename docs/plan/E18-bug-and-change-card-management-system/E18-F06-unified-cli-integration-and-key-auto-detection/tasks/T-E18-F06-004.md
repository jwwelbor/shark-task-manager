# Task: Search Extension for Bugs and Change-Cards

## Goal

Extend the search command and repository to include bugs and change-cards in full-text search results, and add `--type=bug` and `--type=change` as valid filter values. After this task, `shark search "login"` returns matching bugs and change-cards alongside existing entity types, and `shark search "login" --type=bug` filters to bugs only.

## Success Criteria

- [ ] `shark search "login"` returns matching bugs and change-cards alongside epics, features, and tasks
- [ ] `shark search "login" --type=bug` returns only bug results
- [ ] `shark search "dark mode" --type=change` returns only change-card results
- [ ] Bug search results include: key, title, status, severity
- [ ] Change-card search results include: key, title, status (no severity)
- [ ] `shark search "query" --type=invalid` returns error listing valid types including "bug" and "change"
- [ ] `shark search "query" --json` returns structured JSON results for all entity types
- [ ] Empty search returns gracefully (no error, empty results)
- [ ] `make fmt && make lint && make test` passes with zero failures

## Implementation Guidance

This task covers architecture dispatch points #21-22 and is the most complex task in F06. The current search.go implements file-based search only. This task adds a full-text query mode.

### Key Requirements

- Extend search command per [Architecture - Section 9](../02-architecture.md#9-search-architecture)
- Support dual mode: `--file` for existing file search, positional argument for full-text query
- Create or extend SearchRepository with cross-entity UNION query per [Architecture - Section 9.3](../02-architecture.md#93-full-text-search-implementation)
- Validate `--type` flag: valid values are epic, feature, task, bug, change per [Architecture - Section 9.4](../02-architecture.md#94---type-flag-validation)
- Covers PRD requirements F06-REQ-013 and F06-REQ-014

### Files to Create/Modify

- `internal/cli/commands/search.go` -- extend to support positional query argument and --type flag
- `internal/repository/search_repository.go` -- new or extended with SearchAll() method
- `internal/repository/search_repository_test.go` -- repository tests with real DB
- `internal/cli/commands/search_test.go` -- command tests with mocked services

## Brownfield Context

### Existing Files to Read Before Implementing
- `internal/cli/commands/search.go` -- current file-based search implementation
- `internal/repository/` -- existing repository patterns for UNION queries

### Patterns to Follow
- Search result struct follows existing models pattern with json tags
- Repository uses SQLite LIKE for basic search (FTS5 optimization is optional)
- Command follows thin-wrapper pattern: parse args, call service/repo, format output

### Integration Surface
- SearchRepository needs access to bugs and change_cards tables (created by F01)
- Results must include entity_type field to distinguish result types
- JSON output must include severity for bugs, omit it for other types

### Scope Boundary
- DO NOT implement FTS5 indexing as a hard requirement -- LIKE-based search is acceptable for initial implementation
- DO NOT modify the existing `--file` search mode -- add the new query mode alongside it
- DO NOT change the search results format for existing entity types (epic, feature, task)

## Validation Gates

- Repository tests verify cross-entity search returns correct results
- Type filter correctly includes/excludes entity types
- Invalid type values produce clear error with valid options list
- Empty query returns empty results without error
- `make fmt && make lint && make test` passes

## Notes for Agent

- This is the most complex task in F06 -- if timeline pressure exists, implement LIKE-based search first
- The SearchResult struct needs a Severity field that is populated only for bugs (omitempty in JSON)
- The --type flag value "change" (not "change-card") per ADR-F06-003
- Consider whether SearchRepository should be a new file or extend an existing repository
