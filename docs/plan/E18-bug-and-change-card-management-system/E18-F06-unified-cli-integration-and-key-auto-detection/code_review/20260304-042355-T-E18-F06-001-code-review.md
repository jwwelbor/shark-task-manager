## Success Criteria Verification

### 1. keys.EntityTypeBug and keys.EntityTypeChange constants defined
**Status: PASS**

Both constants are present in `internal/keys/service.go`:
```go
EntityTypeBug    = "bug"
EntityTypeChange = "change"
```

### 2. keys.IsBugKey() and keys.IsChangeKey() implemented in validation.go
**Status: PASS**

Both functions are present in `internal/keys/validation.go` with appropriate regex patterns:
- `bugKeyPattern = regexp.MustCompile("^B\\d+$")` (case-insensitive after Normalize)
- `changeKeyPattern = regexp.MustCompile("^C\\d+$")`
- Both correctly call `Normalize(s)` before pattern matching for case insensitivity

### 3. scope.ParseScope returns ScopeBug for B### input and ScopeChange for C### input
**Status: PASS**

`internal/cli/scope/interpreter.go` `parseGetArgsLogic()` returns `"bug"` for `IsBugKey()` matches and `"change"` for `IsChangeKey()` matches. The `ParseScope()` switch correctly maps these to `ScopeBug` and `ScopeChange` respectively.

### 4. ScopeBug and ScopeChange constants defined in scope/types.go
**Status: PASS**

Both constants are present in `internal/cli/scope/types.go`:
```go
ScopeBug    ScopeType = "bug"
ScopeChange ScopeType = "change"
```

### 5. models.EntityTypeBug and models.EntityTypeChange constants defined
**Status: PASS**

Both constants are present in `internal/models/entity_note.go`:
```go
EntityTypeBug    EntityType = "bug"
EntityTypeChange EntityType = "change"
```

### 6. models.ValidEntityTypes map includes bug and change entries
**Status: PASS**

The `ValidEntityTypes` map in `internal/models/entity_note.go` includes:
```go
EntityTypeChange: true,
EntityTypeBug:    true,
```

### 7. commands.DetectEntityType returns "bug" for B### and "change" for C### keys
**Status: PASS**

`internal/cli/commands/helpers.go` `DetectEntityType()` checks `IsBugKey(normalized)` returning `"bug"` and `IsChangeKey(normalized)` returning `"change"`. The bug/change checks occur before epic checks, which is the correct ordering since `B###` and `C###` could otherwise be misidentified.

### 8. Case-insensitive key handling (b001 normalizes to B001)
**Status: PASS**

Normalization is applied via `strings.ToUpper()` in `Normalize()` before all pattern matching. Both `IsBugKey` and `IsChangeKey` in both packages call `Normalize()` before matching.
