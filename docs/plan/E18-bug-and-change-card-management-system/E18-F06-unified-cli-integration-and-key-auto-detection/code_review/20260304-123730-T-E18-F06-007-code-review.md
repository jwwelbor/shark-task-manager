## Finding: FR-005 Non-Compliance — Stale Gap Documentation

**Severity**: Required fix (per spec FR-005)

**Location**: `internal/cli/commands/e18_dispatch_gaps_test.go`

**Issue**: The task spec FR-005 states:

> "TestGAP001 and TestGAP002 in `e18_dispatch_gaps_test.go` MUST be updated to
> remove the FIX REQUIRED log messages and `knownGap` constants."

The following stale content remains unchanged:

1. **File header comment block (lines 7-22)** still reads "KNOWN GAPS (to be fixed
   in a follow-up task):" and lists all 4 gaps as outstanding. This is incorrect —
   all 4 gaps are now fixed in this task.

2. **`TestGAP001_DeleteDispatch_ChangeEntityTypeFallsThrough`** (lines 199-225):
   - Still contains `const knownGapDispatchDelete = "GAP-001: delete_dispatch.go missing case \"change\""`
   - Still logs `t.Logf("FIX: add case \"change\" to dispatchDelete() in delete_dispatch.go")`
   - These messages now appear in test output describing work that is already done.

3. **`TestGAP002_StatusGroup_ChangeEntityTypeFallsThrough`** (lines 234-263):
   - Still contains `knownGap2`, `knownGap3`, `knownGap4` constants describing
     gaps as present in the codebase.
   - Still logs `t.Logf("FIX: add case \"change\": to dispatchTransition, ...")`
   - Again, this work is now complete.

4. **`TestDispatchInventory_FullStatus`** (lines 387-457) IS correctly updated —
   entries #2, #4, #5 show "HANDLED" with fix notes. This is correct.

**Principle of Least Surprise violation**: Future developers running `go test -v`
will see these "FIX REQUIRED" and "GAP" messages in the output and reasonably
conclude the code is still broken. This directly contradicts the intent of test
output as documentation.

**Required action**: Update `e18_dispatch_gaps_test.go` to:
1. Replace the file header comment block with a resolved-gaps summary
2. Convert `TestGAP001_DeleteDispatch_ChangeEntityTypeFallsThrough` to document
   the gap as resolved (remove "FIX REQUIRED" log, replace `knownGapDispatchDelete`
   constant with a resolved-gap comment or remove the constant)
3. Convert `TestGAP002_StatusGroup_ChangeEntityTypeFallsThrough` similarly

The tests do not need to be deleted — they can document that the gaps were once
present and are now fixed. The "FIX REQUIRED" action items must be removed.
