## Code Quality Assessment

### render_common.go — displayEntityTypeName()

The function is clean, appropriately narrow in scope, and follows the principle of least surprise. Using a `switch` statement for explicit mapping is the correct choice over string manipulation, since the "change" → "Change Card" mapping is non-obvious and cannot be derived mechanically.

```go
func displayEntityTypeName(entityType string) string {
    switch entityType {
    case "bug":
        return "Bug"
    case "change":
        return "Change Card"
    default:
        return capitalize(entityType)
    }
}
```

The `default` branch preserving `capitalize()` behavior ensures backward compatibility for existing entity types (epic, feature, task).

`renderHeader()` correctly delegates to `displayEntityTypeName()`. The separation of concerns is correct.

### errors.go — NotFoundError()

The two new switch cases are consistent with existing cases in style and structure. Suggestion text is actionable and includes key format hints. The dual-case `"change card", "change":` grouping handles both the internal entity-type string and the display string gracefully.

### helpers.go — B/C prefix detection

Wrapper functions `IsBugKey()`, `IsChangeKey()`, and `IsChangeCardKey()` correctly delegate to the `keys` package, keeping the helper layer thin. The error message additions for B-prefix and C-prefix invalid keys are consistent in format with existing error messages for other entity prefixes.

`DetectEntityType()` correctly uses `IsChangeKey()` (C### format) for the change entity and `IsChangeCardKey()` (CC-### format) for the change card entity.

`ParseScope()` only checks `IsChangeCardKey()`, not `IsChangeKey()`. This is pre-existing behavior under T-E18-F06-002 scope. It is confirmed out-of-scope here and does not constitute a defect for this task.

### notes_search.go

Single-line addition. Correct and complete. The entity type list is now consistent with supported entity types.

## Test Assessment

### display_entity_type_test.go

The test file is correctly placed in the CLI commands package, uses no real database, and tests presentation-layer behavior in isolation — consistent with the testing architecture rules.

**TestDisplayEntityTypeName** — table-driven with 7 cases covering the explicit mappings ("bug", "change") and the default path (epic, feature, task, empty string, unknown). This is thorough coverage of the function under review.

**TestRenderHeaderBug / TestRenderHeaderChange** — verify that `renderHeader()` does not panic for the new entity types. These are smoke tests. They confirm the integration between `renderHeader` and `displayEntityTypeName` without needing to capture stdout, which is appropriate for the scope.

**TestNotFoundErrorBug / TestNotFoundErrorChange** — assert the error string contains the correct entity name and key. The assertions correctly verify that old entity-type strings ("task not found") are absent, which confirms the switch case is being hit.

**TestInvalidKeyFormatErrorIncludesBugAndChange** — 3 sub-cases covering B-prefix, C-prefix, and generic unknown-prefix scenarios. The tests call the internal helper function `invalidKeyFormatError()` directly. This tests real production code paths.

**TestNoteSearchErrorIncludesBugAndChange** — constructs the expected string manually and asserts it matches `fmt.Sprintf(...)` directly. This does not call `notes_search.go` code. The test verifies `notes_search.go` only indirectly via `strings.Contains()` on a manually composed string. While the test passes, it would pass even if `notes_search.go` had not been modified, since it tests the string itself rather than the function.

This is a minor weakness. The test does not block approval because the actual code change in `notes_search.go` has been verified by inspection and the test suite as a whole passes.

**TestHandleServiceErrorBugDisplayType** — documents a known gap: `handleServiceError()` uses naive `capitalize()` rather than `displayEntityTypeName()`, so "change" would display as "Change" rather than "Change Card" in that specific code path. The test guards the current behavior of `displayEntityTypeName` and documents the limitation with a comment. This is appropriate for a scoped task that explicitly excludes service error rendering.

## Pre-Existing Issues Noted (Out of Scope)

These items are documented for awareness but do not block approval of this task:

1. **ParseScope missing IsChangeKey (C###) check** — `ParseScope` in `helpers.go` handles `CC-###` (change cards) but not `C###` (change entities). `shark get C001` would not dispatch as a change entity through the `ParseScope`/`ParseGetArgs` code path. This is the responsibility of T-E18-F06-002 (dispatch routing), currently `in_development`.

2. **handleServiceError uses naive capitalize** — `handleServiceError()` in `helpers.go` uses `strings.ToUpper(entityType[:1]) + entityType[1:]` rather than `displayEntityTypeName()`. This means "change" appears as "Change" rather than "Change Card" in service-layer error paths. Documented in `TestHandleServiceErrorBugDisplayType` comment. Should be addressed in a follow-up task.
