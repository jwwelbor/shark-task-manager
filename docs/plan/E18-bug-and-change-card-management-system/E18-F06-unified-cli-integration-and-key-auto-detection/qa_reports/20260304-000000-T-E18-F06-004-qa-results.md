## Implementation Notes

### FTS5 Availability

The test environment does not have the SQLite FTS5 module compiled in:
```
Warning: FTS5 not available, skipping full-text search table: no such module: fts5
```
This is expected and acceptable. The task spec explicitly states "LIKE-based search is acceptable for initial implementation." The `SearchAll()` function uses LIKE-based pattern matching (`%query%`) which works correctly without FTS5.

### Change-Card Key Format in Test Seeds

`search_all_test.go` seeds change-cards with key `"CC-001"`. The feature spec defines change-card keys as `C###` format (e.g., C001). This discrepancy is in the test fixture only and does not affect search correctness, since search matches on title/description content, not key format. The key validation is handled by the keys service layer, not the search repository.

This is a minor test data consistency concern (not a defect) - the search functionality is correct regardless.

### Architecture Compliance

`search.go` calls `repository.SearchRepository` directly (bypassing the service layer). A comment in the code acknowledges this as a legacy pattern acceptable for the search command which has no business logic beyond query validation. This is consistent with existing patterns in the codebase.
