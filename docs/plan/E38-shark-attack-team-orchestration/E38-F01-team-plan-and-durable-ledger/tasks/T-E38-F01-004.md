# Implement ledger service and bounded result validation

## Goal
Implement the domain service that atomically confirms a plan, exposes run/items, enforces lifecycle and idempotency rules, and accepts only bounded safe item evidence.

## Scope
- Create: `internal/team/ledger_service.go`, `internal/team/ledger_service_test.go`, `internal/team/models_test.go`
- Use: `internal/repository/teamrun/repository.go` and the planner domain types from the preceding tasks

## Acceptance Criteria
- See `spec.md` AC-F01-006, AC-F01-007, AC-F01-008, and AC-F01-009; NFR-004, NFR-005, and NFR-006.
- See `test-plan.md` TC-006, TC-007, TC-008, TC-009, TC-012, TC-014, and TC-015.
- Confirmed-plan persistence inserts the complete run before any future claim, retries safely, returns the existing run for the same root/hash, and returns typed drift/conflict errors for incompatible repeats.
