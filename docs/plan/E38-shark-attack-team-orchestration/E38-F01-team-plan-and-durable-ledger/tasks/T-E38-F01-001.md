# Extract shared dispatch-step resolution

## Goal
Create the service-level metadata seam that lets `next`, `run`, and the team planner use one canonical workflow/prompt resolution path without persisting prompts or coupling team code to Cobra.

## Scope
- Modify: `internal/cli/commands/next.go`, `internal/cli/commands/run.go`
- Create: `internal/dispatch/step.go`, `internal/dispatch/step_test.go`
- Modify tests: `internal/cli/commands/next_test.go`, `internal/cli/commands/run_test.go`

## Acceptance Criteria
- See `spec.md` AC-F01-010.
- See `test-plan.md` TC-010 and the caller-path contract for the actual Cobra invocations.
- The shared result exposes resolved action, role/agent, provider, model, effort, gate classification, and placeholder diagnostics while keeping rendered prompts transient.
- Existing `next` and `run` response, prompt, ownership, and status behavior remains unchanged.

## Test Cases
Implement tests first, then satisfy `test-plan.md` TC-010, including task/feature/approval, unresolved placeholder, terminal, and provider-failure cases.

## Integration Contracts
No cross-feature or cross-epic contract is produced or consumed by this task.

## Design Reference
Use `spec.md` Architecture: Component changes and API/interface contracts; use `research.md` §§1.4 and 4 for the canonical resolution seam. The broader child snapshot/cascade seam is owned by T003.

## Brownfield Context
Extend the existing `next.go`/`run.go` routing and runner seams; preserve ordinary single-worker behavior and keep business logic out of CLI wrappers.

## Notes for Agent
Do not rebuild prompt assembly, invoke Cobra recursively, mutate claims/status, or store prompt text in team-domain values. Follow the service and testing rules in the repository guidance.
