# Task: Write migration tests: schema version 18, idempotency, all indexes/triggers, cascade deletes, no entity_type CHECK (sprint_tables_migration_test.go)

## Goal

Create `internal/db/sprint_tables_migration_test.go` covering all 11 migration-level tests from spec §6.1. These are repository-style integration tests that use `test.GetTestDB()` and query `sqlite_master` to verify schema structure. They are the primary safety net for the highest-risk change in this feature (schema migration).

## Acceptance Criteria

Tests present and passing (use real test DB per repository testing rules):

- [ ] `TestMigrateSprintTables_CreatesAllThreeTables` — queries `sqlite_master WHERE type='table'` to confirm `sprints`, `sprint_assignments`, `sprint_capacity` all exist.
- [ ] `TestMigrateSprintTables_Idempotent` — runs `migrateSprintTables` twice on the same DB; asserts no error on second call and table/index counts are identical.
- [ ] `TestMigrateSprintTables_CreatesAllIndexes` — queries `sqlite_master WHERE type='index'` to confirm all seven index names exist: `idx_sprints_key`, `idx_sprints_status`, `idx_sprints_slug`, `idx_sprint_assignments_sprint`, `idx_sprint_assignments_entity`, `idx_sprint_assignments_active_one`, `idx_sprint_capacity_sprint`.
- [ ] `TestMigrateSprintTables_PartialUniqueIndex` — inserts two `sprint_assignments` rows with same `(entity_type, entity_id)` and `removed_at IS NULL`; expects `UNIQUE constraint failed` error. Then inserts with one row's `removed_at` set; expects success.
- [ ] `TestMigrateSprintTables_StartEndDateCheck` — inserts a sprint with `start_date='2026-04-01', end_date='2026-03-18'`; expects `CHECK constraint failed` error.
- [ ] `TestMigrateSprintTables_CascadeDeleteFromTask` — inserts a sprint + sprint_assignment for a task, deletes the task row, asserts 0 rows remain in `sprint_assignments`.
- [ ] `TestMigrateSprintTables_CascadeDeleteFromBug` — same pattern for `bugs` table.
- [ ] `TestMigrateSprintTables_CascadeDeleteFromChangeCard` — same pattern for `change_cards` table.
- [ ] `TestMigrateSprintTables_CascadeDeleteFromTechDebt` — same pattern for `tech_debts` table.
- [ ] `TestMigrateSprintTables_NoEntityTypeCheckConstraint` — inserts a `sprint_assignments` row with `entity_type='whatever'`; asserts NO error (confirms the post-B018 convention: entity_type validation is app-layer only).
- [ ] `TestSchemaVersionBumpedTo18` — calls `ApplySchemaAndMigrations` on a fresh test DB; asserts `getSchemaVersion(db) == 18`.
- [ ] `make test ./internal/db/...` passes with all new tests green.

## Implementation Notes

- Mirror `internal/db/entity_notes_migration_test.go` and `internal/db/change_cards_table_test.go` for file structure and `sqlite_master` query patterns.
- Tests use `test.GetTestDB()` (real DB) — clean up inserted rows after each test with `defer` or explicit DELETE to avoid cross-test pollution.
- For cascade-delete tests: use existing seeded epic/feature/task/bug/change_card/tech_debt rows from `test.SeedTestData()` where possible, or insert minimal fixture rows.
- `getSchemaVersion` is an unexported helper in `db.go` — test file must be in `package db` (same package) to access it, or call the exported `ApplySchemaAndMigrations` and infer from side effects.
