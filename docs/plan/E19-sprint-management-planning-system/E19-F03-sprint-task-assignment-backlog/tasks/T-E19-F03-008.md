## UAT Rejection (2026-05-06)

**Unmet AC IDs:** AC-12 (spec.md §1.2 REQ-F-006: "Default carryover behavior is read from `.sharkconfig.json`")

**Classification:** AC Violation — spec was clear, implementation missed the production config load wiring.

**Required Fix:**

1. Add a `sprint_defaults` parsing block to `Manager.Load()` in `internal/config/manager.go`. The block must read `rawData["sprint_defaults"]` and populate `config.SprintDefaults`. Pattern to follow: the `maintainer` and `tag_required_for` blocks already in the same function.

   Specifically, parse `carryover_behavior` (string) and `capacity` (map[string]float64) from the nested object. Example skeleton:
   ```go
   if sprintDefaultsRaw, ok := rawData["sprint_defaults"].(map[string]interface{}); ok {
       sd := &SprintDefaultsConfig{}
       if cb, ok := sprintDefaultsRaw["carryover_behavior"].(string); ok {
           sd.CarryoverBehavior = cb
       }
       if cap, ok := sprintDefaultsRaw["capacity"].(map[string]interface{}); ok {
           sd.Capacity = make(map[string]float64)
           for k, v := range cap {
               if f, ok := v.(float64); ok {
                   sd.Capacity[k] = f
               }
           }
       }
       config.SprintDefaults = sd
   }
   ```

2. Add a `Manager.Load()` integration test in `internal/config/config_test.go` (or a new `manager_test.go`) that:
   - Creates a real `.sharkconfig.json` file with `sprint_defaults.carryover_behavior = "backlog"`
   - Calls `Manager.Load()` (not `json.Unmarshal`)
   - Asserts `Config.SprintDefaults.CarryoverBehavior == "backlog"`

**Secondary (non-blocking, fix in same PR):** The comment on `SprintDefaultsConfig.CarryoverBehavior` says "Default: backlog when absent" but `resolveCarryoverMode()` defaults to `CarryoverNext` ("next"). Correct the comment to match the code behavior.
