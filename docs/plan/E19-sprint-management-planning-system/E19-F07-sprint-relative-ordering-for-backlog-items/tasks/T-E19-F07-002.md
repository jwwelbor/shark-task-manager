# SprintAssignment Model: add SprintOrder field and repo query methods

## Goal
Add `SprintOrder *int` to the `SprintAssignment` struct and update every SCAN/INSERT
in the sprint repository to include the new column. Add four new repository methods
(`SetSprintOrderTx`, `RenumberAssignmentsTx`, `MaxSprintOrder`,
`ListOrderedAssignments`) that service methods will depend on. Also update
`ListBacklog`'s UNION-ALL to project `sa.sprint_order` and update `BulkAssign` to
accept per-row `sprint_order` values.

## Scope
- Files to modify:
  - `internal/models/sprint.go` — add `SprintOrder *int` field to `SprintAssignment`
  - `internal/repository/sprint/repository.go` — update column lists in
    `AddAssignment`, `GetActiveAssignment`, `ListAssignments`,
    `ListAssignmentsForCarryover`, `ListBacklog`, `BulkAssign`; add four new methods
    and `RenumberOp` type
- Files to create:
  - additions to `internal/repository/sprint/repository_test.go` — tests for new
    methods and updated SCAN paths (real DB test pattern)

## Acceptance Criteria
See spec.md §3.1 (model change), §3.2 (new repo method signatures), §3.3 component
table row for `internal/repository/sprint/repository.go`.
Additional task-specific criteria:
- AC-T1: `SprintAssignment.Validate()` is NOT changed (SprintOrder validation is
  service-level per spec §3.1)
- AC-T2: `RenumberAssignmentsTx` uses a single CASE WHEN UPDATE, not a loop
- AC-T3: `MaxSprintOrder` returns 0 (not error) when no ordered items exist

## Test Cases
See test-plan.md TC-011 (MaxSprintOrder returns 0 for empty sprint), TC-028
(idempotent migration via repo layer), and repository section of Test Infrastructure.
Write failing tests for each new method first, then implement.

## Design Reference
See spec.md §3.1 model change snippet and §3.2 new repository method signatures.
See spec.md §3.3 `BulkAssign` update note. The `RenumberOp` type is also defined in
§3.2.
