# Service: AddEntityToSprint with --at position and sprint_order auto-assign

## Goal
Extend `AddEntityInput` DTO with an optional `Position *int` field and update
`SprintService.AddEntityToSprint` to (a) auto-assign `sprint_order = max + 1` when
Position is nil, (b) insert at Position N and shift existing items when Position is
set, (c) validate position range, and (d) update `BulkAddToSprint` to auto-number
bulk rows with post-insert dense-renumber for gaps from `INSERT OR IGNORE`.

## Scope
- Files to modify:
  - `internal/services/sprint_service.go` — update `AddEntityInput` struct, update
    `AddEntityToSprint`, update `BulkAddToSprint` (§3.6 bulk-add interaction)
- Files to create/extend:
  - `internal/services/sprint_service_test.go` — table-driven tests for TC-005
    through TC-012 using `MockSprintRepository`

## Acceptance Criteria
See spec.md §1.3 REQ-F-002 ACs and §3.2 `AddEntityInput` DTO definition.
Additional task-specific criteria:
- AC-T1: `Position *int` reaches service as nil (not defaulted in CLI); service
  detects presence via nil check, not CLI flag (developer note from test-plan.md §3)
- AC-T2: Shift/renumber inside a service-owned transaction (spec §3.9 TD-9)
- AC-T3: `--at` mutually exclusive with bulk flags validated at service level
  (returns error before any repo call)
- AC-T4: BulkAddToSprint assigns sequential `sprint_order` per row, then calls
  `RenumberAssignmentsTx` to repair gaps from skipped duplicates

## Test Cases
See test-plan.md TC-005 (at=1 shifts), TC-006 (at=count+1 valid), TC-007
(at=count+2 out-of-range), TC-008 (at=0 invalid), TC-009 (at=-N invalid), TC-010
(nil=append), TC-011 (empty sprint → position 1), TC-012 (bulk-add gap repair).
All tests use MockSprintRepository, no real DB.
