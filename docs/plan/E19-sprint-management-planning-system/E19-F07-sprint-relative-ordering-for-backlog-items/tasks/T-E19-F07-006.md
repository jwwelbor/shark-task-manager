# CLI: sprint add --at flag, sprint reorder command, backlog --view flag

## Goal
Wire three new CLI surfaces: (1) `--at=<int>` flag on `sprintAddCmd` piped into
`AddEntityInput.Position`, with mutual-exclusion validation against bulk flags; (2)
new `sprintReorderCmd` (`shark sprint reorder <sprint> <entity> [<position>]
[--top] [--bottom]`) registered under `sprintCmd`; (3) `--view=ordered|grouped` and
`--include-completed` flags on `sprintBacklogCmd` with active-sprint default. All
three are thin wrappers calling service methods via `sprintAssignmentServicer`.

## Scope
- Files to modify:
  - `internal/cli/commands/sprint.go` — add `--at` flag to `sprintAddCmd`; add
    `sprintReorderCmd` with `--top`/`--bottom` flags and `MarkFlagsMutuallyExclusive`;
    add `--view` and `--include-completed` to `sprintBacklogCmd`; register
    `sprintReorderCmd` in `init()`; update `sprintAssignmentServicer` interface to
    include `ReorderAssignment`
- Files to create/extend:
  - `internal/cli/commands/sprint_test.go` — CLI tests for TC-014 (--top passes
    ReorderTarget.Top), TC-014b (sprint add --at --json includes sprint_order),
    TC-022 (close prints Order preserved: yes)

## Acceptance Criteria
See spec.md §1.3 REQ-F-002 ACs (--at), REQ-F-003 ACs (reorder command), REQ-F-005
ACs (backlog view), §3.3 component table rows for `internal/cli/commands/sprint.go`.
Additional task-specific criteria:
- AC-T1: `--at` detected via `cmd.Flags().Changed("at")` before dereferencing;
  nil passed to service when flag absent (dev note test-plan.md §3)
- AC-T2: `--top`, `--bottom`, and positional `<position>` are mutually exclusive
  (use `MarkFlagsMutuallyExclusive` or equivalent Cobra mechanism)
- AC-T3: Bulk flags (`--bulk`, `--bulk-bugs`, etc.) and `--at` mutually exclusive —
  returns error before service call
