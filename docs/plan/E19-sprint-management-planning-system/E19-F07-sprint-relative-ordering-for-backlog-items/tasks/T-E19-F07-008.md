# Integration and decoupling regression tests (multi-component)

## Goal
This task exists because TC-029 and TC-030 (decoupling regression tests) exercise
the boundary between `TaskService` and `SprintService` — both repos must be real (or
the cross-mutation is invisible to mocks). They cannot be co-located in a single
implementation task. Additionally, this task collects the new shared test helpers
(`intPtr`, `assertRenumberOps`, `runCLICommand`, `newTestDBWithSprintData`) and
verifies the full suite passes after all changes (`make test` exit 0, TC-027).

## Scope
- Files to create/extend:
  - `internal/services/sprint_decoupling_test.go` (new file) — TC-029 (task update
    does not change sprint_order) and TC-030 (sprint reorder does not change task
    priority/ExecutionOrder); uses real test DB for cross-service assertions
  - `internal/services/sprint_service_test.go` — add `intPtr`, `assertRenumberOps`
    test helpers if not already added in prior tasks
  - `internal/cli/commands/sprint_test.go` — extract `runCLICommand` helper if not
    already shared
  - `internal/db/sprint_tables_migration_test.go` — add
    `newTestDBWithSprintData` helper used across TC-025, TC-028, TC-029

## Acceptance Criteria
See spec.md §3.8 entity-level decoupling and §1.3 REQ-F-008 ACs.
Additional task-specific criteria:
- AC-T1: TC-029 uses real test DB (not mock) so `sprint_assignments.sprint_order`
  can be read back directly after a `TaskService` update
- AC-T2: TC-030 asserts mock `TaskRepository.Update` call count == 0 after
  `SprintService.ReorderAssignment`
- AC-T3: `make test` exits 0 after all E19-F07 changes; no existing tests broken

## Test Cases
See test-plan.md TC-029 (task update does not mutate sprint_order), TC-030 (sprint
reorder does not mutate entity priority/ExecutionOrder), TC-027 (full suite passes).
This task is a TDD exception: the "implementation" is test code itself, verifying
decoupling of two already-implemented components.
