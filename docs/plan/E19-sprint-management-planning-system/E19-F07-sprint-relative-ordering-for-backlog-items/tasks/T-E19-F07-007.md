# CLI: sprint next output, sprint start warning, sprint close carryover_preserved

## Goal
Update three existing CLI handlers with new display lines: (1) `runSprintNext` human
mode adds `Sprint position: N of K  |  Selected by: <reason>` and `Sprint: <key>`
lines after the existing task block; (2) `runSprintStart` emits the soft warning when
the service returns a non-zero NULL-order count; (3) `runSprintClose` prints `Order
preserved: yes|no` from `SprintCloseResult.CarryoverPreserved`. JSON mode is
unchanged for start warning per REQ-F-009.

## Scope
- Files to modify:
  - `internal/cli/commands/sprint.go` — update `runSprintNext` human output;
    update `runSprintStart` to read NULL-order count and print warning in non-JSON
    mode; update `runSprintClose` to print `Order preserved:` line from result
- Files to create/extend:
  - `internal/cli/commands/sprint_test.go` — CLI tests for TC-024 (start warning
    human vs JSON mode), TC-022 (close prints Order preserved)

## Acceptance Criteria
See spec.md §1.3 REQ-F-004 ACs (sprint next JSON), REQ-F-006 ACs (close output),
REQ-F-009 ACs (start warning), §3.5 CLI display changes.
Additional task-specific criteria:
- AC-T1: Warning line is omitted in `--json` mode for `sprint start` — JSON output
  does not include a `warning` key (REQ-F-009 last bullet)
- AC-T2: `Sprint position: N of K` uses candidates-after-agent-filter count, not
  total sprint backlog count (spec §3.5)
- AC-T3: `--field sprint_order` returns JSON literal `null` (exit 0) when selected
  item is unordered (REQ-F-004 last bullet)

## Test Cases
See test-plan.md TC-024 (four cells: NULL-count > 0 × human mode, NULL-count > 0 ×
JSON mode, count=0 × human, count=0 × JSON), TC-022 (stdout contains "Order
preserved: yes"), TC-015c (existing fields unchanged — additive contract).

## Design Reference
See spec.md §3.5 CLI display changes for exact human-mode format strings for all
three commands. See §1.3 REQ-F-004 for `sprint next` JSON field requirements.
