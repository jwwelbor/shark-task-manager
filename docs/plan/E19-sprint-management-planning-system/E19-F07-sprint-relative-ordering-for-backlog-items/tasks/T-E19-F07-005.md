# Service: ordered backlog view and carryover sprint_order renumbering

## Goal
Update `GetSprintBacklog` to support `--view=ordered` (Items array sorted by
`sprint_order ASC NULLS LAST`, with computed `position` dense rank) and default to
ordered view for active sprints. Update `CloseSprintWithCarryover` to append
carried-over items at `M+1..M+K` in the receiving sprint and set `CarryoverPreserved`
on the result. Update `DropAssignmentsTx` (carryover-to-backlog) to clear
`sprint_order` atomically. Add `SprintOrder` and `SprintKey` to `BacklogItemView`
and `CarryoverPreserved` to `SprintCloseResult`.

## Scope
- Files to modify:
  - `internal/services/sprint_service.go` — update `GetSprintBacklog` with view
    logic and `BacklogOptions.View`; update `CloseSprintWithCarryover` carryover-next
    and carryover-backlog branches; add `CarryoverPreserved` to `SprintCloseResult`;
    update `StartSprint` to count NULL sprint_order rows and return warning count
  - `internal/repository/sprint/repository.go` — update `DropAssignmentsTx` SQL to
    clear `sprint_order = NULL` in the same UPDATE as `removed_at`
- Files to create/extend:
  - `internal/services/sprint_service_test.go` — tests for TC-017 through TC-024
    using MockSprintRepository

## Acceptance Criteria
See spec.md §1.3 REQ-F-005, REQ-F-006, REQ-F-009 ACs, §3.2 `BacklogItemView`
and `SprintCloseResult` additions, §3.7 carryover renumbering logic.
Additional task-specific criteria:
- AC-T1: `position` is 1-based dense rank computed at view time; unordered items
  have `position` set but `sprint_order = nil` (they diverge — spec §3.2)
- AC-T2: `DropAssignmentsTx` clears `sprint_order` in the same UPDATE statement as
  `removed_at` (not a separate call — TC-023)
- AC-T3: Carried-over items sorted by `(sprint_order ASC NULLS LAST, assigned_at
  ASC, id ASC)` before renumbering from `M+1`
