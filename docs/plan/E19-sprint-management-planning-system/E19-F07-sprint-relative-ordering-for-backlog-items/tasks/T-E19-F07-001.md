# Schema Migration: add sprint_order column and backfill

## Goal
Add the nullable `sprint_order INTEGER` column to `sprint_assignments`, create the
partial unique index, and backfill planning/active sprints using `ROW_NUMBER()`. Bump
`CurrentSchemaVersion` from 19 to 20. This is the foundational DB change all other
tasks in this feature depend on.

## Scope
- Files to modify:
  - `internal/db/db.go` — add `migrateSprintAssignmentsAddSprintOrder`, wire into
    `runMigrations()`, bump `CurrentSchemaVersion` 19 → 20
- Files to create:
  - `internal/db/sprint_tables_migration_test.go` — real-DB migration integration
    tests (no mocks)

## Acceptance Criteria
See spec.md §1.3 REQ-F-007 ACs and §3.1 data model changes.
Additional task-specific criteria:
- AC-T1: Migration checks `pragma_table_info` before `ALTER TABLE` (idempotent,
  mirrors `migrateSlugColumns` pattern in `db.go`)
- AC-T2: Partial unique index `idx_sprint_assignments_order_unique` on
  `(sprint_id, sprint_order) WHERE sprint_order IS NOT NULL AND removed_at IS NULL`
- AC-T3: Backfill via `ROW_NUMBER() OVER (PARTITION BY sprint_id ORDER BY
  assigned_at, id)` for planning/active sprints only, `removed_at IS NULL`
- AC-T4: Completed/archived sprint assignments remain `sprint_order = NULL`

## Test Cases
See test-plan.md REQ-F-007 section: TC-025, TC-026, TC-027, TC-028.
Write failing tests first (TDD): assert column absent, run migration, assert column
present with correct values, run migration again, assert no error (idempotency).
