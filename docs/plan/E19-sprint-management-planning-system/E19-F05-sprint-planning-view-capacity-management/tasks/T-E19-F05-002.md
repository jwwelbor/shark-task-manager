# Sprint repository: capacity and backlog query methods with DTOs

## Goal

Extend `SprintRepository` with the five query methods and two DTOs required by
the service layer for planning, capacity management, and bulk assignment. The
`ListUnassignedBacklog` query must use a `NOT EXISTS` subquery (not N+1) to
satisfy the 500ms performance budget at 500 entities.

## Scope

- Files to modify:
  - `internal/repository/sprint/repository.go` — add `BacklogItem` and
    `AssignmentWithSize` DTOs; add `GetCapacity`, `SetCapacity`, `BulkAssign`,
    `ListUnassignedBacklog`, `GetAssignmentsWithSize` methods; `SetCapacity`
    uses `INSERT OR REPLACE` upsert
  - `internal/repository/sprint/repository_test.go` — TC-011-05 (perf),
    TC-014-01..02 (set/upsert), TC-014-03 (empty returns slice not error),
    and TC-012-09..10 (BulkAssign skips duplicate without error) using real
    test DB with cleanup before each test

## Design Reference

See spec.md Architecture Sections 2.3.2 (query signatures and DTOs) and 2.6
(SQL queries). `ListUnassignedBacklog` uses `NOT EXISTS` correlated subquery on
`sprint_assignments WHERE removed_at IS NULL AND s.status IN ('planning',
'active')`. `BulkAssign` wraps all inserts in one transaction.
