# Task: Tech debt: surface malformed depends_on JSON in readiness Factor 2 Detail string

## Goal

From code review of T-E19-F05-005 at 20260506-072159.

Finding:
sprint_service.go:1664-1666 — RISK — When depends_on JSON is malformed, the entity is silently skipped (treated as zero dependencies). This can inflate Factor 2 score to 20/20 for tasks whose dependency data is unreadable. The Detail string will say 'All task dependencies are satisfied' even if data is corrupt.

Suggested fix: track malformedCount in the loop; when > 0, append '(N entities have unreadable dependency data)' to the Detail string. Also add a test case with DependsOn: '{invalid}' to verify the graceful-degradation behavior explicitly.
