# SprintService: SetSprintCapacity and GetSprintCapacity methods

## Goal

Implement `SetSprintCapacity` (validates `points > 0`, resolves sprint key to
ID, upserts via `SprintCapacityRepository`) and `GetSprintCapacity` (computes
`allocated_points` and `remaining` per agent type from live assignment data,
returns empty slice not error when no rows exist).

## Scope

- Files to modify:
  - `internal/services/sprint_service.go` — add `CapacityRow`,
    `SetSprintCapacityInput` types; implement `SetSprintCapacity` (with
    `points > 0` validation before repo call) and `GetSprintCapacity` (computes
    allocated as Σ size filtered by agent_type; `remaining` can be negative)
  - `internal/services/sprint_service_test.go` — TC-014-01..08: create new
    row, upsert guard, reject zero/negative points, empty slice on no rows,
    computed allocation from multi-agent mock data, unsized_assigned count,
    negative remaining (overcommit), JSON structure validation

## Acceptance Criteria

See spec.md REQ-F-014 §1.1.4 AC-1..8 (set/show, computed allocation, empty-not-
error, remaining can be negative, JSON output)

## Test Cases

See test-plan.md Section 7: TC-014-01 through TC-014-08; Section 9.3 test layer
assignment (TC-014-07..08 are CLI-layer, verified in T-E19-F05-007)

## Design Reference

See spec.md Architecture Section 2.4 (`SetSprintCapacity` and `GetSprintCapacity`
signatures and `CapacityRow` type). `GetSprintCapacity` joins `GetCapacity` with
`GetAssignmentsWithSize` in memory — no additional queries per agent type.
`unsized_assigned` counts assignments with `size IS NULL` per agent.
