# CLI commands: sprint plan, readiness, capacity set/show, and bulk-add flags

## Goal

Add five new thin-wrapper commands to `internal/cli/commands/sprint.go`:
`sprintPlanCmd`, `sprintReadinessCmd`, `sprintCapacityCmd` (parent),
`sprintCapacitySetCmd`, `sprintCapacityShowCmd`. Extend `sprintAddCmd` with
`--bulk`, `--bulk-bugs`, `--bulk-tech-debt`, `--bulk-changes` flags. Register
all new commands in `init()`.

## Scope

- Files to modify:
  - `internal/cli/commands/sprint.go` — add the five new commands and four new
    flags on `sprintAddCmd`; `--default` on capacity set routes to
    `config.SetSprintCapacityDefault` not service; all commands follow parse
    -> call -> format; register in `init()`
  - `internal/cli/commands/sprint_test.go` — TC-011-06..07 (plan JSON and
    human sections), TC-012-04 (bulk JSON output), TC-013-08..09 (readiness
    JSON and human factor table), TC-014-07..08 (capacity show JSON and
    negative remaining), TC-015-04 (--default routes to config not service),
    TC-012-01..02 (bulk-by-feature and bulk-bugs CLI routing) using extended
    `MockSprintService`

## Design Reference

See spec.md Architecture Section 2.5 (all new command sketches). Commands must
never import the repository package directly. `sprintCapacitySetCmd` with
`--default` calls `config.Manager.SetSprintCapacityDefault`; without `--default`
it calls `GetSprintService().SetSprintCapacity`. Human output for plan must
show three labeled sections (Backlog / Capacity / Readiness).
