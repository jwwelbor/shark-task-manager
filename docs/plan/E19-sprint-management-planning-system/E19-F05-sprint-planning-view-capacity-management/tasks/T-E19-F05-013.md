# Task: Tech debt: improve entity-type filter test discriminating power in BulkAddToSprint bulk entity tests

## Goal

From code review of T-E19-F05-004 at 20260506-072540.

Finding F2:
internal/services/sprint_service_test.go:2185-2328 — TESTS — TC-K04 (Bugs), TC-K05 (TechDebt), TC-K06 (ChangeCards) use homogeneous fixtures that contain ONLY the requested entity type. The mock ListUnassignedBacklog does not filter by requested type — so a buggy impl that ignored the entityTypes parameter would still pass all count assertions (the mock returns the same items regardless). The capturedEntityTypes assertion provides partial protection, but is insufficient on its own.

Suggested fix: Use mixed-type fixtures in these tests so that a buggy impl that ignores the type filter would return wrong counts. E.g., for TC-K04 (bugs), include a task item in the fixture alongside the bugs; assert AddedByType['bug'] == 2 (not 3), which proves filtering is active.
