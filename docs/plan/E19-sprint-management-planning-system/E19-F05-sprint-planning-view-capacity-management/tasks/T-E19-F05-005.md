# SprintService: GetSprintReadiness 6-factor scoring algorithm

## Goal

Implement `GetSprintReadiness` on `SprintService` with the 6-factor, 0-100
scoring algorithm computed entirely in-memory after exactly two repository calls
(`GetAssignmentsWithSize` and `GetCapacity`). The algorithm is deterministic:
identical inputs always produce the same score.

## Scope

- Files to modify:
  - `internal/services/sprint_service.go` — add `SprintReadiness` and
    `ReadinessFactor` types; implement `GetSprintReadiness` with all six
    factors per the algorithm in spec §2.4; populate `UnsizedEntities` and
    `OversizedEntities` lists
  - `internal/services/sprint_service_test.go` — TC-013-01..14: all six factor
    boundary tables (utilization zones, dependency deduction, count scale,
    agent balance, sizing coverage, oversized flag), overall sum, zero-entity
    degenerate case, unsized/oversized list population, determinism assertion,
    and two-query call-count assertion

## Acceptance Criteria

See spec.md REQ-F-013 §1.1.3 AC-1..12 (all factors, JSON output, determinism,
zero-entity, two-query constraint)

## Test Cases

See test-plan.md Section 7: TC-013-01 through TC-013-14 (all table-driven
factor BVA tests, JSON contract, determinism, call-count mock verification)

## Design Reference

See spec.md Architecture Section 2.4 (Readiness Score Algorithm pseudocode).
Factor 1 penalty formula for overcommit: `max(0, 25 - int((util-1.0)*50))`.
Factor 2 checks task `depends_on` only (bugs/changes/tech-debt excluded per
§2.10). No DB queries inside factor computation — fetch once, compute in memory.
