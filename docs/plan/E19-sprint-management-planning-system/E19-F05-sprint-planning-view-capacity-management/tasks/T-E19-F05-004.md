# SprintService: PlanSprint and BulkAddToSprint methods

## Goal

Implement `PlanSprint` (composite view: backlog + capacity + readiness) and
`BulkAddToSprint` (transactional bulk assignment by feature or entity type with
capacity-exceeded warning) on `SprintService`. Both methods call `GetSprintReadiness`
and the repository methods from T-E19-F05-002.

## Scope

- Files to modify:
  - `internal/services/sprint_service.go` — add `SprintPlanView`, `BulkAddInput`,
    `BulkAddResult` types; implement `PlanSprint` and `BulkAddToSprint` methods
  - `internal/services/sprint_service_test.go` — TC-011-01..04 (PlanSprint happy
    path, empty sprint, backlog filtering, three-section output); TC-012-01..10
    (BulkAddToSprint: by feature, by entity type, eligible status boundary, over-
    capacity warning, transactional rollback, concurrent race protection) using
    `MockSprintAssignmentQueryRepository` and `MockSprintCapacityRepository`

## Acceptance Criteria

See spec.md REQ-F-011 §1.1.1 AC-1..5; REQ-F-012 §1.1.2 AC-1..9

## Test Cases

See test-plan.md Section 7: TC-011-01..04, TC-012-01..10; Section 9.2 for
`MockSprintAssignmentQueryRepository` helper definition

## Design Reference

See spec.md Architecture Sections 2.4 (`PlanSprint` and `BulkAddToSprint`
signatures and DTOs). `BulkAddToSprint` is all-or-nothing per entity type group;
capacity check generates warning in `BulkAddResult.Warnings`, never an error.
`PlanSprint` calls `GetSprintReadiness` internally — do not mock readiness.
