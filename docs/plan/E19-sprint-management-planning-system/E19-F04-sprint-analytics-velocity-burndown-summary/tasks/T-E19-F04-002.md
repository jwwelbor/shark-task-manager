# SprintAnalyticsRepository: Velocity and Assignment Queries

## Goal

Implement the `SprintAnalyticsRepository` struct in `internal/repository/sprint/analytics.go` with the `GetVelocityData` and `GetSprintAssignedEntities` query methods. These are the two queries underpinning velocity and burndown features.

## Scope

- Files to create:
  - `internal/repository/sprint/analytics.go` — struct, constructor, `GetVelocityData`, `GetSprintAssignedEntities`
  - `internal/repository/sprint/analytics_test.go` — repository tests using real test DB; `seedSprintWithAssignments` test helper; TC-NF-02 EXPLAIN QUERY PLAN assertions
- Files to modify: none

## Acceptance Criteria

See spec.md Section 4.3 (repository layer, GetVelocityData and GetSprintAssignedEntities method signatures and query design notes).

`GetVelocityData` uses four UNION ALL subqueries (one per entity type) to compute `COALESCE(size, 0)` per completed assignment, grouped by sprint. Results ordered oldest-first. Only sprints with status=`completed` are included.

`GetSprintAssignedEntities` returns all assignment rows including removed ones (removed_at IS NOT NULL). `Size` field is `*int` (nil when NULL in entity table).

All queries use `?` placeholders. Errors wrapped with `fmt.Errorf("failed to get ...: %w", err)`.
