# SprintAnalyticsService: Burndown Calculation

## Goal

Implement `GetBurndown` on `SprintAnalyticsService`, covering REQ-F-008: active-sprint lookup when no key given, piecewise ideal-line calculation with mid-sprint entity additions/removals, actual-remaining reconstruction from completion events, and nil ActualRemaining for future days.

## Scope

- Files to modify:
  - `internal/services/sprint_analytics_service.go` — add `GetBurndown` method
  - `internal/services/sprint_analytics_service_test.go` — burndown test cases; time-source injection for controlling "today"

## Acceptance Criteria

See spec.md Section 4.4 (GetBurndown logic, 6 numbered steps) and REQ-F-008.

When key is empty, calls `sprintRepo.List` with active-status filter and takes the first result. Returns informational message (not error) for planning-status sprint. Ideal line resets piecewise on mid-sprint net size changes. `ActualRemaining` is `*float64`; nil for days after today. `UnsizedRemaining` counted on each data point.

The service must accept an injectable time source (or use `time.Now()` by default) so tests can control "today" deterministically.

## Test Cases

See test-plan.md TC-B-01 through TC-B-12. Key cases: TC-B-04 (planning sprint = informational, exit 0), TC-B-05 (linear ideal line exact values), TC-B-06 (piecewise reset when entity added day 3 of 14-day sprint), TC-B-12 (nil ActualRemaining for future days, not 0.0).
