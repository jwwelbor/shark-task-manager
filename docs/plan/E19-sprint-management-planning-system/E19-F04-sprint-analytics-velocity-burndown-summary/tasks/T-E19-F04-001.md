# Analytics DTOs and Repository Interface Contracts

## Goal

Define all output DTO structs and the `SprintAnalyticsRepository` interface consumed by the service layer. Establishing these contracts first lets downstream tasks compile against the interface before the implementation exists.

## Scope

- Files to create:
  - `internal/services/sprint_analytics_dto.go` — 7 DTO structs + `SprintAnalyticsRepository` interface
  - `internal/services/sprint_analytics_dto_test.go` — JSON marshalling tests for null vs. omit contract

## Acceptance Criteria

See spec.md Section 4.5 (DTOs) and Section 4.4 (SprintAnalyticsRepository interface).

All pointer fields on `SprintSummaryResult` (detailed fields) must use pointer types without `omitempty` JSON tags so JSON renders `null` not absent. See spec.md AC-S-4.

`BurndownDataPoint.ActualRemaining` must be `*float64` (nil for future dates). See spec.md AC-B-8.

## Test Cases

See test-plan.md TC-S-07, TC-S-08 (null vs. omit), TC-B-12 (nil ActualRemaining).

Unit tests: marshal `SprintSummaryResult` with all nil detailed fields; assert `"cycle_time_by_phase":null` present in JSON output (not absent). Test `BurndownDataPoint` with nil `ActualRemaining` marshals without `actual_remaining` key.
