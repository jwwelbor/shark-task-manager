# CLI Commands: Velocity, Burndown, Summary and Service Accessor

## Goal

Wire the three analytics commands (`shark sprint velocity`, `shark sprint burndown`, `shark sprint summary`) into the existing sprint command group, add `GetSprintAnalyticsService()` to the global accessor file, and implement all output formatters (human-readable table and JSON). This is the final integration layer for REQ-F-007, REQ-F-008, REQ-F-009.

## Scope

- Files to modify:
  - `internal/cli/commands/sprint.go` — add `sprintVelocityCmd`, `sprintBurndownCmd`, `sprintSummaryCmd` vars, three `RunE` handlers, flag registration in `init()`
  - `internal/cli/services_global.go` — add `GetSprintAnalyticsService()` (~15 lines)
  - `internal/cli/commands/sprint_test.go` — CLI command tests using mocked `SprintAnalyticsService`

## Acceptance Criteria

See spec.md Section 4.6 (CLI command definitions) and Section 4.7 (GetSprintAnalyticsService accessor).

Commands follow three-step pattern: parse args/flags → call service → format output. No business logic in handlers.

`velocity`: `--sprints=N` flag, default 5. Validates 1–100 at CLI layer before passing to service. Renders table with unsized_completed column. Human-readable output shows "insufficient data" message when `InsufficientData=true`.

`burndown`: optional SPRINT_KEY arg (cobra.MaximumNArgs(1)). Human output is ASCII text table per spec.md AC-B-6 (no Unicode block chars U+2580–U+259F). Future days render `—` in Actual column.

`summary`: required SPRINT_KEY arg (cobra.ExactArgs(1)), `--detailed` flag. `--json` output renders nil detailed pointer fields as JSON `null` (no `omitempty`).

All three commands support `--json` and `--field` flags via existing `cli.OutputJSON` path.
