# SprintAnalyticsService: Summary and Detailed Report

## Goal

Implement `GetSummary` on `SprintAnalyticsService`, covering REQ-F-009: base summary fields for completed/archived sprints, `--detailed` additions (size-band distribution, carryover list, cycle-time by phase), and graceful nil degradation when `GetCycleTimeByPhase` returns an empty slice.

## Scope

- Files to modify:
  - `internal/services/sprint_analytics_service.go` — add `GetSummary` method
  - `internal/services/sprint_analytics_service_test.go` — summary test cases

## Acceptance Criteria

See spec.md Section 4.4 (GetSummary logic steps) and REQ-F-009.

`GetSummary` validates sprint status is `completed` or `archived`; returns informational result (not error) for other statuses. Planned size = entities assigned at or before start_date. Trailing average computed by calling `GetVelocity(ctx, 6)` and using the first 5 rows (excluding current sprint). When `GetCycleTimeByPhase` returns empty slice, `CycleTimeByPhase` is set to `nil` (not empty slice) in the DTO.

`CompletionPctBySize` = `completed_size / planned_size * 100`; no divide-by-zero panic when `planned_size=0` (returns 0.0).

## Test Cases

See test-plan.md TC-S-01 through TC-S-08. Key cases: TC-S-02 (active/planning sprint = informational exit 0), TC-S-04 (division by zero edge case), TC-S-06 (empty CycleTimeByPhase → nil in DTO, no error), TC-S-07 (nil detailed fields serialize as JSON null not absent).
