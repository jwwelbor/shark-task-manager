# SprintAnalyticsService: Velocity Calculation

## Goal

Implement `SprintAnalyticsService` struct with constructor and the `GetVelocity` method. This covers REQ-F-007 business logic: N-sprint limit validation, trailing average computation including zero-velocity sprints, and the insufficient-data flag when fewer than 3 sprints exist.

## Scope

- Files to modify:
  - `internal/services/sprint_analytics_service.go` — fill in struct, `NewSprintAnalyticsService`, `GetVelocity`
- Files to create:
  - `internal/services/sprint_analytics_service_test.go` — mock `SprintAnalyticsRepository` (function-field pattern); velocity test cases

## Acceptance Criteria

See spec.md Section 4.4 (GetVelocity logic steps, validation rules) and REQ-F-007.

`GetVelocity` validates N in range 1–100 before calling repo; returns error for out-of-range N. Trailing average divides by total sprint count (including zero-velocity sprints). `InsufficientData=true` when repo returns fewer than 3 rows; returns no error in this case.

## Test Cases

See test-plan.md TC-V-01 through TC-V-10. Key cases: TC-V-04 (N=0 and N=101 return error), TC-V-07 (zero-velocity sprint included in denominator returns 10.0 not 15.0), TC-V-08 (all-zero average is 0.0 without panic), TC-V-09 (InsufficientData flag set, no error returned).

All service tests use `MockSprintAnalyticsRepository` (function-field mock). No real database.
