# Add sprint.yaml to embedded workflow defaults

## Goal
Create `internal/sharkdata/default_data/workflow/sprint.yaml` with the full sprint state machine so that `shark admin init` materializes a sprint workflow and the embedded loader serves it with zero configuration.

## Scope
- Files to create: `internal/sharkdata/default_data/workflow/sprint.yaml`

## Acceptance Criteria
See spec.md REQ-F-001, REQ-F-002, REQ-F-003.
- AC-T1: YAML is valid and parseable by the existing workflow loader
- AC-T2: All statuses present: planning, active, closing, archived, on_hold
- AC-T3: `start:` is set to `planning`
- AC-T4: `archived` has `terminal: true`
- AC-T5: `on_hold` has `parking: true`
- AC-T6: Each workable step defines `pass` and `blocked` outcomes; `fail` outcomes are optional per spec

## Test Cases
See test-plan.md Section on sprint.yaml state machine and embedded loader.
Integration tests live in T-E19-F08-006.

See spec.md Architecture — Component Changes and sprint.yaml section.
Model the structure after `internal/sharkdata/default_data/workflow/feature.yaml`.
