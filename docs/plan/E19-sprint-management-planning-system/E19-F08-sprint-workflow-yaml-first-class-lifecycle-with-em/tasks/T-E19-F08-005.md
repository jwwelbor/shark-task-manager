# Make GetNextTask tolerant of multiple active sprints

## Goal
Update `GetNextTask` so it correctly selects the next unassigned task when multiple sprints are simultaneously active, using deterministic first-match (first active sprint by current ordering).

## Scope
- Files to modify:
  - `internal/services/sprint_service.go` — GetNextTask multi-active query/selection logic
  - `internal/services/sprint_service_test.go` — add multi-active scenario tests

## Acceptance Criteria
See spec.md REQ-F-007.
- AC-T1: GetNextTask returns a task when two sprints are both active
- AC-T2: Selection is deterministic: first active sprint by current ordering (not priority-based — no new sort key added)
- AC-T3: If all tasks in all active sprints are assigned, returns nil/not-found without error
- AC-T4: Single-sprint behaviour is unchanged

See test-plan.md Section on multi-active GetNextTask selection.
