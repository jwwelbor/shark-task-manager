# Task: Repository: CRUD operations and key generation

## Goal
Implement `SprintRepository` as the data access layer for sprint CRUD operations and key generation. This is the foundational layer that SprintService will depend on.

## Scope
**Files to create:**
- `internal/repository/sprint/repository.go` — SprintRepository struct and all CRUD methods
- `internal/repository/sprint/repository_test.go` — Repository tests using real test DB

**Files to modify:** None

## Acceptance Criteria
See spec.md Part 2 (Repository Layer Design):
- AC-1: GetNextKey() generates S001, S002, ... monotonically
- AC-2: GetByKey() is case-insensitive (UPPER(key) = UPPER(?) in SQL)
- AC-3: Create(), Update(), Delete() use parameterized queries
- AC-4: UpdateStatus() atomic single transaction
- AC-5: List() supports SprintListFilters{Status}
- AC-6: All methods return NotFoundError when appropriate

## Test Cases
Reference test-plan.md:
- TC-005 (key generation monotonicity)
- TC-013 (case-insensitive lookup)
- TC-001..009 (Create indirectly via service)
- Repository-level constraint validation (unique key, FK checks)
