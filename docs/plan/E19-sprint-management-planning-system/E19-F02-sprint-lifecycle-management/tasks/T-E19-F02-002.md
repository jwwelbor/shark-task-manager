# Task: Service layer: business logic and state machine

## Goal
Implement `SprintService` as the business logic layer. Service owns validation, status transitions, and workflow-aware state machine logic. All CLI commands delegate to this service.

## Scope
**Files to create:**
- `internal/services/sprint_service.go` — SprintService struct and 8 public methods
- `internal/services/sprint_service_test.go` — Service tests with mocked repository

**Files to modify:** None

## Acceptance Criteria
See spec.md Part 2 (Service Layer Design):
- AC-1: CreateSprint() validates date ordering, generates key/slug
- AC-2: GetSprint() returns NotFoundError if missing
- AC-3: ListSprints() supports status filter
- AC-4: UpdateSprint() validates date ordering and status
- AC-5: DeleteSprint() allows only planning status
- AC-6: StartSprint() enforces single-active-sprint constraint
- AC-7: All status transitions validated via workflow.Service
