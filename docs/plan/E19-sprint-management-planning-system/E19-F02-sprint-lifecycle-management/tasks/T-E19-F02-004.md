# Task: Service accessor and integration wiring

## Goal
Add GetSprintService() global accessor function in services_global.go and register sprintCmd to RootCmd. This enables CLI commands to obtain a SprintService instance with lazy initialization.

## Scope
**Files to create:** None

**Files to modify:**
- `internal/cli/services_global.go` — Add GetSprintService() function (10 lines)
- `internal/cli/root.go` — Register sprintCmd (1 line)

## Acceptance Criteria
See spec.md Part 2 (Service Accessor Pattern):
- AC-1: GetSprintService() creates new SprintService per call
- AC-2: Reuses global DB and workflow service
- AC-3: Panics on DB error (fail-fast for CLI)
- AC-4: Follows existing GetTaskService/GetEpicService pattern

## Test Cases
Integration verification:
- All CLI commands can obtain service via cli.GetSprintService()
- Service is properly initialized with dependencies
- Injection chain complete: DB → repository → service → CLI

## Design Reference
See spec.md Part 2, "Service Accessor Pattern" (lines 443–467).
Matches existing pattern from GetTaskService(), GetBugService() in services_global.go.
