# Task: Tech debt: SprintRepository test cleanup uses ignored errors and missing Update/Delete injection coverage

## Goal

From code review of T-E19-F02-001 at 20260505-210105.

Findings (non-blocker, codex-flagged):

1. internal/repository/sprint/repository_test.go:338, 387, 501 (and others) — Tests use `_, _ = database.ExecContext(...)` for cleanup and `_ = repo.Create(...)` for setup. coding-standards.md line 117 says "Never ignore errors; use _ only when documented why error is impossible." Setup errors are particularly risky — a silent Create failure would make the assertion logic look correct for the wrong reason. Fix: use require.NoError(t, err) for setup, t.Cleanup() for teardown, and at minimum log cleanup errors.

2. AC-3 (parameterized queries) is verified for Create (TestSprintRepository_Create_Parameterized) but Update is only exercised with regular text in TestSprintRepository_Update. Update's user-supplied string fields (Name, Goal, Slug, FilePath) are not exercised with SQL-injection payloads. The implementation uses ? placeholders correctly, so this is a coverage gap, not a vulnerability. Fix: extend the parameterized-query test to also exercise repo.Update with malicious input in Name/Goal/Slug/FilePath.

3. TestSprintRepository_List declares wantStatus on the test struct but never sets it for the filter cases, so the per-row status assertion at line 458 only runs when nil (never). Fix: populate wantStatus and assert it for every result row to actually verify the WHERE clause matches what the filter requests.
