# Task: Tech debt: SprintRepository test isolation in GetNextKey_Monotonic

## Goal

From code review of T-E19-F02-001 at 20260505-210105.

Finding (non-blocker, codex-flagged):
internal/repository/sprint/repository_test.go:292 — TestSprintRepository_GetNextKey_Monotonic/no_existing_sprints_in_range deletes only S500-S504 and asserts the next key is S001. Because GetNextKey() runs SELECT COALESCE(MAX(CAST(SUBSTR(key,2) AS INTEGER)),0) FROM sprints across the whole table, any sprint row outside the S500-S504 range causes the assertion to fail (returned key would be MAX+1, not S001).

The test currently passes because the shared test DB happens to have no sprints outside the test range, but this is fragile and a future test (or a developer running tests after manual exploration) can break it.

Fix: Either (a) DELETE FROM sprints in this test, (b) use a per-test isolated DB, or (c) change the assertion to compute expected = (max-existing-num + 1) up-front rather than hardcoding S001.
