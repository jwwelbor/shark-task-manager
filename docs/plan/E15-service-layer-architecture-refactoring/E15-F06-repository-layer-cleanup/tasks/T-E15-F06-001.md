# Task: Remove business logic from repositories (pure data access only)

## Goal

Remove all business logic methods from FeatureRepository, TaskRepository, and EpicRepository. Repositories must only perform CRUD + List operations (pure data access). Progress calculations, status breakdowns, and health derivations must be moved to corresponding services.

**Success Looks Like**: Repositories contain only data access methods (SELECT/INSERT/UPDATE/DELETE). All business logic exists in services (FeatureService.GetProgress, TaskService.GetStatusSummary, EpicService.GetHealth). Service tests use mocked repositories (no database required).

## Requirements

### Functional Requirements

**REQ-F-001**: Remove FeatureRepository.CalculateProgress()
- Method removed from FeatureRepository
- Logic migrated to FeatureService.GetProgress()
- All callers updated to use FeatureService method
- Tests updated to mock repository, test service logic

**REQ-F-002**: Remove FeatureRepository.GetHealthStatus()
- Method removed from FeatureRepository
- Logic migrated to FeatureService.GetHealth()
- All callers updated to use service method

**REQ-F-003**: Remove TaskRepository.GetStatusBreakdown()
- Method removed from TaskRepository
- Logic migrated to TaskService.GetStatusSummary()
- All callers updated to use service method

**REQ-F-004**: Remove EpicRepository.GetHealthStatus()
- Method removed from EpicRepository
- Logic migrated to EpicService.GetHealth()
- All callers updated to use service method

**REQ-F-005**: Simplify EpicRepository.GetImpediments()
- Method returns only raw SQL query results (WHERE status = 'blocked')
- No impediment analysis/categorization in repository
- Logic moved to EpicService.GetImpediments()

### Non-Functional Requirements

**REQ-NF-001**: Repository Purity
- 100% of repository methods perform only data access operations
- 0 business logic methods remain in repositories
- Code review verification required

**REQ-NF-002**: Service Layer Testability
- All service methods test business logic with mocked repositories
- No service tests require real database connection

### Technical Approach

**Migration Pattern (Per Repository Method)**:
1. Create service method with same functionality
2. Update all callers to use service method
3. Run tests (ensure behavior unchanged)
4. Remove repository method
5. Update tests (business logic tests → service tests)

**Key Principles**:
- **Repository methods**: SELECT/INSERT/UPDATE/DELETE only (raw data models)
- **Service methods**: Business logic, calculations, derivations (uses repository for data)
- **Test strategy**: Repository tests use database, service tests use mocks

### Code Patterns

**Before (Repository with Business Logic)**:
```go
// ❌ Business logic in repository
func (r *FeatureRepository) CalculateProgress(ctx context.Context, featureID int64) (float64, error) {
    tasks, _ := r.ListByFeature(ctx, featureID)
    completed := 0
    for _, t := range tasks {
        if t.Status == "completed" {
            completed++
        }
    }
    return float64(completed) / float64(len(tasks)) * 100, nil
}
```

**After (Repository Pure Data Access, Service with Business Logic)**:
```go
// ✅ Repository: pure data access only
func (r *TaskRepository) ListByFeature(ctx context.Context, featureID int64) ([]*models.Task, error) {
    query := "SELECT * FROM tasks WHERE feature_id = ?"
    // ... execute query, return raw models
}

// ✅ Service: business logic
func (s *FeatureService) GetProgress(ctx context.Context, featureID int64) (*ProgressMetrics, error) {
    tasks, err := s.taskRepo.ListByFeature(ctx, featureID)
    if err != nil {
        return nil, err
    }

    completed := 0
    for _, t := range tasks {
        if t.Status == "completed" {
            completed++
        }
    }

    return &ProgressMetrics{
        CompletionPercent: float64(completed) / float64(len(tasks)) * 100,
    }, nil
}
```
