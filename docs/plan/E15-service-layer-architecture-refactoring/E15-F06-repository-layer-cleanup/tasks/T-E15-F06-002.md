# Task: Migrate FeatureRepository progress calculation to FeatureService

## Goal

Remove progress calculation business logic from FeatureRepository and ensure FeatureService.GetProgress() (already implemented in E15-F05) is used instead. Remove or simplify the following methods:

1. `CalculateProgress` (line 623) - Config-driven weighted progress calculation
2. `CalculateProgressByKey` (line 680) - Wrapper
3. `UpdateProgress` (line 690) - Calculates progress AND auto-completes at 100%
4. `UpdateProgressByKey` (line 722) - Wrapper
5. `UpdateProgressTx` (line 730) - Transaction variant with auto-complete

**Note**: FeatureService.GetProgress() already exists from E15-F05. This task focuses on removing the duplicated repository logic and updating callers.

## Implementation Plan

### Step 1: Identify all callers of repository progress methods

```bash
grep -rn "CalculateProgress\|UpdateProgress\|UpdateProgressByKey\|UpdateProgressTx" internal/ --include="*.go" | grep -v "_test.go" | grep -v "feature_repository.go"
```

Key callers to update:
- `internal/cli/commands/feature.go` - Multiple calls to `featureRepo.UpdateProgress()`
- `internal/cli/commands/epic.go` - Calls to `featureRepo.UpdateProgress()`
- `internal/status/calculation_service.go` - Calls to `CalculateProgress`

### Step 2: Ensure FeatureService has equivalent methods

FeatureService.GetProgress() already returns `FeatureProgressInfo` with weighted and completion percentages. If callers need a "recalculate and persist" method, add `RecalculateProgress()` to FeatureService that:
1. Calls GetProgress() to compute
2. Calls repo.SetProgress() to persist the result
3. Handles auto-completion logic (status → completed when 100%)

### Step 3: Update callers to use FeatureService

Replace all `featureRepo.CalculateProgress(ctx, id)` calls with `featureService.GetProgress(ctx, key)`.
Replace all `featureRepo.UpdateProgress(ctx, id)` calls with `featureService.RecalculateProgress(ctx, key)`.

### Step 4: Remove business logic methods from FeatureRepository

Delete the 5 methods listed above. Keep the pure data access methods:
- `GetProgress()` (line 528) - reads stored progress_pct (pure data)
- `SetProgress()` (line 543) - writes progress_pct (pure data)
- `SetProgressTx()` (line 557) - transaction variant (pure data)

### Step 5: Update tests

- Remove FeatureRepository tests for business logic methods
- Verify FeatureService tests cover the equivalent logic
- Run `make fmt && make lint && make test`

## Acceptance Criteria

- [ ] FeatureRepository.CalculateProgress() removed
- [ ] FeatureRepository.CalculateProgressByKey() removed
- [ ] FeatureRepository.UpdateProgress() removed (auto-complete logic moved to service)
- [ ] FeatureRepository.UpdateProgressByKey() removed
- [ ] FeatureRepository.UpdateProgressTx() removed (auto-complete logic moved to service)
- [ ] FeatureService has RecalculateProgress() method (or equivalent)
- [ ] All callers updated to use FeatureService methods
- [ ] No regressions: `make test` passes
- [ ] Service tests use mocked repositories

- Test auto-completion at 100% in service layer
