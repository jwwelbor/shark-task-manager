# Task: Migrate TaskRepository status enrichment to services

## Goal

Remove status enrichment business logic from TaskRepository. These methods add workflow config metadata (phase, color, ordering) to raw status counts, which is business logic that belongs in a service.

Methods to remove/migrate:
1. `GetStatusBreakdown` (line 1230) - Enriches counts with phase/color/order metadata from workflow config
2. `GetStatusBreakdownMap` (line 1303) - Deprecated, hardcoded status list
3. `getOrderedStatuses` (line 1400) - Orders statuses by workflow phase
4. `getStatusMetadata` (line 1441) - Config lookup helper in repo

**Keep as pure data access**: `GetStatusBreakdownMapBatch` (line 1347) - Returns raw SQL counts without enrichment.

## Implementation Plan

### Step 1: Identify callers

```bash
grep -rn "GetStatusBreakdown\|getOrderedStatuses\|getStatusMetadata" internal/ --include="*.go" | grep -v "_test.go"
```

Key callers:
- `internal/cli/commands/feature.go` - Calls `taskRepo.GetStatusBreakdown()`
- `internal/cli/commands/epic.go` - Calls `taskRepo.GetStatusBreakdown()`

### Step 2: Create service method

Add to TaskService (or a shared StatusService):
- `GetStatusBreakdown(ctx, featureID)` - calls repo for raw counts, enriches with workflow config metadata
- Can reuse existing `GetTaskStatusBreakdown` from FeatureService if already available

### Step 3: Update callers

Replace `taskRepo.GetStatusBreakdown()` with service method call.

### Step 4: Remove methods

Delete the 4 methods. Keep `GetStatusBreakdownMapBatch` as it's pure SQL aggregation.

### Step 5: Quality gate

- `make fmt && make lint && make test`

## Acceptance Criteria

- [ ] TaskRepository.GetStatusBreakdown() removed (logic in service)
