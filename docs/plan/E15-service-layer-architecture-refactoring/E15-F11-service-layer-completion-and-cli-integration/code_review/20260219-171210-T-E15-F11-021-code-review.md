# Code Review: T-E15-F11-021

**Task**: Migrate task_resume.go to thin wrapper calling ResumeService methods
**Reviewer**: TechLead
**Date**: 2026-02-19
**Status**: CHANGES_REQUESTED

---

## Summary

The task title states "Migrate task_resume.go to thin wrapper calling ResumeService methods." After reviewing the implementation, the file **has NOT been migrated**. It remains a fat controller that directly creates repositories and contains substantial business logic. The `ResumeService` that exists in `internal/services/resume_service.go` is not called from `task_resume.go` at all.

---

## Critical Findings

### 1. Fat Controller - No Service Call (BLOCKER)

`internal/cli/commands/task_resume.go` does NOT call `ResumeService` at all. The entire implementation still accesses repositories directly:

```go
// Lines 67-72 - Direct repository creation (anti-pattern)
dbConn := repoDb
taskRepo := repository.NewTaskRepository(dbConn)
noteRepo := repository.NewEntityNoteRepository(dbConn)
sessionRepo := repository.NewWorkSessionRepository(dbConn)
```

The `GetResumeService()` accessor exists in `internal/cli/services_global.go` (line 74) but is never called from `task_resume.go`. The command must use `cli.GetResumeService()` instead of constructing repositories directly.

### 2. Business Logic Remains in the Command (BLOCKER)

The following business logic belongs in the service layer but remains in the command:

- **Context data parsing** (lines 86-91): `models.FromJSON()` call and null checks
- **Work session retrieval and aggregation** (lines 100-115): Multiple repo calls for sessions, stats, and active sessions
- **Dependency string parsing** (lines 118-124): Splitting and trimming the `DependsOn` string
- **Completion metadata assembly** (lines 127-144): Conditional business logic to build `CompletionMetadata`
- **Active session null check** (line 113): `err != sql.ErrNoRows` is a logic error (the condition `err == nil && err != sql.ErrNoRows` is always equivalent to just `err == nil` when err is nil - this is a bug)

### 3. ResumeService Missing Task Resume Method (BLOCKER)

`ResumeService` in `internal/services/resume_service.go` provides:
- `GetEpicResume(ctx, epicKey)` - for epics
- `GetFeatureResume(ctx, featureKey)` - for features

There is **no `GetTaskResume()` method** on `ResumeService`. The task's goal is to migrate the task resume logic to use this service, but the service does not yet have a task-level resume method. The developer needed to:
1. Add `GetTaskResume(ctx context.Context, taskKey string) (*TaskResumeContext, error)` to `ResumeService`
2. Move the `ResumeContext` struct to the service package
3. Migrate work session, note, and dependency retrieval into the service method
4. Call `cli.GetResumeService()` from the command

### 4. Local Context Type Exposes Repository Type (BLOCKER)

The `ResumeContext` struct (lines 42-51) references `*repository.SessionStats`:

```go
type ResumeContext struct {
    // ...
    SessionStats   *repository.SessionStats   `json:"session_stats,omitempty"`
    // ...
}
```

This leaks a repository-layer type into the command layer. This DTO should live in the service package and use only model or service-level types.

### 5. Direct Repository Import Not Removed

`internal/repository` is still imported (line 14) for direct use. After migration, the command should not import the repository package.

### 6. Unused/Wrong Context Variable (Minor)

Line 55: A new context with timeout is created but the `cmd.Context()` context is used for the DB call on line 61. The 30-second timeout context (`ctx`) is then used for repository calls. This is inconsistent - the command should use `cmd.Context()` throughout for cancellation propagation from the CLI framework.

## What Was Done Correctly

- The `printResumeContext()` function is appropriate presentation logic that belongs in the command
- The `formatDuration()` helper is a valid presentation utility
- The JSON output check follows the correct pattern (`cli.GlobalConfig.JSON`)
- Command registration in `init()` is correct
- The `ResumeService` accessor `GetResumeService()` in `services_global.go` is correctly wired (pre-existing work)

---

## Required Changes

1. **Add `GetTaskResume()` to `ResumeService`** in `internal/services/resume_service.go`:
   - Move `ResumeContext` struct from command to service
   - Add `ResumeTaskRepository` interface methods for work sessions (GetByTaskID, GetSessionStatsByTaskID, GetActiveSessionByTaskID)
   - Implement all the business logic currently in `runTaskResume` within this service method

2. **Refactor `task_resume.go` to a thin wrapper**:
   - Remove all repository construction
   - Remove all business logic (context parsing, session assembly, dependency parsing, completion metadata)
   - Call `cli.GetResumeService(cmd.Context())` and then `svc.GetTaskResume(ctx, taskKey)`
   - Keep only: arg parse, service call, JSON output or `printResumeContext()`

3. **Remove `repository` import** from `task_resume.go`

4. **Fix the logic error** on line 113: `err == nil && err != sql.ErrNoRows` is redundant; the intent is likely to check `activeSession != nil` or to differentiate sql.ErrNoRows from other errors

5. **Use consistent context**: Use `cmd.Context()` rather than creating a separate timeout context in the command layer

---

## Verdict

CHANGES_REQUESTED - The migration task has not been completed. The command still operates as a fat controller with direct repository access and no ResumeService invocation. The ResumeService also lacks the required `GetTaskResume()` method that would enable this migration.
