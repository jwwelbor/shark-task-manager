## Summary

The implementation of `task_note.go` has been successfully migrated from a fat controller pattern (directly calling repositories) to a thin wrapper that delegates to the `NoteService` via global accessor functions. The migration is complete and clean.

---

## Review Checklist

### Architecture Compliance

- [x] **Thin wrapper pattern**: The file follows the parse → call service → format output pattern throughout all three command handlers
- [x] **No direct repository access**: Zero calls to `repository.NewTaskRepository`, `repository.NewEntityNoteRepository`, `cli.GetDB()`, or any other direct repository instantiation
- [x] **Uses NoteService**: All note operations go through `cli.GetNoteService(cmd.Context())` which returns the injected `*services.NoteService`
- [x] **Uses TaskService**: The `runTaskNotes` and `runTaskTimeline` handlers also correctly use `cli.GetTaskService()` and `cli.GetTaskServiceWithDeps()` for task-level operations
- [x] **Global accessor pattern**: Services accessed via `cli.GetNoteService()`, `cli.GetTaskService()`, `cli.GetTaskServiceWithDeps()` - matches project conventions

### Command Implementation Quality

#### `runTaskNoteAdd` (lines 88-128)
- Parse: `taskKey`, `content`, `noteTypeStr`, `createdBy` parsed cleanly from args/flags
- Call: `noteSvc.AddNote(ctx, models.EntityTypeTask, taskKey, noteTypeStr, content, createdBy)` - correct service call
- Format: JSON branch via `cli.OutputJSON(note)`, human-readable branch with clear formatting
- Status: PASS

#### `runTaskNotes` (lines 131-187)

- Call: `noteSvc.ListNotes(ctx, models.EntityTypeTask, taskKey, noteTypes)` - correct service call

### Minor Observations (Non-blocking)

1. **Bubble sort in timeline** (lines 301-307): A simple O(n²) sort is used for timeline ordering. For typical task timelines (likely <100 events), this is acceptable. Could be replaced with `sort.Slice` for readability, but this is a minor style note, not a blocking issue.

2. **`fmt.Printf` vs `cli.Success`**: The output functions use `fmt.Printf` directly rather than the `cli.Success/Info` helpers for the main body output. This is consistent with the pre-existing pattern in this file and other note display commands in the codebase. Not a violation.

3. **Task spec is a placeholder**: The task spec at `T-E15-F11-022.md` contains only the default template with no populated requirements. The implementation exists and was already partially in place from prior commits (`6c43100` added NoteService, services_global.go accessor was added). The current task appears to have formalized/verified this migration.
