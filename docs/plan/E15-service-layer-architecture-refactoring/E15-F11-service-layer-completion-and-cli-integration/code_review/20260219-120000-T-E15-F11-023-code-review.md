## Findings

### Positive Observations

**Clean import list:** The file imports only `fmt`, `cli`, `models`, and `cobra`. No `repository` package, no `db` package, no direct data access.

**Consistent accessor pattern:** `GetCriteriaService()` in `services_global.go` (lines 218-235) follows the established panic-on-failure pattern matching `GetTaskService()` and `GetViewService()`. It correctly wires `criteriaRepo`, `taskRepo`, and `featureRepo` to match the `NewCriteriaService` constructor.

**Service ownership validation:** The `CheckCriterionForTask` and `FailCriterionForTask` service methods (not in the command) verify that the criterion belongs to the specified task before updating - a business rule correctly kept in the service layer.

**Presentation logic appropriately placed:** The multi-pass criteria sort in `runTaskCriteriaList` (lines 170-196) that orders failed first, then pending, in_progress, complete, NA is display-ordering logic - correctly in the command layer.

### Minor Observations (Non-blocking)

**Double validation on `--note` for fail command:** The `--note` flag is validated in both `MarkFlagRequired("note")` in `init()` and an explicit nil check in `runTaskCriteriaFail`. This is redundant but harmless - Cobra catches the missing flag before the handler runs, so the explicit check in the handler is never triggered in practice. This does not warrant a change request.

**`getCriteriaStatusIcon` helper:** A local presentation helper mapping `models.CriteriaStatus` to display icons (`✓`, `✗`, `○`, `◐`, `−`). Correctly placed in the command file.
