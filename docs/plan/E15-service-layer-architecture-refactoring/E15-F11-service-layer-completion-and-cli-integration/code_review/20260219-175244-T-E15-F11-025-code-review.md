## Summary

This is the second code review attempt for the `history.go` fat-controller fix. The previous review FAILED because `svc.GetTaskRepository()` was called from the CLI layer to obtain raw repository access, violating the service layer architecture.

The developer has corrected the issue by:
1. Adding `TaskService.GetTaskByID(ctx, id)` to `task_service.go`
2. Replacing `svc.GetTaskRepository().GetByID()` calls in `history.go` with `svc.GetTaskByID(ctx, h.TaskID)`
3. Defining a local `taskByIDGetter` interface in `history.go` to keep `outputHistoryExport` testable without coupling to the full `*TaskService` type
