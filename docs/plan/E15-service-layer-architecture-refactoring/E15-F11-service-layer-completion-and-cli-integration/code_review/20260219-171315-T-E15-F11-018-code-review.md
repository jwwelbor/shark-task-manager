## Summary

The task objective has **not been met**. `notes_search.go` remains a fat controller that directly instantiates repositories and calls repository methods. It does not use the `NoteService` that already exists in `internal/services/note_service.go` and is already wired via the global accessor `cli.GetNoteService()`.

---

## Critical Issues (Must Fix)

### 1. Direct Repository Instantiation in CLI Command

Lines 67-78 of `notes_search.go`:
```go
repoDb, err := cli.GetDB(cmd.Context())
...
ctx := context.Background()
dbWrapper := repoDb
noteRepo := repository.NewEntityNoteRepository(dbWrapper)
taskRepo := repository.NewTaskRepository(dbWrapper)
epicRepo := repository.NewEpicRepository(dbWrapper)
featureRepo := repository.NewFeatureRepository(dbWrapper)
```

CLI commands must NOT create repositories directly. This is the fat controller anti-pattern. The `repository` package import (line 10) should not exist in a CLI command file.

### 2. Direct Repository Method Calls Instead of NoteService

Lines 106-113:
```go
if since != "" || until != "" {
    notes, err = noteRepo.SearchWithTimePeriod(ctx, ...)
} else {
    notes, err = noteRepo.Search(ctx, ...)
}
```

Lines 140-179 - entity detail lookups using `taskRepo.GetByID()`, `epicRepo.GetByID()`, `featureRepo.GetByID()` directly.

The `NoteService` already provides all these operations:
- `svc.SearchNotes()` - maps to `noteRepo.Search()`
- `svc.SearchNotesWithTimePeriod()` - maps to `noteRepo.SearchWithTimePeriod()`
- `svc.GetEntityDetails()` - handles entity key/name lookup for all entity types

### 3. Business Logic in the Command Handler

The following logic belongs in a service, not a CLI command:

- Note type parsing and validation (lines 81-91)
- Entity type validation (lines 94-102)
- Entity detail lookup with caching (lines 124-183)

The caching logic (taskCache, epicCache, featureCache) is particularly notable - this is query orchestration that belongs in the service layer.

### 4. Context Misuse

Line 73: `ctx := context.Background()` - ignores `cmd.Context()`. All service calls should use `cmd.Context()` to support proper cancellation propagation.

## Test Issues (Must Fix)

database := test.GetTestDB()  // NEVER DO THIS in CLI command tests

## Required Refactoring

The command should follow the thin wrapper pattern:

```go
func runNotesSearch(cmd *cobra.Command, args []string) error {
    // Step 1: Parse arguments and flags
    query := args[0]
    epicKey, _ := cmd.Flags().GetString("epic")
    featureKey, _ := cmd.Flags().GetString("feature")
    noteTypesStr, _ := cmd.Flags().GetString("type")
    since, _ := cmd.Flags().GetString("since")
    until, _ := cmd.Flags().GetString("until")
    entityTypeStr, _ := cmd.Flags().GetString("entity-type")

    // Step 2: Call NoteService
    svc, err := cli.GetNoteService(cmd.Context())
    if err != nil {
        return fmt.Errorf("failed to get note service: %w", err)
    }
    // ... call svc.SearchNotes() or svc.SearchNotesWithTimePeriod() ...
    // ... call svc.GetEntityDetails() for entity lookups ...

    // Step 3: Format output
    if cli.GlobalConfig.JSON {
        return cli.OutputJSON(results)
    }
    // ... human-readable output ...
}
```

Note: Note type validation and entity type validation should move to the `NoteService` or remain as simple input parsing in the command (for immediate user feedback). The entity detail enrichment MUST move to the service layer.
