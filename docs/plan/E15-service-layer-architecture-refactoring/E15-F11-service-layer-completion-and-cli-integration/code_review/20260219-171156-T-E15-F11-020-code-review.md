# Code Review: T-E15-F11-020

**Task**: Migrate task_context.go to thin wrapper calling ContextService methods
**File Reviewed**: `internal/cli/commands/task_context.go`
**Date**: 2026-02-19
**Reviewer**: TechLead Agent
**Status**: CHANGES_REQUESTED

---

## Summary

The implementation does NOT meet the thin wrapper requirement. `task_context.go` still contains fat-controller patterns: direct repository access, duplicated business logic, and field validation that belongs in the service layer. A `ContextService` and a `GetContextService` global accessor already exist and are ready to use, but `task_context.go` does not call them.

---

## Findings

### BLOCKER 1: Direct Repository Access in All Three Handlers

`task_context.go` calls `repository.NewTaskRepository(repoDb)` directly in all three command handlers. This is the exact anti-pattern that E15 is eliminating.

**Lines affected**: 114-122, 248-256, 362-370

```go
// BAD - repeated in runTaskContextSet, runTaskContextGet, runTaskContextClear
repoDb, err := cli.GetDB(cmd.Context())
...
repo := repository.NewTaskRepository(repoDb)
```

**Required fix**: Remove all direct repository access. Call `GetContextService()` (already implemented in `internal/cli/services_global.go`) and delegate to `ContextService` methods.

### BLOCKER 2: Duplicated updateContextField Function

The function `updateContextField` is defined identically in two places:
- `internal/cli/commands/task_context.go` lines 174-239
- `internal/services/context_service.go` lines 176-244

The CLI command layer must not contain business logic. The `updateContextField` function in `task_context.go` must be removed. The service already owns this logic.

### BLOCKER 3: Field Validation Logic in the Command Layer

`runTaskContextSet` contains a `validFields` map check (lines 97-112) that belongs in the service. The `ContextService.SetContextField` method already performs this validation via `isValidContextField`. The command is duplicating validation that is already in the service.

```go
// BAD - in task_context.go
validFields := map[string]bool{
    "current_step":               true,
    ...
}
if !validFields[field] {
    cli.Error(...)
    os.Exit(3)
}
```

**Required fix**: Remove the `validFields` check from the command. Let the service return an error for invalid fields, and translate that error to an exit code in the command.

### BLOCKER 4: Context Parsing and JSON Merging Logic in the Command

`runTaskContextSet` (lines 133-158) contains context data parsing (`models.FromJSON`), field merging, and JSON serialization (`contextData.ToJSON()`). This is business orchestration logic that belongs in `ContextService.SetContextField`, which already implements this exact flow.

**Required fix**: Replace lines 133-158 with a single call to `svc.SetContextField(ctx, models.EntityTypeTask, taskKey, field, value)`.

### BLOCKER 5: Context Parsing Logic in runTaskContextGet

`runTaskContextGet` (lines 266-273) manually parses the raw context JSON from the task. `ContextService.GetContext` already encapsulates this logic and returns a parsed `*models.ContextData`.

**Required fix**: Replace manual parsing with `svc.GetContext(ctx, models.EntityTypeTask, taskKey)`.

## What the Correct Implementation Should Look Like

```go
// runTaskContextSet - thin wrapper
func runTaskContextSet(cmd *cobra.Command, args []string) error {
    taskKey := args[0]
    field, _ := cmd.Flags().GetString("field")
    value, _ := cmd.Flags().GetString("value")

    svc, err := cli.GetContextService(cmd.Context())
    if err != nil {
        return fmt.Errorf("failed to get context service: %w", err)
    }

    if err := svc.SetContextField(cmd.Context(), models.EntityTypeTask, taskKey, field, value); err != nil {
        return err // Service returns typed errors; command translates to exit codes
    }

    if cli.GlobalConfig.JSON {
        return cli.OutputJSON(map[string]interface{}{"task_key": taskKey, "field": field, "success": true})
    }
    cli.Success(fmt.Sprintf("Updated context field '%s' for task %s", field, taskKey))
    return nil
}

// runTaskContextGet - thin wrapper
func runTaskContextGet(cmd *cobra.Command, args []string) error {
    taskKey := args[0]

    svc, err := cli.GetContextService(cmd.Context())
    if err != nil {
        return fmt.Errorf("failed to get context service: %w", err)
    }

    contextData, err := svc.GetContext(cmd.Context(), models.EntityTypeTask, taskKey)
    if err != nil {
        return err
    }
    if contextData == nil {
        contextData = &models.ContextData{}
    }

    if cli.GlobalConfig.JSON {
        return cli.OutputJSON(map[string]interface{}{"task_key": taskKey, "context_data": contextData})
    }
    // ... human-readable formatting (stays in command) ...
    return nil
}

// runTaskContextClear - thin wrapper
func runTaskContextClear(cmd *cobra.Command, args []string) error {
    taskKey := args[0]

    svc, err := cli.GetContextService(cmd.Context())
    if err != nil {
        return fmt.Errorf("failed to get context service: %w", err)
    }

    if err := svc.ClearContext(cmd.Context(), models.EntityTypeTask, taskKey); err != nil {
        return err
    }

    if cli.GlobalConfig.JSON {
        return cli.OutputJSON(map[string]interface{}{"task_key": taskKey, "success": true, "message": "Context data cleared"})
    }
    cli.Success(fmt.Sprintf("Cleared context data for task %s", taskKey))
    return nil
}
```

- The `"encoding/json"` and `"os"` imports can be removed once business logic is extracted.
