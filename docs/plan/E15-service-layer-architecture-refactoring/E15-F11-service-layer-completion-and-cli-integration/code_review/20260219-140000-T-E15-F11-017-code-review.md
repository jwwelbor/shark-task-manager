## Summary

The task goal is to migrate `analytics.go` from a fat controller (direct repository access) to a thin wrapper calling `TaskService.GetSessionAnalytics()`. The `TaskService` already has a fully-implemented `GetSessionAnalytics` method at line 1940 of `task_service.go`, and the `services_global.go` already wires an analytics-capable TaskService in `GetTaskServiceWithDeps()` (line 204).

**The migration was NOT completed.** The `analytics.go` file still contains the original fat-controller implementation — it calls repositories directly and bypasses the service layer entirely.

## Critical Issues (Blocking)

### Issue 1: Direct Repository Calls in CLI Command (FAT CONTROLLER)

**Severity:** Critical — this is the primary violation the task exists to fix.

**Location:** `internal/cli/commands/analytics.go`, lines 74-129

The command directly instantiates and calls three repositories:

```go
// Lines 74-78 — VIOLATION: Repositories created directly in CLI command
dbConn := repoDb
epicRepo := repository.NewEpicRepository(dbConn)
featureRepo := repository.NewFeatureRepository(dbConn)
sessionRepo := repository.NewWorkSessionRepository(dbConn)

// Lines 86-128 — VIOLATION: Business orchestration logic in CLI command
feature, err := featureRepo.GetByKey(ctx, featureKey)
analytics, err = sessionRepo.GetSessionAnalyticsByFeature(ctx, feature.ID, agentTypePtr)
// ...
epic, err := epicRepo.GetByKey(ctx, epicKey)
analytics, err = sessionRepo.GetSessionAnalyticsByEpic(ctx, epic.ID, agentTypePtr)
```

The `TaskService.GetSessionAnalytics()` method at line 1940 of `task_service.go` already implements this exact orchestration (resolve feature/epic key to ID, then call session repo). The CLI command must delegate to it instead.

**Required fix:** Replace the repository instantiation and orchestration block (lines 67-129) with a single service call:

```go
svc := cli.GetTaskServiceWithDeps()
analytics, err := svc.GetSessionAnalytics(cmd.Context(), services.SessionAnalyticsInput{
    EpicKey:    epicKey,
    FeatureKey: featureKey,
    AgentType:  agentType,
})
if err != nil {
    return fmt.Errorf("failed to get analytics: %w", err)
}
```

### Issue 2: Import of `repository` Package in CLI Command

**Severity:** Critical — a symptom of the fat-controller violation.

**Location:** `internal/cli/commands/analytics.go`, line 10

```go
"github.com/jwwelbor/shark-task-manager/internal/repository"
```

CLI commands must not import the `repository` package. Per CLAUDE.md: "CLI commands must NOT create repositories directly." The `repository` import must be removed once the fat-controller is replaced with a service call.

Additionally, the output formatting functions reference `*repository.SessionAnalytics` (lines 153 and 190). After migration, they should reference `*services.SessionAnalytics` instead (the service layer's analytics DTO).

### Issue 3: Manual `context.WithTimeout` Instead of Using `cmd.Context()`

**Severity:** Minor — but reflects a pattern inconsistency.

**Location:** `internal/cli/commands/analytics.go`, lines 46-47

```go
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()
```

Other commands in this codebase use `cmd.Context()` which inherits the Cobra command's context. Creating a separate `context.WithTimeout` from `context.Background()` is fine for timeout behavior but is inconsistent with the project pattern and does not compose with signals properly. After migration, use `cmd.Context()` directly and pass it to the service.

## Minor Issues (Non-Blocking, Should Fix)

### Issue 4: Validation Logic in the CLI Command

**Location:** `internal/cli/commands/analytics.go`, lines 56-65

```go
if !sessionDuration && !pauseFrequency {
    cli.Error("Please specify at least one analysis type: --session-duration or --pause-frequency")
    os.Exit(3)
}
if epicKey == "" && featureKey == "" {
    cli.Error("Please specify --epic or --feature for analysis scope")
    os.Exit(3)
}
```

Input validation for "at least one analysis type selected" is a UI-level check (the command defines the flags, so it is acceptable here). However, the scope validation (requiring epic or feature) duplicates the guard already in `TaskService.GetSessionAnalytics()` which returns `"either EpicKey or FeatureKey must be specified"`. These two should not both exist; the command should delegate and let the service error propagate.

The analysis-type validation (session-duration / pause-frequency) is purely a CLI concern and is acceptable in the command.

### Issue 5: `runAnalytics` Is Not Wired to the Command

**Location:** `internal/cli/commands/analytics.go`, line 237 (second `init()` function)

```go
func init() {
    analyticsCmd.RunE = runAnalytics
}
```

Having two `init()` functions in the same file is valid Go but unusual and a readability concern. The `RunE` assignment should be done in the first `init()` alongside flag registration, or as part of the `var analyticsCmd = &cobra.Command{...}` declaration.
