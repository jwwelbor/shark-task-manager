# Task: Implement Advanced Task Query Methods

## Goal

Implement advanced query methods in TaskService to support complex filtering, sorting, and search operations. Current ListTasks method has basic filtering - this task adds pagination, multi-field sorting, fuzzy search, and query builder pattern for composable filters.

## Requirements

### Functional Requirements

- [ ] Add pagination support to ListTasks (limit, offset)
- [ ] Implement multi-field sorting (execution_order ASC, priority DESC)
- [ ] Add fuzzy title search with relevance scoring
- [ ] Implement query builder for composable filter chains
- [ ] Add GetTasksByStatus method with count aggregation
- [ ] Implement GetTasksByAgent with workload distribution metrics
- [ ] Add GetBlockedTasks with blocking duration calculation

### Non-Functional Requirements

- [ ] Query performance: List operations complete in <100ms for 10K tasks
- [ ] Memory efficiency: Pagination prevents loading entire result sets
- [ ] Type safety: Compile-time validation of filter combinations
- [ ] Code reuse: Filter logic extracted into reusable functions

## Implementation Plan

### Steps

1. [ ] Create TaskQueryBuilder type for composable filters
   - Support chaining: `.WithStatus("todo").WithAgent("backend").WithPriority(>5)`
   - Return filtered slice without modifying original
   - Extract filter predicates into separate functions for reuse

2. [ ] Implement pagination in ListTasks
   - Add `Limit` and `Offset` to TaskFilters struct
   - Apply pagination after all filters and sorting
   - Return total count alongside results for UI pagination

3. [ ] Add sorting support to ListTasks
   - Add `SortBy` and `SortOrder` to TaskFilters (support multiple fields)
   - Default sort: execution_order ASC, priority DESC (existing behavior)
   - Support sorting by: created_at, updated_at, key, title

4. [ ] Implement fuzzy title search
   - Add `TitleSearch` to TaskFilters
   - Use simple substring matching (case-insensitive)
   - Future: Consider fuzzy matching library if needed

5. [ ] Add GetTasksByStatus method
   - Group tasks by status with counts
   - Return map[string]int for quick status distribution
   - Use existing ListTasks under the hood

6. [ ] Add GetTasksByAgent method
   - Group tasks by agent with workload stats (count, avg priority)
   - Return structured data for capacity planning
   - Filter out completed tasks by default

7. [ ] Add GetBlockedTasks method
   - List all blocked tasks with blocking duration
   - Calculate duration from last status change timestamp
   - Include blocking reason from task notes

### Technical Approach

**Pattern**: Builder pattern for composable queries
- TaskQueryBuilder wraps filters and builds query incrementally
- Each builder method returns `*TaskQueryBuilder` for chaining
- `.Build()` executes query and returns results

**Example**:
```go
tasks, total, err := svc.Query().
    WithStatus("todo").
    WithAgent("backend").
    WithPriorityRange(5, 10).
    SortBy("priority", "DESC").
    Paginate(0, 20).
    Build(ctx)
```

**Trade-offs**:
- In-memory filtering (current): Simple, works for <10K tasks, no DB changes needed
- SQL WHERE clauses (future): Better performance for large datasets, requires repository updates
- Decision: Start with in-memory, migrate to SQL if performance issues arise
