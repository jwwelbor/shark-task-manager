## Specific Violations in epic_helpers.go

### 1. `performEpicCreate` — lines 685–701

```go
repoDb, err := cli.GetDB(ctx)        // line 685
...
epicRepo := repository.NewEpicRepository(repoDb)    // line 700
featureRepo := repository.NewFeatureRepository(repoDb) // line 701
```

**Function:** `performEpicCreate`
**Issue:** Epic creation uses repository directly instead of delegating to `cli.GetEpicService()`. The `getNextEpicKey()` call and the `epicRepo.GetByKey()` call for duplicate-key checking should be handled by the EpicService.

---

### 2. `performEpicUpdate` — status auto-recalculation — lines 1129–1146

```go
repoDb, dbErr := cli.GetDB(ctx)      // line 1129
...
calcService := status.NewCalculationService(repoDb, cfg)
result, calcErr := calcService.RecalculateEpicStatus(ctx, epic.ID)
```

**Function:** `performEpicUpdate` (inside `statusFlag == "auto"` branch)
**Issue:** The comment acknowledges this is a pre-E15 pattern not yet migrated. It must be migrated: either expose `RecalculateEpicStatus` on `EpicService` or create a dedicated status recalculation method on the service.

---

### 3. `performEpicUpdate` — cascade on force-complete — lines 1169–1181

```go
repoDb, dbErr := cli.GetDB(ctx)      // line 1169
...
epicRepo := repository.NewEpicRepository(repoDb)    // line 1177
epicRepo.CascadeStatusToFeaturesAndTasks(...)
```

**Function:** `performEpicUpdate` (inside `force && epicStatus == EpicStatusCompleted` branch)
**Issue:** The comment acknowledges this is not yet exposed through the service layer. The `EpicService` must expose a `CascadeStatusToFeaturesAndTasks` method (or equivalent) so the CLI helper can delegate to it.

---

### 4. `performEpicUpdate` — key rename — lines 1232–1244

```go
repoDb, dbErr := cli.GetDB(ctx)      // line 1232
...
epicRepo := repository.NewEpicRepository(repoDb)    // line 1240
epicRepo.UpdateKey(ctx, epicKey, newKey)
```

**Function:** `performEpicUpdate` (inside the `newKey != epicKey` branch)
**Issue:** The comment acknowledges this is not yet exposed as a dedicated service method. The `EpicService` must expose a `RenameEpicKey` or `UpdateKey` method.

## Required Changes

The developer must:

1. **`performEpicCreate`**: Replace direct `cli.GetDB` + `repository.NewEpicRepository` + `repository.NewFeatureRepository` calls with a call to `cli.GetEpicService()`. The EpicService should provide:
   - Next key generation (or expose `getNextEpicKey` via service)
   - Duplicate key check via `EpicService.GetEpic()`

2. **`performEpicUpdate` — auto status recalculation**: Add a method to `EpicService` (e.g., `RecalculateStatus`) that wraps `status.CalculationService.RecalculateEpicStatus`. Replace the direct DB + `status.NewCalculationService` usage in `epic_helpers.go` with a call to that service method.

3. **`performEpicUpdate` — cascade on force-complete**: Add a method to `EpicService` (e.g., `CascadeStatusToFeaturesAndTasks`) that wraps the repository's cascade call. Replace the direct DB + `repository.NewEpicRepository` usage with a service call.

4. **`performEpicUpdate` — key rename**: Add a method to `EpicService` (e.g., `RenameKey`) that wraps `epicRepo.UpdateKey`. Replace the direct DB + `repository.NewEpicRepository` usage with a service call.

After making these changes, re-verify:
- `grep -c "repository.New\|cli.GetDB" internal/cli/commands/epic_helpers.go` → must be 0
- `make test` → must pass
- `make lint` → must pass
