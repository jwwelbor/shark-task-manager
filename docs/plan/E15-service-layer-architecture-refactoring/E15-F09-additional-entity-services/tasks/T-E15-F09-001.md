# Task: Add missing CRUD and lifecycle unit tests to epic_service_test.go

## Context

`EpicService` is fully implemented at `internal/services/epic_service.go` (~1069 lines). The
existing test file `internal/services/epic_service_test.go` (1299 lines) covers status
transitions, rollup, progress, health, impediments, and action resolution. However, the test plan
(09-test-plan.md) identifies the following gaps that must be closed to meet the 80%+ coverage
target and satisfy the feature quality gates.

## Goal

Extend `internal/services/epic_service_test.go` with missing unit tests for CRUD operations,
`CompleteEpic`, `CascadeStatusToFeaturesAndTasks`, `RenameKey`, and nil-taskRepo graceful
degradation. All tests must use mocked repositories (no real database). The suite must pass with
`make test` and `make lint`.

## Acceptance Criteria

### CRUD Operations (AC1.1 - AC1.5 from test plan)

- [ ] `TestEpicService_CreateEpic_Success` - mock `CreateFunc` captures input; returned epic has
  non-empty key; `Create` called exactly once
- [ ] `TestEpicService_CreateEpic_ValidationError` - empty title triggers validation error before
  any repo call; `Create` not called
- [ ] `TestEpicService_UpdateEpic_Success` - `GetByKeyFunc` returns existing epic; `UpdateFunc`
  captures update; returned epic reflects changed fields; `Update` called once
- [ ] `TestEpicService_UpdateEpic_NotFound` - `GetByKeyFunc` returns `NotFoundError`; error
  propagated; `Update` not called
- [ ] `TestEpicService_DeleteEpic_Success` - `DeleteFunc` called with correct ID; no error returned
- [ ] `TestEpicService_DeleteEpic_NotFound` - `GetByKeyFunc` returns `NotFoundError`; `Delete` not
  called

### Lifecycle Operations (AC1.13 - AC1.14 from test plan)

- [ ] `TestEpicService_CompleteEpic_AllFeaturesComplete` - mock `EpicFeatureCounter` returns
  features all in terminal status; `Update` called to set completed status; no error returned
- [ ] `TestEpicService_CompleteEpic_FeaturesIncomplete` - mock `EpicFeatureCounter` returns
  features with non-terminal status; `force=false`; error returned; `Update` not called
- [ ] `TestEpicService_CompleteEpic_Force` - same setup as above but `force=true`; completion
  succeeds despite incomplete features; `Update` called
- [ ] `TestEpicService_CascadeStatusToFeaturesAndTasks` - mock `EpicFeatureCounter` returns 2
  features; mock task repo captures update calls; feature and task repos each called with new
  status; returns nil error
- [ ] `TestEpicService_CascadeStatusToFeaturesAndTasks_ZeroFeatures` - mock returns empty feature
  list; no task updates needed; no error returned

### Graceful Degradation (AC1.10 from test plan)

- [ ] `TestEpicService_GetImpediments_NilTaskRepo` already exists — verify it does NOT panic and
  returns empty `[]*Impediment{}` (not nil); add assertion for non-nil empty slice if missing

### Architecture Compliance (AC4.1, AC4.3 from test plan)

- [ ] Verify `grep -c "\.db\." internal/services/epic_service.go` returns 0 (no direct DB calls in
  service file); include this as a shell assertion in a comment or table test note
- [ ] Verify `NewEpicService` constructor calls `workflowSvc.ForLevel(workflow.LevelEpic)`

## Implementation Plan

### Steps

1. Open `internal/services/epic_service_test.go` and review mock structs available (look for
   `MockEpicRepository`, `MockEpicFeatureCounter`, `MockEpicNoteRepository`)
2. Check `internal/services/epic_service.go` signatures for `CreateEpic`, `UpdateEpic`,
   `DeleteEpic`, `CompleteEpic`, `CascadeStatusToFeaturesAndTasks` to confirm parameter and return
   types
3. Add mock method implementations if missing (e.g., `CreateFunc`, `UpdateFunc`, `DeleteFunc`,
   `DeleteByKeyFunc` on mock epic repo)
4. Write test cases in the following order: CRUD (Create, Update, Delete), then lifecycle
   (CompleteEpic variants, Cascade), then graceful degradation verification
5. Use table-driven tests for `CompleteEpic` force/no-force scenarios
6. Run `go test ./internal/services/ -run TestEpicService -v` to verify all new tests pass
7. Run `make fmt && make lint && make test` for full quality gate

### Technical Approach

- All tests must use mock repos defined in `mocks_test.go` or inline in `epic_service_test.go`
- No real database (`test.GetTestDB()`) allowed in this file
- Follow the function-field mock pattern already used in the file:
  ```go
  mockRepo := &MockEpicRepository{
      CreateFunc: func(ctx context.Context, epic *models.Epic) error {
          assert.Equal(t, "Test Epic", epic.Title)
          return nil
      },
  }
  ```
- Use `assert` from `github.com/stretchr/testify/assert` (already imported)
- Check `TestEpicService_GetImpediments_NilTaskRepo` at line 912 — update assertion if it only
  checks `err == nil` without checking that the slice is non-nil
