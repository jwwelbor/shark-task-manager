# Task: Add missing CRUD and lifecycle unit tests to feature_service_test.go

## Context

`FeatureService` is fully implemented at `internal/services/feature_service.go` (~1123 lines). The
existing test file `internal/services/feature_service_test.go` (1530 lines) covers status
transitions, progress calculation, health, work breakdown, action items, status breakdown, and
`RecalculateAndSetProgress`. However, the test plan (09-test-plan.md) identifies the following
gaps that must be closed to meet the 80%+ coverage target and satisfy the feature quality gates.

## Goal

Extend `internal/services/feature_service_test.go` with missing unit tests for CRUD operations
(`CreateFeature`, `UpdateFeature`, `DeleteFeature`), `CompleteFeature` (both force variants), and
`CascadeFeatureStatusToTasks`. All tests must use mocked repositories (no real database). The
suite must pass with `make test` and `make lint`.

### Technical Approach

- All tests use mocked repos — no `test.GetTestDB()` allowed in this file
- Follow the function-field mock pattern already used in the file:
  ```go

      CreateFunc: func(ctx context.Context, feature *models.Feature) error {
          assert.Equal(t, "New Feature", feature.Title)
          return nil
      },
  }
  ```
- `FeatureEpicLookup` interface is needed for `CreateFeature` and `ListFeaturesByEpicKey` — check
  if the mock for it already exists in the file, add if missing
- Use `assert` from `github.com/stretchr/testify/assert` (already imported)
