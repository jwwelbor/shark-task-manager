# Task: Create service_accessors_test.go with adapter unit tests and accessor integration tests

## Context

`internal/cli/service_accessors.go` wires `GetEpicService()` and `GetFeatureService()` for CLI
commands. It also contains `epicNoteAdapter` and `featureNoteAdapter` — adapter structs that
bridge the impedance mismatch between the service-layer `EpicNoteRepository`/`FeatureNoteRepository`
interfaces (which use plain `string` for entityType and documentPath) and the concrete
`*repository.EntityNoteRepository` (which uses `models.EntityType` and `*string`).

No test file for this module currently exists. This task creates
`internal/cli/service_accessors_test.go` covering:
1. Unit tests for the adapter translation logic
2. Integration tests verifying that `GetEpicService()` and `GetFeatureService()` return correctly
   wired, callable services using the test database

## Goal

Create `internal/cli/service_accessors_test.go` that verifies:
- `epicNoteAdapter` correctly translates `string` entityType to `models.EntityType` and empty
  documentPath to `nil *string` (non-empty to `*string`)
- `featureNoteAdapter` has identical correct translation behavior
- `GetEpicService()` returns a non-nil, usable `*services.EpicService` that can call `GetEpic`
- `GetFeatureService()` returns a non-nil, usable `*services.FeatureService` that can call
  `GetFeature`
- `GetEpicService()` wires `taskRepo` correctly (for `GetImpediments`)
- `GetEpicService()` wires `docRepo` via `SetDocRepo` (no nil pointer panic on doc access)
- `GetFeatureService()` uses `NewFeatureServiceWithRelationships` constructor

All tests must satisfy the test plan quality gates from 09-test-plan.md (AC3.1 - AC3.9).

## Implementation Plan

### Steps

1. Create file `internal/cli/service_accessors_test.go` in package `cli_test` (or `cli` depending
   on whether adapter types are exported)
2. Check if `epicNoteAdapter` and `featureNoteAdapter` are exported or unexported in
   `service_accessors.go` — if unexported, the test file must be in `package cli` (same package)
3. For adapter unit tests, create a `MockEntityNoteRepository` that captures the arguments passed
   to its `CreateRejectionNote` call:
   ```go
   type mockEntityNoteRepository struct {
       capturedEntityType  models.EntityType
       capturedDocPath     *string
   }
   func (m *mockEntityNoteRepository) CreateRejectionNote(ctx context.Context,
       entityType models.EntityType, entityID, historyID int64,
       fromStatus, toStatus, reason, rejectedBy string, documentPath *string) (*models.EntityNote, error) {
       m.capturedEntityType = entityType
       m.capturedDocPath = documentPath
       return &models.EntityNote{}, nil
   }
   ```
4. Construct adapter with mock: `adapter := &epicNoteAdapter{repo: mockRepo}`
5. For integration tests, set up test DB by calling `cli.ResetDB()` in defer and using the test
   database infrastructure already in place (check `internal/cli/db_global.go` for test helpers)
6. Run tests: `go test ./internal/cli/ -run TestGetEpicService -v`
7. Run `make fmt && make lint && make test` for full quality gate

### Technical Approach

- Adapter struct fields (`epicNoteAdapter.repo`) may be unexported — test file must be `package cli`
- For integration tests, check how other CLI tests initialize the DB (look at existing CLI test
  files for patterns using `cli.ResetDB()` or `test.GetTestDB()`)
- The integration tests verify wiring correctness: "does the accessor produce a service that works
  without panicking" — not that the underlying SQL is correct (that is a repository test)
- Do not duplicate service logic tests — those belong in `epic_service_test.go` and
  `feature_service_test.go`

### Key File References

- `internal/cli/service_accessors.go` - file being tested; contains adapter types and accessor functions
- `internal/cli/db_global.go` - global DB state; used for `GetDB()` in accessors
- `internal/repository/entity_note_repository.go` - concrete repo that adapters wrap
- `internal/services/epic_service.go`, `feature_service.go` - services returned by accessors
