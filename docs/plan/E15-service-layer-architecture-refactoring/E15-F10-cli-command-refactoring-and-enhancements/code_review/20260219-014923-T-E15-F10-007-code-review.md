## Remaining Blocking Issues

### Blocker 1: `task_deps.go` — `runTaskDeps` is 34 lines (lines 93–126)

```go
func runTaskDeps(cmd *cobra.Command, args []string) error {
    taskKey := args[0]
    filterTypes, _ := cmd.Flags().GetString("type")
    showTree, _ := cmd.Flags().GetBool("tree")
    upstream, _ := cmd.Flags().GetBool("upstream")
    downstream, _ := cmd.Flags().GetBool("downstream")
    maxDepth, _ := cmd.Flags().GetInt("max-depth")
    // ... 27 more lines including service calls, error handling, output formatting
```

**The fix:** The flag parsing block (5 lines) should be extracted into a helper function `parseTaskDepsOptions(cmd)` returning a struct. This would reduce the handler to ~22 lines.

### Blocker 2: `related_docs.go` — `runRelatedDocsAdd` is 34 lines (lines 74–107) and `runRelatedDocsListList` is 32 lines (lines 172–203)

Both handlers contain a repeated 3-way dispatch pattern (epic/feature/task) that inflates the line count. The dispatch for each entity type is only 2–4 lines, but together they push the handlers over 30 lines.

**For `runRelatedDocsAdd`:** Extract the entity resolution and service dispatch into a `dispatchDocumentLink(ctx, epic, feature, task, title, path)` helper.

**For `runRelatedDocsListList`:** Extract the entity dispatch into a `dispatchDocumentList(ctx, epic, feature, task, useJSON)` helper.

### Blocker 3: `idea.go` — `runIdeaConvertEpic` (32 lines), `runIdeaConvertFeature` (32 lines), `runIdeaConvertTask` (38 lines)

All three handlers follow the same pattern: get idea → create entity → mark converted → format output. The 32–38 lines arise from multi-line struct literals passed to service methods.

These handlers contain no business logic and correctly call services exclusively. However, the struct literal initializations span multiple lines. The 30-line limit is exceeded due to the verbose struct initialization syntax.

**Note on `runIdeaConvertTask` specifically:** This is 38 lines, the most egregious violation. It includes an inline `description` variable extraction (nil-guard) that could be moved to a `parseIdeaDescription(idea)` helper.

**The fix:** Extract a `formatIdeaConvertResult(ideaKey, entityKey, entityType string, extra map[string]string)` helper for the JSON/success output block, and optionally a `parseIdeaDescription(idea)` helper for the nil-guard.
