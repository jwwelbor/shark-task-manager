## Minor Observations (Non-Blocking)

These do not block QA approval but should be tracked for future cleanup:

### 1. UnlinkFile Method Name is Misleading (Minor Naming Issue)

`UnlinkFile` removes typed task *relationship* records (`depends_on`, `blocks`), not file system links. The name implies file operations. The docstring partially clarifies this but developers encountering the method name first will be confused.

Suggested future rename: `RemoveRelationship(ctx, taskKey, relType, targetKey)`.

This is a naming-only issue with no functional impact.

### 2. IdeaFilters.DateFrom / DateTo Not Forwarded to Repository (Minor Gap)

`IdeaFilters` in `idea_dto.go` defines `DateFrom` and `DateTo` fields, but `ListIdeas` in `idea_service.go` only maps `Status` to `repository.IdeaFilter`. The date filter fields are dropped silently.

If the repository supports date-range filtering, the service should wire those fields through. If not yet implemented in the repository, the DTO fields are misleading.

Non-blocking because the filter fields are additive and don't break existing behavior.

### 3. ListDependencies Comment Claims Logging But Does Not Log (Minor)

The inline comment in `ListDependencies` says "Log warning but continue" when a dependency task is not found, but there is no actual log call — the function just continues silently. This creates misleading documentation and masks potential data integrity issues (orphaned dependency records).

Non-blocking since graceful degradation is the right behavior; the comment should either be removed or an actual log statement added.
