# Task: Implement EpicService with CRUD and feature rollup operations

## Goal

Expand the existing EpicService (in `internal/services/epic_service.go`) with business logic methods for health analysis, impediment tracking, and feature rollup operations. Currently EpicService only has TransitionStatus, GetNextStatus, and ValidateStatus. This task adds the missing methods that CLI commands need to stop calling repositories directly.

## Requirements

### Functional Requirements

- [ ] FR-1: Implement `GetEpic(ctx, epicKey) (*models.Epic, error)` - retrieve epic by key with error wrapping
- [ ] FR-2: Implement `ListEpics(ctx, filters EpicFilters) ([]*models.Epic, error)` - list epics with optional status filter
- [ ] FR-3: Implement `GetHealth(ctx, epicKey) (*EpicHealthInfo, error)` - calculate health from feature statuses and blocked tasks
- [ ] FR-4: Implement `GetImpediments(ctx, epicKey) ([]*Impediment, error)` - analyze blocked tasks with age and priority
- [ ] FR-5: Implement `GetFeatureRollup(ctx, epicKey) (*FeatureRollup, error)` - aggregate feature statuses into rollup
- [ ] FR-6: Implement `GetTaskStatusRollup(ctx, epicKey) (map[string]int, error)` - aggregate task statuses across all features
- [ ] FR-7: Implement `GetProgress(ctx, epicKey) (*EpicProgressInfo, error)` - calculate epic progress from feature completion

### Non-Functional Requirements

- [ ] NFR-1: All methods must accept `context.Context` as first parameter
- [ ] NFR-2: All methods must return domain models and errors (no formatting)
- [ ] NFR-3: Service must use repository interfaces (not concrete types)
- [ ] NFR-4: All new methods must be tested with mocked repositories (no real DB)
- [ ] NFR-5: Error messages must include business context (e.g., "failed to get health for epic E15")

## Implementation Plan

### Steps

1. [ ] Step 1: Expand the `EpicRepository` interface in `epic_service.go` with the additional methods needed (GetByID, List, GetFeatureStatusBreakdown, GetTaskStatusRollup, GetFeatureStatusRollup)
2. [ ] Step 2: Add a `EpicTaskLister` interface for listing tasks across an epic (needed for impediments and health)
3. [ ] Step 3: Define DTOs: `EpicFilters`, `EpicHealthInfo`, `Impediment`, `FeatureRollup`, `EpicProgressInfo` in `epic_dto.go`
4. [ ] Step 4: Implement `GetEpic()` and `ListEpics()` - simple CRUD wrappers with error wrapping
5. [ ] Step 5: Implement `GetFeatureRollup()` - calls `epicRepo.GetFeatureStatusRollup()` and wraps into DTO
6. [ ] Step 6: Implement `GetTaskStatusRollup()` - calls `epicRepo.GetTaskStatusRollup()` and wraps result
7. [ ] Step 7: Implement `GetProgress()` - uses feature completion data to calculate epic progress
8. [ ] Step 8: Implement `GetHealth()` - analyzes feature statuses, blocked tasks, approval age to return healthy/warning/critical
9. [ ] Step 9: Implement `GetImpediments()` - finds blocked tasks, calculates age, returns structured data
10. [ ] Step 10: Write comprehensive tests for all new methods

### Technical Approach

**Existing code to reference:**
- `internal/status/calculation_service.go` - Has RecalculateEpicStatus which uses repo methods
- `internal/repository/epic_repository.go` - Has GetFeatureStatusRollup, GetTaskStatusRollup, CalculateProgress
- `internal/status/action_items.go` - Has GetActionItems logic for categorizing tasks
- `internal/cli/commands/epic.go` - Current fat controller with business logic to extract

**Interface expansion pattern:**
```go
// Add to existing EpicRepository interface
type EpicRepository interface {
    GetByKey(ctx context.Context, key string) (*models.Epic, error)
    Update(ctx context.Context, epic *models.Epic) error
    // NEW methods:
    GetByID(ctx context.Context, id int64) (*models.Epic, error)
    List(ctx context.Context, status *models.EpicStatus) ([]*models.Epic, error)
    GetFeatureStatusBreakdown(ctx context.Context, epicID int64) (map[models.FeatureStatus]int, error)
    GetFeatureStatusRollup(ctx context.Context, epicID int64) (map[string]int, error)
    GetTaskStatusRollup(ctx context.Context, epicID int64) (map[string]int, error)
    CalculateProgress(ctx context.Context, epicID int64) (float64, error)
}
```

**New task lister interface (for impediments):**
```go
// EpicTaskLister lists tasks across all features in an epic
type EpicTaskLister interface {
    ListByEpic(ctx context.Context, epicKey string) ([]*models.Task, error)
}
```

**Health calculation logic (from CLI/status package):**
- healthy: no blocked tasks, no approvals older than 3 days
- warning: approvals older than 3 days OR 1 blocked task
- critical: multiple blocked tasks OR high-priority blocked

**Constructor update:**
Update NewEpicService to accept optional EpicTaskLister dependency for impediment tracking.

## Notes
