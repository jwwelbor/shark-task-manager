## NON-BLOCKING ISSUES

### NB1: epic_dto.go contains DTOs for both EpicService AND FeatureService (epic_dto.go)

**File:** `epic_dto.go:41-92`

The file is named `epic_dto.go` but contains DTOs for both domains:
- Epic DTOs: `EpicFilters`, `EpicHealthInfo`, `Impediment`, `FeatureRollup`, `EpicProgressInfo` (lines 6-39)
- Feature DTOs: `FeatureFilters`, `FeatureProgressInfo`, `FeatureHealthInfo`, `WorkBreakdown`, `FeatureActionItems`, `ActionTaskItem` (lines 41-92)

**Recommendation:** Either rename the file to `dto.go` or split into `epic_dto.go` and `feature_dto.go`. This is a naming/organization issue that does not affect functionality but violates the Principle of Least Surprise -- a developer looking for `FeatureProgressInfo` would not expect to find it in `epic_dto.go`.

### NB2: EpicService.GetHealth does not check approval age (epic_service.go:410-449)

The architecture spec for health calculation states:
```
health = {
  "healthy" if no_blockers AND all_approvals_old_< 3_days,
  "warning" if approvals_old_> 3_days OR minor_blockers,
  "critical" if multiple_blockers OR high_priority_blocked
}
```

`EpicService.GetHealth` only checks blocked tasks and their priority. It does not check approval age. Meanwhile, `FeatureService.GetHealth` (feature_service.go) does check for stale approvals. This is an inconsistency between the two services.

**Recommendation:** Either add approval age checking to EpicService.GetHealth for consistency, or document why it is intentionally omitted at the epic level.
