# Task: Extract shared document linking helper for TaskService FeatureService EpicService

## Goal

Eliminate ~15-20 lines of duplicated code in `LinkDocument()` and `UnlinkDocument()` across TaskService, FeatureService, and EpicService. All three implementations are nearly identical - they should share a common helper.

## Requirements

### Functional Requirements

- [ ] Create a shared helper function or generic wrapper for document link/unlink operations
- [ ] TaskService.LinkDocument() / UnlinkDocument() uses shared helper
- [ ] FeatureService.LinkDocument() / UnlinkDocument() uses shared helper
- [ ] EpicService.LinkDocument() / UnlinkDocument() uses shared helper
- [ ] Helper should accept an interface for the writable document repository (since each entity has a slightly different type)

### Non-Functional Requirements

- [ ] No behavioral changes
- [ ] Reduces duplicated code by ~60-90 lines across 3 services
- [ ] All tests pass

## Implementation Plan

### Steps

1. [ ] Compare LinkDocument/UnlinkDocument implementations across all 3 services to identify exact commonalities and differences
2. [ ] Design a shared interface that captures the common document repository methods (CreateOrGet, GetByTitle, LinkToEntity, UnlinkFromEntity)
3. [ ] Create shared helper in `internal/services/document_helpers.go` (or similar)
4. [ ] Refactor all 3 services to use the shared helper
5. [ ] Ensure existing tests still pass
6. [ ] Run `make fmt && make lint && make test`

### Technical Approach

Option A: Generic helper function with entity-type-specific adapters
```go
func linkDocument(ctx context.Context, repo WritableDocumentRepo, entityID int64, title, content string) error
```

Option B: Embed shared struct in each service
```go
type DocumentLinker struct { repo WritableDocumentRepo }
func (d *DocumentLinker) LinkDocument(ctx, entityID, title, content) error
```

Choose whichever approach fits Go idioms better.

## Acceptance Criteria

- [ ] No duplicated LinkDocument/UnlinkDocument code across services
- [ ] Shared helper is well-tested
- [ ] All existing tests pass

## Dependencies

- None (independent of repo cleanup tasks)
