# Task: Extract workflow validation from TaskRepository to TaskService

## Goal

Remove `isValidStatusEnum()` and `isValidTransition()` methods (~lines 818-860) from TaskRepository. These methods validate statuses and transitions against the workflow config, which is business logic that belongs in the service layer (via `workflow.Service`).

## Requirements

### Functional Requirements

- [ ] Remove `TaskRepository.isValidStatusEnum()` method
- [ ] Remove `TaskRepository.isValidTransition()` method
- [ ] Ensure TaskService uses `workflow.Service.ValidateStatus()` and `ValidateTransition()` for all validation
- [ ] Verify no other code paths call the repository validation methods directly
- [ ] Remove any remaining references to workflow config within TaskRepository query methods

### Non-Functional Requirements

- [ ] No behavioral changes for end users
- [ ] All existing tests pass
- [ ] Workflow validation coverage maintained via service-level tests

## Implementation Plan

### Steps

1. [ ] Audit all callers of `isValidStatusEnum()` and `isValidTransition()` in task_repository.go
2. [ ] Ensure each call site has equivalent validation in the service layer (TaskService methods should already validate via `s.workflowSvc`)
3. [ ] Remove the two methods from TaskRepository
4. [ ] Remove any workflow config usage that's no longer needed in the repository
5. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- These methods are currently called within `updateStatusForcedInternal()` which is being extracted in T-E15-F13-001
- After T-E15-F13-001 is complete, these methods should have no remaining callers in the repository
- The service layer already has `s.workflowSvc.ValidateTransition()` calls

## Acceptance Criteria

- [ ] No `isValidStatusEnum` or `isValidTransition` methods exist in TaskRepository
- [ ] All workflow validation happens through `workflow.Service` in the service layer
- [ ] All tests pass

## Dependencies

- T-E15-F13-001 (status orchestration extraction should happen first)
