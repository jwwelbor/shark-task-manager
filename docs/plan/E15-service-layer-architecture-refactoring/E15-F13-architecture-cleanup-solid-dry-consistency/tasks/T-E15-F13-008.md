# Task: Standardize GetByKey slug lookup across all entity repositories

## Goal

All three entity repositories (Epic, Feature, Task) implement GetByKey with slug lookup using different algorithms. Standardize them to use a single shared approach, reducing code duplication and ensuring consistent behavior.

Current inconsistencies:
- **EpicRepository** (~lines 99-182): Tries numeric match, then slug lookup after numeric fails
- **FeatureRepository** (~lines 112-148): Tries exact, numeric, then slugged
- **TaskRepository** (~lines 180-292): Different parsing strategy entirely

## Requirements

### Functional Requirements

- [ ] Create a shared slug lookup helper (e.g., `internal/repository/key_lookup.go`)
- [ ] Helper implements the standard algorithm: try exact key match -> parse key to extract numeric + slug -> query with both
- [ ] EpicRepository.GetByKey() uses shared helper
- [ ] FeatureRepository.GetByKey() uses shared helper
- [ ] TaskRepository.GetByKey() uses shared helper
- [ ] All key formats still work: numeric (`E07`), slugged (`E07-user-management`), case insensitive

### Non-Functional Requirements

- [ ] All existing GetByKey tests pass without changes
- [ ] Performance unchanged (numeric lookup tried first)
- [ ] Reduces duplicated lookup code by ~200 lines

## Implementation Plan

### Steps

1. [ ] Read and compare all 3 GetByKey implementations to document exact differences
2. [ ] Design shared helper that handles: key parsing, slug extraction, case normalization
3. [ ] Create `internal/repository/key_lookup.go` with shared helper
4. [ ] Refactor EpicRepository.GetByKey() to use shared helper
5. [ ] Refactor FeatureRepository.GetByKey() to use shared helper
6. [ ] Refactor TaskRepository.GetByKey() to use shared helper
7. [ ] Run all repository tests to verify no regressions
8. [ ] Run `make fmt && make lint && make test`

### Technical Approach

The shared helper could accept:
- The database connection
- The table name and column names
- The key string to look up
- A scan function (to handle different column sets per entity)

Or use a simpler approach with just key parsing/normalization shared.

## Acceptance Criteria

- [ ] Single GetByKey algorithm used across all 3 repos
- [ ] All key formats (numeric, slugged, case variants) work for all entities
- [ ] All existing tests pass
- [ ] Shared code in a single file

## Dependencies
