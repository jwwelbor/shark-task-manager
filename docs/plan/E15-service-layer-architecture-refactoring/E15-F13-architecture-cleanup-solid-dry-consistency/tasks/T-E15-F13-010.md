# Task: Fix analytics command os.Exit usage and extract constructor validation helper

## Goal

Two minor cleanup items:

1. **analytics.go os.Exit()**: The analytics command (~line 55) calls `os.Exit(3)` directly instead of returning an error. This bypasses Cobra's cleanup hooks and makes the command untestable. Should return error like all other commands.

2. **Constructor validation helper**: Every service constructor has the same nil-check panic pattern:
```go
if repo == nil {
    panic("XxxService requires a non-nil XxxRepository")
}
if workflowSvc == nil {
    panic("XxxService requires a non-nil workflow.Service")
}
```
This is duplicated ~6 times. Extract a `requireNonNil(value, name)` helper.

## Requirements

### Functional Requirements

- [ ] Replace `os.Exit()` calls in analytics.go with error returns
- [ ] Create `requireNonNil(value interface{}, name string)` helper in `internal/services/` (or similar)
- [ ] Replace all constructor nil-check panic blocks with helper calls
- [ ] Helper should panic with clear message: `"ServiceName requires a non-nil DependencyName"`

### Non-Functional Requirements

- [ ] analytics command behavior unchanged (errors still cause non-zero exit)
- [ ] Constructor panics produce same messages
- [ ] All tests pass

## Implementation Plan

### Steps

1. [ ] Fix analytics.go: replace `os.Exit(3)` with `return fmt.Errorf(...)`

4. [ ] Run `make fmt && make lint && make test`
