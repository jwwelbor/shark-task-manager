# Task: Unify service constructor patterns for optional dependencies

## Goal

Standardize how services handle optional dependencies. Currently:
- TaskService: 2 constructors + 4 setters (SetFeatureRepo, SetHistoryRepo, SetFeatureService, SetDepRepo)
- FeatureService: 2 constructors + 1 setter
- EpicService: 2 constructors + 2 setters
- NoteService: 1 constructor + 0 setters
- ContextService: 1 constructor + 0 setters

Pick ONE pattern and apply consistently across all services.

## Requirements

### Functional Requirements

- [ ] Choose one approach for optional dependencies (evaluate options below)
- [ ] Apply chosen pattern to TaskService, FeatureService, EpicService
- [ ] Remove `NewXxxServiceWithRelationships()` variant constructors if adopting a different pattern
- [ ] Update `services_global.go` and `cmd/server/services.go` wiring to use new pattern
- [ ] Document the chosen pattern in `.claude/rules/services/service-design.md`

### Options to Evaluate

**Option A: Functional Options Pattern**
```go
func NewTaskService(repo TaskRepo, workflow *workflow.Service, opts ...TaskServiceOption) *TaskService
type TaskServiceOption func(*TaskService)
func WithHistoryRepo(r HistoryRepo) TaskServiceOption { ... }
func WithFeatureService(s *FeatureService) TaskServiceOption { ... }
```

**Option B: Consistent Setters (current, just standardize naming)**
- Keep setter pattern but ensure every service follows same naming: `SetXxxRepo()`, `SetXxxService()`
- Remove variant constructors, use single constructor + setters

**Option C: Single Constructor with Nil-safe Optional Params**
```go
func NewTaskService(repo TaskRepo, workflow *workflow.Service, opts *TaskServiceOpts) *TaskService
type TaskServiceOpts struct {
    HistoryRepo  HistoryRepo
    FeatureSvc   *FeatureService
    ...
}
```

### Non-Functional Requirements

- [ ] Consistent cognitive model for "how do I construct a service?"
- [ ] All tests pass
- [ ] DI wiring code is cleaner

## Implementation Plan

### Steps

1. [ ] Evaluate each option against Go idioms and project size
