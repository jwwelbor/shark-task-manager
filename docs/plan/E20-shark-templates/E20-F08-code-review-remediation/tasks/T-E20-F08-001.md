# Task: Fix silent file permission reset in writeConfig (H-3)

## Goal

The `writeConfig` method in `internal/init/profile_service.go` (line 289-336) reads the existing file permissions via `os.Stat` but then discards the result (`_ = info.Mode().Perm()`). The temp file created by `os.CreateTemp` gets default permissions (typically 0600), and after `os.Rename` the config file silently loses its original permissions. Fix this so that existing file permissions are preserved across writes.

## Requirements

### Functional Requirements

- [ ] Read existing file permissions before writing (if file exists)
- [ ] Apply the original permissions to the temp file before renaming via `os.Chmod`
- [ ] Default to 0644 if the file does not already exist
- [ ] Ensure the `writeConfig` function in `manager.go` (which already handles this correctly at line 110-113) is not regressed

### Non-Functional Requirements

- [ ] No behavioral change for new files (0644 default is fine)

## Implementation Plan

### Steps

1. [ ] In `writeConfig` (profile_service.go), capture the file permissions from `os.Stat` into a variable instead of discarding with `_`
2. [ ] After writing to the temp file and before `os.Rename`, call `os.Chmod(tmpPath, filePerms)` to apply the original permissions
3. [ ] Add a test that creates a config with non-default permissions (e.g., 0600), calls writeConfig, and verifies permissions are preserved

### Files to Modify

- `internal/init/profile_service.go` (lines 290-295)

## Acceptance Criteria

- [ ] Existing file permissions are preserved after `writeConfig` is called
- [ ] New files default to 0644
- [ ] Unit test verifies permission preservation
- [ ] `make fmt && make lint && make test` passes

## Testing Strategy

- [ ] Test: create a file with 0600 perms, call writeConfig, verify perms are still 0600
- [ ] Test: call writeConfig on a non-existent path, verify file is created with 0644
