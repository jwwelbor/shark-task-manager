# Task: Fix unsafe type assertion panic in config show (H-4)

## Goal

The `configShowCmd` in `internal/cli/commands/config.go` (lines 93 and 99) uses bare type assertions (`value.(map[string]interface{})` and `value.(map[string]string)`) without the comma-ok idiom. If the database config or workflow sources value has an unexpected type (e.g., due to a malformed `.sharkconfig.json`), these assertions will panic and crash the CLI. Convert to safe type assertions with graceful fallback.

## Requirements

### Functional Requirements

- [ ] Replace `dbMap := value.(map[string]interface{})` (line 93) with comma-ok pattern
- [ ] Replace `sourcesMap := value.(map[string]string)` (line 99) with comma-ok pattern
- [ ] On type assertion failure, print the value using `fmt.Sprintf("%v", value)` instead of panicking

### Non-Functional Requirements

- [ ] No change to JSON output mode (only affects human-readable output)
- [ ] No panics from `shark config show` regardless of config file content

## Implementation Plan

### Steps

1. [ ] Change line 93 to: `dbMap, ok := value.(map[string]interface{}); if !ok { fmt.Printf("  %s: %v\n", key, value); continue }`
2. [ ] Change line 99 to: `sourcesMap, ok := value.(map[string]string); if !ok { fmt.Printf("  %s: %v\n", key, value); continue }`
3. [ ] Add test with malformed config that would trigger the assertion failure

### Files to Modify

- `internal/cli/commands/config.go` (lines 91-102)

## Acceptance Criteria

- [ ] `shark config show` does not panic with any valid or invalid config
- [ ] Normal output is unchanged for well-formed configs
- [ ] `make fmt && make lint && make test` passes

## Testing Strategy

- [ ] Manual test: corrupt database config in `.sharkconfig.json` to be a string instead of map, run `shark config show`
- [ ] Verify no panic occurs and value is printed as-is
