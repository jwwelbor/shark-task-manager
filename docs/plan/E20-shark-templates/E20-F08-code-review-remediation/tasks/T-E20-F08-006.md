# Task: Fix os.Exit in configValidateCmd and test cache pollution (M-5, M-6)

## Goal

Two related issues in configuration commands:

**M-5**: The `configValidateCmd` in `internal/cli/commands/config.go` (lines 161, 243) calls `os.Exit(1)` directly inside a Cobra `RunE` handler. This bypasses Cobra's `PersistentPostRunE` cleanup hooks (which close the database connection) and makes the command untestable. Should return an error instead.

**M-6**: The workflow config loading uses a package-level cache (`multiLevelCache` in `workflow_parser.go`). Tests that load different configs in sequence may see stale cache entries. Verify that `ClearWorkflowCache()` is called appropriately in tests, and add `t.Cleanup` calls where missing.

## Requirements

### Functional Requirements

- [ ] Replace `os.Exit(1)` calls in `configValidateCmd` (lines 161, 243) with returning an error from `RunE`
- [ ] Also fix `os.Exit(2)` and `os.Exit(1)` calls in `configGetStatusAction` (lines 667-699) to return errors
- [ ] Audit config-related tests for cache pollution and add `ClearWorkflowCache()` cleanup where needed

### Non-Functional Requirements

- [ ] Exit behavior should be equivalent (non-zero exit on validation failure) -- Cobra handles this when RunE returns an error
- [ ] No test pollution between test cases

## Implementation Plan

### Steps

1. [ ] In `configValidateCmd`, replace `os.Exit(1)` on lines 161 and 243 with `return fmt.Errorf("validation failed")`
2. [ ] In `configGetStatusAction` function, replace `os.Exit` calls with error returns
3. [ ] Review test files in `internal/config/` for tests that load workflow configs without calling `ClearWorkflowCache()` between cases
4. [ ] Add `t.Cleanup(config.ClearWorkflowCache)` where needed

### Files to Modify
