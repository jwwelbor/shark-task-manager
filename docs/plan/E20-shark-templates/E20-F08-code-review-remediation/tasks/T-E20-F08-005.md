# Task: Include require_rejection_reason in extractWorkflowData output (M-4)

## Goal

The `extractWorkflowData()` function in `internal/init/profile_service.go` (line 248) constructs the task workflow block from legacy top-level keys when `task_workflow` block is absent. It copies `status_flow`, `status_metadata`, `special_statuses`, `status_flow_version`, and `orchestrator_actions` -- but omits `require_rejection_reason`. This means when configs are migrated from legacy format to `.sharkworkflow.json`, the `require_rejection_reason` setting is silently dropped.

## Requirements

### Functional Requirements

- [ ] Add `require_rejection_reason` to the list of legacy keys extracted into the task workflow block
- [ ] Only include it if present in the merged config (follow the existing `if ok` pattern)
- [ ] Verify the key name matches what `parseTopLevelTaskWorkflow()` in `workflow_parser.go` (line 436) expects

### Non-Functional Requirements

- [ ] No change to behavior when `require_rejection_reason` is not set in config

## Implementation Plan

### Steps

1. [ ] In `extractWorkflowData()` (profile_service.go line 248-287), add a check for `require_rejection_reason` key alongside the existing checks for `status_flow`, `status_metadata`, etc.
2. [ ] Add it after the `orchestrator_actions` check (around line 280)
3. [ ] Add a test that verifies `require_rejection_reason: true` in merged config appears in the extracted task_workflow block

### Files to Modify

- `internal/init/profile_service.go` (add ~3 lines in extractWorkflowData)

## Acceptance Criteria

- [ ] `extractWorkflowData` includes `require_rejection_reason` in task_workflow block when present in merged config
- [ ] Existing tests in `internal/init/profile_service_test.go` continue to pass
- [ ] New test verifies the inclusion of `require_rejection_reason`
- [ ] `make fmt && make lint && make test` passes

## Testing Strategy

- [ ] Unit test: merged config with `require_rejection_reason: true` -> verify it appears in extracted task_workflow
- [ ] Unit test: merged config without `require_rejection_reason` -> verify task_workflow does not include it
