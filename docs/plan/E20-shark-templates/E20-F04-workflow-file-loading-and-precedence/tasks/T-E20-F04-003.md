# Task: Add WorkflowConfig field and template directory precedence

## Goal

Add the `WorkflowConfig *string` field to the `Config` struct for configurable workflow file paths, extract it in `Manager.Load()`, add `TemplateDirectory *string` to `MultiLevelWorkflow`, and implement template directory precedence (workflow file > config > default). This enables custom workflow file locations and ensures the template directory setting follows the same precedence chain as entity workflows.

## Success Criteria

- `Config` struct has `WorkflowConfig *string` field with `json:"workflow_config,omitempty"` tag
- `Manager.Load()` extracts `workflow_config` from raw JSON and populates the field
- `MultiLevelWorkflow` has `TemplateDirectory *string` field
- Custom `workflow_config` path is resolved correctly (relative to project root, absolute paths supported)
- Template directory from workflow file wins over config value
- Missing custom path falls back silently to inline data
- Empty string `""` for `workflow_config` is treated as absent

## Requirements

### Functional Requirements

- [ ] REQ-F04-004 AC-1: Custom path -- `workflow_config` points to non-default location, system loads from it
- [ ] REQ-F04-004 AC-2: Missing custom path -- falls back to inline config, no error
- [ ] REQ-F04-004 AC-3: Absent key -- system checks default `.sharkworkflow.json`
- [ ] REQ-F04-004 AC-4: Empty string -- treated as absent
- [ ] REQ-F04-004 AC-5: Absolute path supported
- [ ] REQ-F04-004 AC-6: Relative paths resolved relative to config directory
- [ ] REQ-F04-005: `Config` struct has `WorkflowConfig *string` field; extracted by `Manager.Load()`
- [ ] REQ-F04-006 AC-1: `template_directory` from workflow file wins over config
- [ ] REQ-F04-006 AC-2: Fallback to `.sharkconfig.json` when workflow file omits it
- [ ] REQ-F04-006 AC-3: Fallback to default `"shark-templates"` when neither file has it

### Non-Functional Requirements

- [ ] REQ-NF04-001: Zero breaking changes -- existing configs without `workflow_config` work identically
- [ ] REQ-NF04-004: All new tests use `t.TempDir()` and fixture files

## Implementation Plan

### Key Files to Modify

1. `internal/config/config.go` -- Add `WorkflowConfig *string` field to `Config` struct
2. `internal/config/manager.go` -- Extract `workflow_config` from raw JSON in `Manager.Load()`
3. `internal/config/workflow_multilevel.go` (or equivalent) -- Add `TemplateDirectory *string` to `MultiLevelWorkflow`
4. `internal/config/workflow_parser.go` -- Update `resolveWorkflowFilePath()` to read `workflow_config` from config; extract `template_directory` from workflow file into `MultiLevelWorkflow.TemplateDirectory`

### Steps

1. [ ] Add `WorkflowConfig *string json:"workflow_config,omitempty"` to `Config` struct in `config.go`
2. [ ] In `Manager.Load()`, extract `workflow_config` from raw JSON data and populate `Config.WorkflowConfig`
3. [ ] Add `TemplateDirectory *string` field to `MultiLevelWorkflow` struct
4. [ ] Update `resolveWorkflowFilePath()` in `workflow_parser.go` to use `workflow_config` value when present:
   - Non-empty string: resolve relative to config directory (or use as-is if absolute)
   - Empty string or nil: use default `.sharkworkflow.json` in config directory
5. [ ] In `LoadMultiLevelWorkflow()`, after parsing workflow file, extract `template_directory` and set `result.TemplateDirectory`
6. [ ] Update `GetTemplateDirectory()` (or create `GetTemplateDirectoryFromConfig()`) to check `MultiLevelWorkflow.TemplateDirectory` first, then `Config.TemplateDirectory`, then default
7. [ ] Write tests for custom path scenarios, template directory precedence

### Technical Approach (from Architecture Doc)

Per ADR-F04-006: `TemplateDirectory *string` on `MultiLevelWorkflow` keeps template dir coupled with workflow data. Precedence: workflow file > config > `DefaultTemplateDir` constant.

Per Section 3.2-3.3 of architecture doc: Minimal changes -- one field on `Config`, one field on `MultiLevelWorkflow`, one extraction line in `Manager.Load()`.
