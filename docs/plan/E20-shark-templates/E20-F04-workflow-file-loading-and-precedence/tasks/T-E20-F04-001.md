# Task: Standardize task workflow to use task_workflow block pattern

## Goal

Add `task_workflow` block parsing to `LoadMultiLevelWorkflow()` in `workflow_parser.go`, using the same `parseWorkflowSection()` function already used for epic, feature, bug, and change entity types. When a `task_workflow` block is present in the config, it takes precedence over the legacy top-level keys. The legacy `parseTopLevelTaskWorkflow()` function is retained as a backward-compatible fallback.

This task was originally scoped as feature E20-F03 but was reclassified during scope validation as a single atomic change applying an existing pattern.

## Requirements

### Functional Requirements (REQ-F-005)

- [ ] `LoadMultiLevelWorkflow()` checks for a `task_workflow` block before falling back to `parseTopLevelTaskWorkflow()`
- [ ] `task_workflow` block is parsed via the existing `parseWorkflowSection()` function (same as epic/feature/bug/change)
- [ ] When `task_workflow` block is present, it populates `MultiLevelWorkflow.Task`
- [ ] When no `task_workflow` block is present, legacy `parseTopLevelTaskWorkflow()` fallback is used (no behavior change)
- [ ] When both `task_workflow` block and legacy top-level keys exist, the block takes precedence

### Non-Functional Requirements

- [ ] Zero breaking changes: existing configs without `task_workflow` block work identically (REQ-NF-001)
- [ ] Single parsing path: eliminates task-specific bifurcation in config loading (REQ-NF-003)
- [ ] Test isolation: new tests use fixtures, not production config (REQ-NF-004)

## Implementation Plan

### Key Files to Modify

1. `internal/config/workflow_parser.go` -- Add `task_workflow` block check in `LoadMultiLevelWorkflow()` before the legacy `parseTopLevelTaskWorkflow()` call
2. `internal/config/workflow_parser_test.go` or `workflow_multilevel_test.go` -- Add test cases

### Steps

1. [ ] In `LoadMultiLevelWorkflow()`, add a check for `task_workflow` key in the config map
2. [ ] If present, call `parseWorkflowSection()` with the `task_workflow` data (same function used for other 4 entity types)
3. [ ] Assign result to `MultiLevelWorkflow.Task`
4. [ ] Only fall through to `parseTopLevelTaskWorkflow()` if `task_workflow` block was not found
5. [ ] Add tests: block parsed correctly, legacy fallback works, block takes precedence over legacy keys, full regression with current config

### Estimated Scope

- ~15-20 lines of new code in `workflow_parser.go`
- ~100-150 lines of new tests
- Complexity: S (Small)

## Acceptance Criteria

- [ ] Config with `task_workflow` block: `MultiLevelWorkflow.Task` populated from the block
- [ ] Config without `task_workflow` block: `MultiLevelWorkflow.Task` populated from legacy top-level keys (identical to pre-change behavior)
- [ ] Config with both: block takes precedence, legacy keys ignored
- [ ] All existing tests pass without modification
- [ ] `make fmt && make lint && make test` passes
