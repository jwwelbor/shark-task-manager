# Task: Performance benchmark and regression tests

## Goal

Add performance benchmarks to verify the two-file loading model stays within the 5ms latency budget, add a regression test comparing config-only loading to a known-good baseline, verify legacy cache synchronization, verify the single-code-path NFR, and run full `make test` as the final regression gate.

## Success Criteria

- Benchmark `BenchmarkLoadMultiLevelWorkflow_TwoFiles` shows <5ms per operation
- Regression test confirms config-only loading produces identical results to pre-E20-F04 behavior
- Legacy `workflowCache` is synchronized with the winning task workflow source
- `grep` verification confirms no workflow-file-awareness outside `internal/config/`
- Full `make test` passes with no modifications to existing tests

### Steps

1. [ ] Add `BenchmarkLoadMultiLevelWorkflow_TwoFiles` -- both files present with full advanced profile (~1500 lines), measure ns/op; target <5ms
2. [ ] Add `BenchmarkLoadMultiLevelWorkflow_ConfigOnly` -- config-only baseline for comparison; measure overhead delta
3. [ ] Add `TestLoadMultiLevelWorkflow_RegressionNoWorkflowFile` -- load production-shaped config (advanced profile), compare result field-by-field against a known-good baseline
4. [ ] Add `TestLoadMultiLevelWorkflow_LegacyCacheSync` -- after loading with both files, verify `GetWorkflowOrDefault()` returns same task workflow as `result.Task`
5. [ ] Add `TestLoadMultiLevelWorkflow_CacheClearedBetweenLoads` -- load config A, clear cache, load config B, verify second load returns config B data
6. [ ] Add `TestLoadMultiLevelWorkflow_ResolutionHappensOnce` -- verify via `grep` that `.sharkworkflow.json` references only exist in `internal/config/` Go files (excluding test fixtures and docs)
7. [ ] Run `make fmt && make lint && make test` as final validation

### Technical Approach

**Benchmarks**: Use `t.TempDir()` with realistic fixture files (~1500 lines of JSON, matching the current advanced profile size). Call `ClearWorkflowCache()` in each benchmark iteration to avoid cache hits. Use `b.ReportAllocs()` for memory profiling.

**Regression test**: Build a known-good `MultiLevelWorkflow` from the same fixture data using the pre-E20-F04 code path (config-only, no workflow file), then compare against the post-E20-F04 code path with the same config-only setup. Assert field-by-field equality.

**Cache verification**: The legacy `workflowCache` is populated from `result.Task` at the end of `LoadMultiLevelWorkflow()`. Test that `GetWorkflowOrDefault()` returns the same `*WorkflowConfig` pointer as `result.Task`.
