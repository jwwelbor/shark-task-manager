# Task: Generate .sharkworkflow.json from init update command

## Goal

Update `ProfileService.ApplyProfile()` in `internal/init/profile_service.go` so that when `--workflow=advanced|basic` is specified, it also writes a `.sharkworkflow.json` file containing all five entity workflow blocks. The existing `.sharkconfig.json` writing continues unchanged.

## Context

- Feature spec: `docs/plan/E20-shark-templates/E20-F05-init-update-workflow-file-generation/feature.md`
- E20-F04 (completed) added workflow file loading in `internal/config/workflow_parser.go`
- The workflow file format uses keys: `epic_workflow`, `feature_workflow`, `task_workflow`, `bug_workflow`, `change_workflow`
- `task_workflow` must use block format (not legacy top-level `status_flow`/`status_metadata` keys)

## Requirements

- [ ] `shark init update --workflow=advanced` generates `.sharkworkflow.json` alongside `.sharkconfig.json`
- [ ] `shark init update --workflow=basic` generates `.sharkworkflow.json` with basic profile
- [ ] Generated file contains all 5 entity workflow blocks in `{entity}_workflow` format
- [ ] `task_workflow` uses block format (matches epic/feature/bug/change structure)
- [ ] `--dry-run` shows workflow file preview without writing it
- [ ] If `.sharkworkflow.json` already exists, create timestamped backup before overwriting
- [ ] Generated file is valid JSON loadable by the E20-F04 workflow file loader

## Implementation Guidance

### Files to Modify

1. `internal/init/profile_service.go` - Add workflow file generation to `ApplyProfile()`
2. `internal/init/types.go` - Add `WorkflowFilePath` to `UpdateResult`
3. `internal/init/profiles.go` or wherever `GetProfileMap()` lives - Extract workflow-only data

### Approach

- After the existing `.sharkconfig.json` write succeeds, extract workflow keys from the merged config
- Write them to `.sharkworkflow.json` using the same atomic write pattern
- Reuse `createConfigBackup()` for the workflow file backup
- For dry-run, include workflow file content in the result

## Acceptance Criteria

- [ ] `shark init update --workflow=advanced` creates both files
- [ ] `shark init update --workflow=basic` creates both files
- [ ] `--dry-run` shows what would be written without creating files
- [ ] Existing `.sharkworkflow.json` gets timestamped backup
- [ ] Generated file passes `shark config validate`
- [ ] All existing `init_update_test.go` tests still pass
- [ ] `make fmt && make lint && make test` passes

## Dependencies

- E20-F04 (completed) - Workflow file loading
