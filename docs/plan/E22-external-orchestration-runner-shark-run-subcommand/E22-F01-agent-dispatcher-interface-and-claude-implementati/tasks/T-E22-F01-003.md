# Implement ClaudeDispatcher with command construction and subprocess execution

## Goal

Implement `ClaudeDispatcher`, the concrete `AgentDispatcher` that invokes the `claude` CLI via `os/exec`. This struct must correctly construct the `claude -p` command with all required flags (disallowed tools, output format, max turns, allowed tools, model), capture stdout and stderr independently, handle context cancellation, and validate tool availability before dispatch.

## Scope

- Files to create:
  - `internal/runner/claude_dispatcher.go` — ClaudeDispatcher struct, DefaultDisallowedTools package variable, Dispatch() and Name() methods

## Acceptance Criteria

See spec.md Functional Requirements REQ-F01-004, REQ-F01-005, REQ-F01-006.

- AC-T1: `ClaudeDispatcher.Name()` returns `"claude"`
- AC-T2: `Dispatch()` calls `exec.LookPath("claude")` before construction; returns `ToolNotFoundError` if missing
- AC-T3: Command includes `claude -p "<instruction>" --output-format json` as base structure
- AC-T4: `DefaultDisallowedTools` package variable contains all 6 patterns from REQ-F01-005
- AC-T5: All 6 default disallowed tools are passed as `--disallowedTools` flags; user-specified `DisallowedTools` are appended additively
- AC-T6: `--max-turns N` flag included only when `DispatchInput.MaxTurns > 0`
- AC-T7: `--allowedTools` entries included only when `DispatchInput.AllowedTools` is non-empty
- AC-T8: `--model` flag included only when `DispatchInput.Model` is non-empty
- AC-T9: `cmd.Dir` set to `DispatchInput.WorkingDir` when non-empty; not set when empty
- AC-T10: Uses `exec.CommandContext(ctx, ...)` for context cancellation support
- AC-T11: Stdout and stderr captured independently (separate pipes or equivalent)
- AC-T12: `DispatchResult.Command` is populated with a non-empty command string
- AC-T13: `cmdFactory` function field on the struct enables test substitution without executing real subprocesses
