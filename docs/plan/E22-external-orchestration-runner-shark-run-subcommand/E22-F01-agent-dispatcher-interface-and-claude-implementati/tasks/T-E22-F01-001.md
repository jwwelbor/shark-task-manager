# Extend OrchestratorAction and PopulatedAction with Provider and Model fields

## Goal

Add `Provider` and `Model` fields to the existing `OrchestratorAction` and `PopulatedAction` config structs. These fields allow the run controller (future feature) to select which AI agent CLI to invoke and which model to use per workflow status. Both fields are optional (`omitempty`) so all existing configs remain backward-compatible.

## Scope

- Files to modify:
  - `internal/config/orchestrator_action.go` — add Provider and Model to OrchestratorAction struct
  - `internal/config/action_service.go` — add Provider and Model to PopulatedAction struct and copy them in GetStatusActionPopulated()

## Acceptance Criteria

See spec.md Architecture Section 5.2 for exact struct definitions and the rationale.

- AC-T1: `OrchestratorAction.Provider` field exists with JSON tag `"provider,omitempty"`
- AC-T2: `OrchestratorAction.Model` field exists with JSON tag `"model,omitempty"`
- AC-T3: `PopulatedAction.Provider` and `PopulatedAction.Model` fields exist with `"omitempty"` tags
- AC-T4: `GetStatusActionPopulated()` copies Provider and Model from OrchestratorAction to PopulatedAction
- AC-T5: `OrchestratorAction.Validate()` does NOT reject missing or empty Provider
- AC-T6: Existing config files without these fields load and validate without error
- AC-T7: `make fmt && make lint && make test` passes with no regressions in `internal/config/`
