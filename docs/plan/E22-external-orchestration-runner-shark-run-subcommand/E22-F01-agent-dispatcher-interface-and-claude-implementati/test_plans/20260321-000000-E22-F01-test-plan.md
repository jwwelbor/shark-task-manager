## Acceptance Criteria Review

### Ambiguity Findings

**REQ-F01-004 — "Invokes `claude -p "<instruction>"`"**

The AC does not specify whether the instruction is passed as a single argument (which might be shell-split on whitespace) or as a quoted string. Since `exec.CommandContext` passes args as a slice without shell interpretation, the instruction is passed as a single argument element. Test cases should use multi-word instructions to verify this is handled correctly.

**REQ-F01-004 — Command string in DispatchResult**

The AC says "full command string that was executed (for logging/debugging)". No format is specified. Tests should verify the string contains the binary name and key flags. Exact format need not be pinned.

**REQ-F01-005 — Additive with user DisallowedTools**

"Additive" is clear — all 6 defaults PLUS any user-supplied ones. Tests should verify user-specified tools appear in addition to (not instead of) the defaults.

**REQ-F01-NF-002 — No memory size limit**

This is explicitly out of scope for this feature (truncation is deferred to E22-F03+). No test is needed for memory bounding in this feature.

### Missing Coverage

None. All 8 functional requirements and 2 of 3 non-functional requirements have testable acceptance criteria. REQ-F01-NF-002 (memory bounds) is explicitly deferred.

#### TC-015: Context cancellation kills subprocess

**Feature Requirement:** REQ-F01-NF-003 — When context is cancelled, subprocess is killed
**Task Acceptance Criterion:** Uses `exec.CommandContext(ctx, ...)` for cancellation

**Preconditions:**
- `ClaudeDispatcher` with cmdFactory pointing to a long-running no-op process (e.g., `TestHelperProcess` pattern with a `sleep` command)
- OR: verify that `exec.CommandContext` is used (structural test via cmdFactory inspection)

**Input:**
```go
ctx, cancel := context.WithCancel(context.Background())
input := DispatchInput{Instruction: "test", ...}
// Launch Dispatch in goroutine
go dispatcher.Dispatch(ctx, input)
cancel() // Cancel immediately
```

**Expected Output:**
- `Dispatch` returns `context.Canceled` error (or an error wrapping it)
- The subprocess does not continue running after cancellation

**Edge Cases:**
- Context already cancelled before Dispatch call: returns immediately with error
- Context deadline exceeded (`context.WithDeadline`): also kills process

**Negative Cases:**
- Must NOT return `nil` error when context is cancelled
- Must NOT hang after context cancellation

- Validation must happen at dispatch time, NOT at construction time (verified by: construction succeeds even when claude is absent)
