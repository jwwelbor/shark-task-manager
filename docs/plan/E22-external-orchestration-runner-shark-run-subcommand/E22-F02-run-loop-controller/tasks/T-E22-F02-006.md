# T-E22-F02-006: Implement context cancellation support in run loop

## References
- spec.md §2 REQ-F02-013 (Context Cancellation Support)
- spec.md §2 REQ-F02-004 AC (checks ctx.Done() at loop boundary)
- test-plan.md §2 TC-F02-013-1 through TC-F02-013-4

## Goal

Add `ctx.Done()` checks at each loop iteration boundary in the `Run` method in `internal/runner/controller.go`. Agent subprocess cancellation is handled automatically by `exec.CommandContext` in the dispatcher layer (E22-F01).

## File

`internal/runner/controller.go` (2-3 line addition at top of each loop iteration, ~10 lines total)

## Deliverables

- `select { case <-ctx.Done(): ... default: }` check at the top of each loop iteration
- On context cancellation: return partial `RunResult` with `Outcome: "failed"`, `Error: ctx.Err().Error()`, and stages completed so far
- Status is NOT advanced after a cancelled dispatch
- `TotalDuration` still populated to reflect elapsed time before cancellation

## Acceptance Criteria

- [ ] Context cancelled before loop starts: returns `Outcome: "failed"` with zero stages
- [ ] Context cancelled between iterations: returns partial `RunResult` with stages completed so far
- [ ] `Error` field populated with `ctx.Err().Error()` on cancellation
- [ ] No `TransitionStatus` call made after cancellation
- [ ] `make build` and `make test` pass

## Dependencies

- T-E22-F02-003 (Run loop structure must exist)
