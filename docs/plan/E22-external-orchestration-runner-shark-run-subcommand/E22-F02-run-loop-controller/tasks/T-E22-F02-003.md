# T-E22-F02-003: Implement Run loop core logic: action dispatch, status transitions, terminal detection

## Goal

Implement the main `Run` method body in `internal/runner/controller.go`. This is the primary orchestration loop: read entity status, read action, dispatch agent for `spawn_agent` actions, gate advancement on exit code 0, advance status, detect terminal, loop.

## File

`internal/runner/controller.go` (replaces stub from T-E22-F02-002, ~80 lines for Run method)

## Loop Sequence (per REQ-F02-004)

1. Call `transitioner.GetNextStatus(ctx, key)` — return `already_terminal` if `IsTerminal: true`
2. Call `placeholders.GeneratePlaceholders(ctx, key)` for template variable map
3. Call `actionSvc.GetStatusActionPopulated(ctx, currentStatus, vars)` — return `no_action` if nil
4. Route by action type (handled in T-E22-F02-004 for spawn_agent, T-E22-F02-005 for others)
5. After successful dispatch (exit 0): call `GetNextStatus` again, take `AvailableTransitions[0].TargetStatus`, call `TransitionStatus`, update `currentStatus`
6. Check `workflowSvc.IsTerminalStatus(currentStatus)` after each transition; break on terminal
7. On non-zero exit: return `Outcome: "failed"` with `AgentFailedError`
8. Record `StageLog` entry per iteration; accumulate `TotalDuration`

## Acceptance Criteria

- [ ] Entity already terminal returns immediately with `Outcome: "already_terminal"`, zero stages
- [ ] Successful single-stage spawn_agent returns `Outcome: "completed"`, `StagesCompleted: 1`
- [ ] Multi-stage run iterates correctly through N statuses
- [ ] Non-zero exit code stops loop, returns `Outcome: "failed"`
- [ ] `TransitionStatus` called with `AvailableTransitions[0].TargetStatus` (not empty string)
- [ ] `StageLog` entries populated with `Status`, `Action`, `AgentType`, `Provider`, `Duration`, `ExitCode`
