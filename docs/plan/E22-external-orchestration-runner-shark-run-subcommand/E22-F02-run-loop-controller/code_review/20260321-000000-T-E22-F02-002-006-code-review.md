### T-E22-F02-003: Run Loop Core Logic

**Acceptance Criteria Review:**
- [x] Entity already terminal returns immediately with `Outcome: "already_terminal"`, zero stages — `TestRunController_AlreadyTerminal`
- [x] Successful single-stage spawn_agent returns `Outcome: "completed"`, `StagesCompleted: 1` — `TestRunController_DispatcherSelection_DefaultProvider` (transitions to "completed" which is terminal, loop ends)
- [x] Non-zero exit code stops loop, returns `Outcome: "failed"` — `TestRunController_AgentFailure`
- [x] `TransitionStatus` called with `AvailableTransitions[0].TargetStatus` — verified in `TestRunController_DispatchInputConstruction` and `TestRunController_AgentFailure` (verifies it is NOT called on failure)
- [x] `StageLog` entries populated with `Status`, `Action`, `AgentType`, `Provider`, `Duration`, `ExitCode` — struct fields present and populated at each exit point

**Notes:** The loop is structured clearly. Initial terminal check before the loop avoids a redundant first iteration. The `startTime` / `stageStart` pattern for duration tracking is correct. Error paths all populate `TotalDuration` before returning, which is correct behavior.

One observation (non-blocking): placeholder error currently returns `result, nil` (result with `Outcome: "failed"`, error in `result.Error`) rather than `nil, err`. This is intentional per the spec — `Run` returns `(*RunResult, error)` where the Go error is reserved for unexpected/structural failures and `RunResult.Outcome` carries operational outcomes. The pattern is used consistently across all error paths and is appropriate here.

### T-E22-F02-006: Context Cancellation

**Acceptance Criteria Review:**
- [x] Context cancelled before loop starts: returns `Outcome: "failed"` with zero stages — `TestRunController_ContextCancellation` cancels before `Run` is called
- [x] `Error` field populated with `ctx.Err().Error()` on cancellation — asserted in test
- [x] No `TransitionStatus` call made after cancellation — the `select` check is the first statement in the loop body, before any dispatch or transition
- [x] `TotalDuration` populated — present at the cancellation return path

**Notes:** The `select { case <-ctx.Done(): ... default: }` pattern is the idiomatic Go non-blocking channel check. Placement at the top of each loop iteration (before placeholder generation and action lookup) is correct — it ensures cancellation is detected promptly even when actions are cheap. Agent subprocess cancellation is propagated automatically through `exec.CommandContext` in the dispatcher layer (out of scope for this task), which is correctly noted in the task spec.

## Code Quality Assessment

### Readability
The implementation is well-structured. Each action type in the `Run` switch is self-contained. The godoc comment on `Run` gives a numbered sequence that matches the implementation. The `startTime` / `stageStart` separation is clear.

### Simplicity
No unnecessary abstractions. `selectDispatcher` is a three-line lookup with a descriptive error — the right size for what it does. No premature generalization.

### Error Handling
All error paths populate `TotalDuration`, `FinalStatus`, and `Outcome` before returning. This is consistent and correct. Errors from `GetNextStatus`, `GetStatusActionPopulated`, `Dispatch`, and `TransitionStatus` are all handled. No silent swallows.

The `makeController` helper reduces boilerplate while keeping test intent clear. Assertions verify both the positive outcome and the absence of side effects (e.g., `TestRunController_AgentFailure` verifies `TransitionStatus` is not called).
