## Review Findings

### Strengths

**Type definitions are complete and well-documented.**
`RunOptions`, `RunResult`, `StageLog`, `DispatchInput`, `DispatchResult`, `ToolNotFoundError`, and `AgentFailedError` are all defined in `dispatcher.go` and `controller.go` with godoc comments that explain every field. The field-level comments are thorough and will reduce cognitive overhead for implementors of the `shark run` command.

**Interfaces are defined at point of use.**
`EntityTransitioner` and `PlaceholderGenerator` live in `controller.go`, following the project convention of placing interfaces on the consumer side. Both match the signatures specified in the spec exactly.

**Dependency injection is well-structured.**
`RunControllerDeps` bundles all dependencies into a single struct, making the constructor signature stable as the feature evolves. The constructor enforces required vs optional dependencies correctly: `Transitioner`, `ActionSvc`, and `WorkflowSvc` panic on nil (programming errors), while `Placeholders` is allowed to be nil with graceful degradation in the run loop. The empty `Dispatchers` map returns an error rather than panicking, which is the right call since it is a configuration mistake rather than a programming mistake.

**`DefaultDisallowedTools` is well-placed and documented.**
The package-level var in `dispatcher.go` with its explanation of why agent self-advancement must be blocked is exactly the kind of "why" comment the codebase standards call for.

**Run loop control flow is clear and safe.**
The loop in `Run()` checks context cancellation at the top of every iteration before performing work. Each exit path populates all `RunResult` fields before returning. The `default` case in the action-type switch fails safely with a descriptive error rather than silently looping.

**Tests are meaningful and cover real behavior.**
All 71 tests use mock dependencies (no real database). The compile-time interface satisfaction assertions at the top of `controller_test.go` (`var _ EntityTransitioner = (*MockTransitioner)(nil)`) catch interface drift at compile time. Test names describe intent clearly. Coverage hits the critical paths: already-terminal, no-action, pause variants, dispatcher selection (default and unknown), context cancellation, agent failure exit-code gating, and `DispatchInput` field mapping.

**`selectDispatcher` provides a useful error message.**
When a provider is not found, the error lists available keys including the `""` default key rendered as `""`. This is exactly the information an operator needs to diagnose a misconfigured `.sharkconfig.json`.

### Minor Observations (not blocking)

**`RunResult.TotalDuration` JSON tag is `total_duration_ns`.**
This is an accurate tag name since `time.Duration` serialises as nanoseconds. Consider adding a note to the field comment making this explicit so consumers of the JSON output know the unit. Not a blocker.

**`StageLog.EntityType` is absent.**
`DispatchInput` carries `EntityType` but `StageLog` does not record it. This is fine for the current scope — the run loop only processes one entity at a time — but may be worth adding in a later iteration if log aggregation across entity types is needed.

**`ActionCheckOrResume` grouped with pause actions.**
`config.ActionCheckOrResume` is handled identically to `ActionPause` and `ActionWaitForTriage`. The grouping is correct for now (they all mean "stop and let a human decide"), but the comment should note this equivalence explicitly in a follow-up if the semantics diverge.

**No table-driven test for `selectDispatcher`.**
The two existing tests (`DefaultProvider`, `UnknownProvider`) cover the main paths, but a table-driven test would make it easier to add edge cases (e.g., multiple configured providers) in future iterations.
