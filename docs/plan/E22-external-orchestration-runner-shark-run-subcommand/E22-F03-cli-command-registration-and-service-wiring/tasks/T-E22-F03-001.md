# Task: Implement CLI command registration and service wiring for shark run

## Goal

Implement the `shark run` CLI command and wire `GetActionService()` in
`internal/cli/services_global.go`. This registers the external orchestration
runner command with the Cobra root and provides the service accessor for CLI use.

## Context

Verification confirmed that neither `internal/cli/commands/run.go` nor
`GetActionService()` currently exist. E22-F02 implemented the underlying
`ActionService` in `internal/config/action_service.go`. This task registers
it with the CLI layer.

## Requirements

### Functional Requirements

- [ ] Create `internal/cli/commands/run.go` with a `shark run` Cobra command
- [ ] Register the command with the root CLI via `init()`
- [ ] Add `GetActionService()` to `internal/cli/services_global.go`
- [ ] `GetActionService()` must wire `config.ActionService` using the project
      root path from `GetProjectRoot()`
- [ ] `./bin/shark run --help` must produce usage output without error

### Non-Functional Requirements

- [ ] Command follows the thin-wrapper pattern: parse args, call service, format output
- [ ] Service accessor follows the existing global accessor pattern (see `GetTaskService()`)
- [ ] No business logic in the command handler

## Implementation Plan

### Files to Create/Modify

1. **Create** `internal/cli/commands/run.go`
   - Cobra command `runCmd` with `Use: "run"`
   - `init()` registers it with `cli.RootCmd`
   - Handler calls `GetActionService()` for future sub-operations

2. **Modify** `internal/cli/services_global.go`
   - Add `GetActionService()` function
   - Wire `config.NewActionService(projectRoot)` or equivalent constructor
   - Follow the `sync.Once` lazy-init pattern used by other accessors

### Technical Approach

- Reference `internal/config/action_service.go` for the `ActionService` interface
- Reference `internal/config/manager.go` for how `ActionService` is constructed
- Reference existing accessors (`GetTaskService`, `GetNoteService`) for the wiring pattern

## Acceptance Criteria

- [ ] `internal/cli/commands/run.go` exists and compiles
- [ ] `GetActionService()` is defined in `internal/cli/services_global.go`
- [ ] `./bin/shark run --help` produces usage output without error
- [ ] `make fmt && make lint && make test` all pass
- [ ] No regressions in existing CLI tests

## Testing Strategy

- Build the binary and run `./bin/shark run --help`
- Run full test suite: `make fmt && make lint && make test`

## Dependencies

- E22-F02 (completed): `config.ActionService` implementation in `internal/config/action_service.go`

## Notes

- The initial `run` command can be a stub with `--help` working; full
  orchestration logic is in a later E22 feature.
- Keep the command handler minimal — argument wiring to the service will
  expand in subsequent features.
