# Task: Add output capture and summary formatting to run logging

## Goal

Extend the run logging infrastructure with output capture and a non-verbose display
helper so that `shark run` shows meaningful per-stage summaries without flooding
the terminal.

## Requirements

### Functional Requirements

- [ ] `StageLog` in `internal/runner/controller.go` gains an `OutputSummary string` field
- [ ] The run loop populates `OutputSummary` from `DispatchResult.Stdout` after a
      successful `spawn_agent` dispatch
- [ ] `truncateOutput(s string, maxLen int) string` helper exists in
      `internal/runner/` (package-private) for use by the CLI display layer
- [ ] Non-verbose human-readable output in `run.go` uses `truncateOutput` to show
      a one-line snippet per stage instead of nothing

### Non-Functional Requirements

- [ ] No change to the JSON schema of `RunResult` beyond the new `output_summary`
      field on each `StageLog` entry
- [ ] `truncateOutput` is pure (no I/O) and fast (no allocation for short strings)

## Implementation Plan

### Steps

1. [ ] Add `OutputSummary string \`json:"output_summary,omitempty"\`` to `StageLog`
2. [ ] After `dispatchResult, err := dispatcher.Dispatch(...)` succeeds (exit 0),
       set `stage.OutputSummary = dispatchResult.Stdout` before appending to
       `result.Stages`
3. [ ] Add `truncateOutput(s string, maxLen int) string` to a new file
       `internal/runner/output_format.go`
4. [ ] In `run.go` non-verbose path, print a truncated summary per stage when
       `OutputSummary` is non-empty

### Technical Approach

- `OutputSummary` on failed stages (non-zero exit) is left empty — only captured
  on successful agent execution
- `truncateOutput` replaces newlines with spaces and appends `…` when the result
  exceeds `maxLen`
- Default maxLen for CLI display: 120 characters

## Acceptance Criteria

- [ ] `StageLog.OutputSummary` is populated in integration-style tests using mock
      dispatchers that return non-empty `Stdout`
- [ ] `truncateOutput` unit tests cover: empty, short, exact-length, over-length,
      multi-line input
- [ ] `go vet ./internal/runner/` passes
- [ ] `go test -v ./internal/runner/` passes

## Testing Strategy

- [ ] Unit tests for `truncateOutput` in `internal/runner/output_format_test.go`
- [ ] Controller test: mock dispatcher returns `Stdout = "agent output"`;
      assert `result.Stages[0].OutputSummary == "agent output"`

## Dependencies

No external dependencies. Builds on E22-F02 RunController already merged.

## Notes

- Keep `OutputSummary` omitempty in JSON so existing consumers aren't broken
- Failed stages intentionally don't capture output in this iteration; callers
  can access `DispatchResult.Stderr` via the error string already stored in
  `result.Error`
