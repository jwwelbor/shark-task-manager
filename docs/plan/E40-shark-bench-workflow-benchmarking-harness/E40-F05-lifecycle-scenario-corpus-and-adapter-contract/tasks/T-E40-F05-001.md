# Task: Python fixture repo scaffold and submodule wiring

## Goal
Create the standalone Python task-manager fixture repository, commit a base
application, and wire it into this repo as `bench/fixture-py` via
`.gitmodules`, following the existing Go fixture-repo submodule pattern. This
is the required first task in this feature's build order (ADR-F05-09): no
scenario package can name a `base_sha` until this repository exists and is
pushed.

## Scope
- Files to create: `.gitmodules` entry for `bench/fixture-py`; `bench/fixture-py/` submodule pointer at this task's initial commit
- The standalone fixture repo's own `pyproject.toml`, lint config, formatter config, package source, and initial test suite (owned by that separate repository, referenced here only by commit SHA)
- No files under `internal/` or `cmd/`

## Acceptance Criteria
See spec.md REQ-F-016; ADR-F05-09.
- AC-T1: `bench/fixture-py`'s `pyproject.toml` carries dependency, lint, and formatter configuration sections, and a discoverable test suite exists.
- AC-T2: the test suite includes at least one plain-pass test, one parametrized test, and one explicitly-skipped test, so all three terminal outcomes exist for the adapter's `test` capability to normalize.
- AC-T3: this commit is **provisional**, not the frozen `base_sha` — T-E40-F05-008/010/011/012 add further commits embedding each family's subject; T-E40-F05-014 freezes the final commit. The working tree at every commit contains fixture code only — no scenario package, no evaluator-only material, no shark source.
