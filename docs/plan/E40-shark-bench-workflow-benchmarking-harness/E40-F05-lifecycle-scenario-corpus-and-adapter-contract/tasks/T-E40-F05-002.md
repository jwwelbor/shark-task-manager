# Task: Python adapter: six-capability contract

## Goal
Implement `bench/adapters/python/adapter.sh` and `adapter.yaml`: the
execution adapter that runs `bench/fixture-py`'s toolchain (pytest, its
configured linter, an import/compile build check, a formatter check) behind
the closed six-verb capability contract, so no generic scenario or admission
component ever branches on Python.

## Scope
- Files to create: `bench/adapters/python/adapter.yaml`, `bench/adapters/python/adapter.sh`
- Files to modify: none outside `bench/adapters/python/`

## Acceptance Criteria
See spec.md REQ-F-006, REQ-F-007; Adapter capability contract table.
- AC-T1: all six capabilities (`identity`, `inject-tests`, `test`, `lint`, `build`, `format-check`) emit exactly the JSON shape fixed in spec.md's Adapter capability contract table.
- AC-T2: `test` emits ids normalized to `<module path>::<test name>`; subtests/parametrized cases are distinct entries under their full name.
- AC-T3: exit status `0` means "ran successfully" even when the subject failed (a red test, a lint issue); a genuinely broken toolchain invocation exits non-zero.
- AC-T4: an undefined seventh capability name is rejected with a non-zero exit (closed verb set, proven jointly with the Go adapter by T-E40-F05-004).

## Test Cases
