# Task: Adapter conformance test across both adapters

## Goal
Write `bench/scripts/tests/tc031_adapter_conformance_test.sh` (TC-031): one
assertion set run against both `bench/adapters/go/adapter.sh` and
`bench/adapters/python/adapter.sh`, proving the two independently
implemented adapters satisfy an identical contract. This is the workflow's
stated TDD exception — a suite spanning two components that cannot be
co-located inside either adapter's own implementation task.

## Scope
- Files to create: `bench/scripts/tests/tc031_adapter_conformance_test.sh`
- Files to modify: `bench/scripts/tests/run-all.sh` (register the new test)

## Acceptance Criteria
See spec.md AC-010, AC-011, AC-012.
- AC-T1: for each of the six capabilities, both adapters' stdout JSON validates against the identical shape assertion set (AC-010).
- AC-T2: `test`'s emitted ids are normalized on both sides (Go: `<package import path>::<test name>`; Python: `<module path>::<test name>`) for the same conceptual entry set, with no language-aware id parsing in the harness itself (AC-011).
- AC-T3: a seventh, undefined capability name is rejected with a non-zero exit by both adapters, proving the closed six-verb set rather than merely exercising the six that exist (AC-010).
- AC-T4: a grep of `admit-scenario.sh`, `eval-predicate.sh`, `checkout-scenario-fixture.sh`, and `run-all.sh` for `python|pytest|pip|go test|golangci-lint|go build` returns zero hits outside `bench/adapters/*/`; a source-level check confirms none of these scripts branches on `fixture_id`/`adapter.name`/`scenario_id` (AC-012).
