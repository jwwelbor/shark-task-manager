**Cancelled and merged into [T-E40-F05-013](T-E40-F05-013.md).**

Task-review round 3 (`docs/review/.../E40-F05-task-review.md`) found this
task's split from T-E40-F05-013 was not the permitted feature-level
integration-suite exception: it shipped fixture implementation with no
owning test file, which is test-after, not TDD. The fix was to merge this
task's fixture-content scope into T-E40-F05-013, which now owns both the
`bench/fixture-py` recurring-task implementation and its evaluator-only
integration tests as one task.

This file is kept (not deleted) because `shark task update --depends-on` is
confirmed dead code — it accepts the flag and reports success but never
persists the change to the task's legacy `depends_on` column — so the
column on T-E40-F05-013 could not be cleared of this key, and `shark delete`
refuses to remove a task another task's legacy column still names as a
dependency. `shark task link`/`unlink --depends-on` correctly updated the
live `entity_relationships` edges (T-E40-F05-013 no longer depends on this
task there), but that table is not what `shark delete`'s dependents check or
`shark list`'s displayed `depends_on` field read. Filed as tech-debt for
`/triage` after E40-F05 ships; do not work this task.
