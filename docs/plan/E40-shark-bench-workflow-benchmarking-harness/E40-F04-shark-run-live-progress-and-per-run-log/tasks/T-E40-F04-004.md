# LivenessRecorder: Finish() run-end summary, including the zero-stage case

## Goal
Extend `internal/runner/liveness.go` with `Finish(*runner.RunResult)`: closes
any still-open stage, and appends the file-only `run_end` summary line (spec.md
D3) sourced from the `RunResult` when one is available. This is the last piece
of the recorder itself — T-E40-F04-005 wires it into `run.go`.

**Implementation-shape decision, resolved here per test-plan.md AC-08
decision-table row 8b (test-plan.md explicitly left this format
unprescribed, calling it "an explicit, must-resolve implementation decision
for task generation"):** when `Finish` is called with **zero prior `Observe`
calls** (no slot was ever opened) and `result == nil` (the shape
`controller.Run` returns when it fails with a bare `error` before its first
`iteration` — e.g. `GetNextStatus` failing at `controller.go:359-361`), write
exactly one `run_end`-shaped line with unknown-valued fields:
`<ts>  run_end  <topLevelKey>  outcome=unknown final_status=unknown stages=0 total=<total_elapsed>`.
This satisfies AC-06's "non-empty file" invariant without fabricating a
`stage_start`/`stage_end` pair for a slot that never opened.

## Scope
- Files to modify: `internal/runner/liveness.go`, `internal/runner/liveness_test.go`
- Same REQ-N-004 constraint: zero diff to `controller.go`/`transcript.go`.

## Acceptance Criteria
See spec.md AC-06, AC-08 (decision-table row 8), D3's `run_end` line
definition, and test-plan.md TC-016, TC-017.
- AC-T1 (row 8b — zero `Observe` calls, `Finish(nil)`): `run.log` exists and
  is non-empty, containing exactly the synthetic `run_end` line specified
  above. No `stage_start`/`stage_end` is fabricated. `Finish` does not panic.
- AC-T2 (sub-case a — one open, unclosed stage, `Finish(nil)`): the open
  slot's lazily-emitted `stage_start` and a closing `stage_end` are written;
  **no `run_end` line is written** in this sub-case (D3 ties `run_end`
  strictly to `RunResult` availability — closing the stage already makes the
  file non-empty, so no synthetic line is needed here).
- AC-T3 (row 8a — zero `Observe` calls, `Finish(&runner.RunResult{...})` with
  a real but stage-less result, e.g. `Outcome: "already_terminal"`): `run.log`'s
  only content is the `run_end` line sourced from that result's real fields
  (`outcome=already_terminal final_status=... stages=0 total=...`) — no
  fabricated stage lines.
- AC-T4 (primary case — at least one stage ran, `Finish(&runner.RunResult{...})`):
  the closing `stage_end` fires (lazily starting it first if needed), then the
  `run_end` line is appended, sourced from the result's real fields.
- AC-T5: `run_end` is never written to stderr in any mode — assert the stderr
  capture from the same driven sequence contains no `run_end` line. `event`
  stays closed to the three-value enum on stderr; `run_end` is `run.log`-only.

## Test Cases
TC-016 (both sub-cases of `Finish(nil)`: open-unclosed-stage and
zero-`Observe`), TC-017 (both `Finish(result)` cases: primary and
decision-table row 8a). Assert stderr capture separately from `run.log`
content in both to prove the file-only claim (AC-T5).

## Integration Contracts
None — internal implementation increment. I-03/X-08 are declared in
T-E40-F04-001, T-E40-F04-005, and T-E40-F04-006.

## Design Reference
See spec.md §"Architecture" D3 ("`run_end` is a file-only summary line, not a
fourth `event` value") and D1 (run-end row of the phase table: "close the
open slot", "`stage_end` for the closed slot"). See test-plan.md's AC-08
Decision Table row 8 and its surrounding prose for the two production shapes
that reach this method with no prior `Observe` call.

## Notes for Agent
- `Finish` must be safe to call exactly once per run (T-E40-F04-005's
  teardown pattern is `defer func() { rec.Stop(); rec.Finish(runResult) }()`)
  — do not design it to require multiple calls or external sequencing beyond
  that.
- Do not treat "`result` is nil" and "`result.Stages` is empty" as the same
  case — AC-T3 (row 8a) has a real, non-nil result with zero stages, and must
  render its actual `Outcome`/`FinalStatus` fields, not the AC-T1 fallback
  text.
