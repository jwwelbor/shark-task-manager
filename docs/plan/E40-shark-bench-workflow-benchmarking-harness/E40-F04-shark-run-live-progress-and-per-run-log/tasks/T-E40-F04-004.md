# LivenessRecorder: Finish() run-end summary, including the zero-stage case

## Goal
Extend `internal/runner/liveness.go` with `Finish(*runner.RunResult)`: closes
any open stage and appends the file-only `run_end` line (D3) sourced from
`RunResult` when available. Last piece of the recorder — T-E40-F04-005 wires it in.

**Resolved per test-plan.md AC-08 row 8b (left unprescribed there,
"must-resolve implementation decision for task generation"):** when `Finish`
has **zero prior `Observe` calls** and `result == nil` (bare `error` from
`controller.Run` before its first `iteration`), write exactly one line:
`<ts>  run_end  <topLevelKey>  outcome=unknown final_status=unknown stages=0 total=<total_elapsed>`.
Satisfies AC-06's non-empty-file invariant without fabricating stage lines.

## Scope
- Modify: `internal/runner/liveness.go`, `internal/runner/liveness_test.go`
- REQ-N-004: zero diff to `controller.go`/`transcript.go`.

## Acceptance Criteria
See spec.md AC-06, AC-08 (row 8), D3's `run_end` definition; test-plan.md TC-016, TC-017.
- AC-T1 (row 8b, `Finish(nil)`, zero `Observe`): `run.log` non-empty, contains only the synthetic line above; no fabricated stage lines; no panic.
- AC-T2 (open-unclosed stage, `Finish(nil)`): lazy `stage_start` + closing `stage_end` written; **no `run_end` line** (D3 ties it to `RunResult` availability).
- AC-T3 (row 8a, zero `Observe`, `Finish(&RunResult{Outcome:"already_terminal",...})`): `run.log`'s only content is `run_end` sourced from the result's real fields.
- AC-T4 (primary — stage(s) ran, `Finish(&RunResult{...})`): closing `stage_end` fires, then `run_end` appended from real fields.
- AC-T5: `run_end` never appears on stderr in any mode; `event` stays closed to 3 values there.

## Test Cases
TC-016 (both `Finish(nil)` sub-cases), TC-017 (both `Finish(result)` cases:
primary and row 8a). Assert stderr and `run.log` content separately in both.

## Integration Contracts
None here — I-03/X-08 declared in T-E40-F04-001, -005, -006.

## Design Reference
spec.md D3 (`run_end` is file-only, not a 4th `event` value), D1 (run-end row
of the phase table). test-plan.md's AC-08 Decision Table row 8.

## Notes for Agent
- `Finish` is called exactly once per run via T-E40-F04-005's `defer func() { rec.Stop(); rec.Finish(runResult) }()` — don't require multiple calls.
- AC-T3 (real, non-nil, zero-stage result) is distinct from AC-T1 (nil result) — render real `Outcome`/`FinalStatus`, not the fallback text.
