# LivenessRecorder: fixed 10s ticker and heartbeat cadence

## Goal
Extend `internal/runner/liveness.go` with `Start()`/`Stop()` for the 10s
ticker (REQ-N-001, REQ-F-006), heartbeat when no stage is open (spec.md's
"decisions the implementer does not get to make"), and the `run.log` path
announcement (REQ-F-008/AC-10).

**Deviation, resolved per test-plan.md §"Recommendation" (Rule 7, surfaced
not silent):** `LogPath()` is announced from inside `Start()`, not from
`run.go` as spec.md D6 edit 2 literally states — converts AC-10 into a real
runtime test here (TC-024) instead of AST-only. Consequence: spec.md's AC-10
"Verified by: run_test.go" row is superseded by this task's `liveness_test.go`
(TC-024) plus T-E40-F04-005's AST ordering guard (TC-025, unchanged).

## Scope
- Modify: `internal/runner/liveness.go`, `internal/runner/liveness_test.go`
- REQ-N-004: zero diff to `controller.go`/`transcript.go`.

## Acceptance Criteria
See spec.md AC-01 (cadence), AC-10, REQ-N-001, REQ-N-003; test-plan.md
TC-012, TC-024, TC-026, TC-027.
- AC-T1: constructor takes no `time.Duration`; source has none of `TTL(`, `claim_ttl_seconds`, `DefaultClaimTTL` — interval is a literal `10 * time.Second`.
- AC-T2: per-tick action is a separately callable **unexported** method (e.g. `tick()`), used by both `Start()`'s loop and tests — no real 10s sleep in tests, not externally configurable.
- AC-T3: a tick with no open stage emits one `heartbeat` with `entity_key=topLevelKey`, `iteration:0`, `status`/`action` empty, elapsed measured from run start.
- AC-T4: `Start()` prints `LogPath()` to stderr exactly once, before any event line, in both `jsonMode` values.
- AC-T5: `go test -race ./internal/runner/...` clean under concurrent `Observe` + tick.

## Test Cases
TC-012 (cadence via tick method), TC-024 (runtime, table-driven `jsonMode`,
pipe-capture), TC-026 (signature + TTL-identifier source scan), TC-027
(`-race` stress).
