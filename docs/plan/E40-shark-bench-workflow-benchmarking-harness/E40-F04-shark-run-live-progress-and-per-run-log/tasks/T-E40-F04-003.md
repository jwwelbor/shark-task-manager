# LivenessRecorder: fixed 10s ticker and heartbeat cadence

## Goal
Extend `internal/runner/liveness.go` with `Start()`/`Stop()` for the 10-second
heartbeat ticker (REQ-N-001, REQ-F-006), heartbeat emission when no stage is
open (spec.md's "decisions the implementer does not get to make" table), and
the `run.log` path announcement (REQ-F-008 / AC-10).

**Implementation-shape decision, resolved here per test-plan.md
§"Recommendation":** the `LogPath()` stderr announcement is printed from
inside `Start()`, not from `internal/cli/commands/run.go` as spec.md D6 edit
2 literally states. This is a deliberate deviation from D6's literal text
(Rule 7 — surfaced, not silently applied): it converts AC-10 from an
AST-only guard into a real `os.Pipe`-captured runtime test here, matching
this test plan's own stated reasoning (testability, and consistency with
D6's own layering principle that all liveness I/O lives beside
`transcript.go`). Consequence: spec.md's AC-10 row ("Verified by:
`internal/cli/commands/run_test.go`") is superseded — verification moves to
this task's `liveness_test.go` (TC-024, runtime) plus T-E40-F04-005's AST
ordering guard (TC-025, unchanged: recorder `Start()` must still be called
before `run.go`'s preflight).

## Scope
- Files to modify: `internal/runner/liveness.go`, `internal/runner/liveness_test.go`
- Same REQ-N-004 constraint: zero diff to `controller.go`/`transcript.go`.

## Acceptance Criteria
See spec.md AC-01 (cadence), AC-10, REQ-N-001, REQ-N-003 and test-plan.md
TC-012, TC-024, TC-026, TC-027.
- AC-T1: The constructor signature carries no `time.Duration` parameter and
  `internal/runner/liveness.go`'s source text contains none of `TTL(`,
  `claim_ttl_seconds`, `DefaultClaimTTL` — the interval is a literal `10 *
  time.Second` constant (Vocabulary section: never the claim/lease heartbeat
  cadence).
- AC-T2: The ticker's per-tick action is exposed as a separately callable
  **unexported** method (e.g. `tick()`), called by both `Start()`'s
  `select`-loop goroutine and by tests directly — not a real 10-second sleep
  per test run, and not a configurable interval reachable from outside the
  package.
- AC-T3: A tick with no stage currently open emits one `heartbeat` with
  `entity_key` = `topLevelKey`, `iteration: 0`, `status: ""`, `action: ""`,
  and `stage_elapsed_ms` measured from run start (not stage start).
- AC-T4: `Start()` prints the absolute `LogPath()` value to stderr exactly
  once, before any `stage_start`/`heartbeat`/`stage_end` line, in **both**
  `jsonMode` values.
- AC-T5: `go test -race ./internal/runner/...` reports no data race when N
  goroutines call `Observe` concurrently with repeated ticks.

## Test Cases
TC-012 (heartbeat fires at least once per simulated 10s window via the tick
method, including the no-open-stage boundary), TC-024 (runtime, table-driven
over `jsonMode`: pipe-capture stderr, call `Start()`, drive one `Observe`
sequence, assert exactly one path line before any event line, in both
modes), TC-026 (`reflect` signature check on `NewLivenessRecorder` plus a
source-text grep for the three TTL identifiers), TC-027 (`-race` stress:
concurrent `Observe` + tick).

## Notes for Agent
- Do not make the tick interval configurable "just for tests" — TC-026
  explicitly fails a constructor with a duration parameter, even if
  unreachable from production code; a reviewer reads it as a REQ-N-001
  violation regardless.
- `Stop()` must be safe to call before any tick fires and idempotent enough
  that T-E40-F04-004's teardown sequence (`rec.Stop(); rec.Finish(...)`) can
  call it unconditionally.
