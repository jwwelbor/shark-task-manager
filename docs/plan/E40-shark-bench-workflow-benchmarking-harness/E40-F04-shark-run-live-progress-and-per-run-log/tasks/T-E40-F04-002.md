# LivenessRecorder: plain-mode renderer and per-run log writer

## Goal
Extend `internal/runner/liveness.go` (from T-E40-F04-001) with the plain-mode
text renderer (spec.md D3's fixed-column line format) and the `run.log` file
sink: per-event open-append-write-close durability (D4), directory/file
permissions matching `internal/runner/transcript.go` (0o755/0o644), fail-soft
error handling matching `internal/observability/file_jsonl_exporter.go`
(`slog.Debug` + swallow, never returned to the caller), and the empty-root
no-op behavior mirroring `NewFileJSONLExporter("")`.

## Scope
- Files to modify: `internal/runner/liveness.go`, `internal/runner/liveness_test.go`
- Same REQ-N-004 constraint as T-E40-F04-001: zero diff to
  `internal/runner/controller.go` and `internal/runner/transcript.go`.

## Acceptance Criteria
See spec.md AC-04, AC-07 (partial — durability), AC-09, REQ-N-005 (perms) and
test-plan.md TC-014, TC-019, TC-022, TC-023, TC-028.
- AC-T1: In `jsonMode=false`, every emitted line (stderr and `run.log`, both
  use the same plain renderer) matches D3's fixed-column format
  (`<ts>  <event>  <entity_key>  key=value...`) with empty-valued keys
  omitted entirely, never printed as `key=`.
- AC-T2: `run.log` writes are `os.OpenFile(path, os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0o644)` per event — no `bufio.Writer` anywhere in the path. Reading the file directly (`os.ReadFile`) immediately after an `Observe` call that emitted a line, without any later flush/close step, already contains that line (REQ-F-010 flush-free durability).
- AC-T3: `LogPath()` is implemented in this task as a real getter returning the
  resolved absolute `run.log` path (the same `projectRoot`/`runID` join this
  task already computes to open the file sink) — not a stub. `NewLivenessRecorder("", ...)`
  disables the file sink only: stderr events still fire for every `Observe`
  call, no error is returned, no panic, and `LogPath()` resolves to an empty
  value / no file being created. T-E40-F04-003 only adds *printing* this
  value inside `Start()`; it does not own `LogPath()`'s resolution.
- AC-T4: A file sink write failure (e.g. `EACCES` from a `chmod 0o555` directory) is swallowed: `Observe` returns no error, stderr events still fire, and at least one `slog.Debug` record describing the failure is emitted, matching `file_jsonl_exporter.go`'s pattern.
- AC-T5: Created file mode is `0o644`, parent directory mode is `0o755` (skip on `windows`, matching `transcript_test.go`'s convention).

## Notes for Agent
- The recorder must perform its own `MkdirAll` for `.shark/runs/<run_id>/` —
  `writeTranscript`'s directory creation is conditional on
  `CaptureAgentTranscripts` and cannot be relied on (research Finding 6).
  `MkdirAll` on an already-existing directory is a no-op, so concurrent
  creation with a transcript writer in the same run is safe.
- Do not wrap `os.Stderr` in a buffered writer — it is unbuffered in Go by
  default; wrapping it would silently reintroduce the durability defect this
  task exists to prevent.
