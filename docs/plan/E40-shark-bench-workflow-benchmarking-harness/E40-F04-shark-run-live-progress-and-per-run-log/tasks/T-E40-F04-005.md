# Wire LivenessRecorder into shark run and fix worktree stdout leak

## Goal
Wire the completed `LivenessRecorder` (T-E40-F04-001..004) into
`internal/cli/commands/run.go`, and fix the second, independently-discovered
stdout-purity defect at `run.go:275` (research Finding 3). This is the task
that actually makes `shark run` observable — everything before it built the
recorder in isolation.

## Scope
- Files to modify: `internal/cli/commands/run.go`, `internal/cli/commands/run_test.go`, `internal/cli/commands/run_worktree_test.go`
- Do not extend the `runClaimSvcOverride`/`withRunClaimSvcOverride` injection
  pattern to make `runRun` fully mockable — test-plan.md's
  §"Considered and rejected" explicitly rules this out as disproportionate
  scope for a STANDARD-scored feature (six-plus call sites would need
  refactoring into injectable seams). Use the AST-guard technique this
  feature's test plan establishes instead.
- Same REQ-N-004 constraint applies here too: this task's diff to
  `internal/runner/controller.go` and `internal/runner/transcript.go` must be
  zero lines. Every change in this task lives in `internal/cli/commands/`.

## Acceptance Criteria
See spec.md D6 (all five edits — note edit 2's print step is now handled
inside `LivenessRecorder.Start()` per T-E40-F04-003's resolved deviation, so
this task's job is only to call `Start()` at the right point, not to print
anything itself) and test-plan.md TC-013, TC-018, TC-025. This task
*implements* the fix AC-02 and AC-03 require; TC-002 (both halves) and this
task's own TC-013 verify it — TC-002 itself is written in T-E40-F04-006.

**AC-06 note (do not re-derive an end-to-end test here):** AC-06 ("`run.log`
exists and is non-empty after any run") is already covered at the recorder
level by T-E40-F04-004's `Finish()` tests. This task's contribution to AC-06
is structural only: TC-018 (the teardown-defer closure shape) and TC-025
(construction/`Start()` ordering) — both AST-level, because `runRun` cannot
be driven end-to-end under this repo's CLI-test rules (no override seam for
the entity services it resolves via `cli.Get*Service()`). Do not add a test
that invokes `runRun` and asserts `run.log`'s existence.

- AC-T1 (D6 edit 1): a separate, non-fatal `cli.FindProjectRoot()` lookup is
  added immediately after `runID := generateRunID()`, whose error is
  discarded (empty root disables the file sink per T-E40-F04-002). The
  existing hard-error `cli.FindProjectRoot()` call used for `opts.ProjectRoot`
  is left exactly where it is — do not move or soften it.
- AC-T2 (D6 edit 2, ordering only): the recorder is constructed and
  `Start()`'d immediately after `emitRunStart` and before the preflight
  (`acquireRunLeaseForRunnableAction` / `preflightCascadeQuestionBlock`) — so
  a run that pauses at a Question block still leaves a log. Teardown is
  `defer func() { rec.Stop(); rec.Finish(runResult) }()` — a closure, **not**
  `defer rec.Finish(runResult)` (captures `nil` forever per Go's
  argument-evaluated-at-registration-time semantics; `run.go` already
  documents this exact trap for `emitRunEnd`).
- AC-T3 (D6 edit 3): the `if !cli.GlobalConfig.JSON { ... }` block wrapping
  the inline ticker and `opts.Progress` assignment is replaced entirely with
  `opts.Progress = rec.Observe`, removing the JSON-mode gate, the inline
  ticker, and the `normalizedKey`-vs-`update.EntityKey` mislabeling in one change.
- AC-T4 (D6 edit 4): the `--worktree` cleanup `defer`'s warning becomes
  `fmt.Fprintf(os.Stderr, ...)`, matching the claim-release/claim-heartbeat sites.
- AC-T5 (D6 edit 5, verification only): `outputRunResult` confirmed unchanged,
  remains the sole stdout writer.
- AC-T6: no `cli.Success`/`Warning`/`Info`/`OutputTable`/`Title` call exists
  in `run.go` outside `outputRunResult` (none exist today — see Notes; do not
  introduce one while making the edits above).
