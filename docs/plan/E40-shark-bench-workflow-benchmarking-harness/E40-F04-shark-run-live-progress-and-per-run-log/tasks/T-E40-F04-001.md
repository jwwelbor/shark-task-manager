# LivenessRecorder: stage-boundary state machine and JSON stderr renderer

## Goal
Create `internal/runner/liveness.go`'s core: the single-open-stage state
machine deriving `stage_start`/`heartbeat`/`stage_end` from `RunProgress`
(spec.md D1), plus the `--json`-mode NDJSON stderr renderer (D3's JSON
table). Foundation only — no ticker, file writer, or `Finish()` yet.

## Scope
- Create: `internal/runner/liveness.go`, `internal/runner/liveness_test.go`
- REQ-N-004: zero diff to `internal/runner/controller.go` and
  `internal/runner/transcript.go`, this task and every later F04 task. Only
  seam used is `RunOptions.Progress`'s existing callback signature.

## Acceptance Criteria
See spec.md AC-01, AC-05, AC-08; test-plan.md TC-011 (stderr half — file half
is T-E40-F04-002), TC-015, TC-020, TC-021, TC-029.
- AC-T1: `NewLivenessRecorder(projectRoot, runID, topLevelKey string, jsonMode bool, start time.Time) *LivenessRecorder` — no duration parameter (TC-026 depends on this later).
- AC-T2: `Observe(RunProgress)` implements D1's phase table — `iteration` closes/reopens slots (lazy `stage_start` if needed), `action` enriches + emits `stage_start`, other phases ignored. Mutex-guarded (REQ-N-003).
- AC-T3: `jsonMode=true` lines unmarshal into D3's 11-field schema, `event` closed to `{stage_start, heartbeat, stage_end}`, `agent_type`/`provider` omitted when unset, no `phase` key ever.
