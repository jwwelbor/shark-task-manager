# Task: Aggregator statistics: metric registry, acceptance intervals, flags, digest

## Goal
Extend `aggregate-runs.sh` with the metric registry (Class A/B/C), per-`(item,variant,metric)` statistics and ADR-F03-04's acceptance-interval formula, per-step token/cost/duration keying, the locked regression signal, `rejections.by_gate` zero-vs-excluded handling, the three flags, the computed `input_digest`, the `baseline_id`, and the corpus-level rollup — the `tasks[]`/`corpus`/`flags` blocks. ## Acceptance Criteria
See spec.md AC-12..AC-18; REQ-F-012..019, ADR-F03-03/04/06.
- Class A/B/C statistics and ADR-F03-04's three-branch interval formula (`r>0`; `r==0, median≠0`; identically-zero) — `accept_lo<=min` and `accept_hi>=max` for every Class B/C metric.
- `n<2` publishes `insufficient_reps` and no interval (REQ-F-016).
- Per-step totals sum repeated `stages[].status` occurrences, never take one arbitrarily (REQ-F-013).
- The aggregate's regression field is `oracle.p2p_regressions_count` only — never derived from `quality.tests_pass` (REQ-F-014, ADR-F03-06).
- An omitted gate key in a **present** `rejections.by_gate` counts as 0; a wholly absent `rejections` block is excluded, not zeroed (REQ-F-015).
- `input_digest` is **computed** — sha256 over sorted `"<sha256>  <relpath>"` lines, order-invariant (REQ-F-019).
- `baseline_id` matches `<variant_id>-<fixture_base_sha[:12]>-r<reps>` exactly (12 hex chars of the SHA, literal `r` + integer reps) — TC-018p's own format-string check, the gap test-plan.md's REQ-indexed pass found with no AC stating it explicitly.
