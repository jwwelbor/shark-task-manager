# Task: Replay preconditions and synthetic corpus dispatch

## Goal
Implement `replay-manifest.sh`'s dispatch half: check REQ-F-027's three preconditions before any API spend, build the synthetic single-item `corpus.yaml` pinning the stored manifest's `fixture_base_sha`/`corpus_schema_version`/`p2p_set`, record `corpus_drift` against the live corpus, and invoke `run-one.sh` (via `RUN_ONE_BIN`) with the manifest's stored `--rep` value against a distinct `--out` root.

## Scope
- Create: `bench/scripts/replay-manifest.sh` (arg parsing, precondition checks, synthetic corpus builder, dispatch), `bench/scripts/tests/tc019_replay_manifest_test.sh` (sub-cases a, b, c, h)
- Modify: `bench/scripts/tests/run-all.sh` (register `tc019`), `bench/README.md` (append the replay procedure and REQ-N-007's two preconditions to the section T-E40-F03-004 opened), `bench/scripts/tests/tc018_aggregate_report_test.sh` (add sub-case v, a content-only read of the README addition below)

## Acceptance Criteria
See spec.md AC-22..AC-24; REQ-F-025..028, REQ-N-007, ADR-F03-02.
- `bench/README.md`'s new section states both REQ-N-007 preconditions in substance: (i) never delete `bench/corpus/ledgers/<sha>/` for any SHA a published manifest references; (ii) a corpus item's seed file and held-back F2P files are immutable for any SHA a published manifest references (Q005) — TC-018v reads this content directly.
- **Preconditions report every failing check, not just the first** (operator-debuggability reading of REQ-F-027, pinned here for test-plan.md TC-019a): ledger directory exists, item id resolves in `--corpus`, the `--band` aggregate has an entry for `(item_id, variant_id)` — all three checked before dispatch; zero stub invocations on any failure.
- Synthetic corpus: `fixture.base_sha` and the item's own `fixture_base_sha` both equal the manifest's value (byte-identical, per `corpus.yaml`'s own INVARIANT); `seed_path`/`f2p.paths` absolute, resolved against the corpus file's own directory; `items:` holds exactly the one item, `negative_items:` omitted (REQ-F-026, ADR-F03-02).
- A live-corpus/manifest divergence on `fixture_base_sha`/`p2p_set`/`schema_version` is a named `corpus_drift` entry; the synthetic corpus dispatched always carries the **manifest's** values (REQ-F-028).
- Dispatch passes the manifest's stored `--rep` value against a distinct `--out` root, so the fresh `manifest.run_key` is byte-identical to the stored one (REQ-F-025).
- `RUN_ONE_BIN` defaults to `$SCRIPT_DIR/run-one.sh` when unset (TD-077's defect class, same as T-E40-F03-001).
