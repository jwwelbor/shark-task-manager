# Task: Aggregator core: record classification and provenance uniformity

## Goal
Implement `aggregate-runs.sh`'s core: enumerate `record.jsonl` files by the pinned glob, structurally validate each, classify every record `complete`/`explained_absence`/`anomaly` by the named per-outcome rule, check five-field provenance uniformity across contributing records, and emit the aggregate's `schema_version`, `provenance`, `inventory`, `outcomes`, and `anomalies[]` blocks. This is F03's real I-02 caller path.

## Scope
- Create: `bench/scripts/aggregate-runs.sh` (arg parsing, glob enumeration, record parse/validate, classification, uniformity check, `schema_version`/`provenance`/`inventory`/`outcomes`/`anomalies[]` blocks), `bench/scripts/tests/tc018_aggregate_report_test.sh` (sub-cases a, b, c, d, e, f, q, s, t)
- Modify: `bench/scripts/tests/run-all.sh` (register `tc018`)

## Acceptance Criteria
See spec.md AC-06..AC-11; REQ-F-007..011, REQ-N-004/005.
- Reads only `record.jsonl` files under the artifact root, nothing else — an unreadable `batch-log.jsonl` never affects the result (REQ-F-007).
- Enumeration is the bash glob `"$root"/*/*/rep-*/record.jsonl`, never `find` — a well-formed record under `.incomplete/` must contribute to nothing.
- A structurally invalid record (unsupported `schema_version`, unparseable JSON, missing `manifest`/`outcome`) names the file, exits non-zero, writes **no** `aggregate.json` (REQ-F-010).
- A family's presence is read from the family block itself, never from `sources` (REQ-F-007 2nd sentence — the TD-076 consumer-side consequence).
- Non-uniform provenance across all five fields (`model_ids`/`.fixture_base_sha`/`.variant_bundle_sha256`/`.corpus_schema_version`/`.shark_version`) is reported invalid, naming both differing values, never published as a result (REQ-F-011).
