# Task: Replay resolver (replay-answer.sh)

## Goal
Build the single named owner of request matching, response supply, and consumption recording —
ordinal-primary matching with a topic assertion, three named outcomes, no nearest-match path, byte-
identical reproducibility across runs.

## Scope
- Create: `bench/scripts/replay-answer.sh`, `bench/scripts/tests/tc054_replay_resolver_test.sh`,
  ambiguous-topic fixtures under `bench/scripts/testdata/replay/`

## Acceptance Criteria
See spec.md REQ-F-006, REQ-F-007, REQ-F-008; AC-004, AC-005.
- AC-T1: `--bundle <path> --stage <D0X> --kind <kind> --topic <key>` supplies the lowest unconsumed
  ordinal's response only when `request_kind` and `topic_key` both equal the caller's values; appends
  exactly one consumption record; makes no network call.
- AC-T2: exhaustion of a stage's entries fails `unresolved_gate` naming stage, kind, and topic; a
  disagreeing `--topic` fails `replay_desync` naming both expected and supplied topic; a near-miss topic
  never supplies a response.
- AC-T3: two consecutive passes over the same bundle and call sequence produce byte-identical supplied
  responses and consumption ledgers, exercised against the T-E40-F07-003 fixture's same-stage,
  distinct-ordinal ambiguity.
