# Stop-outcome eligibility triad, partial-evidence durability, and fail-loud writes

## Goal
Implement the §2.6 stop-outcome eligibility triad as a single named,
extractable function; ensure incremental writes survive an aborted/signaled
run without truncation; make any producer write failure terminate loudly.

## Scope
- Modify: `bench/scripts/run-lifecycle.sh` (named triad-writer function,
  called from the termination hook and from `release_on_signal()` line 750
  as an addition, not a change, to its lease-release behavior; write-failure
  handling around every bundle-artifact write).
- Modify: `bench/scripts/tests/tc115_i05_producer_test.sh` (append cases).

## Acceptance Criteria
See spec.md AC-013, AC-014, AC-020.

## Test Cases
Reference test-plan.md TC-013 (5 end-to-end stop outcomes + clean run +
invalid-transition case), TC-014 (5 direct-unit outcomes via source
extraction of the named triad function, plus state-addition regression
against `STOP_OUTCOMES`), TC-015 (partial evidence survives SIGTERM),
TC-022 (mid-run write failure via read-only `stages/`, isolating one write).

## Brownfield Context
`release_on_signal()` raises `SystemExit`, uncaught by `main()`'s except
block — a signal-terminated run skips the normal end-of-run path
(test-plan.md TC-015 implementation-contract note). The triad-writer must
be a single named function so TC-014's source-extraction technique (the one
`tc075` already uses) has a clean boundary.

## Notes for Agent
`bundle.json`'s `stop_outcome` MUST equal the same run's I-07
`outcome.terminal` for every one of the 11 closed-table rows. Never defer a
write to a single end-of-run flush; never truncate an earlier snapshot on
failure. A write failure names the failing artifact in both records.
