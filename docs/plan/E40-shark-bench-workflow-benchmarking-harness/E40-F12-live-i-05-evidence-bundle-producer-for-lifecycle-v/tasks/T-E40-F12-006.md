# Batch and comparison driver pass-through with guard reordering

## Goal
Thread the operator-configured `i05_bundle_dir` from both batch drivers into
`run-lifecycle.sh`, and move each driver's configuration guard to run before
dispatch, so a misconfigured pair fails before burning provider spend.

## Scope
- Modify: `bench/scripts/run-lifecycle-batch.sh` (`dispatch_pair()` line
  822: add `--i05-bundle-dir "$i05_bundle_dir"` to the invocation at line
  887; move the guard at line 902 to before it).
- Modify: `bench/scripts/run-review-comparison.sh` (`dispatch_gate()` line
  719: same pass-through; move its guard at line 819 to before it).
- Modify: `bench/scripts/tests/tc115_i05_producer_test.sh` (append cases).

## Acceptance Criteria
See spec.md AC-018.

## Test Cases
Reference test-plan.md TC-019 (`dispatch_pair()` pass-through + guard
reorder via the `RUN_LIFECYCLE_BIN`/`EVALUATE_LIFECYCLE_BIN` stub
convention, plus the real `e40-benchmark.sh preflight` P5-blocker
regression check), TC-020 (`dispatch_gate()`, same shape, independent call
site).

## Integration Contracts
None — internal argument plumbing between two already-trusted E40-F08
driver scripts; touches no I-## or X-## interface shape.

## Design Reference
See spec.md §2.1 (batch/comparison driver rows), §2.8 (Integration —
"Batch driver"/"Comparison driver"), REQ-F-013, ADR-F12-07.

## Brownfield Context
Both call sites are live, already-wired consumers waiting on this producer
today (Finding 7): they already receive `i05_bundle_dir` and use it for
evaluation/retention but never pass it to the lifecycle binary. No change
to `lib/retain_pair` is in scope (Decision 5).

## Notes for Agent
Assert the pass-through by having the stub record its received argv and
grep for the flag, not merely exit codes. The guard reorder means a
misconfigured pair is recorded invalid before the binary is invoked at all.
