# Benchmark corpus v1: fixture repo and screened tasks

**Feature Key**: E40-F01

See [shark-bench-design.md](../shark-bench-design.md) §2 (corpus & oracles) and §3 (per-entity oracles).

---

## Goal

A benchmark is only as trustworthy as its oracle. This feature builds the fixture repo and the first ~10 corpus tasks (tasks + bugs only in v1) with execution-based oracles, so every bench run has an objective pass/fail independent of any LLM judgment.

## Scope

1. **Fixture repo**: a small, self-contained Go service with a real test suite, pinned at a base commit. Lives outside the shark repo (separate repo or vendored fixture dir — decide at implementation).
2. **Corpus manifest**: per task — issue-style prompt, shark entity seed spec (type, title, description; bugs include severity), held-back F2P test files, P2P test set identifier, reference patch.
3. **Held-back tests never appear in the repo the agent sees** — they live in the corpus dir and are injected post-run.
4. **Admission gate script**: base commit → F2P red + P2P green; reference patch applied → both green. A task failing the gate is excluded.
5. **Base-SHA ledgers**: full test results and golangci-lint issue set at the base commit, stored with the corpus (used post-run to count regressions and *new* lint issues only).

## Acceptance Criteria

- [ ] ~10 tasks/bugs admitted, each passing the admission gate reproducibly
- [ ] Bug entries include an author-written repro test as their F2P oracle
- [ ] Manifest is machine-readable (one format, documented) and sufficient for the harness (E40-F02) to seed and score a run with no manual steps
- [ ] Base-SHA test + lint ledgers generated by script, committed with the corpus

## Out of Scope

- Feature/epic/change-card/tech-debt corpus entries (Phase 2/3; tech-debt blocked on B051)
- SWE-bench Verified instances (Phase 3)
- Difficulty-band pruning (needs baseline data first; revisit after E40-F03)

## Success Metric

Admission gate re-run on a clean checkout reproduces identical results for all corpus entries.
