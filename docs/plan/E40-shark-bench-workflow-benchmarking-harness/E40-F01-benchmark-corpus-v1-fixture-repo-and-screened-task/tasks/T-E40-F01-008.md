# Task: Base-SHA ledger builder

## Goal
Implement `build-ledgers.sh`, generate the base-SHA test and lint ledgers by running the fixture's own `fmt`/`vet`/`lint`/`test`-equivalent targets against a fresh checkout at the `base_sha` T-E40-F01-004 froze, and commit the resulting ledger files — the artifacts every later diff and future E40-F02 post-run check depends on.

## Scope
- Files to create: `bench/scripts/build-ledgers.sh` (`build-ledgers.sh <checkout_dir> <output_dir>`); `bench/corpus/ledgers/<base_sha>/tests.json`; `bench/corpus/ledgers/<base_sha>/lint.json` (committed output of running the script once against the frozen `base_sha` from T-E40-F01-004; the ledger directory name must equal that exact SHA); `bench/scripts/tests/tc007_ledger_reproducibility_test.sh`
- Files to modify: `bench/scripts/tests/run-all.sh` (register the new test script, per the T-E40-F01-005 convention)

## Acceptance Criteria
See spec.md AC-006; REQ-F-008, REQ-F-009, REQ-F-010, REQ-F-012.
- AC-T1: `tests.json` contains one entry per `<package import path>::<test name>`, subtests as distinct slash-named entries, with the terminal action (`pass`/`fail`/`skip`) per entry; `Elapsed` is dropped before writing.
- AC-T2: `lint.json`'s issue identity is the tuple `(from_linter, fixture-relative file path, issue text)`, excluding line/column; identical identities are counted (multiset), and entries are written in a fixed sort order.
- AC-T3: Both ledgers record the toolchain that produced them (Go version, `golangci-lint` version, `GOOS`/`GOARCH`, `.golangci.yml` content hash); `build-ledgers.sh` records this but never compares it against anything (comparison is T-E40-F01-009's sole responsibility).
- AC-T4: Re-running the script against a second, independently provisioned checkout of the same base SHA produces a byte-identical entry set for both ledgers.

## UAT Rejection (2026-08-05)

**Classification:** AC Violation  
**Defect class:** A result-producing subprocess is allowed to fail without a required parseable result, so transport failure is misclassified as an empty domain result.  
**Unmet criteria:** AC-T2 — `lint.json` records the lint issue identity multiset; REQ-F-009 — the base-SHA lint ledger is generated from the linter's JSON report.

**What happened:** `bench/scripts/build-ledgers.sh:98` suppresses every lint exit and stderr. Its parser at `:160-177` writes an empty `entries` list if the linter emitted no JSON. A version-valid temporary linter that exited `1` without stdout made the builder exit `0` and report `22` test entries and `0` lint entries.

**Fix required:**

1. Sweep every result-producing subprocess in `bench/scripts/build-ledgers.sh`, `bench/scripts/admit.sh`, and `bench/scripts/diff-ledgers.sh` for this defect class first. List every swept site and its disposition in the completion note.
2. Preserve non-zero lint exit codes that represent reported issues, but require a parseable v2 JSON report before accepting and writing `lint.json`; fail loudly with the captured diagnostic when the report is absent or malformed.
3. Add a TC-007 regression using a version-valid `golangci-lint` executable that exits non-zero without a JSON report. Assert the builder fails and does not accept an empty lint ledger.
4. Re-run the root gate and the full bench self-test suite.
