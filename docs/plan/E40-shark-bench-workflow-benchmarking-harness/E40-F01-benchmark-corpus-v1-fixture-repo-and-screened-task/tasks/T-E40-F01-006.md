# Task: Admission gate script: five-check decision table

## Goal
Implement `admit.sh`, the execution-based admission gate: for each candidate, run the five checks (F2P red at base, P2P green at base, patch applies, F2P green post-patch, P2P green post-patch) against a fresh `checkout-fixture.sh` checkout, and prove both the all-pass path (admitted items) and every rejection branch names its own failing check.

## Scope
- Files to create: `bench/scripts/admit.sh` (`admit.sh <corpus_yaml_path> [--item <id>]`); `bench/scripts/tests/tc004_admit_full_set_test.sh`; `bench/scripts/tests/tc005_admit_rejection_branches_test.sh` (this script also builds the transient (c)/(e) candidates: copies an admitted item's `reference.patch`, then truncates it for (c) or adds a one-line P2P-flipping mutation for (e))
- Files to modify: `bench/scripts/tests/run-all.sh` (T-E40-F01-005) — register both new test scripts

Follows the Tier 1b/Tier 2 test convention established in T-E40-F01-005.

## Acceptance Criteria
See spec.md AC-003, AC-004; REQ-F-005, REQ-F-006, REQ-F-007.
- AC-T1: Run with no `--item` over the full admitted set: all five checks pass for each of the ≥10 admitted items; ≥1 `bug`-type item's manifest-named repro test is confirmed; output is one JSON verdict line per item, sorted by item id.
- AC-T2: Run with `--item <id>` against each of the three committed negatives (T-E40-F01-004) and the two transient candidates built here: each is rejected with exactly its own check named — (a) F2P-green-at-base, (b) P2P-red-at-base, (c) patch-apply failure surfaced from `git apply`'s own exit status, (d) F2P-still-red-post-patch, (e) P2P-red-post-patch.
- AC-T3: No negative or transient candidate appears in the admitted-item list any run driver would consume.

## Test Cases
TC-004 (`tc004_admit_full_set_test.sh`), TC-005 (`tc005_admit_rejection_branches_test.sh`) — test-plan.md AC test matrix and Caller-Path Contracts: real `git apply`, `go test`, and `golangci-lint` subprocesses in a temp checkout at `base_sha`; do not stub any of the five checks' subprocess results or hardcode a boolean per item; do not special-case negative/transient items to force a specific rejection message.

## UAT Rejection (2026-08-05)

**Classification:** AC Violation
**Defect class:** A package-level test-process failure is considered fully explained by any named test failure, allowing an independent runtime failure to be masked by an expected or excluded failing test.
**Unmet criteria:** AC-T1 — all five checks pass for each admitted item; AC-T2 — the post-patch P2P failure is rejected as `P2P-red-post-patch`.

**What happened:** `admit.sh:272-281` treats any per-test failure as sufficient explanation for a package-level failure. The default P2P set excludes the permanent inventory probe, but that probe masks an added inventory `TestMain` `os.Exit(1)`: the real test command exits 1 while `admit.sh --item inventory-reserve-boundary --patch <combined-patch>` returns admitted.

**Fix required:**

1. Enumeration sweep FIRST: inspect every package-terminal reconciliation path in `admit.sh` and list each swept site in the completion note.
2. Reconcile against only the failures allowed for the current phase, or run P2P in an isolated invocation where F2P and excluded failures cannot mask the package exit.
3. Add a TC-005 regression that puts `TestMain` failure in `pkg/inventory`, which already has the excluded permanent probe; require `P2P-red-post-patch` and a non-zero gate exit.
