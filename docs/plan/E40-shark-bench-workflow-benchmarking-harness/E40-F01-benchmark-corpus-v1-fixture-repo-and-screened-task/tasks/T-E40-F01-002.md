# Task: Corpus manifest schema and first wave of admitted items

## Goal
Define the corpus manifest (`corpus.yaml`) schema and author the first wave of admitted corpus items against the fixture repo from T-E40-F01-001, establishing the reusable item-authoring pattern (prompt, seed spec, held-back F2P tests, reference patch) that T-E40-F01-003 completes to the required count.

## Scope
- Files to create: `bench/corpus/corpus.yaml` (`schema_version`, `fixture` block, `p2p_sets` map, `items[]`); `bench/corpus/items/<item_id>/{prompt.md,seed.yaml,testdata/f2p/*.go,reference.patch}` for the first several admitted items
- Files to modify: fixture repo source (a new commit on the submodule, advancing past T-E40-F01-001's initial commit) to embed the bugs/incomplete behavior each reference patch fixes

## Acceptance Criteria
See spec.md AC-002, AC-013; REQ-F-002, REQ-F-003, REQ-NF-004.
- AC-T1: Every authored item's manifest entry carries the full REQ-F-002 field set (`id`, `type`, prompt path, entity seed spec, held-back F2P paths, F2P test names, `p2p_set` id, reference-patch path, `fixture_base_sha`), well-typed.
- AC-T2: Each item's `p2p_set` resolves to a named entry in `p2p_sets`, declaring package patterns and any `-run` selector/exclusions.
- AC-T3: `corpus.yaml`'s `fixture.base_sha` is set to the submodule's current commit at the end of this task; it is still **provisional** — T-E40-F01-003 advances it further, and T-E40-F01-004 freezes the final value. Update this field with each fixture-content commit; do not treat it as fixed yet.
- AC-T4 (REQ-NF-004): every prompt, seed, F2P source, reference patch, and fixture-repo change authored in this task is original and free of credentials, tokens, personal data, and third-party licensed code. Record a manual corpus-content review of this task's authored artifacts as a task completion note (`shark task note add`) — this is a human-review verification method (test-plan.md's "Corpus review at admission"), not an automated test.
