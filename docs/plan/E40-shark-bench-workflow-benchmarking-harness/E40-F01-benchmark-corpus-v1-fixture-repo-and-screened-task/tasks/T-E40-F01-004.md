# Task: Negative candidate set and transient candidate design

## Goal
Author the committed negative-candidate set that proves the admission gate's rejection path (REQ-F-007), stored apart from the admitted set and never emitted into any run list; document how rejection branches (c)/(e) are built transiently at test time from an admitted item; and **freeze the fixture's final commit as the corpus `base_sha`** now that every admitted and negative item's content exists in one shared fixture state.

## Scope
- Files to create: `bench/corpus/negative/<item_id>/{prompt.md,seed.yaml,testdata/f2p/*.go,reference.patch}` for exactly three items — one exercising rejection branch (a) F2P already green at base, one branch (b) P2P already red at base, one branch (d) reference patch leaves F2P red
- Files to modify: `bench/corpus/corpus.yaml` (`negative_items[]` entries for the three items above; set the final, frozen `fixture.base_sha`)

## Acceptance Criteria
See spec.md AC-004; REQ-F-007, REQ-NF-004.
- AC-T1: Each of the three negative items is structured so `admit.sh` (T-E40-F01-006) rejects it on exactly its intended branch — no negative item accidentally passes all five checks.
- AC-T2: None of the three negative items appears in `corpus.yaml`'s `items[]` (admitted set); they live only under `negative_items[]`.
- AC-T3: Branches (c) patch-apply failure and (e) post-patch P2P failure need no committed fixture (spec.md REQ-F-007) — document, in this task's own notes to T-E40-F01-006, that they are built transiently from a copy of an admitted item's `reference.patch` (truncated for (c); mutated to flip one P2P test for (e)).
- AC-T4: The fixture's commit at the end of this task is **frozen** as `corpus.yaml`'s `fixture.base_sha` — no later E40-F01 task adds further fixture-repo commits; T-E40-F01-008's ledgers and T-E40-F01-010's cross-encoding check are both generated against this exact commit.
- AC-T5 (REQ-NF-004): every prompt, seed, F2P source, and reference patch authored for the three negative candidates is original and free of credentials, tokens, personal data, and third-party licensed code. Record a manual corpus-content review of this task's authored artifacts as a task completion note (`shark task note add`) — human review, not an automated test.
