# Conservative provider-call-plan derivation and arithmetic

## Goal
Implement REQ-F-006: make preflight emit a conservative, evidence-backed
provider-call plan before spend approval — separating fixed, bounded, and
worst-case totals — so an operator never approves spend against a dynamic
estimate presented as an exact count.

## Scope
- Files to modify: `bench/scripts/lib/e40_benchmark.py` (`call_plan.totals` and
  `call_plan.evidence[]` emission inside `_cmd_preflight_locked`;
  `calls_per_entity(family)` reading `spawn_agent` steps from the workflow file
  named in `call_plan.evidence[].workflow_file`, never a harness literal;
  `bounded_descendant_calls` summing over declared descendant families;
  admission-time rejection when both `expected_entity_graph` and
  `max_generated_tasks` are present and the graph's task maxima exceed the
  ceiling).
- Files to create: `bench/scripts/tests/tc106_provider_call_plan_test.sh`.

## Acceptance Criteria
See spec.md AC-F11-16, AC-F11-17, AC-F11-18, AC-F11-25a (§Part 1, REQ-F-006).

## Test Cases
Reference spec.md §7.1 rows 16-18/25a, §7.1a's closed inventories for rows 17
and 18, §7.3.4 (comparator surface, B1-B8 including B7's max-vs-sum trap), and
test-plan.md TC-16/17/18 (`tc106_provider_call_plan_test.sh`).

## Integration Contracts
None new — consumes the `expected_entity_graph` shape T-E40-F11-005 already
declares; no I-## or X-## row changes.

## Design Reference
See spec.md §2.3.3 (`preflight-result.json.call_plan`) and §2.3.3a (Call-plan
arithmetic, ADR-F11-12): `bounded_descendant_calls = SUM(d.max *
calls_per_entity(d.family))`, a **sum**, not `min(graph.max, policy.max)`.

## Brownfield Context
The plan must separate fixed replay-prelude calls, fixed root-lifecycle calls,
review-gate calls, and bounded descendant calls, each with the package,
workflow, model, provider, and resource-policy evidence used to derive it
(feature.md REQ-F-006) — 8 evidence fields per AC-F11-18, not a subset.

## Notes for Agent
A worked example must total 26 for the sum formula, not 18 (a maximum-based
implementation is the exact defect B7 catches). Mutate the workflow file in a
test and require the computed total to change, proving `calls_per_entity` is
read from evidence, not a literal (spec.md §7.1 row 17).
