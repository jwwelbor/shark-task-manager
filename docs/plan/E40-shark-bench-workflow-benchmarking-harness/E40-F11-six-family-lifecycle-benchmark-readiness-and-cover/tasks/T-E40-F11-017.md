# Scenario-root isolation foundation: keyed setup and --scenario-index

## Goal
Implement the REQ-F-012 seeding foundation ahead of curation: key setup roots
by `scenario_id` (not `entity_family`) so same-family scenarios can never
collide, and add `setup --scenario-index <path>` so later tasks seed
dedicated host hierarchies through the production CLI. This unblocks
T-E40-F11-008/009, which need a collision-free seeding mechanism before they
can admit and exercise their new scenarios (task-review remediation: split
out of the former single T-E40-F11-011 to fix reverse build order).

## Scope
- Modify: `bench/scripts/lib/e40_benchmark.py` (`setup_config` 1007-1055:
  per-`scenario_id` seed-record lookup, remove
  `matrix_roots[scenario_id] = {"root_key": roots[family], ...}`;
  `_cmd_setup_locked` seed block ~1198-1272: independent per-`scenario_id`
  hierarchy, every key captured from `shark ... --json`; `cmd_demo`'s
  synthesized `setup` namespace carries a `scenario_index` attribute; add
  `setup --scenario-index <path>`, default `bench/scenarios/scenarios.yaml`).
- Create: `bench/scripts/tests/tc111a_scenario_index_seeding_test.sh` (keyed
  seeding for the four already-admitted families; the full six-family
  isolation and live-db non-mutation proof is T-E40-F11-011's scope).
