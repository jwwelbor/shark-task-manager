# Ceiling validation hardening and fourth-ceiling threading

## Goal
Implement the numeric hardening and the fourth ceiling (`max_provider_calls`)
required by REQ-F-003/REQ-NF-002: reject non-finite/fractional-under-integer
inputs, and thread `--max-provider-calls` through all 8 seams so an approved
ceiling can never be silently dropped before it reaches the batch runner.

## Scope
- Files to modify: `bench/scripts/lib/e40_benchmark.py` (`require_positive`
  754-763; seams S1 4445-4447, S3 788-790, S4 1041-1043, S5 2008-2017, S6
  2407-2409, S7 2604-2609, S8 2708-2712 — see spec.md AC-F11-06a's seam table
  for names; `call_plan.totals`, `resource_policy_digest`).
- Files to modify (breaking-change repair, same cause per spec.md §2.1.6):
  `tc079/080/081/082/087/088/094_*.sh`, `bench/scripts/run-review-comparison.sh`,
  `bench/scripts/run-lifecycle-batch.sh`, `bench/scripts/lib/spend-gate.sh`
  (argv forwarding only).

## Acceptance Criteria
See spec.md AC-F11-06a (8-seam thread table), AC-F11-06b (§Part 1, REQ-F-003
support) and epic.md G12 (already updated per spec.md §2.1.7a to require four
ceilings).

## Brownfield Context
S1's `required=True` is a breaking CLI change — every existing `pilot`/`baseline`/
`variant` invocation in the seven listed suites fails at argparse until updated
(spec.md §2.1.6, `grep -rln 'max-generated-tasks' bench`). S2 (`prepare-replay`)
is parser-optional/handler-required — do not make it `required=True` (would
block T-E40-F11-006's zero-provider preview).

## Notes for Agent
`require_positive` must reject NaN, `+inf`, values overflowing to `inf`
(`must be a finite number`) and reject a fractional value under `integer=True`
(`must be a whole number, got <v>`) rather than truncating. Keep `" 3 "` and
`"1_0"` accepted (spec.md §2.1.2(i)). Each of S1-S8 needs its own negative case
(8 total) — a ceiling accepted at S1 but dropped before S8 is exactly the
defect this task exists to prevent.
