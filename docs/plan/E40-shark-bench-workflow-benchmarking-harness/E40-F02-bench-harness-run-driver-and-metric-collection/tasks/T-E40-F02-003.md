# Task: Driver core: provisioning, seeding, timeout invocation

## Goal
Implement `run-one.sh`: provision the scratch project, repoint `workflow_config` and enable transcript capture, check out the fixture, seed the corpus item via the shark CLI (capturing every assigned key from `--json`), invoke `shark run` under a process-group timeout cap with its own monotonic t0/t1, capture raw stdout/stderr/`run.log` before any parsing, write `meta.json` (t0/t1, exit status, seeded keys, `skip_canary`), and hand off to `collect-run.sh` (T-E40-F02-001) to produce `record.jsonl`.

## Scope
- Create: `bench/scripts/run-one.sh`, `bench/scripts/tests/tc014_run_one_smoke_test.sh` (sub-cases a, b, c, e, g), PATH-stub `shark`/`claude` executables under `bench/scripts/testdata/stubs/`
- Modify: `bench/scripts/tests/run-all.sh` (register `tc014`)

## Acceptance Criteria
See spec.md AC-01, AC-04, AC-11, AC-16, AC-21; REQ-F-001–007, REQ-F-020 (invocation + `--skip-canary` wiring only, not the canary script itself), REQ-N-002/003/006.
- `run-one.sh` resolves `shark` via `PATH` (or a single overridable variable), never a hardcoded path, so TC-014's stub can substitute it.
- The invocation runs in its own process group; cap expiry signals the group, not only the `shark` process (ADR-F02-03).
