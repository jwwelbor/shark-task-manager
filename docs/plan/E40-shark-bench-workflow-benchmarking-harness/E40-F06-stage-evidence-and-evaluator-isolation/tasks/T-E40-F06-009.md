# Task: X-09 usage-mapping canary

## Goal
Build the canary that re-verifies `usage-mapping.yaml` against a real
captured provider envelope, detecting both named REQ-F-019 drift classes —
a mapped path going missing, and the envelope source itself becoming
undecodable — as distinct, correctly-attributed failures.

## Scope
- Create: `bench/scripts/canary-usagemapping.sh`,
  `bench/scripts/tests/tc047_usage_mapping_canary_test.sh`, a drifted
  envelope and a non-JSON transcript fixture under `bench/scripts/testdata/`

## Acceptance Criteria
See spec.md REQ-F-009, REQ-F-019; AC-007, AC-021.
- AC-T1: against the committed envelope fixtures under
  `bench/scripts/testdata/run/`, every `anthropic_claude_cli` slot resolves
  and the canary exits `0`.
- AC-T2: against a copy with one mapped path deleted, the canary fails
  naming the exact slot and path (drift class (a)).
- AC-T3: `--transcript <path>` accepts an operator-supplied real transcript.
- AC-T4: against a transcript whose `---STDOUT---` block is non-JSON, the
  canary fails as one `envelope_source_unavailable` naming the transcript
  path — never nine per-slot failures (drift class (b)).
