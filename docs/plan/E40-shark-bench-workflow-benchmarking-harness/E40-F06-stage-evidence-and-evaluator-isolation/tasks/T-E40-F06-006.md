# Task: Artifact producer/consumer record verdicts

## Goal
Add artifact-record validation to `verify-stage-evidence.sh` keeping "no
observed consumer" (`consumers: []`) and "consumption evidence not
collected" (absent `consumers` key) as two distinguishable, non-coercible
verdicts.

## Scope
- Modify: `bench/scripts/verify-stage-evidence.sh`
- Create: `bench/scripts/tests/tc046_artifact_record_test.sh`, an
  artifact-record fixture under `bench/scripts/testdata/evidence/`

## Acceptance Criteria
See spec.md REQ-F-008; AC-006.
- AC-T1: `consumers: []` yields verdict `orphan`.
- AC-T2: absent `consumers` key yields verdict `consumption_evidence_missing`.
- AC-T3: neither verdict is produced for the other entry, in either
  direction — no coercion of absent-to-empty or empty-to-absent.

## Test Cases
tc046 — test-plan.md AC test matrix row AC-006; Caller-Path Contracts row
tc046.

## Integration Contracts
None — this slice is internal to I-05's own artifact-record schema.

## Design Reference
spec.md "Stage snapshot (I-05)" `artifacts` row; ADR-F06-07.

## Brownfield Context
- Modify `bench/scripts/verify-stage-evidence.sh` (T-E40-F06-004) — keep the
  ledger portion untouched.
- Follow ADR-F06-07: `consumers: []` and an absent key are two distinct,
  both-legal states — verify raw JSON key presence, not a decoded zero
  value that would default an absent key to an empty slice.
- Do not implement candidate identity, access ordering, or stop-outcome
  eligibility here (T-E40-F06-005, -007, -008).

## Notes for Agent
A Go-style `omitempty`/zero-value decode collapsing the two states is the
exact trap this check must not fall into.
