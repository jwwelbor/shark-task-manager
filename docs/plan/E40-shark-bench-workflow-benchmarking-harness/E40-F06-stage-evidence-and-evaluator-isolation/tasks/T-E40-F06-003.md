## UAT Rejection (2026-08-15, round 4)

**Classification:** AC Violation
**Defect class:** isolation guards that approximate a declared normalized test identity with a filename-derived token leave renamed semantic leaks undetected.
**Unmet criteria:** AC-009 — the guard must reject every evaluator-only test identity in a fresh checkout and in either live worker-visible root (REQ-F-010, REQ-F-011).

**What happened:** `verify-evidence-roots.sh`'s `test_identity` match kind (`bench/scripts/verify-evidence-roots.sh:212-217,243-261`) derives its search target from the `oracle_tests[]` file's *basename stem* (e.g. `test_recurring` from `test_recurring.py`), not from the actual normalized test identity the file defines (e.g. `test_recurring.py::test_add_task_accepts_recurrence_rule`). A file renamed to something unrelated (`renamed_oracle_identity.py`) that still contains `def test_add_task_accepts_recurrence_rule(): pass` matches none of the three check kinds (filename, content_digest, test_identity) and the guard exits `0` / `CLEAN` — a real held-back oracle test identity leaks into an agent-visible root undetected.

**Reproduction (UAT round 4):** planted `renamed_oracle_identity.py` containing the real `py-feature-recurring-tasks` oracle test function in a clean fixture root; `verify-evidence-roots.sh` exited `0`.

**Fix required:**
1. Before fixing the cited instance, sweep the touched module for every other place a declared identity is approximated by a filename-derived token rather than the actual identity, and list swept sites in the completion note.
2. Derive the normalized test identity(ies) each `oracle_tests[]` file defines through the package's adapter/I-04 identity contract (e.g. `bench/adapters/python/adapter.sh`'s own identity derivation), not via filename/stem heuristics in the generic guard — REQ-F-007 language-neutrality still applies: the generic guard must not itself parse language-specific syntax; delegate identity derivation to the adapter.
3. Reject a match on the derived identity string appearing in either agent-visible root, independent of the file's name or digest.
4. Add a negative test: a renamed, content-different file carrying a held-back test's real identity must be rejected, naming the identity. Preserve existing clean-root and false-positive (AC-T3 rename-changes-target, word-boundary) coverage — do not regress tc043's existing cases.
5. Preserve the report at `docs/review/E40-shark-bench-workflow-benchmarking-harness/E40-F06-stage-evidence-and-evaluator-isolation/uat-20260815T144821Z-E40-F06.md`.

## Code Review Rejection (2026-08-15, round 3)

**Verdict:** FAIL — three blockers on commit `032a7136` (the round-4 UAT fix above).
**Full report:** `docs/review/E40-shark-bench-workflow-benchmarking-harness/E40-F06-stage-evidence-and-evaluator-isolation/code-review-20260815T152646Z-E40-F06.md`

The round-4 fix's intent (adapter-derived real test identity instead of filename-stem approximation) is correct and closes the exact non-parametrized reproduction case, confirmed by counter-factual revert/restore. But it introduced three new defects:

(1) `verify-evidence-roots.sh:212-219`'s `derive_test_identities` joins the candidate `package.yaml`'s own `adapter.name` directly into a filesystem path with no registry lookup or containment check, unlike this exact codebase's own established precedent (`admit-scenario.sh:151-158`'s `resolve_adapter_script`, a `scenarios.yaml` `adapters:` registry lookup) and unlike `resolve_in_evaluator_root` 20 lines above in the same file, which explicitly treats `package.yaml`-declared paths as untrusted and enforces containment. Reproduced: `os.path.join` with an absolute or `'../'`-laden `adapter_name` escapes `bench/adapters/` entirely, letting a not-yet-admitted candidate package select and execute an arbitrary script with real `--checkout`/`--file` arguments, in the exact script whose job is to gate that candidate. Fix by resolving `adapter.name` through a registry (`scenarios.yaml`'s `adapters:` map, mirroring `admit-scenario.sh`) or, at minimum, validating it is a bare identifier with no path separators before any path join.

(2) The `derived_test_identity` signal searches for the literal pytest node-id string (e.g. `test_foo[1]`), which for parametrized tests never appears in the file's actual source text (`def test_foo(n): ...`) — silently defeating the signal for the exact renamed-and-stripped attack this round exists to close, for any oracle test using `@pytest.mark.parametrize`. No committed package triggers this today, but it is a standard pytest idiom and AC-009/REQ-F-011 say "every" test identity, not "every non-parametrized" one. Fix by deriving a base identity (without the trailing `[param]` suffix, or in addition to it) for the word-boundary search, or by searching for the underlying function-definition-derived component pytest generates the node id from.

(3) `bench/adapters/python/adapter.sh` was edited, and REQ-NF-006 (spec.md:78/508/579) names `bench/adapters/**` as part of this feature's frozen, byte-unchanged surface; AC-018's diff review (test-plan.md:212) exists to catch exactly this, and round 1's report confirmed all 9 REQ-NF-006 files byte-unchanged before this commit.

**Do not revert** the underlying `derived_test_identity` fix or the counter-factually-verified tc043 regression case — both are correct in intent.

**Before re-submitting:**
(a) Fix items 1 and 2 above with tc043 regression coverage for each (a malicious/escaping `adapter.name` case; a parametrized-oracle-test rename case) — sweep `verify-evidence-roots.sh`, `verify-stage-evidence.sh`, `replay-stage-evidence.sh`, and `canary-usagemapping.sh` for every other place a `package.yaml`/bundle-derived value reaches `os.path.join` or a subprocess argv without a registry lookup or containment check (this is a different, broader sweep than the filename-stem-approximation sweep the round-4 fix's commit message already performed — list every site checked and its outcome in the completion note).

(b) For item 3: **reimplement the identity-derivation capability without touching `bench/adapters/**` at all.** `cmd_test` is not a safe substitute (it executes the held-back oracle's body). The parent loop has decided: do not seek a spec-amendment/owner-sign-off path for this round — that decision requires human authorization this task cannot obtain on its own, and complying with the existing REQ-NF-006 boundary as written needs no such authorization. Before building the new collector, **prototype its file placement first** and run `bash bench/scripts/tests/tc051_evidence_offline_determinism_test.sh` standalone to confirm AC-019's forbidden-token sweep (which greps generic evidence/isolation/replay scripts for `python|pytest|pip|go test|golangci-lint|go build`, excluding only `bench/adapters/*/` and tc051 itself) does not trip on the new file. If it does trip, STOP — do not widen tc051's exception regex to accommodate the new code (that would be silently editing an AC-019 guard to pass itself); report the conflict back to the parent loop instead of proceeding.

Two additional non-blocking, empirically-reproduced hardening gaps were logged as review-finding notes for optional inclusion in the same pass: malformed adapter JSON (empty/non-string names) not schema-validated, and pytest warning-summary lines containing `::` parsed as spurious identities (false-positive risk, not a leak-detection miss). Both live in the exact code being rewritten — fold them in now since they're free in this pass, per the reviewer's own note.

## Code Review Rejection (2026-08-15, round 4)

**Verdict:** FAIL — one blocker on commit `bc716aff` (the round-3 rework fix above).
**Full report:** `docs/review/E40-shark-bench-workflow-benchmarking-harness/E40-F06-stage-evidence-and-evaluator-isolation/code-review-20260815T161637Z-E40-F06.md`

All three round-3 blockers (adapter.name path-escape, `[param]`-suffix parametrize gap, frozen `bench/adapters/python/adapter.sh` edit) are genuinely fixed — independently re-verified by direct exploit reproduction against the fixed code, a counter-factual disproof, and a fresh `git diff --stat` against the actual E40-F05 merge-base. **Do not revert any of that work.**

But this round's own new code (`bench/scripts/id-collectors/python-collect-ids.sh`, entirely new in `bc716aff`) reopens the identical defect class round-3's finding F.2 closed for one pytest idiom, via a different, equally standard one:

`derive_test_identities`/`python-collect-ids.sh:138-160` reconstructs a test's identity by string-splitting `pytest --collect-only -q`'s free-form text output on `::`. A `@pytest.mark.parametrize(..., ids=[...])` custom identifier containing a **space** causes the line-shape filter added in THIS round (line 150, added specifically to close round-3's non-blocker F.8) to silently discard that test's collect-only line entirely — no identity, not even the base name, is ever derived for it. A custom id containing **`::`** causes the `::`-splitting logic (unchanged since the original round-4 implementation) to take the wrong segment as the name, emitting a garbage identity instead of the real one.

**Reproduction (round 4 code review):** end-to-end against a real `checkout-scenario-fixture.sh` checkout of `py-feature-recurring-tasks`: a mixed oracle file (one ordinary test plus one `ids=["case with space"]`-parametrized test, replacing the real `evaluator/test_recurring.py`) verifies `CLEAN` on untouched roots (no false hard-fail), and **also verifies `CLEAN`** after planting `renamed_leak_custom_id.py` containing only `def test_add_task_accepts_recurrence_rule_custom(): pass` — the real held-back oracle's actual function body, matching none of the four detection signals. This is the identical silent-bypass failure mode UAT round 4 and code-review round 3 both exist to close, now open again.

**Fix required:**
1. Sweep this defect class specifically: any place a test/parameter identity is reconstructed by parsing pytest's own free-form `--collect-only` text output (string-splitting on `::`, filtering on whitespace, or any other heuristic keyed to the *shape* of a normal node id) is fragile against custom, user-supplied parametrize content, since pytest does not escape or bound `ids=` values in that output.
2. Consider deriving the identity from pytest's own structured collection data instead — e.g. a plugin/conftest hook reading `item.originalname` (the literal function name pytest itself computes, with the parametrize suffix already excluded and no custom-id content ever mixed in) — rather than patching the text parser again for this specific case. The last two rounds have each closed one instance of this same underlying fragility only to leave (or, this round, introduce) another; a structural fix is warranted over a third textual-filter patch.
3. Add tc043 regression coverage for BOTH sub-cases (a custom id containing a space; a custom id containing `::`), verified end-to-end against a real fixture checkout the way this round's own two regression cases are. Re-run the full existing tc043 suite (all 12 cases, including both round-3 regression cases) to confirm nothing regresses.
4. Fold in two non-blocking documentation gaps found in the same pass (not required before re-submission, but adjacent and cheap): `bench/README.md:296`'s "Adapter capability contract" section still claims `bench/adapters/<name>/adapter.sh` is "the ONLY place in `bench/` that may know a fixture's language, package manager, or toolchain" — no longer true given `bench/scripts/id-collectors/python-collect-ids.sh`, and the "Three-root policy" section ~650 lines later documents the exception without this section acknowledging it; `bench/README.md:951`'s own new prose claiming the collector emits "every identity a file defines" is inaccurate given this finding and should be corrected as part of the same fix.

**This is round 3 of rework on this task.** All three kickbacks so far have been for different, genuine findings (stem approximation → path-escape/parametrized-suffix/frozen-file trio → this custom-parametrize-id gap) — not a repeat-finding loop, and each round's fix for its own targeted defect has held up under counter-factual/exploit re-verification.
