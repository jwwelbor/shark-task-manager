# run-review-comparison.sh operator comparison driver

## Goal
Build the operator review-comparison driver supporting both
`independent_frozen_candidate` and `sequential_delivery` modes for the
feature-QA gate versus the finish-feature deep-review gate, delegating
identity adjudication entirely to `compare-lifecycle-evaluations.sh`.

## Scope
- Files to create: `bench/scripts/run-review-comparison.sh`;
  `bench/scripts/tests/tc079_operator_preview_zero_spend_test.sh`
  (comparison half, same file as T-004's batch half); `bench/scripts/tests/tc087_review_comparison_operator_test.sh`.

## UAT Rejection (2026-08-21)

**Classification:** AC Violation
**Defect class:** Required retained artifacts with no source are materialized as placeholders and accepted as complete instead of failing closed.
**Unmet criteria:** REQ-F-004 — a comparison run must retain required raw evidence as byte-preserved source copies.

**What happened:** The comparison driver invokes the same shared retention helper as the batch driver and therefore accepts the same fabricated required artifacts for both gate records.

**Fix required:**

1. Sweep both `retain_gate` and its shared helper call path for all required-artifact fallback behavior.
2. Pass and retain real entity-history and held-back-oracle sources for both QA and deep-review gate records; fail closed if unavailable.
3. Add comparison-driver counterfactual tests for every missing-source condition.

**Full UAT results:** `docs/review/E40-shark-bench-workflow-benchmarking-harness/E40-F10-operator-workflow-and-retained-lifecycle-baseline/uat-2026-08-21T200738Z-E40-F10.md`

## UAT Rejection (2026-08-21)

**Classification:** AC Violation
**Defect class:** a provider-backed baseline command proceeds using presence-only or bypassable attestation evidence (paired with T-E40-F10-003) and treating a present file/digest as proof of verified source derivation (paired with T-E40-F10-004)
**Unmet criteria:** AC-004 — "only the verified current attestation proceeds"; AC-005 — "each damaged root fails naming the artifact and reason"

**What happened:**
1. `run-review-comparison.sh` never passes `--batch` to the spend-gate check (see `lib/spend-gate.sh:293-310`), so its baseline dispatch reaches the weak, presence-only ledger check instead of the stronger per-family verification path.
2. `run-review-comparison.sh`'s reuse fast path (`gate_dest_provenance_ok`, `:651-658`) has the same completeness gap as `run-lifecycle-batch.sh`'s: it checks identity-bearing manifest presence, not full artifact/digest verification.

**Fix required:**
1. Enumeration sweep FIRST: search `run-review-comparison.sh` for every spend-gate invocation and every reuse/skip fast-path branch; fix all of them; list the swept sites in the completion note.
2. Coordinate with T-E40-F10-003's fix: once the per-family attestation check is made unconditional (not gated on `--batch`), confirm `run-review-comparison.sh`'s call site actually exercises it — do not just add a redundant `--batch` flag if the library-side fix already removes the gate.
3. Coordinate with T-E40-F10-004's fix: apply the same artifact-presence-plus-digest-recomputation strengthening to `gate_dest_provenance_ok` that T-E40-F10-004 applies to `pair_provenance_ok`, so both drivers enforce identical reuse-completeness semantics.

**Full UAT results:** docs/review/E40-shark-bench-workflow-benchmarking-harness/E40-F10-operator-workflow-and-retained-lifecycle-baseline/uat-2026-08-21T233606Z-E40-F10.md
