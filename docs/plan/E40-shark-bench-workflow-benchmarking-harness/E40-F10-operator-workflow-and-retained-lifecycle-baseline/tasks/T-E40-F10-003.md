# spend-gate.sh acknowledgement and ceiling pre-check library

## Goal
Add the single sourced library owning refusal semantics for both
provider-backed drivers: the explicit `--acknowledge-provider-spend` check,
the ceiling presence/positivity pre-check, the `--retention-root` presence
check, and the pilot-ledger gate check, each emitting a schema-owned refusal
reason and a refusal exit status distinct from the usage-error status.

## Scope
- Files to create: `bench/scripts/lib/spend-gate.sh` (new file in the
  existing `bench/scripts/lib/` directory); `bench/scripts/tests/tc080_spend_gate_refusal_test.sh`.

## Acceptance Criteria
See spec.md REQ-F-002, REQ-F-003, ADR-F10-02, ADR-F10-03. Reference AC-003.
- AC-T1: Refusal occurs before any subprocess, checkout, or Shark call.
- AC-T2: Acknowledgement is satisfiable only by the CLI flag — not an
  environment variable, config default, or stored prior acknowledgement.
- AC-T3: Ceiling positivity delegates to `run-lifecycle.sh`'s existing
  `parse_limits()`; this library re-checks only presence/positivity early,
  adding no second divergent validator.

## UAT Rejection (2026-08-21)

**Classification:** AC Violation
**Defect class:** a provider-backed baseline command proceeds using presence-only or bypassable attestation evidence
**Unmet criteria:** AC-004 — "only the verified current attestation proceeds"

**What happened:** `spend_gate_check_pilot_ledger` (`lib/spend-gate.sh:183-199`) accepts any existing `pilot-ledger.jsonl` file — it does not verify the attestation is current or per-family. The stronger per-family verification path is a no-op whenever the caller does not pass `--batch` (`lib/spend-gate.sh:293-310`), and the non-executable-ledger-helper branch fails open (`lib/spend-gate.sh:334-337`). `run-review-comparison.sh` never passes `--batch` (see T-E40-F10-005's paired rejection), so comparison-mode baseline dispatch reaches provider-backed work with merely a present ledger file.

**Fix required:**
1. Enumeration sweep FIRST: search `lib/spend-gate.sh` for every branch that treats file/flag *presence* as sufficient proof of attestation (not just the `--batch`-gated branch and the fails-open non-executable-helper branch already cited); fix all of them, not just the cited instance; list the swept sites in the completion note.
2. Make per-family attestation verification unconditional — it must run regardless of whether `--batch` was passed, since the underlying risk (a provider-backed baseline running for a family that was never inspected) is identical from both call sites.
3. Change the non-executable-ledger-helper branch to fail closed (refuse dispatch, named reason) instead of failing open.
4. Coordinate with T-E40-F10-005: `run-review-comparison.sh` must be updated to invoke the strengthened gate path so comparison-mode baseline is covered.
