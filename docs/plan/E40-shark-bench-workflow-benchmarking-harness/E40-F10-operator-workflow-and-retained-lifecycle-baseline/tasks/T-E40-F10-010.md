# aggregate-lifecycle.sh noise_bands, comparisons, and invalid blocks

## Goal
Complete the aggregator with `noise_bands` (min/median/max/spread/acceptance
interval/derivation rule/rep count/`insufficient_reps`), `comparisons`
(verbatim comparator verdicts and divergence reasons), and `invalid` (the
invalid-run inventory mirroring `invalid/index.jsonl`), enforcing that no
composite/blended score field exists anywhere in the schema or aggregate.

## Scope
- Files to modify: `bench/scripts/aggregate-lifecycle.sh` (adds these three
  blocks to the file T-008/T-009 started).
- Files to create: `bench/scripts/tests/tc088_dimension_separation_and_noise_band_test.sh`
  (aggregator half).

## Acceptance Criteria
See spec.md REQ-F-007 (`insufficient_reps`), REQ-F-008 (verbatim eligibility
copy), REQ-F-016, ADR-F10-12. Reference AC-011 (aggregator half), AC-013
(partial: `noise_bands` determinism).
- AC-T1: A rep count below the batch policy's declared minimum sets
  `insufficient_reps: true` rather than silently publishing the band.
- AC-T2: `eligibility.aggregate_eligible`/`publication_eligible`/
  `invalidity_reasons` are copied verbatim from I-08 with no recomputation,
  override, or softening.

## Test Cases
See test-plan.md TC-088 full body (aggregator half, target (i): schema
property-name scan against `forbidden_composite_fields`, excluding the
schema's own list declaration).

## Integration Contracts
N/A — `comparisons` re-publishes `compare-lifecycle-evaluations.sh`'s
already-computed verdict (owned by T-005's driver call); `invalid` mirrors
I-08 `eligibility` already copied in T-008.

## Design Reference
See spec.md `aggregate.json` blocks table (`noise_bands`, `comparisons`,
`invalid` rows) and REQ-F-016's "no composite, weighted, or blended... score"
prohibition.

## Brownfield Context
Reuses `aggregate-runs.sh`'s existing noise-band/`insufficient_reps` flag
semantics (spec.md ADR-F10-12) rather than inventing a new statistic.

## Notes for Agent
The noise-band boundary-inclusivity rule (open vs. closed interval) must
already be stated in the schema from T-001; this task implements against
that stated rule rather than picking one ad hoc.
