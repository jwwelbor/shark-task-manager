# verify-retention-root.sh offline retention validator

## Goal
Build the offline retention validator: layout completeness, per-artifact
digest equality against `manifest.json`'s recorded source digests, upstream
schema validity delegated to the existing verifiers, and pair-level lineage —
emitting a bounded verdict without ever repairing a root.

## Scope
- Files to create: `bench/scripts/verify-retention-root.sh`;
  `bench/scripts/tests/tc082_retention_layout_test.sh`.

## Acceptance Criteria
See spec.md REQ-F-004, REQ-NF-007. Reference AC-005.
- AC-T1: A complete root verifies cleanly; each of the eight retained
  artifacts (`package.yaml`, `evidence/`, `transcripts/`,
  `entity-history.json`, `lifecycle.jsonl`, `evaluation.jsonl`,
  `oracle.json`, `manifest.json`) fails distinctly when missing, digest-
  mismatched, or re-serialized, each naming the artifact and reason.
- AC-T2: A root missing `manifest.json` fails layout-completeness before any
  digest check is attempted.

## Test Cases
See test-plan.md TC-082 full body (all eight artifacts individually, not one
representative case).

## Integration Contracts
N/A — this validator checks byte/digest integrity and delegates upstream
schema validity; it does not itself read I-05/I-07/I-08 semantic fields.

## Design Reference
See spec.md Architecture Component-changes row for
`bench/scripts/verify-retention-root.sh` and API section.

## Brownfield Context
Delegates upstream schema validity to the existing
`bench/scripts/verify-lifecycle-run.sh` and
`bench/scripts/verify-lifecycle-evaluation.sh` (spec.md "Integration with
existing code" section) rather than duplicating either validator.

## Notes for Agent
Digest rules are SHA-256 over compact sorted-key UTF-8 JSON, matching the
I-05/I-07/I-08 `digest_rules` referenced by the F10 schema (T-001).

## UAT Rejection (2026-08-21)

**Classification:** AC Violation
**Defect class:** Required retained artifacts with no source are materialized as placeholders and accepted as complete instead of failing closed.
**Unmet criteria:** AC-005 — a complete retention root verifies only when every required artifact is a byte-preserved source copy.

**What happened:** The validator accepts a matching digest for a placeholder and intentionally skips empty `source_path` provenance, so it reports a fabricated required artifact as retained and valid.

**Fix required:**

1. Sweep every required-artifact validation branch, including matching-digest fast paths.
2. Fail a retention root when a required artifact lacks source provenance, regardless of the placeholder digest.
3. Add fixtures for each required file and directory missing-source case, including the entity-history and oracle paths.

## UAT Rejection (2026-08-21)

**Classification:** AC Violation
**Defect class:** treating a present file, digest field, or non-empty provenance string as proof of verified source derivation
**Unmet criteria:** AC-005 — "each damaged root fails naming the artifact and reason"

**What happened:** `verify-retention-root.sh`'s digest check (`:417-428`) accepts digest equality between a manifest entry and the retained file without checking that the manifest's claimed provenance path was real or that the recorded source actually produced that digest. A retained tree whose manifest was hand-crafted with a matching digest for fabricated content would pass this offline validator.

**Fix required:**
1. Enumeration sweep FIRST: search `verify-retention-root.sh` for every manifest-field check that stops at digest/presence equality without an independent provenance cross-check; fix all of them; list the swept sites in the completion note.
2. Extend the check at `:417-428` to validate provenance consistency (e.g., cross-reference against the retention producer's own recorded source metadata, per T-E40-F10-006's coordinated fix), not just bytes-vs-manifest-digest equality.
3. Coordinate with T-E40-F10-006 so both the ledger recorder/verifier and the offline retention validator apply the same provenance standard — a root that passes one must not silently fail the standard the other enforces.

**Full UAT results:** docs/review/E40-shark-bench-workflow-benchmarking-harness/E40-F10-operator-workflow-and-retained-lifecycle-baseline/uat-2026-08-21T233606Z-E40-F10.md
