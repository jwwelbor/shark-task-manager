## Notes

**E22 is an active foundation, not a frozen one** (6 features draft, 1 assessment, 7 completed). X-07 is therefore covered by an explicit canary check rather than by assumption — see ADR-004. Treating the `RunResult`/`StageLog` contract as settled is the single largest silent-corruption risk in this epic.

**Feature-level ownership, not an epic-wide audience.** X-07's producer is named as E22-F08 specifically — it is the only current E22 feature whose title, scope, and live tasks touch `RunController`'s dispatch functions and worktree isolation, i.e. the exact code path that shapes `RunResult`/`StageLog`. X-08 has no legitimate E22 consumer feature to name: `shark run --json` stdout consumers are dispersed across skills, agents, and CLI callers system-wide, not owned by one E22 feature. Its activation owner is therefore E40-F04 itself, accountable via its own UAT-06 stdout-preservation check, with a forward obligation recorded on E22-F08 to keep that check green when it next lands changes to the same dispatch path.

**X-09 stays `proposed` deliberately.** Its owning feature and test coverage are TBD because it is Phase 2 work with no feature boundary yet, and because Q003 must first confirm the live envelope field names. Per the epic-design rule, Phase 2 decomposition or test planning must close both before their gates pass. The producing branch is unmerged on both `main` and this branch: Phase 2 planning must treat its merge state as a precondition, not as landed capability.

**No E23 row.** E40-F04 writes `.shark/runs/<run_id>/run.log` unconditionally, deliberately outside the observability config gate. That is a departure from E23's slog path, not a use or extension of its contract, so it is recorded as architecture prose rather than as an integration row.

**CX review.** X-07 and X-09 are internal seams with no user journey. X-08 is the only row with a user-facing handoff, and it improves continuity for every `shark run` user: a long run stops being indistinguishable from a hung one, and the log path is surfaced at run start rather than left to be discovered.
