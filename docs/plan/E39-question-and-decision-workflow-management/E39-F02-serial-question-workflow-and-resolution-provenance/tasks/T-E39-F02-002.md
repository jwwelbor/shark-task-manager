# Publish the Question workflow, route responders, and record responses

## Goal
Publish the six-state Question workflow and responder prompt before using the existing single Question claim to route only the derived first pending responder and atomically record an authorized, bounded successful response.

## Scope
- Modify `internal/services/question_service.go`, `internal/services/question_repo_adapter.go`, `internal/services/claim_service.go`, `internal/cli/commands/next.go`, `run.go`, `status_group.go`, `internal/sharkdata/default_data/workflow/question.yaml`, and `internal/sharkdata/default_data/prompts/question/` only as I-02 requires.
- Modify focused service, CLI keyed-dispatch, and workflow/prompt loading tests.
- Exclude resolver closure, direct blocking gates, focused reads, and additional claim or queue semantics.

## Acceptance Criteria
- See `spec.md` REQ-F-002, REQ-F-003, REQ-NF-001/002/003, REQ-F-007, and AC-003–AC-004.
- Preserve the standard `NextResponse` envelope and parent-owned claim/release lifecycle.
- The route-based six-state bundle and first-pending responder prompt are available before the real keyed-next tests run.

## Test Cases
- Implement `test-plan.md` TC-103, TC-104, and TC-105 first, including the loaded workflow/prompt, first-only routing, lifecycle-only non-mutation, competing sessions, exact idempotency, and transactional audit rollback.
