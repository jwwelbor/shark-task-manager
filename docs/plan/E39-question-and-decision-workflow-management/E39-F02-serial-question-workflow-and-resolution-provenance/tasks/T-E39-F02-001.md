# Validate Question state, configure workflow, and migrate draft records

## Goal
Establish the bounded, Question-owned I-02 state, initialize one configured Question workflow atomically, and safely migrate registered I-01 Questions from `draft` to `open` without expanding generic context behavior.

## Scope
- Modify `internal/models/question.go`, `internal/models/context_data.go`, `internal/db/db.go`, `internal/repository/question/repository.go`, `internal/services/question_service.go`, and `internal/services/question_repo_adapter.go`.
- Modify focused model, database, repository, and Question-service tests.
- Exclude responder dispatch, response recording, terminal provenance, and all transport routes.

## Acceptance Criteria
- See `spec.md` REQ-F-001, REQ-F-002 migration paragraph, REQ-NF-001, REQ-NF-002, REQ-NF-003, and AC-001–AC-002.
- State validation remains Question-owned; generic context setters cannot accept I-02 fields.
- `QuestionService.ConfigureWorkflow` owns typed initial-state validation and one transactional state, typed-note, and history write; repeat configuration and raw JSON write nothing.

## Test Cases
- Implement `test-plan.md` TC-101 and TC-102 first, including all documented UTF-8 boundary, forbidden-content, atomic-rejection, migration-preservation, and one-time configuration partitions.
