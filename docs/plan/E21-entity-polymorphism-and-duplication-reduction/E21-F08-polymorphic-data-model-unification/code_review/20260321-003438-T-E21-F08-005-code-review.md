# Code Review: T-E21-F08-005 - Simplify EntityDocumentService to Use Polymorphic Repository

**Reviewer**: TechLead
**Date**: 2026-03-21
**Task**: T-E21-F08-005
**Result**: APPROVED

## Summary

This task refactors `EntityDocumentService` from a callback-based pattern (linkFn, unlinkFn, listFn) to a clean interface-based pattern using `EntityDocumentLinkRepository`. The constructor is simplified from 6 parameters to 3, and all 5 entity service callers are updated to pass the polymorphic repository instead of constructing per-entity closures. CLI wiring in `services_global.go` and `service_accessors.go` is updated accordingly.

## Code Quality Assessment

### Strengths

1. **Clean interface definition**: `EntityDocumentLinkRepository` is defined at the point of use (line 20-24), following the project's "define interfaces at the consumer" convention.

2. **Consistent error wrapping**: All error paths use `fmt.Errorf("context: %w", err)` with clear business context (e.g., "failed to link document to epic E07: FK violation").

3. **Idempotent unlink**: The idempotent behavior for missing documents is preserved correctly (lines 90-93).

4. **Non-nil empty slice contract**: `ListDocumentsByKey` properly converts nil to `[]*models.Document{}` (lines 118-120).

5. **entityLookupFn returns EntityType**: The signature change from `(int64, error)` to `(int64, models.EntityType, error)` is clean and eliminates the need for a fixed `entityType` field on the struct.

6. **5 callers are consistent**: All `SetWritableDocRepo` methods follow the exact same pattern -- accept `(EntityDocumentRepository, EntityDocumentLinkRepository)`, construct lookup closure, call `NewEntityDocumentService`.

7. **Tests are thorough**: 14 test cases in entity_document_service_test.go covering happy paths, error paths, idempotency, nil-to-empty-slice, and all 5 entity types. Mock definitions are clean with function field pattern.

8. **Per-entity interfaces cleaned up**: The 5 `*WritableDocumentRepository` interfaces were removed with clear comments explaining the replacement.

### Minor Observations (Non-blocking)

1. **Comment in epic_service.go line 118**: References "EpicWritableDocumentRepository interface" in the SetWritableDocRepo godoc, but the interface no longer exists. This is cosmetic and the meaning is still clear from context.

2. **Fallback paths in EpicService/FeatureService**: `ListForEpic` and `ListForFeature` calls remain in the read-only fallback path using `s.docRepo`. This is explicitly noted as out of scope (deferred to T-E21-F08-009) and is correct behavior.

## Architecture Compliance

- Follows service layer design principles (fat services, thin controllers)
- Interface defined at consumer (entity_document_service.go)
- Constructor injection with explicit dependencies
- No business logic in repositories
- Tests use mocked repositories, never real database
