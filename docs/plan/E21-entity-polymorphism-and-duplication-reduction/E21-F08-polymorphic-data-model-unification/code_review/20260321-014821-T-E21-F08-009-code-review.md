# Code Review: T-E21-F08-009 -- Remove Legacy Document Repository Methods and Dead Code

**Reviewer**: TechLead
**Date**: 2026-03-21
**Task**: T-E21-F08-009
**Status**: APPROVED

## Summary

This task removes 16 entity-specific Link/Unlink/List methods from `document_repository.go`, introduces a `PolymorphicDocRepoAdapter` to bridge service-layer callers to the polymorphic `EntityDocumentRepository`, updates wiring in CLI and display service, and adds deprecation markers to `TaskHistoryRepository`. The implementation is clean, well-structured, and follows the adapter pattern as specified in ADR-3.

## Code Quality Assessment

### Adapter Pattern (polymorphic_doc_adapter.go)
- Clean, focused file (42 lines)
- Clear godoc comments explaining purpose and delegation pattern
- Each method is a trivial one-liner delegating to `EntityDocumentRepository.ListForEntity()`
- Correct use of `models.EntityTypeEpic`, `models.EntityTypeFeature`, `models.EntityTypeTask` constants
- Properly placed in `repository` package alongside its dependency

### display_service.go Change
- `DocumentRepo` field correctly changed from `*repository.DocumentRepository` to `config.DocumentRepository` (interface)
- This decouples the display service from the concrete repository implementation
- All existing call sites (`ListForEpic`, `ListForFeature`) continue to work unchanged through the interface

### Wiring Updates (services_global.go, service_accessors.go)
- Adapter properly constructed: `NewEntityDocumentRepository(db)` -> `NewPolymorphicDocRepoAdapter(entityDocRepo)`
- Injected via `SetDocRepo(docAdapter)` pattern consistent with existing service wiring
- HTTP server (`cmd/server/services.go`) correctly left unchanged as it does not use document repositories

### Deprecation Markers (task_history_repository.go)
- 10 deprecation markers applied to all public types and methods
- Each references the replacement: `Use EntityHistoryRepository instead` or `Use EntityHistoryFilters instead`
- No behavioral changes to the code -- purely documentation

### Principles Followed
- **Appropriate**: Adapter pattern is the right solution for this migration; minimizes blast radius
- **Proven**: Standard GoF Adapter pattern applied correctly
- **Simple**: Each changed file is straightforward; no unnecessary abstractions
- **Principle of Least Surprise**: Service callers see no behavioral change; the adapter transparently delegates

## Minor Finding (Non-blocking)

The `internal/cli/commands/mock_document_repository.go` still defines a `DocumentRepositoryInterface` with legacy `LinkToEpic`, `LinkToFeature`, `LinkToTask`, `UnlinkFromEpic`, `UnlinkFromFeature`, `UnlinkFromTask` methods. These are used by test files (`related_docs_test.go`, `task_reason_doc_test.go`) for testing CLI command logic.

This is acceptable because:
1. The interface is defined in the test package (`commands`), not in production code
2. The mock is self-contained and does not implement any production interface
3. All tests pass
4. The production code path exclusively uses `EntityDocumentRepository.Link()` / `Unlink()` / `ListForEntity()`

A follow-up cleanup task could update these CLI test mocks to use `EntityDocumentRepository`-style methods, but this is purely a test hygiene improvement with no production impact.
