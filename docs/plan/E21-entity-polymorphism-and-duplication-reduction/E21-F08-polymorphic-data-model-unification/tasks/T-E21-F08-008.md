# CLI Updates: Status History and Related-Docs for All Entity Types

## Goal

Update `shark status history` to work for all 5 entity types (epic, feature, task, bug, change-card) and verify `shark related-docs` already supports bugs and change-cards. This delivers the user-facing value of F08: the new polymorphic history and document capabilities exposed through the CLI.

## Why

Users currently cannot run `shark status history E21-F07` because the command hard-gates on `entityType != "task"` (line 555 of `status_group.go`). The polymorphic `entity_history` table and `EntityHistoryService.GetHistory()` method (completed in T-E21-F08-007) now support all entity types, but the CLI command still rejects non-task keys.

For `shark related-docs`, the `--bug` and `--change` flags already exist (lines 282-283, 289-290 of `related_docs.go`) and dispatch through `BugService.LinkDocument` and `ChangeCardService.LinkDocument`. This task must verify this works end-to-end via the new polymorphic `entity_documents` table and `EntityDocumentLinkRepository`, and fix any broken wiring.

**Feature PRD traceability**: Feature Story 2 (status history for all entity types), Feature Acceptance Scenario 2 (history for features). See [feature.md User Stories](../feature.md#must-have-stories).

## User Stories

### US-1: Status History for Features

**As a** developer reviewing a feature's lifecycle,
**I want** to run `shark status history E21-F07`,
**So that** I can see when and why the feature's status changed.

**As a** developer triaging a bug,
**I want** to run `shark status history B001`,
**So that** I can see the audit trail of status changes for that bug.

**I want** `shark status history E21-F08-001` to continue working,

**As a** developer linking analysis documents to a bug,
**I want** `shark related-docs add --bug=B001 --path=docs/analysis.md` to work,
**So that** I can associate design docs with any entity type.

## Business Rules

### BR-1: Entity Type Detection via ParseGetArgs

The `status history` command must use the existing `ParseGetArgs()` function to auto-detect entity type from the key format. No new key-parsing logic should be introduced. Key detection rules:

| Key Pattern | Entity Type |
|-------------|-------------|
| `E##` | `epic` |
| `E##-F##` | `feature` |
| `E##-F##-###` or `T-E##-F##-###` | `task` |
| `B###` | `bug` |
| `CC-###` | `change` |

### BR-2: EntityHistory to StatusHistoryEntry Mapping

The `models.EntityHistory` struct must be mapped to the existing `StatusHistoryEntry` JSON struct as follows:

| EntityHistory Field | StatusHistoryEntry Field | Mapping Rule |
|---------------------|--------------------------|--------------|
| `ChangedAt` | `Timestamp` | Format as `time.RFC3339` |
| `FromStatus` | `OldStatus` | Dereference `*string`; use empty string if nil |
| `ToStatus` | `NewStatus` | Direct copy |
| `ChangedBy` | `Agent` | Dereference `*string`; use empty string if nil |
| `Notes` | `Notes` | Dereference `*string`; use empty string if nil |

### BR-3: Limit Flag Applies After Service Returns

The `--limit` flag truncates the result set in the CLI command layer (not in the service), matching the current task-history behavior. The service returns all records; the command truncates.

### BR-4: Related-Docs Already Has Bug/Change Flags

The `related_docs.go` command already has `--bug` and `--change` flags registered (lines 282-283, 289-290). No new flags need to be added. The task must verify the existing dispatch works through the new polymorphic repository.

## Edge Cases

### EC-1: Invalid Key Format

**Input**: `shark status history INVALID_KEY`
**Expected**: `ParseGetArgs` returns an error; command exits with a descriptive error message.

### EC-2: Entity Exists But Has No History

**Input**: `shark status history E21` (epic exists but has never had a status transition recorded in `entity_history`)
**Expected**: Exit code 0; JSON output has `"history": []`; human-readable output says "No status history found for epic E21".

### EC-3: Very Large History Set

**Input**: Entity with 1000+ history records, no `--limit` flag
**Expected**: All records returned. Performance should be acceptable (indexed query on `entity_type, entity_id`).

### EC-4: Limit of Zero or Negative

**Input**: `shark status history E21-F07 --limit=0` or `--limit=-1`
**Expected**: Treated as "no limit" (return all records), matching the existing behavior where `limit <= 0` means "use default 50" in the service but the CLI passes the flag value directly.

### EC-5: Related-Docs Add with Both --bug and --feature Flags

**Input**: `shark related-docs add "Doc" docs/x.md --bug=B001 --feature=E21-F07`
**Expected**: Command rejects with usage error because exactly one parent flag must be specified. This is already enforced by the `count != 1` check in `runRelatedDocsAdd`.

### EC-6: Case-Insensitive Key for History

**Input**: `shark status history e21-f07` (lowercase)
**Expected**: Command works correctly; `ParseGetArgs` handles case normalization.

## Architecture Decisions (verified 2026-03-21)

### ADR-1: Normalize `change_card` to `change` in runStatusHistory

**Context**: `ParseGetArgs` returns `"change_card"` for `CC-###` keys and `"change"` for `C###` keys, but `models.EntityTypeChange` is `"change"`. The `EntityHistoryService.GetHistory()` method expects `models.EntityType` which maps to the `entity_history.entity_type` column (always `"change"`).

**Decision**: Add a normalization step in `runStatusHistory` that maps `"change_card"` to `"change"` before calling the service. This matches the pattern already used in `dispatchTransition` which has separate `case "change":` and `case "change_card":` branches.

**Implementation**: A single `if entityType == "change_card" { entityType = "change" }` before the service call.

### ADR-2: Keep task history backward-compatible via dual-path

**Context**: The current `runStatusHistory` calls `cli.GetTaskServiceWithHistory().GetTaskHistory()` which queries the legacy `task_history` table. The new `EntityHistoryService.GetHistory()` queries the polymorphic `entity_history` table. Tasks may have history in both tables.

**Decision**: For tasks, use the new `EntityHistoryService.GetHistory()` just like for all other entity types. The task `entity_history` records are written by the polymorphic `EntityService.TransitionStatus()` (T-E21-F08-006). If the task was transitioned via the old path (pre-E21), those records live only in `task_history` and will not appear. This is acceptable because:
1. The old `task history` subcommand (`shark task history`) still queries `task_history` and remains available.
2. The `shark status history` command is being generalized for all entity types and should use the unified table.
3. The `StatusHistoryEntry` JSON schema is identical regardless of which backing table is used.

### ADR-3: Related-docs already fully wired -- verification only

**Context**: After reading `related_docs.go`, the `--bug` and `--change` flags are already registered (lines 282-283, 289-290) and fully dispatched through `BugService.LinkDocument()` and `ChangeCardService.LinkDocument()` for add/delete/list. No code changes needed.

**Decision**: This task only adds test coverage for the existing bug/change paths. No source changes to `related_docs.go`.

## Implementation Notes

### Key Change in `runStatusHistory` (status_group.go)

The current implementation (lines 554-559) has:
```go
if entityType != "task" {
    cli.Error(fmt.Sprintf("Status history is only available for tasks, not %ss", entityType))
    cli.Info("Use 'shark status transitions <key>' to see available transitions for any entity type")

```

This entire block (lines 554-559) plus the legacy task-specific code (lines 561-577) must be replaced. The replacement code should:

1. Normalize entity type: `if entityType == "change_card" { entityType = "change" }` (see ADR-1)
2. Call `cli.GetEntityHistoryService().GetHistory(ctx, models.EntityType(entityType), key)` for all entity types
3. Map `[]*models.EntityHistory` to `[]StatusHistoryEntry` using BR-2 mapping rules:

| EntityHistory Field | StatusHistoryEntry Field | Rule |
|---------------------|--------------------------|------|
| `ChangedAt` | `Timestamp` | `h.ChangedAt.Format(time.RFC3339)` |
| `FromStatus` | `OldStatus` | Dereference `*string`; `""` if nil |
| `ToStatus` | `NewStatus` | Direct copy |
| `ChangedBy` | `Agent` | Dereference `*string`; `""` if nil |
| `Notes` | `Notes` | Dereference `*string`; `""` if nil |

4. Keep the existing `StatusHistoryResult` JSON output format and `--limit` truncation
5. Update the "No status history found" message from `"task %s"` to `"%s %s"` using `displayEntityTypeName(entityType)`

### Refactored `runStatusHistory` target structure (under 50 lines)

```go
func runStatusHistory(cmd *cobra.Command, args []string) error {
    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    // Step 1: Parse arguments
    entityType, key, err := ParseGetArgs(args)
    if err != nil { return fmt.Errorf("invalid key format: %w", err) }

    // Step 2: Normalize entity type for polymorphic table
    if entityType == "change_card" { entityType = "change" }

    limit, _ := cmd.Flags().GetInt("limit")

    // Step 3: Get history via EntityHistoryService
    svc := cli.GetEntityHistoryService()
    history, err := svc.GetHistory(ctx, models.EntityType(entityType), key)
    if err != nil {
        if strings.Contains(err.Error(), "not found") {
            cli.Error(fmt.Sprintf("%s %s not found", displayEntityTypeName(entityType), key))
            os.Exit(1)
        }
        return fmt.Errorf("failed to get status history: %w", err)
    }

    // Step 4: Apply limit and map to StatusHistoryEntry
    if limit > 0 && len(history) > limit {
        history = history[len(history)-limit:]
    }

    entries := make([]StatusHistoryEntry, 0, len(history))
    for _, h := range history {
        entry := StatusHistoryEntry{
            Timestamp: h.ChangedAt.Format(time.RFC3339),
            NewStatus: h.ToStatus,
        }
        if h.FromStatus != nil { entry.OldStatus = *h.FromStatus }
        if h.ChangedBy != nil { entry.Agent = *h.ChangedBy }
        if h.Notes != nil { entry.Notes = *h.Notes }
        entries = append(entries, entry)
    }

    result := &StatusHistoryResult{
        EntityType: entityType,
        EntityKey:  key,
        History:    entries,
        Total:      len(entries),
    }

    // Step 5: Format output
    if cli.GlobalConfig.JSON { return cli.OutputJSON(result) }

    if len(entries) == 0 {
        cli.Info(fmt.Sprintf("No status history found for %s %s", displayEntityTypeName(entityType), key))
        return nil
    }

    // Table output (same as before)
    ...
}
```
