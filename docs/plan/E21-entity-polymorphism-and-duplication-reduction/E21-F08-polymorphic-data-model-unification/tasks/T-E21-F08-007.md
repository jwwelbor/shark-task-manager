# EntityHistoryService: Query History for All Entity Types

## Goal

Create `EntityHistoryService` that provides history query operations for any entity type, and update `TaskHistoryService` to delegate to the new service for backward compatibility. This enables CLI commands (T-E21-F08-008) to query history for epics, features, bugs, and change-cards (previously only tasks had history).

## Why

The existing `TaskHistoryService` only queries `task_history`. With `entity_history` now containing records for all entity types (written by `EntityService` per T-E21-F08-006), a generalized query service is needed. The old `TaskHistoryService` must continue working identically for backward compatibility -- specifically `shark task sessions`, `shark task timeline`, and `shark task history` commands depend on it.

## Architecture Decisions (Verified Against Codebase 2026-03-21)

### ADR-1: Do NOT refactor TaskHistoryService.GetTaskHistory to delegate

**Context**: The spec originally suggested refactoring `GetTaskHistory` to delegate to `EntityHistoryRepository`. However:
- `TaskHistoryService.GetTaskHistory` returns `[]*models.TaskHistory` (different type from `[]*models.EntityHistory`)
- `GetHistoryByTaskKey` in `task_history_repository.go` queries the `task_history` table (line 253-260) which still exists in the schema
- The `task_history` table is kept for backward compatibility (schema comment: "kept for backward compatibility until T-E21-F08-004")
- Both `task_history` (old) and `entity_history` (new) tables coexist; `EntityService.TransitionStatus` writes to `entity_history`
- Converting between `TaskHistory` and `EntityHistory` would require field mapping (`OldStatus`/`NewStatus` vs `FromStatus`/`ToStatus`, `Agent` vs `ChangedBy`, `Timestamp` vs `ChangedAt`)

**Decision**: Leave `TaskHistoryService` completely untouched. The `EntityHistoryService` is a new, parallel service for the new `entity_history` table. No delegation, no refactoring of `TaskHistoryService`.

**Rationale**: Zero regression risk. `TaskHistoryService` continues to work with `task_history` table exactly as before. New functionality uses `EntityHistoryService` with `entity_history` table. Future cleanup of `task_history` table is a separate task.

### ADR-2: EntityHistoryService interface matches actual repository

**Context**: The `EntityHistoryRepository` (verified at `internal/repository/entity_history_repository.go`) exposes:
- `ListByEntity(ctx, entityType, entityID)` -- returns `[]*models.EntityHistory`, ordered `changed_at DESC`
- `ListRecent(ctx, limit)` -- returns `[]*models.EntityHistory`, ordered `changed_at DESC`
- `ListWithFilters(ctx, EntityHistoryFilters)` -- flexible query with optional filters

**Decision**: The `EntityHistoryQuerier` interface needs only `ListByEntity` and `ListRecent`. `ListWithFilters` is not needed for the service's two methods (`GetHistory` and `GetRecentHistory`). If advanced filtering is needed later, `ListWithFilters` can be added to the interface.

### ADR-3: EntityRegistry wiring follows NoteService pattern

**Context**: `GetNoteService` in `services_global.go` (line 79-95) uses `GetEntityRegistry()` for entity type resolution. The `EntityRegistry` is a singleton initialized with `sync.Once` containing adapters for all 5 entity types.

**Decision**: `GetEntityHistoryService` will follow the same pattern -- use `GetEntityRegistry()` for key-to-ID resolution. No need to construct a new registry.

### ADR-4: GetEntityHistoryService uses non-singleton (per-call) pattern

**Context**: Some services use `sync.Once` singleton pattern (NoteService, ContextService, ResumeService), while others are per-call (TaskService variants, BugService, ChangeCardService).

**Decision**: Use per-call pattern (no `sync.Once`) since `EntityHistoryService` is lightweight (two interface references) and has no mutable state. This matches the simpler services.

## User Stories

### US-1: Query History for Any Entity Type

As a CLI user or developer agent, I want to query status change history for any entity type by providing its key, so that I can audit when and why an epic, feature, bug, or change-card's status changed.

### US-2: Query Recent History Across All Entity Types

As a CLI user, I want to retrieve the most recent status changes across all entity types, so that I can see what changed recently in the project without specifying an entity.

### US-3: Backward-Compatible Task History

As an existing CLI user, I want `shark task history`, `shark task sessions`, and `shark task timeline` commands to continue producing identical results, so that upgrading to the polymorphic data model does not break my workflow.

## Acceptance Criteria

### AC-1: EntityHistoryService.GetHistory resolves key and returns history

**Given** an `EntityHistoryService` constructed with an `EntityHistoryQuerier` and `EntityRegistry`
**When** `GetHistory(ctx, entityType, entityKey)` is called with `entityType="feature"` and `entityKey="E21-F07"`
**Then**:
- The service resolves `entityKey` to `entityID` by calling `EntityRegistry.GetRepository(entityType).GetByKey(ctx, entityKey)` then `entity.GetID()`
- The service calls `historyRepo.ListByEntity(ctx, entityType, entityID)`
- The method returns `[]*models.EntityHistory` in `changed_at` DESC order (most recent first, matching repository behavior)
- If the entity does not exist, the method returns a wrapped error from the entity repository (not a nil slice)

### AC-2: GetHistory works for all five entity types

**Given** an `EntityHistoryService`
**When** `GetHistory` is called with each of the five entity types: `epic`, `feature`, `task`, `bug`, `change`
**Then** for each call, the service successfully resolves the key via the corresponding `EntityRepository` adapter (verified: adapters exist for all 5 types in `services_global.go` lines 47-56) and returns the history records from `entity_history`

### AC-3: GetRecentHistory returns cross-entity results

**Given** an `EntityHistoryService`
**When** `GetRecentHistory(ctx, limit)` is called with `limit=10`
**Then**:
- The service calls `historyRepo.ListRecent(ctx, 10)`
- The method returns up to 10 `*models.EntityHistory` records sorted by `changed_at` DESC
- Records may include a mix of entity types (epic, feature, task, bug, change)
- If `limit <= 0`, the service uses a default limit of 50

**Given** an entity that exists but has no status change records in `entity_history`

## Implementation Specification

### File: `internal/services/entity_history_service.go`

```go
// EntityHistoryQuerier is the interface EntityHistoryService depends on for queries.
// Satisfied by *repository.EntityHistoryRepository.
type EntityHistoryQuerier interface {
    ListByEntity(ctx context.Context, entityType models.EntityType, entityID int64) ([]*models.EntityHistory, error)
    ListRecent(ctx context.Context, limit int) ([]*models.EntityHistory, error)
}

// EntityHistoryService provides history query operations for all entity types.
type EntityHistoryService struct {
    historyRepo EntityHistoryQuerier
    registry    *EntityRegistry
}

func NewEntityHistoryService(historyRepo EntityHistoryQuerier, registry *EntityRegistry) *EntityHistoryService {
    requireNonNil(historyRepo, "EntityHistoryService requires a non-nil EntityHistoryQuerier")
    requireNonNil(registry, "EntityHistoryService requires a non-nil EntityRegistry")
    return &EntityHistoryService{historyRepo: historyRepo, registry: registry}
}

// GetHistory retrieves status change history for a specific entity.
// entityType: one of "epic", "feature", "task", "bug", "change"
// entityKey: the entity's key (e.g., "E21", "E21-F07", "E21-F08-001", "B001", "CC-001")
// Returns []*models.EntityHistory in changed_at DESC order.
func (s *EntityHistoryService) GetHistory(ctx context.Context, entityType models.EntityType, entityKey string) ([]*models.EntityHistory, error) {
    // 1. Resolve entity type to repository via registry
    repo, err := s.registry.GetRepository(entityType)
    if err != nil {
        return nil, fmt.Errorf("failed to get history for %s %s: %w", entityType, entityKey, err)
    }

    // 2. Resolve entity key to entity (and thus to ID)
    entity, err := repo.GetByKey(ctx, entityKey)
    if err != nil {
        return nil, fmt.Errorf("failed to get history for %s %s: %w", entityType, entityKey, err)
    }

    // 3. Query history by entity type + entity ID
    return s.historyRepo.ListByEntity(ctx, entityType, entity.GetID())
}

// GetRecentHistory retrieves the most recent status changes across all entity types.
// limit: max records to return. If <= 0, defaults to 50.
func (s *EntityHistoryService) GetRecentHistory(ctx context.Context, limit int) ([]*models.EntityHistory, error) {
    if limit <= 0 {
        limit = 50
    }
    return s.historyRepo.ListRecent(ctx, limit)
}
```

// GetEntityHistoryService returns an EntityHistoryService instance.
// Creates a new instance each call (lightweight, no shared state).
// Panics on DB failure (matching existing GetDB pattern for CLI entry points).
func GetEntityHistoryService() *services.EntityHistoryService {
    db, err := GetDB(context.Background())
    if err != nil {
        panic(fmt.Sprintf("failed to get database for EntityHistoryService: %v", err))

    historyRepo := repository.NewEntityHistoryRepository(db)
    return services.NewEntityHistoryService(historyRepo, GetEntityRegistry())
}

## Business Rules

1. **Key resolution is the service's responsibility**: The caller passes an entity key (e.g., "E21-F07"), not a database ID. The service resolves the key to `(entity_type, entity_id)` via the `EntityRegistry` and entity repository adapters.

2. **History records are read-only from this service**: `EntityHistoryService` only queries history. It does not create history records -- that is `EntityService.TransitionStatus`'s responsibility (T-E21-F08-006).

3. **TaskHistoryService is not modified (ADR-1)**: It remains completely untouched. It continues querying the `task_history` table for backward compatibility with existing CLI commands.

4. **Error propagation**: Repository errors are wrapped with business context (e.g., `"failed to get history for feature E21-F07: ..."`) following the project's error wrapping pattern.

5. **Default limit for GetRecentHistory**: When `limit <= 0`, use 50 as the default (matching `EntityHistoryFilters.Limit` default in the repository).

## Edge Cases

| Edge Case | Expected Behavior |
|-----------|-------------------|
| Entity exists but has zero history records | Return empty non-nil slice, nil error (repo guarantees this) |
| Entity type valid but key does not exist | Return wrapped not-found error from entity repo |
| Entity type not registered in EntityRegistry | Return error "no repository registered for entity type ..." |
| `GetRecentHistory(ctx, 0)` | Use default limit of 50 |
| `GetRecentHistory(ctx, -1)` | Use default limit of 50 |
| `GetRecentHistory(ctx, 1000)` | Pass 1000 to repo (no cap -- repo handles pagination) |
| Concurrent calls to GetHistory | Safe -- EntityRegistry uses RWMutex; repos are stateless |
| Task entity key in short format ("E21-F08-001") vs long format ("T-E21-F08-001") | EntityRepository adapter handles both formats via `TaskRepositoryAdapter.GetByKey` |
| Context cancelled during repository call | Repository returns context.Cancelled; service propagates it |
