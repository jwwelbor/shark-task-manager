# Wire entity_history recording into TaskService, BugService, and ChangeCardService transitions

## Goal

Add `entity_history` recording to TaskService, BugService, and ChangeCardService status transitions so that `shark status history` returns complete history for ALL entity types. Currently only Epic and Feature transitions record to `entity_history` (via EntityService.TransitionStatus). Task/Bug/ChangeCard transitions bypass EntityService and never write to `entity_history`.

## Why (UAT Blocker)

Codex red-team review found that REQ-F-005 ("All status transitions create history records for all entity types") is NOT MET:
- `TaskService.TransitionStatus` (task_service.go:582) calls `StatusUpdateRaw` directly — never writes `entity_history`
- `BugService` (bug_service.go:317) has no history recording at all
- `ChangeCardService` (change_card_service.go:309) has no history recording at all

Result: `shark status history <task-key>` returns empty for new transitions.

## Requirements

### Functional Requirements

- [ ] TaskService.TransitionStatus writes to `entity_history` after successful status update
- [ ] BugService status transitions write to `entity_history`
- [ ] ChangeCardService status transitions write to `entity_history`
- [ ] History records capture: entity_type, entity_id, from_status, to_status, changed_by, notes, forced
- [ ] History recording is non-blocking (errors logged, not propagated — matching EntityService pattern)
- [ ] `shark status history <task-key>` shows new task transitions
- [ ] `shark status history <bug-key>` shows bug transitions
- [ ] `shark status history <change-key>` shows change-card transitions

### Non-Functional Requirements

- [ ] No performance regression on status transitions (history write is async-safe, non-blocking)
- [ ] Backward compatible — existing `task_history` table continues to work for legacy queries

## Implementation Plan

### Approach: Inject EntityHistoryRecorder into each service

Follow the same pattern as EntityService (entity_service.go:173-202):

1. Add `historyRepo EntityHistoryRecorder` field to TaskService, BugService, ChangeCardService
2. Add `SetHistoryRepo(repo EntityHistoryRecorder)` setter (or constructor param) for each
3. After successful status update in each service's transition method, call:
   ```go
   if s.historyRepo != nil {
       history := &models.EntityHistory{
           EntityType: models.EntityType("task"), // or "bug", "change"
           EntityID:   entity.GetID(),
           ToStatus:   targetStatus,
           Forced:     opts.Force,
           ChangedAt:  time.Now(),
       }
       if fromStatus != "" {
           history.FromStatus = &fromStatus
       }
       if opts.Agent != "" {
           history.ChangedBy = &opts.Agent
       }
       if opts.Reason != "" {
           history.Notes = &opts.Reason
       }
       if err := s.historyRepo.Create(ctx, history); err != nil {
           log.Printf("warning: failed to record entity history for %s %s: %v", entityType, key, err)
       }
   }
   ```
4. Wire in `services_global.go` — set historyRepo on GetTaskService(), GetBugService(), GetChangeCardService()
5. Wire in `cmd/server/services.go` for HTTP API

## Notes

- This task was created after UAT REJECT. The original design assumed all transitions would flow through EntityService.TransitionStatus (per ADR-3 in 02-architecture.md). In practice, TaskService/BugService/ChangeCardService have their own TransitionStatus methods. E21-F09 (Service Delegation Completion) may eventually unify these, but F08 must deliver history for all types NOW.
- The `EntityHistoryRecorder` interface (defined in entity_service.go) only requires `Create(ctx, *EntityHistory) error` — minimal surface area to implement.
