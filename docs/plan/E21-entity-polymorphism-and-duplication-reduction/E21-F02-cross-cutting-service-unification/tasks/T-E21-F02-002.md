# Task: Refactor ContextService to use EntityRegistry

## Goal

Refactor ContextService to accept an `*EntityRegistry` instead of 5 per-entity repository fields. Replace the two 5-branch switch statements (`getContextJSON`, `setContextJSON`) with single-line registry lookups. Remove all per-entity setter methods. Target: reduce `context_service.go` from ~308 lines to ~170 lines.

## Requirements

### Functional Requirements

- [ ] Remove 5 per-entity repository interfaces: `ContextEpicRepository`, `ContextFeatureRepository`, `ContextTaskRepository`, `ContextBugRepository`, `ContextChangeCardRepository`
- [ ] Replace ContextService struct fields (5 entity repos) with single `registry *EntityRegistry` field
- [ ] Change constructor to `NewContextService(registry *EntityRegistry)`
- [ ] Constructor must panic if `registry` is nil with message "ContextService: EntityRegistry must not be nil"
- [ ] Replace `getContextJSON` 5-branch switch with: `registry.GetRepository(entityType)` -> `repo.GetByKey()` -> `repo.GetContextData()`
- [ ] Replace `setContextJSON` 5-branch switch with: `registry.GetRepository(entityType)` -> `repo.GetByKey()` -> `repo.UpdateContextData()`
- [ ] Remove `SetBugRepo()` and `SetChangeCardRepo()` setter methods
- [ ] Preserve existing behavior: `GetContext`, `SetContextField`, `ClearContext`, `isValidContextField`, `updateContextField` unchanged

### Non-Functional Requirements

- [ ] `make fmt && make lint && make test` passes
- [ ] Net reduction of ~101 lines in context_service.go
- [ ] Zero behavioral changes for existing CLI context operations

### Technical Approach

- `getContextJSON` becomes:
  ```go
  repo, err := s.registry.GetRepository(entityType)
  entity, err := repo.GetByKey(ctx, entityKey)
  return repo.GetContextData(ctx, entity.GetID())
  ```
- `setContextJSON` becomes:
  ```go
  repo, err := s.registry.GetRepository(entityType)
  entity, err := repo.GetByKey(ctx, entityKey)
  return repo.UpdateContextData(ctx, entity.GetID(), contextJSON)
  ```

### Critical Behavior Preservation

The F01 adapter implementations handle per-entity differences transparently:
- `EpicRepositoryAdapter.GetContextData` -> calls `repo.GetContextData(ctx, id)` (dedicated repo method)
- `TaskRepositoryAdapter.GetContextData` -> calls `repo.GetByID`, returns `task.ContextData` (field read)
- `BugRepositoryAdapter.GetContextData` -> calls `repo.GetByID`, returns `bug.ContextData` (field read)

The ContextService refactoring delegates to these adapters via the registry. The adapters handle the per-entity differences.
