# Add batch GetByIDs repository method to fix N+1 queries

## Goal

Add `GetByIDs(ctx context.Context, ids []int64) ([]*models.Task, error)` to `TaskRepository` and wire it into `EntityRelationshipService` via the `TaskByIDResolver` interface, eliminating the N+1 query pattern in relationship resolution.

## Scope

- Files to modify:
  - `internal/repository/task_repository.go`
  - `internal/services/entity_relationship_service.go` (update `TaskByIDResolver` interface and `resolveTaskRelationships` helper to use batch fetch)
  - `internal/repository/task_repository_test.go`

## Acceptance Criteria

See spec.md REQ-2 for full acceptance criteria.

- AC-T1: `GetByIDs` uses a single SQL query with `WHERE id IN (...)` parameterization
- AC-T2: Empty `ids` slice returns empty slice and no error (no SQL executed)
- AC-T3: IDs not found are silently skipped; no error returned for missing IDs
- AC-T4: `TaskByIDResolver` interface in `entity_relationship_service.go` includes `GetByIDs` (see spec.md Section 3.1)
- AC-T5: `resolveTaskRelationships` uses batch fetch instead of per-ID lookups (see spec.md Section 3.3)

See test-plan.md repository test cases: `GetByIDs_MultipleTasks`, `GetByIDs_EmptyInput`, `GetByIDs_SomeMissing`, `GetByIDs_AllMissing`, `GetByIDs_SingleID`.
