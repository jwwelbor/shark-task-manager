# Task: Eliminate entityLookupFn closure duplication via registry adapters

## Goal

Remove 5 near-identical `entityLookupFn` closures in `SetWritableDocRepo` methods across epic, feature, bug, change_card, and task_dependency services. Each closure does `repo.GetByKey(ctx, key)` then returns `entity.ID, nil`.

## Context

Found during E21-F01 code review. The `EntityRepository` adapters already provide `GetByKey` that returns `models.Entity`. The `entityLookupFn` could be derived from the registry adapter instead of creating per-service closures.

## Implementation Plan

1. Add a helper function (or method on `EntityDocumentService`) that accepts an `EntityRepository` and derives the lookup function
2. Replace the 5 inline closures with calls to the shared helper
3. Consider whether `NewEntityDocumentService` should accept an `EntityRepository` directly instead of a `func(ctx, key) (int64, error)`

## Files

- `internal/services/epic_service.go` (SetWritableDocRepo)
- `internal/services/feature_service.go` (SetWritableDocRepo)
- `internal/services/bug_service.go` (SetWritableDocRepo)
- `internal/services/change_card_service.go` (SetWritableDocRepo)
- `internal/services/task_dependency_service.go` (SetWritableDocRepo)

## Acceptance Criteria

- [ ] No more inline entityLookupFn closures
