# Task: Remove fallback entity repo adapters by making entityRepo required

## Goal

Remove ~90 lines of duplicate inline fallback adapters (`epicEntityRepoAdapter` in `epic_service.go` and `featureEntityRepoAdapter` in `feature_service.go`) by making `entityRepo` a required constructor parameter. Both CLI and HTTP wiring always provide `entityRepo` via the registry, so the fallback is dead code.

## Context

Found during E21-F01 code review. The inline adapters duplicate the dedicated `EpicRepositoryAdapter` and `FeatureRepositoryAdapter` files. The only callers that construct EpicService/FeatureService (CLI `service_accessors.go` and HTTP `cmd/server/services.go`) always pass a non-nil `entityRepo`.

## Implementation Plan

1. Make `entityRepo EntityRepository` a required parameter in `NewEpicService` and `NewFeatureService` constructors
2. Add `requireNonNil` check for `entityRepo` in both constructors
3. Remove `if entityRepo == nil` fallback branches in `TransitionStatus` and `GetNextStatus`
4. Delete `epicEntityRepoAdapter` struct and methods (~45 lines)
5. Delete `featureEntityRepoAdapter` struct and methods (~45 lines)
6. Update all callers (CLI and HTTP wiring) — should already pass non-nil
7. Update tests that construct services without `entityRepo` to pass a mock

## Acceptance Criteria

- [ ] `entityRepo` is required in both constructors (panics on nil)
- [ ] Inline fallback adapters removed
- [ ] All tests pass with mock entityRepo
- [ ] `make fmt && make lint && make test` passes
