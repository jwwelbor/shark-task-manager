# Task: Add UpdateStatus to FeatureRepository for atomic status updates

## Goal

Add an `UpdateStatus(ctx, id, status)` method to `FeatureRepository` (both interface and concrete implementation) to match the pattern already established by `EpicRepository`. Currently, the `FeatureRepositoryAdapter.UpdateStatus` does a non-atomic `GetByID` + `Update` sequence.

## Context

Found during E21-F01 code review. `EpicRepository` has `UpdateStatus` as a single atomic SQL UPDATE, but `FeatureRepository` lacks it. The `FeatureRepositoryAdapter` works around this by doing `GetByID` then `Update` — two separate queries without a transaction.

## Implementation Plan

1. Add `UpdateStatus(ctx context.Context, id int64, status string) error` to `FeatureRepository` interface in `internal/services/feature_service.go`
2. Implement in `internal/repository/feature_repository.go` as a single `UPDATE features SET status = ? WHERE id = ?`
3. Update `FeatureRepositoryAdapter.UpdateStatus` to call the new repo method directly
4. Update any inline fallback adapter (if T-E21-F06-003 hasn't removed it yet)
5. Add repository test for the new method

## Acceptance Criteria

- [ ] `FeatureRepository` interface includes `UpdateStatus`
- [ ] Concrete implementation uses single SQL UPDATE
- [ ] Adapter delegates to repo method (no more GetByID+Update)
- [ ] Repository test covers the new method
- [ ] `make fmt && make lint && make test` passes
