# Task: CLI and HTTP wiring updates for EntityService in services_global.go and server

## Goal

Update CLI wiring in `services_global.go` and HTTP server wiring in `cmd/server/services.go` to create
`EntityService` as a shared singleton and pass it (along with `EntityRepository` adapters) to all
entity-specific service constructors.

## Requirements

### Functional Requirements

- [ ] Add `GetEntityService() *services.EntityService` function with `sync.Once` lazy initialization in `services_global.go`
- [ ] `GetEntityService` creates EntityService with `GetWorkflowService()` dependency
- [ ] Update `GetEpicService()`: pass `entitySvc` and `entityRepo` (from EntityRegistry) to `NewEpicService`, remove direct `workflowSvc` pass
- [ ] Update `GetFeatureService()`: pass `entitySvc` and `entityRepo` to `NewFeatureService`, remove direct `workflowSvc` pass
- [ ] Update `GetTaskService()`: pass `entitySvc` instead of `workflowSvc` to `NewTaskService`
- [ ] Update `ResetServices()`: reset `globalEntityService` and `entityServiceOnce`
- [ ] Update `WireServices()` in `cmd/server/services.go`: create EntityService once, pass to each entity service constructor
- [ ] EntityRepository adapters obtained from EntityRegistry (from F01/F02) for Epic and Feature
- [ ] Task does NOT get EntityRepository adapter for transition path (uses typed repo directly)

### Non-Functional Requirements

- [ ] `make fmt && make lint && make test` passes
- [ ] `make build` succeeds (verifies all constructor signatures match)
- [ ] End-to-end CLI smoke tests pass: `shark status advance` and `shark status set` for epics, features, tasks

## Implementation Plan

### Steps

1. [ ] Add `globalEntityService` var and `entityServiceOnce sync.Once` to `services_global.go`
2. [ ] Implement `GetEntityService()` with `sync.Once` pattern
3. [ ] Update `GetEpicService()`: replace `workflowSvc` with `entitySvc` + `entityRepo` from registry
4. [ ] Update `GetFeatureService()`: same pattern as Epic
5. [ ] Update `GetTaskService()`: replace `workflowSvc` with `entitySvc` (no entityRepo needed for Task transition)
6. [ ] Update `ResetServices()` to reset EntityService global state
7. [ ] Update `WireServices()` in `cmd/server/services.go` with same pattern
8. [ ] Run `make build` to verify all constructor signatures compile
9. [ ] Run CLI smoke tests: `shark status advance` and `shark status set` for all entity types
10. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- `GetEntityService()` uses `sync.Once` for lazy singleton initialization (same pattern as existing services)
- EntityRepository adapters come from `GetEntityRegistry().MustGetRepository(models.EntityTypeEpic)` etc.
- Single `EntityService` instance shared across all entity services in CLI (per-invocation lifecycle)
- HTTP server creates `EntityService` once in `WireServices()` (per-server lifecycle)
- See architecture doc Sections 8.1-8.6 for complete wiring code
