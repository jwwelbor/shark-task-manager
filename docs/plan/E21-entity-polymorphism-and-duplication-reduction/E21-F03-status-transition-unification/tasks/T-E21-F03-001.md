# Task: EntityService core with TransitionStatus, helpers, and ResolveActionForStatus

## Goal

Create the `EntityService` struct in `internal/services/entity_service.go` with the shared transition algorithm,
helper methods for TaskService hybrid use, and the unified `ResolveActionForStatus` and `GetNextStatus` methods.
This is the foundation that all entity-specific services will delegate to.

## Requirements

### Functional Requirements

- [ ] Create `EntityService` struct with `workflowSvc *workflow.Service` field
- [ ] Implement `NewEntityService(workflowSvc *workflow.Service) *EntityService` constructor with nil-check
- [ ] Implement `TransitionStatus(ctx, repo EntityRepository, entityType, key, targetStatus string, opts TransitionOptions, features TransitionFeatures, resolveActionFn ResolveActionFn) (*TransitionResult, error)` -- shared 9-step algorithm
- [ ] Implement `ValidateAndNormalize(currentStatus, targetStatus string, force bool) (string, error)` -- exported helper for TaskService hybrid use
- [ ] Implement `DetectBackward(currentStatus, targetStatus string, force bool, reason string) (bool, error)` -- exported helper for TaskService hybrid use
- [ ] Implement `ResolveActionForStatus(status string, placeholders map[string]string) *config.PopulatedAction` -- shared workflow lookup + nil checks + PopulatedAction construction
- [ ] Implement `GetNextStatus(ctx, repo EntityRepository, entityType, key string, resolveActionFn ResolveActionFn) (*NextStatusInfo, error)` -- shared available-transitions query
- [ ] Implement `GetWorkflowService() *workflow.Service` -- accessor for entity-specific services
- [ ] Define `TransitionFeatures` struct with `DetectBackward`, `CreateRejectionNotes`, `ResolveOrchestratorAction` boolean fields
- [ ] Define `DefaultTransitionFeatures()` (all true except CountChildren is absent -- backward/notes/action all true)
- [ ] Define `SimpleTransitionFeatures()` (only ResolveOrchestratorAction=true)
- [ ] Define `ResolveActionFn` type: `func(entity models.Entity, status string) *config.PopulatedAction`
- [ ] Add `EntityID int64` field to `TransitionResult` in `transition_types.go` (backward-compatible, `json:"entity_id,omitempty"`)

### Non-Functional Requirements

- [ ] `make fmt && make lint && make test` passes after this task
- [ ] No behavioral changes to existing code (this task only adds new code)
- [ ] EntityService methods return nil gracefully for nil workflow, missing metadata, or nil OrchestratorAction

### Technical Approach

- EntityService depends only on `*workflow.Service` (ADR-F03-005: no noteRepo dependency)
- Rejection note creation is NOT performed by EntityService; result includes `IsBackward` so callers handle it in post-hooks
- `TransitionStatus` uses `EntityRepository` interface from F01 for `GetByKey` and `UpdateStatus`
- `ResolveActionForStatus` replaces the structurally identical `resolveAction` methods across 5 services
- `GetNextStatus` uses `ResolveActionFn` callback for entity-specific placeholder enrichment
