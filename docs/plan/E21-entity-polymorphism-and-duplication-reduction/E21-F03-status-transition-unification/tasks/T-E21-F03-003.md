# Task: Refactor EpicService to delegate TransitionStatus to EntityService

## Goal

Refactor `EpicService` to delegate `TransitionStatus`, `GetNextStatus`, and `resolveAction` to `EntityService`,
reducing inline transition logic from ~80 lines to ~20 lines. Retain only entity-specific post-hooks
(rejection note creation and child feature counting).

## Requirements

### Functional Requirements

- [ ] Add `entitySvc *EntityService` and `entityRepo EntityRepository` fields to EpicService struct
- [ ] Update `NewEpicService` constructor: replace `workflowSvc *workflow.Service` with `entitySvc *EntityService` + `entityRepo EntityRepository`
- [ ] Remove `workflowSvc` field; route all workflow access through `s.entitySvc.GetWorkflowService()`
- [ ] Replace `TransitionStatus` body with delegation to `s.entitySvc.TransitionStatus()` + post-hooks
- [ ] Post-hook 1: Create rejection note using `s.noteRepo` when `result.IsBackward || result.IsForced` and reason provided
- [ ] Post-hook 2: Count child features using `s.featureRepo.ListByEpic(ctx, result.EntityID)`
- [ ] Convert `resolveAction` method to `makeResolveActionFn(ctx)` callback factory that generates Epic-specific placeholders and calls `s.entitySvc.ResolveActionForStatus`
- [ ] Replace `GetNextStatus` body with delegation to `s.entitySvc.GetNextStatus()` passing `makeResolveActionFn`
- [ ] Replace all `s.workflowSvc.XXX` calls with `s.entitySvc.GetWorkflowService().XXX` (e.g., `ValidateStatus`, `IsTerminalStatus`)
- [ ] Update all tests in `epic_service_test.go` for new constructor signature

### Non-Functional Requirements

- [ ] `make fmt && make lint && make test` passes
- [ ] All existing EpicService tests pass with unchanged behavioral assertions
- [ ] TransitionStatus body reduced from ~80 lines to ~20 lines
- [ ] ~103 lines removed from EpicService (per architecture doc Section 4.6)

## Implementation Plan

### Steps

1. [ ] Add `entitySvc` and `entityRepo` fields to EpicService struct
2. [ ] Update `NewEpicService` constructor signature and body
3. [ ] Implement `makeResolveActionFn(ctx)` callback factory (preserves Epic enrichment/placeholder logic)
4. [ ] Replace `TransitionStatus` body with: delegation call + rejection note post-hook + child count post-hook
5. [ ] Replace `GetNextStatus` body with one-line delegation
6. [ ] Replace `ValidateStatus` to route through `entitySvc.GetWorkflowService()`
7. [ ] Replace all other `s.workflowSvc` references throughout EpicService
8. [ ] Remove `workflowSvc` field from struct and imports
9. [ ] Update `epic_service_test.go`: update all constructor calls to pass `*EntityService` and `EntityRepository` adapter
10. [ ] Create test helper `newTestEntityService(t)` if not already present
11. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- Constructor change: `workflowSvc *workflow.Service` replaced by `entitySvc *EntityService` + `entityRepo EntityRepository`
- `makeResolveActionFn` preserves the current enrichment/doc/relationship placeholder logic but delegates workflow lookup to `EntityService.ResolveActionForStatus`
- `TransitionResult.EntityID` (added in T-001) used by post-hooks to avoid redundant DB queries
- See architecture doc Sections 4.1-4.6 for complete before/after code
