**Description**:
The task implementation added `valid_transitions` to the direct JSON output in epic.go and feature.go (lines 633 and 774 respectively). However, the feature get command now uses `DisplayService.GetFeatureDisplayInfo()` for JSON output when features are in "planning" mode, which returns a `FeatureDisplayInfo` struct that does NOT include a `valid_transitions` field.

**Evidence**:
```bash
$ ./bin/shark feature get E07-F16 --json | jq 'keys | sort'

  "feature",
  "orchestrator_action",
  "path",
  "phase",
  "phase_description",
  "status_source",
  "workflow_position"
]
# valid_transitions is NOT in the output
```

**Root Cause**:
- Feature.go line 593: Code checks for `DisplayModePlanning`
- If true, uses DisplayService.GetFeatureDisplayInfo() (line 594)
- That function returns a FeatureDisplayInfo struct (internal/services/display_service.go:66-84)
- FeatureDisplayInfo does NOT have a ValidTransitions field
- The code at lines 770-801 (which DOES include valid_transitions) is only reached when displayMode != DisplayModePlanning

**Code Path Comparison**:

*Used Path (DisplayService)*:
```
runFeatureGet()
  → displaySvc.DetermineFeatureDisplayMode()
  → if DisplayModePlanning:
      → displaySvc.GetFeatureDisplayInfo()  // Returns FeatureDisplayInfo
      → cli.OutputJSON(info)  // Missing valid_transitions
```

*Unused Path (Direct Output)*:
```
runFeatureGet()
  → if displayMode != DisplayModePlanning:
      → Build result map with valid_transitions  // Line 774-799
      → cli.OutputJSON(result)  // Has valid_transitions
```
