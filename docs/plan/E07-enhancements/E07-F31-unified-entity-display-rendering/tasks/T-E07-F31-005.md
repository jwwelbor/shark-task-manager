### Technical Approach

**Test Pattern**: Table-driven tests for multiple scenarios
```go
func TestGetValidTransitions(t *testing.T) {
    tests := []struct {
        name     string
        status   string
        workflow *config.WorkflowConfig
        want     []string
    }{
        {
            name:     "nil config returns empty",
            status:   "in_progress",
            workflow: nil,
            want:     []string{},
        },
        {
            name:   "valid status returns transitions",
            status: "in_progress",
            workflow: &config.WorkflowConfig{
                StatusFlow: map[string][]string{
                    "in_progress": {"ready_for_review", "blocked"},
                },
            },
            want: []string{"ready_for_review", "blocked"},
        },
        // ... more test cases
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := GetValidTransitions(tt.status, tt.workflow)
            if !reflect.DeepEqual(got, tt.want) {
                t.Errorf("got %v, want %v", got, tt.want)
            }
        })
    }
}
```

**Output Capture**: Use `captureStdout()` helper to capture and verify terminal output for rendering functions.

## Notes

**No Database Required**: These are pure unit tests. No test database setup needed. Helpers format data only, don't access databases.

**Table-Driven Test Pattern**: Use Go's table-driven test pattern for comprehensive scenario coverage. Each helper function should have a test with multiple subtests (t.Run).

**Output Capture**: For rendering functions that write to stdout, implement `captureStdout()` helper to capture and verify output strings.

**Test Fixtures**: Create reusable test fixtures for common data structures:
- Sample WorkflowConfig with status_flow
- Sample Document slices
- Sample EntityNote slices
- Sample ContextData structs

**Edge Case Priority**:
1. Nil inputs (must not panic)
2. Empty arrays/slices (graceful skip)
3. Missing fields in structs (handle gracefully)
4. Terminal statuses (empty transitions array)
5. Malformed configs (return empty, no crash)
