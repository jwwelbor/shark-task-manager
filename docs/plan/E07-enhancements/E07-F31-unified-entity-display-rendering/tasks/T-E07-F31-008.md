# Task: Show execution_order in list views, falling back to priority when unset

## Observation

Human-readable list views (e.g. `shark list <epic> <feature>`, `shark task list`,
and similar listings for features, epics, bugs, change-cards, ideas, and
tech-debt) currently surface `priority` but not `execution_order`.

Two issues with the current behavior:

1. `execution_order` is the field that actually drives sequencing of work,
   yet it is invisible in human-readable output.
2. `priority`'s "low vs. high" semantics are not obvious at a glance — it is
   not clear which end of the scale is more important.

## Proposed display rule

- If `execution_order` is set on a row, show it in the human-readable list view.
- If `execution_order` is unset (null/zero), fall back to showing `priority`.
- JSON output is unchanged — both fields are already present there.

## Scope

Apply consistently across human-readable list views for **all entity types**
that have these fields: tasks, features, epics, bugs, change-cards, ideas,
tech-debt, and any future entities that adopt the same pattern.

## Open questions for elaboration

- Column header label when both fields can appear in the same column, and how
  (or whether) to indicate which one is being shown for a given row.
- Whether to keep priority as a separate column for entities where ordering is
  not typically used.
