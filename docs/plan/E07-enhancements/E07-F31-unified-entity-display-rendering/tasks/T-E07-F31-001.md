# Task: Create render_common.go with helper functions and EntityDisplayOptions

## Goal

Create the foundational rendering infrastructure file `internal/cli/commands/render_common.go` containing:
- EntityDisplayOptions struct for unified rendering configuration
- RenderEntity() function establishing standard section ordering
- 8 helper functions for common display sections (header, basic info, valid transitions, orchestrator action, related documents, notes, context data, GetValidTransitions)

This infrastructure enables surgical fixes to epic.go and feature.go in subsequent tasks and establishes the foundation for E15-F07 consolidation.

## Requirements

### Functional Requirements (REQ-F-001 to REQ-F-004)

**REQ-F-001**: Create render_common.go with Helper Functions
- [ ] File created at `internal/cli/commands/render_common.go`
- [ ] Package declaration: `package commands`
- [ ] Imports: models, services, config, pterm, fmt
- [ ] 8 helper functions implemented:
  - [ ] `renderHeader(entityType, key string)` - Section header with entity type and key
  - [ ] `renderBasicInfo(info [][]string)` - Key-value info table
  - [ ] `renderValidTransitions(status string, transitions []string)` - Bulleted list of valid next statuses
  - [ ] `renderOrchestratorAction(action *config.PopulatedAction)` - Thin wrapper around displayOrchestratorAction
  - [ ] `renderRelatedDocuments(docs []*models.Document)` - Document list with title and path
  - [ ] `renderNotes(notes []*models.EntityNote)` - Most recent 10 notes with truncation
  - [ ] `renderContextData(contextData *models.ContextData)` - Delegates to printContextData
  - [ ] `GetValidTransitions(status string, workflow *config.WorkflowConfig) []string` - Extract transitions from status_flow

**REQ-F-002**: Implement GetValidTransitions Helper
- [ ] Function signature: `func GetValidTransitions(status string, workflow *config.WorkflowConfig) []string`
- [ ] Returns empty array if status not found in status_flow
- [ ] Returns empty array if workflow config is nil/malformed
- [ ] No panics on nil/missing data

**REQ-F-003**: Implement EntityDisplayOptions Struct
- [ ] Struct includes fields: EntityType, Key, Status, BasicInfo, ValidTransitions, OrchestratorAction, RelatedDocs, Notes, ContextData
- [ ] RenderSpecific field is `func()` callback for entity-specific sections
- [ ] All fields use common types (models.Document, config.PopulatedAction, etc.)
- [ ] Documentation comment: "TODO E15-F07: Commands will use this struct when refactored to service layer pattern"

**REQ-F-004**: Implement RenderEntity Function
- [ ] Function signature: `func RenderEntity(opts EntityDisplayOptions)`
- [ ] Calls helpers in standard order: renderHeader, renderBasicInfo, renderValidTransitions, renderOrchestratorAction, renderRelatedDocuments, [callback], renderNotes, renderContextData
- [ ] Skips sections with nil/empty data (graceful degradation)
- [ ] Documentation includes TODO: "E15-F07 will use this when refactoring commands"

### Non-Functional Requirements

**REQ-NF-002**: Rendering Time Unchanged
- [ ] Helper function overhead < 5ms (within measurement noise)
- [ ] No I/O operations in helpers (just formatting)
- [ ] Same pterm calls as existing code

**REQ-NF-003**: Code Reusability
- [ ] No entity-specific types in helper signatures
- [ ] All helpers callable from any entity type (epic, feature, task)
- [ ] Helpers accept standardized parameters

### Technical Approach

**Design Pattern**: Helper function extraction
- Extract common display sections from existing render functions
- No entity-specific coupling
- Nil-safe, graceful degradation
- Establishes standard section ordering

**Signature Design**:
- Generic parameters ([][]string, []*models.Document, etc.)
- No direct entity dependencies (Epic, Feature, Task)
- Callback pattern for entity-specific sections

## Notes

**Foundation Work**: This task creates infrastructure for E15-F07 to use later. The infrastructure is available immediately but not required to be used in this feature (E07-F31 makes surgical fixes instead).

**Standard Section Order** (defined by RenderEntity):
1. Header (entity type + key)
2. Basic Info (key-value table)
3. Valid Transitions (allowed next statuses)
4. Orchestrator Action (next action instruction)
5. Related Documents (linked artifacts)
6. [Entity-Specific Sections via callback]
7. Notes (entity notes)
8. Context Data (progress, decisions, questions)

**Minimal Changes Philosophy**: This task focuses on creating reusable infrastructure. Subsequent tasks (T-E07-F31-002 to T-E07-F31-004) will make minimal changes to existing epic.go and feature.go files using these helpers.

**E15-F07 Coordination**: Epic E15 (Service Layer Architecture Refactoring) Feature F07 will use this RenderEntity() infrastructure to consolidate all entity rendering, eliminating 500+ lines of duplicate code.
