# Implement opt-in transcript file capture for agent dispatches

## Goal

When `observability.capture_agent_transcripts` is true, write a structured log file to `.shark/runs/{run_id}/{stage_n}-{status}-{provider}.log` for every dispatch, containing the full command, exit code, duration, stdout, and stderr. Populate `transcript_path` on the corresponding slog event. Write failures must be non-fatal and emit a single `run.transcript.warning` event per run. Verify `.shark/runs/` is in `.gitignore`.

## Scope

- Files to modify:
  - `internal/runner/controller.go` — add transcript write logic after each dispatch; pass CaptureAgentTranscripts from config; track transcript-write-failed flag per run
  - `.gitignore` — add `.shark/runs/` entry if not present

## Acceptance Criteria

See feature.md Story 4, REQ-F-012, Error Story 1, and Scenario 3, Scenario 4 for authoritative criteria.

- AC-T1: When enabled, file created at `.shark/runs/{run_id}/{n}-{status}-{provider}.log` with mode 0644; directory with mode 0755.
- AC-T2: File format: `COMMAND: <cmd>\nEXIT: <code>\nDURATION: <ms>ms\n---STDOUT---\n<stdout>\n---STDERR---\n<stderr>`.
- AC-T3: `run.stage.complete` and `run.stage.error` events include `transcript_path` (relative to project root) when file was written.
- AC-T4: If directory creation or file write fails, run continues; `run.transcript.warning` logged once; subsequent stages skip transcript write.
- AC-T5: When `capture_agent_transcripts` is false, no files written and no `transcript_path` field on events.
- AC-T6: `.shark/runs/` appears in `.gitignore`.

## Test Cases

Derive from feature.md Scenario 3 and Scenario 4 (feature-level acceptance).
- With capture enabled: verify file exists with correct path and format after a dispatch.
- With capture disabled: verify no files written and transcript_path absent from events.
- With read-only runs dir: verify run.transcript.warning emitted and run completes normally.
