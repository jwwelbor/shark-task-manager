# Generate run_id and emit run.start / run.end slog events in runRun

## Goal

Instrument `runRun` in `internal/cli/commands/run.go` to generate a run-scoped correlation ID, emit a structured `run.start` slog event at entry, and emit `run.end` on every return path (success and error), giving operators a parsable bracket around each invocation in shark.log.

## Scope

- Files to modify:
  - `internal/cli/commands/run.go` — add run_id generation, run.start/run.end slog calls
  - `internal/runner/controller.go` — accept run_id via RunOptions or a context value so stage events can carry it

## Acceptance Criteria

See feature.md Story 1 (AC list) and REQ-F-001, REQ-F-002 for authoritative criteria.

- AC-T1: `run_id` is a UUID or short random string generated once at the top of runRun.
- AC-T2: `run.start` logged at INFO with fields: command, args, entity_key, entity_type, dry_run, worktree, worktree_path, run_id.
- AC-T3: `run.end` logged on every return path (deferred or explicit) with fields: entity_key, outcome, final_status, stages_completed, duration_ms, error, run_id.
- AC-T4: `run.end` level is INFO on success, ERROR when result.Error is non-empty.
- AC-T5: Events only appear in shark.log when observability.enabled is true (existing F40 gate preserved).

## Test Cases

Derive from feature.md Story 1 AC and Scenario 1 (feature-level acceptance).
- With observability disabled: no slog events emitted.
- With observability enabled and dry_run: run.start and run.end present; outcome reflects dry-run result.
- Simulate error return: run.end emitted with ERROR level and error field populated.
