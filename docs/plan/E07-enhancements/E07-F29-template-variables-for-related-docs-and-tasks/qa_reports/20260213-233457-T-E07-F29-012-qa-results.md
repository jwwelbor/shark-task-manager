### Finding 2: Service Layer Integration Missing (CRITICAL)

**Severity**: Critical
**Priority**: P1 - Feature non-functional
**Status**: Open

**Description**: The `DisplayService` does not use `TaskPlaceholdersWithRelated`, `FeaturePlaceholdersWithRelated`, or `EpicPlaceholdersWithRelated` functions, despite having access to `DocumentRepository`.

**Evidence**:
- File: `internal/services/display_service.go`
- Search result: No references to `*PlaceholdersWithRelated` functions
- `DisplayServiceDeps` struct includes `DocumentRepo *repository.DocumentRepository`

**Impact**:
- End-users see orchestrator actions without `{related_docs}` or `{related_tasks}` populated
- AI agents do not receive related document paths in instructions
- Feature is implemented but not connected to CLI workflow

**Expected Integration**:
```go
// In DisplayService method that builds orchestrator actions
func (s *DisplayService) resolveTaskOrchestratorAction(ctx context.Context, task *models.Task) (*config.PopulatedAction, error) {
    // Get workflow action template for status
    workflowAction := s.workflowSvc.GetActionForStatus(task.Status)

    // Populate with extended placeholders (includes related docs/tasks)
    placeholders := config.TaskPlaceholdersWithRelated(task, s.deps.DocumentRepo, ctx)

    return workflowAction.PopulateTemplate(placeholders), nil
}
```

**Current State**: Display service likely uses basic `TaskPlaceholders()` without repository integration.

**Steps to Reproduce**:
1. Create task with linked documents
2. Run `shark task get <task-key> --json`
3. Observe `orchestrator_action.instruction` does not include document paths

**Recommended Fix**:
1. Update `DisplayService` methods to call `TaskPlaceholdersWithRelated` with `s.deps.DocumentRepo`
2. Similarly update for features and epics
3. Write integration tests in `internal/services/display_service_integration_test.go`

**Verification**: After fix, run manual CLI test:
