# Repository: add GetRecent to Task, Feature, Epic repos

## Goal

Add `GetRecent(ctx context.Context, limit int) ([]*models.T, error)` to all
three entity repositories. Each method runs `ORDER BY created_at DESC LIMIT ?`
against its table, re-using the existing row-scan helper (e.g. `queryTasks`)
so no new scan logic is introduced. Returns an empty (non-nil) slice when no
rows exist.

This task has no dependency on T-E07-F17-001 because it touches only the
repository layer; config is irrelevant here.

## Scope

- Files to modify:
  - `internal/repository/task/repository.go` — add `GetRecent`
  - `internal/repository/feature/repository.go` — add `GetRecent`
  - `internal/repository/epic/repository.go` — add `GetRecent`
  - `internal/repository/task/repository_test.go` — add `TestTaskRepository_GetRecent_*` and `BenchmarkTaskRepository_GetRecent`
  - `internal/repository/feature/repository_test.go` — add `TestFeatureRepository_GetRecent_*`
  - `internal/repository/epic/repository_test.go` — add `TestEpicRepository_GetRecent_*`

## Acceptance Criteria

See spec.md REQ-NF-001, REQ-NF-002; Architecture Section 5.3.1.

- AC-T1: `GetRecent(ctx, 3)` on a 10-row table returns exactly 3 rows
- AC-T2: Rows are ordered `created_at DESC`
- AC-T3: Returns a non-nil empty slice on an empty table
- AC-T4: When limit exceeds row count, returns all rows
- AC-T5: Benchmark `GetRecent(ctx, 100)` on 10 000 rows completes in < 150 ms
