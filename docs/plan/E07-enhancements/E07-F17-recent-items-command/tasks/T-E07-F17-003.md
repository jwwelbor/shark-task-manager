# Service: implement RecentService and DTOs

## Goal

Implement `RecentService` with its consumer-side repository interfaces and
the `RecentFilters` / `RecentItem` DTOs. The service fans out to the enabled
repository types, merges results in memory, sorts by `created_at DESC` (with
deterministic tie-breaking), and applies the final limit. This is the only
layer that contains merge-and-sort business logic.

Depends on T-E07-F17-001 (config type) and T-E07-F17-002 (repository methods).

## Scope

- Files to create:
  - `internal/services/recent_service.go` — `RecentService` struct, consumer-side repo interfaces, `NewRecentService`, `ListRecent`
  - `internal/services/recent_dto.go` — `RecentFilters` and `RecentItem` structs
  - `internal/services/recent_service_test.go` — mocked-repo service tests

## Acceptance Criteria

See spec.md REQ-F-005, REQ-F-006, REQ-F-008, REQ-F-009; Architecture
Section 5.3.2.

- AC-T1: When all `Include*` flags are false, all three repos are called
- AC-T2: When only `IncludeTasks=true`, feature and epic repos are NOT called
- AC-T3: Merged results are sorted `created_at DESC` regardless of repo order
- AC-T4: Tie-break order is epic, feature, task; then key ascending
- AC-T5: Final limit is applied after merge (not per-repo)
- AC-T6: Any single-repo error aborts and is wrapped with `"failed to list recent <type>"`
- AC-T7: When all repos return empty, service returns `[]RecentItem{}` (not nil)
