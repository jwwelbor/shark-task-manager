# Config: add RecentConfig and GetRecentDefaultLimit

## Goal

Extend the config package with the `RecentConfig` sub-struct and
`GetRecentDefaultLimit()` accessor so the rest of the feature can read
the user-configured default limit. This is a pure additive change: no
existing config fields or callers are touched.

## Scope

- Files to modify:
  - `internal/config/config.go` — add `RecentConfig` type, add `Recent *RecentConfig` field to `Config`, add `GetRecentDefaultLimit() int` method
- Files to add tests to:
  - `internal/config/config_test.go` — add `TestGetRecentDefaultLimit_*` cases

## Acceptance Criteria

See spec.md REQ-F-002, REQ-F-010, REQ-F-011; Architecture Section 5.3.3.

- AC-T1: `GetRecentDefaultLimit()` returns 5 when receiver is nil
- AC-T2: Returns 5 when `Recent` section is absent from config JSON
- AC-T3: Returns 5 when `recent.default_limit` is 0 or negative
- AC-T4: Returns the configured value when `recent.default_limit` is positive
- AC-T5: Existing `.sharkconfig.json` without a `recent` key loads without error

## Test Cases

See test-plan.md Section IS-4 and AC-4 (TC-AC4-02, TC-AC4-03).

Named test functions:
- `TestGetRecentDefaultLimit_NilConfig`
- `TestGetRecentDefaultLimit_SectionAbsent`
- `TestGetRecentDefaultLimit_FieldZero`
- `TestGetRecentDefaultLimit_FieldNegative`
- `TestGetRecentDefaultLimit_FieldPositive`
- `TestRecentConfig_BackwardCompat_ExistingConfigLoadsOK`

Use `t.TempDir()` + `os.WriteFile` for config fixtures; never modify the
real `.sharkconfig.json`. Follow the pattern in
`internal/config/config_observability_test.go` lines 12-41.

## Design Reference

See spec.md Architecture Section 5.2 for the `RecentConfig` type definition
and Section 5.3.3 for the `GetRecentDefaultLimit` method contract (including
the nil-safe guard). The `Recent *RecentConfig` field uses `omitempty` to
match the existing `Web`, `Maintainer`, and `Observability` optional fields.
