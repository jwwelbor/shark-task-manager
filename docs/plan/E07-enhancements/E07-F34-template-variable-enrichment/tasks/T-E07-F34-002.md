# Task: Create TemplateEnrichmentData struct and consolidated enrichment repository

## Goal

Create the `TemplateEnrichmentData` struct and `TemplateEnrichmentRepository` interface in `internal/config/template_helpers.go`, and implement the concrete repository in a new file `internal/repository/template_enrichment_repository.go`. The repository uses consolidated SQL queries (one per entity type) to fetch all enrichment data in a single Turso round-trip: previous_status, parent titles, latest note, note counts, and sibling progress counts.

## Scope

- Define `TemplateEnrichmentData` struct (flat value struct, all fields optional via zero-values)
- Define `TemplateEnrichmentRepository` interface with 3 methods: `GetTaskEnrichment`, `GetFeatureEnrichment`, `GetEpicEnrichment`
- Implement concrete repository with consolidated SQL queries per architecture doc sections 5.2-5.4
- Write repository integration tests per test plan section 2.4

## Requirements

### Functional Requirements

- [ ] `TemplateEnrichmentData` struct with fields: PreviousStatus, ParentTitle, GrandparentTitle, LatestNoteContent, LatestNoteType, NotesCount, RejectionCount, SiblingTotal, SiblingCompleted, SiblingBlocked
- [ ] `TemplateEnrichmentRepository` interface with `GetTaskEnrichment(ctx, taskID)`, `GetFeatureEnrichment(ctx, featureID)`, `GetEpicEnrichment(ctx, epicID)`
- [ ] Task enrichment query: fetches previous_status from task_history, parent titles via JOIN to features/epics, latest note from entity_notes, note counts, sibling task counts
- [ ] Feature enrichment query: parent title (epic), latest note, note counts, child task counts (sibling_total/completed/blocked)
- [ ] Epic enrichment query: latest note, note counts, child feature counts
- [ ] All queries use LEFT JOINs and COALESCE for nil safety on missing parents
- [ ] Non-existent entity IDs return zero-valued struct or appropriate error

### Non-Functional Requirements

- [ ] Each enrichment method issues exactly 1 SQL query (single Turso round-trip)
- [ ] All subqueries hit existing indexed columns (task_id, entity_type+entity_id, feature_id, epic_id, status)
- [ ] No database schema changes required

## Implementation Plan

### Steps

2. [ ] Add `TemplateEnrichmentRepository` interface to `internal/config/template_helpers.go`
3. [ ] Create `internal/repository/template_enrichment_repository.go` with concrete implementation
4. [ ] Implement `GetTaskEnrichment()` with consolidated SQL query (architecture doc section 5.2)
5. [ ] Implement `GetFeatureEnrichment()` with consolidated SQL query (architecture doc section 5.3)
6. [ ] Implement `GetEpicEnrichment()` with consolidated SQL query (architecture doc section 5.4)

### Technical Approach

- Place interface in `internal/config/template_helpers.go` alongside existing repository interfaces (DocumentRepository, TaskRelationshipRepository, etc.)
- Concrete implementation in `internal/repository/` follows existing repository patterns (constructor injection of `*DB`)
- Use the exact SQL from architecture doc sections 5.2-5.4 as starting point, adjust column names as needed after verifying actual schema
- For `previous_status`, query `task_history` table `ORDER BY timestamp DESC LIMIT 1` to get the `old_status` field
- Features and epics return empty string for `previous_status` (no history tables exist in v1)
