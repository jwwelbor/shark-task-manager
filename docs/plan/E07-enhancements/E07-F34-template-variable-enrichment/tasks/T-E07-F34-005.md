# Task: Full test coverage for template variable enrichment

## Goal

Ensure comprehensive test coverage for all components of the template variable enrichment feature. Fill any gaps not covered by the unit/integration tests written alongside implementation tasks T-001 through T-004. Run the full quality gate and validate end-to-end template rendering with enrichment variables.

## Scope

- Review and fill gaps in unit tests for `extractContextDataFields()` (T-001 test gaps)
- Review and fill gaps in repository integration tests (T-002 test gaps)
- Review and fill gaps in `applyEnrichmentData()` and nil-safety tests (T-003 test gaps)
- Review and fill gaps in service wiring tests (T-004 test gaps)
- Add edge case and defensive tests per test plan section 4
- Run full quality gate: `make fmt && make lint && make test`
- End-to-end validation: verify enrichment variables appear in populated template output

## Requirements

### Functional Requirements

- [ ] All test cases from test plan sections 1.1-1.5 are covered
- [ ] All edge cases from test plan section 4 are tested

- [ ] Missing parent entity scenarios from test plan section 4.2 are tested
- [ ] Empty data set scenarios from test plan section 4.3 are tested

### Non-Functional Requirements

- [ ] Repository tests use real database with cleanup

## Implementation Plan

### Steps

1. [ ] Audit existing tests from T-001 through T-004 against the full test plan matrix

5. [ ] Write missing service tests in respective `*_service_test.go` files
6. [ ] Add edge case tests: nil safety, missing parents, empty data, repo errors, data ordering
7. [ ] Run `make fmt && make lint && make test` and fix any failures
8. [ ] Perform end-to-end validation with sample template rendering

### Technical Approach

- Use the test plan (09-test-plan.md) as the authoritative checklist
- Table-driven tests for scenarios with multiple variations (e.g., TC-CD-01 through TC-CD-12)
- Repository tests follow existing patterns: `test.GetTestDB()`, `TEST-` prefixed keys, cleanup before/after
- Service tests use mock repositories per existing mock patterns in the codebase
- For end-to-end validation, use `shark task resume <key> --json` on a test task with enrichment data populated
