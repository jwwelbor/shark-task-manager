# Task: Wire enrichment repository into services and CLI global accessors

## Goal

Wire the `TemplateEnrichmentRepository` into TaskService, FeatureService, EpicService, and DisplayService as an optional dependency. Update each service's `resolveAction()` method to fetch enrichment data and pass it to `*PlaceholdersWithRelated()` instead of nil. Update CLI global accessors in `services_global.go` to construct and inject the enrichment repository.

## Scope

- Add optional `enrichRepo` field to TaskService, FeatureService, EpicService constructors
- Add `TemplateEnrichmentRepo` field to DisplayService.Dependencies struct
- Update `resolveAction()` in all 3 entity services to fetch enrichment data
- Update `ResolveTaskAction()`, `ResolveFeatureAction()`, `ResolveEpicAction()` in DisplayService
- Update CLI global accessors: `GetTaskService()`, `GetFeatureService()`, `GetEpicService()`, `GetDisplayService()`
- Graceful degradation: if enrichRepo is nil or query fails, log warning and proceed without enrichment

## Requirements

### Functional Requirements

- [ ] TaskService constructor accepts optional `enrichRepo config.TemplateEnrichmentRepository`
- [ ] FeatureService constructor accepts optional enrichRepo
- [ ] EpicService constructor accepts optional enrichRepo
- [ ] DisplayService.Dependencies gains `TemplateEnrichmentRepo` field
- [ ] TaskService.resolveAction fetches enrichment via `enrichRepo.GetTaskEnrichment()` and passes to placeholder function
- [ ] FeatureService.resolveAction fetches via `enrichRepo.GetFeatureEnrichment()`
- [ ] EpicService.resolveAction fetches via `enrichRepo.GetEpicEnrichment()`
- [ ] DisplayService.ResolveTaskAction/Feature/Epic also fetch and pass enrichment data
- [ ] GetTaskService(), GetFeatureService(), GetEpicService(), GetDisplayService() in services_global.go construct and inject enrichment repo
- [ ] If enrichRepo is nil, skip enrichment fetch (pass nil to placeholder function)
- [ ] If enrichment query returns error, log warning and proceed with nil enrichment (graceful degradation)

### Non-Functional Requirements

- [ ] Adds exactly 1 additional database query per template render (the consolidated enrichment query)
- [ ] No change to external CLI behavior (enrichment data is internal to template rendering)
- [ ] Existing service tests pass (nil enrichRepo preserves existing behavior)

### Technical Approach

- Follow architecture doc section 8.1 for the wiring pattern
- Each resolveAction() method follows the same pattern: check if enrichRepo is not nil, call Get*Enrichment(), log on error, pass result (or nil) to placeholder function
- Constructor changes are additive -- existing callers that pass nil continue to work
- Use `log.Printf` for enrichment fetch warnings (matches existing patterns in resolveAction methods)
