# Task: Extend extractContextDataMetadata to extract structured ContextData fields

## Goal

Extend the existing `extractContextDataMetadata()` function in `internal/config/template_helpers.go` to also extract the structured fields from `ContextData` (Progress, OpenQuestions, Blockers, ImplementationDecisions) into the flat `map[string]string` placeholder map. Rename the function to `extractContextDataFields()` to reflect its expanded scope. This is a zero-query enrichment -- no new database calls are needed since the ContextData JSON is already parsed in-memory.

## Scope

- Rename `extractContextDataMetadata()` to `extractContextDataFields()`
- Extract `ContextData.Progress` fields: `current_step`, `completed_steps`, `remaining_steps`, `completed_steps_count`, `remaining_steps_count`
- Extract `ContextData.OpenQuestions`: `open_questions`, `open_questions_count`
- Extract `ContextData.Blockers`: `blockers_count`, `latest_blocker`
- Extract `ContextData.ImplementationDecisions`: `decisions_count`
- Preserve existing Metadata extraction behavior exactly
- Ensure metadata keys are NOT overwritten by structured field extraction (metadata runs first per architecture doc)

## Requirements

### Functional Requirements

- [ ] Rename `extractContextDataMetadata` to `extractContextDataFields` and update all 3 internal call sites
- [ ] Extract Progress.CurrentStep as `current_step` placeholder
- [ ] Extract Progress.CompletedSteps as comma-joined `completed_steps` and integer `completed_steps_count`
- [ ] Extract Progress.RemainingSteps as comma-joined `remaining_steps` and integer `remaining_steps_count`
- [ ] Extract OpenQuestions as semicolon-joined `open_questions` and integer `open_questions_count`
- [ ] Extract Blockers as `blockers_count` and `latest_blocker` (last element's Description)
- [ ] Extract ImplementationDecisions as `decisions_count`
- [ ] Metadata keys must NOT be overwritten by structured fields (if both `metadata.current_step` and `progress.current_step` exist, metadata wins)

### Non-Functional Requirements

- [ ] No new database queries introduced
- [ ] Graceful degradation on nil/empty/malformed context_data (no panics)
- [ ] All existing `TestExtractContextDataMetadata_*` tests continue passing

## Implementation Plan

### Steps

1. [ ] Rename `extractContextDataMetadata` to `extractContextDataFields` in `internal/config/template_helpers.go`
2. [ ] Update the 3 internal call sites within template_helpers.go that call this function
3. [ ] Add structured Progress field extraction after the existing Metadata extraction loop
4. [ ] Add OpenQuestions extraction
5. [ ] Add Blockers extraction
6. [ ] Add ImplementationDecisions extraction
7. [ ] Ensure structured fields do NOT overwrite keys already set by Metadata extraction
8. [ ] Write unit tests per test plan section 2.1

### Technical Approach

- Follow architecture doc section 6.3 for exact extraction logic
- Use `strings.Join()` for list fields with appropriate delimiters (", " for steps, "; " for questions)
- Use `fmt.Sprintf("%d", ...)` for count fields
- Check for nil pointers on Progress struct before accessing fields
- For the collision handling: extract metadata first (existing behavior), then only set structured fields if key is not already present in the map
