# Task: Create templates directory structure and partials

## Goal

Create the physical directory structure for external template files and implement 3 reusable partial templates (`_tdd_process`, `_exit_gate`, `_read_section`) that will be shared across multiple orchestrator templates.

## Requirements

### Functional Requirements

- [ ] Create `templates/` directory at project root
- [ ] Create subdirectories: `epic/`, `feature/`, `task/`, `partials/`
- [ ] Create partial template: `partials/_tdd_process.tmpl` (4-step TDD process)
- [ ] Create partial template: `partials/_exit_gate.tmpl` (standard exit criteria format)
- [ ] Create partial template: `partials/_read_section.tmpl` (numbered READ items with conditionals)
- [ ] Verify partials load correctly via template engine precompilation

### Non-Functional Requirements

- [ ] Directory structure follows conventions (entity-based subdirectories)
- [ ] Partials use `_` prefix naming convention
- [ ] Partials use `{{define "name"}}...{{end}}` syntax
- [ ] Git: Commit directory structure and initial partials

## Implementation Plan

### Steps

1. [ ] Create directory structure:
   ```bash
   mkdir -p templates/epic
   mkdir -p templates/feature
   mkdir -p templates/task
   mkdir -p templates/partials
   ```
2. [ ] Create `templates/partials/_tdd_process.tmpl`:
   ```go
   {{define "_tdd_process"}}
   TDD PROCESS:
   1. Write failing test first (red)
   2. Implement minimum code to pass (green)
   3. Refactor while keeping tests green
   4. Commit when test suite passes
   {{end}}
   ```
3. [ ] Create `templates/partials/_exit_gate.tmpl`:
   ```go
   {{define "_exit_gate"}}
   EXIT GATE:
   - All acceptance criteria met
   - Tests passing (unit + integration)
   - Code reviewed and approved
   - Documentation updated
   {{end}}
   ```
4. [ ] Create `templates/partials/_read_section.tmpl`:
   ```go
   {{define "_read_section"}}
   READ:
   (1) {{.primary_doc}}
   {{- if .related_docs}}
   (2) Related docs: {{.related_docs}}
   {{- end}}
   {{- if .related_tasks}}
   ({{if .related_docs}}3{{else}}2{{end}}) Related tasks: {{.related_tasks}}
   {{- end}}
   {{end}}
   ```
5. [ ] Test partial loading by running template engine initialization
6. [ ] Commit directory structure and partials to Git

### Technical Approach

- **Directory Structure**: Follow architecture doc design (entity-based subdirectories)
- **Partial Naming**: Use `_` prefix convention (Go template community standard)
- **Partial Definition**: Use `{{define "name"}}` syntax for reusable blocks
- **Smart Numbering**: `_read_section` auto-renumbers based on which conditionals are active

## Testing Strategy

### Verification Tests

**Test Coverage:**
1. **Directory structure tests**:
   - `ls templates/` shows: epic/, feature/, task/, partials/
   - `ls templates/partials/` shows: _tdd_process.tmpl, _exit_gate.tmpl, _read_section.tmpl
2. **Partial syntax tests**:
   - Each partial has `{{define "name"}}...{{end}}` wrapper
   - Partial names match filename without extension (e.g., `_tdd_process`)
3. **Precompilation tests**:
   - Template engine initialization succeeds
   - No syntax errors in partial templates
   - `templates.Lookup("_tdd_process")` returns non-nil
4. **Partial include tests** (AC-3.2-T01 to T04):
   - Create test template: `{{template "_tdd_process" .}}`
   - Render template → outputs TDD process steps
   - Verify context passed to partial (e.g., `{{.task_id}}` works)

**Test Method:**
```bash
# Manual verification
ls -la templates/
ls -la templates/partials/

# Automated test
go test -v ./internal/templates -run TestPartialsLoad
```
