# Task: Add template_directory configuration to .sharkconfig.json

## Goal

Make both template directory paths configurable via `.sharkconfig.json` to allow teams to organize templates in custom locations. This addresses a gap identified during E07-F30 UAT where the orchestrator template directory is hardcoded to "templates".

## Requirements

### Functional Requirements

- [ ] Add `template_directory` field to `.sharkconfig.json` schema for orchestrator templates (default: "templates")
- [ ] Add `markdown_template_directory` field to `.sharkconfig.json` schema for entity markdown templates (default: "shark-templates")
- [ ] Update `GetOrchestratorEngine()` to read `template_directory` from config instead of hardcoding "templates"
- [ ] Update markdown template renderer (if applicable) to read `markdown_template_directory` from config
- [ ] Support both relative paths (from project root) and absolute paths
- [ ] Validate template directories exist at startup and log warning if missing

### Non-Functional Requirements

- [ ] Backward compatibility: If config fields are missing, use default values ("templates", "shark-templates")
- [ ] Security: Validate paths are within project root or explicitly allowed
- [ ] Performance: Directory validation should not slow down startup significantly (< 10ms)
- [ ] Documentation: Update config documentation with new fields

## Implementation Plan

   type Config struct {
       TemplateDirectory         string `json:"template_directory,omitempty"`          // Default: "templates"
       MarkdownTemplateDirectory string `json:"markdown_template_directory,omitempty"` // Default: "shark-templates"
       // ... existing fields
   }
   ```

2. [ ] Update `GetOrchestratorEngine()` to read config:

   func GetOrchestratorEngine() *OrchestratorRenderer {

               // Read from config
               cfg, err := config.Load()
               if err == nil && cfg.TemplateDirectory != "" {
                   templateDir = cfg.TemplateDirectory
               }
           }
           engineInstance, engineError = NewOrchestratorRenderer(templateDir)
           // ...
       })
   }
   ```

6. [ ] Write unit tests for config loading and path validation

### Technical Approach

- **Config Loading**: Use existing config loading mechanism in `internal/config/config.go`
- **Backward Compatibility**: Use `omitempty` JSON tag and default values if fields are missing
- **Path Resolution**: Use `filepath.Abs()` for relative paths, `filepath.Clean()` for sanitization
- **Security**: Validate paths don't escape project root using `filepath.Rel()` checks
- **Testing**: Mock config in tests, verify both default and custom paths work

## Testing Strategy

### Unit Tests

1. **Config Loading Tests**:
   - Load config with template_directory set → returns correct path
   - Load config without template_directory → returns default "templates"
   - Load config with markdown_template_directory set → returns correct path
   - Load config without markdown_template_directory → returns default "shark-templates"

2. **Path Validation Tests**:
   - Relative path "custom-templates" → resolves to project_root/custom-templates
   - Absolute path "/tmp/templates" → validates correctly
   - Path outside project root without allow → returns error
   - Nonexistent directory → logs warning, continues

3. **Engine Initialization Tests**:
   - GetOrchestratorEngine() with custom config → uses custom directory
   - GetOrchestratorEngine() without config → uses default "templates"
   - GetOrchestratorEngine() with test override → uses test directory (existing behavior)

### Integration Tests

1. **Custom Orchestrator Templates**:
   - Create .sharkconfig.json with `"template_directory": "custom-tmpl"`
   - Create custom-tmpl/task/test.tmpl
   - Render template → succeeds with custom directory

2. **Custom Markdown Templates**:
   - Create .sharkconfig.json with `"markdown_template_directory": "custom-md"`
   - Create custom-md/task.md
   - Create new task → uses custom template

3. **Backward Compatibility**:
   - Remove template_directory from config → defaults to "templates"
   - Existing systems continue working
