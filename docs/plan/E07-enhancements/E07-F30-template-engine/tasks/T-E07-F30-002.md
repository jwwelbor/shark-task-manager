# Task: Add .tmpl detection logic to OrchestratorAction.PopulateTemplate()

## Goal

Extend `OrchestratorAction.PopulateTemplate()` to detect `.tmpl` file references and route them to the template engine, while preserving backward compatibility with existing inline string templates. This is the single integration point for the entire template system.

## Requirements

### Functional Requirements

- [ ] Detect if `InstructionTemplate` ends with `.tmpl` suffix
- [ ] If `.tmpl`: call `templates.GetOrchestratorEngine().Render(templateName, vars)`
- [ ] If not `.tmpl`: use existing legacy string replacement (unchanged)
- [ ] Handle template rendering errors gracefully (log error, return empty string)
- [ ] Preserve all existing functionality for inline templates

### Non-Functional Requirements

- [ ] Zero breaking changes to existing inline templates
- [ ] No performance degradation for inline path
- [ ] Clear error logging for template failures
- [ ] Test Coverage: 100% of modified code paths

## Implementation Plan

### Steps

1. [ ] Open `internal/config/orchestrator_action.go`, locate `PopulateTemplate()` method (line ~140)
2. [ ] Add detection logic at start of method:
   ```go
   if strings.HasSuffix(oa.InstructionTemplate, ".tmpl") {
       engine := templates.GetOrchestratorEngine()
       rendered, err := engine.Render(oa.InstructionTemplate, vars)
       if err != nil {
           log.Printf("Template rendering failed for %s: %v", oa.InstructionTemplate, err)
           return ""
       }
       return rendered
   }
   ```
3. [ ] Keep existing legacy path unchanged (lines after detection)
4. [ ] Add import for `internal/templates` package
5. [ ] Write integration tests for both paths (inline and external)

### Technical Approach

- **Single Integration Point**: Only `PopulateTemplate()` changes; service layer unchanged
- **Filename-Based Detection**: `.tmpl` suffix triggers template engine (no config changes needed)
- **Graceful Degradation**: Template errors log warning but don't break workflow (return empty instruction)
- **Backward Compatibility**: Existing inline templates use legacy path (no changes)
