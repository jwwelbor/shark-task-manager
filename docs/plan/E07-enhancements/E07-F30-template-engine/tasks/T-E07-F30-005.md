# Task: Convert 5 task execution templates to external .tmpl files

## Goal

Convert 5 high-value task execution templates from inline JSON strings in `.sharkconfig.json` to external `.tmpl` files with rich formatting, conditionals, and shared partials. This demonstrates immediate readability and maintainability wins.

## Requirements

### Functional Requirements

- [ ] Convert `ready_for_development` → `templates/task/ready_for_development.tmpl`
- [ ] Convert `ready_for_code_review` → `templates/task/ready_for_code_review.tmpl`
- [ ] Convert `ready_for_qa` → `templates/task/ready_for_qa.tmpl`
- [ ] Convert `ready_for_refinement_ba` → `templates/task/ready_for_refinement_ba.tmpl`
- [ ] Convert `ready_for_refinement_tech` → `templates/task/ready_for_refinement_tech.tmpl`
- [ ] Include `{{template "_tdd_process" .}}` partial in development/code-review templates
- [ ] Add conditionals to hide empty `related_docs`, `related_tasks` sections
- [ ] Use tier-based branching if applicable (e.g., refinement templates)

### Non-Functional Requirements

- [ ] Rendered output semantically identical to inline templates (regression test)
- [ ] Improved formatting (multiline, no blank lines for empty sections)
- [ ] Git: Commit all 5 `.tmpl` files

## Implementation Plan

### Steps

1. [ ] Copy inline template content from `.sharkconfig.json` for each status
2. [ ] Create `templates/task/ready_for_development.tmpl`:
   - Use multiline formatting
   - Add conditional: `{{if .related_docs}}(4) Related docs: {{.related_docs}}{{end}}`
   - Include `{{template "_tdd_process" .}}` partial
   - Add smart numbering for READ section
3. [ ] Create `templates/task/ready_for_code_review.tmpl`:
   - Similar structure to development template
   - Focus on code review checklist
   - Include TDD process partial reference
4. [ ] Create `templates/task/ready_for_qa.tmpl`:
   - QA-focused instructions
   - Include test case execution guidance
   - Add conditional for related test plans
5. [ ] Create `templates/task/ready_for_refinement_ba.tmpl`:
   - BA refinement instructions
   - Tier-based output if complexity tier present
   - Include requirements elaboration guidance
6. [ ] Create `templates/task/ready_for_refinement_tech.tmpl`:
   - Tech lead refinement instructions
   - Architecture design focus
   - Include API contract guidance
7. [ ] Test each template by rendering with mock data
8. [ ] Run regression test: compare inline vs external output
9. [ ] Commit all `.tmpl` files to Git

### Technical Approach

- **Copy-Convert-Enhance**: Start with inline content, convert to multiline, add conditionals
- **Partial Reuse**: Use `_tdd_process` partial in 2-3 templates (change once, update all)
- **Smart Numbering**: READ section auto-renumbers based on conditionals
- **Regression Test**: Ensure semantic equivalence with inline versions

## Testing Strategy

### Regression Tests

**Test Method:**
1. **Capture baseline** (before conversion):
   - Render inline templates with test data → save to `baseline/task-ready_for_development-inline.txt`
2. **Create external templates** (this task)
3. **Render external templates** with same test data → save to `baseline/task-ready_for_development-external.txt`
4. **Compare outputs**:
   - Semantic equivalence required
   - Whitespace differences acceptable (fewer blank lines is improvement)

**Test Data:**
```go
vars := map[string]string{
    "task_id":         "E07-F30-001",
    "title":           "Test task",
    "status":          "ready_for_development",
    "file_path":       "docs/plan/.../tasks/001.md",
    "related_docs":    "prd.md, architecture.md",
    "related_tasks":   "E07-F29-003",
    "complexity_tier": "STANDARD",
}
```

**Verification:**
```bash
# Render and compare
diff -u baseline/task-ready_for_development-inline.txt \
        baseline/task-ready_for_development-external.txt
# Should show only whitespace improvements, no semantic changes
```

**Improvement Example:**
Before (inline, unreadable):
```json
"instruction_template": "Launch developer with test-driven-development skill for task {task_id}: \"{title}\". LOAD: test-driven-development + implementation skills. READ: (1) Task spec at {file_path} (2) Feature test plan (09-test-plan.md) (3) Feature architecture docs (4) Related docs: {related_docs} (5) Related tasks: {related_tasks}. TDD PROCESS: 1. Write failing test first (red) 2. Implement minimum code to pass (green) 3. Refactor while keeping tests green 4. Commit when test suite passes. EXIT GATE: - All test cases pass - Implementation matches spec and related docs - Code follows conventions. Advance: shark task next-status {task_id}."
```

After (external, readable):
```go
Launch developer with test-driven-development skill for task {{.task_id}}: "{{.title}}".

LOAD: test-driven-development + implementation skills.

READ:
(1) Task spec at {{.file_path}}
(2) Feature test plan (09-test-plan.md)
(3) Feature architecture docs
{{- if .related_docs}}
(4) Related docs: {{.related_docs}}
{{- end}}
{{- if .related_tasks}}
({{if .related_docs}}5{{else}}4{{end}}) Related tasks: {{.related_tasks}}
{{- end}}

{{template "_tdd_process" .}}

EXIT GATE:
- All test cases pass
- Implementation matches spec{{if .related_docs}} and related docs{{end}}
- Code follows conventions

Advance: shark task next-status {{.task_id}}.
```
