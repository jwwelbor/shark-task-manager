# Task: Create OrchestratorRenderer with text/template engine

## Goal

Implement the core template engine that loads, precompiles, and renders Go text/template files for orchestrator instructions. This is the foundation for Phase 1 (MVP) and enables backward-compatible external template support.

## Requirements

### Functional Requirements

- [ ] Create `internal/templates/orchestrator_renderer.go` with `OrchestratorRenderer` struct
- [ ] Implement singleton pattern with `sync.Once` for thread-safe initialization
- [ ] Precompile all `.tmpl` files from `templates/` directory at startup
- [ ] Provide custom template functions: `eq`, `ne`, `isEmpty`, `isSimple`, `isStandard`, `isComplex`
- [ ] Support partial template includes via `{{template "name" .}}`
- [ ] Handle template execution with `map[string]string` placeholder data

### Non-Functional Requirements

- [ ] Performance: Template rendering < 5ms per call (p95)
- [ ] Memory: Precompiled templates < 100KB total
- [ ] Thread Safety: Singleton accessible from multiple goroutines
- [ ] Error Handling: Fail fast on syntax errors at startup, graceful degradation on execution errors
- [ ] Test Coverage: 95%+ coverage for orchestrator_renderer.go

## Implementation Plan

### Steps

1. [ ] Create `internal/templates/orchestrator_renderer.go` file
2. [ ] Define `OrchestratorRenderer` struct with fields:
   - `templates *template.Template` (precompiled template set)
   - `templateDir string` (base directory)
3. [ ] Implement `NewOrchestratorRenderer(templateDir string) (*OrchestratorRenderer, error)`
   - Use `template.ParseGlob(templateDir + "/*/*.tmpl")` to precompile all templates
   - Add custom functions via `Funcs(orchestratorFuncs())`
   - Return error if parsing fails (syntax errors)
4. [ ] Implement `orchestratorFuncs() template.FuncMap` with custom functions:
   - `eq(a, b interface{}) bool` - equality comparison
   - `ne(a, b interface{}) bool` - not-equal comparison
   - `isEmpty(s string) bool` - empty/whitespace check
   - `isSimple(tier string) bool` - tier == "SIMPLE"
   - `isStandard(tier string) bool` - tier == "STANDARD"
   - `isComplex(tier string) bool` - tier == "COMPLEX"
5. [ ] Implement singleton accessor `GetOrchestratorEngine() *OrchestratorRenderer`
   - Use `sync.Once` for thread-safe initialization
   - Default `templateDir` to "templates"
   - Fail fast on initialization error
6. [ ] Implement `Render(templateName string, vars map[string]string) (string, error)`
   - Lookup template by name
   - Execute template with vars
   - Return rendered string or error
7. [ ] Write unit tests for all functions (target: 95%+ coverage)

### Technical Approach

- **Pattern Reuse**: Follow proven pattern from `internal/templates/renderer.go` (task markdown templates)
- **Singleton Pattern**: Use `sync.Once` for thread-safe lazy initialization (same as existing task renderer)
- **Custom Functions**: Add convenience helpers for common template logic (tier checks, empty checks)
- **Error Handling**: Parse errors fail fast at startup; execution errors return error (caller handles gracefully)

## Testing Strategy

### Unit Tests (internal/templates/orchestrator_renderer_test.go)

**Test Coverage:**
1. **Constructor tests** (API-01 to API-04):
   - Valid template directory → returns renderer
   - Missing directory → returns error
   - Malformed template → returns parse error with file/line
   - Empty directory → returns renderer with no templates
2. **Singleton tests** (API-05 to API-07):
   - First call creates singleton
   - Subsequent calls return same instance (pointer equality)
   - Concurrent access safe (1000 goroutines, no race)
3. **Render method tests** (API-08 to API-12):
   - Existing template → renders correctly
   - Missing template → returns error "template not found"
   - Empty vars → renders with empty placeholders
   - Missing variable → execution error
   - Performance benchmark (< 5ms p95)
4. **Custom function tests** (API-18 to API-26):
   - `eq("a", "a")` → true
   - `ne("a", "b")` → true
   - `isEmpty("")` → true, `isEmpty("   ")` → true
   - `isSimple("SIMPLE")` → true, etc.

**Test Tools:**
- `go test -v ./internal/templates`
- `go test -bench=BenchmarkOrchestratorRenderer -benchmem`
- `go test -race ./internal/templates` (race detector)

**Test Fixtures:**
- `internal/templates/test_fixtures/valid/basic.tmpl`
- `internal/templates/test_fixtures/invalid/malformed.tmpl`

### Performance Benchmarks

- Target: < 1ms average, < 5ms p95
- Run: `go test -bench=BenchmarkRender`
- Expected: ~800 ns/op, < 500 B/op

- Fail-fast on syntax errors prevents runtime surprises
- Custom functions provide template author convenience (no complex Go template syntax needed)
