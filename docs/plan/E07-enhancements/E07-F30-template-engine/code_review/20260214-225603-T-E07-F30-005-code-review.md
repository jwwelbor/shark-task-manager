## Comparison: Before vs. After

**Before (inline, from task spec lines 150-152):**
```json
"instruction_template": "Launch developer with test-driven-development skill for task {task_id}: \"{title}\". LOAD: test-driven-development + implementation skills. READ: (1) Task spec at {file_path} (2) Feature test plan (09-test-plan.md) (3) Feature architecture docs (4) Related docs: {related_docs} (5) Related tasks: {related_tasks}. TDD PROCESS: 1. Write failing test first (red) 2. Implement minimum code to pass (green) 3. Refactor while keeping tests green 4. Commit when test suite passes. EXIT GATE: - All test cases pass - Implementation matches spec and related docs - Code follows conventions. Advance: shark task next-status {task_id}."
```

**After (external, from ready_for_development.tmpl):**
```go
Launch developer with test-driven-development skill for task {{.task_id}}: "{{.title}}".

LOAD: test-driven-development + implementation skills.

READ:
(1) Task spec at {{.file_path}}
(2) Feature test plan (09-test-plan.md) for test cases, acceptance criteria tests, and API contract tests relevant to this task
(3) Feature architecture docs for contracts and patterns
{{- if .related_docs}}
(4) Related docs: {{.related_docs}}
{{- end}}
{{- if .related_tasks}}
({{if .related_docs}}5{{else}}4{{end}}) Related tasks: {{.related_tasks}}
{{- end}}

{{template "_tdd_process" .}}

EXIT GATE:
- All mapped test cases from feature test plan pass
- Implementation matches task spec
- Code follows codebase conventions from research

Advance: shark task next-status {{.task_id}}.
```

**Improvements Achieved:**
1. **Readability:** Multiline format with clear section breaks (10x easier to read)
2. **Maintainability:** Conditionals hide empty sections (no more blank "Related docs: " lines)
3. **Reusability:** TDD process partial can be updated once, affects multiple templates
4. **Clarity:** Enhanced descriptions (e.g., "for test cases, acceptance criteria tests...")
5. **Smart numbering:** Automatic renumbering prevents gaps
