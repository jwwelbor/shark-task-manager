# Replace Viewer Adapter Layer With On-Demand Entity Service Calls

## Goal

The viewer's `Hierarchy()` and `FeatureTasks()` endpoints use a bespoke `taskRelAdapter`
that bypasses `EntityRelationshipService` via a raw SQL bulk-load, causing task→bug and
task→feature links to be silently dropped. Replace this with per-task on-demand calls to
`EntityRelationshipService.GetRelationships()` — the same pattern as `shark get {id}` —
and expose cross-entity relationships in a new `Relationships []ViewerRelatedEntity`
field on `ViewerTask`.

## Scope

Files to delete or strip:
- `taskRelAdapter` struct and `ListAll()` in `internal/viewer/server/wire.go`
- `ViewerTaskRelationshipRepository` interface in `internal/services/viewer_service.go`
- `ViewerTaskRelationship` struct in `internal/services/viewer_service.go`
- `taskRelRepo` field and `WithTaskRelRepo()` method on `ViewerService`
- Tests covering deleted symbols: `TestViewerService_Hierarchy_GracefulWhenRelRepoNil`, `TestViewerService_Hierarchy_DependsOnNilToEmpty`, `TestViewerService_FeatureTasks_DependsOnNilWhenRelRepoNil`, all `WithTaskRelRepo(...)` call sites in viewer tests

Files to modify:
- `internal/services/viewer_service.go` — add `entityRelSvc` (required) and `entityRegistry` fields; replace bulk map-building at lines 837–838 and 1480–1508 with per-task `GetRelationships` calls; replace `DependsOn`/`BlockedBy`/`Blocks []string` on `ViewerTask` with `Relationships []ViewerRelatedEntity`; add `ViewerRelatedEntity` struct
- `internal/viewer/server/wire.go` — delete `taskRelAdapter`, inject `EntityRelationshipService` and `EntityRegistry` into the `ViewerService` constructor
- `internal/services/viewer_service_test.go` — add cross-entity relationship tests; update existing assertions from string-slice fields to `Relationships` field
