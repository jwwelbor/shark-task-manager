# Task: Add unified delete dispatcher

## Goal

Add a `shark delete <KEY>` command that auto-detects the entity type from the key format and dispatches to the appropriate delete handler:

```
shark delete E07                # detects epic, dispatches to: shark epic delete E07
shark delete E07-F01            # detects feature, dispatches to: shark feature delete E07-F01
shark delete E07-F01-001        # detects task, dispatches to: shark task delete E07-F01-001
```

## Requirements

### Functional Requirements

- [ ] `shark delete <KEY>` auto-detects entity type using `DetectEntityType()` from T-E07-F25-002
- [ ] Dispatches to `runEpicDelete`, `runFeatureDelete`, or `runTaskDelete` based on detection
- [ ] Supports `--force` flag (forwarded to underlying handler)
- [ ] Supports `--json` output (inherited from root)
- [ ] Shows confirmation prompt for destructive operations (same as underlying commands)
- [ ] Returns clear error for unrecognized key formats
- [ ] Help text documents auto-detection and shows examples for each entity type

### Non-Functional Requirements

- [ ] Single command, not subcommands (unlike create dispatcher)
- [ ] Uses `DetectEntityType()` helper from T-E07-F25-002
- [ ] Registered in "essentials" command group
- [ ] Zero breaking changes to existing delete commands

## Implementation Plan

### Steps

1. [ ] Create `internal/cli/commands/delete_dispatch.go`
2. [ ] Implement the dispatcher:

```go
var deleteCmd = &cobra.Command{
    Use:     "delete <KEY>",
    Short:   "Delete an epic, feature, or task",
    GroupID: "essentials",
    Long:    `Delete an entity by key. The entity type is auto-detected from the key format.

Key format detection:
  E##              → Epic
  E##-F## or F##   → Feature
  E##-F##-### or T-E##-F##-###  → Task

Examples:
  shark delete E07                    Delete epic E07
  shark delete E07-F01                Delete feature E07-F01
  shark delete E07-F01-001            Delete task E07-F01-001
  shark delete E07-F01 --force        Force delete (cascade)`,
    Args: cobra.ExactArgs(1),
    RunE: runDelete,
}

func runDelete(cmd *cobra.Command, args []string) error {
    key := args[0]
    entityType := DetectEntityType(key)

    switch entityType {
    case "epic":
        return runEpicDelete(cmd, args)
    case "feature":
        return runFeatureDelete(cmd, args)
    case "task":
        return runTaskDelete(cmd, args)
    default:
        return fmt.Errorf("cannot determine entity type from key: %s\nExpected format: E## (epic), E##-F## (feature), or E##-F##-### (task)", key)
    }
}
```

3. [ ] Register command and flags:
```go
func init() {
    cli.RootCmd.AddCommand(deleteCmd)
    deleteCmd.Flags().Bool("force", false, "Force deletion (cascade delete children)")
}
```

### Technical Approach

**Runtime dispatch** (not subcommands): Unlike `shark create` which uses subcommands, `shark delete` uses runtime key detection because the user shouldn't need to specify the entity type -- the key already encodes it. This is the same pattern as `shark get`.

**Flag forwarding challenge**: The underlying delete handlers read `--force` from `cmd.Flags()`. Since the delete dispatcher defines its own `--force` flag, the value is available on `cmd` and the underlying handler reads from the same `cmd`, so it should work transparently.

## Notes

- **Naming**: File is `delete_dispatch.go` (not `delete.go`) to avoid collision with any existing delete-related files. Check during implementation whether `delete.go` already exists.
- The existing `runEpicDelete`, `runFeatureDelete`, `runTaskDelete` handlers all accept `(cmd *cobra.Command, args []string)` and read the key from `args[0]`, which is exactly what the dispatcher passes.
- The `--force` flag semantics differ slightly per entity:
  - Epic delete with `--force`: cascades to features and tasks
  - Feature delete with `--force`: cascades to tasks
  - Task delete: no cascade needed
  - But the flag is named `--force` on all of them, so unified handling works.
