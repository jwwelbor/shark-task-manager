# CLI output rendering: formatSize helper, size in get/list views, --field size

## Goal
Implement the `formatSize(*int) string` helper that renders `"<label> (<num>)"` or `"—"`, add a `Size` column to entity list tables and a `Size:` line to entity detail views for all six entity types, and verify that JSON output carries the numeric `size` field (via `omitempty`) while `--field size` and `--field size_label` behave correctly (null → exit code 4).

## Scope
- Files to create or modify (implementation):
  - A `formatSize` helper in `internal/cli/commands/` or `internal/formatters/` (follow existing formatter patterns)
  - `internal/cli/commands/epic.go`, `feature.go`, `task.go`, `bug.go`, `change.go`, `idea.go` — add Size to detail and list output
- Files to modify (tests):
  - Formatter or command test files for `formatSize` unit tests (TC-F006-C, TC-F006-D)
  - JSON output assertions (TC-F006-A, TC-F006-B, TC-F007-A)

## Acceptance Criteria
See spec.md REQ-F-006, REQ-F-007, Acceptance Scenarios 1–3, 6.
Additional task-specific criteria:
- AC-T1: JSON output uses `"size": null` (or absent via omitempty) when nil; never an empty string or zero
- AC-T2: `--field size_label` is supported as a separate extractable field per spec.md REQ-F-007
- AC-T3: `--field size` on an entity with nil Size exits code 4 (matches existing `--field` null behavior)

## Test Cases
See test-plan.md Section 1: TC-F006-A through TC-F006-D, TC-F007-A through TC-F007-C.
The `formatSize` function tests are pure unit tests (no DB, no service mock needed).
`--field` behavior is verified through existing JSON extraction infrastructure.
