# Service layer: Size field on all 6 Create/Update DTOs and service methods

## Goal
Add `Size *int` to all six `CreateXInput` DTOs and `UpdateXInput` DTOs (plus `ClearSize bool` on Update DTOs), then update the corresponding `CreateX` and `UpdateX` service methods to pass the field through to the model before persistence. No business logic beyond passthrough — model `Validate()` already handles size validation.

## Scope
- Files to modify (DTOs):
  - `internal/services/task_dto.go`, `internal/services/feature_dto.go`, `internal/services/epic_dto.go`
  - `internal/services/bug_dto.go`, `internal/services/change_dto.go`, `internal/services/idea_dto.go`
- Files to modify (service methods):
  - `internal/services/task_service.go`, `internal/services/feature_service.go`, `internal/services/epic_service.go`
  - `internal/services/bug_service.go`, `internal/services/change_service.go` (or equivalent), `internal/services/idea_service.go`
- Files to modify (tests):
  - `internal/services/task_service_test.go`, `internal/services/feature_service_test.go`, `internal/services/epic_service_test.go`
  - `internal/services/bug_service_test.go`, corresponding change and idea service test files

## UAT Rejection (2026-04-26)

**Verdict:** REJECT (codex red-team override of code-review/QA PASS)
**Unmet AC:** AC-T1 (Create-side for TaskService), REQ-F-010 (service half — task path)
**Classification:** AC Violation + Spec Gap

### Defect summary

The service-layer changes for the 5 non-task entities (epic, feature, bug, change-card, idea) are correct and complete. The TaskService.CreateTask path is **broken in production** because `taskcreation.CreateTaskInput` (which the production path delegates to) does not include `Size`, so `input.Size` is silently dropped between `task_service.go:316-328` and `creator.go`. The TC-SVC-A test for TaskService (`task_service_test.go:2725-2755`) passes `nil` for `creatorSvc`, exercising only the unreachable fallback branch — so the broken production branch has zero test coverage.

### Required fixes (bug-fix scope)

1. Add `Size *int` to `taskcreation.CreateTaskInput` (`internal/taskcreation/creator.go:80-93`).
2. Propagate it into the constructed `models.Task` inside `taskcreation.Creator.CreateTask` (around lines 241-257 per codex evidence).
3. Map `input.Size` into `creatorInput.Size` at `internal/services/task_service.go:316-328`.
4. Add a service test that exercises the creator-svc path with `Size: ptr(5)` and asserts the resulting task has `Size == ptr(5)` (mirror the existing `TestTaskService_CreateTask_CreatorSvcPath_*` pattern).
5. Add at least one precedence test (any service) where `ClearSize=true` AND `Size=ptr(8)` are both set, asserting `entity.Size == nil`. This locks in the spec D5 contract that "ClearSize takes precedence over Size".

### Scope expansion justification

The spec §3.5 did not call out the existence of `taskcreation.Creator` as a second Create path that bypasses the DTO. The implementer should have surfaced this as a spec question; instead, the diff was scoped to only the documented service files, leaving the production task path broken. Touching `internal/taskcreation/creator.go` is required to satisfy AC-T1 and REQ-F-010 end-to-end.
