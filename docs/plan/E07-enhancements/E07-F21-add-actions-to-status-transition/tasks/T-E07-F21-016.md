# Task: Add provider and model fields to PopulatedAction orchestrator struct

## Goal

Add `provider` and `model` fields to both `OrchestratorAction` (config input) and `PopulatedAction` (JSON output) so the orchestrator can specify which AI provider/model to use per status action.

## Requirements

### Functional Requirements

- [ ] `OrchestratorAction` struct gains `Provider string` and `Model string` fields (optional, json/yaml tagged)
- [ ] `PopulatedAction` struct gains `Provider string` and `Model string` fields (optional, json tagged)
- [ ] `GetStatusActionPopulated` passes provider and model from config to PopulatedAction
- [ ] All places constructing `PopulatedAction` pass through provider and model
- [ ] Fields are optional — omitempty, no validation required (empty = use default)

### Non-Functional Requirements

- [ ] Backward compatible: existing configs without provider/model continue to work
- [ ] JSON output includes fields only when non-empty (omitempty)

## Implementation Plan

### Files to modify

1. `internal/config/orchestrator_action.go` — Add Provider/Model to OrchestratorAction struct
2. `internal/config/action_service.go` — Add Provider/Model to PopulatedAction struct, pass through in GetStatusActionPopulated
3. All `PopulatedAction` construction sites (display_service.go, entity_service.go, task_service.go, bug_service.go, etc.)

### Steps

1. Add fields to OrchestratorAction struct
2. Add fields to PopulatedAction struct
3. Update GetStatusActionPopulated to copy fields
4. Update all other PopulatedAction construction sites
5. Update tests
