# Task: Update TaskPlaceholders

## Goal

Update TaskPlaceholders in internal/config/template_helpers.go to populate the full canonical variable set with correct hierarchy keys. This is the core bug fix -- currently epic_id and feature_id are both set to the task key value instead of the actual parent keys.

## Rationale

See 02-architecture.md ADR-2 (canonical variables), ADR-3 (enrich existing functions), and ADR-5 (parse parent keys from task key). This is the primary fix for the template variable bug.

## Scope

- File: internal/config/template_helpers.go -- modify TaskPlaceholders function
- File: internal/config/template_helpers_test.go -- add/update tests

## Acceptance Criteria

- Returns "key" with the task's key value
- Returns "task_key" as alias for "key"
- Returns "epic_key" correctly parsed from task key (e.g., T-E07-F01-001 produces epic_key=E07)
- Returns "feature_key" correctly parsed from task key (e.g., T-E07-F01-001 produces feature_key=E07-F01)
- Does NOT return "task_id", "epic_id", or "feature_id" (removed per ADR-2)
- Returns "id" as backward compat alias
- Returns "description" when task description is non-nil
- All existing fields preserved: title, status, priority, agent_type, depends_on, execution_order, blocked_reason, completion_notes, files_changed, slug, file_path, created_at, updated_at
- Nil task input returns empty map without panic
- Handles both T-prefix and short format task keys
- Test cases: see 09-test-plan.md AC-1 (TC-TP-01 through TC-TP-09)
- make fmt and make lint and make test all pass
