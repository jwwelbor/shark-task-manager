# Task: Change GetStatusActionPopulated Signature

## Goal

Change the GetStatusActionPopulated method on ActionService interface and DefaultActionService implementation to accept a vars map instead of a single taskID string. Remove the hardcoded 4-variable map construction that was the core bug.

## Rationale

See 02-architecture.md ADR-4. The current implementation builds a 4-entry map where all values are taskID -- this is the core bug. Callers should pass the full variable map built by the appropriate XxxPlaceholders function.

## Scope

- File: internal/config/action_service.go -- change ActionService interface and DefaultActionService.GetStatusActionPopulated
- Any direct callers of GetStatusActionPopulated (search for call sites)

## Interface Change

- Old: GetStatusActionPopulated(ctx, status string, taskID string) returns PopulatedAction and error
- New: GetStatusActionPopulated(ctx, status string, vars map of string to string) returns PopulatedAction and error
- See 02-architecture.md Section 3 for full interface before/after

## Acceptance Criteria

- ActionService interface has updated signature
- DefaultActionService.GetStatusActionPopulated passes vars directly to PopulateTemplate (no hardcoded map)
- All direct callers updated to pass appropriate XxxPlaceholders map
- Compile-time interface satisfaction verified
- Test cases: see 09-test-plan.md AC-6 (TC-AS-01 through TC-AS-07)
- make fmt and make lint and make test all pass
