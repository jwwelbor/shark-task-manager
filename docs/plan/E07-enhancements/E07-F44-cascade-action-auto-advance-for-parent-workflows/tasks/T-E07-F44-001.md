# Add Workflow-Aware Next-Step Helpers for Parent Cascade Rollups

## Goal
Add the minimal helper logic needed to ask workflow metadata whether a parent status is a `cascade` status and what its next configured step is, without hardcoding `active` or `completed`.

## Scope
- Files to modify:
  - `internal/workflow/service.go`
  - `internal/workflow/service_test.go`
- Files to create: none

Reference spec.md: "See spec.md REQ-F-001, REQ-F-003, REQ-F-007 and Architecture Sections 2.2-2.3.3"

- AC-T1: Helper logic is level-agnostic and uses status metadata plus valid transitions only.
- AC-T2: Ambiguous or missing next-step cases are handled consistently and covered by tests.
