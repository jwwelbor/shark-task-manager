# Task: Make CLI help text and flag descriptions config-driven

## Goal

All `--status` flag descriptions and help text that mention specific status names should be generated dynamically from the workflow config. When using the advanced profile, `--help` should show all 19 statuses, not the hardcoded basic 4.

## Files to Modify

### `internal/cli/commands/task.go`
- **Line 2190**: `"Filter by status (todo, in_progress, completed, blocked)"` → Use `workflow.Service.StatusFlagDescription()`
- **Line 128-129**: Example help text mentioning `--status=todo` and `--status=completed` → Use first and last statuses from config dynamically, or keep as generic examples.

### `internal/cli/commands/shared_flags.go`
- **Lines 144, 159, 207, 221**: Four places with `"Status: draft, active, completed, archived"` for epic/feature statuses. Note: epic/feature statuses are separate from task statuses. For now, these can remain or be addressed if epic/feature status is also config-driven.

### `internal/cli/commands/aliases.go`
- **Lines 27-97**: Help text like `"Mark a task as in_progress"` and `"return it to todo status"`. These describe what the alias commands do, so the status names are inherent to the command's purpose. Consider using `GetDefaultStatus()` for the unblock message.

## Challenge: Cobra Flag Registration Timing

Cobra flags are registered in `init()` functions which run at package load time, before any command executes. The workflow service may not be initialized yet at that point. Options:
1. Initialize workflow service eagerly during init (lightweight - just reads a JSON file)
2. Use a generic help string like `"Filter by status (use 'shark workflow statuses' to see valid values)"`
3. Set flag description dynamically in `PersistentPreRunE` before help is rendered

Recommend option 1 if feasible, option 3 as fallback.

## Acceptance Criteria

- [ ] `shark task list --help` shows all valid statuses from the active workflow config
- [ ] Switching from basic to advanced profile changes the help output
- [ ] No hardcoded task status names in flag description strings
- [ ] `make build && make test` passes
