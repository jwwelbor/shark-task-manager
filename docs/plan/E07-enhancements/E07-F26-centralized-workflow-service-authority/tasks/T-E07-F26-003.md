# Task: Create global workflow service accessor in CLI layer

## Goal

Create a lazy-initialized global `workflow.Service` accessor in the CLI layer, following the same pattern as `cli.GetDB()` in `internal/cli/db_global.go`. This gives all CLI commands a single, cached workflow service instance without each command having to construct one.

## Implementation

Create `internal/cli/workflow_global.go` with:

- **`GetWorkflowService() *workflow.Service`** - Returns the cached service, initializing on first call. Uses project root auto-detection (same as DB init). Thread-safe via `sync.Once`.
- **`ResetWorkflowService()`** - For testing: resets the cached instance so tests can inject different configs.

The service should be initialized from the same project root that `GetDB()` uses.

## Files to Create/Modify

- `internal/cli/workflow_global.go` (new) - Global accessor
- `internal/cli/workflow_global_test.go` (new) - Tests

## Acceptance Criteria

- [ ] `cli.GetWorkflowService()` returns a valid `*workflow.Service`
- [ ] Multiple calls return the same instance (cached)
- [ ] Uses project root auto-detection
- [ ] Falls back to default workflow if no `.sharkconfig.json`
- [ ] `ResetWorkflowService()` clears the cache for test isolation
- [ ] Thread-safe initialization
