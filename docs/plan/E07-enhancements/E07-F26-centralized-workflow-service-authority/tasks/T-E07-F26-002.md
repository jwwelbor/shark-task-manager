# Task: Add missing methods to workflow.Service

## Goal

Extend `internal/workflow/service.go` with the methods needed for it to be the single authority on all workflow questions. The existing service already has `IsValidStatus()`, `GetValidTransitions()`, `IsTerminalStatus()`, `GetAllStatuses()`, etc. Add the missing pieces that other code currently handles with hardcoded logic.

## New Methods to Add

- **`ValidateStatus(status string) error`** - Returns nil if status is valid in the current workflow, or an error listing valid statuses. Replaces `models.ValidateTaskStatus()` and `models.ValidateTaskStatusWithWorkflow()`.
- **`StatusHelpText() string`** - Returns comma-separated list of all valid statuses for use in `--help` flag descriptions. Example: `"todo, in_progress, ready_for_review, completed, blocked"`.
- **`StatusFlagDescription() string`** - Returns full flag help string. Example: `"Filter by status (todo, in_progress, ...)"`.
- **`IsCompletedStatus(status string) bool`** - Alias/synonym for `IsTerminalStatus()`. Replaces direct `== "completed"` comparisons throughout the codebase.
- **`GetDefaultStatus() string`** - Returns the initial status for new tasks from `special_statuses._start_[0]`. Replaces hardcoded `"todo"` references.

## Files to Modify

- `internal/workflow/service.go` - Add the new methods
- `internal/workflow/service_test.go` - Test each new method with both basic and advanced workflow configs

## Acceptance Criteria

- [ ] All five new methods implemented
- [ ] Tests cover basic profile (5 statuses) and advanced profile (19 statuses)
- [ ] Tests cover case insensitivity
- [ ] Tests cover missing/empty config fallback to defaults
- [ ] `ValidateStatus()` error message includes the list of valid statuses
- [ ] Existing methods unchanged, all existing tests still pass
