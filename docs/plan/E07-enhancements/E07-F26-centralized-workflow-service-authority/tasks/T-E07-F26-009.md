# Task: Centralize entity key parsing and normalization into a single service

## Goal

Entity key parsing (detecting epic vs feature vs task from a key string, normalizing `E07-F26-002` to `T-E07-F26-002`, handling case insensitivity, stripping/adding the `T-` prefix, parsing slugged keys) is duplicated across multiple packages. There should be ONE key service/package that all code calls. Currently:

- `--depends-on` requires `T-` prefix while every other flag accepts short format
- Smart dispatchers (`get`, `list`, `status`) have their own key detection logic
- Repository lookup methods each do their own key normalization
- `internal/keys/validation.go` has key format validation
- `internal/keygen/` has key generation
- `internal/cli/commands/` has inline key parsing (e.g., `IsFeatureKeySuffix()`, `DetectEntityType()`)
- `internal/cli/scope/` has scope interpretation from keys

The same "is this an epic, feature, or task key?" question gets answered differently in different places, leading to bugs like `--depends-on` rejecting valid short-format keys.

## Design

Create or consolidate into a single `internal/keys/` package (or similar) that provides:

- **`Parse(key string) (EntityType, ParsedKey, error)`** - Parse any key format into a structured result. Handles `E07`, `E07-F26`, `E07-F26-002`, `T-E07-F26-002`, slugged variants, case insensitivity.
- **`Normalize(key string) string`** - Returns canonical form (e.g., adds `T-` prefix for tasks, uppercases `E`/`F`)
- **`NormalizeTaskKey(key string) string`** - Ensures task key has `T-` prefix
- **`DetectEntityType(key string) EntityType`** - Returns Epic, Feature, or Task
- **`IsValid(key string) bool`** - Validates any key format
- **`Format(parsed ParsedKey) string`** - Formats back to string in canonical form

Every call site that currently does its own regex matching, prefix checking, or case normalization should call this package instead.

## Files to Audit and Refactor

- `internal/keys/validation.go` - Existing validation, extend into full service
- `internal/keygen/` - Key generation (may stay separate but should use shared types)
- `internal/cli/commands/get.go` - `DetectEntityType()` inline logic
- `internal/cli/commands/list.go` - Entity type detection
- `internal/cli/commands/task.go` - `IsFeatureKeySuffix()`, key normalization in depends-on handling
- `internal/cli/scope/` - Scope interpretation
- `internal/repository/task_repository.go` - Key lookup normalization
- `internal/repository/epic_repository.go` - Key lookup normalization
- `internal/repository/feature_repository.go` - Key lookup normalization
