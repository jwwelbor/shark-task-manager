# Task: Replace hardcoded status validation with workflow.Service

## Goal

Remove the hardcoded status maps in validation functions and delegate to `workflow.Service.ValidateStatus()`. After this task, no validation function contains its own list of valid statuses.

## Files to Modify

### `internal/models/validation.go`
- **`ValidateTaskStatusWithWorkflow()`** (lines 113-160): Currently has two hardcoded maps (old 6-status and new 14-status). Replace the body to accept a status validator interface or call through to a provided validator. Since models can't import workflow (circular dep), use an interface or function parameter.
- **`ValidateTaskStatus()`** (lines 104-108): Keep as deprecated wrapper, but document that callers should use `workflow.Service.ValidateStatus()` directly.

### `internal/taskfile/parser.go`
- **Line 162-171**: Remove the hardcoded `validStatuses` map. Use `workflow.Service` to validate parsed statuses. The parser will need the service injected or available globally.

### `internal/cli/commands/validators.go`
- **`ValidateStatus()`** (lines 82-106): Remove hardcoded `draft, active, completed, archived` map. Delegate to workflow service.

## Design Consideration

`models` package cannot import `workflow` (circular dependency). Options:
1. Define a `StatusValidator` interface in `models` that `workflow.Service` satisfies
2. Have callers validate at the CLI/command layer before passing to models
3. Pass a validation function `func(string) error` into the model methods

Recommend option 2: validate at the command layer using `cli.GetWorkflowService().ValidateStatus()`, and simplify the model validation to basic non-empty checks only.

## Acceptance Criteria

- [ ] No hardcoded status lists remain in `models/validation.go`
- [ ] No hardcoded status list in `taskfile/parser.go`
- [ ] No hardcoded status list in `cli/commands/validators.go`
- [ ] All validation flows through `workflow.Service.ValidateStatus()` or delegates to it
- [ ] Invalid status errors include the list of valid options
- [ ] `make test` passes
