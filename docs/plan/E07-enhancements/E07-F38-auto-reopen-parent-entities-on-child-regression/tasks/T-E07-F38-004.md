# Wire Cascade Dependencies into CLI and HTTP Service Accessors

## Goal
Update the global service accessors and the HTTP wiring layer so that `TaskService` and `FeatureService` instances constructed at runtime receive the new cascade dependencies. Without this task, the cascade helper exists in the service layer but never fires in real CLI or HTTP API usage.

## Scope
- Files to modify:
  - `internal/cli/services_global.go`
  - `cmd/server/services.go`

## Acceptance Criteria
Reference spec.md: "See spec.md Section 2.1.2 (services_global.go and cmd/server/services.go rows)"
Additional task-specific criteria:
- AC-T1: `GetTaskService()` in `services_global.go` constructs the new cascade deps lazily from the existing global `*repository.DB` and `*workflow.Service`; no new global state is introduced.
- AC-T2: `GetFeatureService()` in `services_global.go` is updated with the same pattern.
- AC-T3: `WireServices()` in `cmd/server/services.go` explicitly constructs cascade deps and injects them into both service constructors.
- AC-T4: No functional behavior change is observable other than the cascade now firing on backward transitions in CLI and HTTP contexts.
