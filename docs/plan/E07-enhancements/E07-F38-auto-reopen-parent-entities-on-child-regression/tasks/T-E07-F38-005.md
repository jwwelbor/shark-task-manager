# Update Status History Formatter to Label Auto-Reopen Rows

## Goal
Update the `shark status history` output formatter so that history rows whose `notes` field begins with `auto_reopen:` are rendered with a visually distinct label in human output. JSON output is unchanged — consumers already have access to the `notes` field and can filter on the prefix.

## Scope
- Files to modify:
  - `internal/cli/commands/status.go` (or the formatter function that renders `shark status history`)
- Files to modify conditionally:
  - Any formatter helper file used by the status history renderer

## Acceptance Criteria
Reference spec.md: "See spec.md REQ-F-009, AC-14"
Additional task-specific criteria:
- AC-T1: Human output rows with `notes` starting with `auto_reopen:` display a distinct label (e.g., color or bracketed tag) that differentiates them from manually-triggered transitions.
- AC-T2: JSON output schema is unchanged; no new fields are added to the history JSON response.
- AC-T3: The detection logic is purely string-prefix based (`strings.HasPrefix(notes, "auto_reopen:")`); no workflow package import is added to the formatter.
- AC-T4: Rows without the `auto_reopen:` prefix render identically to how they did before this change.
