# Implement cascade_reopen.go — Unified Parent Reopen Helper

## Goal
Create `internal/services/cascade_reopen.go` as the single source of truth for all parent-reopen logic. This file houses `cascadeParentReopens`, `resolveReopenTarget`, `cascadeDeps`, `cascadeTrigger`, and the narrow repository interfaces the cascade depends on. No other file duplicates this logic.

## Scope
- Files to create:
  - `internal/services/cascade_reopen.go`
- Files to modify: none (interfaces defined here; wiring happens in T-E07-F38-003)

## Acceptance Criteria
Reference spec.md: "See spec.md REQ-F-001 through REQ-F-008, REQ-N-001 through REQ-N-003, Section 2.1.1, Section 2.3"
Additional task-specific criteria:
- AC-T1: `resolveReopenTarget` implements the three-step lookup (history → aggregation → initial) per REQ-F-004; no status name hardcoded.
- AC-T2: `cascadeParentReopens` re-fetches each ancestor's current status inside the cascade transaction before deciding to update (idempotency per REQ-F-008).
- AC-T3: If the cascade transaction fails at any point, the error is logged via `slog.Warn` with the triggering child key and the ancestor that failed; the function returns `nil` to the caller per REQ-N-003.
- AC-T4: Each auto-reopen writes exactly one `entity_history` row per reopened ancestor, with `notes` beginning with the `auto_reopen:` prefix per REQ-F-007.
- AC-T5: Fallback paths append `[fallback: aggregation]` or `[fallback: initial]` suffix per REQ-F-004.
