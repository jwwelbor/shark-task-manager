# Add Repository Methods for Cascade Reopen

## Goal
Add three new repository methods that the cascade helper will depend on: a transactional history write (`CreateTx`), a history lookup for the most recent prior non-terminal status (`GetLastNonTerminalStatus`), and transactional status-update methods on feature and epic repositories. These are pure data-access additions with no business logic.

## Scope
- Files to modify:
  - `internal/repository/entityhistory/repository.go`
  - `internal/repository/feature_repository.go`
  - `internal/repository/epic_repository.go`
- Files to create: none

## Acceptance Criteria
Reference spec.md: "See spec.md Section 2.1.2 (Files Modified), Section 2.3.1 (API and Interface Contracts), REQ-N-002, REQ-N-005"
Additional task-specific criteria:
- AC-T1: `GetLastNonTerminalStatus` uses a parameterized `NOT IN` clause built from the caller-supplied slice; no status names are hardcoded.
- AC-T2: All three new methods accept `context.Context` as first parameter.
- AC-T3: `UpdateStatusTx` on feature and epic mirrors the signature of their existing `UpdateStatus`, adding only the `*sql.Tx` parameter.
- AC-T4: If the index check (REQ-N-005) finds a missing index, add the migration in `internal/db/db.go` following `.claude/rules/database-critical.md` (bump `CurrentSchemaVersion`, notify developer).
