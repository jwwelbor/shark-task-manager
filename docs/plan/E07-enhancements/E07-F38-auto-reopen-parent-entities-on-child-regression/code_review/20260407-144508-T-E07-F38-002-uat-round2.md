## 3. Race Fix Verification (BUG-QA-001)

**Question:** Does the per-goroutine mock refactor preserve the in-tx isolation contract that the concurrent-cascade test was designed to verify?

**Answer: YES.**

The fix moves `epicRepo` and `histQuerier` construction inside a `makeDeps` closure so each goroutine gets a fresh mock, eliminating unsynchronized shared counters. The key test invariants remain intact:

- Shared history sink with mutex (`cascade_reopen_test.go:1626,1660`) still receives writes from both goroutines.
- Concurrent cascades simulate different in-tx statuses per goroutine (`:1671,1675`).
- Primary assertion `featureRows == 1` (`:1714,1723`) is unchanged — the test still proves exactly one cascade wins under concurrent contention via the in-tx re-fetch idempotency guard (AC-T2 / REQ-F-008).

The race fix is **test-only** and does not soften or bypass the contract under test.
