## Standards Compliance (CLAUDE.md)

- **Repository layer purity:** Methods are pure data access — no business logic, no workflow knowledge. The terminal-status set is supplied by the caller, satisfying REQ-F-005 (no hardcoded status names).
- **Error wrapping:** All errors use `fmt.Errorf("...: %w", err)` with descriptive context (`failed to get last non-terminal status`, `failed to create entity history in transaction`, `failed to update feature/epic status in transaction`). Matches `.claude/rules/go/error-handling.md`.
- **SQL injection safety:** `GetLastNonTerminalStatus` uses `fmt.Sprintf` only to inject `?` placeholders (not user data); all real values flow through `args...` to `QueryRowContext`. No injection vector. Empty-slice branch has its own static query.
- **Validation:** `CreateTx` calls `history.Validate()` before INSERT, mirroring `Create()`. Consistent.
- **`sql.ErrNoRows` handling:** `GetLastNonTerminalStatus` correctly distinguishes "no rows" (returns `("", false, nil)`) from real errors. Matches the contract in spec.md Section 2.3.1.
- **Context placement:** All methods take `ctx` as first param.

## Findings

None blocking. Two minor observations for downstream tasks (not defects in this task):

1. **Unused parameters in `UpdateStatusTx`:** The `agent`/`notes` params are accepted but not persisted. The doc comment makes this explicit and the cascade helper (T-E07-F38-002 onwards) is expected to use these for the accompanying `entity_history` row, not for the `features`/`epics` tables. The Go `_ *string` pattern suppresses unused-arg warnings cleanly.
2. **`CreateTx` requires `history.ChangedAt` to be set by the caller** (no `CURRENT_TIMESTAMP` fallback in the SQL, mirroring `Create`). The cascade helper must populate `ChangedAt` explicitly. This is consistent with the existing `Create` method.
