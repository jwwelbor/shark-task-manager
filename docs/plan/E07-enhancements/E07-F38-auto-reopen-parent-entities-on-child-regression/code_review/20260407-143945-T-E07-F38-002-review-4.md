## 1. Race Fix Verification

### 1.1 Per-goroutine mock construction (the fix)

`internal/services/cascade_reopen_test.go:1671-1694` — `epicRepo` and `histQuerier` are now constructed **inside** the `makeDeps` closure. Each invocation of `makeDeps` (one per goroutine) returns a fresh `mockCascadeEpicRepo` and a fresh `mockParentReopenHistoryQuerier`:

```go
// epicRepo and histQuerier are constructed inside makeDeps so each goroutine
// gets its own instance. This eliminates the data races on the unsynchronized
// call-counter fields (getByIDCalls, calls) that would otherwise be mutated
// concurrently by both goroutines. (BUG-QA-001)
makeDeps := func(featureRepo *mockCascadeFeatureRepo) cascadeDeps {
    epicRepo := &mockCascadeEpicRepo{ ... }
    histQuerier := &mockParentReopenHistoryQuerier{ ... }
    return cascadeDeps{
        db:             &mockTxBeginner{},
        featureRepo:    featureRepo,
        epicRepo:       epicRepo,       // per-goroutine
        historyQuerier: histQuerier,    // per-goroutine
        historyTx:      sharedHistTx,   // intentionally shared (mutex-protected)
        workflowSvc:    wf,
    }
}
```

The `getByIDCalls++` and `m.calls++` increments that BUG-QA-001 reported as racing now occur on goroutine-local instances. There is no shared mutable state for those counters, so the race is eliminated by construction (not by adding a mutex — by removing the sharing).

### 1.2 `sharedHistTx` mutex remains shared (intentional)

`cascade_reopen_test.go:1660-1669` — `sharedHistTx` is constructed **outside** `makeDeps` and shared between both goroutines. This is necessary because the test's primary correctness assertion (`featureRows == 1`) requires both cascades to write into the same history sink so the test can observe that exactly one row was produced. The `CreateTxFunc` already protects all writes with `mu.Lock()`/`defer mu.Unlock()`, and the final read at line 1714 is also under `mu.Lock()`. Race-free, intent preserved.

### 1.3 Test intent preserved

The test still meaningfully proves the in-tx isolation contract for U-01:

- Cascade 1 receives a `featureRepo` whose `GetByIDTxFunc` returns status `"completed"` (still terminal) → proceeds to write the history row.
- Cascade 2 receives a `featureRepo` whose `GetByIDTxFunc` returns status `"in_qa"` (non-terminal, simulating that Cascade 1 already committed) → idempotent skip.
- Both goroutines run concurrently against `sharedHistTx`.
- Final assertion: `featureRows == 1` proves the in-tx re-fetch via `GetByIDTx` correctly enforces idempotency under concurrent cascades. AC-T2 / REQ-F-008 contract is still exercised.

The fix is purely mechanical — it changes which mocks are shared without altering the assertions, the per-goroutine GetByIDTx return values, or the timing.
