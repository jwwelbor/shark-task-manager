### U-01 (HIGH) — In-tx re-fetch routed through tx — **RESOLVED**

**Spec contract (AC-T2 / REQ-F-008):** *"cascadeParentReopens re-fetches each ancestor's current status inside the cascade transaction before deciding to update."*

**Evidence — interface signatures now carry `*sql.Tx`:**
- `cascade_reopen.go:54` — `GetByIDTx(ctx context.Context, tx *sql.Tx, id int64) (*models.Feature, error)` added to `CascadeFeatureRepo`
- `cascade_reopen.go:65` — same on `CascadeEpicRepo`
- Both have a doc comment explicitly tying them to "REQ-F-008 / AC-T2".

**Evidence — re-fetch site routes through tx:**
- `cascade_reopen.go:269` — `freshFeature, ferr := deps.featureRepo.GetByIDTx(ctx, tx, feature.ID)` (was `GetByID(ctx, feature.ID)` in round 2)
- `cascade_reopen.go:319` — `freshEpic, eerr := deps.epicRepo.GetByIDTx(ctx, tx, epic.ID)` (was `GetByID(ctx, epic.ID)` in round 2)

The interface now structurally requires a `*sql.Tx` handle for the re-fetch — Codex's exact U-01 complaint is now impossible to repeat without changing the interface.

**Evidence — concurrent-cascade test exists and asserts exactly one history row:**
- `cascade_reopen_test.go:1620` — `TestCascade_ConcurrentCascadeOnSameAncestorWritesExactlyOneHistoryRow`
- Two goroutines fire `cascadeParentReopens` simultaneously against the same `featureID=500`. The first cascade's `GetByIDTxFunc` returns `"completed"` (terminal → proceeds to write); the second cascade's `GetByIDTxFunc` returns `"in_qa"` (non-terminal — simulating that the first has already committed → idempotent skip).
- A shared `mockEntityHistoryTxRecorder` with a mutex counts the number of feature rows written.
- Final assertion at `cascade_reopen_test.go:1721`: `if featureRows != 1 { t.Errorf(...) }` — proves the in-tx re-fetch path that gates the duplicate write is exercised.
- Test passed in this run.

**Honest caveat (already disclosed in the test's own godoc, lines 1614–1619):** Because `*sql.Tx` cannot be constructed in unit tests, the "concurrency" is simulated at the mock level by giving each cascade a different in-tx status. This proves the *code path* that prevents the duplicate write executes, but it does not exercise actual SQLite locking. End-to-end concurrency proof would require an integration test against the real test DB. For a unit-level guarantee of the in-tx re-fetch contract, this is appropriate; the structural contract (`*sql.Tx` parameter) prevents the round-2 mistake regardless of test fidelity. **Acceptable.**

### U-03 (HIGH) — Commit_failure test exercises the commit path — **RESOLVED**

**Spec contract (REQ-N-006):** *"All error paths (BeginTx failure, history-lookup error, repository update failure, **commit failure**) MUST have explicit unit tests."*

**Evidence — production cascade exposes a test seam without altering production behavior:**
- `cascade_reopen.go:125-135` — `cascadeDeps.commitFn func(tx *sql.Tx) error` field added with a doc comment that explicitly says *"Production callers leave this nil; tests may set it to intercept the commit path."*
- `cascade_reopen.go:368-384` — commit dispatch:
  ```go
  if deps.commitFn != nil {
      if cerr := deps.commitFn(tx); cerr != nil {
          slog.Warn("cascade: commit failed", ...)
          return
      }
  } else if tx != nil {
      if cerr := tx.Commit(); cerr != nil {
          slog.Warn("cascade: commit failed", ...)
          return
      }
  }
  ```
  Production wiring leaves `commitFn` nil, so the existing `tx.Commit()` path is preserved (lines 376–383). Tests inject a non-nil `commitFn` to drive the warn branch directly.

**Evidence — Commit_failure test actually invokes the commit hook:**
- `cascade_reopen_test.go:1285-1354`:
  - Line 1299: `commitCalled := false`
  - Line 1327-1330: `commitFn: func(_ *sql.Tx) error { commitCalled = true; return commitErr }`
  - Line 1339: `cascadeParentReopens(ctx, deps, trigger)`
  - Line 1342-1344: `if !commitCalled { t.Error("expected commitFn to be called (commit path not exercised)") }` — direct assertion that the commit hook fired.
  - Lines 1348-1353: assertions that both `featureRepo.updateStatusTxCalls` and `epicRepo.updateStatusTxCalls` are exactly 1, proving the cascade reached the post-update commit branch.
- Runtime confirmation: `WARN cascade: commit failed trigger_key=E07-F01-003 error="simulated commit failure"` appears in the verbose test output, proving the warn branch executed.

**Production path is unchanged:** The `else if tx != nil` branch still calls `tx.Commit()` directly when `commitFn` is nil. No production wiring change is implied — `task_service.go` and `feature_service.go` will continue to construct `cascadeDeps` without ever setting `commitFn`. The seam is purely additive for testability, which matches the cleanest of the three remedies the UAT report suggested. **Resolved.**
