# Task: Refactor renderFeatureDetails to use RenderEntity with callbacks

## Goal

Rewrite `renderFeatureDetails()` in `feature_helpers.go` to use the unified `RenderEntity()` function from `render_common.go` with a `RenderSpecific` callback for feature-specific display sections. This matches the reference implementation in `runTaskGet` (`task.go:106`). Currently, `renderFeatureDetails()` is a monolithic function with 12 parameters that does not use `RenderEntity()` and is missing features like valid transitions display.

## Requirements

### Functional Requirements

- [ ] `renderFeatureDetails()` (line 356 in `feature_helpers.go`) is rewritten to call `RenderEntity()` from `render_common.go`
- [ ] Feature-specific sections (task breakdown, progress, action items) are implemented as a `RenderSpecific` callback
- [ ] Valid transitions are displayed (currently missing from feature get output)
- [ ] `renderFeaturePlanning` is also refactored to use `RenderEntity()` or a similar unified approach
- [ ] The `runFeatureGet` call site in `feature.go:222` is updated to use the new rendering approach
- [ ] Output is visually equivalent to current output (plus the addition of valid transitions)

### Non-Functional Requirements

- [ ] Code duplication between feature rendering and the common render functions is eliminated
- [ ] The feature rendering follows the same architectural pattern as task rendering
- [ ] No regression in existing feature get display

## Implementation Plan

### Steps

1. [ ] Study the reference implementation: `runTaskGet` in `task.go:106` and how it calls `RenderEntity()`
2. [ ] Study `RenderEntity()` in `render_common.go` to understand the `EntityRenderConfig` struct and callback pattern
3. [ ] Create the `RenderSpecific` callback function for feature-specific sections (task breakdown by status, progress bars, action items requiring attention)
4. [ ] Rewrite `renderFeatureDetails()` to build an `EntityRenderConfig` and call `RenderEntity()`
5. [ ] Similarly refactor `renderFeaturePlanning` to use the unified pattern
6. [ ] Update `runFeatureGet` in `feature.go:222` to call the refactored functions
7. [ ] Test: `shark get E07-F01` should show all existing sections plus valid transitions
8. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- `RenderEntity()` handles common sections: header, status with color, description, dates, notes, context data, related docs, valid transitions, orchestrator action
- The `RenderSpecific` callback renders feature-specific sections:
  - Task breakdown table (tasks grouped by status)
  - Progress display (weighted and completion percentages)
  - Action items (tasks in `blocks_feature: true` statuses)
  - Work remaining summary (by responsibility)
- The existing 12-parameter function signature collapses to a single `EntityRenderConfig` struct
