# Task: Refactor renderEpicDetails to use RenderEntity with callbacks

## Goal

Rewrite `renderEpicDetails()` in `epic_helpers.go` to use the unified `RenderEntity()` function from `render_common.go` with a `RenderSpecific` callback for epic-specific display sections. This matches the reference implementation in `runTaskGet` (`task.go:106`). Currently, `renderEpicDetails()` is a monolithic function with 12 parameters that does not use `RenderEntity()` and is missing features like valid transitions display.

## Requirements

### Functional Requirements

- [ ] `renderEpicDetails()` (line 214 in `epic_helpers.go`) is rewritten to call `RenderEntity()` from `render_common.go`
- [ ] Epic-specific sections (feature status rollup, impediments, feature summaries) are implemented as a `RenderSpecific` callback
- [ ] Valid transitions are displayed (currently missing from epic get output)
- [ ] `renderEpicPlanning` (line 126) is also refactored to use `RenderEntity()` or a similar unified approach
- [ ] The `runEpicGet` call site in `epic.go:206` is updated to use the new rendering approach
- [ ] Output is visually equivalent to current output (plus the addition of valid transitions)

### Non-Functional Requirements

- [ ] Code duplication between epic rendering and the common render functions is eliminated
- [ ] The epic rendering follows the same architectural pattern as task rendering
- [ ] No regression in existing epic get display

## Implementation Plan

### Steps

1. [ ] Study the reference implementation: `runTaskGet` in `task.go:106` and how it calls `RenderEntity()`
2. [ ] Study `RenderEntity()` in `render_common.go` to understand the `EntityRenderConfig` struct and callback pattern
3. [ ] Create the `RenderSpecific` callback function for epic-specific sections (feature status rollup, impediments, feature summaries)
4. [ ] Rewrite `renderEpicDetails()` to build an `EntityRenderConfig` and call `RenderEntity()`
5. [ ] Similarly refactor `renderEpicPlanning` to use the unified pattern
6. [ ] Update `runEpicGet` in `epic.go:206` to call the refactored functions
7. [ ] Test: `shark get E07` should show all existing sections plus valid transitions
8. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- `RenderEntity()` handles common sections: header, status with color, description, dates, notes, context data, related docs, valid transitions, orchestrator action
- The `RenderSpecific` callback renders epic-specific sections that go between the common header and common footer sections
- Epic-specific sections to extract into the callback:
  - Feature status rollup table
  - Impediments list (blocked tasks with age)
  - Feature summary list with progress
- The existing 12-parameter function signature collapses to a single `EntityRenderConfig` struct
