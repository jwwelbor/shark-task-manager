# Task: Extract buildFeatureBasicInfo and feature-specific render callbacks

## Goal

Create a `buildFeatureBasicInfo()` helper function in `feature_helpers.go` that maps feature data into the `BasicEntityInfo` struct used by `RenderEntity()`. Also extract the feature-specific render callback logic into clean, reusable functions. This mirrors the existing `buildTaskBasicInfo` pattern in `task.go:164`.

## Requirements

### Functional Requirements

- [ ] Create `buildFeatureBasicInfo()` function that converts feature display data into `BasicEntityInfo` struct
- [ ] The function maps feature fields: key, title, status, description, created/updated dates, epic key, etc.
- [ ] Extract feature-specific render callback functions from the monolithic `renderFeatureDetails`:
  - Task breakdown table renderer (tasks grouped by status)
  - Progress display renderer (weighted and completion percentages)
  - Action items renderer (tasks in blocking statuses)
  - Work remaining summary renderer (by responsibility)
- [ ] Each extracted callback function has a clear, single responsibility
- [ ] The refactored `renderFeatureDetails` (from T-E07-F32-005) uses these extracted helpers

### Non-Functional Requirements

- [ ] Code is clean, well-documented with godoc comments
- [ ] Functions are testable in isolation
- [ ] Follows the same naming conventions as `buildTaskBasicInfo`

## Implementation Plan

### Steps

1. [ ] Study `buildTaskBasicInfo` in `task.go:164` to understand the pattern
2. [ ] Create `buildFeatureBasicInfo()` in `feature_helpers.go` mapping feature data to `BasicEntityInfo`
3. [ ] Extract task breakdown rendering into a standalone callback function
4. [ ] Extract progress display rendering into a standalone callback function
5. [ ] Extract action items rendering into a standalone callback function
6. [ ] Extract work remaining summary into a standalone callback function
7. [ ] Update the refactored `renderFeatureDetails` to use `buildFeatureBasicInfo()` and the extracted callbacks
8. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- `BasicEntityInfo` is the common struct that `RenderEntity()` uses for the shared header/footer sections
- `buildFeatureBasicInfo()` maps: Key, Title, Status, Description, CreatedAt, UpdatedAt, and any feature-specific fields that `BasicEntityInfo` supports
- Feature-specific fields not in `BasicEntityInfo` (like task counts, progress metrics) are handled by the `RenderSpecific` callback
- Each callback function takes the relevant display data as input and writes formatted output
