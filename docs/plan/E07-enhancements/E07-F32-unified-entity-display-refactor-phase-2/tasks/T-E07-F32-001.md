# Task: Fix: Add related docs fetch to planning mode populate functions

## Goal

Add related document fetching to the planning mode populate functions in `display_service.go`. Currently, `populateEpicPlanningInfo` and `populateFeaturePlanningInfo` do not fetch related documents from `DocumentRepo`, causing planning mode to return empty `RelatedDocs` fields. The aggregation path (`populateEpicAggregationInfo`) already does this correctly and serves as a reference.

## Requirements

### Functional Requirements

- [ ] `populateEpicPlanningInfo` (line ~347 in `display_service.go`) calls `s.deps.DocumentRepo.ListForEpic(ctx, epicID)` to fetch related docs
- [ ] `populateFeaturePlanningInfo` (line ~520 in `display_service.go`) calls `s.deps.DocumentRepo.ListForFeature(ctx, featureID)` to fetch related docs
- [ ] Fetched documents are assigned to the `RelatedDocs` field of the respective display info structs
- [ ] Error handling follows existing patterns (log warning, do not fail the whole request)

### Non-Functional Requirements

- [ ] No performance regression; document fetch is a single DB query
- [ ] Consistent with how `populateEpicAggregationInfo` (line ~506) fetches documents

## Implementation Plan

### Steps

1. [ ] Open `internal/services/display_service.go`
2. [ ] In `populateEpicPlanningInfo` (~line 347), add `s.deps.DocumentRepo.ListForEpic(ctx, epicID)` call and assign result to `info.RelatedDocs`
3. [ ] In `populateFeaturePlanningInfo` (~line 520), add `s.deps.DocumentRepo.ListForFeature(ctx, featureID)` call and assign result to `info.RelatedDocs`
4. [ ] Follow the error handling pattern from `populateEpicAggregationInfo` for consistency
5. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- Reference `populateEpicAggregationInfo` (line ~506) for the exact API call pattern
- The `DocumentRepo` dependency is already wired into the display service via `deps`
- No new dependencies or interfaces needed
