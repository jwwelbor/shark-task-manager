# Task: Fix: Add Notes/ContextData fields to planning mode structs

## Goal

Add note fetching and context data population to the planning mode populate functions in `display_service.go`. Currently, `renderEpicPlanning` and `renderFeaturePlanning` do not display notes or context data because the `EpicDisplayInfo`/`FeatureDisplayInfo` structs have no Notes/ContextData fields populated when in planning mode.

## Requirements

### Functional Requirements

- [ ] `populateEpicPlanningInfo` fetches entity notes via the note repository and assigns to the display info struct
- [ ] `populateEpicPlanningInfo` fetches context data and assigns to the display info struct
- [ ] `populateFeaturePlanningInfo` fetches entity notes via the note repository and assigns to the display info struct
- [ ] `populateFeaturePlanningInfo` fetches context data and assigns to the display info struct
- [ ] Planning mode render functions display notes and context sections when data is present

### Non-Functional Requirements

- [ ] Error handling follows existing patterns (log and continue, do not fail the request)
- [ ] No performance regression; note and context fetches are lightweight DB queries

## Implementation Plan

### Steps

1. [ ] Identify the note repository method used in aggregation mode for epics/features (likely `NoteRepo.ListForEntity`)
2. [ ] Add note fetching to `populateEpicPlanningInfo` in `display_service.go`
3. [ ] Add context data population to `populateEpicPlanningInfo`
4. [ ] Add note fetching to `populateFeaturePlanningInfo` in `display_service.go`
5. [ ] Add context data population to `populateFeaturePlanningInfo`
6. [ ] Verify `renderEpicPlanning` and `renderFeaturePlanning` render the notes/context sections when present
7. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- Follow the same pattern used in the aggregation populate functions for fetching notes and context
- The display info structs likely already have Notes and ContextData fields; they just need to be populated in the planning code path
- If the render functions need updates to display these sections, add them following the aggregation render pattern

## Deliverables
