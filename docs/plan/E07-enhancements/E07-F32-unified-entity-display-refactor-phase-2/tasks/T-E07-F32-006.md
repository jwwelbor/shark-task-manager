# Task: Extract buildEpicBasicInfo and epic-specific render callbacks

## Goal

Create a `buildEpicBasicInfo()` helper function in `epic_helpers.go` that maps epic data into the `BasicEntityInfo` struct used by `RenderEntity()`. Also extract the epic-specific render callback logic into clean, reusable functions. This mirrors the existing `buildTaskBasicInfo` pattern in `task.go:164`.

## Requirements

### Functional Requirements

- [ ] Create `buildEpicBasicInfo()` function that converts `EpicDisplayInfo` (or epic model + display data) into `BasicEntityInfo` struct
- [ ] The function maps epic fields: key, title, status, description, created/updated dates, priority, business value, etc.
- [ ] Extract epic-specific render callback functions from the monolithic `renderEpicDetails`:
  - Feature status rollup renderer
  - Impediments list renderer
  - Feature summary renderer
- [ ] Each extracted callback function has a clear, single responsibility
- [ ] The refactored `renderEpicDetails` (from T-E07-F32-004) uses these extracted helpers

### Non-Functional Requirements

- [ ] Code is clean, well-documented with godoc comments
- [ ] Functions are testable in isolation
- [ ] Follows the same naming conventions as `buildTaskBasicInfo`

## Implementation Plan

### Steps

1. [ ] Study `buildTaskBasicInfo` in `task.go:164` to understand the pattern
2. [ ] Create `buildEpicBasicInfo()` in `epic_helpers.go` mapping epic data to `BasicEntityInfo`
3. [ ] Extract feature status rollup rendering into a standalone callback function
4. [ ] Extract impediments rendering into a standalone callback function
5. [ ] Extract feature summary rendering into a standalone callback function
6. [ ] Update the refactored `renderEpicDetails` to use `buildEpicBasicInfo()` and the extracted callbacks
7. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- `BasicEntityInfo` is the common struct that `RenderEntity()` uses for the shared header/footer sections
- `buildEpicBasicInfo()` maps: Key, Title, Status, Description, CreatedAt, UpdatedAt, and any epic-specific fields that `BasicEntityInfo` supports
- Epic-specific fields not in `BasicEntityInfo` (like business_value, feature counts) are handled by the `RenderSpecific` callback
- Each callback function takes the relevant display data as input and writes to `fmt.Fprintf` or returns strings
