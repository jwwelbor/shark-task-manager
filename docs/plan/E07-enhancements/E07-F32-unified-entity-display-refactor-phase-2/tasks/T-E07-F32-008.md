# Task: Consolidate JSON builders for consistent field output

## Goal

Verify and update the JSON builder functions for epic, feature, and task get commands to ensure all three include a consistent set of fields. Currently, the task JSON builder (`buildTaskGetJSON` in `task.go`) includes fields like `valid_transitions`, `orchestrator_action`, `related_docs`, `notes`, and `context_data` that may be missing from the epic and feature JSON builders.

## Requirements

### Functional Requirements

- [ ] Audit `buildEpicGetJSON` in `epic_helpers.go` for missing fields compared to `buildTaskGetJSON`
- [ ] Audit `buildFeatureGetJSON` in `feature_helpers.go` for missing fields compared to `buildTaskGetJSON`
- [ ] Add `valid_transitions` field to epic and feature JSON output if missing
- [ ] Add `orchestrator_action` field to epic and feature JSON output if missing
- [ ] Add `related_docs` field to epic and feature JSON output if missing
- [ ] Add `notes` field to epic and feature JSON output if missing
- [ ] Add `context_data` field to epic and feature JSON output if missing
- [ ] All three JSON builders produce a consistent base set of fields

### Non-Functional Requirements

- [ ] JSON output is backward-compatible (new fields are additive, no existing fields removed)
- [ ] Field naming is consistent across all entity types (same key names, same structure)
- [ ] Empty arrays/objects used instead of null for missing collections

## Implementation Plan

### Steps

1. [ ] Read `buildTaskGetJSON` in `task.go` and document all fields it includes
2. [ ] Read `buildEpicGetJSON` in `epic_helpers.go` and identify missing fields
3. [ ] Read `buildFeatureGetJSON` in `feature_helpers.go` and identify missing fields
4. [ ] Add missing fields to `buildEpicGetJSON`, sourcing data from the display service or workflow service as needed
5. [ ] Add missing fields to `buildFeatureGetJSON`, sourcing data from the display service or workflow service as needed
6. [ ] Verify JSON output with `shark get E07 --json`, `shark get E07-F01 --json`, `shark get E07-F01-001 --json`
7. [ ] Run `make fmt && make lint && make test`

### Technical Approach

- The consistent base fields across all entity JSON output should be:
  - `key`, `title`, `status`, `description`, `created_at`, `updated_at`
  - `valid_transitions` (array of valid next status strings)
  - `orchestrator_action` (string or null, the action for the current status)
  - `related_docs` (array of related document objects)
  - `notes` (array of entity notes)
  - `context_data` (object/map of context key-value pairs)
- Entity-specific fields remain as-is (e.g., epic has `features`, feature has `tasks`, task has `dependencies`)
- Data for new fields may already be available in the display info structs from the display service; if not, add the necessary fetches
