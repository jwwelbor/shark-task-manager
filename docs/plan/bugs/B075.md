# workflow result application fails after claim lease expires

## Description

Triage source: shark-tool-failure-log.md, Entry 6. Long-running tests or subagent execution exceeded the default claim lease, so shark run --apply-result failed authorization until the entity was re-claimed. Workflow execution needs a reliable heartbeat or lease-safe result application path.

## Expected Behavior

Long-running workflow execution should keep its claim valid or provide a safe,
session-aware way to apply the result after the execution completes.

## Actual Behavior

The default claim lease expires during tests or subagent execution, and
`shark run --apply-result` then fails authorization until the entity is re-claimed.

## Steps to Reproduce

1. Claim an entity and start a long-running workflow execution.
2. Allow the default lease duration to elapse without a heartbeat.
3. Run `shark run <key> --apply-result ... --session <session-id>`.
4. Observe the expired-claim authorization failure.

## Fix Notes

Related workarounds: send `shark heartbeat` during execution or re-claim immediately
before applying the result.
