# admit.sh: TestMain in a writable checkout can hide its own test files before enumerate_tests runs

## Description

Discovered via codex red-team during B053 code review (docs/review/bugs/b053/code-review-20260828-0215-B053.md): bench/scripts/admit.sh's check_p2p_green() calls enumerate_tests(pkg_dir) (static testenum) AFTER run_go_tests() has already executed the package under test in a writable checkout. A malicious or buggy TestMain could delete its own *_test.go files (or otherwise mutate the checkout) and exit 0 before enumerate_tests runs, causing expected = {} for that package -- the "no missing evidence" completeness check would go vacuous with no error surfaced.

This contradicts admit.sh's own documented Evidence-forgeability property (header comments, ~lines 76-84), which the file has been rewritten multiple times to uphold. Confirmed present on main -- B053's fix does not introduce or worsen this; it's a pre-existing, independent gap in the enumerate-after-run ordering.

Suggested fix direction (not verified/designed, needs its own research pass): enumerate tests BEFORE running them (snapshot expected from source before any package code executes), or enumerate from a read-only/pristine checkout separate from the one go test runs against.

Evidence: bench/scripts/admit.sh check_p2p_green() call ordering (run_go_tests before enumerate_tests); header lines ~76-84 (Evidence-forgeability property).
