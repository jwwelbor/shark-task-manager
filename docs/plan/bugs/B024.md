# shark create bug silently drops --description and --linked-type/--linked-key flags

## Description

`shark create bug` accepts `--description`, `--linked-type`, and `--linked-key` flags (they appear in `--help` and the help block shows an explicit example using all three), but the values are silently discarded. No warning, no error, no exit code change — the flag value just disappears.

User reports this used to work; this is suspected to be a recent regression.

## Expected Behavior

```bash
shark create bug "Payment fails" --severity=critical \
  --description="Card is declined unexpectedly" \
  --linked-type=feature --linked-key=E07-F01
```

After this command:
- `shark get B###` should show the description (in JSON and/or markdown body)
- The bug should be linked to E07-F01 (queryable via some `shark link`-style command or `shark get E07-F01` showing the linked bug)
- The generated markdown should pre-populate the Description section instead of leaving the `[Describe the bug...]` placeholder

## Actual Behavior

Reproducer (verified 2026-05-11 against this branch's `./bin/shark`):

```bash
$ ./bin/shark create bug "PROBE all-flags-test" --severity=critical \
    --description="DESC_SHOULD_PERSIST" \
    --linked-type=feature --linked-key=E32-F02 --json
{
  "entity_type": "bug",
  "file_path": "docs/plan/bugs/B024.md",
  "file_state": "placeholder",
  "key": "B024",
  "title": "PROBE all-flags-test",
  ...
}
# No description echoed back; no linked_* fields anywhere in response.

$ ./bin/shark get B024 --json
{
  "key": "B024",
  "severity": "critical",   # ← persisted
  "title": "PROBE all-flags-test",
  # description: ABSENT      ← dropped
  # linked_type / linked_key: ABSENT  ← dropped
  ...
}

$ cat docs/plan/bugs/B024.md
---
bug_key: B024
title: PROBE all-flags-test
status: draft
severity: critical
slug: probe-all-flags-test
---

# PROBE all-flags-test

## Description

[Describe the bug and how to reproduce it]    # ← placeholder, not the --description value
...
```

`--severity` does persist correctly; `--description` and `--linked-type`/`--linked-key` do not.

## Steps to Reproduce

1. `./bin/shark create bug "x" --severity=low --description="should appear" --linked-type=feature --linked-key=<any-feature> --json`
2. `./bin/shark get <returned-key> --json` — observe no `description` or `linked_*` fields
3. `cat docs/plan/bugs/<returned-key>.md` — observe placeholder Description text instead of the flag value

## Fix Notes

- Likely in the `internal/cli/commands/` bug create handler — the flags are wired into Cobra but not passed through to the service/repository layer.
- Should verify whether the schema has columns to hold them; if so, fix the wiring. If not, the flags shouldn't be advertised in `--help` until the columns exist.
- Also check `shark create epic` for similar drift on description (verified working as of 2026-05-11) and `shark create feature` (verified working).
