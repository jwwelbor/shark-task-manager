# B054 Research Report: FindProjectRoot Escapes Intended Project

## Scope

**Problem Statement:** `findProjectRootFrom()` in `internal/cli/root.go` (lines 296–338) accepts ANY directory with a `.git` name as a valid project marker, with zero validation that it is an actual git repository. A stray empty `/tmp/.git` directory causes scratch projects initialized under `/tmp` to resolve their project root to `/tmp` instead of their intended scratch directory, resulting in `shark-tasks.db` being written outside the scratch project.

**Affected Surface:**
- All scratch-based workflows (E40 bench harness, `scripts/shark-scratch-env.sh`)
- Any shark invocation from a subdirectory under `/tmp` when a stray `/tmp/.git` exists
- CLI commands that rely on `FindProjectRoot()` → `findProjectRootFrom()`
- The thin wrapper in `internal/filepath/filepath.go` delegates to the same function

**Symptom:** `shark admin init` or any command resolves to `/tmp` as project root; database/config searches start from `/tmp` instead of the scratch directory.

**Impact Severity:** HIGH
- Data isolation violation (concurrent scratch projects share a `/tmp/shark-tasks.db`)
- Bench harness isolation (E40-F02 test failures)
- Silent data loss (new scratch projects overwrite shared DB or discover unintended database state)
- Cross-machine vulnerability (if `/tmp` persists across runs)

## Research Checklist

- [x] `scope_vocabulary` — Evidence: The bug report specifies priority order (.sharkconfig.json > shark-tasks.db > .git) and the exact validation gap: `.git` is checked via `os.Stat()` (line 312 in root.go) with zero verification of its contents.

- [x] `affected_implementation_or_contract` — Evidence: Two code paths must be fixed: (1) `findProjectRootFrom()` at lines 296–338 in `internal/cli/root.go` sets `foundGit = currentDir` on ANY `os.Stat(.../.git) == nil`; (2) `FindProjectRoot()` at line 275 delegates directly to `findProjectRootFrom()`. The `internal/filepath/filepath.go` FindProjectRoot (line 91) is a thin delegate to the same CLI version — one canonical implementation confirmed.

- [x] `pattern_contract` — Evidence: Existing tests in `internal/cli/root_test.go` (lines 183–237) already use a `.git` directory marker in `TestFindProjectRoot_WithGitDir` (line 183) but create it with `os.MkdirAll(gitDir, 0755)` — an empty directory, never validated to contain `HEAD` or `objects/`. The test itself includes a guard (lines 184–195) to skip if `/tmp` already has markers, proving the author knew this was a risk. This guard suggests the test harness has experienced real pollution from stray markers in system temp.

- [x] `dependency_impact` — Evidence: The `.git` fallback is documented in the function's comment (line 287) and prioritized last, so fixing it will not break the priority order if markers are real. However, legitimate git worktrees use `.git` as a FILE (not directory) containing a `gitdir:` pointer to the real `.git` directory. This is a crucial edge case: `os.Stat()` succeeds on both files and directories, so the current code treats worktree `.git` files identically to directories. A fix that requires `.git` to be a directory and contain `HEAD` or `objects/` would silently ignore valid worktree `.git` files. This is a breaking change that must be handled explicitly.

- [x] `cross_boundary_risks` — Evidence: (1) `shark-scratch-env.sh` (line 42) already mitigates this by passing `--db "$scratch_dir/shark-tasks.db"` explicitly to `admin init`. This means the bug is known and the workaround is in production. (2) `run-lifecycle.sh` (line 472 in bench/scripts) invokes `shark next` from within a scratch directory without explicit `--db`/`--config` flags, relying on auto-detection. If the lifecycle runner runs under `/tmp` and a stray `.git` exists, it will fail silently. (3) Tests in `root_test.go` use t.TempDir() which avoids `/tmp`, so they don't naturally reproduce the bug. The guard at line 188 confirms test pollution is a known concern. (4) The bench fixture (run-batch.sh) does not pass explicit `--db` to its dispatched `run-one.sh` commands, creating a gap.

- [x] `alternatives` — Evidence: **Fix A (Minimal — Recommended):** Validate `.git` marker: require it to contain either `HEAD` (regular repo) or `objects/` (bare repo) before accepting it as a valid project marker. This rejects stray empty `.git` directories while accepting legitimate git repos. Git worktrees (which have `.git` as a file) require special handling: `os.Stat()` returns os.FileInfo for both files and directories; if `.git` is a file, it is a worktree pointer, which should also be accepted (it points to a real repo elsewhere). Implementation: `stat, err := os.Stat(gitPath); if err == nil && stat.IsDir() { check for HEAD or objects } else if err == nil && !stat.IsDir() { accept as worktree }`. **Fix B (Defense-in-Depth — Optional Backstop):** After resolving a `.git` marker, additionally refuse roots that are system temp directories (`/tmp`, `/var/tmp`, `os.TempDir()`) unless `--db` or `--config` is explicitly set. This prevents even a valid (non-stray) `.git` in a temp directory from becoming the project root. Trade-off: this risks rejecting a legitimate project intentionally living under `/tmp` (e.g., a test fixture that creates a real git repo there). For this project's use cases (section §3 below), the risk is acceptable because: (a) legitimate projects have `.sharkconfig.json` or `shark-tasks.db` markers anyway (priority order still applies), (b) only auto-detection fallback to `.git` is affected, and (c) `--db`/`--config` explicitly opt-out any such project.

## Findings

### 1. Current Behavior: Vulnerable Priority Order

The priority order in `findProjectRootFrom()` is correct *in principle*:
1. `.sharkconfig.json` (highest)
2. `shark-tasks.db`
3. `.git` (lowest fallback)

**However**, the `.git` check has NO validation:
```go
if foundGit == "" {
    if _, err := os.Stat(filepath.Join(currentDir, ".git")); err == nil {
        foundGit = currentDir  // Line 313: accepted unconditionally
    }
}
```

This accepts:
- Empty `.git` directories (stray markers)
- `.git` files (git worktrees — legitimate but rare)
- `.git` with any contents (valid or corrupt)

### 2. Test Coverage Confirms Risk

Test `TestFindProjectRoot_WithGitDir` (lines 183–237 in root_test.go):
- Creates an empty `.git` directory
- Includes a guard skipping the test if `/tmp` already has markers (lines 184–195)
- This guard proves the author was aware of pollution risk

This is the only `.git` test. It does NOT test:
- Detection of stray `.git` outside the project
- Behavior when both `.git` and `.sharkconfig.json` are present
- Worktree `.git` files vs directories

### 3. Real-World Impact Confirmed

**shark-scratch-env.sh (line 42):**
```bash
"$binary" admin init --non-interactive --db "$scratch_dir/shark-tasks.db" >&2
```
Explicitly passes `--db` to avoid this exact bug. Comments confirm it:
> "Project-root auto-detection can otherwise discover a stray /tmp/shark-tasks.db shared by concurrent harness runs"

**run-lifecycle.sh (line 472):**
```python
response = run_command(shark, ["next", requested, "--json", "--prompt-out", str(prompt_path)], scratch)
```
Does NOT pass `--db` or `--config`. Relies entirely on auto-detection from within `scratch` directory.

**Implication:** If run-lifecycle.sh executes under `/tmp` and a `.git` stray exists, `shark next` resolves `/tmp` as project root, not the scratch directory. This breaks the E40 bench harness isolation contract.

### 4. Git Worktree Edge Case

A legitimate git worktree is a checkout stored in a separate directory from `.git`. The `.git` marker is a FILE, not a directory:
```
my-worktree/.git  (FILE containing "gitdir: /path/to/.git/worktrees/my-worktree")
```

Current code:
```go
if _, err := os.Stat(filepath.Join(currentDir, ".git")); err == nil {
    foundGit = currentDir
}
```

`os.Stat()` succeeds on both files and directories. This means `.git` files (worktrees) are accepted, which is good for legitimate cases. However, the lack of validation means a symlink to anywhere (`/tmp/.git → /dev/null`, etc.) would also be accepted.

### 5. Proposed Fix: Dual-Layer Validation

**Layer 1: Validate `.git` is a real repository marker**

```go
if foundGit == "" {
    gitPath := filepath.Join(currentDir, ".git")
    stat, err := os.Stat(gitPath)
    if err == nil {
        // .git exists; check if it's a directory (normal repo) or file (worktree)
        if stat.IsDir() {
            // Normal repo: require HEAD or objects/ subdirectory
            if isValidGitDir(gitPath) {
                foundGit = currentDir
            }
        } else {
            // File (worktree pointer): accept as valid marker
            foundGit = currentDir
        }
    }
}

func isValidGitDir(gitPath string) bool {
    // Check for HEAD (all repos have this)
    if _, err := os.Stat(filepath.Join(gitPath, "HEAD")); err == nil {
        return true
    }
    // Check for objects/ (required in all repos, even bare ones)
    if _, err := os.Stat(filepath.Join(gitPath, "objects")); err == nil {
        return true
    }
    return false
}
```

**Rationale:**
- Rejects stray empty `.git` directories
- Accepts regular repos (have `HEAD` and `objects/`)
- Accepts bare repos (have only `objects/`)
- Accepts worktrees (`.git` is a file, not a directory)
- Minimal code, no external dependencies

**Test cases required:**
```
1. Empty .git directory        → rejected
2. .git directory + HEAD       → accepted
3. .git directory + objects/   → accepted
4. .git FILE (worktree)        → accepted
5. .git symlink (bad)          → depends on symlink target
```

**Layer 2 (Optional, Defense-in-Depth): Refuse temp dirs without explicit flags**

After resolving any `.git` marker:
```go
if foundGit != "" {
    // Refuse system temp directory unless explicitly configured
    tempDir := os.TempDir()  // /tmp typically
    if foundGit == tempDir || strings.HasPrefix(foundGit, tempDir + string(os.PathSeparator)) {
        // Project root would be in system temp — likely unintended
        // Only allow if --db or --config explicitly set
        if GlobalConfig.DBPath == "" && GlobalConfig.ConfigFile == "" {
            foundGit = ""  // Ignore this marker
        }
    }
}
```

**Trade-off:** This breaks a legitimate (but rare) case where a project intentionally lives under `/tmp`. For this codebase:
- E40 bench harness: Uses `scripts/shark-scratch-env.sh` which already passes `--db` explicitly
- run-lifecycle.sh: Should pass `--db` or `--config` to scratch directory
- General users: Rarely create permanent projects under `/tmp`

**Recommendation:** Implement Layer 1 (minimal validation) only. Layer 2 is defensive but risks false positives. If run-lifecycle.sh or other scripts need fixes, those are separate from the core bug fix.

### 6. Breaking Changes

**Git Worktree `.git` Files:**
- Current code: `.git` files are accepted (via `os.Stat` succeeding)
- After Layer 1 fix: `.git` files are explicitly accepted (preserved)
- No breaking change

**Bare Git Repositories (`objects/` without `HEAD`):**
- Some git implementations have `HEAD` in a different location
- Layer 1 fix accepts `objects/`, so bare repos are supported
- Low risk; if a case breaks, add another check

**Corrupt Git Directories:**
- Current: Accepted and used as project root (Bug!)
- After fix: Rejected (Correct behavior)
- This is the desired breaking change

## Decisions

### Decision 1: Implement Minimal Fix (Layer 1 Only)

**Recommendation:** YES — implement `isValidGitDir()` validation.

**Rationale:**
1. Closes the reported bug (rejects stray empty `.git` directories)
2. Minimal code footprint (~8 lines)
3. No external dependencies
4. Preserves legitimate git repos and worktrees
5. Existing workaround scripts (shark-scratch-env.sh) already pass `--db`, so they're unaffected
6. run-lifecycle.sh should be fixed separately to pass `--db` explicitly

### Decision 2: Omit Layer 2 (Temp Directory Refusal)

**Recommendation:** NO — do not implement temp directory refusal.

**Rationale:**
1. Layer 1 alone closes the reported bug (the `.git` validation)
2. Layer 2 is defense-in-depth but adds complexity and risk of false positives
3. If run-lifecycle.sh or bench harness needs fixes, those are separate improvements (pass `--db`/`--config` explicitly)
4. The priority order (.sharkconfig.json > shark-tasks.db > .git) means even a valid `.git` under `/tmp` is only a fallback — if a scratch project creates `.sharkconfig.json` or `shark-tasks.db` explicitly, it wins
5. Legitimate projects intentionally living under `/tmp` (though rare) should not be broken

### Decision 3: Add Test Cases

**Recommendation:** YES — expand `TestFindProjectRoot_WithGitDir` and add new tests.

**Test Cases to Add:**
1. **Empty .git directory** (the reported bug) → should be rejected (resolve to startDir or search further up)
2. **Valid .git directory with HEAD** → should be accepted
3. **Valid .git directory with objects/ only** → should be accepted
4. **Stray .git in parent** → should be ignored if better markers exist in child

## Pattern Contract

**Marker Validation Pattern:** Every fallback marker in project-root detection must validate that the marker is legitimate before accepting it as a project root. The pattern applies:

1. `.sharkconfig.json` — Already valid by definition (if file exists, it can be parsed)
2. `shark-tasks.db` — Already valid by definition (SQLite will reject corrupt DBs on connection)
3. `.git` — **GAP:** No validation; just `os.Stat()` check

The fix establishes the pattern: for fallback markers that could be stray/corrupt (`.git`), check internal structure (`HEAD` or `objects/`) before accepting.
