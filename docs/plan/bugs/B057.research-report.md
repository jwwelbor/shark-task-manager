# B057 Research Report: identity_digest formula disagreement

## Scope

**Bug Summary:** `bench/scripts/run-lifecycle.sh` and `bench/scripts/verify-lifecycle-run.sh` compute `candidate.identity_digest` over different sets of fields, causing systematic validation failures across all lifecycle runs.

**Affected Capability:** E40-F08 (lifecycle run record producer) → E40-F09 (lifecycle evaluation) → E40-F10 (operator workflow and baseline reporting)

**Discovery Context:** Found during smoke-lifecycle.sh wiring (E40-F08 operator convenience wrapper) on py-bug-due-date-boundary scenario; the first of five consecutive producer/validator contract mismatches in the same session.

## Findings

### Finding 1: Producer/Validator Formula Mismatch
**Severity:** High  
**Evidence:** Byte-for-byte comparison of the two formulas shows they operate on different field sets.

The producer (run-lifecycle) includes `scratch_content_digest` in the digest computation; the validator (verify-lifecycle) explicitly excludes it. This is not a rounding or precision issue—it's a structural disagreement.

**Impact:** Every lifecycle run produced by run-lifecycle is rejected by verify-lifecycle-run. The smoke-lifecycle.sh wrapper cannot progress past the first dry-run without skipping validation.

---

### Finding 2: Spec/Implementation Divergence
**Severity:** Medium  
**Evidence:** 
- E40-F09 spec REQ-F-007 names exactly six identity components.
- E40-F09 ADR-F09-05 references "parent ADR-009 and the I-05 candidate fields" as the source.
- The I-05 candidate fields (from run-lifecycle's original `candidate_identity()` function) are the same 6 components.

**Context:** The spec was written with the 6-field formula in mind. Run-lifecycle was later extended to compute an additional digest (identity_digest v2) that includes scratch_content_digest, but this extension was not reflected in the spec or the validator.

---

### Finding 3: Scratch Content Digest Semantics
**Severity:** Medium  
**Evidence:**
- `scratch_content_digest()` function (run-lifecycle lines 131–150) digests the worker's scratch-project directory contents at stage end.
- It is stored in the candidate dict and used to recompute identity.
- The term "meaningful evidence" in the bug report is apt: it captures the actual state the worker left behind after a stage.

**Assessment:** Scratch_content_digest is valid evidence and should probably be retained in the candidate record. The question is whether it belongs in the identity formula or is a separate field.

**Options:**
1. **Option A (Recommend):** Extend the 6-field identity formula to include scratch_content_digest as a 7th component. Update verify-lifecycle-run, update E40-F09 spec REQ-F-007 to document all 7 components, update contract tests.
2. **Option B:** Keep the 6-field identity formula; modify run-lifecycle to exclude scratch_content_digest from identity recomputation and store it as a separate non-identity field. Cleaner separation of concerns but loses evidence from the identity hash.

---

### Finding 4: Four Prior Mismatches Fixed in the Same Session
**Severity:** Medium  
**Evidence:** Bug report Fix Notes section lists four narrower fixes already committed:
- Schema required `/dispatches[]/response/effort`, `/resolved_via`, `/unresolved_placeholders` but shark marks them `omitempty`.
- Schema required `/workflow_policy/reviewer/effort` but run-lifecycle writes `""`.
- Validator rejected `/limits/first_exceeded` as null despite schema declaring it `nullable_string`.
- Validator unconditionally indexed `/response/resolved_via]` after it became optional.

**Pattern:** These are all producer/validator contract drift bugs—changes in one script without corresponding updates in the other. This bug follows the same pattern.

**Implication:** The identity_digest disagreement is the fifth in a batch of synchronization failures, suggesting the need for a unified contract specification (e.g., schema-driven validation).

---

## Decisions

### Decision 1: Authority and Source of Truth
**Recommendation:** Use E40-F09 spec REQ-F-007 and the contract test (TC-067) as authoritative.

**Rationale:** 
- The spec was written to define the evaluation contract.
- E40-F10 depends on F09's identity semantics.
- The contract test encodes the agreed-upon behavior.
- Run-lifecycle is a producer; it must conform to the spec, not the reverse.

**Action:** Modify run-lifecycle to produce a 6-field identity digest that matches the spec (Option A above, unless Option B is preferred for separation of concerns).

---

### Decision 2: Scratch Content Digest Disposition
**Recommendation:** Include it as a 7th component of the identity formula (Option A).

**Rationale:**
- Scratch_content_digest is meaningful evidence of what the worker produced.
- It should be part of the candidate identity so comparisons account for worker output differences.
- REQ-F-007 can be updated to name all 7 components without breaking upstream constraints.
- This extends the identity formula, not narrows it, so F09's comparison logic naturally supports it.

**Implication:** Verify-lifecycle-run.sh must be updated to compute the identity over all 7 fields, and E40-F09 spec must be updated to document the 7-field formula in REQ-F-007.

---

### Decision 3: Repair Scope
**Recommendation:** Fix both scripts in a single commit to restore synchronization.

**Rationale:**
- The bug is a producer/validator mismatch; fixing only one side leaves validation broken.
- A single commit ensures both are updated consistently.
- Contract tests (TC-067) must pass before the feature can advance.

**Changes required:**
1. Update `verify-lifecycle-run.sh` line 260–264 to include `scratch_content_digest` in the expected identity computation.
2. Update E40-F09 spec REQ-F-007 to list all 7 components.
3. Ensure contract test TC-067 validates the 7-field formula.
4. Verify run-lifecycle output still matches the new expected formula.
