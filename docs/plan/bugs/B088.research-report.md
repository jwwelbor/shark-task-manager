## Findings

**A preference can disqualify a clean pass.** I called the production Python angle and decision validators with a one-file scope, matching candidate identity and a single finding at `example.go:12`. The rule was `NAMING`, severity `nit`, summary “Prefer item to entry” and diagnosis “Both names are allowed”. The angle validator accepted it without an impact. With disposition `report-only` and reason “Either name is permitted”, the decision validator rejected PASS with “clean pass contains an undispositioned finding” and accepted PASS-WITH-TRIAGE. To repeat, pass that finding through `_angle_findings` with the changed file in `reviewed_files`, then through `validate_review_decisions` under both verdicts with the same raw finding and candidate identity. This exercised packet acceptance locally. No reviewer, tracker transition or host edit was needed. The consolidator reserves its compact report for zero Nits as well as zero other findings, yet describes PASS-with-triage in terms of actionable non-blockers. A Nit alone falls between those written verdict rules.

**The rubric generates work independently of a defect.** Consolidator Step 5 and craft Step 11 require five justified scores for each modified file. Applying their thresholds to a dimension averaging 3 generates triage, and 2 generates a blocker, without either rule requiring a failed invariant or affected caller. For ten files the unabridged instruction requests 50 scores. Craft makes an exception below 50 changed lines while the consolidator states no such exception. Omitting the table from the final Markdown leaves the scoring and threshold instructions active. These are source-level reproductions. Actual time, tokens and prevalence in historical reviews were not measured.

**The contract has multiple producers and readers.** All six angle references offer Nit. The native workflow supplies its own JSON schema and validates angle and footer severities. Dispatched angles and the comparable CLI use Python validation, and the CLI constructs its own packet prompt and persists its selected report. Bug, change and shared prompts use the common craft process. Feature includes the craft file directly. The separate craft report skeleton also lists the rubric and hotspots. Changes in only one producer leave another able to emit old findings. At bug review admission and QA replay, Go checks retained decisions and angle evidence, including severity, candidate identity and correspondence with raw findings. Removing Nit from a reader can therefore invalidate previously accepted evidence. Matching uses file, line, rule, summary and diagnosis, so rewriting those fields during consolidation can orphan the original finding.

Bug and dispatched-review instructions send a justified downgrade through host triage. Craft makes this final severity report-only, while triage Step 0 can edit a trivial rename. ## Decisions

Recommend extending the existing contract. Admit an issue when the reviewer can name an affected caller, user, invariant, required standard or maintenance operation, describe the consequence, and cite evidence. For example, two permitted variable names yield no finding. Silently dropping a required audit event identifies both a consumer and an observable loss and merits review even on a one-line diff. Retain blocker and actionable non-blocker severity, relevant risk hotspots, standards crosswalk and compact clean reports. Incomplete coverage must still surface as INCOMPLETE.

A display-only change would hide the preference while the validator still rejects a clean pass. Extending the tiny-diff exception would save scoring only below its cutoff. Removing the scoring trigger and preference admission across producers directly addresses both causes. Keep a candidate-bound reason and explicit disposition for every raw blocker. A later judgment that a finding lacks impact must not silently drop the raw evidence or mislabel an unrefuted assertion as refuted. Recommend an explicit audited no-action disposition for a preference after downgrade, subject to the B085 owner decision. Its acceptance should produce zero host edits and zero tracker filings. This report supplies a diagnosis and recommendation, not owner approval.

Verify the repair with a preference-only input, a real non-blocker, a blocker, an evidence-backed downgrade, incomplete coverage, and replay of an existing retained packet. Exercise native, dispatched and comparable CLI paths and render all four prompt variants. Verify both verdict and host action, including reuse of a non-blocker's fingerprint after a line shift. Define how new packets identify the revised contract before enforcing stricter reader rules. Keep historical hashes and accepted packets intact.
