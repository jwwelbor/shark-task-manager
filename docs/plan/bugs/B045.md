# Embedded Shark sprint skills ship stale planning and retrospective guidance

## Description

The embedded Shark sprint bundle under `internal/sharkdata/default_data` has
drifted from the maintained Rider workflows. The embedded sprint-planning
workflow still uses the invalid `/shark-rider query: get` command and omits the
owner-ratified requirement that one sprint deliver one coherent, demoable
increment. Earlier review evidence also found stale sprint-execution and
sprint-analytics guidance, including an incorrect retrospective buffer
calculation.

This bug owns the embedded Shark source and distribution regression coverage.
Extracted project copies such as WWGM's `shark-data/` tree are deployment
outputs and should be refreshed by redeploying the corrected Shark bundle.

## Expected Behavior

The embedded sprint skill bundle under
`internal/sharkdata/default_data/skills/` should carry the maintained Rider
behavior for sprint-planning, sprint-execution, and sprint-analytics. Fresh
deployments should receive valid Shark commands, the owner-ratified coherent
sprint guidance, and the correct retrospective recommendation formulas.

## Actual Behavior

The embedded bundle has drifted. In addition to the older analytics and
execution differences, its sprint-planning workflow still contains
`/shark-rider query: get` and ends before the coherent/demoable-increment rules
present in `skills/shark-rider/skills/sprint-planning/workflows/plan-sprint.md`.
Freshly extracted project content therefore ships stale instructions.

## Steps to Reproduce

1. Compare
   `internal/sharkdata/default_data/skills/sprint-planning/workflows/plan-sprint.md`
   with `skills/shark-rider/skills/sprint-planning/workflows/plan-sprint.md`.
2. Observe the invalid query command and missing owner-ratified section in the
   embedded copy.
3. Compare the corresponding sprint-execution and sprint-analytics workflows,
   including the retrospective `buffer_pct` recommendation formula.
