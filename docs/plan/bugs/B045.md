# Embedded sprint skills drift from repo copies and ship incorrect retro guidance

## Description

2026-07-09 sprint review follow-up: embedded sprint-planning/execution/analytics skill files still differ from the repo copies under skills/shark/skills. Verified with diff -ru. The embedded retro-sprint workflow still computes buffer_pct from inverse completion rate instead of carryover/planned, and the embedded skill text still references older slash-command forms and stale wording. Fresh installs therefore receive different sprint guidance than the repo copy. Evidence: internal/sharkdata/default_data/skills/sprint-analytics/workflows/retro-sprint.md vs skills/shark/skills/sprint-analytics/workflows/retro-sprint.md, plus matching drift in sprint-planning and sprint-execution skill trees.

## Expected Behavior

The embedded sprint skill bundle under
`internal/sharkdata/default_data/skills/` should match the maintained repo
copies under `skills/shark/skills/` for sprint-planning, sprint-execution, and
sprint-analytics. Fresh installs should receive the same slash-command wording,
workflow guidance, and retro recommendation formulas that the repo copy
documents.

## Actual Behavior

The embedded bundle has drifted. The sprint analytics workflow still uses the
older inverse-completion formula for `buffer_pct`, and the embedded skill text
still carries older slash-command forms and wording that no longer match the
repo copy. Users who rely on embedded content therefore get different sprint
instructions than contributors reading the checked-in skills.

## Steps to Reproduce

1. Compare the repo skill trees under `skills/shark/skills/sprint-*` with the
   embedded copies under `internal/sharkdata/default_data/skills/sprint-*`.
2. Inspect `retro-sprint.md` in both locations and compare the `buffer_pct`
   recommendation formula.
3. Inspect the corresponding `SKILL.md` and workflow files for sprint-planning
   and sprint-execution and note the stale slash-command references and wording
   drift in the embedded copies.
