## Diagnosis and repair boundary

At the original baseline, switching harnesses could drop the requested model or forward an incompatible pin. E40-F13's routing profile had no production materialization caller. A later repair required a second account catalog, preventing an advertised route from reaching execution. At the delivered candidate, both profile and explicit-workflow paths materialize the route and can reach the executable. Its adapter asks for JSONL but searches for Copilot messages or generic wrappers. On a successful Codex stream it selects the trailing turn usage object and misses the preceding completed agent message. The controller receives an adapter error and persists it. The earlier test adapter manufactured both the requested tuple and the result, masking the defect. [Original capture, parent checkout](/home/jwwel/projects/shark-task-manager/docs/plan/bugs/B083.md) · [Independent review F1–F15](../../review/bugs/b083/code-review-20261124T020915Z-B083.md)

**Which stages need a route.** The benchmark accepts a workflow or a profile for selected families. Both readers and both writers use E40’s `_route_action_mapping`, which recognizes only the authored verb `spawn_agent`. The existing integration fixture builds its expected stages with the same literal. Meanwhile, keyed Shark trims the resolved verb and uses the populated agent to decide whether that status starts a worker. The materializer can therefore produce internally consistent route data for an incomplete set. A post-write digest can include an untouched Sonnet pin and still agree with disk. Use a single E40 action-mapping predicate for *potential worker dispatches* across route discovery, catalog selection, validation and writes. Read the fields Shark actually loads in each supported layout. In `steps` the agent is `agent`. In nested legacy `status_metadata.*.orchestrator_action` it is `agent_type`. Preserve existing flat mappings accepted by E40. Include a literal spawn, a resume check, an advance with a populated agent, and an empty verb when a populated action supplies an agent. In a step with an empty verb the loader needs a prompt to construct that action. Respect terminal stages and container actions. Route the final returned worker after an automatic advance, cascade or fork. Transient claim and question pauses suppress a particular dispatch without removing the configured worker stage from static coverage. Keep native Shark’s action semantics and stage transitions. Effort can change at six sites. The workflow reader `_live_stage_effort` and materializer `_resolve_route` fold pins before catalog lookup. Shark’s `ToPopulatedAction` normalizes the value before the keyed response. The adapter’s `_codex_route` folds it again. Keep provider-specific validation and exact catalog values through all six sites, including comparisons with configured exec overrides. A differently cased override is a conflict even when a case-insensitive comparison would accept it. Resolving an omitted effort and comparing an explicit pin are separate operations.
