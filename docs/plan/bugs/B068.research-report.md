# B068 Research Report — stable-fingerprint requirement never implemented

## Scope

Verify whether B066/B067's fixes to the review-triage pipeline satisfied
the review-triage-and-agent-attention-plan's Workstream 1 requirement for
a stable per-finding fingerprint, and if not, implement it across the
canonical producers and the triage skill's dedup step.

## Research checklist

- [x] `scope_vocabulary` — Evidence: dev-artifacts/2026-09-15-review-triage-and-agent-attention-plan/plan.md (Workstream 1: "Each item should include a stable fingerprint...")

## Findings

`grep -rn fingerprint` across `internal/sharkdata/default_data/skills/quality/workflows/review-code.md`,
`internal/sharkdata/default_data/agents/tech-lead.md`, and
`skills/shark-rider/skills/deep-review/references/consolidator.md` returned
zero matches before this fix. The plan's own acceptance criterion
("Repeated reviews link by stable fingerprint instead of creating
duplicates") and completion-evidence item were both unmet. B066 and B067
each closed a different, real gap (direct-to-tech-debt mapping; a missed
sibling file) but neither touched this specific requirement.

A concurrent commit (2566999b, "consolidate triage prose") landed while
this fix was in progress, extracting the previously-duplicated
triage-routing prose into a new "Routing contract" section in
triage/SKILL.md and shortening review-code.md/tech-lead.md/consolidator.md/
deep-review-SKILL.md's own copies to reference it. This is TD-233's own
resolution (already cross-linked during this session's earlier audit
work). The fingerprint fix was rebased on top of that consolidation rather
than the original duplicated-prose structure.

## Decisions

Defined the fingerprint format as `<relative_file_path>#<rule>#<slug>` —
deliberately excludes the raw line number (which drifts between review
rounds) and instead uses inputs that stay stable for the same recurring
defect: the file's repo-relative path, its rule/category, and a short
normalized slug of the defect description. Added computation guidance to
review-code.md (the source-of-truth producer) and mirrored the exact same
format string in consolidator.md so both producers speak the same
fingerprint shape. Extended triage/SKILL.md to search on the fingerprint
first, falling back to the existing broader search when none is present
or no match is found — preserves the existing dedup path for non-review
triage requests, which never carry a fingerprint.
