# shark sprint next ignores active claims and can double-dispatch sprint work

## Description

2026-07-09 sprint review follow-up: internal/services/sprint_service.go:GetNextTask still pulls non-terminal sprint backlog items and sorts them without consulting claim state, unlike internal/cli/commands/next.go which filters through ClaimService.IsClaimable. Two agents calling 'shark sprint next' can therefore receive the same item from an active sprint. Consider claim-aware filtering or an atomic next-and-claim path. Evidence: internal/services/sprint_service.go:1354-1448; review artifact dev-artifacts/2026-07-07-sprint-review/analysis/sprint-ai-dlc-review.md.

## Expected Behavior

`shark sprint next` should avoid returning a sprint backlog item that is already
held by a live claim. Its behavior should match the regular `shark next` path,
which asks the claim service whether a candidate is claimable before handing it
out. If the sprint surface needs stronger guarantees, the selection path should
atomically lease the returned item instead of requiring a second call.

## Actual Behavior

`SprintService.GetNextTask` lists execution-phase sprint backlog items, removes
only terminal statuses, and sorts the remaining candidates. It never checks
claim state, so two concurrent agents can be told to work the same entity from
an active sprint.

## Steps to Reproduce

1. Put at least one non-terminal entity in an active sprint.
2. Lease that entity through the claim service, or have one agent begin work on
   it.
3. Call `shark sprint next` from another session while the lease is still live.
4. Observe that the same entity can still be returned because the sprint path
   does not consult claimability.

## Fix Notes

- Review artifact: `dev-artifacts/2026-07-07-sprint-review/analysis/sprint-ai-dlc-review.md`
- Relevant code: `internal/services/sprint_service.go` (`GetNextTask`) and
  `internal/cli/commands/next.go` (claim-aware selection reference path)
- Likely fix directions:
  - Filter sprint candidates through `ClaimService.IsClaimable`, or
  - Add an atomic sprint next-and-claim path so the pull and lease happen
    together
