# severity required when creating bug

## Description

`shark bug create "<title>"` requires a `--severity` flag, but the requirement is enforced at the **service layer** rather than the CLI layer. When a user omits `--severity`, they get a confusing "invalid severity" error instead of a clean "missing required flag" error from Cobra. More importantly, requiring severity at *creation* time conflicts with the existing `shark bug triage --severity=<S>` subcommand whose entire purpose is to set severity on an already-reported bug.

The natural lifecycle of a bug report is:

1. **Report** the bug — capture title and (optional) initial classification.
2. **Triage** the bug — set severity, possibly assign an agent, advance to `ready_for_development`.

The `bug triage` command already enforces this:

```go
// internal/cli/commands/bug.go:241-243
bugTriageCmd.Flags().StringVar(&bugSeverity, "severity", "", "Bug severity (required)")
_ = bugTriageCmd.MarkFlagRequired("severity")
```

…but `bug create` does **not**:

```go
// internal/cli/commands/bug.go:205
bugCreateCmd.Flags().StringVar(&bugSeverity, "severity", "", "Bug severity (critical, high, medium, low)")
// no MarkFlagRequired
```

The validation lives in the service layer instead:

```go
// internal/services/bug_service.go:122-124
if !models.ValidBugSeverities[input.Severity] {
    return nil, fmt.Errorf("invalid severity %q: must be one of critical, high, medium, low", input.Severity)
}
```

So an omitted `--severity` produces `invalid severity "": must be one of critical, high, medium, low` rather than `Error: required flag(s) "severity" not set`. Worse, this means the user *must* know the severity at the moment of capture, even if they are still investigating — which contradicts the existence of the dedicated triage subcommand.

## Expected Behavior

`shark bug create` should make `--severity` optional. When omitted, the bug is created with a default severity (e.g., `medium`) and stays at status `draft`. The user (or `bug triage`) sets the real severity later when the bug has been investigated.

If the project decides that severity *must* be specified at creation, then the requirement should at least be enforced at the CLI layer (`MarkFlagRequired("severity")`) so Cobra produces a clean, standard error message rather than the service-layer "invalid severity" surprise.

## Actual Behavior

Omitting `--severity` produces a service-layer validation error:

```
$ shark bug create "API timeout"
Error: failed to create bug: invalid severity "": must be one of critical, high, medium, low
```

…which is technically correct but confusing — it sounds like the user *passed* an invalid value, when in reality they passed nothing at all. And the existence of `bug triage --severity=<S>` makes "severity required at create" feel redundant.

## Steps to Reproduce

1. Build the latest binary: `make build`.
2. Run `./bin/shark bug create "Some new bug"` (no `--severity`).
3. Observe the "invalid severity" error.
4. Compare with `./bin/shark bug triage <key>` (no `--severity`) which produces a clean Cobra `Error: required flag(s) "severity" not set` instead.

## Fix Notes

Two viable approaches.

### Option A (preferred): Make severity optional at create, default to "medium"

This aligns with the triage workflow and matches typical bug-tracker UX (Jira, GitHub Issues default to a middle severity if the reporter does not specify).

Changes:

1. `internal/services/bug_service.go::CreateBug` (around line 122) — when `input.Severity == ""`, default it to `models.BugSeverityMedium` (or similar) before validation. Document the default in the godoc.
2. `internal/cli/commands/bug.go` — leave `--severity` flag unmarked-required (current behaviour) but update the flag help text to mention the default ("Bug severity (critical, high, medium, low; default: medium)").
3. Add a regression test in `internal/services/bug_service_test.go`:
   - `TestBugService_CreateBug_DefaultSeverity_WhenOmitted` — call `CreateBug` with empty `Severity`, expect success and `bug.Severity == "medium"`.
   - Confirm existing tests that pass an explicit severity still pass.
4. Update `docs/cli-reference/bug-commands.md` to document the optional flag and the default.

### Option B: Make severity strictly required at the CLI layer

Smaller change but does not address the workflow concern.

Changes:

1. `internal/cli/commands/bug.go::init()` — add `_ = bugCreateCmd.MarkFlagRequired("severity")` (matches the triage command's pattern at line 243).
2. Service-layer validation stays as-is — it becomes a defence-in-depth check.
3. Test: `TestBugCreateCommand_RequiresSeverity` — invoke create without `--severity`, assert Cobra returns the standard required-flag error.
4. Update `docs/cli-reference/bug-commands.md` to mark the flag as required.

### Recommendation

Option A. The bug title ("severity required when creating bug") reads as a complaint that severity *is* required at create time, not a request to enforce that requirement more cleanly. Option A also makes the `bug triage` command's existence sensible.
