# B050 Research Report: task update --depends-on Flag Wiring

## Scope

Verify the current implementation status of B050: "task update --depends-on flag is registered but unwired (silent no-op)" on the bug-hunt branch. This bug alleges that `shark task update <key> --depends-on <keys>` reports SUCCESS but silently fails to update the tasks.depends_on column in the database.

- [x] scope_vocabulary — Evidence: `docs/plan/bugs/B050.md` (bug description), `internal/cli/commands/task_helpers.go` lines 310-345 (flag parsing), `internal/services/task_dto.go` lines 64-70 (TaskUpdates fields)
- [x] affected_implementation_or_contract — Evidence: `internal/cli/commands/task_helpers.go` lines 314-319 (parseTaskUpdates calling parseDependsOnUpdateFlag), `internal/services/task_service.go` lines 597-605 (UpdateTask applying DependsOn), `internal/cli/commands/task_update_depends_on_test.go` (comprehensive test suite)
- [x] pattern_contract — Evidence: `internal/services/task_service.go` lines 597-605 shows three-way dispatch pattern (ClearDependsOn takes precedence, DependsOn sets when provided, else no-op), matches existing --size pattern in `internal/cli/commands/size_flag_update_test.go`

## Findings

### 1. **Bug is Already Fixed (RESOLVED)**

The alleged bug described in B050 has been fully implemented and wired. The three sites identified in the bug description are all connected:

**Site 1: parseTaskUpdates (CLI Layer)**
- `internal/cli/commands/task_helpers.go` lines 314-319: `parseTaskUpdates` correctly calls `parseDependsOnUpdateFlag(cmd)` and assigns results to `updates.DependsOn` and `updates.ClearDependsOn`
- `internal/cli/commands/task_helpers.go` lines 326-345: `parseDependsOnUpdateFlag` fully implements three-way dispatch:
  - Flag absent → `nil, false, nil` (no-op)
  - Flag empty (`--depends-on=`) → `nil, true, nil` (clear)
  - Flag with keys → `&jsonString, false, nil` (set)

**Site 2: TaskUpdates DTO (Service Input)**
- `internal/services/task_dto.go` lines 64-70: TaskUpdates struct defines both fields:
  ```go
  DependsOn      *string  // Sets JSON-encoded dependency list
  ClearDependsOn bool     // Clears (takes precedence)
  ```

**Site 3: TaskService.UpdateTask (Service Layer)**
- `internal/services/task_service.go` lines 597-605: UpdateTask correctly applies the three-way dispatch to the task model:
  ```go
  if updates.ClearDependsOn {
      task.DependsOn = nil
  } else if updates.DependsOn != nil {
      task.DependsOn = updates.DependsOn
  }
  // else: no-op
  ```

### 2. **Original Root Cause Was Addressed**

The original B050 description pointed to `parseTaskUpdates` having no code block reading the flag. This has been fixed on `main` by commit `91ab8559` ("fix: resolve task and question test debt", PR #164).

- Before: No `parseDependsOnUpdateFlag` function existed; the flag was registered but never read
- After: Full three-way dispatch pattern implemented, mirroring the working --size flag behavior
- Evidence: The wiring was first implemented on branch `fix/B048-task-update-depends-on-noop` (commit `bfd879d1`), but that commit never merged to `main` (`git merge-base --is-ancestor bfd879d1 main` fails). Bug B048 carries a note explicitly warning: "Do not treat this completed status as proof the fix shipped." The equivalent wiring that actually landed on `main` is commit `91ab8559`; core implementation is present in current codebase and the code comments at `task_dto.go:64-70` and `task_service.go:597-605` still reference "B048" as their origin.

- Absent = no-op (flag not changed)
- Empty = clear (set to null/nil)
- Provided = set (value applied)
