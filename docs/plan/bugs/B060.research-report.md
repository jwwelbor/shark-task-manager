# B060 research report

## Scope

Repair the P2P admission evidence boundary in `bench/scripts/admit.sh`. The
gate must retain the static set of in-scope test names before any package under
test executes. A package must not be able to delete its writable `*_test.go`
sources in `TestMain`, exit successfully without calling `m.Run`, and make the
later completeness comparison vacuously pass.

This work is limited to the P2P static-enumeration ordering and its regression
coverage. It does not replace `testenum`, change the corpus schema or the
F2P gate, or introduce a second checkout.

## Findings

1. **The current ordering leaves the expected set forgeable in a writable checkout.** For each package, `check_p2p_green()` calls `run_go_tests()` at `bench/scripts/admit.sh:583-585` before it calls `enumerate_tests(pkg_dir)` at lines 586-587. `run_go_tests()` runs `go test -json` in the checkout (`:331-371`), so package code can mutate the same source directory that `testenum` later reads.

2. **The failure reproduces without a test failure or nonzero exit.** In an isolated Go module, static enumeration first returned `TestEvidenceMustExist`. A `TestMain` then deleted every `*_test.go` file and called `os.Exit(0)` without `m.Run()`. The real `go test -json` invocation exited 0 and emitted no per-test terminal event; static enumeration afterward returned an empty set. With the current ordering, `expected`, `observed`, `missing`, and `failed` are all empty, so `package_clean` at `admit.sh:615` becomes true. This is the documented B060 threat, not a theoretical interaction.

3. **The existing enumerator remains the correct trust anchor, but only for a pre-execution snapshot.** `testenum` deliberately avoids building or executing the target package and explicitly rejects `go test -list` because it executes `TestMain` (`bench/scripts/testenum/main.go:1-24`). Reading static source after untrusted execution breaks that otherwise sound trust boundary.

4. **A per-package swap is insufficient for the stated evidence property.** Moving `enumerate_tests()` immediately above `run_go_tests()` inside the current loop protects a package from its own `TestMain`, but a package executed earlier could still modify a later package's source in the shared writable checkout. Resolve all P2P package directories and snapshot all expected sets before the first P2P test process starts. This remains a two-phase operation over the same checkout; no new checkout capability is needed.

5. **B053 supplies a compatible pattern, not the repair itself.** Its shipped code filters a static expected set with the validated `run_selector` and rejects a selector that selects no static tests. Those operations must occur while building snapshots. The old B053 report's `go test -list` recommendation is superseded by the current code and must not be revived.

## Decisions

1. **Extend `check_p2p_green()` with a snapshot phase.** First call `go_list_packages()`, then for every resolved package calculate `pkg_skip_names`, call `enumerate_tests(pkg_dir)`, apply `filter_expected_by_run_selector()`, and retain the resulting expected set plus package metadata. Do this for every package before calling `run_go_tests()` for any package.

2. **Keep execution and verdict semantics unchanged after snapshotting.** In a second pass, run each package once with the same `run_selector` and package-local skip pattern, derive observed terminal events and failures exactly as today, and compare against the saved expected set. Keep the raw process-exit corroboration and the observed-event failure scan.

3. **Evaluate the existing set-wide zero-match guard before execution.** Its inputs are entirely static after snapshotting. Raising its current diagnostic before P2P test execution avoids an unnecessary mutable-checkout process and retains the B053 behavior.

4. **Add one end-to-end regression to the established admission test surface.** Extend `tc005_admit_rejection_branches_test.sh` (or add a narrowly named sibling registered in `run-all.sh`) using its transient patch pattern. The patch must add a P2P-only `TestMain` that deletes the package's `*_test.go` files and exits 0 without `m.Run`. The unpatched base must pass; the patched invocation must reject as `P2P-red-post-patch` and name missing terminal evidence. Do not mock `check_p2p_green()` or `testenum`.

5. **Treat this as an extension of an existing capability, not new work.** The repair changes the timing of trusted input capture in the existing P2P admission gate. It reuses `testenum`, `run_go_tests()`, corpus fields, checkout provisioning, and the shell regression harness.
