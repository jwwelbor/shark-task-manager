# B078 repair plan — verify the selected document link is absent

`shark related-docs delete <title>` must resolve one parent, remove its uniquely matching link or establish that the link is already absent, then report success. On failure it must return a specific error. A successful invocation preserves the document, its file and every other association.

**Review baseline.** Use `bbf490c6ec2bd597d6f3e6e4cdd93e68ca54fa50` throughout. B078 assignment note 3556, the parent of the first repair commit `932dd5080aaa592e24a427ce1a999ee34603f554`, and the four historical code reviews identify the same commit. Independent reviews confirmed it in Shark notes 3827, 3839 and 3850. Revision 3 at `269a533fccda77b73df84ddf099a5f5a06ab71a3` addressed all nine earlier planning findings. Revision 4 addressed notes 3851–3853, then its independent review found two further coverage gaps: exact change-card alias precedence and mismatched tech-debt key/slug identity. Revision 5 adds distinguishing assertions for both while retaining the original baseline. It requires independent plan review. ## Diagnosis

WWGM recorded two successful deletes of “S010 current continuation” followed by a list that still contained document 563 on T-E10-F02-013. The stored title is shared by 542 on B107. The valid workaround, 564, has a different title and is shared by T013 and T011. Both 542 and 564 point to the existing root file. WWGM decision note 3043 corrects note 3041's claim of removal. On the inspected database the baseline title query returned 542 first. Neither historical delete captured the row it selected. [Intake](B078.md) · [Research report](B078.research-report.md) · [Consumer records](B078.repair-plan-evidence.md#consumer)

The baseline identifies documents by ID and permits duplicate titles at different paths. Its service looks up a title globally, takes the first result without an ordering guarantee and asks the repository to delete that ID on the selected parent. Deleting (task, 452, 542) affects zero links and leaves (task, 452, 563) present. The service also converts all title-query failures to success. The CLI discards unlink errors for five entity types and accepts zero or multiple selectors. The question branch already wraps errors. These are distinct ways the command can acknowledge an unsuccessful request. [Research findings 1–6](B078.research-report.md#findings)

The branch's first repairs and shipped B079 already implement parent-scoped title selection. The association repository still returns success whenever its DELETE executes without an error. An isolated trigger can ignore a delete or restore a deleted row within the same statement. Either leaves the selected link present. This counterexample tests the promised postcondition. The WWGM incident has no evidence of either trigger. [Independent findings F3 and F4](B078.plan-review-r1.md) · [SQLite observations](B078.repair-plan-evidence.md#revision-2)

On the shipped B079 path all seven service accessors can panic while acquiring the database. The process can exit 2 before emitting its JSON error. On a rejected write, the service and command both describe the unlink and parent. Six entity wrappers separately check whether their writable document service was configured. The question route uses the shared service directly. These findings define failure paths the repair must cover. [Revision 2 findings](B078.plan-review-r2.md#open-findings)

The shipped change-card and tech-debt repositories each discard a database error on their key-and-slug fallback. The change-card exact-key path preserves its scan error. A malformed row can therefore appear as a missing parent when the same card is selected by slug. This affects the diagnosis reported to the caller. At the association boundary, shipped `Unlink` validates the entity type and parent ID before using storage and passes the caller’s context to the write. Those existing guarantees apply when adding a transaction. [Revision 3 findings](B078.plan-review-r3.md#open-findings)

## Repair and scope

1. Integrate the shared selector, service wiring, typed entity kinds, public labels, help and contracts delivered in B079 at `c0a66d2fe9295107527a2c00f80933dabaedbca6`. Use the shipped implementations where the branch duplicates them. The B079 merge is a production dependency. The B078 review baseline remains the commit declared above. [Delivered command](https://github.com/jwwelbor/shark-task-manager/blob/c0a66d2fe9295107527a2c00f80933dabaedbca6/internal/cli/commands/related_docs.go) · [Delivered contracts](https://github.com/jwwelbor/shark-task-manager/blob/c0a66d2fe9295107527a2c00f80933dabaedbca6/tests/contracts/b079_research_cli_test.go)
2. After selector validation, acquire the database through the error-returning `cli.GetDB(cmd.Context())` before calling a factory that assumes initialization. The existing accessor caches the result of initialization for the command. On failure return the wrapped cause immediately. On success reuse the registered service wiring and preserve the six direct service configuration guards. [Database accessor](../../../internal/cli/db_global.go)
3. Resolve the parent through its registered service. Match the supplied title exactly against `ListForEntity` for its type and ID. A successful empty match confirms absence at the scoped read. Multiple matches give an ambiguity error before mutation. A unique match supplies the document ID. Keep the existing title argument and service interfaces where possible.
4. Make `EntityDocumentRepository.Unlink` call its existing type and positive-parent-ID validators, in that order, before any storage access. Start one write transaction with `BeginTxContext(ctx)` and pass the caller’s context to `tx.ExecContext` for the parameterized DELETE and to `tx.QueryRowContext` for the subsequent `SELECT EXISTS` on the identical (entity_type, entity_id, document_id) triple. Read after statement triggers have finished, for **every** successful execution. A retained row is a storage failure identifying the intended association. Return success only after absence is verified and the transaction commits. Propagate begin, execution, verification and commit failures with their causes. Roll back an uncommitted transaction on error. If a competing delete removed the selected row first, the same check can establish absence. A separately committed relink after completion is a new operation. [Repository](../../../internal/repository/entitydoc/repository.go) · [Transaction API](../../../internal/repository/dbconn/db.go)
5. At the command boundary distinguish a missing parent from an operational database failure using the returned cause and operation. Preserve the question sentinel and the task lookup's existing not-found forms. In the change-card and tech-debt key-and-slug lookups, translate only a genuine no-row result into the existing not-found error. Return other query and scan failures with their underlying cause. Preserve supported key forms and exact-key lookup order: for change cards, try the canonical `CC-` key first, use the stored compact spelling only after a genuine no-row result, and never fall through after a scan or storage error. For tech debt, require the supplied numeric key and slug to identify the same row. Use neutral lookup context for an operational failure in the shared unlink service. Classify the cause before formatting the public diagnostic. Let the delete command supply the public unlink operation, label and key once. Lower layers contribute the failing step and preserve the original cause. Reconcile repository and service wrapping on the rejected-write path, including the existing B078 task diagnostic and the question handler. Convey the numeric exit through the existing executable convention while retaining the wrapped error. Emit confirmation only on success. [Process exit handling](../../../cmd/shark/main.go) · [Project error conventions](../../../.claude/rules/go/error-handling.md)

The implementation scope is the delete path from each registered CLI selector through its service and repository, plus affected test doubles, documentation and regression contracts. Keep existing add/list behavior, document identity, file contents and link metadata. Use isolated test data. This repair requires no schema migration, path rewrite, new delete syntax, consumer data cleanup, catalog change or provider call.
