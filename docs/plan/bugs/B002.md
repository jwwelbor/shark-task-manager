# Unstable Turso client dependency (v0.0.0 dev commit)

## Description

The `github.com/tursodatabase/libsql-client-go` package is pinned to a pseudo-version
(`v0.0.0-20251219100830-236aa1ff8acc`) because the upstream repository has **never published
a stable release tag**. This violates Go module best practices and makes dependency management
less reliable (no semantic versioning, no stable API guarantees).

## Current State

`go.mod` line 11:
```
github.com/tursodatabase/libsql-client-go v0.0.0-20251219100830-236aa1ff8acc
```

Used in `internal/db/turso_driver.go`:
```go
import _ "github.com/tursodatabase/libsql-client-go/libsql"
```

This side-effect import registers a `"libsql"` SQL driver for Turso Cloud connectivity
(HTTP/WebSocket). `TursoDriver.Connect()` calls `sql.Open("libsql", dsn)`.

## Investigation Findings (2026-03-23)

### libsql-client-go is deprecated

The commit we are using (`236aa1ff8a`, merged 2025-12-19) **is the deprecation commit**.
The README now says:

> This repository is deprecated.
> - For Turso Cloud, use go-libsql which provides better performance and support for
>   embedded replicas.
> - For a Go driver for Turso Database, consider using turso-go.

The library has never had a stable release tag and never will.

### Recommended replacements evaluated

#### Option 1: `github.com/tursodatabase/turso-go` (v0.2.2 available)

- Has proper stable release tags (v0.2.2 as of 2025-10-18)
- Uses `purego` to call a native Rust library (`libturso_go.so`) at runtime
- Registers SQL driver as `"turso"` (not `"libsql"`)
- **Critical limitation**: Only supports local SQLite and in-memory databases
  (`:memory:`, local file paths). Does NOT support Turso Cloud remote connections
  via `libsql://...` URLs.
- Would require changing `sql.Open("libsql", dsn)` → `sql.Open("turso", dsn)`
  AND the DSN format would need investigation since remote URLs aren't documented.

#### Option 2: `github.com/tursodatabase/go-libsql`

- Supports Turso Cloud remote connections (the correct replacement per Turso's own docs)
- Has recent commits (December 2025)
- **Critical limitation**: No stable release tags — also uses a pseudo-version
- Requires CGO (`CGO_ENABLED=1`) — significant build complexity change
- Only supports `linux amd64`, `linux arm64`, `darwin amd64`, `darwin arm64`

### Summary

Both officially-recommended replacements are unsuitable for this project:

| Library | Stable Tags | Turso Cloud | No CGO |
|---------|-------------|-------------|--------|
| `libsql-client-go` (current) | No (deprecated) | Yes | Yes |
| `turso-go` v0.2.2 | Yes | No | Yes |
| `go-libsql` | No | Yes | No (requires CGO) |

We are already on the most recent commit of `libsql-client-go`.

## Fix Status: BLOCKED

A clean fix requires a decision on one of:

1. **Accept `turso-go` v0.2.2** and investigate whether it can actually connect to Turso
   Cloud URLs (undocumented). This is the only option with stable tags.
   - Risk: May not support `libsql://` cloud URLs at all.

2. **Migrate to `go-libsql`** (still unstable, but is the correct functional replacement).
   - Risk: Introduces CGO requirement, constrains supported platforms.
   - Benefit: Actively maintained, correct Turso Cloud client per Turso's recommendation.

3. **Keep current dependency** and accept the pseudo-version until Turso publishes a
   stable tag on either `go-libsql` or another library. Track upstream.

4. **Remove Turso Cloud support** from the codebase since local SQLite is the primary
   use case (all existing tests and usage are SQLite-based). This eliminates the
   unstable dependency entirely.

## Expected Behavior

The Turso Cloud dependency should use a published stable semver tag (e.g., `v1.0.0`).

## Actual Behavior

No stable tag exists for `libsql-client-go`. Both recommended replacements also lack
stable tags (for Turso Cloud connectivity) or introduce CGO requirements.

## Steps to Reproduce

1. Check `go.mod` — line 11 shows `v0.0.0-20251219100830-236aa1ff8acc`
2. Run `curl https://api.github.com/repos/tursodatabase/libsql-client-go/git/refs/tags`
   — returns empty array (no tags ever published)
3. Check the library README — shows deprecation notice

## Fix Notes

Investigation complete as of 2026-03-23. Dependency is already pinned to the newest
available commit of the deprecated library. A true fix requires upstream action or
an architectural decision about Turso Cloud support vs. CGO acceptance.

Recommend Option 4 (remove Turso Cloud dependency) if Turso Cloud is not actively
used in production. Otherwise Option 2 (`go-libsql`) is the correct functional
replacement despite lacking stable tags.
