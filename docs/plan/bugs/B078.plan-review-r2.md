## Open findings

### F1. A second task can lose its link to the target document

Rows 3, 4 and 7 protect the entity type with a bug/task collision and protect the document ID with another document on the target task. Their specified same-type shared document is **564**. The deletion is of **563**. A predicate using only `entity_type` and `document_id` gives the expected result on every specified pair, including the synthetic bug that holds 563.

I compared that predicate with the full three-column predicate using SQLite 3.45.1 and the project DDL. With the four consumer pairs plus `(bug,452,563,specification)`, both deletes removed one row and left identical survivors. Adding `(task,450,563,design)` made the difference observable. The full predicate removed one row. The two-column predicate removed **two**. After correct removal, exact verification returned absent, while verification omitting the parent ID returned present. Either defect can pass the original fixture independently.

Require a same-type, different-ID holder of the **target** in an isolated fixture. After normal deletion and an idempotent retry, assert that its association ID, creation time and link type survive. Retain the existing cross-type and different-document controls. Check mutation and verification independently so dropping any of the three predicates fails. This preserves the existing many-to-many contract. ### F2. A database initialization panic satisfies the numeric exit check

Row 5 exercises lookup, list, write, verification and commit errors after acquisition of a database handle. The seven factories in row 2 can panic on `GetDB` failure before any of those operations or the command's error wrapper runs.

I built `./cmd/shark` from the delivered B079 commit and ran each of the seven valid selectors against a disposable file containing non-SQLite bytes, with `--json` and an isolated project config. **All seven exited 2 with empty stdout.** Stderr began with a database initialization panic and omitted the requested parent key on its diagnostic line. A post-initialization storage-failure test can pass while a consumer receives no parseable response for this database failure.

Cover acquisition failure after successful selector validation. Require the delete handler to return the wrapped cause, the public operation, label and key, and require the executable to exit 2 with its normal diagnostic in each mode. In JSON mode, parse the error from stdout and check `error=true`, the existing `COMMAND_ERROR` code and the contextual message. In human mode, check the diagnostic on stderr. A panic or success confirmation must fail the assertion. This obligation is local to the seven delete routes. ### F3. One unconfigured service cannot establish six independent guards

Row 5 asks for “an unconfigured wrapper.” Epic, feature, task, bug, change-card and tech-debt each implement their own nil guard in `UnlinkDocument`. Each returns `writable document repository not configured` before storage access. The question route calls the generic service directly. Shipped direct unlink tests exercise the epic and feature guards. All seven compiled happy paths use configured services.

Returning nil from the unconfigured task wrapper alone would silently acknowledge the request and pass a representative epic guard test plus all configured CLI checks. Bind the assertion to each of the six wrapper methods, reusing the existing tests. Check the configuration error and absence of storage access at their actual service entry points. ### F4. Repeated unlink context passes the diagnostic assertions

Repair step 4 says to wrap the public operation, label and key once. Historical B078 code review r2 F3 identified repeated unlink context. Parent note 3597 records its removal, and note 3625 requires preserving question context. Rows 2 and 5 check for the presence of the label, key and cause. The shipped service and CLI both add unlink context on rejected writes. For a task, the resulting text contains both `unlink document from task <key>` and `failed to unlink document from task <key>`. The current B078 regression counts only the latter string. Its count is still one.

At the rejected-write boundary, require one occurrence of the operation and parent context while retaining the cause, public label, key and exit status. Include the task and the shared dispatcher, where the public labels `change-card` and `tech-debt` differ from the stored kinds. Preserve the question handler's required wrapping check. This is a gap in proof of a disposition already accepted on B078.
