# shark update verb-first form missing --severity flag

## Description

The unified verb-first form `shark update <key>` does not expose `--severity` (and likely other entity-specific flags). Triggered while updating B030 — `shark update B030 --severity=medium` failed with `unknown flag: --severity`. The entity-first form `shark bug update B030 --severity=medium` worked.

Project convention (recorded in user feedback memory): any flag added to entity-first commands must also be wired into the unified verb-first form.

## Expected Behavior

`shark update <key> --severity=<level>` accepts the flag and updates the entity (auto-detected from key), matching `shark bug update`/`shark td update` behavior.

Same expectation for every other entity-specific update flag — they should be reachable from the verb-first form. Likely candidates beyond `--severity`: `--size`, `--file`, `--tag` (verb-first already has some flags; audit needed).

## Actual Behavior

```
$ ./bin/shark update B030 --severity=medium
Error: unknown flag: --severity
```

`./bin/shark bug update B030 --severity=medium` succeeds.

## Steps to Reproduce

1. Have any bug (e.g., B030) in the system
2. `./bin/shark update B030 --severity=medium` → `unknown flag: --severity`
3. `./bin/shark bug update B030 --severity=medium` → success

## Fix Notes

Audit verb-first `shark update` flag set against the union of `shark <entity> update` flags for every entity that participates in verb-first dispatch (epic, feature, task, bug, change, tech-debt, idea). Wire missing flags through to the auto-detected entity service.

Add a regression test that enumerates every entity update command and asserts every flag is also present on `shark update`.
