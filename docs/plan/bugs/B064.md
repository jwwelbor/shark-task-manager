# E40 lifecycle benchmark cannot capture a provider-backed run

## Description

The shipped E40 F08/F10 caller chain could not produce a complete,
publication-eligible provider-backed baseline. The first failure occurred
before provider execution because `run-lifecycle.sh` streamed adapter requests
on standard input while `lifecycle-worker-adapter.sh` required `--request`.
Subsequent live probes exposed missing lifecycle looping, run-matched evidence,
retention, outcome, timing, deadline, and authority wiring.

## Expected Behavior

The F08 controller and provider-neutral adapter agree on one request transport;
the controller follows the complete Shark workflow through archive; each pair
uses an isolated admitted fixture checkout and produces run-matched I-05/I-07/
I-08 evidence, transcripts, oracle output, and entity history; failed work is
preserved; time and cost partitions reconcile; and an inspected pilot can be
attested and promoted to a publication-eligible F10 baseline.

## Actual Behavior

`run-lifecycle.sh` writes the adapter request to stdin, but
`lifecycle-worker-adapter.sh` exits with usage status 2 because it requires a
`--request` file. The controller then invokes `shark release` without `--json`
and misclassifies its successful human-readable output as another error.

After those first defects were removed, live probes also showed that the
controller stopped after one stage, F10 lacked a production fixture/evidence
caller path, the adapter did not decode Claude structured output or usage,
legacy outcome words escaped the workflow vocabulary, failed pair work was
deleted, transcripts were absent, an in-flight worker could exceed the wall
deadline, I-05 nanoseconds were copied into I-07 seconds, stopped runs were
misdiagnosed as pre-terminal evaluator access, and provider-supplied session
metadata could invalidate the parent-owned claim session.

## Steps to Reproduce

1. Run `e40-benchmark.sh setup` against an isolated output root.
2. Copy the generated scratch template and invoke `run-lifecycle.sh --mode live`
   with `LIFECYCLE_ADAPTER=bench/scripts/lifecycle-worker-adapter.sh`.
3. Inspect the resulting I-07 record: the first dispatch ends in
   `worker_failure` before a provider call, with `--request` named as missing.

## Fix Notes

The repair:

- accepts controller-owned standard-input requests and decodes Claude's
  structured result plus measured usage/cost;
- keeps claim/session and workflow-outcome authority in the parent;
- executes the full dispatch/claim/heartbeat/advance/release loop through
  archive with an in-flight wall deadline;
- provisions a fresh admitted fixture checkout per pair and emits run-matched
  I-05, I-07, I-08, oracle, transcript, and entity-history artifacts;
- preserves failed pair work and preflights retention inputs atomically;
- records I-05 ledgers in nanoseconds but I-07 intervals in seconds; and
- distinguishes a terminal ineligible stop from genuinely pre-terminal
  evaluator access;
- records typed stage-input lineage and a digest-addressable policy for every
  configured review gate, including gates not reached;
- fails publication closed when provider usage or test identity is incomplete;
- includes ignored provider-created files in candidate identity while running
  test discovery in an isolated copy; and
- forwards and binds feature-scenario I-06 replay evidence through F10.

## Verification

The first complete provider-backed pilot, `baseline-bug-003`, proved that the
repaired caller chain could reach a held-back oracle and retain the required
artifact set. A subsequent evidence audit classified that result as
provisional: stage candidate identity lagged worker changes, aggregate API time
was mislabeled as a wall-clock interval, semantic usage fields were fabricated
when unavailable, and review policy was hardcoded instead of observed.

The evidence-integrity rework repairs those defects and their sibling classes.
The repository quality gate, the complete benchmark regression suite, focused
deadline and signal counterfactuals, and a zero-provider operator preflight
pass. A replacement provider-backed pilot must pass offline verification and
operator inspection before this bug is complete.
