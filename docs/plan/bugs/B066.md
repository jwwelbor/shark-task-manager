# Review pipeline bypasses triage and directly converts non-blockers into tech debt

## Description

Shipped review instructions tell the host to file non-blocking findings directly as tech debt. This bypasses Shark Rider triage's required fix-now check, duplicate search, and entity classification, so broken behavior, incomplete accepted scope, and decisions can be mislabeled and deferred. Route every review finding through an explicit disposition: fix now, duplicate/link, bug, task, question/change/decision, or true tech debt; add batch review triage and regression coverage across canonical review prompts, deep-review consolidation, and finish-feature.

## Expected Behavior

Every review finding receives an explicit disposition before a feature ships:

1. Fix it now when it is in scope and reasonably safe to resolve.
2. Search for and link an existing entity when the work is already tracked.
3. Classify new follow-up work by what it is: bug, task, question, change/decision,
   or tech debt.
4. Create tech debt only when the current behavior is correct and the finding is
   a maintainability, performance, or architectural cost that can safely wait.

The review and finish-feature workflows should invoke this policy consistently,
support batching multiple findings, and prevent CI/merge progression while a
finding has no durable disposition.

## Actual Behavior

The canonical review workflow and tech-lead instructions direct the host to file
non-blocking findings as tech debt. The deep-review consolidation and
finish-feature paths do not require the Shark Rider triage decision tree first.
As a result, review severity is treated as entity type and agents can defer
broken behavior or incomplete accepted scope as tech debt without a duplicate
search or fix-now decision.

## Steps to Reproduce

1. Read
   `internal/sharkdata/default_data/skills/quality/workflows/review-code.md`.
2. Observe that `non_blockers_to_triage` directs the host to file findings as
   tech debt and that PASS-with-triage makes the host responsible for creating
   that debt.
3. Read `internal/sharkdata/default_data/agents/tech-lead.md` and the host-side
   deep-review consolidator instructions; observe the same direct mapping.
4. Compare those instructions with
   `skills/shark-rider/skills/triage/SKILL.md`, which requires fix-now,
   duplicate-search, and type-classification gates.
5. Run a review containing a non-blocking functional defect and observe that the
   workflow permits direct tech-debt creation instead of bug classification.

## Fix Notes

Update every canonical producer and host workflow, including finish-feature, to
route findings through one shared review-triage contract. Add prompt/golden and
policy tests proving that no review severity maps directly to an entity type.
Redeploy the generated Shark data bundle after the canonical sources pass.
