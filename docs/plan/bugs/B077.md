# Rider Codex worker launches inherit parent model without verified route mapping

## Description

Observed in WWGM S010 on 2026-10-03: the Codex parent and all six sampled deep-review workers ran gpt-5.6-luna xhigh; sampled native spawn calls omitted model overrides, and the parent also edited application code. Shark inspection metadata separately requested anthropic/sonnet for B101 development and anthropic/opus for B100 review. These are not captured keyed dispatches, so exact request-to-worker causality still needs tracing. Preserve Shark persona, host worker class, provider/model and effort as distinct fields; parent inheritance or an effort-only class is not proof of model selection. Related completed coverage: E38-F09 Codex/Claude adapters, E34-F01 harness rendering, E40-F13 benchmark-only routing. Fingerprint: skills/shark-rider/verbs/run.md#host-worker-routing#unattested-model-inheritance. Owner requested capture only; no runner/config changes.

## Expected Behavior

Keep the Shark persona, host-native worker class, provider/model, and reasoning
effort distinct. Launch through a verified host adapter; retain requested and
effective settings. An unsupported provider/model must be reported, not silently
replaced by the parent's model. Keep keyed `response.prompt` unchanged.

## Actual Behavior

The sampled native Codex review workers all used `gpt-5.6-luna` with `xhigh`
effort. Parent spawn calls had no explicit model selection. The parent also
performed application edits, so it was not merely a mechanical coordinator.
Changing global defaults alone is not evidence that an existing session or its
children changed models.
