# B074 research report

## Scope

B074 covers feature-scoped task listing through `shark list <feature>`, its
`shark task list` delegate, and the JSON contract when the feature has tasks but
all visible tasks are filtered because they are completed. It includes the
repository query, service filtering, CLI delegation, and empty-result
serialization. It does not change the existing default that hides completed
tasks or the meaning of `--all`.

Vocabulary used in this report:

- **source tasks**: tasks returned for the feature before list filters apply.
- **visible tasks**: source tasks remaining after status and other filters.
- **completed filtering**: the default `ShowAll == false` exclusion of tasks
  whose status is `completed`.
- **empty collection**: a JSON array `[]`, distinct from JSON `null`.

## Findings

1. The reported behavior reproduces against the current checkout. `./bin/shark
   list E04-F01 --json` exits successfully and prints `null`. The same query
   with `--all --json` returns a JSON array of six tasks, all with
   `"status": "completed"`. This proves the feature has source tasks and that
   the default filter, not feature lookup, removes every visible row. The
   direct command `./bin/shark task list E04-F01 --json` has the same `null`
   result.

2. The unified dispatcher forwards a feature query to `runTaskList` through
   `runTaskListWithFlags` (`internal/cli/commands/list.go:176-184`). The task
   command passes `FeatureKey` and the `ShowAll` flag to the service, then
   serializes the returned slice directly with `cli.OutputJSON`
   (`internal/cli/commands/task.go:127-138`). No feature or repository lookup
   is missing from this path.

3. `TaskRepository.ListByFeatureKey` returns the feature's raw task rows
   (`internal/repository/task/repository.go:607-624`). The defect is in
   `TaskQueryService.ListTasks`: `filtered` is declared as a nil slice at line
   63, completed rows are skipped at lines 79-81 when `ShowAll` is false, and
   the nil slice is returned at line 101. Go's JSON encoder therefore emits
   `null`; a non-nil zero-length slice would emit `[]`.

4. Hiding completed tasks by default is an established contract, not the
   accidental part of this defect. The task-list command help states that
   completed tasks are hidden unless `--all` is used (`internal/cli/commands/task.go:68-70`),
   the unified dispatcher forwards `--all` (`internal/cli/commands/list.go:69-91`),
   and the existing filter tests cover both all-completed default filtering and
   all-completed `--show-all` visibility (`internal/cli/commands/task_list_filter_test.go:63-83`).

5. The repository has an established empty-collection convention. Epic JSON
   listing explicitly returns `results: []` and `count: 0` when no rows exist
   (`internal/cli/commands/epic.go:227-239`), and the idea service has a
   regression test requiring a non-nil empty slice when its repository returns
   nil (`internal/services/idea_service_test.go:524-545`). B074 should apply
   the same machine-readable distinction to task listing without changing
   filtering semantics.

6. TD-236 is directly related work: it records the sibling human-readable
   problem that an all-completed feature prints `No results found` without
   explaining that `--all` is required (`docs/plan/tech-debt/TD-236.md:9-21`).
   B074 is the JSON shape portion of the same completed-task discoverability
   problem. The repair should coordinate with that item rather than duplicate
   its planned terminal-output hint.

7. Targeted existing tests pass: `go test ./internal/services -run
   'TestTaskService_ListTasks|TestIdeaService_ListIdeas_ReturnsEmptySlice'`
   and `go test ./internal/cli/commands -run 'TestTaskListFiltering'` both
   pass. These tests confirm the current completed-task filter and the local
   non-nil-empty-slice convention, but neither asserts B074's JSON `null` to
   `[]` contract.

## Decisions

1. Repair B074 by extending the existing task-list capability at the service
   result boundary: initialize the filtered task slice as a non-nil empty
   slice, and add regression coverage proving an all-completed feature returns
   `[]` in JSON while `--all` still returns the completed tasks.

2. Keep completed tasks hidden by default. The current `--all` workaround is
   an intentional contract used by the task command and unified dispatcher;
   changing that behavior would be a separate product decision and would
   broaden B074 beyond the observed serialization defect.

3. Treat this as an extension of an existing capability, not new task-listing
   or persistence work. No repository schema, feature lookup, workflow status,
   or new API endpoint is needed. The implementation should also be reviewed
   alongside TD-236 so human and machine output explain the same filtered
   state consistently.
