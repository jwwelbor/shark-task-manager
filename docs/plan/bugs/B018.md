# entity_notes / entity_relationships / entity_tags CHECK constraints exclude idea and tech_debt

## Description

Four entity-type CHECK constraints across three polymorphic-association tables were not extended when E25 added the tech-debt entity type, and three of them were also not extended when E08 added the idea entity type. Notes, relationships, and tags fail with SQLite CHECK errors when used on TD-### (and partly on idea) entities.

## Expected Behavior

`shark create note`, `shark <entity> link`/`unlink` (entity_relationships), and `shark <entity> tag add` work for every first-class entity type the system supports — including `idea` and `tech_debt`.

## Actual Behavior

Operations on the affected entities fail at the database layer with `SQLite error: CHECK constraint failed: entity_type IN (...)`.

## Steps to Reproduce

1. `shark create note TD-050 "test" --type=reference`
2. Observe: `failed to add note: failed to create note: failed to create entity note: failed to execute SQL: SQLite error: CHECK constraint failed: entity_type IN ('epic', 'feature', 'task', 'bug', 'change')`

## Affected Constraints

In `internal/db/db.go`:

| # | Table.column | Approx line | Current allowlist | Missing |
|---|---|---|---|---|
| 1 | `entity_notes.entity_type` | 2277 | epic, feature, task, bug, change | idea, tech_debt |
| 2 | `entity_relationships.from_entity_type` | 2996 | epic, feature, task, bug, change | idea, tech_debt |
| 3 | `entity_relationships.to_entity_type` | 3000 | epic, feature, task, bug, change | idea, tech_debt |
| 4 | `entity_tags.entity_type` | 3323 | epic, feature, task, bug, change, idea | tech_debt |

`bugs.linked_entity_type` has no CHECK and validates at the app layer — works as the precedent for fix-direction (b) below.

The narrower allowlist on `ideas.converted_to_type` (`'epic','feature','task'`) is intentional domain meaning, not an entity-type-allowlist — leave alone.

## Fix Notes

Two fix directions to choose between during refinement:

- **(a) Extend the constraints.** One migration that rebuilds the four CHECKs to include all current first-class types: `epic, feature, task, bug, change, idea, tech_debt`. Conservative, minimal blast radius. Requires bumping `CurrentSchemaVersion`. Same bug recurs the next time someone adds an entity type.
- **(b) Drop the CHECKs and validate in Go.** Polymorphic-association tables (`entity_notes`, `entity_relationships`, `entity_tags`) lose their `entity_type` CHECK; validation moves to a single canonical Go allowlist. Matches `bugs.linked_entity_type` precedent. Matches the recommendation in the E18 tech-feasibility review note (2026-03-03 05:00): *"entity_notes CHECK constraint migration recommended (remove constraint, rely on app-layer validation)."* Future-proofs the next entity-type addition.

Either path requires a regression test that creates a note + relationship + tag against TD-### and idea entities.
