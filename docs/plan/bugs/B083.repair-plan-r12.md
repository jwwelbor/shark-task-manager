# B083 repair plan, revision 12

The shipped tech-debt workflow dispatches three worker stages. E40 currently materializes only two. At `in_progress`, a selected Codex profile left the worker on Anthropic/Sonnet, while explicit-workflow validation admitted an unadvertised Codex pin. Independent review reproduced both cases with the setup-owned Shark binary. R12 corrects the stage-selection and verification obligations rejected in finding 4646. It retains R11’s exact-effort, terminal-result, provider accounting and comparison requirements. The earliest invalidated stage was repair planning. Independent review of R12 is due. [R11 review](../../review/bugs/b083/plan-review-r11-f15476a3.md) · [Research](B083.research-report.md) · [Planning evidence](B083.repair-plan-r12-evidence.md#worker-stage-coverage)

## Diagnosis and repair boundary

At the original baseline, switching harnesses could drop the requested model or forward an incompatible pin. E40-F13's routing profile had no production materialization caller. A later repair required a second account catalog, preventing an advertised route from reaching execution. At the delivered candidate, both profile and explicit-workflow paths materialize the route and can reach the executable. Its adapter asks for JSONL but searches for Copilot messages or generic wrappers. On a successful Codex stream it selects the trailing turn usage object and misses the preceding completed agent message. The controller receives an adapter error and persists it. The earlier test adapter manufactured both the requested tuple and the result, masking the defect. [Original capture, parent checkout](/home/jwwel/projects/shark-task-manager/docs/plan/bugs/B083.md) · [Independent review F1–F15](../../review/bugs/b083/code-review-20261124T020915Z-B083.md)

**Which stages need a route.** The benchmark accepts a workflow or a profile for selected families. Both readers and both writers use E40’s `_route_action_mapping`, which recognizes only the authored verb `spawn_agent`. The existing integration fixture builds its expected stages with the same literal. Meanwhile, keyed Shark trims the resolved verb and uses the populated agent to decide whether that status starts a worker. The materializer can therefore produce internally consistent route data for an incomplete set. A post-write digest can include an untouched Sonnet pin and still agree with disk. [E40 collector and writer](../../../bench/scripts/lib/e40_benchmark.py) · [Explicit and profile materializers](../../../bench/scripts/materialize-routing-profile.py) · [Fixture](../../../bench/scripts/tests/lib/b083_production_route_fixture.py) · [Keyed resolver](../../../internal/cli/commands/next.go)

Use a single E40 action-mapping predicate for *potential worker dispatches* across route discovery, catalog selection, validation and writes. Read the fields Shark actually loads in each supported layout. In `steps` the agent is `agent`. In nested legacy `status_metadata.*.orchestrator_action` it is `agent_type`. Preserve existing flat mappings accepted by E40. Include a literal spawn, a resume check, an advance with a populated agent, and an empty verb when a populated action supplies an agent. In a step with an empty verb the loader needs a prompt to construct that action. Respect terminal stages and container actions. Route the final returned worker after an automatic advance, cascade or fork. Transient claim and question pauses suppress a particular dispatch without removing the configured worker stage from static coverage. Keep native Shark’s action semantics and stage transitions. [Loader](../../../internal/config/workflow/steps.go) · [Wire-action contract and controls](../../../internal/cli/commands/next_normalize_test.go)

Effort can change at six sites. The workflow reader `_live_stage_effort` and materializer `_resolve_route` fold pins before catalog lookup. In profile mode `_effective_profile_route` folds the resolved value and `_validate_effective_routes` can then validate the same error. Shark’s `ToPopulatedAction` normalizes the value before the keyed response. The adapter’s `_codex_route` folds it again. Keep provider-specific validation and exact catalog values through all six sites, including comparisons with configured exec overrides. A differently cased override is a conflict even when a case-insensitive comparison would accept it. Resolving an omitted effort and comparing an explicit pin are separate operations. [Research](B083.research-report.md#where-the-advertised-effort-changes)

**Proposed CLI contract.** Add the boolean flag `--benchmark-catalog-effort` to keyed `shark next`, default off. The operator enables it on the setup-owned binary for a materialization containing a validated Codex/OpenAI route, in both resolve-route preview and live execution. Carry the option in invocation-local resolver state through recursion. At action population, retain the original effort from the same entity-scoped action instance that supplies the normalized effort and rendered prompt, for example in an internal field with a read accessor excluded from serialization. At the final wire assignment select the original field only for an opted-in Codex/OpenAI worker dispatch. Preserve the existing public JSON shape, prompt rendering, recursion and native effort validation. The flag selects a representation. E40 remains responsible for catalog validation and dispatch authorization. [Action service](../../../internal/config/action/service.go) · [Keyed resolver](../../../internal/cli/commands/next.go)

Bind preview and live to the frozen catalog and the run-specific materializer result. Carry the source- and pointer-qualified routing records and existing identity digests from batch into both consumers using a run-local artifact. Verify them against the operator identity before use. Identify the expected stage from the *returned* entity family and status in the actual workflow layout. Require one effective route and compare provider, model and effort before recording preview success or starting a worker. Choose the expected route independently of the response’s provider, so a wrong provider cannot disable this check. Use the returned response for the record and adapter request. Re-reading YAML to repair a lossy response would conceal the divergence. Handle an older setup binary in the benchmark failure path and retain its identity and a bounded actionable reason. Ordinary Shark reads retain their four native levels. A global change to their vocabulary would require the Shark workflow owner’s disposition. [Batch](../../../bench/scripts/run-lifecycle-batch.sh) · [Preview and live keyed consumers](../../../bench/scripts/run-lifecycle.sh)

Extend the current materializer, operator, adapter and their existing failure consumers. Preserve the lifecycle controller's transition and accounting rules. Decode Codex event streams at the adapter after checking the process exit and before existing control projection. The event recognition in benchmark branch commit `caf8fe3a` is reusable. Its reverse scan can accept an older pass after a malformed final answer. Track the last turn and its last completed agent message, require successful turn completion, and decode that message exactly once. An incomplete or failed last turn, invalid terminal text, or missing message produces a worker failure. A process that exits nonzero always fails. Retain direct control envelopes and supported plain-text outcomes for existing adapters. Apply text fallback only to authoritative message content once a Codex event stream is recognized. [Codex JSONL contract](https://developers.openai.com/codex/noninteractive/#make-output-machine-readable) · [Adapter](../../../bench/scripts/lifecycle-worker-adapter.sh)

The repair also addresses the defects that the independent review found before and after launch. The coverage index specifies the production boundaries and distinguishes retained behavior from required corrections. Use an offline synthetic executable that handles discovery and execution. Feed real operator inputs to the run-local workflow, derive the request from the real keyed response for that workflow, and pass it through the production adapter. Keep the benchmark source, fixture and evaluator roots isolated. Live inventory, entitlement, service availability and billing require separate evidence for any claim about them.
