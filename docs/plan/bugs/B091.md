# Plain status advance from a parking step does not resume the parked step

## Description

Advancing a parked (blocked) entity by key takes the first sorted transition, not the step it was parked from: change and bug parked in development go to code_review, tech debt goes to identified. Docs say the resume target is computed from history. Found in E31-F01 code review r2. fingerprint: internal/sharkdata/default_data/prompts/tech_debt/blocked.md#CORRECTNESS#resume-advance-skips-parked-step (engine half)

## Expected Behavior

A plain status advance from a parking step resumes the step the entity was parked from.

## Actual Behavior

It takes the first sorted transition (change/bug parked in development go to code_review; tech debt goes to identified).

## Steps to Reproduce

1. Park a change or bug from development with a blocked outcome.
2. Run `shark status advance <key>`.
3. Observe the new status is code_review.
