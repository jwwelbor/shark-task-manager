# E40 harness switching does not resolve compatible model routes

## Description

Bench routing gap confirmed offline during CC-044 planning: main bench/scripts/lifecycle-worker-adapter.sh command_for() drops the Codex model; bench-working passes -m but accepts an incompatible Sonnet model unchanged. load_routing_profile/apply_routing_profile in bench/scripts/lib/e40_benchmark.py have only definitions and test callers. Switching harnesses therefore does not materialize and validate compatible available model routes. E40-F13 provides explicit route profiles, not automatic availability resolution. Compare branch-only caf8fe3a/90e44690 without overwriting active work. Distinct from B077 native Rider routing attestation. Fingerprint: bench/lifecycle-worker-adapter#harness-switch-incompatible-model-route. Context: dev-artifacts/2026-11-03-cc-044-workflow/architect-consult-prompt.md.

## Expected Behavior

Selecting a benchmark harness should materialize compatible model routes before dispatch. Preserve explicit route identity and report unsupported or unresolved model availability instead of silently ignoring a model or forwarding an incompatible model name.

## Actual Behavior

On main, the Codex adapter constructs `codex exec --json` without forwarding the requested model. On `bench-working`, it forwards `-m sonnet` unchanged when requested. Profile application has test callers but no discovered production caller. No automatic model support or account-availability resolution was found.

## Steps to Reproduce

1. Inspect `command_for()` in `bench/scripts/lifecycle-worker-adapter.sh` on main and `bench-working`.
2. Evaluate command construction offline with provider `codex` and models `sonnet` and `gpt-6-luna`; do not invoke either provider.
3. Observe that main drops both model choices while `bench-working` forwards both, including the incompatible choice.
4. Search callers of `load_routing_profile` and `apply_routing_profile` under `bench/`; inspection found only definitions and tests.

## Fix Notes

No fix performed. Linked feature: E40-F13. B077 tracks a distinct native Rider requested-versus-effective model issue. Preserve active `bench-working` changes; inspect existing profile/adapter mechanisms before choosing a repair. Harness model support, account authorization, and temporary availability are separate concerns.
