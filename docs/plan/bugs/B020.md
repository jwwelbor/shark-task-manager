# shark next prompt has double-prefixed branch refs (E01-E01-F41)

## Description

Trial 3 of the shark 2.0 dispatch path in `~/projects/wormwoodGM` produced a rendered developer-agent prompt containing double-prefixed branch and feature references like `E01-E01-F41`. Looks like the template substitutes `{epic}-{feature_key}` where `{feature_key}` already includes the epic prefix.

## Expected Behavior

The git checkout snippet should read `git checkout -b E01-F41` (or equivalent slug-suffixed branch name). The "Feature:" header line should read `Feature: E01-F41 — …`.

## Actual Behavior

`prompt.txt` line 171: `git checkout -b E01-E01-F41   # e.g., E01-F35`
`prompt.txt` line 469: `Feature: E01-E01-F41 — link to feature spec at docs/plan/E01/E01-F41/feature.md`

A worker that follows the snippet literally creates a wrong-named branch.

## Steps to Reproduce

1. In a project with a feature whose key follows the `E##-F##` pattern (e.g., wormwoodGM `E01-F41`)
2. Run `shark next E01-F41 --json` (or any cascade that resolves to a developer-agent prompt)
3. Inspect the rendered prompt for `git checkout -b` and `Feature:` lines

## Reproducer artifact

`/home/jwwel/projects/wormwoodGM/dev-artifacts/2026-05-11-shark2-trial-3/prompt.txt` lines 171, 469.

## Fix Notes

Likely a template substitution where the developer-agent body builds the branch name from `{epic_key}-{feature_key}` but `{feature_key}` is already in `E01-F41` form. Either drop the epic prefix or use a `{feature_short}` token that's just the `F##` part.
