# B087 research report

## Scope

B087 concerns the effort needed to review a successor to a previously reviewed candidate. The **accepted baseline** defines everything the gate still owns. The **previous candidate** defines what changed since the last review. Those two commits can differ. E34 note 3962 proposes using both comparisons and requires cross-file invalidation. This research traces capture through dispatch, evidence persistence, bug admission and QA at repository revision `1d78ad660`.

## Findings

**Reproduction.** In a disposable Git repository, commit two one-line files named `a` and `b` as the baseline. Change both and commit round one. Change only `a` and commit round two. Run the shipped `get_diff.sh` after each round with the same explicit `REVIEW_BASE`. Both captures returned `changed_files = ["a", "b"]`. Git's round-one-to-round-two name-only diff returned `a`. Feed six empty-findings angle objects to the production Python writer's `validate_six_angles` against round two. The observed outcomes were:

| Identity supplied | Files each angle reports | Writer result |
|---|---|---|
| Round one | a, b | Rejected on candidate identity |
| Round two | a | Rejected on incomplete coverage |
| Round two | a, b | Accepted by the angle validator |

This exercises the scope and evidence contracts without running a model. The existing native-workflow unit test also passed, including its rejection of a wrong tree or empty coverage before consolidation. Neither experiment measures elapsed reviewer time or paid token savings.

**Cause.** Capture computes the binary diff, manifest and shortstat from the accepted base to HEAD. Each native angle receives that complete diff. Native validation, host-dispatch instructions, Python persistence and Go bug admission independently require each of six angle results to cover the entire manifest and match the current candidate. Prior bug findings enter the prompt as context. Retained scopes and decisions can explain earlier judgments, but none of those inputs lets the validator credit a prior inspection for a particular angle and file. A review can therefore fail correctly for missing evidence even when the omitted file's bytes are unchanged. Changing only the prompt would leave the downstream rejection intact.

**Callers and other gates.** Bug and change code-review templates invoke the shared process body. The shared task-style template also includes it. The Rider deep-review verb exposes the host skill directly. The bug path additionally binds the approved baseline and plan digest, verifies report, decisions and (for six-angle modes) angle sidecars, and hands the retained scope to QA. Comparable-CLI evidence has its own report/decisions contract. Feature code review has a distinct craft procedure. Its tier decides whether AC, wiring, caller-path and test verification run there or in QA. Both tiers inspect the full changeset for craft. The repeat-review reproduction occurs without a feature tier, so changing tier routing would leave the demonstrated cause intact.

**Prior findings and sibling risk.** CC-044 retained candidate-bound evidence, an authoritative approved plan, and full-class re-verification after rejection. E34-F06 requires a new enumeration across the declared search scope and the calling gate's full rubric. E34-F07 supplies change-impact evidence for material decisions. A changed producer can invalidate a previously reviewed caller whose blob is identical. A changed template include, test fixture, approval criterion or prior finding's causal site can likewise invalidate a conclusion outside the patch. An inserted line can move the site of a finding even if its text survives. Whole-file hashes establish byte equality only. Prior blockers, dispositions and evidence-backed downgrades must remain traceable to the current decision.

## Capability map

| Capability | Decision | Implication |
|---|---|---|
| Frozen base, tree, manifest, diff and approved bug plan | REUSE | Keep the accepted-baseline scope authoritative through QA. |
| Deep-review dispatch, report writer and parent admission | EXTEND | Teach all applicable producers and consumers to distinguish fresh inspection from justified prior coverage. Preserve runner identity and honest completion counts. |
| Prior dispositions, defect-class sweeps and change-impact records | REUSE | Use earlier judgments to identify what needs verification. Re-enumerate the full declared class after rejection. |
| Per-angle coverage provenance across candidates | NEW | Existing angle results record candidate identity and file names. Reuse needs independently checkable links between prior evidence, current content, dependency scope and obligations. |
| Substituting the previous candidate as the gate baseline | CONTRADICTS | This drops unaccepted predecessor changes from the evidence used by admission and QA. |

## Decisions

1. Extend existing review capture and admission. Keep the full candidate evidence and compute a second diff against an identifiable, verified prior review. Record fresh and carried coverage separately. Never populate a fresh reviewer's inspected-file list from history. A first review, missing sidecar, incompatible rubric, changed plan/base, ambiguous lineage or unverifiable dependency should trigger fresh coverage for the affected scope, up to the entire candidate.
2. Reopen changed lines, prior finding sites and newly implicated causal lines (the bug calls these `caused_by`), plus affected callers, tests and siblings. Cover deletions, renames, binary or mode-only changes, and changed contracts in unchanged files. No structured `caused_by` field was found in the tracked implementation; the repair plan must define how to identify and re-anchor those sites or conservatively widen review.
3. Changed-line counts can size work packets. Preserve a cross-file pass and reconcile all obligations at consolidation. Existing prompt-only guidance already targets rendering and includes. Use change type to direct attention, including test-only changes that weaken assertions. Skipping angles would change the six-angle evidence contract. Any such mode needs explicit reporting and admission rules. No chunk threshold or safe universal angle subset follows from this reproduction.
4. Retain full review as the compatible fallback and for unprovable impact. Before enabling reuse, demonstrate a two-round positive case, a byte-identical consumer invalidated by its producer, a newly implicated causal line and stale or missing evidence. Verify native dispatch, host persistence, Go admission and QA agree. Treat a prompt-only optimization as insufficient and retain existing handling of incomplete runs, blockers and triage.
