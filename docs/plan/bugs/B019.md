# `--size` flag missing from unified `shark create <entity>` command

## Description

The unified verb-first `shark create <entity>` command does not expose the `--size` flag for task, feature, epic, bug, or change. Passing `--size` to any of these is silently rejected with `Error: unknown flag: --size`. The entity-first equivalents (`shark task create`, `shark feature create`, etc.) all support `--size` correctly. `shark create tech-debt` is the only unified form that already has the flag.

This means an agent using the recommended `shark create task` form cannot set size at creation time and must issue a follow-up `shark update <key> --size=N`. If the follow-up is missed, tasks land in the sprint without estimates, silently degrading readiness scores.

## Affected Commands

| Command | `--size` present? |
|---|---|
| `shark task create --size` | ✅ works |
| `shark feature create --size` | ✅ works |
| `shark epic create --size` | ✅ works |
| `shark bug create --size` | ✅ works |
| `shark change create --size` | ✅ works |
| `shark td create --size` | ✅ works |
| `shark create task --size` | ❌ **missing** |
| `shark create feature --size` | ❌ **missing** |
| `shark create epic --size` | ❌ **missing** |
| `shark create bug --size` | ❌ **missing** |
| `shark create change --size` | ❌ **missing** |
| `shark create tech-debt --size` | ✅ works |

## Steps to Reproduce

```bash
# Fails — unknown flag
shark create task E27 F14 "My task" --size=S

# Works — entity-first form
shark task create E27 F14 "My task" --size=S

# Workaround: create then update
shark create task E27 F14 "My task"
shark update T-E27-F14-NNN --size=S
```

## Expected Behavior

`shark create task E27 F14 "My task" --size=S` creates the task with size set, identical to `shark task create E27 F14 "My task" --size=S`.

All five affected entity types (task, feature, epic, bug, change) should accept `--size` on both the unified and entity-first forms.

## Actual Behavior

`Error: unknown flag: --size` — the flag does not exist on the unified `create` dispatcher for these entity types. The task/feature/bug/epic/change is created without a size, and no warning is shown that the size was not applied.

## Impact

Sprint readiness scoring penalises unsized entities (up to -15 pts from the sizing coverage factor). An agent that uses `shark create task` exclusively has no way to set size at creation time, causing all new tasks to land in sprints without estimates.

## Fix Notes

The unified `shark create` dispatcher (likely `internal/cli/commands/create.go`) routes to each entity's create handler but does not forward `--size`. The fix is to add `--size` as a flag on the `create task`, `create feature`, `create epic`, `create bug`, and `create change` subcommands and pass it through to the underlying create handler — matching the pattern already working for `create tech-debt`.
