# Bug development prompt does not enforce linked decision constraints

## Description

Fingerprint: internal/sharkdata/default_data/prompts/bug/development.md#ROUTE#linked-decision-constraints-not-enforced. The bug workflow routes development to the Developer with Anthropic/Sonnet metadata and debugging/TDD skills, but its prompt reads only the bug file, CLAUDE.md, and related code; its exit gate checks regression test, quality gate, and unrelated changes. It does not require loading linked/referenced decision briefs or converting their constraints into testable checks. Concrete WWGM B110 example: accepted route DB-2026-11-03-b099-residual-redraw-route.md and predecessor review overall-review.md are linked in Shark, yet B110.md has no explicit acceptance checklist. The accepted route requires extracting retry orchestration, correct scanner key/value state, retained ordered attempt evidence, and regressions for later terminal faults/accounting. Frozen B099 review examples include a materially enlarged retry method, a custom scanner key/value false positive, lost prior-attempt evidence, and missing exact accounting regression assertions. Distinct from completed B066 review-triage routing and B036 status-prompt coverage. `shark next B110` reports Anthropic/Sonnet route metadata; that is not evidence of the model used in the earlier run.

## Expected Behavior

When a bug has linked or referenced decisions, the development instructions should direct the developer to read them, carry their applicable constraints into the bug's verification, and treat an otherwise green test/quality gate as insufficient while those constraints remain unchecked or undispositioned.

## Actual Behavior

`internal/sharkdata/default_data/workflow/bug.yaml` routes `development` to `developer` with provider/model metadata `anthropic`/`sonnet` and debugging/TDD skills. `internal/sharkdata/default_data/prompts/bug/development.md` asks the developer to read the bug file, `CLAUDE.md`, and related code. Its exit gate only requires a regression test, a passing quality gate, and no unrelated changes; it does not require reading related decision briefs or checking their constraints.

## Steps to Reproduce

1. Inspect `workflow/bug.yaml`'s `development` route and `prompts/bug/development.md`'s READ and EXIT GATE sections.
2. Dispatch a bug with an accepted linked decision and predecessor review, as in WWGM B110.
3. Observe that the bug-specific prompt does not require the developer to read those documents or verify the route constraints before passing.

## Fix Notes

### WWGM B110 example

At capture time, B110's related-doc list already contained the accepted B110 route decision, the B099 predecessor review, and the B110 research report. The B110 bug file still contained discovery and route prose without an explicit acceptance checklist. The prompt gap is therefore that the reusable developer instructions do not require consuming and checking available decision evidence.

The accepted route requires explicit top-level JSON key/value tracking, ordered failed-attempt evidence retained through later terminalization, retry orchestration extracted from the enlarged part-attempt method, and regressions for a target-like top-level value and later terminal/accounting paths. The frozen predecessor review records concrete misses: a scanner false positive, dropped first-attempt evidence after a successful chunk redraw, a materially expanded retry method, and no B099 terminal accounting regression after an earlier completed part. The earlier B099 review also records single/chunked attempt-history and usage/cost assertion gaps.

Model evidence is limited: `shark next B110 --json` resolved route metadata as Anthropic/Sonnet. That does not establish which model ran in the earlier implementation session.
