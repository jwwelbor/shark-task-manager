## Open plan findings

### F1. A short stale slug can still select a real parent

Row 16 requires qualified misses, unique shorthand successes and ambiguous shorthand failures. It omits a zero-match **short** slug at the registered delete caller. With only E10-F02, slug `multi-word`, and a linked document, `--feature=F02-stale` matches zero rows. A delete-specific resolver that retries the bare number after a short-slug miss can delete E10's document and acknowledge the stale key. Qualified stale, unique short and ambiguous short cases still behave as specified. The shipped direct repository wrong-short-slug test also passes if the erroneous fallback lives in the delete path alone.

The isolated SQLite comparison returned no ID for the number-plus-stale-slug predicate and ID 10 for the numeric fallback. With E11-F02 under a different slug, bare F02 matched both IDs while F02-multi-word matched only 10. Require the compiled stale shorthand to exit 1 with the supplied key, no confirmation and the original link intact. Include the no-feature bare shorthand control and the two-epic, one-matching-slug success. Observe zero link calls on a parent miss and read back the exact associations independently. These are executable consequences of decision 3952 and the existing missing-parent contract. ### F2. A global ambiguity check can break callers outside delete

Repair step 6 expressly preserves shorthand lookup for other callers. A two-match rejection inserted in common `FeatureRepository.GetByKey` would make ambiguous document delete reject correctly and would pass qualified feature get, qualified add/list readback and unique shorthand checks. It would also make previously accepted shorthand fail at document add, document list and feature get. The production add, list and unlink methods share the lookup supplied by `FeatureService.SetWritableDocRepo`. Feature get uses the feature service's key lookup. The shipped shorthand query reads one matching row with no ordered winner. In the two-match SQLite fixture a single-row read succeeded, while the bounded candidate set contained both IDs.

Require controls at those three non-delete callers for both shorthand forms with two matching features. On isolated data, preserve successful lookup, the feature identity returned by the existing lookup for the fixture, and the relevant document associations and readback. Avoid asserting an ordering guarantee the shipped lookup never made. Require ambiguity and a request for a fully qualified key on delete against the same initial data. This binds the user’s delete-specific disposition to the command where it applies. ### F3. Counting rollback calls cannot detect a discarded rollback failure

B078/3917 and 3925 retain the requirement to preserve a meaningful rollback failure alongside the primary cause. The earlier development disposition is fixed for its own candidate. The inspected implementation uses `errors.Join`. Row 5 requires four injected causes for begin, execute, verify and commit, and counts rollback attempts. A cleanup that calls rollback exactly once, discards its error and returns only the primary error passes those assertions. Ordinary SQLite rollback durability and context-cancellation controls can pass too.

Extend the planned recording driver with one failure after a transaction starts and an independent rollback failure. Assert one rollback, no commit, and `errors.Is` for **both** distinct causes on the returned error from the public repository method. Keep normal successful cleanup and `sql.ErrTxDone` handling. This is a plan assertion gap. The existing implementation's earlier fixed disposition stands at its recorded identity. ### F4. The error contract omits the other changed command handlers

The prior candidate review explicitly traces the shared repository error contract into **change get/update/delete** and **tech-debt get/update/delete/triage**, including the confirmation read and forced mutation branches. Rows 5, 6 and 13 name document delete and its underlying lookups. They omit the sibling commands and their observable failure classifications. For example, adding a misleading “not found” wrapper in change get around the correctly mapped storage error preserves exit 2, the typed marker and the existing handler test's substring assertions. Every named document-delete assertion still passes.

Map these callers to the project exit convention and prior review section H. Bind the existing handler tests and executable marker test to the integrated candidate. Require genuine missing-parent exit 1, operational failure exit 2 with the underlying cause and no false missing-parent diagnostic, including the forced-delete outer wrapping. Keep update or delete diagnostics appropriate to the failing operation. Existing evidence can satisfy each check it actually observes.
