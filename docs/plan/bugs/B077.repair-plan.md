# B077 repair plan — verify the worker Rider actually launched

Revision 7 is proposed for independent review. The project file is `docs/plan/bugs/B077.repair-plan.md`. Its [evidence record](B077.repair-plan-evidence.md) retains the digests of all revisions, earlier findings, owner dispositions and results. The index below is the sole source of repair obligations.

## Diagnosis and review baseline

At Shark Task Manager commit **`bbf490c6ec2bd597d6f3e6e4cdd93e68ca54fa50`**, keyed `shark next` already carries the persona, requested provider, optional model, effort and assembled prompt. Rider told Claude Code how to select a model. Its native Codex handoff lacked both an explicit model-selection rule and a check of the model used by the particular child. Its long-running Codex CLI example also launched without a model argument. A successful worker response could therefore enter the parent loop without establishing which route ran. The defect is at the host adapter and its result-consumption boundary. [Bug](B077.md) · [Research](B077.research-report.md) · [Baseline checks](B077.repair-plan-evidence.md#baseline-and-historical-observation)

In WWGM S010, six deep-review children recorded Luna/xhigh. Three retained parent spawn call sites omitted a model override and the parent also edited application code. The separate B101 developer/Sonnet and B100 tech-lead/Opus inspection results have no shared keyed dispatch ID with those children. The historical trace establishes inheritance risk. A new keyed capture is required to establish end-to-end behavior for the repair. It cannot establish which historical request produced a given child or why E13 failed.

The declared baseline is the parent of the first B077 implementation commit. The assigned branch already contains several attempted fixes and a separate test-capture repair. Independent plan review must resolve the full baseline to a commit in this project, inspect the pre-repair dispatch above, and verify ancestry and the complete delta to the candidate. Use the same baseline for development, review and QA, including unaccepted predecessor changes. [Baseline and prior attempts](B077.repair-plan-evidence.md#baseline-and-historical-observation)

## Decision and repair

Extend the existing Rider instruction and adapter contract, and correct deep-review CLI metadata so it reports the identity of the invocation that produced the accepted packet. Carry reasoning effort separately from model identity through each supported CLI selector and worker observation. Add caller-level checks for effort, alias resolution, preflight cost, history attribution, consultation and result admission, telemetry, retry attribution, claim races, and both published schemas. Centralize route selection in Rider's keyed dispatch procedure and keep the provider reference responsible for installed-host capability facts. Reconcile earlier implementation attempts against each assertion below. Shark retains prompt assembly and workflow authority. This repair calls for no new routing service, credential or workflow configuration, model registry, persistent route store, worker-envelope field, or change to ordinary `shark run`. [E34-F01 decisions and implementation addendum](../E34-prompt-and-skill-improvements/E34-F01-harness-aware-prompt-rendering/decisions.md) · [E38 dispatch and ownership decisions](../E38-shark-attack-team-orchestration/architecture.md)

If the exact route is unavailable, consider only an explicit compatible mapping. Record the original request, selected route, adapter and mapping reference separately. If effort is omitted, add no effort override. Reject an unsupported explicit Codex effort during preflight. For native Codex, check the installed spawn primitive in the requested dispatch mode. An explicit model needs a usable native selector and a native child observation path. If the mode only inherits the parent model, it cannot serve as that selector. Apply the existing route policy before claim.
4. Before using any worker result, compare independent observations for that worker with the **selected** provider and model, and compare effort whenever the request specified it. For Codex CLI, join the invocation's `thread.started.thread_id` to `session_meta.payload.id` in its persistent rollout. Record the literal selector, expected resolution and observed child ID/model separately. A dated sample shows how to correlate the records. It cannot pin an alias for future runs. Use only checked installed formats. A conclusive provider, model, or requested-effort difference is `mismatch`. Missing, ambiguous or conflicting observations or alias rules are `unverified`. A launch with no attributable worker ID cannot furnish an attestation. Reject its result and follow parent failure cleanup without manufacturing an ID.
