# B077 repair plan — verify the worker Rider actually launched

Revision 1 is proposed for independent review. The project document is `docs/plan/bugs/B077.repair-plan.md`. Its [evidence record](B077.repair-plan-evidence.md) holds the digest, source checks, prior findings and subsequent results. The coverage index below owns the obligations.

## Diagnosis and review baseline

At Shark Task Manager commit **`bbf490c6ec2bd597d6f3e6e4cdd93e68ca54fa50`**, keyed `shark next` already carries the persona, requested provider, optional model, effort and assembled prompt. Rider told Claude Code how to select a model. Its native Codex handoff lacked both an explicit model-selection rule and a check of the model used by the particular child. Its long-running Codex CLI example also launched without a model argument. A successful worker response could therefore enter the parent loop without establishing which route ran. The defect is at the host adapter and its result-consumption boundary. [Bug](B077.md) · [Research](B077.research-report.md) · [Baseline checks](B077.repair-plan-evidence.md#baseline-and-historical-observation)

In WWGM S010, six deep-review children recorded Luna/xhigh. Three retained parent spawn call sites omitted a model override and the parent also edited application code. The separate B101 developer/Sonnet and B100 tech-lead/Opus inspection results have no shared keyed dispatch ID with those children. The historical trace establishes inheritance risk. A new keyed capture is required to establish end-to-end behavior for the repair. It cannot establish which historical request produced a given child or why E13 failed.

The declared baseline is the parent of the first B077 implementation commit. The assigned branch already contains several attempted fixes and a separate test-capture repair. Independent plan review must resolve the full baseline to a commit in this project, inspect the pre-repair dispatch above, and verify ancestry and the complete delta to the candidate. Use the same baseline for development, review and QA, including unaccepted predecessor changes. [Baseline and prior attempts](B077.repair-plan-evidence.md#baseline-and-historical-observation)

## Decision and repair

Extend the existing Rider instruction and adapter contract. Centralize route selection in Rider's keyed dispatch procedure and keep the provider reference responsible for installed-host capability facts. Reconcile earlier implementation attempts against each assertion below. Shark retains prompt assembly and workflow authority. This repair calls for no new routing service, credential or workflow configuration, model registry, persistent route store, worker-envelope field, or change to ordinary `shark run`. [E34-F01 decisions and implementation addendum](../E34-prompt-and-skill-improvements/E34-F01-harness-aware-prompt-rendering/decisions.md) · [E38 dispatch and ownership decisions](../E38-shark-attack-team-orchestration/architecture.md)

1. Read the exact keyed response. Before claim, attempt the exact requested route. For an Anthropic request, prefer an eligible Claude Code adapter. Establish that the installed adapter can select the model and can subsequently obtain a worker-correlated observation. If the exact route is unavailable, consider only an explicit compatible mapping. Record the original request, selected route, adapter and mapping reference separately. A proven missing route is `unsupported`. A selected route with incomplete capability evidence is `unverified`. Both stop before any lease or worker exists.
2. Use the six default bug-stage mappings below when Claude is unavailable and the Codex CLI passes preflight. Match the entire tuple against the keyed response. All six select host class `codex-cli`, provider `openai` and model `gpt-6.2-astra` under `B077-default-bug-anthropic-codex-v1`. This is a limited operational substitution authorized by the owner's optional-Claude direction and scoped in the Architect consultation. It makes no model-equivalence claim. Check the installed selector, authentication and readable identity source before claim. A changed or custom tuple outside this mapping requires its own documented authority. 3. After eligible preflight and parent claim, pass the selection to the actual adapter and the original prompt bytes to its worker. For explicit Codex CLI models use `codex exec --model <selected_model>`, including an exact Codex request with a different model. For Claude use its documented `model` selector and route effort to its own worker class. An empty model stays empty in the request. Use a documented, observable provider default only under that provider's rule. A mapped Anthropic request always has an explicit nonempty selector. A CLI capability cannot authorize native Codex spawning.
4. Before using any worker result, compare independent observations for that worker with the **selected** provider and model. For Codex CLI, join the invocation's `thread.started.thread_id` to `session_meta.payload.id` in its persistent rollout. Use `session_meta.payload.model_provider` and every relevant `turn_context.payload.model` from that thread. Use only a checked installed format. Equal observations admit the result to the existing envelope and lease checks. A conclusive difference in either field is `mismatch`. Missing, ambiguous or conflicting observations are `unverified`. A launch with no attributable worker ID cannot furnish an attestation. Reject its result and follow parent failure cleanup without manufacturing an ID.
