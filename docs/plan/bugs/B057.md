# E40 bench: candidate identity_digest formula disagrees between run-lifecycle.sh and verify-lifecycle-run.sh

## Description

`bench/scripts/run-lifecycle.sh`'s `refresh_candidate()` computes each
stage's `candidate.identity_digest` as `canonical_digest()` over **every**
key currently on the candidate dict except `identity_digest`/`snapshot_digest`
themselves — which includes `scratch_content_digest` (7 fields total,
computed after `scratch_content_digest` is added to the dict).

`bench/scripts/verify-lifecycle-run.sh`'s `validate_record()` independently
recomputes the expected digest over only the original **six** identity
components (`base_commit`, `tree_digest`, `binary_diff_digest`,
`changed_path_digest`, `dirty_untracked_manifest`, `test_suite_digest`) —
`scratch_content_digest` excluded.

The two formulas structurally disagree, so `verify-lifecycle-run.sh` rejects
every `candidate.identity_digest` that `run-lifecycle.sh` itself ever writes,
in any mode (dry-run, contract, or live), for any scenario.

Discovered while wiring up `bench/scripts/smoke-lifecycle.sh` (an operator
convenience wrapper for the "Operator quick start: CLI dispatch smoke test"
sequence in `bench/README.md`) — the very first real dry-run against
`py-bug-due-date-boundary` surfaced this as the fifth consecutive
producer/validator contract mismatch, after four narrower ones already fixed
in the same session (see Fix Notes).

## Expected Behavior

`verify-lifecycle-run.sh` accepts a `candidate.identity_digest` that
`run-lifecycle.sh` actually produced for a structurally valid record.

## Actual Behavior

```
verify-lifecycle-run: identity_mismatch: /stages[0]/candidate/identity_digest: candidate identity digest does not match its six identity components
```
on every single dry-run/live invocation, unconditionally.

## Steps to Reproduce

1. `make shark`
2. `bench/scripts/smoke-lifecycle.sh --out /tmp/e40-smoke` (or drive
   `run-lifecycle.sh --mode dry-run` by hand per the README's manual steps)
3. `bench/scripts/verify-lifecycle-run.sh <lifecycle.jsonl> --schema bench/runs/i07-schema.yaml`
4. Observe the `identity_mismatch` failure on `/stages[0]/candidate/identity_digest`

## Fix Notes

Pick one side as authoritative and make the other match — do not average
them. Likely correct: `scratch_content_digest` is meaningful evidence (it
digests the worker's actual scratch-project contents at stage end) and
should probably be part of the identity, so `verify-lifecycle-run.sh`'s
`expected_identity` computation should likely be extended to include it
rather than narrowing `run-lifecycle.sh`. Confirm against how F09/F10
downstream consumers key off `candidate.identity_digest`/`snapshot_digest`
before changing the formula, since both are read elsewhere (I-05/I-08).

Four narrower producer/validator mismatches were found and fixed in the same
investigation, all committed ahead of this bug:
- `i07-schema.yaml` required `/dispatches[]/response/effort`,
  `/response/resolved_via`, and `/response/unresolved_placeholders`
  unconditionally, though `shark next --json` marks all three
  `json:"...,omitempty"` and legitimately omits them.
- `i07-schema.yaml` required `/workflow_policy/reviewer/effort`, though
  `run-lifecycle.sh` always writes it as `""` (no real reviewer identity is
  wired into `workflow_policy` yet) and the validator rejects any required
  empty string.
- `verify-lifecycle-run.sh`'s required-field null check rejected
  `/limits/first_exceeded` even though it is declared `nullable_string` in
  the schema's own `properties` map — the null check never consulted that
  type before failing.
- `verify-lifecycle-run.sh` unconditionally indexed
  `response["resolved_via"]` after that key became legitimately optional,
  raising a `KeyError` instead of a clean validation failure.
