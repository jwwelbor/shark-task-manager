# shark next prompt uses key-only feature paths (docs/plan/E01/E01-F41/) instead of slug-suffixed

## Description

The rendered developer-agent prompt references feature files at `docs/plan/E01/E01-F41/feature.md`, but the on-disk path is the slug-suffixed form: `docs/plan/E01-content-ingestion/E01-F41-lexicon-observation-staging-and-reconciliation-cor/feature.md`. The prompt's step 1 does cite the `shark get … --json --field=file_path` escape hatch, but the cosmetic paths sprinkled throughout the body are wrong and would mislead a worker trying to read context inline.

## Expected Behavior

Either:
- **Option A:** The prompt should substitute the actual slug-suffixed file_path everywhere it appears (looked up via repo at render time), or
- **Option B:** Strip the cosmetic paths from the prompt body entirely and rely solely on the `shark get --field=file_path` escape hatch.

## Actual Behavior

Body prompt repeatedly references `docs/plan/E01/E01-F41/feature.md`, `docs/plan/E01/E01-F41/test_plans/…`, etc. These paths do not exist on disk.

## Steps to Reproduce

1. In wormwoodGM (or any project with slug-suffixed feature directories): `shark next E01-F41 --json`
2. Grep the rendered prompt for `docs/plan/E01/E01-F41/`
3. Compare with the actual path: `shark get E01-F41 --field=file_path`

## Reproducer artifact

`/home/jwwel/projects/wormwoodGM/dev-artifacts/2026-05-11-shark2-trial-3/prompt.txt` — see `prompt-review.md` in the same trial directory for context.

## Fix Notes

Probably the developer-agent body template hard-codes `docs/plan/{epic}/{feature_key}/...` paths. Either feed the rendered `file_path` from the entity (preferred — the repo has it via service layer) or stop pretending the path is predictable.
