# Run and release paths bypass claim ownership and break non-task worksessions

## Description

Full code review on 2026-07-07 found shark run never claims heartbeats or releases the entity it drives, shark release without --session performs an unscoped administrative release, and worksession repository reads scan nullable task_id into plain int64 for non-task claims. See dev-artifacts/2026-07-07-full-code-review/code-review-report.md sections M5 and M14.

## Expected Behavior

`shark run` should preserve the claim contract end-to-end, unscoped release should
require explicit force semantics, and worksession reads should tolerate NULL
`task_id` values for non-task claims.

## Actual Behavior

The run controller never performs claim, heartbeat, or release operations around
execution. `shark release <key>` without `--session` performs an administrative
release, and worksession repository scans fail when a non-task claim stores a NULL
`task_id`.

## Steps to Reproduce

1. Start two concurrent `shark run <key>` invocations and observe that both can
   dispatch the same entity.
2. Release another session's claim without passing `--session`.
3. Read worksessions for a non-task claim and observe the NULL scan failure.

## Fix Notes

Review source points:
- `internal/cli/commands/run.go`
- `internal/runner/controller.go`
- `internal/cli/commands/claim.go`
- `internal/services/claim_service.go`
- `internal/repository/worksession/repository.go`
- report sections M5 and M14
