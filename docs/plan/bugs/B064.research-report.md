# Research E40 lifecycle benchmark capture failures

## Scope

Determine why the shipped E40 F08/F10 path cannot complete a provider-backed
benchmark, identify every contract boundary exposed by a live run, and choose
the smallest repair that produces retained, publication-eligible evidence.

## Findings

The existing capability already defined the correct component boundaries:
F08 owns the lifecycle, F09 evaluates run-matched evidence, and F10 retains and
reports the result. The production wiring between those boundaries was
incomplete.

The first live dispatch failed because the controller wrote its request to
standard input while the adapter required a `--request` file. After that fix,
successive retained probes exposed related defects in command-output parsing,
multi-stage traversal, fixture isolation, evidence production, retention,
Claude structured-output decoding, outcome normalization, deadline handling,
time units, evaluator stop handling, and claim-session authority.

The repair extends the existing E40 capability. It does not define a new
benchmark model or bypass any admission, evaluation, or retention contract.
The live run at
`/home/jwwel/e40-benchmarks/2026-09-03-e40-capture-fixed/runs/baseline-bug-003`
proves the repaired caller chain: four provider stages completed, the held-back
oracle passed, retention verification passed, and the promoted baseline is
publication eligible.

## Decisions

- Keep Shark as the sole workflow and lease authority.
- Accept adapter requests on standard input and attach the parent session after
  provider output is decoded.
- Create a fresh fixture checkout and run-matched evidence bundle for each
  scenario repetition.
- Preserve failed attempts for diagnosis and preflight all required sources
  before installing retained artifacts.
- Enforce the wall-clock limit while a provider process is active.
- Store I-05 time ledgers in nanoseconds and I-07 intervals in seconds, as
  required by their separate contracts.
- Treat stopped lifecycle outcomes as terminal but aggregate ineligible; do not
  misclassify them as pre-terminal evaluator access.
