# Duplicate history tables (task_history + entity_history)

## Description

The codebase has two parallel history systems:

1. **`task_history` table** — legacy, task-specific. Written to by `TaskHistoryRepository`
   (`internal/repository/task/history.go`). All methods are marked `Deprecated`.
2. **`entity_history` table** — new, polymorphic. Written to by `EntityHistoryRepository`
   (`internal/repository/entityhistory/repository.go`). Supports epic, feature, task, bug, change.

This is an **intentional in-progress migration** tracked as task T-E21-F08-004. The
`task_history` table comment in `db.go` explicitly reads:
`"kept for backward compatibility until T-E21-F08-004"`.
Data is also copied from `task_history` to `entity_history` during migration
(`migrateHistoryDataToPolymorphic` in `db.go`).

There is also a **true duplicate**: the test file
`internal/repository/task_history_repository_test.go` is a near-identical copy of
`internal/repository/task/history_test.go`. Both files contain the same 8 test functions
testing the same `TaskHistoryRepository` code, differing only in package name and
`//nolint:staticcheck` annotations. Running both results in redundant test execution.

## Expected Behavior

- `task_history` table and `TaskHistoryRepository` should exist only while callers still
  depend on them (pending T-E21-F08-004).
- Test coverage for `TaskHistoryRepository` should not be duplicated across two files.

## Actual Behavior

- Both tables exist and are both actively created in the schema (`db.go` lines 184-222).
- Multiple call sites use `NewTaskHistoryRepository` with `//nolint:staticcheck` comments
  acknowledging the deprecated status.
- The test file `internal/repository/task_history_repository_test.go` duplicates all 8
  tests from `internal/repository/task/history_test.go`.

## Steps to Reproduce

1. Search for `TestTaskHistoryRepository` — the same test names appear in two packages
2. Run `go test ./internal/repository/... -v -run TestTaskHistoryRepository` — tests run twice

## Fix Applied

Removed the duplicate test file `internal/repository/task_history_repository_test.go`.

The authoritative tests live in `internal/repository/task/history_test.go` (package `task`),
which tests `TaskHistoryRepository` directly without going through the alias layer.
The root-level file was created when code was reorganised into subpackages and was never
removed.

**NOT fixed (deferred to T-E21-F08-004):**
- The `task_history` table and `TaskHistoryRepository` are intentionally kept as a
  backward-compatibility shim. Removing them requires migrating all callers in:
  - `internal/taskcreation/creator.go`
  - `internal/cli/services_global.go`
  - `internal/cli/service_accessors.go`
  - `internal/status/status.go`
  - `cmd/server/services.go`
  - `cmd/test-db/main.go`
  - Multiple test files in `internal/taskcreation/`
  This migration should be done as part of T-E21-F08-004.
