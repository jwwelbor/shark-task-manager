## Scope

B036 covers the keyed dispatch contract for workflow steps that declare a prompt: `shark next <key> --json` must return the rendered, status-specific instruction together with the agent persona. The affected entity types are epic, feature, task, bug, change, and tech-debt. The scope includes workflow-index loading, prompt-directory resolution, action population, and representative isolated integration coverage.

The scope excludes workflow-state transitions, changes to agent personas, and new workflow statuses. It also excludes Question and Sprint workflows because B036's reported and required coverage set does not include them.

## Findings

1. The reported failure class crosses more than one workflow. Each route-based YAML step supplies a prompt path, `defaultWorkflowDataLoader` projects every entity workflow into the action service, and `resolveEntity` requests the populated action before `assembleDispatchPrompt` joins it with the persona. A failure in workflow-index or prompt-directory resolution can therefore leave any supported entity with a persona-only dispatch.

2. The current dispatch path fails loudly for worker actions whose populated instruction is empty. `resolveEntity` rejects empty instructions for `spawn_agent` and `check_or_resume` before it returns a worker prompt. The same guard is exercised for keyed planning as well as keyed dispatch in `plan_dispatch_test.go`.

3. Existing B036 regression coverage reproduces the required environment without touching this repository's project database. `TestNext_RendersRepresentativeDispatchPromptsFromWorkflowIndexBundle` creates a temporary project and `shark-tasks.db`, writes a workflow-index fixture, initializes entities, sets representative statuses, and invokes `next --json`. It asserts status-specific content for epic assessment, feature assessment, task development, bug development/code review/QA, change development/code review, and tech-debt in-progress/code review.

4. The reproduction passed on the current branch with `go test ./internal/cli/commands -run '^TestNext_RendersRepresentativeDispatchPromptsFromWorkflowIndexBundle$' -count=1 -v`. The test's reviewer-persona lookup warnings are expected fixture behavior; each dispatch response still contained the required status-specific instruction.

5. Commit `14d8f57a` introduced the B036-named integration test and shared workflow-index fixture. The needed repair is therefore an extension of the established action-population and isolated integration-test capabilities, not new workflow infrastructure.

6. A static audit of YAML prompt fields or unit testing template population alone would not protect the full defect class. It would miss the configured workflow-index path, template-directory selection, CLI initialization, entity-specific placeholder generation, and final `next --json` response assembly. The existing temporary-project integration test is the appropriate structural guard.

## Decisions

1. Treat B036 as an extension of the existing keyed-dispatch rendering contract. Keep the single action-population path and the fail-loud empty-instruction guard; do not add an entity-specific fallback that could return a persona-only worker prompt.

2. Retain the isolated workflow-index integration test as the regression gate. Add representative statuses when a supported entity workflow gains a new prompt-resolution path, rather than relying on the live project database or a static YAML crawl.

3. Preserve the six required entity types and the multi-status bug, change, and tech-debt cases. These exercise both development and review/QA prompt locations, where directory or index drift could otherwise remain hidden.

4. No new workflow state, entity type, or prompt assembly subsystem is required. The repair reuses the workflow loader, action renderer, keyed dispatch assembler, and fixture capability already present on this branch.
