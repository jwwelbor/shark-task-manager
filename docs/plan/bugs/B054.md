# FindProjectRoot escapes intended project when a stray /tmp/.git exists

## Description

Discovered during T-E40-F02-003 testing: a stray empty /tmp/.git directory made FindProjectRoot() resolve to /tmp, so scratch-project initialization (run in a scratch dir under /tmp) wrote shark-tasks.db outside every scratch project on the machine. Root-cause: project-root auto-detection walks up to the .git fallback marker with no sanity check that the marker is a real repository (or that the root is sane, e.g. not a system temp dir). Impact: bench harness scratch provisioning (E40-F02 run-one.sh), scripts/shark-scratch-env.sh users, and any workflow relying on scratch dirs under /tmp — DB writes land at /tmp, breaking isolation guarantees. Workaround applied: removed the stray /tmp/.git. Suggested fix: validate the .git marker (require HEAD or objects/) and/or refuse roots that are system temp directories unless --db/--config is explicit.
