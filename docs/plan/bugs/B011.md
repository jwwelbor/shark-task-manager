# Broken cross-reference links in tags.md and task-commands.md

## Description

Two cross-reference links in the CLI reference docs do not resolve to existing targets. A reader clicking either link in a Markdown viewer (GitHub, IDE preview, mkdocs, etc.) gets a "missing anchor / file not found" jump.

### Link 1: tags.md → configuration.md#database-skip_migrations  (broken anchor)

`docs/cli-reference/tags.md:792`

```markdown
See [Initialization → Migrating an existing project to v14 (E28 tagging)](initialization.md#migrating-an-existing-project-to-v14-e28-tagging)
for the full procedure and [Configuration → `skip_migrations`](configuration.md#database-skip_migrations) for the field reference.
```

The target heading exists at `docs/cli-reference/configuration.md:75`:

```markdown
#### `database.skip_migrations`
```

…but GitHub-flavored Markdown's anchor algorithm strips backticks AND strips dots without replacement, so the slug for that heading is `databaseskip_migrations` (no hyphen, no dot), **not** `database-skip_migrations`. The link's anchor therefore does not exist.

This was already noted as a pre-existing defect in `docs/plan/E28-entity-tagging-with-managed-vocabulary/E28-F07-tagging-documentation/code_review/20260425-134708-T-E28-F07-006-uat.md:137` ("Anchor missing in target. Introduced by T-E28-F07-005"). It was deferred from that task and is now this bug.

### Link 2: task-commands.md → workflow-config.md  (broken file path)

`docs/cli-reference/task-commands.md:1013`

```markdown
- [Workflow Configuration](workflow-config.md) - Status flows and phases
```

There is no `docs/cli-reference/workflow-config.md`. The actual file is `docs/cli-reference/workflow-configuration.md` (note the full word). The link 404s.

## Expected Behavior

Both links resolve to existing targets:

- `configuration.md#database-skip_migrations` either (a) becomes a real anchor (explicit `<a id="database-skip_migrations">` above the existing heading) or (b) the link is updated to use the actual GitHub-generated slug for the existing `#### `database.skip_migrations`` heading.
- `workflow-config.md` becomes `workflow-configuration.md`.

## Actual Behavior

Both links produce dead jumps in any Markdown renderer that follows GitHub anchor rules.

## Steps to Reproduce

### Reproduce link 1 (tags.md → configuration.md anchor):

1. Open `docs/cli-reference/tags.md` at line 792 in a renderer that uses GitHub anchor rules (e.g., view on github.com or any IDE preview with that algorithm).
2. Click the `[Configuration → `skip_migrations`]` link.
3. Renderer scrolls to the top of `configuration.md` (anchor not found) instead of jumping to the `#### `database.skip_migrations`` subsection.

Alternatively, with a markdown link checker:

```bash
markdown-link-check docs/cli-reference/tags.md
# Reports: configuration.md#database-skip_migrations  →  HASH NOT FOUND
```

### Reproduce link 2 (task-commands.md → workflow-config.md):

1. Open `docs/cli-reference/task-commands.md` at line 1013.
2. Click the `[Workflow Configuration](workflow-config.md)` link.
3. Renderer reports "file not found" — the actual file is `workflow-configuration.md`.

```bash
ls docs/cli-reference/workflow-config.md         # does not exist
ls docs/cli-reference/workflow-configuration.md  # exists
```

## Fix Notes

Two minimal edits — one per link.

### Fix 1 (tags.md:792)

**Option A (preferred — minimal-touch on the target file):**

Add an explicit HTML anchor immediately above the existing heading in `configuration.md`:

```markdown
<a id="database-skip_migrations"></a>
#### `database.skip_migrations`
```

This preserves all existing references that use `#database-skip_migrations` (the `tags.md` reference plus several mentions in `docs/plan/.../E28-F07-.../code_review/*`). The HTML anchor is GFM-safe and renders identically.

**Option B (touch only the originating file):**

Rewrite the link in `tags.md:792` to use the GitHub-generated slug or a different stable anchor:

- `(configuration.md#databaseskip_migrations)` — matches GitHub's actual slug, but the underscore-collapsed form is ugly.
- Promote the field to its own H3 (`### skip_migrations`) in `configuration.md` and link to `configuration.md#skip_migrations`. Requires reordering the configuration page slightly.

Option A is safest: lowest blast radius, preserves all existing references, no other docs need changing.

### Fix 2 (task-commands.md:1013)

Single-token change: `workflow-config.md` → `workflow-configuration.md`.

```diff
-- [Workflow Configuration](workflow-config.md) - Status flows and phases
+- [Workflow Configuration](workflow-configuration.md) - Status flows and phases
```
