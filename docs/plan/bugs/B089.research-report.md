# B089 — Change-card creation rejects supplied size

## Scope

Determine why `shark create change` rejected both `--size M` and `--size 3` while recording review-loop work, and whether the assigned revision still needs a repair. E07-F42 defines both inputs as canonical size 3. The parent configuration includes `change` in `size_required_for`.

## Findings

Each executable ran in its own empty temporary directory with Shark environment overrides removed, local SQLite, and a .sharkconfig.json containing `{"size_required_for":["change"]}`. Each invocation used a distinct title. SQLite readback of `change_cards` confirmed every stored size and the final row count.

| Invocation after the executable | Parent checkout's ./shark | Installed shark at 1dc22b13 |
| --- | --- | --- |
| create change TITLE --size M | Exit 1, size is required for change | Exit 0, stored 3 |
| create change TITLE --size 3 | Exit 1, same error | Exit 0, stored 3 |
| create change-card TITLE --size M | Exit 1, same error | Exit 0, stored 3 |
| change create TITLE --size 3 | Exit 0, stored 3 | Exit 0, stored 3 |
| create change TITLE | Exit 1, size required | Exit 1, size required |
| create change TITLE --size 4 | Exit 1, size required | Exit 1, invalid size |
| Final rows | 1 | 4 |

**Causal path.** Before B082, both unified commands registered the size flag and dispatched to `runChangeCardCreate`. That handler constructed `CreateChangeCardInput` without assigning `Size`. The service therefore received nil for both valid spellings. Its required-size check runs before key generation and persistence. Under an optional-size policy, the same omission could silently store NULL. The entity-first command used its own handler and forwarded the size correctly. B082 also found the unified handler omitted tags, another input shared by the two unified spellings.

**Delivered repair.** Commit `fda465cb` (PR #286) made both handlers use `readChangeCreateSizeAndTags`. It reads the invoking command's flags, calls `models.ParseSize` on explicit values, and forwards the canonical pointer and tags. `ChangeCardService.CreateChangeCard` checks the pointer, assigns it to the model, and the repository inserts it. The tests in `b082_unified_change_create_test.go` exercise the handler-to-service boundary. The SQLite runs above independently cover dispatch through persistence.

**Executable provenance.** The failing parent-root executable reports version `dev`. Go build metadata identifies `4e0e6878` with local modifications, and its SHA-256 is `60b67027fc201f1cd2bca4ccf2180c8fe2135ae9c7265334b8b740284b973729`. The successful PATH executable, `/home/jwwel/go/bin/shark`, reports `dev (1dc22b13)`, matching the worker checkout. The Makefile builds the CLI at `bin/shark`. B089 records neither the original executable path nor its revision, so the old binary reproduces the incident without establishing which copy the reporting process invoked.

## Decisions

Treat B089 as covered by B082 on `1dc22b13`. No further source change is indicated. Preserve required-size rejection, optional omission, invalid-input rejection, tag forwarding and entity-first compatibility. If the reporting workflow still fails, capture its resolved executable path and version in that process before reopening the implementation. Use a build containing PR #286 for review-loop intake.
