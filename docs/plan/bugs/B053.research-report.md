# B053 Research Report: admit.sh rejects valid non-empty p2p run selectors

## Scope

Bug B053 reports a deterministic false failure in `bench/scripts/admit.sh`'s `check_p2p_green()` function when a `p2p_set` specifies a non-empty `run_selector` (a `-run` regex pattern for filtering test execution). The check passes the selector to `go test` to filter which tests actually run, but computes the expected test-name list (`expected`) from ALL enumerated tests in the package, never filtering `expected` by the same selector. This causes intentionally-excluded tests to appear as "missing terminal events," deterministically reporting P2P-red even when the selected subset of tests passes completely.

**Evidence location**: Lines 448-457 of `bench/scripts/admit.sh`, plus the usage of `run_selector` at line 596 and its definition in `bench/README.md:167-169` (`"an optional `-run` regex"`).

**Repro**: With the fixture's `pkg/pricing` package having four top-level tests (`TestApplyDiscount`, `TestApplyFlatFee_AddsFeeToSubtotal`, `TestRoundedUnitPrice_ExactDivisionNeedsNoRounding`, `TestTaxAmount`):
1. `go test -json -run '^TestTaxAmount$' ./pkg/pricing` emits a terminal event only for `TestTaxAmount`
2. `testenum bench/fixture-repo/pkg/pricing` lists all four top-level tests
3. If a `p2p_set` specifies `run_selector: ^TestTaxAmount$`, `check_p2p_green` treats the other three tests as missing and fails P2P-green even though no other test was supposed to run

The mismatch between `results` (filtered by selector) and `expected` (not filtered) causes the false "missing terminal events" verdict.

The same pattern-generation logic should apply to filter `expected` by `run_selector` before the cross-reference check at lines 452-457.

## Findings

### Shape of run_selector

`run_selector` is a raw `-run` regex string read from `corpus.yaml`'s `p2p_sets.<id>.run_selector` (line 596). Example: `^TestTaxAmount$`. Currently, all defined p2p_sets in `bench/corpus/corpus.yaml` (lines 58-68) set `run_selector: ""` (empty string, treated as None/falsy), so the bug is not yet exercised in the corpus but would be triggered as soon as a non-empty selector is used.

### Shape of enumerate_tests output

`enumerate_tests(pkg_dir)` (lines 384-395) returns a Python set of bare top-level test names (e.g., `{"TestAlpha", "TestBeta", "TestGamma"}`). It never includes subtests in its enumeration — only the top-level function name is returned. This is by design: `testenum` is a separate Go module that parses `*_test.go` source files without compiling or running the package.

### Go's -run regex semantics

From the code comments at lines 306-313 and empirical testing: Go's `-run` pattern matches against each "/" separated segment of a test name independently. A pattern without slashes (e.g., `^TestTaxAmount$`) only needs to match the top-level test name for the entire test and all its subtests to be selected. This is consistent with Go's documented `-run` behavior — the pattern is "applied against the test name [and] '/' in a test name is a separator" and subtests inherit the parent's selection.

### Verification of go test -list

Empirical testing confirms `go test -list=<pattern>` exists (Go 1.26.0) and behaves correctly:
- `go test -list=. <pkg>` lists all top-level tests
- `go test -list='^TestTaxAmount$' <pkg>` lists only tests matching the pattern (same filtering as `-run`)
- Exit code is 0 even when the pattern matches nothing
- Output is exactly one test name per line (no subtests listed unless they match independently)

This is more robust than reimplementing Go's `-run` semantics in Python, which would require understanding slash-path matching and edge cases.

### Existing tests of admit.sh

Located in `bench/scripts/tests/`:
- `tc004_admit_full_set_test.sh`: Tests full corpus admission (all items, all checks)
- `tc005_admit_rejection_branches_test.sh`: Tests the five rejection branches with both committed and transient candidates
- `tc006_admit_reproducibility_test.sh`: Determinism verification
- `tc013_admit_offline_test.sh`: Offline hardening (golangci-lint presence check)

The test pattern is shell-based: each test script directly invokes `admit.sh` with corpus.yaml or transient candidates and validates the JSON output. No synthetic corpus with a non-empty `run_selector` currently exists.

## Decisions

**Recommended Fix**: Use `go test -list <pattern>` to filter the expected test list.

**Rationale**:
1. **Correctness**: Go's own `-list` flag is the authoritative source of which tests a pattern selects. No reimplementation risk.
2. **Maintainability**: Stays in sync with future Go changes to `-run` semantics automatically.
3. **Simplicity**: Single subprocess call; avoids error-prone regex pattern reimplementation.
4. **Precedent**: The admission gate already uses `go test`, so adding one more subprocess is consistent.

**Implementation sketch**:

In `check_p2p_green()`, after line 451, insert filtering logic:

```python
# If run_selector is specified, filter expected to only tests the selector would match
if run_selector:
    listed = subprocess.run(
        ["go", "test", "-list", run_selector, import_path],
        cwd=checkout_dir, capture_output=True, text=True
    )
    if listed.returncode != 0:
        raise RuntimeError(f"'go test -list' failed for {import_path}: {listed.stderr.strip()}")
    # Collect bare test names from listed output
    selected = {
        bare_test_name(line.strip())
        for line in listed.stdout.splitlines() if line.strip()
    }
    expected = expected & selected  # Intersect with go test's own selection
```

Then `expected` correctly reflects only the tests that would actually run under `-run run_selector`.

**Test coverage**: Add a new p2p_set to corpus.yaml with a non-empty selector (e.g., `run_selector: ^TestTaxAmount$` for `pkg/pricing` if a fixture item uses that set), ensuring admit.sh passes all five checks for a valid, selected-test subset and no longer reports false "missing terminal events."

## Pattern Contract

The filtering logic must preserve the semantic contract established in README.md lines 199-224 (REQ-F-003): a p2p_set's tests are the intersection of (package matches) AND (not excluded by p2p_sets.exclude_tests) AND (not excluded by item's f2p.test_names). With a `run_selector` present, the contract extends to: AND (selected by run_selector). The three filters (exclude_tests skip-pattern, run_selector, enumerated-name presence check) must all be applied consistently to both the actual test run and the expected-name list.
