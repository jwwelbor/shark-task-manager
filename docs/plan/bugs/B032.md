# shark get JSON omits size for bug feature change card

## Description

`shark get <key> --json` is inconsistent about exposing the `size` field across entity types. Epic shows it; bug, feature, and change card hide it. The field is settable on all four via their respective `<entity> update --size=` commands, and was added to the schema for Task/Feature/Epic/Bug/ChangeCard by E07-F42 (Task T-E07-F42-008). TechDebt and Idea correctly exclude it by design.

Triggered when checking B030 to verify its severity update — noticed `size` wasn't in the JSON keys despite `shark bug update --size=` being a documented option.

## Expected Behavior

`shark get <key> --json` includes the `size` field (and `size_label`, if available) for every entity type that has it in the schema: epic, feature, task, bug, change card. Value is the numeric points (1/2/3/5/8/13) or `null` if unset.

## Actual Behavior

```
$ ./bin/shark get E07 --json | jq 'has("size"), .size'
true
5

$ ./bin/shark get E07-F42 --json | jq 'has("size"), .size'
false
null

$ ./bin/shark get B030 --json | jq 'has("size"), .size'
false
null

$ ./bin/shark get CC-038 --json | jq 'has("size"), .size'
false
null
```

Only epic exposes the `size` key in its JSON output. Feature, bug, and change card all omit the key entirely (not even as `null`).

## Steps to Reproduce

1. Pick one entity of each type that supports size (epic, feature, bug, change card)
2. Run `./bin/shark get <key> --json | jq 'has("size")'` for each
3. Observe only epic returns `true`

## Fix Notes

Likely in the JSON serializer / DTO layer for bug/feature/change-card `get`. Epic already has the right shape — pattern-match it.

Cross-check `shark list <type> --json` outputs too — list and get should agree on which fields are exposed. Easy regression to introduce if size was wired into one path and not the other.

Reference: E07-F42 (add size field to all entities); T-E07-F42-008 (template-layer wiring; the same scope should have covered get/list output).
