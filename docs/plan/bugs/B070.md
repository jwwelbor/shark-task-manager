# shark status documentation claims dashboard support but CLI only exposes subcommands

## Description

Documentation in CLAUDE.md, quickref.md, and CLI reference states that 'shark status' displays project dashboard and 'shark status <key>' displays entity status. In implementation, shark status without subcommands prints help and directs users to 'shark progress'.

## Expected Behavior

Either:
1. `shark status` displays the project dashboard and `shark status <key>` displays entity status (as claimed in `CLAUDE.md`, `quickref.md`, and `docs/cli-reference/README.md`), OR
2. Documentation is updated to state that `shark progress [key]` / `shark get <key>` is the command for dashboards and entity inspection, and `shark status` is strictly a subcommand namespace (`set`, `advance`, `transitions`, `history`).

## Actual Behavior

Running `shark status` or `shark status <key>` (e.g. `shark status E40-F13`) invokes Cobra's default parent command behavior, printing the subcommand help page and adding:
`Use 'shark progress' for project/entity progress dashboards.`
`Use 'shark get <key>' for entity details.`

## Steps to Reproduce

1. Run `./bin/shark status` or `./bin/shark status E40-F13`.
2. Notice the help menu is printed rather than a dashboard or status display.

## Fix Notes

Decide whether `shark status` should attach a default `RunE` handler routing to `runProgress` / `runGet` when arguments are supplied, or align documentation across `CLAUDE.md`, `docs/cli-reference/`, and `quickref.md` to remove references to `shark status [key]` as a dashboard command.
