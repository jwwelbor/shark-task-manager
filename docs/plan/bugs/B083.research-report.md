# B083 research report — E40 harness switching and worker outcomes

## Scope

The original harness switch lost or forwarded the wrong model. The delivered E40 materializer now selects from the active CLI catalog, but the route can still change in keyed dispatch and a successful worker result can still be lost on return. The November 25 replay used worker checkout `ab7ef3b8`. Its committed `bench/` and `internal/` trees match the delivered candidate `3d7f2c77`. The latest owner-directed decision, Shark note 5055, settles how the existing Copilot fallback must behave during repair. [R17 evidence](B083.repair-plan-r17-evidence.md)

**Earlier keyed-dispatch investigation.** On the R10 development tree, the real scratch Shark can change a catalog-validated effort between the written workflow and the keyed dispatch. Even with an ordinary lowercase effort, the adapter can turn a successful Codex final message into a worker failure. Both failures reproduced offline in explicit-workflow and selected-profile modes. Development note 4601 returned R10 to research. Findings 4604 and 4607 identify the outbound and return boundaries respectively. [R10 development replay](B083.repair-plan-r10-evidence.md#development-replay-at-the-real-shark-request-boundary)

The **requested route** comes from the workflow or profile. The **effective route** is the provider, model and effort materialized for a stage. The **observed attempt** is the executable, arguments, start count and outcome at the worker boundary. Codex catalog membership establishes an advertised route. Service access can only be observed on an actual attempt. B083 covers E40 from preview through the retained lifecycle outcome. B077 owns native Rider dispatch attestation.

### Native callers and compatibility

Native Shark defines four case-insensitive effort levels and an omitted override. Both validation methods normalize for membership. They do not supply the dispatch value. In a separate scratch control, keyed `next` and `admin workflow show-action` both returned `high` for Codex `HiGh` and Anthropic ` HiGh `. Admin validation accepted both. For Codex `FixtureBoost`, validation rejected the native level and both reads returned `fixtureboost`. For omitted Anthropic effort, both JSON responses omitted the field and validation passed. This explains why validation alone cannot detect an altered advertised spelling or guarantee that an invalid native level stops a keyed read. [Native contract and validators](../../../internal/config/action/orchestrator.go#L30) · [Admin preview](../../../internal/cli/commands/workflow_show_action.go#L110)

Direct users of the population helper include epic, feature and task displays, entity status-action resolution and the task repository. Rider uses the native effort for worker selection. Changing the global projection or adding every catalog effort to native validation would broaden all these contracts. The current evidence establishes the populated value at the reader, with no claim about a native child's actual argv. ### Where the failure enters the lifecycle

1. The original capture at `f4b03228` found that the default adapter built `codex exec --json` for either requested model. The benchmark branch forwarded `-m` even for a Claude model. E40-F13 provided stage profiles and routing digests. An intermediate repair added production profile application but required a second, unavailable account catalog, blocking advertised routes before dispatch. These describe earlier revisions.
2. On `3d7f2c77`, the operator's `execute_profile()` path and batch preflight use run-local workflow materialization. The Codex client consumes paginated app-server `model/list` results. Both profile and explicit workflow routes feed the selected tuple into identity and the adapter request. The default Codex command adds `exec --json -m <model>` and the selected effort. The repro reached that executable. [Operator](../../../bench/scripts/lib/e40_benchmark.py) · [Catalog client](../../../bench/scripts/lib/codex_model_catalog.py) · [Materializer](../../../bench/scripts/materialize-routing-profile.py) · [Batch runner](../../../bench/scripts/run-lifecycle-batch.sh)
3. After a zero process exit, the adapter calls `decode_envelope()`. Its JSONL scan recognizes Copilot's `assistant.message/data.content`. Its fallback takes the last non-result object, which here is `turn.completed`. That record carries usage. The preceding `item.completed` with `item.type=agent_message` carries the worker's final text in `item.text`. The fallback never reads that text. A single Codex event object also misses the existing top-level wrapper keys. Parsing stops before `project_result()` can validate the worker outcome. [Adapter](../../../bench/scripts/lifecycle-worker-adapter.sh) · [Codex JSONL event contract](https://developers.openai.com/codex/noninteractive/#make-output-machine-readable)
4. The controller's `adapter_result()` receives a nonzero adapter exit. Its dispatch error path records the attempted stage as a worker failure. The older TC-123 recording adapter manufactured its own success or denial and counted adapter calls. That fixture could pass with zero Codex exec starts. The development record reports 162 passing Python checks alongside green Go gates using the earlier coverage. ## Decisions

**Carry exact effort across the keyed read.** For successor planning, use an opt-in projection on the setup-owned benchmark invocation of keyed `next`. At the final, entity-scoped Codex/OpenAI spawn action, retain the raw configured effort from the same loaded action used to populate the prompt. Select it for the benchmark wire response before preview, retention and request construction. The existing loader and entity-scoped lookup already have this value before normalization. Apply the choice to the resolved child after cascade and only to worker actions. Native reads keep their current projection. E40 owns exact catalog membership, including wrong-case rejection and omitted-pin resolution. Compare the keyed tuple against the materialized, source-qualified stage and frozen runtime identity before launch. A missing capability on an older setup binary or a mismatched route must produce an attributable route defect with zero starts. Generic admin validation continues to describe native workflow validity. The successor plan should name the opt-in interface, its scope and its compatibility tests. [Raw and populated lookup](../../../internal/config/action/service.go#L161) · [Keyed resolution](../../../internal/cli/commands/next.go#L849) · [Setup binary identity](../../../bench/scripts/lib/e40_benchmark.py)

An E40-only alternative could join the keyed entity type and status to the run-local materializer's qualified route, preserving the native response separately from the effective worker tuple. This avoids a CLI change but leaves the real keyed effort folded, introduces a second lookup for cascades and legacy layouts, and changes the meaning of retained dispatch evidence. Correcting argv alone has the same evidence gap. The opt-in approach can meet the existing exact-keyed-response requirement while preserving native semantics. A global change to the four-level vocabulary would require a Shark workflow owner decision. The narrower approach needs no such redefinition. [Qualified route collection](../../../bench/scripts/lib/e40_benchmark.py#L326) · [Retained dispatch](../../../bench/scripts/run-lifecycle.sh#L2526)

1. **Extend the existing E40 adapter.** Select the terminal completed agent message of the successful Codex turn and decode only its text for workflow authority. Exercise multiple messages, command/tool output containing envelope-like text, malformed/missing final text and failed or incomplete turns. Preserve direct envelopes, supported text outcomes and structured questions through existing projection. Keep nonzero process exits decisive. A feasible alternative is `--output-last-message` with a private per-attempt file. It adds argv, file handling and cleanup to every attempt. Include a positive mixed-case and novel advertised effort, an unadvertised wrong-case pin with zero starts, and a native control against the same binary. A YAML-derived request skips the newly established cause.
