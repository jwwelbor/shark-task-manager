# shark run stalls tech-debt at in_progress: check_or_resume treated as pause

## Description

The tech-debt workflow's in_progress step declares action: check_or_resume with a full dispatch spec (agent: developer, provider: anthropic, model: sonnet, skills, prompt: tech_debt/in_progress.md) — see internal/sharkdata/default_data/workflow/tech-debt.yaml (in_progress step, ~line 38). But the run controller groups ActionCheckOrResume with ActionPause/ActionWaitForTriage (internal/runner/controller.go:496): it sets outcome=paused and returns without dispatching. Result: 'shark run TD-###' silently stalls at in_progress and never invokes the developer agent, while 'shark next' dispatches the same step like spawn_agent — a run/next divergence. Decision needed: either dispatch check_or_resume in the run controller (resume-aware) or change the tech-debt workflow to spawn_agent. Impact: tech-debt entities cannot be driven end-to-end by shark run; also blocks tech-debt coverage in the planned shark-bench workflow benchmarking (Phase 2).

## Expected Behavior

`shark run TD-###` drives a tech-debt entity through its full workflow. When the entity reaches `in_progress`, the run controller dispatches the developer agent per the step's dispatch spec (agent/provider/model/skills/prompt are all declared on the step), exactly as `shark next` does for the same step.

## Actual Behavior

The run controller's action switch groups `ActionCheckOrResume` with `ActionPause`/`ActionWaitForTriage` (`internal/runner/controller.go:496`): it sets `outcome=paused` and returns without dispatching. The run reports "paused" and the developer agent is never invoked. `shark next` dispatches the same step, so run and next diverge on `check_or_resume`.

## Steps to Reproduce

1. In a scratch project (scripts/shark-scratch-env.sh), create a tech-debt entity and advance it to `in_progress` (default embedded workflow: `internal/sharkdata/default_data/workflow/tech-debt.yaml`, `in_progress` step declares `action: check_or_resume`).
2. Run `shark run TD-001 --verbose`.
3. Observe the run ends with outcome `paused` at `in_progress`; no agent process is spawned. Compare with `shark next TD-001`, which resolves the step as dispatchable.

## Fix Notes

Decision needed before fixing — two options:

1. Make the run controller dispatch `check_or_resume` (resume-aware: check for an existing claim/session, resume if present, dispatch fresh otherwise).
2. Change the tech-debt workflow's `in_progress` step to `spawn_agent` if `check_or_resume` is intentionally a next-only action — in which case the workflow validator should reject `check_or_resume` steps that carry a dispatch spec, so the mismatch can't recur silently.

Also blocks tech-debt coverage in the planned shark-bench benchmarking effort (Phase 2).
