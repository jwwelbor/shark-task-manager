# CLI contract drifts on status filters, exit codes, and case-insensitive keys

## Description

Full code review on 2026-07-07 found unified shark list silently drops --status for bugs changes and tech-debt, most RunE errors collapse to exit code 1, and several bug idea and link paths violate the case-insensitive key contract. See dev-artifacts/2026-07-07-full-code-review/code-review-report.md sections M7, M9, and M11.

## Expected Behavior

Verb-first and entity-first CLI paths should honor the same filters, non-not-found
errors should preserve the documented exit-code contract, and key handling should
remain case-insensitive anywhere the CLI accepts Shark keys.

## Actual Behavior

Unified `shark list` drops `--status` when routing bug, change-card, and tech-debt
list calls. Many bare `RunE` errors exit 1 regardless of failure class, and
several idea, bug-link, and `--link` detection paths still require exact casing.

## Steps to Reproduce

1. Run `shark list bug --status=<value>` and compare it to the entity-first bug
   listing behavior.
2. Trigger a non-not-found command failure and observe exit code 1.
3. Use lowercase keys in the affected bug, idea, or `--link` flows.
