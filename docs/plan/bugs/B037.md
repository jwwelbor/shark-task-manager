# Standalone server binds 0.0.0.0 and leaks raw mutation errors

## Description

Full code review on 2026-07-07 found cmd/server/main.go defaults to :8080, exposing unauthenticated mutation endpoints beyond loopback, while viewer mutation handlers return err.Error on 500s and skip request body caps on several write paths. See dev-artifacts/2026-07-07-full-code-review/code-review-report.md sections C3 and M8.

## Expected Behavior

The standalone server should default to loopback-only binding, return generic 5xx
messages on mutation failures, and cap request bodies on write paths.

## Actual Behavior

`cmd/server/main.go` returns `:8080` by default, which binds all interfaces.
The routed surface includes unauthenticated mutation endpoints, and viewer
mutation handlers return raw `err.Error()` strings on some 500 responses. Several
write handlers also skip `http.MaxBytesReader`.

## Steps to Reproduce

1. Start the standalone server entry point without an explicit address override.
2. Confirm it binds `0.0.0.0:8080` instead of `127.0.0.1:8080`.
3. Trigger a viewer mutation failure and observe the raw internal error in the
   HTTP response body.

## Fix Notes

Review source points:
- `cmd/server/main.go`
- `internal/cli/commands/web.go`
- `internal/api/viewer/mutation_handler.go`
- viewer write handlers called out in report section M8
