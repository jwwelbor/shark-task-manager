# Feature files created in wrong folder instead of using epic existing path

## Description

When creating new features under an epic, shark constructs a new folder name from the epic slug/title instead of reading the epic's existing `file_path` field from the database. This causes features and tasks to be placed in incorrect directories.

## Expected Behavior

`shark create feature E01 "..."` and `shark create task E01-F## "..."` should resolve the epic's existing `file_path` field and place files under that directory.

For example, with `E01` having path `docs/plan/E01-content-ingestion/`, a new feature F23 should go to:
```
docs/plan/E01-content-ingestion/E01-F23-async-pipeline-execution-via-celery/
```

## Actual Behavior

Shark generates a new folder name from the epic slug or title, producing incorrect paths:

| Entity | Expected Path | Actual Path |
|--------|--------------|-------------|
| F23, F24, F26, F27 | `docs/plan/E01-content-ingestion/E01-F2x-*/` | `docs/plan/E01-content-ingestion-epic-feature-prds/E01-F2x-*/` |
| F28, F29 | `docs/plan/E01-content-ingestion/E01-F2x-*/` | No `file_path` set at all |
| T-E01-F17-011 | `docs/plan/E01-content-ingestion/E01-F17-*/tasks/T-E01-F17-011.md` | `docs/plan/E01-E01/E01-F17-E01-F17/tasks/T-E01-F17-011.md` |

## Steps to Reproduce

1. Have an epic E01 with existing path `docs/plan/E01-content-ingestion/`
2. Run `shark feature create E01 "Some Feature Name"`
3. Observe the created feature's `file_path` — it uses a newly generated folder name instead of the epic's existing path

## Root Cause Hypothesis

The feature/task creation code constructs the epic directory path from the epic's slug or title rather than querying the epic's stored `file_path` field. The path construction logic should be replaced with a lookup of the epic's actual `file_path`.

Likely locations to investigate:
- `internal/taskcreation/creator.go` — task file creation
- `internal/cli/commands/feature.go` — feature creation command
- `internal/fileops/writer.go` — file path resolution
