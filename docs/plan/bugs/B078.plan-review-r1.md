Rows 1, 4 and 5 specify six selectors and service-only tech-debt coverage. On November 19 at 13:00 UTC, before the plan commit at 17:00 UTC, repository owner `jwwelbor` merged PR #285 at `c0a66d2fe9295107527a2c00f80933dabaedbca6`. Shark B079 notes 3622/3623 record review and QA of the delivered head, and 3802 records the merge. I verified the command, shared service and compiled contract files agree between that merge and remote main `f4b03228fa1a71efe295ecc051d8fd9f5dc6e40d`. The command registers seven selectors. Removing only the tech-debt flag would leave six successful CLI routes and a working `TechDebtService.UnlinkDocument` while breaking an accepted production command. [Merged PR #285](https://github.com/jwwelbor/shark-task-manager/pull/285) · [Shipped dispatcher, labels and selectors](https://github.com/jwwelbor/shark-task-manager/blob/c0a66d2fe9295107527a2c00f80933dabaedbca6/internal/cli/commands/related_docs.go#L186-L245)

Revise those rows around the shipped caller. Cover `--tech-debt` → `GetTechDebtService` → scoped unlink, JSON parent `tech-debt` (stored type `tech_debt`), and human confirmation with the selected key. Retain numeric and slugged key handling, trimming of padded tech-debt keys, rejection of blank/conflicting selectors before service access, retry on absence, ambiguity, and lookup/write failure. Reuse B079's tests for TD-002 deletion, TD-001 survival, and positional/explicit list readback. Preserve the other six mappings and the shared add/list behavior when integrating. Keep the confirmed B078 baseline when recording this delivered dependency. [Production CLI contracts](https://github.com/jwwelbor/shark-task-manager/blob/c0a66d2fe9295107527a2c00f80933dabaedbca6/tests/contracts/b079_research_cli_test.go#L78-L156)

For the other routes, the flag-to-output mappings are `--epic → epic`, `--feature → feature`, `--task → task`, `--bug → bug`, `--change → change-card`, and `--question → question`. The task uses `GetTaskServiceWithDocs`. The question uses its generic document service directly. Across all seven routes, successful JSON carries `status="unlinked"`, the supplied title and the public parent label. Human output is `Document unlinked from <label> <key>\n`. On main the command preserves the cause under `unlink document from <label> <key>`. A mislabelled change or tech-debt result can remove the right database row while misleading a caller.

### F2. Any nonzero exit satisfies the planned database-error test

T-E07-F05-003 and the project CLI standard distinguish successful unlink or confirmed absence (0), missing parent (1), and database failure (2). Row 4 accepts “nonzero with the cause.” The compiled test helper inspects the error message and never checks `ExitCode()`. A rejected database write carrying the correct text with exit 1 passes that assertion. The executable's fallback for an unclassified command error is exactly 1. Require the numeric exits at the compiled CLI boundary with a real missing parent and a forced database failure. Keep the cause, absence of confirmation, and persisted link checks. ### F3. One affected row can leave the exact association present

Proposal 3 accepts one affected row as sufficient evidence of removal. Using the project's `documents` and `entity_documents` DDL in SQLite 3.45.1, I measured the exact delete of `(task,452,563)`. A normal delete returned **1 affected / 0 present**. A fixture `BEFORE DELETE` trigger that ignores the delete returned **0 / 1**. An `AFTER DELETE` fixture trigger that restores the old row, including its ID and metadata, returned **1 / 1**. Restoration happens inside the same statement before it returns. This is a plan counterexample, with no evidence either trigger existed in WWGM.

Revise the success condition and row 3 so both retained-row cases return a specific error and suppress confirmation, while normal removal and verified absence succeed. Check the exact triple at a consistent completion point, distinguish verification failure from absence, and demonstrate the outcome through the command. This addresses B078's existing postcondition. ### F4. The proposed fixtures do not distinguish the entity-type predicate

Rows 2, 3 and 6 preserve other parents, but their stated pairs allow every parent to have a different numeric ID. Using the WWGM-shaped rows plus another task holding document 563, an in-memory delete filtered by only `entity_id` and `document_id` removed exactly the intended row. After adding `(bug,452,563,specification)`, the same incorrect predicate removed both the task and the bug link. Explicitly require a second **entity type sharing both the numeric ID and document ID**. Verify that its link, including a nondefault link type, survives. Exercise the same isolation on the exact-absence verification path. The schema allows the pair and distinguishes it by type. ### F5. The question assertion loses error identity while retaining the expected text

Row 5 requires a wrapped cause in its planned change, but its missing-question assertion checks the operation, key and lack of confirmation. Replacing `%w` with `%v` at the question wrapper preserves all three. Row 4 enumerates five other wrappers. The question path calls `GetQuestionDocumentService` directly, and the question repository supplies a real not-found sentinel. Require `errors.Is` on the error **returned by the question command handler** as well as the message at the process boundary.
