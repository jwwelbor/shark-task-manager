# shark next exits 3 on ready_for_code_review — unrendered `<review-base>` placeholder

## Description

`shark next <entity-key> --json` exits 3 with the error
`unrendered placeholder <review-base> left in prompt for <key>` when the
entity is in status `ready_for_code_review`. The post-render guard in
`internal/templates/agent_body.go` (`FirstUnrenderedToken`) is firing
correctly; the underlying gap is that the code-review agent body (or the
workflow renderer for that status) references a `<review-base>` token
that no placeholder generator populates.

## Expected Behavior

`shark next <entity-key> --json` returns a fully-rendered code-review
agent prompt (no unrendered `<token>` survivors) and exits 0, allowing
the dispatch loop to spawn the code-review agent.

## Actual Behavior

`shark next` exits 3 with:

```
[shark next] unrendered placeholder <review-base> left in prompt for B020
```

This halts the `/shark run` dispatch loop after the developer stage
advances the entity to `ready_for_code_review`.

## Steps to Reproduce

1. Be on the `shark2-engine` branch.
2. Have a bug (e.g. B020) at status `ready_for_code_review`.
3. Run `./bin/shark next B020 --json`.
4. Observe exit code 3 and the unrendered-placeholder error.

## Fix Notes

Likely either (a) the code-review agent body uses `<review-base>` but no
placeholder generator emits a `review_base` / `review-base` key, or
(b) the workflow YAML for the code-review status passes the wrong
variable name, or (c) the value is intentional but the alias was missed
when `AugmentPlaceholderAliases` was last extended. Investigation should
start by grepping `shark-data/` and `internal/sharkdata/default_data/`
for `review-base` / `review_base`, then tracing the placeholder map
that `shark next` assembles for `ready_for_code_review`.
