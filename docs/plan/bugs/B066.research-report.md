## Scope

B066 is limited to the workflow contract for routing code-review findings into work-item creation. The scope includes:

- **Review finding producers**: The canonical review-code.md skill workflow, tech-lead.md agent persona, deep-review/references/consolidator.md consolidation contract, and finish-feature shipping skill
- **Review triage consumer**: The triage skill at skills/shark-rider/skills/triage/SKILL.md
- **Mapping rule**: Every non-blocking review finding must pass through the explicit triage decision tree (fix-now gate, duplicate search, classification by type) before becoming an entity

The scope excludes:
- Task/feature/bug/change-card/idea creation commands (those correctly route through triage when invoked)
- Workflow automation and status-management logic
- UI or display of findings
- Specification language for individual review checks

## Findings

1. **Direct mapping of finding severity to entity type.** The review-code.md workflow at line 21 explicitly states `non_blockers_to_triage: list of {finding_id, file_line, rule, summary, fix_suggestion} — host files these as tech-debt`. Lines 53 and 260-263 reinforce this mapping without reference to the triage skill's decision tree. The output contract claims the host will "file as tech-debt" but provides no decision logic and no backward reference to the triage skill.

2. **Agent persona lacks triage methodology.** tech-lead.md line 34 says "Triage every finding" but does not reference the triage skill or the decision tree. It does not distinguish between findings that should be fixed immediately (Step 0: Fix-Now Gate), searched for duplicates, or classified by type (bug vs. tech-debt). The persona remains generic on how triaging happens.

3. **Consolidator and finish-feature gate repeat the same contract ambiguity.** consolidator.md line 81 says "host triages as tech-debt" for PASS-with-triage verdicts, and finish-feature.md line 27 requires "explicitly triaged" findings before merge. Neither specifies or references the triage skill's decision tree. They assume a shared understanding of "triage" that does not exist in the workflow output.

4. **Distribution split enables configuration drift.** Review prompts live in `internal/sharkdata/default_data/` (the embedded bundle) and are redeploy-only; the triage skill lives in `skills/shark-rider/skills/triage/SKILL.md` (repo tree). No shared contract file, no CI validation that they reference each other, no test gate preventing prompts from bypassing the triage decision tree. The B066 reproducibility confirms this: three separate instructions in three separate producers all drift in the same direction (direct mapping) with no contract to align them.

5. **Existing pattern for policy gates.** `internal/sharkdata/embed_test.go:1948-1980` (`TestEmbedded_AgentsDescribeRoleNotWorkflow`) validates purity rules by banning specific substrings from agent files. This is the canonical pattern for embedding policy enforcement and prevents future regression when the code is edited.

6. **Canonical triage decision tree exists and is unambiguous.** The triage skill (`skills/shark-rider/skills/triage/SKILL.md`) Step 0 (Fix-Now Gate) and Step 4 (Classify) establish the required contract: non-blocking findings **must** pass through a fix-now check, duplicate search, and type-classification gate before becoming entities. Findings classified as "bug" when they should be "tech-debt" or vice versa is the exact mislabeling B066 is trying to prevent.

## Decisions

1. **Update every review-finding producer** (review-code.md, tech-lead.md, consolidator.md, finish-feature) to explicitly reference the triage skill and mandate its decision tree for non-blocking findings. Replace "host files these as tech-debt" with "host routes these through the triage skill decision tree."

2. **Add a policy test** to the embedded-bundle test suite that scans review prompts and agent personas for the string "tech-debt" and requires that every instance be accompanied by or preceded by a reference to the triage skill or the triage decision tree. Prevent future edits from re-introducing direct mapping without the decision-gate reference.

3. **Create a shared contract document** (either at the top of each prompt or as a separate contract reference) that explicitly binds the review output (`non_blockers_to_triage` and PASS-with-triage verdicts) to the triage skill's Step 0 (fix-now check) and Step 4 (type-classification). This document lives in the embedded bundle and is referenced by both producers.

4. **Consolidate the triage references** in finish-feature.md to explicitly name the triage skill and link to it, since finish-feature is a critical gate before merge. Currently it says "explicitly triaged" but does not tell the host how or where to triage.

5. **Test coverage for the policy:** The new test extends the existing `TestEmbedded_` gate pattern. It verifies no review prompt maps finding-severity directly to entity-type without routing through the triage skill's decision tree. This repair extends the embedded-bundle policy enforcement infrastructure rather than inventing a new gate.

This repair extends the existing review-triage contract validation and policy-testing capability. It does not create new workflow states, new entity types, or new review checks. It enforces an existing decision tree that was documented in the triage skill but was not being followed by the review producers due to the distribution split and lack of a shared contract.
