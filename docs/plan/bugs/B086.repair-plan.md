## Host procedure

Put the unattended branch in Rider triage's routing contract. Invoke it from the embedded host handoff and the Rider review paths. Select it when the parent dispatch explicitly identifies a noninteractive review loop or says no respondent is available. Preserve ordinary confirmation for interactive intake. If mode is unknown and confirmation is needed, return the pending proposal to the parent. Silence, a missing TTY and a reviewer verdict grant no permission.

Process each surviving fingerprint using the following order. Record the inputs and the first applicable decision. This is a proposed host policy subject to independent approval.

1. Retain evidence-backed refutations and report-only nits. Determine accepted scope and blocker status first. Keep mandatory work with the active deliverable. Return it for repair through the parent when the worker is read-only, lacks budget, or needs an owner decision.
2. For discretionary work, choose Fix when the host has edit authority, the proposed edit is confined to already-changed lines or their directly covering tests, the correction is unambiguous, and a focused verification plus required candidate re-review fits the remaining authorized loop budget. Treat changes to public contracts, security, persistence or cross-owner behavior as higher stakes requiring separate scope authority. Use the proposed patch extent and affected boundary. The triage skill's approximate 20 lines is an example. For identical inputs take the same branch regardless of overall diff size or review-round number.
3. Source budget from the parent dispatch's remaining authorized attempts/time and the applicable project retry/escalation limit, using the tighter bound. Deduct consumed attempts once from each applicable total. Use a stated remaining allowance directly. At the applicable repeat-rejection limit, send an evidenced recurrence to the parent for owner judgment before spending another attempt. Compare the defect class, affected behavior and prior repair evidence across rounds. An unspecified allowance is unknown. If a required input for deciding scope, risk or budget is unknown, escalate. If a known budget cannot fund a discretionary Fix, or the edit extends beyond the local safe scope, consider Defer only with an explicit reason why accepted behavior remains satisfied.
4. For Defer, search the stable fingerprint first, then the plausible types and parents. Verify an existing item actually owns the same outstanding work. Otherwise classify and create only within explicit unattended write authority. Read back the project, key, type, scope and persisted fingerprint before recording Defer. A generic feature note, a closed unrelated item, a proposed key or a successful create exit alone is insufficient. A note on an already verified owner may record the association.
5. Write host outcomes separately from reviewer evidence. For each fingerprint retain the original candidate and finding, mode, decision inputs, reason, and either the resulting candidate plus repair and check receipts, or the verified owning key and readback. Record unresolved findings with the failed operation and parent action. Persist each confirmed outcome before proceeding to the next. On interruption or ambiguous creation, reconcile the tracker before retrying. If the previous write cannot be resolved, stop that write and escalate. Only the owning host serializes writes for a batch.
6. Reconcile all actionable findings before a host success, CI or merge handoff. After Fix, run focused verification and all required gates bound to the new candidate. Preserve earlier evidence for audit. A read-only worker returns findings to the parent to apply this procedure. Reviewer evidence alone never closes the host gate.
