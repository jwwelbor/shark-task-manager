# B079 research report

## Scope

Investigate whether a tech-debt research worker can retrieve the v2 universal
recipe catalog and register its report against the tech-debt entity. Trace the
prompt, embedded-resource loader, content getter, related-document CLI, and
tech-debt document service. The repair should preserve the existing catalog
source and document-link storage while making both capabilities usable from
the documented CLI.

## Findings

### Catalog access

The v2 `universal` recipe includes `tech_debt`, requires the five report
sections used by this artifact, and defines the category and module vocabulary
in `internal/sharkdata/default_data/research/recipes.yaml`. `LoadCatalog`
reads the configured `shark-data` override or default and falls back to the
embedded catalog. Research validation calls that loader, so workflow validation
can use the catalog when no `shark-data` directory exists.

The researcher-facing getter has a narrower contract. `shark skill get`
retrieves content only from the `skills/` bundle kind; `shark agent get`
retrieves `agents/`. The catalog is a separate `research/recipes.yaml` resource,
not a file under `skills/research/`. On 2026-11-18, installed Shark
`af80a92a` returned the research skill for `shark skill get research`, returned
`skill not found: research/recipes.yaml` for the valid nested-path form
`shark skill get research recipes.yaml`, and returned the reported unsupported
entity error for `shark related-docs list TD-595 --json`. This worktree also has
no materialized `shark-data/research/recipes.yaml`; the source catalog is
available in the repository, while the runtime's embedded fallback is not
exposed by a read-only CLI getter. `shark admin install-shark-data` writes the
whole bundle and may update `.sharkconfig.json`, so it is not a read-only
retrieval operation.

The prompt audit covered all five bundled research templates. `epic` and
`feature` name `shark-data/research/recipes.yaml`; `bug`, `change`, and
`tech_debt` only say to use the v2 catalog. The latter three therefore share
the missing-locator defect. The two explicit paths also depend on a materialized
bundle, unlike `LoadCatalog`'s embedded fallback.

### Tech-debt document registration

The related-docs CLI exposes add, delete, and list selectors for epic, feature,
task, bug, change, and question. It has no tech-debt selector. Positional list
selection calls the shared `DetectEntityType`, which recognizes `TD-###` as
`tech_debt`, but the related-docs whitelist excludes that type and returns
`cannot infer a supported entity type`. Add and delete likewise omit a
tech-debt dispatch branch. The maintained CLI reference and command help need
to include any newly supported selector.

The persistence and service layer already supports this entity. `TechDebtService`
has `LinkDocument`, `UnlinkDocument`, and `ListRelatedDocumentsByKey`; the CLI
accessor wires the service to the shared `EntityDocumentService` and polymorphic
document-link repository. The missing path is command exposure, not a new
document table or relationship model. I also found a stale `EntityDocumentRepository`
comment that lists the shared entity types without tech-debt.

This report targets bug B079, so its own report can be registered through the
existing `--bug B079` selector. That does not resolve the direct tech-debt
registration failure recorded for TD-595.

### Related work and prior disposition

B072 established positional key inference for related-document listing and
explicitly kept tech-debt and sprint outside that repair pending a separate
capability decision. B079 is the separate work item for deciding and delivering
that capability. Source inspection now
shows that the tech-debt service methods and shared persistence seam already
exist, so the extension can reuse them without expanding B072's original scope.

The preserved TD-595 research report records the original blocked result and a
later, explicitly authorized workaround: read the tracked core catalog, link
the report to existing task `T-E10-F02-011`, and record the exact report path
on TD-595. The report says this made that research usable but did not provide
direct tech-debt registration or catalog retrieval through the CLI. It also
names B079 as the owner of those host-contract defects.

## Capability map

| Capability | Decision | Evidence and implication |
|---|---|---|
| V2 recipe loading and validation | REUSE | `research.LoadCatalog` already applies configured disk and embedded fallback behavior; preserve that source of truth. |
| Read-only CLI retrieval of the recipe catalog | NEW | No command exposes the embedded or configured catalog. Add a read-only resource getter that uses the same source precedence, then name it in the research prompts. |
| Tech-debt document persistence | REUSE | `TechDebtService` and `EntityDocumentService` already link, unlink, and list documents for tech-debt entities. |
| Related-docs command contract | EXTEND | Add tech-debt routing to add, delete, and list, including positional `TD-###` inference, using the existing service and key detector. |
| Research prompt catalog locator | EXTEND | Update the bug, change, and tech-debt templates; use the same retrieval contract in all five templates so the locator does not depend on entity type or bundle extraction. |
| B072 positional key behavior | REUSE | Keep B072's generic inference and ambiguity handling; B079 separately adds the tech-debt type it intentionally left out. |

## Decisions

1. Add a read-only catalog getter, for example
   `shark data get research/recipes.yaml`, using the source precedence already
   implemented by `LoadCatalog`: configured override, installed default, then
   embedded catalog. Do not initialize or rewrite the project bundle. Update
   all five research prompts to name this retrieval path. Keep `shark skill
   get` scoped to skill content.
2. Extend `related-docs add`, `delete`, and `list` with a tech-debt selector
   that dispatches to `TechDebtService`. Reuse `DetectEntityType` for positional
   list keys so `TD-595` works through the established list form. Update command
   help and `docs/cli-reference/discovery-commands.md`, including the stale
   shared-service comment.
3. Add CLI contract coverage for tech-debt add/list/delete, positional list
   inference, and unsupported or conflicting selector input. Keep the existing
   generic document relationship model; this repair extends its command
   surface and adds one new read-only catalog retrieval surface.
