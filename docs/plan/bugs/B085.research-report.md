The process's final detailed-report list mentions findings and AC verification, omits F/G, and summarizes the verdict as PASS or FAIL. ## Decisions

- Extend the existing procedure. Have the host supply the absolute directory containing the loaded deep-review SKILL.md and verify the capture script and references exist there. A home-relative default would still assume a particular host layout. The source identifies no universal host environment variable for the loaded skill. Verify the instructions from an alternate installation path containing a space, with a separate target repository.
- Preserve each specialist's full-manifest requirement, including when the union covers all files. Persist INCOMPLETE with actual completion metadata for a gap. Keep the existing fallback ladder and the separate comparable-CLI contract. Use the native partial-result fixture and retained-angle admission checks as repair evidence.
- Give the detailed six-angle review a single content authority in the existing craft workflow. Keep rubric and applicable hotspots for detailed reports pending B088. Preserve a compact complete zero-finding PASS and a full report for retained findings regardless of diff size. Preserve decisions JSON, finding dispositions and host triage alongside the human-readable verdict. Keep the entity's outer outcome and feature-tier routing distinct from that verdict. Check the four rendered variants with a clean review, a tiny diff with a finding, and incomplete coverage.
- E34 note 3963 proposes evaluating removal of Nit and per-file scoring and retaining substantive standards and risk evidence. B088 records that evaluation. Neither source establishes approval for removal. B066/B067 previously required a follow-up when triage wording was updated in one producer and missed in the host skill. Recheck the standalone Rider instructions and rendered prompts together. No live reviewer or external host was required to reproduce the conflicting texts. Behavior of individual host path-discovery mechanisms remains an implementation verification item.

- Revise the approved plan before development resumes. Require a reviewer-authored `reviewed_files` array on the CLI decisions object, alongside its existing candidate identity. Retain it in the existing hashed decisions sidecar. Validate that every frozen manifest path is present using exact repository-relative names. Allow supplemental inspected paths. A count, a copied scope header, a finding path or a Markdown heading cannot distinguish two different same-size file sets. Parsing Markdown would also couple admission to report formatting. A separate sidecar would require another hash and evidence reference without adding an independent witness.
- Apply this check to every candidate CLI response before selection, recheck against the final frozen scope before persistence, and apply the same rule to direct writes and the Go verifier. Preserve bounded fallback across already eligible reviewers. Only a complete independent response may supply the verdict. If all eligible attempts lack coverage, retain INCOMPLETE with the missing paths or malformed-field reason and exit nonzero. Historical CLI reports without the field lack sufficient evidence for fresh admission or replay. Preserve the records and require fresh complete evidence when such a receipt is relied on.
- Add paired controls at both writer entries and through isolated parent code-review ingestion and QA replay. Hold scope and findings fixed, then vary full coverage, omission, duplicate or unrelated replacement with the same count, missing or malformed list, and wrong candidate identity. Include a full list plus a supplemental context path and a complete review with an actual blocker. Verify the stored sidecar and hash, successful complete control, rejection of partial evidence even with consistent hashes, and absence of a success transition for the rejected case. Retain the prior six-angle, feature-tier, I-04, finding-identity and severity checks from revision 6.
