# B076 Research Report — Legacy integration candidates without path digests

## Scope

B076 covers the final epic `integration_review` gate when it reads an
`integration-candidate.json` created before candidate-level tracked and
untracked path digests were added. The affected vocabulary is **integration
run** (the immutable epic base), **integration event** (one feature
completion), **integration candidate** (the accumulated candidate head),
**path-digest inventory** (the dirty tracked and untracked paths captured at
candidate-update time), and **backfill** (the operator bootstrap for an epic
that has no pre-execution integration run). This research does not change the
review gate's fail-closed rule or infer a base from Git history.

## Findings

1. The failure reproduces at the contract boundary. The candidate schema now
   contains `tracked_path_digests` and `untracked_path_digests`, and
   `UpdateCandidate` populates them from a real `git status --porcelain=v1 -z`
   walk before recomputing the candidate digest. `readCandidate`, however,
   accepts any JSON object that unmarshals into the struct; absent fields become
   nil maps and are not rejected. The historical candidate type before the
   path-digest change had only `epic_run_id`, `base_commit`, `head_commit`,
   `event_ids`, and `digest`, so pre-change records are accepted as structurally
   parseable but cannot prove that a path-digest inventory was captured.

2. The review prompt correctly refuses to infer missing integration evidence:
   it requires the run record and candidate, names the path-digest fields, and
   blocks when either record is missing, unreadable, or unverifiable. This is
   why a legacy candidate reaches `RECOMMENDED OUTCOME: blocked`. The current
   live candidate at `.shark/runs/c121f7ea-963d-4c53-9b7f-e97449a95955/integration-candidate.json`
   demonstrates the post-change shape: it contains both digest maps and a
   candidate digest.

3. The schema deliberately omits empty path-digest maps. The architecture
   states that `UpdateCandidate` records dirty-path digests and omits both maps
   when the working tree was clean. Therefore, “field absent” is ambiguous:
   it can mean a current clean-tree candidate or an older candidate that never
   observed the working tree. The repair must not make the review trust absence
   as proof, but it also must not classify every current clean-tree candidate as
   legacy solely because JSON omits empty maps.

4. The documented backfill workaround does not cover this defect. `Backfill`
   is designed for an epic with no pre-execution `IntegrationRun`; its
   validation rejects an existing registration/run and its recovery manifest
   rejects legacy partial state without a manifest. A legacy candidate that
   already has its run, events, and registration therefore cannot be repaired
   by the command named in the review prompt. The existing
   `TestBackfill_LegacyPartialStateWithoutManifestFailsClosed` test confirms
   that this fail-closed behavior is intentional for partial bootstrap state,
   but it does not cover migration of a complete pre-digest candidate.

5. The existing write path is the correct implementation seam for a repair.
   `FeatureService` folds completion events through `GetCandidate` and
   `UpdateCandidate`; `UpdateCandidate` already owns path-digest computation,
   candidate digest calculation, CAS publication, and archived-head retention.
   A migration should reuse those invariants and preserve the legacy
   candidate's `base_commit`, `head_commit`, and `event_ids`. It should not
   re-create a run, synthesize an event, or silently advance the review.

6. Targeted validation passed on 2026-09-21:
   `GOCACHE=/tmp/shark-b076-gocache GOMODCACHE=/tmp/shark-b076-gomodcache go test ./internal/integration -run 'Test(UpdateCandidate_CreatesCandidateFile|UpdateCandidate_DigestExcludesItself|Backfill_LegacyPartialStateWithoutManifestFailsClosed|ValidateEpicRunID)' -count=1`.
   The existing dirty-path test also covers staged tracked and untracked files,
   while the clean-tree test confirms both computed maps are empty. No
   production code was changed during this research, and no live LLM review
   replay was run; the reproduction is deterministic from the persisted schema
   and the review/backfill contracts.

## Decisions

1. Repair B076 by extending the existing integration-candidate capability with
   an explicit, authorized migration for already-registered legacy candidate
   records. The migration should read and verify the existing run/candidate,
   capture the current tracked/untracked path inventory through the existing
   helper, preserve the accumulated event/base/head identity, recompute the
   candidate digest, and publish through the existing archive/CAS safeguards.
   It should produce durable operator evidence that the legacy candidate was
   migrated before `integration_review` retries.

2. Make the persisted shape distinguish “inventory was computed and found
   clean” from “inventory was never captured.” The implementation can use an
   explicit candidate schema/version marker or a non-omitted, verified empty
   map representation; the choice belongs in implementation/specification
   work, but accepting nil maps as verified evidence is not safe. The migration
   must preserve old candidate bytes as an archived predecessor rather than
   overwriting history without provenance.

3. Keep `shark integration backfill` scoped to its current purpose. Do not
   broaden it to rewrite a registered run or regenerate events, because that
   would conflate pre-execution bootstrap with in-place candidate migration and
   weaken the existing registration/CAS boundaries. Add a separate migration
   operation or an explicitly named recovery mode with its own authorization,
   dry-run, conflict, and zero-mutation-on-rejection contract.

4. This is an extension of an existing capability, not a new integration
   review or candidate store. Implementation work should include regression
   partitions for: legacy candidate with a clean current tree; legacy
   candidate with dirty tracked paths; legacy candidate with untracked paths;
   already-migrated candidate; digest tampering; concurrent candidate update;
   missing run/event/registration state; and unauthorized migration.
