# shark next/run fail for every change-card regardless of status (ActionService.ForEntity not normalizing change_card->change)

## Description

shark next <CC-###> and shark run <CC-###> fail unconditionally for every change-card, at every status, including the default 'draft' status a freshly-created change-card starts in. Reproduced locally: ./bin/shark next CC-041 --json (a plain draft change-card in this repo's own DB) prints '[shark next] warning: status "draft" is not defined in the workflow configuration for entity type "change_card" -- treating as pause (B022)' even though examples/route-based-codex/workflow/change.yaml (the active workflow_config target) and the embedded default both define a full draft: step with outcomes. shark run CC-041 --dry-run fails the same way ('status change not found in workflow configuration'). Control case: shark next B033 (a bug entity) dispatches correctly, so this is change-card-specific, not a general engine break.

Root cause: internal/cli/commands/next.go:88 and internal/cli/commands/run.go:124 call actionSvcRoot.ForEntity(entityType) with the raw CLI/DB entity-type string "change_card" (as produced by DetectEntityType/ParseScope for CC-### keys, helpers.go:751-754). But internal/config/action/service.go's DefaultActionService keys s.statusData directly off whatever string ForEntity receives, with no normalization -- and the workflow-loading subsystem (internal/config/workflow/index.go normalizeIndexEntity, multilevel.go GetByType, aliases.go entityTypesForLoader) only ever registers a "change" key, never "change_card". So getStatusActionFor("change_card", status) misses the map lookup and returns StatusNotFoundError for literally every status value, before the YAML's step contents are ever consulted -- next.go's isStatusNotFoundError catches this and silently degrades to the B022 pause path, masking it as a legacy-status situation when it is actually a total entity-type lookup miss.

Two other call sites already apply this exact translation under an established 'ADR-1: change_card -> change' convention: internal/cli/commands/status_group.go:581 and internal/cli/commands/history.go:113. buildTransitioner/buildPlaceholderGenerator in run.go (lines 249-250, 270-271) also already handle both strings inline. Only the ForEntity() call sites in next.go:88 and run.go:124 were missed.

Surfaced 2026-07-05 via a bug report from ~/projects/wwgm: change-card CC-001 there (created by an AI agent's epic-intake-triage reclassification of epic E01 via shark create change -- a legitimate, non-buggy path, confirmed from the wwgm Claude session log ee58bd3b-0ca6-4249-8dbc-f47092c638c1) landed in the normal default draft status and then could not be dispatched via shark next at all, surfacing the same B022-shaped warning. That report initially looked like it might just be an edge case of B022's already-shipped graceful-degradation fix, but reproducing it locally against a plain draft change-card in this repo's own database (no wwgm involvement) confirmed it is a distinct, real defect in the change-card dispatch path, not expected legacy-status behavior.

## Expected Behavior

`shark next <CC-###>` / `shark run <CC-###>` should dispatch whatever step the active workflow config defines for the change-card's current status (e.g. the `draft` step's `advance_status` action), the same way it does for bugs, tasks, features, and epics.

## Actual Behavior

`shark next`/`shark run` unconditionally return the B022-shaped "status not defined in workflow configuration" pause/error for every change-card, at every status — including `draft`, the normal status a freshly-created change-card starts in — because the entity-type lookup into the action service's per-entity-type map never resolves for `"change_card"`.

## Steps to Reproduce

1. In a repo whose active `workflow_config` defines a `draft:` step for change-cards (true of both `internal/sharkdata/default_data/workflow/change.yaml` and `examples/route-based-codex/workflow/change.yaml`).
2. `shark create change "some title"` — lands in the default `draft` status.
3. `shark next <CC-key> --json` (or `shark run <CC-key> --dry-run`) — prints `[shark next] warning: status "draft" is not defined in the workflow configuration for entity type "change_card" — treating as pause (B022)` and returns `action: pause` with an error, instead of dispatching the `draft` step.
4. Contrast with `shark next <bug-key>` against the same database, which dispatches normally — isolating the defect to change-cards specifically.

## Fix Notes

Normalize `entityType` from `"change_card"` to `"change"` before calling `actionSvcRoot.ForEntity(entityType)` at `internal/cli/commands/next.go:88` and `internal/cli/commands/run.go:124`, matching the existing `"change_card"` → `"change"` normalization already applied under the "ADR-1" convention at `internal/cli/commands/status_group.go:581` and `internal/cli/commands/history.go:113`, and already handled inline by `buildTransitioner`/`buildPlaceholderGenerator` in `run.go:249-250,270-271`. Worth considering a single shared helper (e.g. `normalizeEntityTypeForWorkflow(entityType string) string`) so future `ForEntity`-style call sites can't miss this translation again — this is now at least the third call site to need it.
