# B044 Research Report: Sprint Next Claim-Awareness Gap

## Scope

**Bug**: `shark sprint next` ignores active claims and can dispatch the same sprint item to multiple concurrent agents.

**Affected Code**: `internal/services/sprint_service.go:GetNextTask()` (lines 1590–1696)

**Comparison Point**: `internal/cli/commands/next.go:resolveEntity()` (lines 481–687) which correctly filters claimed entities via `nextInfo.IsClaimed` before dispatch.

**Category**: Concurrent dispatch safety — two agents calling `shark sprint next` during an active sprint can both receive the same backlog item because claim state is not consulted in the selection path.

## Research Checklist

- [x] `scope_vocabulary` — Evidence: B044.md (bug description), sprint_service.go:1590–1696 (GetNextTask), internal/cli/commands/next.go:537–540 (claim filtering in keyed next)
- [x] `affected_implementation_or_contract` — Evidence: SprintService struct (internal/services/sprint_service.go:131–140) has no ClaimService dependency; GetNextTask filters only terminal status, never claims. ClaimService.IsClaimable exists (internal/services/claim_service.go:242–251) and is used by StandalonePlanningService (internal/services/standalone_planning_service.go:56–58, 215) as the standard filtering pattern.
- [x] `pattern_contract` — Evidence: next.go line 537–540 checks `nextInfo.IsClaimed` to pause claimed entities; standalone_planning_service.go:215 uses `s.claims.IsClaimable(ctx, string(candidate.EntityType), candidate.Key)` to filter candidates before dispatch. Both are read-only claimability checks that don't mutate lease state.

## Findings

### Current Behavior (Race Condition)

GetNextTask (lines 1590–1696) executes this sequence:
1. Lists all execution-phase sprints (lines 1600–1606)
2. Collects all non-terminal backlog items across sprints (lines 1617–1636)
3. Applies workflow terminal-status filtering via `workflowIndex.allows()` (line 1629)
4. Performs four-tier stable sort (lines 1642–1679)
5. Returns the top candidate without any claim check (line 1695)

**No ClaimService integration exists**: A `grep -n "IsClaimable\|ClaimService" internal/services/sprint_service.go` returns zero matches. The SprintService struct (lines 131–140) has no claim-aware field.

**Contrast with keyed next path** (next.go:537–540): After reading status via transitioner, resolveEntity immediately checks `if nextInfo.IsClaimed { resp.Action = "pause"; return resp, nil }`, blocking dispatch of claimed entities.

### Why This Matters (Race Window)

In a concurrent scenario:
- **Agent A** calls `shark sprint next` at time T1, receives Item-X (unclaimed at T1)
- **Agent A** begins work, establishes a claim on Item-X
- **Agent B** calls `shark sprint next` at time T2 (T2 > T1, Item-X still claimed)
- **Agent B** also receives Item-X because GetNextTask never checked the claim service

Both agents now hold the same item, violating the sprint dispatch contract.

### Claim-Aware Pattern (Template for Fix)

**StandalonePlanningService** (standalone_planning_service.go:94–116) demonstrates the correct pattern:
1. Accepts a `StandalonePlanClaimReader` interface with `IsClaimable(ctx, entityType, entityKey) (bool, error)` method
2. Iterates candidates and filters: `if !claimable { continue }`
3. Only returns candidates that pass `IsClaimable` check

**ClaimService.IsClaimable** (claim_service.go:242–251) provides the implementation:
- Returns `true` if entity is unclaimed OR has an expired lease
- Returns `false` if a live claim exists
- Sweeps expired leases as a side-effect (TTL backstop)

### Design Decision: Integration Path

Two options analyzed:

**Option A (Simpler, Lower-Risk)**: In-process filtering via read-only claimability check
- Add a `ClaimReader` interface to SprintService (narrow dependency: read-only check only)
- After GetNextTask collects candidates, filter out claimed items before sorting
- No transaction, no mutation — just read and skip
- Matches standalone_planning_service pattern exactly

**Option B (Stronger, Requires Redesign)**: Atomic next-and-claim path
- Merge GetNextTask and Claim into a single DB transaction
- Reduces the T1→T2 window but complicates the API and error handling
- Would require returning claim metadata alongside the item
- Not currently used by any other sprint consumer; breaking change to return signature

**Recommended**: **Option A** is the minimal correct fix. Claim filtering should be read-only and non-mutating at the sprint planning layer (like keyed next). If agents need an atomic lease-at-dispatch, that is an orchestration concern, not a selection concern.

### Minimal Fix Location

In GetNextTask, after line 1640 (after all candidates are collected):

```go
// Filter out claimed entities before sorting
claimable := make([]*BacklogItemView, 0, len(candidates))
for _, item := range candidates {
  ok, err := s.claimReader.IsClaimable(ctx, item.EntityType, item.Key)
  if err != nil {
    return nil, fmt.Errorf("failed to check claim for %s: %w", item.Key, err)
  }
  if ok {
    claimable = append(claimable, item)
  }
}
if len(claimable) == 0 {
  return nil, nil // No unclaimed items in sprint
}
candidates = claimable
```

Then proceed to sort and return the winner (existing logic, lines 1642–1695).

### Dependency Addition

**Required Change**:
1. Add a `ClaimReader` field to SprintService struct (similar to `assignmentRepo`, `capacityRepo` — optional, nil-safe)
2. Add a `SetClaimReader(reader ClaimReader)` method to inject it (matching the nil-safe degradation pattern)
3. Define `ClaimReader` interface locally in sprint_service.go with single method: `IsClaimable(ctx context.Context, entityType, entityKey string) (bool, error)`
4. In GetNextTask, guard the filter with `if s.claimReader != nil { ... filter ... }`

**No signature changes needed**: GetNextTask returns `*BacklogItemView` today; return type stays the same. Filtering is transparent to callers.

## Decisions

1. **Filtering is read-only**: Do not attempt to claim in GetNextTask. Filtering happens at plan time; claiming is orthogonal and happens at orchestration time (harness responsibility).

2. **Add optional nil-safe ClaimReader**: Follow the SprintService pattern for optional dependencies (assignmentRepo, capacityRepo, db). No breaking change if not wired.

3. **Early filter before sort**: Apply claim filtering (line ~1640) before the four-tier sort (line 1642). This avoids sorting items that will be discarded, saving cycles on large sprints.

4. **Guard all calls**: Every `s.claimReader.IsClaimable()` call happens inside `if s.claimReader != nil { ... }` so tests/legacy code that don't inject a claim reader continue to work.

5. **Preserve sort stability**: Use `sort.SliceStable` (already in use, line 1643) so repeated calls with same unclaimed set return same item.
