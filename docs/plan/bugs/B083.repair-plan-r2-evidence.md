## Runtime model catalog discovery

- **Owner rule:** Shark decision note 3959 says to discover Codex model identifiers from the Codex CLI, never maintain a static supported-model list, and treat the current picker values as evidence rather than code or test constants.
- **CLI version:** `codex-cli 0.171.0`.
- **Protocol schema:** `codex app-server generate-json-schema --out <temporary-directory>` generated the installed CLI's v2 protocol schema. `ModelListParams` accepts a continuation cursor. `ModelListResponse` returns `data` and `nextCursor`. Each model entry exposes `model`, `displayName`, `description`, `hidden`, `isDefault`, `defaultReasoningEffort`, and `supportedReasoningEfforts`.
- **Read-only runtime probe:** initialized `codex app-server --listen stdio://`, then requested `model/list` with `includeHidden: false`. The response contained 10 entries, including the eight current choices supplied by the owner and two additional catalog entries. The probe made no inference request and did not query `/v1/models` or read a credential file. Model identifiers are intentionally omitted from this evidence file.
- **Catalog limit:** OpenAI documents that app-server `model/list` can be bundled or cached catalog data. It establishes what the CLI advertises, not entitlement or successful service. Record account, quota, or service failures only after attempting the exact selected route.
- **Discovery/dispatch binding:** Revision 2 requires model discovery and adapter dispatch to use the same resolved CLI executable and effective configuration. Do not validate with one Codex installation and dispatch with another.
