# admit.sh rejects valid non-empty p2p run selectors

## Description

UAT round 4: bench/scripts/admit.sh check_p2p_green passes p2p_sets.<id>.run_selector to go test but computes expected terminal names from every static testenum result. A valid non-empty selector therefore leaves intentionally unselected tests in expected and deterministically reports P2P-red/missing terminal events. Evidence: bench/scripts/admit.sh:448-457; bench/README.md:23-25,56-73. Reproduce in pkg/pricing: -run ^TestTaxAmount$ emits only TestTaxAmount while testenum emits four top-level tests. Fix by applying the same selector semantics to expected names and add an admission test using a non-empty selector.

## Expected Behavior

For a `p2p_set` with a non-empty `run_selector`, admission should require
terminal events only for selected, non-excluded tests. A passing selected subset
must remain P2P-green both before and after the reference patch.

## Actual Behavior

`check_p2p_green` passes `run_selector` to `go test`, but calculates `expected`
from every `testenum` result. Tests intentionally omitted by the selector are
therefore reported as missing terminal events, making a valid selected P2P set
deterministically P2P-red.

## Steps to Reproduce

1. Run `bench/scripts/testenum` for `bench/fixture-repo/pkg/pricing`; it lists
   `TestApplyDiscount`, `TestApplyFlatFee_AddsFeeToSubtotal`,
   `TestRoundedUnitPrice_ExactDivisionNeedsNoRounding`, and `TestTaxAmount`.
2. Run `go test -json -run '^TestTaxAmount$' ./pkg/pricing` in the fixture; it
   emits terminal events only for `TestTaxAmount` and the package.
3. Configure that selector in a valid `p2p_set`. `admit.sh` treats the other
   three top-level tests as missing, despite their intentional exclusion.

## Fix Notes

Apply the same selector semantics when deriving the expected test names, then
add an admission test with a non-empty selector. Sweep all expected-versus-
observed result comparisons in the admission surface for predicates applied to
only one side of the comparison.

**Correction (implementation, 2026-08-27/28):** do NOT use `go test -list
<pattern>` for this, despite the earlier suggestion in this section and in
B053.research-report.md's Decisions. `admit.sh`'s own header (Evidence-
forgeability property, ~lines 76-78) already evaluated and rejected `-list`
as an admission-gate signal: it executes `TestMain`, making it exactly as
forgeable as every other package-under-test-controlled signal this file was
rewritten three times to stop trusting. A malicious `TestMain` could forge
`-list`'s output the same way it forges exit codes, shrinking `expected` to
hide a real failure. The shipped fix instead filters `expected` (testenum's
non-executing, non-forgeable enumeration) with a plain Python regex derived
from `run_selector`'s own top-level ("/"-split) element -- see
`run_selector_top_level_pattern` / `filter_expected_by_run_selector` in
`bench/scripts/admit.sh`. This never runs any code from the package under
test, preserving the file's trust model. The sweep found no second instance:
`f2p_red_or_green`'s run pattern (`anchored_alternation(f2p_ids)`) and its
expected set (`f2p_ids`) are already derived from the same source and cannot
diverge.
