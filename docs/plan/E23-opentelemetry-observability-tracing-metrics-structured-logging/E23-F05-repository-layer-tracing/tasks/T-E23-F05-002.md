# Add tracing to FeatureRepository

## Goal

Instrument FeatureRepository with a package-level OTel tracer and spans on all key CRUD and status methods, enabling visibility into feature-level database operations in any OTel-compatible backend.

## Scope

- Files to modify: internal/repository/feature_repository.go

## Acceptance Criteria

See spec.md REQ-F-001, REQ-F-002, REQ-F-003, REQ-F-004, REQ-F-005, REQ-F-007, AC-001, AC-002, AC-006.
- AC-T1: var repoTracer declared at package level in feature_repository.go (same variable name as other repo files; this is a package-level var, one per file)
- AC-T2: 8 methods from REQ-F-007 each have ctx, span := repoTracer.Start(...) as first statement
- AC-T3: defer span.End() immediately follows every Start call
- AC-T4: All error return paths call span.RecordError(err) and span.SetStatus(codes.Error, ...)
- AC-T5: make build succeeds with no new lint warnings

## Test Cases

See test-plan.md Category 1 (regression), Category 3 (build), and Category 2 case TEST-TR-003.

## Design Reference

See spec.md Architecture Section 3.3 (package-level tracer), Section 3.4 (method instrumentation pattern), Section 3.5 (span naming: FeatureRepository.MethodName), Section 3.7 (import management).

## Notes

The 8 methods to instrument are: Create, GetByID, GetByKey, Update, Delete, List, ListByEpic, UpdateStatus. Private helpers (getByExactKey, getByNumericKey, getBySluggedKey, listByEpicInTx) are NOT instrumented to avoid double-counting.
