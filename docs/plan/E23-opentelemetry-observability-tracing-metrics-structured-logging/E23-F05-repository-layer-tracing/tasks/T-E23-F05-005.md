# Write repository tracing tests

## Goal

Create a tracing test suite in internal/repository/ that verifies spans are created with correct attributes, errors are recorded on spans, and existing repository tests continue to pass without modification (no-op safety).

## Scope

- Files to create: internal/repository/tracing_test.go
- Files to modify: none (regression tests use existing test files)

## Acceptance Criteria

See spec.md AC-001 (compilation), AC-002 (test suite), AC-003 (span visibility), AC-004 (no-op overhead), AC-005 (error recording), AC-006 (attribute correctness).
- AC-T1: TEST-TR-001 through TEST-TR-008 from test-plan.md all pass
- AC-T2: testSpanExporter helper implemented in tracing_test.go
- AC-T3: spanAttrMap helper implemented in tracing_test.go
- AC-T4: Each test restores the original TracerProvider after completion
- AC-T5: make test ./internal/repository/... exits 0

## Test Cases

See test-plan.md Category 2 (all 8 test cases TEST-TR-001 through TEST-TR-008), Category 1 (regression), Category 3 (build verification), Category 4 (benchmark).

## Design Reference

See spec.md Architecture Section 3.3 (package-level tracer — no injection, test via global provider). See test-plan.md Test Helpers section for testSpanExporter and spanAttrMap implementations.

## Notes

Tests use sdktrace.NewTracerProvider with a synchronous in-memory exporter. The otel.SetTracerProvider call in each test must be paired with a defer to restore the previous provider. Repository tests run against the real test database (internal/test/testdb.go pattern). No mock repositories needed for these tests.
