# Add tracing to TaskRepository

## Goal

Instrument TaskRepository with a package-level OTel tracer and spans on all key CRUD and status methods, providing full database-level visibility for task operations in any OTel-compatible backend.

## Scope

- Files to modify: internal/repository/task_repository.go

## Acceptance Criteria

See spec.md REQ-F-001, REQ-F-002, REQ-F-003, REQ-F-004, REQ-F-005, REQ-F-006, AC-001, AC-002, AC-005, AC-006.
- AC-T1: var repoTracer declared at package level in task_repository.go
- AC-T2: 11 methods from REQ-F-006 each have ctx, span := repoTracer.Start(...) as first statement
- AC-T3: defer span.End() immediately follows every Start call
- AC-T4: All error return paths call span.RecordError(err) and span.SetStatus(codes.Error, ...)
- AC-T5: make build succeeds with no new lint warnings

## Test Cases

See test-plan.md Category 1 (regression), Category 3 (build), and Category 2 cases TEST-TR-001, TEST-TR-002, TEST-TR-006, TEST-TR-007, TEST-TR-008.

## Design Reference

See spec.md Architecture Section 3.3 (package-level tracer), Section 3.4 (method instrumentation pattern), Section 3.5 (span naming convention), Section 3.7 (import management).

## Notes

Depends on go.opentelemetry.io/otel being present in go.mod (added by E23-F01). The 11 methods to instrument are: Create, GetByID, GetByKey, Update, Delete, List, ListByFeature, ListByEpic, UpdateStatus, UpdateStatusForced, FilterCombined.
