# Add tracing to EntityNoteRepository

## Goal

Instrument EntityNoteRepository with a package-level OTel tracer and spans on the key CRUD methods, enabling visibility into entity note operations for task rejection, decision logging, and annotation workflows.

## Scope

- Files to modify: internal/repository/entity_note_repository.go

## Acceptance Criteria

See spec.md REQ-F-001, REQ-F-002, REQ-F-003, REQ-F-004, REQ-F-005, REQ-F-009, AC-001, AC-002, AC-006.
- AC-T1: var repoTracer declared at package level in entity_note_repository.go
- AC-T2: 5 methods from REQ-F-009 each have ctx, span := repoTracer.Start(...) as first statement
- AC-T3: defer span.End() immediately follows every Start call
- AC-T4: All error return paths call span.RecordError(err) and span.SetStatus(codes.Error, ...)
- AC-T5: make build succeeds with no new lint warnings

## Test Cases

See test-plan.md Category 1 (regression), Category 3 (build), and Category 2 case TEST-TR-005.

## Design Reference

See spec.md Architecture Section 3.3 (package-level tracer), Section 3.4 (method instrumentation pattern), Section 3.5 (span naming: EntityNoteRepository.MethodName), Section 3.7 (import management).

## Notes

The 5 methods to instrument are: Create, GetByID, GetByEntity, Delete, CreateRejectionNote. Complex search methods (Search, SearchWithTimePeriod, GetByEntityAndType, GetRejectionHistory) are explicitly out of scope per spec.md Section 5. The db.table attribute is "entity_notes" for all spans.
