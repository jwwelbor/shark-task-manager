# Add tracing to EpicRepository

## Goal

Instrument EpicRepository with a package-level OTel tracer and spans on all key CRUD and status methods, completing tracing coverage at the top of the entity hierarchy.

## Scope

- Files to modify: internal/repository/epic_repository.go

## Acceptance Criteria

See spec.md REQ-F-001, REQ-F-002, REQ-F-003, REQ-F-004, REQ-F-005, REQ-F-008, AC-001, AC-002, AC-006.
- AC-T1: var repoTracer declared at package level in epic_repository.go
- AC-T2: 7 methods from REQ-F-008 each have ctx, span := repoTracer.Start(...) as first statement
- AC-T3: defer span.End() immediately follows every Start call
- AC-T4: All error return paths call span.RecordError(err) and span.SetStatus(codes.Error, ...)
- AC-T5: make build succeeds with no new lint warnings

## Test Cases

See test-plan.md Category 1 (regression), Category 3 (build), and Category 2 case TEST-TR-004.

## Design Reference

See spec.md Architecture Section 3.3 (package-level tracer), Section 3.4 (method instrumentation pattern), Section 3.5 (span naming: EpicRepository.MethodName), Section 3.7 (import management).

## Notes

The 7 methods to instrument are: Create, GetByID, GetByKey, Update, Delete, List, UpdateStatus. Complex analytics methods (CascadeStatusToFeaturesAndTasks, GetEpicDisplayDataRaw, GetFeatureStatusBreakdown, etc.) are explicitly out of scope per spec.md Section 5.
