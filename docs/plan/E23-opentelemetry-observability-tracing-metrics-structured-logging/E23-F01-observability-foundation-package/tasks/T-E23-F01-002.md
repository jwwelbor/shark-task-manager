# Task: Add ObservabilityConfig struct to internal/config/config.go

## Goal

NOTE: Per the specification (section 3.1), the `ObservabilityConfig` struct lives in `internal/config/config.go`, NOT in `internal/observability/`, to prevent the import cycle `config -> observability -> config`. This task adds the struct definition to `internal/config/config.go` only. The parsing wiring in `manager.go` is covered in T-E23-F01-003.

Add the `ObservabilityConfig` struct definition to `internal/config/config.go` and add the `Observability` field to the existing `Config` struct.

## Requirements

### Functional Requirements

- [ ] Add `ObservabilityConfig` struct with all 9 fields and correct JSON tags to `internal/config/config.go`
- [ ] Add `Observability ObservabilityConfig` field to the `Config` struct with `json:"observability,omitempty"` tag
- [ ] Zero value of `ObservabilityConfig` disables all telemetry (all bool fields false, all strings empty)
- [ ] `omitempty` on the `Config.Observability` field causes JSON marshaling to omit the key when zero

### Non-Functional Requirements

- [ ] No breaking changes to existing `Config` struct callers (REQ-NF-005)
- [ ] `go build ./...` passes after changes

## Implementation Plan

### Steps

1. [ ] Read `internal/config/config.go` to understand the existing `Config` struct layout
2. [ ] Add `Observability ObservabilityConfig` field to the `Config` struct immediately before the `RawData` field
3. [ ] Add the `ObservabilityConfig` struct definition after the `Config` struct:

```go
// ObservabilityConfig holds configuration for the observability subsystem.
// All fields have sensible defaults; the zero value means "disabled".
// When Enabled is false, no OTel SDK is initialized and no network connections
// are made. Existing users without this key in their config are unaffected.
type ObservabilityConfig struct {
    Enabled        bool   `json:"enabled"`
    TracingEnabled bool   `json:"tracing_enabled"`
    MetricsEnabled bool   `json:"metrics_enabled"`
    LogLevel       string `json:"log_level"`
    LogFormat      string `json:"log_format"`
    Exporter       string `json:"exporter"`
    OTLPEndpoint   string `json:"otlp_endpoint"`
    OTLPProtocol   string `json:"otlp_protocol"`
    ServiceName    string `json:"service_name"`
}
```

4. [ ] Run `make fmt && make lint && make test` — all must pass

### Technical Approach

- Place the `ObservabilityConfig` struct immediately after the `Config` struct definition, before any method declarations on `Config`
- The `omitempty` tag ensures backward compatibility: existing callers marshaling `Config` to JSON will not see an `"observability"` key added if the field is zero
- No OTel imports are needed in `internal/config/` — this is a pure Go struct with no dependencies beyond the standard library
