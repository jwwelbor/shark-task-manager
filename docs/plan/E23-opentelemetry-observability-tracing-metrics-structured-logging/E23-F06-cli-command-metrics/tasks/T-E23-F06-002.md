# Write tests for CLI command metrics

## Goal

Provide unit test coverage for the command metrics wiring added in T-E23-F06-001, using a noop/mock OTel meter to verify that RecordInvocation and RecordDuration are called with correct arguments on success and error paths.

## Scope

- Files to create:
  - internal/cli/command_metrics_test.go (new test file)
- Files to modify: none (tests only)

## Acceptance Criteria

- AC-T1: Test verifies that a successful command invocation records status="ok" on both invocations counter and duration histogram
- AC-T2: Test verifies that a command returning an error records status="error" on the invocations counter
- AC-T3: Test verifies no panic when CommandMetrics is zero value (OTel not initialized)
- AC-T4: Test uses ResetObservability() for test isolation (see observability_global.go pattern)
- AC-T5: All tests pass make test with no race conditions

## Test Cases

- Happy path: run a stub command, assert RecordInvocation called with command name and nil error
- Error path: run a stub command returning error, assert error counter incremented
- No-op path: zero-value CommandMetrics, no panic when methods called

## Design Reference

See internal/observability/metrics_test.go for existing CommandMetrics test patterns.
See internal/cli/observability_global.go ResetObservability() for test isolation.
See .claude/rules/testing/architecture.md: CLI tests use mocks, never real database.
