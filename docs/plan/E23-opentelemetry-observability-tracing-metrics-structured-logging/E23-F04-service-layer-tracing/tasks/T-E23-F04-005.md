# Write service tracing tests

## Goal
Verify that all instrumented service methods emit correctly-named spans with the expected attributes, and that errors are recorded on the span. Uses the OTel in-memory exporter — no network, no database.

## Scope
- Files to create: `internal/services/task_service_tracing_test.go`
- Files to create: `internal/services/feature_service_tracing_test.go`
- Files to create: `internal/services/epic_service_tracing_test.go`

## Acceptance Criteria
See spec.md REQ-F-001 through REQ-F-008 (test coverage).
- AC-T1: Each test injects an in-memory exporter tracer via `SetTracer`.
- AC-T2: Happy path: span name matches `"<Service>.<Method>"` and expected attribute is present.
- AC-T3: Error path: span status code is `codes.Error` and error is recorded.
- AC-T4: Nil-tracer path: no panic, correct result returned.
- AC-T5: `make test` passes with zero failures; no real database used in these tests.

## Test Cases
See test-plan.md all sections (TC-TASK-01 through TC-TASK-07, TC-FEAT-01 through TC-FEAT-06, TC-EPIC-01 through TC-EPIC-05) and the "Helper Pattern" section.

## Design Reference
See test-plan.md "Helper Pattern" section for the `newTestTracerWithExporter` utility. Uses `sdktrace.NewSimpleSpanProcessor` + `tracetest.NewInMemoryExporter` from `go.opentelemetry.io/otel/sdk/trace/tracetest`.
