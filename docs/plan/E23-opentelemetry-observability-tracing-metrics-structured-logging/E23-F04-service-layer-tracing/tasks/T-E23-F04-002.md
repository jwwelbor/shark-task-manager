# Add tracer field and SetTracer to FeatureService

## Goal
Add an optional `trace.Tracer` field to `FeatureService` and instrument 5 key public methods with OpenTelemetry spans, providing visibility into feature-level operations.

## Scope
- Files to modify: `internal/services/feature_service.go`

## Acceptance Criteria
See spec.md REQ-F-002 and REQ-F-005.
- AC-T1: `FeatureService` struct has `tracer trace.Tracer` field.
- AC-T2: `SetTracer(t trace.Tracer)` setter exists on `*FeatureService`.
- AC-T3: Private `getTracer()` returns `s.tracer` or falls back to `otel.Tracer("shark/services/feature")`.
- AC-T4: Methods `GetFeature`, `ListFeatures`, `TransitionStatus`, `CompleteFeature`, `GetProgress` each start a child span, defer `span.End()`, record errors, and pass enriched ctx downstream.
- AC-T5: Span attributes include `feature.key` where applicable.

## Test Cases
See test-plan.md FeatureService section, cases TC-FEAT-01 through TC-FEAT-06.

## Design Reference
See spec.md Architecture "Tracer Field Pattern" section. Same pattern as T-E23-F04-001.
