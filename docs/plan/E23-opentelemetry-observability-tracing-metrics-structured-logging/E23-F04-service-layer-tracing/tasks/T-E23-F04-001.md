# Add tracer field and SetTracer to TaskService

## Goal
Add an optional `trace.Tracer` field to `TaskService` and instrument 7 key public methods with OpenTelemetry spans, enabling end-to-end visibility for all task operations.

## Scope
- Files to modify: `internal/services/task_service.go`

## Acceptance Criteria
See spec.md REQ-F-001 and REQ-F-004.
- AC-T1: `TaskService` struct has `tracer trace.Tracer` field.
- AC-T2: `SetTracer(t trace.Tracer)` setter exists on `*TaskService`.
- AC-T3: Private `getTracer()` returns `s.tracer` or falls back to `otel.Tracer("shark/services/task")`.
- AC-T4: Methods `CreateTask`, `GetTask`, `UpdateTask`, `DeleteTask`, `ListTasks`, `TransitionStatus`, `GetNextStatus` each start a child span, defer `span.End()`, call `span.RecordError` + `span.SetStatus` on error, and pass enriched ctx downstream.
- AC-T5: Span attributes follow spec.md Architecture "Methods to Instrument" table.

## Test Cases
See test-plan.md TaskService section, cases TC-TASK-01 through TC-TASK-07.

## Design Reference
See spec.md Architecture "Tracer Field Pattern" and "Span Instrumentation Pattern" sections for exact field placement and import list.
