# Add tracer field and SetTracer to EpicService

## Goal
Add an optional `trace.Tracer` field to `EpicService` and instrument 4 key public methods with OpenTelemetry spans, completing service-layer coverage at all three entity levels.

## Scope
- Files to modify: `internal/services/epic_service.go`

## Acceptance Criteria
See spec.md REQ-F-003 and REQ-F-006.
- AC-T1: `EpicService` struct has `tracer trace.Tracer` field.
- AC-T2: `SetTracer(t trace.Tracer)` setter exists on `*EpicService`.
- AC-T3: Private `getTracer()` returns `s.tracer` or falls back to `otel.Tracer("shark/services/epic")`.
- AC-T4: Methods `GetEpic`, `ListEpics`, `TransitionStatus`, and the complete/approve equivalent each start a child span, defer `span.End()`, record errors, and pass enriched ctx downstream.
- AC-T5: Span attributes include `epic.key` where applicable.

## Test Cases
See test-plan.md EpicService section, cases TC-EPIC-01 through TC-EPIC-05.

## Design Reference
See spec.md Architecture "Tracer Field Pattern" section. Same pattern as T-E23-F04-001 and T-E23-F04-002.
