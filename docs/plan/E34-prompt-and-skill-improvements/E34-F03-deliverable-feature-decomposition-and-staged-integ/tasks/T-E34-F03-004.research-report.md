# Research report: Align the F02 readiness consumer and cross-surface regression guard

## Scope

This task extends the E34-F02 feature brief as the read-only consumer of the
map-assigned I-01 readiness evidence shape, and extends the existing
rendered-prompt/direct-content regression boundary. The consumer must preserve
all nine fields and classify an open activation as `pending-integration`; it
must not implement the demo recipe, redefine readiness, create a second I-##
row, or create a producer-only test.

The concrete affected contract is the documented F03-to-F02 handoff in
`E34-interaction-map.md#i-01-readiness-evidence-shape` and the corresponding
bundle-integrity check in `internal/cli/commands/interaction_prompts_test.go`.
This task extends those content contracts only. It introduces no persistence,
runtime, CLI behavior, schema, or workflow-transition work.

## Findings

1. I-01 is already assigned in `E34-interaction-map.md`: E34-F03 produces the
   documentation-policy shape, E34-F02 consumes it read-only, and E34-F02 is
   the activation owner. Its shared structural pointer is
   executable TC-I-01-READINESS-SYMMETRY; no new I-## or consumer-specific
   test may be invented. Historical TC-002 covers rendered prompts only.

2. The F02 brief already contains the required integration-contract location.
   Its consumer wording must enumerate assessor verdict, owner decision, open
   conditions, gate mode, activation owner, closure key, counterpart status,
   review basis, and demonstrability disposition, and must leave open
   activation as `pending-integration`. Completion markers, a demo, or an
   owner override cannot substitute for closed production-path evidence.

3. The amended scope verifies that the interaction map plus the F03 and F02
   feature files exist. Review the readiness wording manually against the
   specification instead of requiring a vocabulary-drift assertion.

4. The established `interaction_prompts_test.go` pattern uses the real
   orchestrator renderer for templates and verifies the documented map and
   feature-file references. Do not add a classifier, runtime fixture, database
   dependency, or vocabulary-matching test.

5. No related capability is newly discovered. The parent Capability map in
   `../research-report.md` already classifies E34-F02 as an EXTEND of the
   producer contract; this report intentionally cites it rather than copying a
   second Capability map.

## Decisions

1. **Extend the map-assigned consumer contract.** Mirror I-01 and its
   TC-I-01-READINESS-SYMMETRY pointer verbatim in the F02 brief, preserving all nine readiness
   fields as read-only input to truthful demo classification.

2. **Validate the documented handoff.** Confirm that the map, F03 feature, and
   F02 feature files exist; review the consumer wording against the
   specification.

3. **Keep scope content-only.** Do not add a demo implementation, a readiness
   classifier, a new test identifier, a runtime abstraction, or any Shark
   persistence/workflow change. The existing real-renderer and direct-file test
   patterns are sufficient.
