# Research report: Preserve UAT gate integrity and activation closure

## Scope

This task extends the bundled UAT policy contract in
`internal/sharkdata/default_data/skills/uat/SKILL.md`, its red-team rubric,
and the UAT agent persona. It also extends the rendered-content regression
boundary in `internal/cli/commands/interaction_prompts_test.go`. The policy
must keep the independent assessor verdict, owner decision, conditions, and
demonstrability disposition as distinct facts; it must keep missing live
wiring, authentication, authorization, integrity, unsafe exposure, and an
unmet current acceptance criterion blocking even when a future owner or
`override-accept` exists.

For a declared `contract-only` edge, the activation owner must prove the real
caller chain, shared-contract evidence, production-path integration test, and
wiring-removal counterfactual before internal epic completion. This is a
content and test-contract extension only: it introduces no runtime state,
workflow transition, database schema, or automatic acceptance decision.

## Findings

1. The established UAT policy separates assessment from approval: the skill
   makes Codex the sole assessor, reserves final approval to the user, and
   forbids auto-completion. The task should make the related reported facts
   explicit rather than introduce an override mechanism that mutates the
   assessor verdict.

2. The current rubric already makes a CRITICAL/HIGH finding and an unwired
   component a rejection/blocker. The extension must enumerate the E34
   non-waivable classes in every UAT surface: missing live caller (including an
   undeclared edge), authentication, authorization, integrity, unsafe
   exposure, and an unmet current acceptance criterion. Crossing each class
   with either a named future owner or `override-accept` must remain blocking.

3. Existing quality QA supplies the required closure-proof pattern, but the
   UAT skill, rubric, and agent must carry it consistently. A complete
   `contract-only` declaration changes only the staged disposition; it does
   not represent verified end-to-end delivery while its activation obligation
   remains open.

4. The amended test plan validates the UAT bundle through rendering, include
   resolution, golden snapshots, and documented-file checks. Review non-waiver,
   fact-separation, and closure wording against the specification rather than
   using wording-mutation tests.

5. No new related capability is discovered. The parent feature Capability map
   at `../research-report.md` already classifies the UAT wiring/verdict policy
   as an EXTEND responsibility, so this task intentionally does not duplicate
   a Capability map.

## Decisions

1. **Extend the existing UAT policy surfaces.** Add explicit language to the
   UAT skill, rubric, and agent; do not add a persistence model, workflow
   state, or decision-writing command.

2. **Keep the assessor verdict immutable as a reported fact.** Record the
   independent assessor verdict, owner decision, conditions, and
   demonstrability disposition separately. An owner decision may govern
   workflow handling, but it cannot rewrite a blocking assessment into a
   verified delivery claim.

3. **Make blocker wording clear.** A future key, activation owner, or
   `override-accept` cannot waive missing live wiring,
   security/authentication/authorization, integrity, unsafe exposure, or a
   current-feature AC. Review this policy wording against the specification.

4. **Require activation-owner closure proof before internal completion.** The
   closure record requires caller-chain, shared-contract, production-path, and
   wiring-removal evidence. An unresolved internal obligation remains pending
   integration rather than accepted end-to-end work.

5. **Validate bundle integrity.** Use the established renderer, golden
   snapshots, and documented-file checks. Review policy wording manually;
   do not simulate prose decisions in tests.
