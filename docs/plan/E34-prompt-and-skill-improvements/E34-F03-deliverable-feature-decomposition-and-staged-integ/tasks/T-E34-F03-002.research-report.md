# Research report: Propagate staged-edge rules through feature and quality gates

## Scope

This task extends the existing design-time feature and quality-gate content
contracts so every consumer of an interaction-map `I-##` row preserves the
same staged-edge disposition. It covers feature specification, test planning,
task generation and review, code review, QA, and the four quality workflows.
It does not introduce a persisted field, workflow state, runtime enforcement,
or a parallel acceptance ledger.

The authoritative vocabulary and capability decisions remain in the parent
feature report at `../research-report.md`. In this task, **live** remains the
default disposition; a complete **contract-only** declaration must retain the
map-assigned mode, counterpart entity and status, shared evidence, activation
owner, closure key, and review basis through every downstream gate.

## Findings

1. The repository already propagates cross-feature contracts as markdown
   policy, rather than runtime data: task review requires each declared `I-##`
   to be mirrored in task specifications with the map's shape source and one
   shared test pointer, while QA requires a wiring-coverage row for each
   produced or consumed `I-##`. The staged-edge fields must extend that same
   contract rather than create a new review artifact.

2. The currently affected feature prompts and quality workflows have related
   but incomplete views of the contract. Feature authoring/generation surfaces
   establish what work and tests will exist; task review and design validation
   reject missing or mismatched I-## coverage; code review and QA evaluate the
   implemented evidence. Each must explicitly carry the map's mode,
   counterpart status, shared evidence, activation owner, closure key, and
   review basis, so a partial declaration cannot become acceptable merely by
   moving downstream.

3. `qa-testing.md` already makes zero non-test call sites, a missing
   production caller-signature test, or missing I-## wiring coverage an
   automatic failure. The extension must preserve those hard gates for `live`
   edges. For a complete, predeclared `contract-only` edge, its documentation
   evidence and named closure remain reviewable, but it does not waive a
   missing current security, integrity, or acceptance requirement.

4. The amended test plan requires real rendering, include resolution, golden
   snapshots, and documented-file checks. It does not simulate staged-edge
   decisions or require wording-mutation tests for this content-only change.

5. This task does not discover a new related capability. The parent feature
   Capability map already records the relevant EXTEND decisions for the
   interaction-map lifecycle and feature-to-quality propagation; no additional
   Capability map is added here.

## Decisions

1. **Extend the existing I-## propagation contract.** Treat the parent map as
   the sole source of staged-edge values. Every named consumer mirrors its
   fields and rejects absent or mismatched values; it must not invent an ID,
   counterpart, evidence pointer, or closure disposition.

2. **Keep `live` strict.** Existing QA reachability, caller-signature, and
   I-## wiring-coverage failures remain blocking for live work. A later Shark
   key or owner decision cannot turn an undeclared or incomplete live edge into
   a passing result.

3. **Constrain `contract-only` at every gate.** It is valid only when declared
   no later than specification and confirmed by task review with all six map
   fields. Review and QA must retain the activation owner's closure obligation
   and warn on reverse build-order consumption; incomplete internal closure
   prevents epic completion.

4. **Validate bundle integrity.** Render the changed prompts, refresh intended
   golden snapshots, and verify documented file references. Review policy
   wording manually against the specification.
