# Task: Implement `shark impact record` CLI command

## Goal

Add the thin CLI wrapper registering `shark impact record <entity-key>
--source-kind=<kind> --source-key=<key> --source-pointer=<path>
--impact-file=<path>` — the exact flag-based ADR-adoption boundary
architecture.md's "Compatibility and migration" section declares — and prove
happy-path/not-found/persistence behavior end to end, per spec.md's
"Component changes" (`impact_cmd.go` row) and Key technical decision #1.

**REWORK (UAT round 1, HIGH-1):** the original implementation used a
positional `<entity-key> <content-or-@file>` shape that diverged from
architecture.md's flag-based contract. That positional form is removed
entirely — architecture.md documents only the flag form.

## Scope

- Create: `internal/cli/commands/impact_cmd.go` (`runImpactRecord` — parses
  the entity-key positional arg and the four required flags, reads
  `--impact-file`'s bytes, merges `--source-kind`/`--source-key`/
  `--source-pointer` into that JSON as the authoritative top-level I-04
  fields (overriding any value already in the file), calls
  `services.ImpactService.RecordImpact`, formats `--json`/success output per
  `notes_add_dispatch.go`'s thin-wrapper precedent)
- Create: `internal/cli/commands/impact_cmd_test.go`

## Acceptance Criteria

See spec.md AC-4 (command-level half). Task-specific: exits non-zero on a
nonexistent target key; exits non-zero (via cobra's `MarkFlagRequired`) when
any of the four flags is omitted; `--impact-file` reads real file bytes (not
the literal path string) and fails clearly on a missing/unreadable file, zero
repo calls; the `--source-kind`/`--source-key`/`--source-pointer` flag values
are merged into the persisted note content, overriding any conflicting value
already present in the impact-file.

## Test Cases

test-plan.md TC-007, TC-008, TC-009 via the registered Cobra command per
Caller-Path Contracts (mock the entity-type repository and
`NoteEntityNoteRepository`; never `ImpactService`/`NoteService`), driven
through `cmd.SetArgs(...)` + `cmd.Execute()` on a freshly-built command
registering the same flags as production `impactRecordCmd`, per
`change_test.go`'s isolated-cobra-command convention — this exercises real
cobra flag parsing (including `MarkFlagRequired`), not just a direct
Go-function call with pre-populated flag values. TC-007 also runs once
against a real repository pair to confirm genuine persistence.

## Notes for Agent

Don't mock `os.ReadFile` for `--impact-file` (TC-008) — use a real temp file
so the file read is genuinely exercised. Merge the
`--source-kind`/`--source-key`/`--source-pointer` flags into the
impact-file's JSON before calling the service (flags win on conflict); if the
impact-file's bytes are not valid JSON, pass them through to the service
unchanged so `ImpactService`'s existing malformed-content error fires,
instead of shadowing it with a CLI-layer parse error.
