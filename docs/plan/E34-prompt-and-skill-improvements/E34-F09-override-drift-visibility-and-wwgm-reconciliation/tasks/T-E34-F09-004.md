# Task: Add shark admin overrides CLI command group

## Goal

Wire the classifier and acknowledge functions to a new CLI command group so
operators can run `shark admin overrides status` and `... acknowledge`, per
spec.md "REQ-F-001 (spec)" and "REQ-F-002 (acknowledge)".

## Scope

- Create: `internal/cli/commands/overrides_cmd.go` — `overridesCmd` group
  (registered via `adminCmd.AddCommand`), `status`/`acknowledge`
  subcommands, human + `--json` rendering.
- Create: `internal/cli/commands/overrides_cmd_test.go`
- Modify: `docs/cli-reference/setup-commands.md` — document both subcommands.

## Acceptance Criteria

See spec.md AC "empty overrides" JSON shape and "acknowledge success/
failure" exit codes.
- AC-T1: `status`/`acknowledge` resolve project + data root exactly as
  `runSharkUpgrade` does (`cli.FindProjectRoot()` +
  `config.ResolveSharkDataRoot`).
- AC-T2: `acknowledge` failure exits non-zero and names the failing path.

## Test Cases

See test-plan.md TC-001, TC-007, TC-008 exercised at the CLI layer (human
and `--json` output). Caller-Path Contract: production `overridesCmd`
handlers, no mocked repository (filesystem-only).

## Design References

Follow the `cloudCmd`/`configCmd` nested-group pattern in
`internal/cli/commands/cloud.go` (spec.md "REQ-F-001 (spec)").

## Brownfield Context

No `overridesCmd` or `overrides` admin subcommand exists today
(research-report.md Capability map); `adminCmd`'s existing children
(`cloudCmd`, `configCmd`, `workflowCmd`) are the only prior art.

## Notes for Agent

Command handlers are thin adapters — all classification/write logic lives
in `internal/sharkdata` (T-E34-F09-002, T-E34-F09-003); do not duplicate it
here.
