# Resolve and inject harness metadata in shark next (NextResponse + resolveEntity)

## Goal
Wire `HarnessResolver` (T-E34-F01-003) and the persisted claim (T-E34-F01-002)
into `shark next`, so a rendered prompt actually branches on resolved harness
identity and the resolution is observable on `NextResponse`.

## Scope
- Files to modify: `internal/cli/commands/next.go`,
  `internal/cli/services_global.go`.
- Files to create: `internal/cli/commands/next_harness_test.go` (mocked
  services per `.claude/rules/cli/commands.md` — no real database).

## Acceptance Criteria
Reference spec.md: "See spec.md AC-02, AC-03, AC-04, AC-05, AC-06, AC-13"
- AC-T1: Three additive `NextResponse` fields (`Harness`, `HarnessVersion`,
  `HarnessModel`), each `omitempty`, placed after `Effort` and before
  `Prompt` (spec.md §3.2).
- AC-T2: Harness vars are merged into `vars` immediately after
  `templates.AugmentPlaceholderAliases(vars)` and before
  `GetStatusActionPopulated` (spec.md §3.3).
- AC-T3: `GetHarnessResolver()` follows the existing lazy global-accessor
  pattern in `internal/cli/services_global.go`.

## Test Cases
- TC-003/004 (test-plan.md): claimed `harness=claude`/`codex` — branching
  template renders the matching arm only.
- TC-005 (test-plan.md): no claim, no env — exit 0, generic arm renders,
  `harness` absent from JSON.
- TC-006 (test-plan.md): claim=codex, env=claude, flag=claude — flag beats
  claim beats env.
- TC-007 (test-plan.md): claim=codex (no version), env version=9.9 —
  resolved per-field, not per-source.
- TC-016 (test-plan.md): bare-form `{{.harness}}` with no claim/env — exit 0,
  no literal `<no value>` leaked.
- TC-018 (test-plan.md): `ClaimReader.Get` errors — exit 0, generic branch
  renders, a warning is logged, never a render error (D-F01-05).
