# Add harness columns to entity_claims (schema 34->35) and extend EntityClaim model

## Goal
Add the persistence foundation for harness identity: three nullable columns on
`entity_claims` and the corresponding `EntityClaim` model fields with length
validation, so later tasks have a place to read and write harness metadata.

## Scope
- Files to modify: `internal/db/db.go`, `internal/models/entity_claim.go`,
  `internal/db/db_test.go`, `internal/models/entity_claim_test.go`.
- Files to create: none.

## Acceptance Criteria
Reference spec.md: "See spec.md AC-10, AC-11"
Additional task-specific criteria (if any):
- AC-T1: `CurrentSchemaVersion` is bumped from 34 to 35 with a version-history
  comment, per spec.md §3.1.
- AC-T2: The migration uses the `ALTER TABLE ... ADD COLUMN` +
  `PRAGMA table_info` guard pattern already used by
  `migrateSprintAssignmentsAddSprintOrder`, so it is safe to rerun.

## Test Cases
Concrete test cases (spec/test-plan gates are not waived for this STANDARD
feature; these are the specific cases this task must implement):
