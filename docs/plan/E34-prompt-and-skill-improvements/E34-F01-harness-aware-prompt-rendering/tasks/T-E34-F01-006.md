# Add harness OTel span attribute, byte-identical golden regression, and docs

## Goal
Close out the feature's regression guards and observability: prove
unbranched prompts are byte-identical before/after this feature, add the
bounded-cardinality span attribute, and document the new flags and response
fields.

## Scope
- Files to modify: `internal/cli/commands/next.go` (span attribute only —
  the `runNext` OTel span, line ~399), `internal/cli/commands/next_test.go`,
  `internal/cli/commands/next_golden_test.go`, `docs/cli-reference/*.md`
  (document the new `claim`/`next` flags and `NextResponse` fields).
- Files to create: none.

## Acceptance Criteria
Reference spec.md: "See spec.md AC-07"
Additional task-specific criteria (if any):
- AC-T1: Harness type (not version/model) is added as a span attribute on
  the existing `runNext` OTel span, to avoid unbounded attribute cardinality
  (spec.md §5).
- AC-T2: `docs/cli-reference/*.md` documents the three `claim`/`next`/`run`
  override flags and the three additive `NextResponse` fields.

## Test Cases
- TC-008 (test-plan.md): extend `TestRenderedPromptsGolden` in
  `next_golden_test.go` to compute `PromptSHA256` before and after this
  feature's full change set for every shipped prompt containing no harness
  branch — all digests identical. Use the full existing golden corpus, not a
  hand-picked fixture (test-plan.md Caller-Path Contract for TC-008).
- TC-017 (test-plan.md): claimed entity with `harness=claude` — assert the
  emitted span carries a `harness` attribute equal to the resolved type, and
  that `harness_version`/`harness_model` are NOT added as span attributes.
