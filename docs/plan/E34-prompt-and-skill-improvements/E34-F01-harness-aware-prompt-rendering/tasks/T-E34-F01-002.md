# Wire harness fields through claim repository, service, and CLI flags

## Goal
Make `shark claim` accept, normalize, and persist the three harness fields
added in T-E34-F01-001, so a claim row is the durable source the resolver
(T-E34-F01-003) later reads from.

## Scope
- Files to modify: `internal/repository/claim/claim_repository.go`,
  `internal/services/claim_service.go`, `internal/cli/commands/claim.go`.
- Files to create: none (extend existing `*_test.go` files for each package
  above, e.g. `claim_repository_test.go`, `claim_service_test.go`,
  `claim_test.go`).

## Acceptance Criteria
Reference spec.md: "See spec.md AC-01, AC-09, AC-10"
Additional task-specific criteria (if any):
- AC-T1: The three columns are included in the `Claim` insert/upsert, the
  `scanOne` column list, and the `Get`/`List`/`getByID` select lists, all via
  parameterized placeholders (spec.md §3.3).
- AC-T2: `--harness` is trimmed and lowercased before persistence;
  `--harness-version`/`--harness-model` are trimmed only, per spec.md
  REQ-F-001.

## Test Cases
- TC-001 (test-plan.md): `shark claim <key> --harness=claude
  --harness-version=2.1.0 --harness-model=opus` succeeds; `shark claims
  --json` reports all three values on that claim. Mock only the repository
  seam per test-plan.md's Caller-Path Contract for TC-001 — do not mock
  `ClaimService` itself.
- TC-002 (test-plan.md): claim with no harness flags succeeds; captured
  `ClaimInput.Harness*` fields are empty strings, not a sentinel value.
- TC-012 (test-plan.md): `--harness="  CLAUDE  "` round-trips as `claude` in
  `shark claims --json`; version/model are NOT lowercased.
- TC-013 (test-plan.md, CLI/service integration): `--harness=<101 chars>`
  fails with a non-zero exit and a validation error naming the field and
  quoting the input; assert the repository mock's `Claim` method is never
  called.
