# TC-I-01-READINESS-SYMMETRY checker

## Goal
Add the shared structural guard proving every I-## row in architecture.md
names a producer, consumer, Rider verb (where applicable), embedded skill
reference, and interaction-map entry — kept structurally separate from the
table parser so a shared defect between parser and checker cannot hide
behind one green test.

## Scope
- Files to create: `internal/sharkdata/i01_readiness.go` (or equivalent name
  matching this task's checker/parser separation requirement)
- Files to modify: `internal/sharkdata/embed_test.go` (add
  `TestI01ReadinessSymmetry`; depends on T-E34-F08-010, which also extends
  this file, closing the shared-file ordering risk)
- Uses `ParseI01Table` from T-E34-F08-001; does not modify it.

## Acceptance Criteria
Reference spec.md AC-8.
Additional task-specific criteria:
- AC-T1: `CheckI01ReadinessSymmetry(table []I01Row) []error` is a distinct
  function from `ParseI01Table` — the checker's fixture subtests construct
  `[]I01Row` directly, bypassing the parser, so a parser bug cannot mask a
  checker bug or vice versa.
- AC-T2: The checker distinguishes "Rider verb not applicable" (per that
  field's own "where applicable" qualifier) from "missing" — a legitimately
  N/A row is not flagged.

## Test Cases
See test-plan.md TC-014: (a) run the checker against the real, parsed
architecture.md I-## table — assert it passes for every row. (b) a
parameterized subtest per required-reference field (producer, consumer,
Rider verb where applicable, embedded skill reference, interaction-map
entry) with a test-local copy missing that field — assert the checker fails,
naming the specific missing field and row.

## Integration Contracts

### Cross-feature
None — this is a structural bundle-completeness guard over
architecture.md's own I-## table, not a cross-feature interface itself.
