# I-## and tier-matrix table parsers for structural checks

## Goal
Add programmatic parsers over architecture.md's I-## table, its I-05 section,
and (later) tier-matrix.md's tier table, so downstream structural tests never
hand-transcribe expected values that can silently drift from the source
tables they verify.

## Scope
- Create: `internal/sharkdata/table_parser.go`, `internal/sharkdata/table_parser_test.go`
- No modification yet — `tier-matrix.md`'s table doesn't exist until
  T-E34-F08-002; expose a parser generic enough for the I-## / I-05 /
  tier-matrix header shapes, or add the tier-matrix variant as a follow-on
  once T-E34-F08-002 lands (coordinate, do not block on it).

## Acceptance Criteria
See spec.md AC-8 (prerequisite for TC-014's checker).
- AC-T1: `ParseI01Table(architectureMD []byte) ([]I01Row, error)` returns
  one row per I-## entry, with producer, consumer, Rider verb (nullable),
  embedded skill reference, and interaction-map entry populated.
- AC-T2: A second entrypoint parses the I-05 `CanonicalAdoptionManifest v1`
  field list from architecture.md's I-05 section into an ordered
  field-name slice, for TC-I-05-ADOPTION-MANIFEST in T-E34-F08-010.
- AC-T3: Malformed or missing table input returns a typed error, not a
  panic or a silently empty slice.

## Test Cases
Write directly (TC-014/TC-I-05-ADOPTION-MANIFEST consume this parser but
don't test it standalone):
- Parse real architecture.md; assert I-## row count and one known row's
  fields match a hand-checked expectation.
- Parse a test-local I-## table copy with one field blanked; the parser
  still returns the row (validation is T-E34-F08-011's job, not parsing).
- Parse architecture.md's I-05 section; assert exactly 8 field names.

## Integration Contracts

### Cross-feature

TC-I-05-ADOPTION-MANIFEST (T-E34-F08-010).
