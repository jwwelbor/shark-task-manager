# Interaction-map and I-05 table parsers for structural checks

## Goal
Add programmatic parsers over `E34-interaction-map.md`'s Interaction
Contracts table and architecture.md's I-05 field list, so downstream
structural tests never hand-transcribe expected values that can silently
drift from the source tables they verify.

## Scope
- Create: `internal/sharkdata/table_parser.go`, `internal/sharkdata/table_parser_test.go`

## Acceptance Criteria
See spec.md AC-8 (prerequisite for TC-014's checker, T-E34-F08-011).
- AC-T1: `ParseInteractionMapTable(interactionMapMD []byte) ([]InteractionRow, error)`
  parses `E34-interaction-map.md`'s Interaction Contracts table (the actual
  producer/consumer/shape-source source for I-01–I-05 — architecture.md's
  per-interaction sections are field-meaning tables only, a different
  document with a different shape) and returns one row per I-## entry, with
  ID, producer feature, consumer feature(s), shape-source link, payload,
  and style populated.
- AC-T2: A second entrypoint parses the I-05 `CanonicalAdoptionManifest v1`
  field list from architecture.md's I-05 section into an ordered
  field-name slice, for TC-I-05-ADOPTION-MANIFEST in T-E34-F08-010.
- AC-T3: Malformed or missing table input returns a typed error, not a
  panic or a silently empty slice.

## Test Cases
Write directly (TC-014/TC-I-05-ADOPTION-MANIFEST consume this parser but
don't test it standalone):
- Parse real `E34-interaction-map.md`; assert exactly 5 rows and I-02's row
  fields match a hand-checked expectation.
- Parse a test-local Interaction Contracts table copy with one field
  blanked; the parser still returns the row (validation is
  T-E34-F08-011's job, not parsing).
- Parse architecture.md's I-05 section; assert exactly 8 field names.

## Integration Contracts

### Cross-feature
None — internal plumbing consumed by TC-014 (T-E34-F08-011) and
TC-I-05-ADOPTION-MANIFEST (T-E34-F08-010).
