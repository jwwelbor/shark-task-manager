# I-## and tier-matrix table parsers for structural checks

## Goal
Add programmatic parsers over architecture.md's I-## table, its I-05 section,
and (later) tier-matrix.md's tier table, so downstream structural tests never
hand-transcribe expected values that can silently drift from the source
tables they verify.

## Scope
- Files to create: `internal/sharkdata/table_parser.go` (or equivalent name
  agreed with existing package conventions), `internal/sharkdata/table_parser_test.go`
- Files to modify: none yet — `tier-matrix.md`'s own table does not exist
  until T-E34-F08-002; expose a parser function generic enough to parse any
  markdown table matching the I-## / I-05 / tier-matrix header shapes, or add
  the tier-matrix variant as a follow-on function once T-E34-F08-002 lands
  (coordinate ordering with that task; this task must not block on it).

## Acceptance Criteria
See spec.md AC-8 (parser is a prerequisite dependency for TC-014's checker).
Additional task-specific criteria:
- AC-T1: `ParseI01Table(architectureMD []byte) ([]I01Row, error)` returns one
  row per I-## entry in architecture.md's canonical table, with producer,
  consumer, Rider verb (nullable), embedded skill reference, and
  interaction-map entry fields populated.
- AC-T2: A second entrypoint (or the same function generalized) parses the
  I-05 `CanonicalAdoptionManifest v1` field list from architecture.md's I-05
  section into an ordered field-name slice, for use by
  TC-I-05-ADOPTION-MANIFEST in T-E34-F08-010.
- AC-T3: Malformed or missing table input returns a typed error, not a panic
  or a silently empty slice.

## Test Cases
Write these directly (test-plan.md's TC-014 and TC-I-05-ADOPTION-MANIFEST
consume this parser but do not test it standalone):
- Parse the real, current architecture.md and assert the I-## row count and
  one known row's fields match a hand-checked expectation.
- Parse a test-local copy of the I-## table with one row's field blanked;
  assert the parser still returns the row (parsing is not validation — the
  checker in T-E34-F08-011 does validation).
- Parse architecture.md's I-05 section; assert exactly 8 field names are
  returned, matching spec.md's Component-changes / architecture references.

(T-E34-F08-010).
