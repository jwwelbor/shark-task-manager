# Interaction-map and I-05 table parsers for structural checks

## Goal
Add programmatic parsers over `E34-interaction-map.md`'s Interaction
Contracts table, architecture.md's I-05 field list, and
`tier-matrix.md`'s SIMPLE/STANDARD/COMPLEX table, so downstream
structural tests never hand-transcribe expected values that can silently
drift from the source tables they verify.

## Scope
- Create: `internal/sharkdata/table_parser.go`, `internal/sharkdata/table_parser_test.go`

## Acceptance Criteria
See spec.md AC-8 (prerequisite for TC-014's checker, T-E34-F08-011) and
AC-2 (prerequisite for TC-002's set-equality check, T-E34-F08-002).
- AC-T1: `ParseInteractionMapTable(interactionMapMD []byte) ([]InteractionRow, error)`
  parses `E34-interaction-map.md`'s Interaction Contracts table (the actual
  producer/consumer/shape-source source for I-01–I-05 — architecture.md's
  per-interaction sections are field-meaning tables only, a different
  document with a different shape) and returns one row per I-## entry, with
  ID, producer feature, consumer feature(s), shape-source link, payload,
  and style populated.
- AC-T2: A second entrypoint parses the I-05 `CanonicalAdoptionManifest v1`
  field list from architecture.md's I-05 section into an ordered
  field-name slice, for TC-I-05-ADOPTION-MANIFEST in T-E34-F08-010.
- AC-T3: Malformed or missing table input returns a typed error, not a
  panic or a silently empty slice.
- AC-T4: A third entrypoint,
  `ParseTierMatrixTable(tierMatrixMD []byte) ([]TierRow, error)`, parses
  `tier-matrix.md`'s SIMPLE/STANDARD/COMPLEX × planning source/test
  source/same-model gate/separate QA/final UAT table into one `TierRow`
  per tier, each with `Tier` (`"SIMPLE"`/`"STANDARD"`/`"COMPLEX"`) and a
  `RequiredArtifacts []string` / `RequiredGates []string` pair derived
  from that tier's row (e.g. `spec.md`/`test-plan.md` when the row
  requires them, `same-model gate`/`separate QA`/`final UAT` when the row
  marks them required for that tier). This is the same parser family
  named in test-plan.md's TC-014 caller-path row and reused, per TC-002
  and TC-I-05-ADOPTION-MANIFEST, against a different table shape each
  time (`tier-matrix.md` here; the I-## table for TC-014; the I-05
  field list for TC-I-05-ADOPTION-MANIFEST) — there is exactly one
  parser implementation per table shape, never a second hand-rolled copy
  for the same table. Malformed/missing tier rows return a typed error
  (same rule as AC-T3), not a panic or empty slice.
  T-E34-F08-002 owns `tier-matrix.md`'s content and consumes
  `ParseTierMatrixTable` from this task for TC-002's rendered-route
  set-equality assertion; it does not re-implement or fork the parser.

## Test Cases
Write directly (TC-002/TC-014/TC-I-05-ADOPTION-MANIFEST consume this
parser but don't test it standalone):
- Parse real `E34-interaction-map.md`; assert exactly 5 rows and I-02's row
  fields match a hand-checked expectation.
- Parse a test-local Interaction Contracts table copy with one field
  blanked; the parser still returns the row (validation is
  T-E34-F08-011's job, not parsing).
- Parse architecture.md's I-05 section; assert exactly 8 field names.
- Parse real `tier-matrix.md`; assert exactly 3 `TierRow`s (SIMPLE,
  STANDARD, COMPLEX) and that COMPLEX's row includes a separate-QA gate
  while SIMPLE's does not (mirrors TC-002's own edge case).
- Parse a test-local `tier-matrix.md` table copy with one tier row's gate
  column blanked; assert a typed error, not a panic or silently empty
  `RequiredGates`.
