# Interaction-map and I-05 table parsers for structural checks

## Goal
Add programmatic parsers over `E34-interaction-map.md`'s Interaction
Contracts table, architecture.md's I-05 field list, and `tier-matrix.md`'s
tier table so downstream tests never hand-transcribe drifting values.

## Scope
- Create: `internal/sharkdata/table_parser.go`, `internal/sharkdata/table_parser_test.go`

## Acceptance Criteria
See spec.md AC-8 (prerequisite for TC-014's checker, T-E34-F08-011) and
AC-2 (prerequisite for TC-002's set-equality check, T-E34-F08-002).
- AC-T1: `ParseInteractionMapTable(interactionMapMD []byte) ([]InteractionRow, error)`
  parses the Interaction Contracts table (producer/consumer/shape-source
  source for I-01–I-05; architecture.md's per-interaction sections are a
  different, field-meaning-only shape) into one row per I-## entry: ID,
  producer feature, consumer feature(s), shape-source link, payload, style.
- AC-T2: parses the I-05 `CanonicalAdoptionManifest v1` field list from
  architecture.md into an ordered field-name slice, for TC-I-05-ADOPTION-MANIFEST (T-E34-F08-010).
- AC-T3: Malformed/missing table input returns a typed error, never a
  panic or silently empty slice — applies to all three entrypoints.
- AC-T4: `ParseTierMatrixTable(tierMatrixMD []byte) ([]TierRow, error)`
  parses `tier-matrix.md`'s tier table into one `TierRow` per tier (`Tier`
  + derived `RequiredArtifacts []string`/`RequiredGates []string`). One
  parser per table shape, reused (never forked) across three tables: this
  one for `tier-matrix.md` (TC-014's caller-path row), the I-## table for
  TC-002, the I-05 field list for TC-I-05-ADOPTION-MANIFEST.
  T-E34-F08-002 owns `tier-matrix.md`'s content and consumes this parser
  for its set-equality assertion, not a fork.

## Test Cases
Write directly (TC-002/TC-014/TC-I-05-ADOPTION-MANIFEST consume, don't test standalone):
- Real interaction map: exactly 5 rows; I-02's fields match a hand-checked
  expectation. Local copy, one field blanked: row still returned
  (validation is T-E34-F08-011's job, not parsing).
- Architecture.md's I-05 section: exactly 8 field names.
- Real `tier-matrix.md`: exactly 3 `TierRow`s; COMPLEX has a separate-QA
  gate, SIMPLE does not (mirrors TC-002's edge case). Local copy, gate
  column blanked: typed error, not an empty `RequiredGates`.

## Integration Contracts
None — internal plumbing consumed by TC-002 (T-E34-F08-002), TC-014
(T-E34-F08-011), TC-I-05-ADOPTION-MANIFEST (T-E34-F08-010).
