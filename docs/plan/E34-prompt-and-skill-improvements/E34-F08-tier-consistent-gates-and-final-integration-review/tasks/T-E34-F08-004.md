# IntegrationRun and CaptureBase idempotent capture

## Goal
Add the new `internal/integration` package's `IntegrationRun` type and
`CaptureBase` function: the once-per-epic-run base-commit capture that all
later integration-event work builds on.

## Scope
- Files to create: `internal/integration/run.go`, `internal/integration/run_test.go`
- No modification to existing packages in this task (wiring into the real
  cascade path is T-E34-F08-008).

## Acceptance Criteria
Reference spec.md AC-3.
Additional task-specific criteria:
- AC-T1: `CaptureBase(epicKey string) (*IntegrationRun, error)` writes exactly
  one run record on first call for a given epic key and returns the identical
  `BaseCommit`/`EpicRunID` on a second call for the same key without
  overwriting `BaseCommit`.
- AC-T2: A concurrent second caller racing the first for the same epic key
  results in exactly one run record on disk, both callers observing the same
  `BaseCommit`.
- AC-T3: An unparseable existing run file returns a typed error, not a
  silent second run creation.

## Test Cases
See test-plan.md TC-006 (sequential idempotency, goroutine race via
`sync.WaitGroup`, corrupted-file edge case).

## Integration Contracts

### Cross-feature
None — this is internal epic-run state, not a cross-feature interface.
