# tier-matrix.md single-source-of-truth content and prompt references

## Goal
Create the shared tier-contract reference and update the five consuming
prompts to reference it instead of restating the tier matrix, closing the
drift surface spec.md's REQ-F-001/REQ-F-002 describe.

## Scope
- Files to create:
  `internal/sharkdata/default_data/skills/quality/context/tier-matrix.md`
- Files to modify:
  `internal/sharkdata/default_data/prompts/feature/assessment.md`,
  `task_generation.md`, `code_review.md`, `qa.md`, `approval.md`
- Test files: `internal/templates/includes_test.go` (extend or add sibling
  test), plus a new `internal/templates/tier_matrix_render_test.go`
  (tier-render assertion test).

## Acceptance Criteria
Reference spec.md AC-1, AC-2, REQ-F-001, REQ-F-002.
Additional task-specific criteria:
- AC-T1: `tier-matrix.md` contains the SIMPLE/STANDARD/COMPLEX × planning
  source/test source/same-model gate/separate QA/final UAT table (verbatim
  from feature.md), the "Executable gate evidence" section (exact command,
  working directory, exit status, runner-native counts, expected-skip
  comparison, bounded log pointer), and the "missing artifacts are failures
  only when the selected tier requires them" paragraph.
- AC-T2: All five listed prompts reference `tier-matrix.md` by path/include
  and contain no second copy of the tier table.

## Test Cases
See test-plan.md TC-001, TC-002. For TC-002's set-equality assertion, use
`ParseTierMatrixTable(tierMatrixMD []byte) ([]TierRow, error)` — the
`tier-matrix.md` parser owned and tested by T-E34-F08-001
(`internal/sharkdata/table_parser.go`) — to derive each tier's expected
required-artifact/gate list from this task's own `tier-matrix.md` content,
and diff it against the set parsed out of `task_generation.md`'s/
`code_review.md`'s/`qa.md`'s rendered output for that tier. Do not
hand-transcribe expected lists, and do not fork a second tier-matrix
parser here — `ParseTierMatrixTable` is owned solely by T-E34-F08-001.
TC-014 and TC-I-05-ADOPTION-MANIFEST reuse the same parser family against
`E34-interaction-map.md`'s I-## table and architecture.md's I-05 field
list, respectively — no per-TC forked implementation.
