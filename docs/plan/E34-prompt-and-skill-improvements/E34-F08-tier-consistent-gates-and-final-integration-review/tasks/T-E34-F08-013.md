# Fail-closed base/history handling: rebase, squash, and interleaved commits

## Goal
Close the REQ-F-004/REQ-F-005 history gaps: fail closed on a missing or
unreachable base, and handle rebased/squashed feature branches and
unrelated interleaved commits without silently rewriting or hiding scope.
Dirty/untracked path-digest inventory (the remaining REQ-F-004 gap) is
T-E34-F08-016, which is independent of this task's file scope.

## Scope
- Modify: `internal/integration/backfill.go`, `internal/integration/backfill_test.go`
  (base-reachability and history validation, shared with steady-state
  capture per spec.md's "one correctness argument" decision)
- Create: `internal/integration/history.go`, `internal/integration/history_test.go`
  (rebase/squash/interleaved-commit detection and explicit
  replacement-record creation)

## Acceptance Criteria
Per feature.md:124-141 and architecture.md:296-303:
- AC-T1: A missing or unreachable base fails closed (typed error), never
  silently inferred from `merge-base HEAD main`.
- AC-T2: A rebase or squash-merge is detected and creates an explicit
  replacement record linked by `prior_record_digest`; the base is never
  silently rewritten.
- AC-T3: Unrelated interleaved commits remain visible in the full
  base-to-candidate inventory and are flagged as requiring a disposition,
  not silently included or excluded.

## Test Cases
See test-plan.md TC-018: pinned-base histories — independently
squash-merged features, unrelated interleaved commits, rebases, and a
missing base (one subtest each, per feature.md's verification plan).
Assert no case infers scope from `merge-base HEAD main`.
