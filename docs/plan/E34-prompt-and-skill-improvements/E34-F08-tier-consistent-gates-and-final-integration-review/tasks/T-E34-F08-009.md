# integration_review workflow step in epic.yaml

## Goal
Insert the new non-terminal `integration_review` step between `active` and
`completed` in the epic workflow, so a route exists to gate epic completion
without touching any feature's own status.

## Scope
- Files to modify: `internal/sharkdata/default_data/workflow/epic.yaml`
- Test files: `internal/workflow/service_multilevel_test.go` (extend,
  following the existing `TestValidateTransition_ValidEpic` /
  `TestGetValidTransitions_EpicLevel` pattern)

## Acceptance Criteria
Reference spec.md REQ-F-004 (workflow step subsection).
Additional task-specific criteria:
- AC-T1: `active`'s `outcomes.pass` changes from `completed` to
  `integration_review`.
- AC-T2: `integration_review` is added with
  `outcomes: {pass: completed, fail: active, blocked: blocked, on_hold: on_hold}`,
  `action: spawn_agent`, and `prompt: epic/integration_review.md` (prompt
  content itself is T-E34-F08-010's scope — this task only wires the step).

## Test Cases
See test-plan.md TC-015: load the real `epic.yaml` (no hand-constructed
workflow struct literal) and assert
`ValidateTransition("active", "integration_review")` and
`ValidateTransition("integration_review", <completed|active|blocked|on_hold>)`
all succeed — proving the new step is reachable, not merely defined.
