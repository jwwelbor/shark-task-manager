# IntegrationEvent and RecordEvent concurrent writes

## Goal
Add `IntegrationEvent` and `RecordEvent`, writing one immutable, idempotent
JSON file per feature completion under a given epic run, surviving two
concurrent writes for two different features.

## Scope
- Files to create: `internal/integration/event.go`, `internal/integration/event_test.go`
- Depends on `internal/integration/run.go` (T-E34-F08-004) for `EpicRunID`
  plumbing; does not modify `run.go`.

## Acceptance Criteria
Reference spec.md AC-4.
Additional task-specific criteria:
- AC-T1: `EventID` is derived deterministically as the first 16 hex
  characters of `sha256(epic_run_id + feature_key + feature_commit)`; a
  retried write of the same completion is byte-identical and idempotent.
- AC-T2: A different `feature_commit` for a re-opened, re-completed feature
  produces a new, distinct `EventID`.

## Test Cases
See test-plan.md TC-007's package-level subtest only (the wiring subtest for
the feature-completion call site is T-E34-F08-008): two goroutines racing
`RecordEvent` for two different feature keys under the same `EpicRunID`
against a real temp directory; assert two distinct, readable event files and
correct `EventID` derivation.
