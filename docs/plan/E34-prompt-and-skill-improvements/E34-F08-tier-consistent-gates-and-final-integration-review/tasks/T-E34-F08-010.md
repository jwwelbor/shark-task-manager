# epic/integration_review.md closure-check and I-05 adoption manifest prompt

## Goal
Write the epic-level final-review gate prompt: it reads the candidate's
accumulated diff, checks I-##/X-## closure and I-03/I-04 disposition, states
the non-supersession authority rule, and produces the I-05
`CanonicalAdoptionManifest` entry nested inside the existing `GateResult`
envelope.

## Scope
- Files to create: `internal/sharkdata/default_data/prompts/epic/integration_review.md`
- Test files: `internal/sharkdata/embed_test.go` (grep regression guard for
  the non-supersession sentence), plus the field-list-diff test for the
  `adoption_manifest` output (using T-E34-F08-001's I-05 parser).

## Acceptance Criteria
Reference spec.md AC-7, REQ-F-005, REQ-F-006, REQ-F-007.
Additional task-specific criteria:
- AC-T1: The prompt's closure check reports every I-##/X-## row whose
  producer or consumer feature is in this epic, every referenced E34-F06
  defect-class sweep, and every referenced E34-F07 `ChangeImpactSet`, scoped
  to in-epic rows only (out-of-epic rows are excluded, not treated as
  closed).
- AC-T2: The prompt's literal text contains REQ-F-006's non-supersession
  sentence verbatim: "This review adds a gate; it never overrides or
  supersedes an existing feature verdict...".
- AC-T3: The `adoption_manifest` field list matches architecture.md's 8 I-05
  fields exactly (`schema_version`, `source_commit`, `bundle_digest`,
  `changed_paths`, `workflow_changes`, `promoted_policies`,
  `override_actions`, `validation_evidence`), nested as a `GateResult`
  sibling to `remediation_sweeps`/`change_impacts`.
- AC-T4: No WWGM/Python-env/LLM-name/host-only leakage (extends T-E34-F08-003's
  sanitization sweep to this new file).

## Test Cases

regression guard) and TC-I-05-ADOPTION-MANIFEST (programmatic field-list diff
against the T-E34-F08-001 parser's output; negative case: `adoption_manifest`
