# Cascade wiring for CaptureBase and RecordEvent

## Goal
Wire the real cascade dispatch path to `CaptureBase` (epic `active` step,
first feature dispatch only) and to `RecordEvent` (feature-completion
transition), so a passing unit test on either function is not, by itself,
proof production code ever calls it.

## Scope
- Files to modify: `internal/cli/commands/next.go`'s cascade handler
  (`resolveEntity` / `resolveCascade`, confirmed by direct read as the real
  handler for `action: cascade`) or the workflow-cascade service it
  delegates to; the feature-completion cascade/hook call site identified
  during implementation (spec.md's own gap — no named call site — resolve
  it here, not by inventing a second wiring pattern).
- Test files: new cascade-dispatch test harness (or extension of an existing
  one, if one already partially exists for other cascade behaviors — confirm
  during implementation and extend rather than duplicate).

## Acceptance Criteria
Reference spec.md REQ-F-004 (cascade wiring subsection) and "Integration
with existing code".
Additional task-specific criteria:
- AC-T1: The `active` step's cascade action calls `integration.CaptureBase`
  exactly once per epic run, on first feature dispatch only; a second
  feature's dispatch under the same epic run does not create a second run
  record.
- AC-T2: A feature-completion transition calls `integration.RecordEvent` at
  the call site this task identifies; two concurrent feature completions
  under the same epic run both produce event files through this real wiring
  point (not just through `RecordEvent` called directly by a test).

## Test Cases
See test-plan.md TC-011 (drives the real cascade dispatch path against a
fixture epic/feature pair, temp `.shark/` dir, asserting a run record exists
after dispatch without calling `CaptureBase` by name) and TC-007's wiring
subtest (feature-completion `RecordEvent` call site, written against
whichever call site this task identifies — flag any deviation from the
spec's described shape as this task's own note, not a silent assumption).
