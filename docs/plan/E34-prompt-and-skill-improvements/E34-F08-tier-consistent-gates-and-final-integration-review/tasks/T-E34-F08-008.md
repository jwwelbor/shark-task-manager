# Cascade wiring for CaptureBase and RecordEvent

## Goal
Wire the real production paths to `CaptureBase` and `RecordEvent`, so a
passing unit test on either function is not, by itself, proof production
code ever calls it.

## Scope
- Modify: `internal/cli/commands/next.go`'s `resolveCascade` (the confirmed
  real handler for the epic `active` step's `action: cascade`) to call
  `integration.CaptureBase` on first feature dispatch.
- Modify: `internal/services/feature_service.go`'s `FeatureService.TransitionStatus`
  (the resolved call site — closes spec.md's named gap): in the branch that
  already detects a feature's `ToStatus` newly reaching a terminal status
  (mirroring the existing `featureWf.IsTerminalStatus(...)` regression check
  around lines 344 and 381), call `integration.RecordEvent` with the
  feature's commit and changed paths when an `IntegrationRun` exists for
  the feature's epic. Applies to both the `aggregateCoordinator` and
  non-aggregate branches.
- Test files: extend `internal/cli/commands/next_cascade_traversal_test.go`
  (AC-T1: `CaptureBase`-on-first-dispatch wiring through `resolveCascade`)
  and extend `internal/services/feature_service_test.go` (AC-T2:
  `RecordEvent`-on-terminal-transition wiring through
  `FeatureService.TransitionStatus`).

## Acceptance Criteria
Reference spec.md REQ-F-004 and "Integration with existing code".
- AC-T1: `active`'s cascade calls `CaptureBase` exactly once per epic run,
  on first feature dispatch only; a second feature's dispatch does not
  create a second run record.
- AC-T2: `FeatureService.TransitionStatus` calls `RecordEvent` at the named
  call site when a feature newly reaches a terminal status under an epic
  with an active `IntegrationRun`; two concurrent feature completions
  produce event files through this real wiring point, not just via a test
  calling `RecordEvent` directly.

## Test Cases
See test-plan.md TC-011 (real cascade dispatch, temp `.shark/` dir, no
direct `CaptureBase` call) and TC-007's wiring subtest, now written against
`FeatureService.TransitionStatus` as the named call site.

## Integration Contracts
None — internal wiring between existing cascade/transition dispatch and
`internal/integration`.
