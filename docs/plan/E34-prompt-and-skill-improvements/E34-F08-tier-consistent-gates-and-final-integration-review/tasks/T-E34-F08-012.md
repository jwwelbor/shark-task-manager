# Archived candidate-head retention and run-scoped registration lock

## Goal
Close the write-path half of the REQ-F-004 durability gaps: retain every
prior candidate head before replacement, and add a run-scoped lock plus a
deterministic suboperation ID guarding the registration-note write
sequence. Crash-restart repair (the second half) is T-E34-F08-014, which
depends on this task.

## Scope
- Create: `internal/integration/lock.go`, `internal/integration/lock_test.go`
  — a run-scoped advisory lock guarding only the registration-note write
  sequence (CAS stays T-E34-F08-006's mechanism for candidate updates, per
  spec.md's "CAS over a mutex" decision).
- Modify: `internal/integration/candidate.go`, `internal/integration/candidate_test.go`
  — write the prior head unchanged to
  `integration-heads/<record-digest>.json` before replacement.
- Modify: `internal/integration/run.go`, `internal/integration/run_test.go`
  — registration note write, suboperation ID computation, fsync ordering
  under the lock.

## Acceptance Criteria
Per feature.md:106-119 and architecture.md:273-316:
- AC-T1: Before replacing `integration-candidate.json`, the prior head is
  written unchanged to `integration-heads/<record-digest>.json`, so every
  `prior_record_digest` is recomputable from retained bytes.
- AC-T2: Registration suboperation ID = `sha256(epic_key + epic_run_id +
  base + first_head_digest)`. Under the run-scoped lock, events and head
  are fsynced before the note is inserted.

## Test Cases
See test-plan.md TC-016: lock acquisition/release under concurrent
registration attempts, archived-head write-then-replace ordering,
suboperation-ID determinism. Real temp `.shark/` directories, no mocks
(this repo's filesystem-only testing convention).
