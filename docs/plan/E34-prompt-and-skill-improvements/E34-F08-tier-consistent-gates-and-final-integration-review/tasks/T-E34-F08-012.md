# Archived candidate-head retention, run-scoped registration lock, and crash-restart repair

## Goal
Close the REQ-F-004 durability gaps the task-review flagged as missing:
archived candidate heads, a run-scoped lock around registration, the
registration suboperation ID, and exact-retry note repair — so a crash or a
restarted parent loop never loses or duplicates the epic's integration
identity.

## Scope
- Modify: `internal/integration/run.go` (registration note, suboperation
  ID, run-scoped lock), `internal/integration/candidate.go` (write prior
  head to `integration-heads/<record-digest>.json` before replacement)
- Create: `internal/integration/lock.go` (run-scoped advisory lock guarding
  only the registration-note sequence — CAS stays T-E34-F08-006's mechanism
  for candidate updates, per spec.md's "CAS over a mutex" decision)

## Acceptance Criteria
Per feature.md:106-119 and architecture.md:273-316:
- AC-T1: Before replacing `integration-candidate.json`, the prior head is
  written unchanged to `integration-heads/<record-digest>.json`, so every
  `prior_record_digest` is recomputable from retained bytes.
- AC-T2: Registration suboperation ID = `sha256(epic_key + epic_run_id +
  base + first_head_digest)`. Under the run-scoped lock, events and head
  are fsynced before the note is inserted.
- AC-T3: Exact retry (matching head, no note) repairs only the missing
  note. A note whose referenced head is absent/corrupt, or conflicting
  bytes, fails closed without reconstruction; the parent cannot acknowledge
  active entry or dispatch a feature until head and note reconcile.
- AC-T4: A second registration for a different `EpicRunID` while one is
  nonterminal is rejected.

## Test Cases
Failure-inject after event fsync, after archived-head fsync, and after
candidate-head replacement before note ack; after each restart assert
identical retry, no duplicate/lost event, a recomputable prior-head chain,
and rejection of a same event ID with different bytes. Add tamper,
truncation, and reordering detection against the retained
`integration-heads/` chain.

## Integration Contracts

### Cross-feature
None — internal durability state; the lock is reused by `backfill`
(T-E34-F08-007) and read by `integration_review` (T-E34-F08-010).
