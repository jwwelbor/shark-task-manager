# Add Capacity and Blockers panels to Overview tab

## Goal

The wireframe specifies a two-column health zone between the metric pills and the Sprint Backlog section. Left panel: per-agent Capacity rows with OK/HIGH/OVER indicators and failing Readiness factors. Right panel: enumerated Blockers with days-blocked age and an unsized-item warning count. All data is already in the overview payload — no new API calls required.

## Scope

- Files to modify: `internal/viewer/assets/viewer.html`
  - Add `renderSprintHealthColumns(payload)` function (~line 6181)
  - Insert call to `renderSprintHealthColumns(payload)` in `renderSprintOverview()` between metrics section and Sprint Backlog section
  - Add `.sprint-health-columns` CSS grid with 900 px responsive breakpoint

## Acceptance Criteria

See spec.md AC-017, AC-018, AC-019.

Additional task-specific criteria:
- AC-T1: All data is read from `payload.capacity`, `payload.readiness`, and `payload.backlog.groups` — no additional fetch.
- AC-T2: Blocked item rows have a click handler that calls `selectSprintItem(key)` (existing drawer function from E27-F13).
- AC-T3: Capacity indicator thresholds: >100% = OVER, 85-100% = HIGH, <85% = OK.
