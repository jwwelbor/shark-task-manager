# Fix Plan tab unknown status badges

## Goal

Every item in the Plan tab candidate backlog shows an `[unknown]` status badge because `BacklogItem.Status` is empty for unassigned items and the current badge line falls back to the literal string `"unknown"`. Fix the badge fallback to use `item.status_category` when `item.status` is absent, and render `"unassigned"` (neutral style) when neither is present.

## Scope

- Files to modify: `internal/viewer/assets/viewer.html`
  - Update `renderSprintPlan()` badge line to use `status || status_category || 'unassigned'` (~line 5957)
- Files to modify (Part B — only if `status_category` is also absent): `internal/repository/sprint/repository.go`
  - Add `t.status` to the task sub-select in `ListUnassignedBacklog()` UNION ALL query (~line 1010)
  - Add consistent column for other entity sub-selects (bugs, change_cards, tech_debts)

Start with Part A (frontend only). Only perform Part B if confirming `status_category` is also absent on plan items.

## Acceptance Criteria

See spec.md AC-011, AC-012.

Additional task-specific criteria:
- AC-T1: The badge fallback order is: `item.status` first, then `item.status_category`, then `"unassigned"`.
- AC-T2: `"unassigned"` badge uses the neutral/gray CSS class — not the error/red class.
- AC-T3: The string `"unknown"` never appears as a badge text.
