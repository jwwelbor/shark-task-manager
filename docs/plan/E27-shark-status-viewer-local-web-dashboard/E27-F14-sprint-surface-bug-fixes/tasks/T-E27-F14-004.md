# Task: Fix Plan tab unknown status badges

## Goal

Every item in the Plan tab candidate backlog shows an `[unknown]` status badge. The `BacklogItem` returned by `ListUnassignedBacklog()` has an empty `status` field — the unassigned backlog query doesn't JOIN back to entity status. In `renderSprintPlan`, the badge falls back to `item.status || 'unknown'`. The fix: fall back to `item.status_category` when `item.status` is empty, since candidate items do have a `status_category` field populated from the overview backlog groups.

## Root Cause

`internal/viewer/assets/viewer.html`, `renderSprintPlan()`:

```js
const statusBadge = ovStatusBadge(item.status || 'unknown');
```

`BacklogItem` from `ListUnassignedBacklog` (`internal/repository/sprint/repository.go`):

```go
type BacklogItem struct {
    ...
    Status    string    `json:"status,omitempty"`  // empty for unassigned items
    ...
}
```

The unassigned backlog query selects from tasks/bugs/etc but doesn't look up the current entity status; the `Status` field comes back as `""`.

## Implementation

Two-part fix:

**Part A — Frontend fallback (immediate):**

In `renderSprintPlan()`, use `status_category` as fallback when `status` is absent:

```js
// Before:
const statusBadge = ovStatusBadge(item.status || 'unknown');

// After:
const displayStatus = item.status || item.status_category || 'unassigned';
const statusBadge = ovStatusBadge(displayStatus);
```

**Part B — Backend population (if Part A is insufficient):**

If `status_category` is also absent on plan backlog items, update `ListUnassignedBacklog` in `internal/repository/sprint/repository.go` to JOIN the status from the source entity table:

```sql
-- For tasks:
SELECT t.key, t.title, t.status, t.agent_type, t.priority, t.size, ...
FROM tasks t
LEFT JOIN sprint_assignments sa ON sa.entity_id = t.id AND sa.entity_type = 'task' AND sa.removed_at IS NULL
WHERE sa.id IS NULL  -- not assigned to any active sprint
```

Start with Part A (frontend only). Only do Part B if the query confirms status is not returned.

## Acceptance Criteria

- [ ] Plan tab candidate items show real status badges (e.g., `todo`, `in_development`, `ready_for_approval`) instead of `unknown`
- [ ] Status badge color matches the status color from the workflow config
- [ ] Items with no status at all show `unassigned` badge in neutral color (not red/error)
