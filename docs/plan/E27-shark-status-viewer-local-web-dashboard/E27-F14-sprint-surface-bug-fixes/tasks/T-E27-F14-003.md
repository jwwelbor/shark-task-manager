# Fix sprint date range format strip time component

## Goal

Sprint date ranges display with a time component (e.g., "May 7 19:00:00 → May 21 19:00:00") instead of date-only. Sprint start/end dates are midnight UTC timestamps; the local-timezone time component is noise. Add a `formatDateOnly()` helper that parses the ISO string's date part directly (avoiding timezone day-shift) and update `sprintFormatRange()` to use it.

## Scope

- Files to modify: `internal/viewer/assets/viewer.html`
  - Add `formatDateOnly(isoString)` function adjacent to `formatDate()` (~line 5753)
  - Update `sprintFormatRange()` to call `formatDateOnly()` instead of `formatDate()`

## Acceptance Criteria

See spec.md AC-009, AC-010.

Additional task-specific criteria:
- AC-T1: `formatDateOnly` parses `isoString.split('T')[0]` — not `new Date(isoString)` — to avoid timezone day-shift on midnight-UTC values.
- AC-T2: Cross-year detection uses the current wall-clock year (parsed from the ISO string) vs `new Date().getFullYear()`.
- AC-T3: Absent dates render as `"—"`, not empty string.
