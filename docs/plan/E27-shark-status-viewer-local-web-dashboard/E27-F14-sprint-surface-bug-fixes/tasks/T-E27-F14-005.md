# Add Assigned This Sprint column to Plan tab

## Goal

The Plan tab currently shows only the Candidate Backlog (unassigned items). The wireframe specifies a two-column layout: Candidate Backlog on the left and Assigned This Sprint on the right. Restructure `renderSprintPlan()` to a side-by-side layout using data already present in `sprintOverviewData` — no new API call required.

## Scope

- Files to modify: `internal/viewer/assets/viewer.html`
  - Update `renderSprintModePanels()` to pass `sprintOverviewData` as a third argument to `renderSprintPlan()` (~line 5944)
  - Restructure `renderSprintPlan(payload, filters, overviewPayload)` to render two columns
  - Add `.sprint-plan-columns` CSS grid and a `@media (max-width: 900px)` stacking rule

## Acceptance Criteria

See spec.md AC-014, AC-015, AC-016.

Additional task-specific criteria:
- AC-T1: No new XHR/fetch is triggered when the Plan tab is opened; right column data comes from in-memory `sprintOverviewData`.
- AC-T2: Assigned column header reads "Assigned This Sprint (N)" where N is the item count.
- AC-T3: CSS breakpoint is exactly 900 px — columns are side-by-side at 900 px and stacked below 900 px.
