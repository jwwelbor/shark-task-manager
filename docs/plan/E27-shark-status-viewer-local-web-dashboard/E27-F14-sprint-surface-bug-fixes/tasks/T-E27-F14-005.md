# Task: Add Assigned This Sprint column to Plan tab

## Goal

The wireframe specifies a two-column Plan view: Candidate Backlog (unassigned tasks eligible for the sprint) on the left, Assigned This Sprint (tasks already in scope) on the right. The current implementation renders only the Candidate Backlog. Users have no way to see what is already scoped while making add/remove decisions. The fix restructures `renderSprintPlan()` to a side-by-side layout using data already present in the overview payload.

## Data Source

No new API call needed. The plan API returns the same `backlog.groups` structure as the overview API — these groups ARE the currently assigned sprint items. The candidate backlog comes from `PlanSprint.Backlog` (flat `[]BacklogItem` of unassigned tasks).

In `renderSprintModePanels()`, the plan view already has access to `sprintOverviewData` (assigned items in `backlog.groups`) alongside `sprintPlanData` (candidate backlog in `backlog` flat array).

## Implementation

Restructure `renderSprintPlan(payload, filters)` to accept both payloads:

```js
// Pass both payloads into the render function
mainPanel.innerHTML = renderSprintPlan(planPayload, sprintPlanFilters, sprintOverviewData);

function renderSprintPlan(payload, filters, overviewPayload) {
  // Candidates — from plan payload (unassigned)
  const candidates = sprintPlanItems(payload);  // flat BacklogItem[]
  const filtered = candidates.filter(item => sprintPlanMatchesFilters(item, filters));

  // Assigned — from overview payload (already in sprint, grouped by status)
  const assignedItems = sprintBacklogItems(overviewPayload || payload);

  // Render two-column layout
  return `
    <div class="sprint-overview-grid">
      <section class="sprint-hero">...</section>
      <section class="ov-section">
        <div class="ov-section-header">Filters</div>
        ${filtersHtml}
      </section>
      <div class="sprint-plan-columns">
        <section class="ov-section sprint-plan-col">
          <div class="ov-section-header">Candidate Backlog</div>
          ${actionButtons}
          ${candidateRows}
        </section>
        <section class="ov-section sprint-plan-col">
          <div class="ov-section-header">Assigned This Sprint
            <span style="color:var(--fg-dim)">${assignedItems.length}</span>
          </div>
          ${assignedRows}
        </section>
      </div>
      <section class="ov-section">
        <div class="ov-section-header">Capacity by Agent Type</div>
        ${capacityRowsHtml(capacity)}
      </section>
    </div>`;
}
```

Add CSS for the two-column plan layout:

```css
.sprint-plan-columns {
  display: grid;
  grid-template-columns: 1fr 1fr;
  gap: 16px;
}

.sprint-plan-col {
  min-width: 0;  /* prevent grid blowout */
}

@media (max-width: 900px) {
  .sprint-plan-columns {
    grid-template-columns: 1fr;  /* stack on narrow */
  }
}
```

The assigned column renders each item as a read-only row (no checkbox) with a status badge from `ovStatusBadge(item.status || item.status_category)` and an "Open entity" button. Items in the assigned column that are blocked should show a visual indicator.

## Acceptance Criteria

- [ ] Plan tab renders two columns side by side on desktop (≥900px)
- [ ] Left column: "Candidate Backlog" shows unassigned tasks with checkboxes and filters
- [ ] Right column: "Assigned This Sprint" shows currently scoped items with count in header
- [ ] Assigned column items show correct status badges (benefits from T-E27-F14-004)
- [ ] Blocked items in assigned column have a visual distinction
- [ ] Columns stack vertically at narrow viewport (< 900px)
- [ ] Selecting a row in either column opens the detail drawer
