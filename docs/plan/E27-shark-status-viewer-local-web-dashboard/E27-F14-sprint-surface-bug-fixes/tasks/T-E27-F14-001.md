# Task: Fix Report tab 500 for planning and active sprints

## Goal

`GET /api/v1/viewer/sprint/report` returns HTTP 500 for any sprint not in `completed` or `archived` status. `SprintAnalyticsService.GetSummary` has a status guard that returns an error for planning/active sprints, and `ViewerService.SprintReport` propagates it unconditionally. The fix degrades gracefully: return available burndown + velocity with `summary: null` rather than failing the whole response.

## Root Cause

`internal/services/sprint_analytics_service.go` ~line 283:
```go
if status != "completed" && status != "archived" {
    return nil, fmt.Errorf("sprint summary is available for completed or archived sprints only...")
}
```

`GetBurndown` already returns empty `DataPoints` for planning sprints (no error). `GetVelocity` has no status guard. Only `GetSummary` needs treatment.

## Implementation

In `internal/services/viewer_service.go`, `SprintReport()` (~line 755):

```go
// Before (propagates error):
summary, err := s.sprintAnalyticsSvc.GetSummary(ctx, sprintEntity.Key, false)
if err != nil {
    return nil, fmt.Errorf("viewer sprint report: failed to load summary: %w", err)
}

// After (non-fatal for non-completed sprints):
summary, err := s.sprintAnalyticsSvc.GetSummary(ctx, sprintEntity.Key, false)
if err != nil {
    summary = nil  // summary only available for completed/archived sprints
}
```

No frontend change needed — `renderSprintReport` already handles `payload.summary == null`.
