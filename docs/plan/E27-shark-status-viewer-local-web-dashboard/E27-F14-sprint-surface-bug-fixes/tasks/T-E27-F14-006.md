# Task: Fix WIP counter to include active workflow categories

## Goal

The "WIP" metric card in the Overview always shows 0 for sprints using the wormwoodGM workflow. The counter filters for `in_progress`, `in_review`, `in_qa` status categories, but the actual workflow uses `ready_for_approval` and `ready_for_development` as primary active-work states. Update the WIP filter to cover all active-work categories from the bucket mapping introduced in T-E27-F14-002, and rename the metric to "Active" to accurately describe what is measured.

## Root Cause

`internal/viewer/assets/viewer.html`, `renderSprintOverview()`:

```js
const wipCount = sprintBacklogGroups(payload)
  .filter(group => ['in_progress', 'in_review', 'in_qa'].includes(group?.status_category || ''))
  .reduce((acc, group) => acc + (Array.isArray(group.items) ? group.items.length : 0), 0);
```

The hardcoded list does not include `ready_for_development`, `ready_for_approval`, `in_development`, `in_refinement` — all of which represent active work in the wormwoodGM workflow config.

## Implementation

After T-E27-F14-002 lands, derive the active categories from `SPRINT_BUCKET_MAP` to avoid duplicating the list:

```js
// Derive active (non-done, non-blocked, non-ready) categories from the bucket map
const ACTIVE_SPRINT_CATEGORIES = new Set(
  Object.entries(SPRINT_BUCKET_MAP)
    .filter(([, bucket]) => bucket === 'in_progress')
    .map(([cat]) => cat)
);

// In renderSprintOverview():
const activeCount = sprintBacklogGroups(payload)
  .filter(group => ACTIVE_SPRINT_CATEGORIES.has(group?.status_category || ''))
  .reduce((acc, group) => acc + (Array.isArray(group.items) ? group.items.length : 0), 0);
```

Update the metric card label from `'WIP'` to `'Active'` and update the note text from `'Items currently in progress'` to `'Items in active workflow states'`.

This means `SPRINT_BUCKET_MAP` (from T-E27-F14-002) becomes a shared constant used by both the sidebar and this counter — dependency on that task is intentional.

## Acceptance Criteria

- [ ] "Active" metric card counts items in `in_development`, `ready_for_approval`, `ready_for_development`, `in_progress`, `in_review`, `in_qa`, `ready_for_refinement_*`, `in_refinement`
- [ ] Metric card label reads "Active" (not "WIP")
- [ ] Blocked items are not counted in Active (they have their own card)
- [ ] Completed/done items are not counted
- [ ] Count matches the sum of items in the sidebar "In Progress" bucket (T-E27-F14-002)
