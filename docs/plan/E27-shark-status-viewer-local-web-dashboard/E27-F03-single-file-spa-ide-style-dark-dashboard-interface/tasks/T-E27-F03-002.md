# Task: Pick Folder screen wiring + API client module (7 fetch wrappers)

## Goal

Wire the Pick Folder button to trigger the full initial data load sequence, implement all 7 async fetch wrappers for the `/api/v1/viewer/` endpoints, add shared error handling with toast/banner UI, and implement the `pick_folder` → `dashboard` state transition. End result: clicking "Pick Folder" fetches real data from a running E27-F02 server and transitions to the (stub) Dashboard state.

## Spec References

- spec.md §3 (API Integration), §5.2 State Transitions #1, §6 Task 2
- spec.md §3 Error Handling Strategy

## Requirements

### Functional Requirements

- [ ] 7 async API fetch functions in a labeled `// === API CLIENT ===` section:
  - `apiGetWorkflowMeta()` → `GET /api/v1/viewer/workflow-meta`
  - `apiGetHierarchy()` → `GET /api/v1/viewer/hierarchy`
  - `apiGetSummary()` → `GET /api/v1/viewer/summary`
  - `apiGetRecentActivity(limit=25)` → `GET /api/v1/viewer/recent-activity?limit=25`
  - `apiGetFile(key)` → `GET /api/v1/viewer/file/{key}`
  - `apiGetHistory(key)` → `GET /api/v1/viewer/history/{key}`
  - `apiGetFeatureTasks(key)` → `GET /api/v1/viewer/features/{key}/tasks`
- [ ] All fetch wrappers return parsed JSON on success; throw or return null on HTTP error
- [ ] Shared `showError(message)` — renders a dismissible banner/toast; logs to console
- [ ] Loading state: `showLoading()` / `hideLoading()` in content area during initial load
- [ ] Pick Folder button click handler (async):
  1. Show loading state
  2. Fetch `workflow-meta` (non-blocking if fails — use hardcoded `STATUS_COLORS` as fallback)
  3. Fetch `hierarchy` — if fails: stay on Pick Folder, call `showError()`
  4. On hierarchy success: set `treeData`, seed `expandedEpics` with all epic keys
  5. Fetch `summary` and `recent-activity` in parallel (`Promise.all`)
  6. Set `summaryData` and `recentActivity` caches
  7. Set `appState = 'dashboard'`, call `render()`
- [ ] `workflow-meta` supplements `STATUS_COLORS`: for statuses in workflow-meta not in hardcoded table, add with `#666666` fallback
- [ ] Hierarchy failure: stay on Pick Folder, show error banner
- [ ] Partial failure (summary/activity): proceed to dashboard, affected sections show inline "Failed to load" message

### Non-Functional Requirements

- [ ] All API calls use relative URLs (e.g., `/api/v1/viewer/hierarchy`)
- [ ] No external dependencies beyond the built-in `fetch` API
