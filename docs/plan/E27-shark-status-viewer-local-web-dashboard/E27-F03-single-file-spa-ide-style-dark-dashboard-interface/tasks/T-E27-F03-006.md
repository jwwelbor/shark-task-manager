# Task: Entity View — properties panel, Marked.js markdown rendering, Info/Transitions toggle

## Goal

Implement `renderEntityView()`: the properties metadata grid, the Info/Transitions content toolbar, and the markdown content pane that renders entity file content via Marked.js. Clicking a sidebar tree node or dashboard entity key should show this view with entity properties and rendered markdown.

## Spec References

- spec.md §2.7 (Entity View Layout): §2.7.1 Properties Panel, §2.7.2 Content Toolbar, §2.7.3 Markdown Content Pane
- spec.md §6 Task 6
- status-viewer-ui.md §Application States #03 Main App — Entity View
- Test cases: TC-VIS-08, TC-VIS-09, TC-API-04, TC-API-08

## Requirements

### Functional Requirements

- [ ] `renderEntityView()` in a labeled `// === ENTITY VIEW ===` section
- [ ] Entity metadata lookup: find the entity with key = `selectedKey` in `treeData` (walk epics/features/tasks)
- [ ] **Properties panel** (`renderPropertiesPanel(entity)`):
  - Key-value grid (CSS grid, 2-column: label | value)
  - Fields: `key` (monospace accent), `status` (colored badge), `type`, `parent`, `agent`, `created_at` (formatted), `updated_at` (formatted), `file_path`, `linked_content_path`
  - `file_path` and `linked_content_path`: each has a copy-to-clipboard button (`navigator.clipboard.writeText()`)
  - `status` field rendered as a colored pill badge using `getStatusColor(entity.status)`, white text
  - Omit fields that are null/undefined
- [ ] **Content toolbar**:
  - Entity name displayed prominently
  - "Info" toggle button (default active state)
  - "Transitions" toggle button
  - Clicking "Info" → show markdown pane
  - Clicking "Transitions" → show history drawer (stub for now, implemented in T-E27-F03-007)
  - Active button has distinct styling (accent background or underline)
- [ ] **Markdown content pane** (Info view, `renderMarkdownPane(key)`):
  - Call `apiGetFile(key)` to load content
  - Show loading spinner while fetching
  - If `response.exists === true`: call `marked.parse(response.content)`, wrap in `<div class="markdown-body">`, set `innerHTML`
  - If `response.exists === false`: show "No content available for this entity." placeholder
  - Marked.js CDN `<script>` tag must be in `<head>`: `https://cdn.jsdelivr.net/npm/marked/marked.min.js`
  - Fallback: if `typeof marked === 'undefined'` (CDN blocked), render content as `<pre>` with warning banner "Markdown renderer unavailable (CDN blocked). Showing raw content."
  - API endpoint: `GET /api/v1/viewer/file/{key}`
- [ ] **Dark-themed markdown CSS** in `<style>` block:
  - `.markdown-body h1, h2, h3`: slightly larger, white/light text, bottom border for h1/h2
  - `.markdown-body p`: readable line-height
  - `.markdown-body code, pre`: monospace, dark code block background (e.g., `#1e1e1e`), padding, rounded
  - `.markdown-body table`: bordered, alternating row shading
  - `.markdown-body ul, ol`: proper list indentation
  - `.markdown-body a`: accent blue color
  - `.markdown-body blockquote`: left border accent, muted text
- [ ] `entityViewTab` state variable (or local var): `'info'` or `'transitions'` — controls which pane is shown in entity view

### Non-Functional Requirements

- [ ] Markdown rendering via Marked.js only — do not hand-roll a markdown parser
- [ ] `navigator.clipboard.writeText()` for copy buttons (graceful degradation if not available)
- [ ] API call to `/file/{key}` is made each time an entity is selected (not cached — content may change)
