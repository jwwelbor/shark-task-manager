# Task: Dashboard: Status Breakdown cards + Feature Progress bars

## Goal

Implement `renderDashboard()` orchestrator and the first two dashboard sections: Status Breakdown (entity-type cards with colored status badge counts) and Feature Progress (list with horizontal progress bars and percentages). Renders from cached `summaryData` and `treeData`.

## Spec References

- spec.md §2.5.1 Status Breakdown, §2.5.2 Feature Progress, §6 Task 4
- status-viewer-ui.md §Content area — Dashboard sections 1 and 2
- Test cases: TC-VIS-04, TC-VIS-05

## Requirements

### Functional Requirements

- [ ] `renderDashboard()` in a labeled `// === DASHBOARD ===` section — orchestrates all 4 sections; places results in `<main id="content">`
- [ ] **Status Breakdown section** — `renderStatusBreakdown()`:
  - Grid of cards, one per entity type present in `summaryData` (Epics, Features, Tasks, Bugs, Ideas, Change Cards)
  - Each card:
    - Uppercase type label (e.g., `EPICS`)
    - Large bold total count number
    - Row of colored status badges below the total; each badge: background = `getStatusColor(status)`, label = `status_name count`
  - Data source: `summaryData.epics.status_counts`, `summaryData.features.status_counts`, `summaryData.tasks.status_counts`, `summaryData.bugs.status_counts` (optional fields guarded with `?.`)
  - Skip cards with 0 total items
- [ ] **Feature Progress section** — `renderFeatureProgress()`:
  - Section title "Feature Progress"
  - List of features; per-row: `[key — accent blue, clickable] [title — secondary] [horizontal progress bar — blue fill] [percentage string]`
  - Progress = `(count of completed tasks / total tasks) * 100` — derived from `treeData` per-feature task list
  - If a feature has 0 tasks: show "0%" and empty bar
  - Click feature key → call `navigateToEntity(featureKey)` (stub for now)
  - Progress bar: CSS `<div>` with `width: X%`, blue fill (`var(--accent)`)
- [ ] `renderDashboard()` shows section header + calls both section renderers for this task (stubs for Active Transitions and Stale Entities — see T-E27-F03-005)
- [ ] If `summaryData` is null (failed load), Status Breakdown section shows inline "Failed to load status data" message
- [ ] If `treeData` is empty, Feature Progress section shows "No features found"

### Non-Functional Requirements

- [ ] Renders purely from cached data — no API calls during render
- [ ] Guard all `?.` optional chaining on potentially missing response fields per spec §3 API Contract Robustness

## Implementation Plan

### Steps

1. [ ] Add `// === DASHBOARD ===` section in `<script>` block
2. [ ] Implement `renderDashboard()` orchestrator — calls section renderers, assembles HTML, sets `content.innerHTML`
3. [ ] Implement `renderStatusBreakdown()` — builds grid of entity type cards with status badge rows
4. [ ] Implement `renderFeatureProgress()` — walks `treeData`, calculates per-feature progress, builds list with progress bars
5. [ ] Wire click handlers for feature keys in progress list → `navigateToEntity(key)` stub
6. [ ] Test with real data: verify card layout, badge colors, progress percentages
