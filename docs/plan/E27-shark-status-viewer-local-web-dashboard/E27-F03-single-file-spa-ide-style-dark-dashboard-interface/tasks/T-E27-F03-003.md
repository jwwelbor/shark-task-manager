# Task: Sidebar tree navigator with expand/collapse and selected state

## Goal

Implement the full sidebar tree navigator: `renderSidebar()` function that builds the "Hierarchy" section (epics → features → tasks + docs, with correct indentation) and flat sections (Ideas, Change Cards, Tags, Tech Debt), with expand/collapse arrow handling and click-to-select node behavior. This is the most complex single component (~350 LOC).

## Spec References

- spec.md §2.6 (Sidebar Tree Navigator): §2.6.1 Sections, §2.6.2 Indentation, §2.6.3 Node Format, §2.6.4 Expand/Collapse, §2.6.5 Selected State
- spec.md §6 Task 3
- status-viewer-ui.md §Sidebar Tree Structure
- Test cases: TC-TREE-01 through TC-TREE-05, TC-COLOR-01 (status dots)

## Requirements

### Functional Requirements

- [ ] `renderSidebar()` function in a labeled `// === SIDEBAR ===` section
- [ ] "Hierarchy" section header: sticky uppercase `HIERARCHY` label
- [ ] Epic nodes (top-level): start expanded by default (all epic keys in `expandedEpics` on initial load); bold typography; 16px left padding
- [ ] Feature nodes (children of epics): start collapsed; normal typography; 40px left padding
- [ ] Task nodes (children of features, shown when feature is expanded): 56px left padding; normal typography
- [ ] Doc nodes at epic level: 16px left padding; italic; muted color
- [ ] Doc nodes at feature level: 40px left padding; italic; muted color
- [ ] Flat sections (only rendered if items exist in `treeData`): Ideas, Change Cards, Tags, Tech Debt — each with sticky uppercase section header; flat list at 18px left padding
- [ ] Each entity node renders left-to-right: `[▶/▼ arrow if expandable] [status dot — colored circle] [key — mono accent blue] [title — muted, truncated with ellipsis]`
- [ ] Status dot: 9px filled circle, `background-color: getStatusColor(node.status)`
- [ ] Key: monospace font, accent blue color (`var(--accent)`)
- [ ] Title: sans-serif, muted gray (`var(--fg-muted)`), `text-overflow: ellipsis; overflow: hidden; white-space: nowrap`
- [ ] Expand/collapse: clicking the `▶`/`▼` arrow toggles `expandedEpics` or `expandedFeatures` Set, re-renders sidebar only (not full page)
- [ ] Clicking the node body (not arrow): sets `selectedKey = key; appState = 'entity_view'; render()`
- [ ] Selected state: darker background tint, 3px left border in `var(--accent)`, title text → `var(--fg)` (white)
- [ ] `scrollIntoView()` called on selected node when selected programmatically (for navigation from dashboard)
- [ ] Scroll-into-view helper: `function scrollSidebarToKey(key)` — finds node DOM element by data-key attribute, calls `scrollIntoView({block: 'nearest'})`
- [ ] On data refresh, preserve `expandedEpics` and `expandedFeatures` state (do not reset)

### Non-Functional Requirements

- [ ] Sidebar renders entirely from `treeData` cache — no additional API calls
- [ ] Efficient re-render: `renderSidebar()` sets `sidebar.innerHTML` — acceptable for data sizes in scope
- [ ] `data-key` attribute on each node element for programmatic selection and scrolling
