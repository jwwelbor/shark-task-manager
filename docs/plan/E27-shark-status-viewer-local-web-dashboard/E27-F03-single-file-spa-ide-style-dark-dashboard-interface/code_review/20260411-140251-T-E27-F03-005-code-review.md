### Minor Finding (non-blocking): Partial entity walk for stale detection

The task spec §Requirements lists: "walk all epics, features, tasks, bugs, ideas, change-cards". The current implementation only walks `treeData` (epics → features → tasks). Bugs, ideas, and change-cards from `summaryData` are NOT included in the stale walk.

Assessment: **Non-blocking** — the spec note directly above this requirement says "Client-side filter applied to `treeData`" and the data source in §2.5.4 explicitly states "derived from cached `treeData` from `/hierarchy`". The hierarchy endpoint only returns epics/features/tasks. Bugs, ideas, and change-cards live in `summaryData` which does not carry per-entity `updated_at` fields. The implementation is consistent with the data model and correctly follows the `treeData` source. The listing in requirements is aspirational; the data source note governs.
