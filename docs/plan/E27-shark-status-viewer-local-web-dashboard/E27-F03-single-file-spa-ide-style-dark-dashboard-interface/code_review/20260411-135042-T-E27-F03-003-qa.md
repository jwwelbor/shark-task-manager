## 3. Structural Validation

### Key/Indentation Values (Spec §2.6.2)

Verified directly in `viewer.html` CSS:

| Node Type | Required Padding | Actual CSS | Match |
|-----------|-----------------|------------|-------|
| Epic | 16px | `.tree-node-epic { padding-left: 16px; }` | YES |
| Feature | 40px | `.tree-node-feature { padding-left: 40px; }` | YES |
| Task | 56px | `.tree-node-task { padding-left: 56px; }` | YES |
| Flat section node | 18px | `.tree-node-flat { padding-left: 18px; }` | YES |
| Doc at epic level | 16px, italic | `.tree-node-doc-epic { padding-left: 16px; font-style: italic; }` | YES |
| Doc at feature level | 40px, italic | `.tree-node-doc-feature { padding-left: 40px; font-style: italic; }` | YES |

Selected-node compensation (3px subtracted to keep visual alignment): 13px/37px/53px/15px — verified correct.

### Security (XSS)

`escapeHtml()` is applied to all user-controlled values inserted into HTML (`key`, `title`, `status`, `color`, node class strings). `CSS.escape()` used in `scrollSidebarToKey` to prevent CSS injection. No XSS vectors found.

### Event Delegation

Single `onclick` handler replaced on `sidebarContent` on each `renderSidebar()` call — avoids accumulating listeners. Arrow click intercepted via `closest('[data-arrow-key]')` BEFORE `data-select-key` handler — correct order preventing unintended selection on arrow click.

### Node Format (Spec §2.6.3)

Each entity node renders: `[arrow/spacer] [status dot] [key in mono accent] [title muted truncated]`. The `buildNodeHtml` function produces this in order, satisfying the left-to-right spec requirement.
