**Status: PARTIALLY MET (data plumbing correct; inline message requires Task 4-5 render stubs)**

`apiGetSummary()` and `apiGetRecentActivity()` both return `null` on failure (try/catch pattern, lines 1274-1296). The `Promise.all` at line 1467-1470 handles nulls gracefully — no rejection. After the parallel fetch:


The state machine proceeds to `appState = 'dashboard'; render()` regardless of whether summary/activity succeeded. The `null` cache value is the signal for downstream dashboard renders to show inline "Failed to load" text.

**Caveat**: The inline "Failed to load" message in the dashboard sections is implemented by the render functions for Tasks 4-5 (which check `summaryData === null`). The data plumbing for AC-5 is fully in place. The code review identified this as a known limitation within Task 2 scope (risk hotspot I in the code review). This is a correct assessment — Task 2 scope is met; the inline rendering will be verified in Tasks 4-5 QA.
