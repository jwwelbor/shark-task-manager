## 3. Red-Team Findings

### Finding RT-01: STATUS_COLORS is a plain object (prototype pollution — theoretical, non-blocking)

`STATUS_COLORS` is declared as `const STATUS_COLORS = { ... }` (line 1091) — a plain
object literal, not `Object.create(null)`. The supplement loop at line 1441 uses:
```javascript
if (!(status in STATUS_COLORS)) {
  STATUS_COLORS[status] = ...
}
```

The `in` operator on a plain object checks the prototype chain. For status keys like
`__proto__`, `constructor`, or `toString`, the `in` check returns `true`, so the
guard correctly prevents assignment for these keys. For other inherited property names,
the guard also prevents assignment. The attack surface is limited to a malicious
E27-F02 server returning adversarial status names — which is a trusted local server
in this use case. **No real risk in the localhost deployment context. Non-blocking.**

### Finding RT-02: Pick Folder button event listener not wrapped in null-check (theoretical, non-blocking)

Line 1880: `document.getElementById('pick-folder-btn').addEventListener(...)` — no null
guard. If the element were missing from the DOM (malformed HTML), this would throw a
TypeError at page load. However, the HTML at line 1065 confirms `id="pick-folder-btn"`
exists unconditionally in the static HTML structure. Non-blocking.

### Finding RT-03: Stale JSDoc in renderPickFolder() (cosmetic, non-blocking)

Line 1543–1544 still reads: "The 'Pick Folder' button will be wired to API load logic in
Task 2. For now it is a stub." This is stale — the button is now wired. Previously
flagged as F-01 in the code review. Non-blocking cosmetic issue.

### Finding RT-04: recentActivity null-masking (minor, non-blocking)

Line 1474: `recentActivity = Array.isArray(activity) ? activity : [];`

When `activity` is `null` (API failure), this sets `recentActivity = []` rather than
`null`. This means downstream render functions cannot distinguish between "empty activity"
and "failed to load activity" — they would need to check `summaryData` or another flag to
show "Failed to load." The spec's AC-5 only explicitly requires the `summaryData` path to
show "Failed to load." For `recentActivity`, the empty-array masking means failed loads
silently render as an empty list, not an error. This deviates slightly from the spirit of
AC-5 but is not named explicitly in the acceptance criteria as a requirement.
**Non-blocking for this task. Recommend Tasks 4–5 address the distinction.**
