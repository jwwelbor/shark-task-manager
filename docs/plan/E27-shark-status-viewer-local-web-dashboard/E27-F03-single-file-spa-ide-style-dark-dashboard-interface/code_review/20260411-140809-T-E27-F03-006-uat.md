## Red-Team Findings

### Finding 1: h1 missing bottom border (MINOR — NON-BLOCKING)

**Location:** CSS lines 753-754

**Observation:** Task spec line 54 states: `.markdown-body h1, h2, h3`: "bottom border for h1/h2". The implementation has `border-bottom` on h2 only — h1 has no bottom border.

**Assessment:** Non-blocking for the following reasons:
1. The higher-level spec (spec.md §2.7.3) does not mandate h1 bottom border by name — it only says "wrap in styled `.markdown-body` container."
2. Markdown files generated by shark (task/feature/epic files) rarely use h1 — they use h2+ for sections. The visual impact is negligible.
3. All 8 acceptance criteria are met; this CSS detail appears only in the implementation plan section (line 54), not in the formal AC list.
4. All 19 tests pass.

**Classification:** Cosmetic deviation, lower-level requirement only.

---

### Finding 2: `entityViewTab` not reset on entity navigation (OBSERVATION — NON-BLOCKING)

**Location:** `navigateToEntity()` (line 1569) and sidebar click handler (line 2373)

**Observation:** When navigating from one entity to another, `entityViewTab` retains its previous value. If a user viewed Entity A on the "Transitions" tab and then clicks Entity B, Entity B opens on "Transitions" rather than "Info."

**Assessment:** Non-blocking — the formal AC only requires the default initial state to be Info (which is correct: `let entityViewTab = 'info'` at line 1866), and the toggle to work correctly (which it does). Resetting per-navigation is a UX improvement, not a stated requirement. This could be addressed in a follow-up task (e.g., T-E27-F03-007).

---

### Finding 3: No XSS vulnerabilities found (SECURITY — PASS)

**Scope:** All `innerHTML` assignments in the entity view section verified:
- All user/API data routed through `escapeHtml()` before injection
- `copyBtn()` uses `JSON.stringify()` for safe attribute embedding
- Markdown content (`wrapper.innerHTML = rendered`) is intentionally unescaped (Marked.js produces HTML from the project's own files — not from user input)
- Fallback `<pre>` path correctly escapes raw content with `escapeHtml(rawContent)`

No XSS vectors identified.

---

### Finding 4: `renderEntityView` refetch on tab toggle (OBSERVATION — NON-BLOCKING)

**Location:** Toggle click handlers (lines 2044-2050) call `renderEntityView()` which calls `renderMarkdownPane()` again, causing a second `apiGetFile()` request when returning to "Info" from "Transitions."

**Assessment:** The task spec explicitly states "API call to `/file/{key}` is made each time an entity is selected (not cached)". Returning to Info tab is semantically a re-select and the spec permits this. Non-blocking.
