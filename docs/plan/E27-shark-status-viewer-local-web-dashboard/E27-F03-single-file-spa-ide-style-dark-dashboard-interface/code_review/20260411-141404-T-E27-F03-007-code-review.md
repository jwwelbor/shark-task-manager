## A. Executive Summary

T-E27-F03-007 implements the final integration task for the E27-F03 SPA: Doc View, ancestor expansion in `navigateToEntity()`, the Escape key handler, header button wiring, and Go embed smoke tests. Additionally, ~100 shark-template files are modified in this commit outside T-E27-F03-007's scope.

**Verdict: FAIL**

## C. Findings Table

### Finding 001 — BLOCKER: History drawer missing "Open" button

| Field | Value |
|---|---|
| **ID** | 001 |
| **Severity** | Blocker |
| **File:Line** | `internal/viewer/assets/viewer.html:2132–2137` |
| **Rule** | SPEC-FIDELITY |
| **AC** | "Open button at top of drawer: switches back to Info view (calls `renderMarkdownPane()`)" |
| **Spec Reference** | spec.md §2.7.4, spec.md §5.2 transition #7, task spec Acceptance Criteria |

**Diagnosis**: The transitions pane rendered inside `renderEntityView()` builds a `<table>` with transition rows but contains no "Open" button. The spec (§2.7.4) states: *"Open button toggles back to Info view (only rendered if content exists)"*. Spec transition #7 maps: `entity_view (History)` → `entity_view (Info)` via "Click 'Info' toggle OR 'Open' button in history".

The `open-btn` class defined at line 595 and used at line 1760 belongs to the Active Transitions table rows, not the history drawer.

**Correction**:

Add an "Open" button at the top of the history drawer HTML output inside `renderEntityView()`. The button should set `entityViewTab = 'info'` and call `renderEntityView()`.

```javascript
// Before (line 2132):
paneEl.innerHTML = `
  <div class="history-drawer">
    <table class="history-table">
      <tbody>${rows}</tbody>
    </table>
  </div>`;

// After:
paneEl.innerHTML = `
  <div class="history-drawer">
    <div class="history-drawer-toolbar">
      <button class="open-btn" id="ev-history-open-btn">Open</button>
    </div>
    <table class="history-table">
      <tbody>${rows}</tbody>
    </table>
  </div>`;

// Wire the Open button (add after innerHTML assignment):
const openBtn = document.getElementById('ev-history-open-btn');
if (openBtn) {
  openBtn.addEventListener('click', () => {
    entityViewTab = 'info';
    renderEntityView();
  });
}
```

Note: The "Open" button should only appear when content exists (when the entity has `linked_content_path` or the file API returns `exists: true`). The simplest conformant approach is to render it unconditionally (showing "No content" placeholder) unless entity metadata indicates no file. Spec says "only rendered if content exists" — at minimum render it and let `renderMarkdownPane` handle the no-content case.

### Finding 002 — BLOCKER: Escape key does not implement drawer-first behavior

| Field | Value |
|---|---|
| **ID** | 002 |
| **Severity** | Blocker |
| **File:Line** | `internal/viewer/assets/viewer.html:2509–2518` |
| **Rule** | SPEC-FIDELITY |
| **AC** | Task spec: "If a drawer is open within entity view (Transitions pane active): switch back to Info pane first, second Escape goes to dashboard" |
| **Spec Reference** | spec.md §5.4: "if a drawer is open, closes the drawer first" |

**Diagnosis**: The current Escape handler unconditionally navigates to dashboard from both `entity_view` and `doc_view`. It does not check whether the transitions pane is active (`entityViewTab === 'transitions'`). Per spec, a first Escape when the transitions drawer is open should switch back to the Info pane; only a second Escape (when already in Info pane) should return to dashboard.

**Evidence**:
```javascript
// Current (lines 2510–2518):
document.addEventListener('keydown', (e) => {
  if (e.key === 'Escape') {
    if (appState === 'entity_view' || appState === 'doc_view') {
      selectedKey = null;
      appState = 'dashboard';
      render();
    }
  }
});
```

**Correction**:
```javascript
document.addEventListener('keydown', (e) => {
  if (e.key === 'Escape') {
    if (appState === 'entity_view') {
      if (entityViewTab === 'transitions') {
        // Drawer is open — close it first (switch to Info pane)
        entityViewTab = 'info';
        renderEntityView();
      } else {
        // Info pane already showing — return to dashboard
        selectedKey = null;
        appState = 'dashboard';
        render();
      }
    } else if (appState === 'doc_view') {
      selectedKey = null;
      appState = 'dashboard';
      render();
    }
  }
});
```

### Finding 003 — BLOCKER: Refresh clears expansion state

| Field | Value |
|---|---|
| **ID** | 003 |
| **Severity** | Blocker |
| **File:Line** | `internal/viewer/assets/viewer.html:1464` |
| **Rule** | SPEC-FIDELITY |
| **AC** | "Header 'Refresh' reloads all cached data (TC-NAV-07)" — spec §2.6.4: "Expansion state persists across data refreshes" |
| **Spec Reference** | spec.md §2.6.4: "Expansion state persists across data refreshes (stored in `expandedEpics`/`expandedFeatures` Sets)" |

**Diagnosis**: `loadProjectData()` is called by both the initial Pick Folder button click AND the Refresh button. On every call it unconditionally reseeds `expandedEpics` to all epic keys (line 1464), effectively resetting any user-collapsed epics and losing any user-expanded features. The spec requires expansion state to survive refreshes.

**Evidence**:
```javascript
// Line 1464 — runs on every loadProjectData() call including Refresh:
expandedEpics = new Set(treeData.map(epic => epic.key).filter(Boolean));
```

**Correction**: The initial seed should only run on first load (from `pick_folder` state), not on Refresh. Split the behavior:

```javascript
// In loadProjectData(), replace line 1464:
// Only seed expandedEpics on initial load (from pick_folder state), not on refresh
if (appState === 'pick_folder') {
  expandedEpics = new Set(treeData.map(epic => epic.key).filter(Boolean));
  expandedFeatures = new Set();
}
// On Refresh: preserve expandedEpics and expandedFeatures as-is
// (add new epic keys that appear in the refreshed treeData, don't remove existing ones)
```

Or alternatively, merge new epic keys into existing expansion state:
```javascript
const newEpicKeys = new Set(treeData.map(epic => epic.key).filter(Boolean));
if (appState === 'pick_folder') {
  // First load: expand all epics
  expandedEpics = newEpicKeys;
  expandedFeatures = new Set();
} else {
  // Refresh: preserve existing expansion, add newly-appeared epics
  for (const k of newEpicKeys) {
    if (!expandedEpics.has(k)) expandedEpics.add(k);
  }
}
```
