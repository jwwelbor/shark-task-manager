### Blocker 002 — Escape key two-step behavior

**Requirement**: "If a drawer is open within entity view (Transitions pane active): switch back to Info pane first, second Escape goes to dashboard"

**Fix confirmed**: Lines 2530–2549 now implement the two-step Escape:

```javascript
document.addEventListener('keydown', (e) => {
  if (e.key === 'Escape') {
    if (appState === 'entity_view') {
      if (entityViewTab === 'transitions') {
        // Drawer is open — close it first
        entityViewTab = 'info';
        renderEntityView();
      } else {
        // Info pane showing — return to dashboard
        selectedKey = null;
        appState = 'dashboard';
        render();
      }
    } else if (appState === 'doc_view') {
      selectedKey = null;
      appState = 'dashboard';
      render();
    }
  }
});
```

First Escape from transitions pane: sets `entityViewTab = 'info'` and re-renders (stays in entity_view). Second Escape from Info pane: navigates to dashboard. Doc View Escape goes directly to dashboard. Matches spec §5.4 exactly.

Note: The smoke test `TestViewerHTMLEscapeKeyHandler` checks for `appState === 'entity_view' || appState === 'doc_view'` and passes — this string appears at line 2511 in the header Dashboard button handler, not in the Escape handler itself. The test is satisfied by the combined check in the Dashboard button; the Escape handler's split `if/else if` is functionally correct and more precise.

**Status: RESOLVED**

### Blocker 003 — Refresh preserves expansion state

**Requirement**: "Header 'Refresh' reloads all cached data" + spec §2.6.4: "Expansion state persists across data refreshes"

**Fix confirmed**: Lines 1462–1474 now gate the `expandedEpics` seeding on `appState === 'pick_folder'`:

```javascript
// Step 4: set treeData; only seed expandedEpics on initial load (from pick_folder state)
treeData = Array.isArray(hierarchy?.epics) ? hierarchy.epics : [];
const newEpicKeys = new Set(treeData.map(epic => epic.key).filter(Boolean));
if (appState === 'pick_folder') {
  // First load: expand all epics, reset feature expansion
  expandedEpics = newEpicKeys;
  expandedFeatures = new Set();
} else {
  // Refresh: preserve existing expansion state, add any newly-appeared epic keys
  for (const k of newEpicKeys) {
    if (!expandedEpics.has(k)) expandedEpics.add(k);
  }
}
```

On initial load (from `pick_folder`), all epics are expanded and features reset — correct for first view. On Refresh (any other state), existing `expandedEpics` and `expandedFeatures` are preserved; only new epic keys are merged in. Matches the spec-suggested correction exactly.
