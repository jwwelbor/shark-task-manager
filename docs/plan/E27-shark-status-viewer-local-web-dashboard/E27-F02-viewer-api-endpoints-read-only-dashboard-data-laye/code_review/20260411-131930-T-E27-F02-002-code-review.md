## Findings

### FINDING-01 (BLOCKER): `ViewerEntityHistoryRepository` interface signature is incompatible with the concrete repository

**File:** `internal/services/viewer_service.go` lines 82–86

The interface declares:
```go
type ViewerEntityHistoryRepository interface {
    ListByEntity(ctx context.Context, entityType models.EntityType, entityID int64) ([]*models.EntityHistory, error)
    ListRecentAcrossEntities(ctx context.Context, opts RecentActivityOptions) ([]*models.EntityHistory, error)
}
```

The concrete repository (`internal/repository/entityhistory/repository.go`) implements:
```go
func (r *EntityHistoryRepository) ListRecentAcrossEntities(
    ctx context.Context,
    opts ListRecentAcrossEntitiesOptions,
) ([]*RecentActivityRow, error)
```

Two mismatches:
1. Parameter type: interface expects `RecentActivityOptions`; repository uses `entityhistory.ListRecentAcrossEntitiesOptions`.
2. Return type: interface expects `[]*models.EntityHistory`; repository returns `[]*entityhistory.RecentActivityRow`.

Because Go interfaces are structurally typed, the concrete repository does NOT satisfy the interface. This only compiles today because the service is never wired with the real repository in a build unit. The moment `cmd/server/services.go` (or any wire-up code) tries to pass `*entityhistory.EntityHistoryRepository` as `ViewerEntityHistoryRepository`, it will fail to compile.

The concrete `RecentActivityRow` carries a `Title` field used to detect orphaned history rows (INNER JOIN in SQL eliminates them at the repository layer), which also means the service comment "Omit orphan entries" is misleading — the orphan-omission logic lives in the SQL query, not in the service loop, but the service is receiving `*models.EntityHistory` records which do not have a `Title` field at all, making the orphan filter code in the service unreachable.

**Required fix:** Align the interface with the concrete repository. Options:
- Define a separate `RecentActivityEntry` type in the `services` package that mirrors `entityhistory.RecentActivityRow`, and add an adapter/wrapper on the repository side, OR
- Import `entityhistory.RecentActivityRow` as the return type and adjust `RecentActivityOptions` to match or embed `entityhistory.ListRecentAcrossEntitiesOptions`.

### FINDING-02 (MINOR): `RecentActivity` orphan-omission is a no-op

**File:** `internal/services/viewer_service.go` lines 840–844

The comment says "Omit orphan entries (entity was deleted — title empty/nil from JOIN)" but the loop unconditionally appends every record:
```go
for _, r := range records {
    result = append(result, &ActivityRecord{EntityHistory: r})
}
```

There is no check on a `Title` field (which `*models.EntityHistory` does not have). The INNER JOIN in the SQL query (`repository.go`) already eliminates orphans at the DB layer, so no orphan records will arrive. The code comment is therefore misleading but not currently a functional bug — it would become one if the repository ever used an OUTER JOIN.

The comment should either be removed or updated to note "orphans are filtered by the INNER JOIN in the repository query". This is a clarity issue; it does not block the task on its own, but should be corrected alongside FINDING-01.
