## Independent Red-Team Findings

### Wiring Check (Not a defect)

`NewViewerHandler` and `RegisterRoutes` are defined in `internal/api/viewer/handler.go` but are NOT called from `cmd/server/main.go` (lines 83-85 wire task/feature/epic handlers only, not the viewer handler).

**This is intentional.** Task T-E27-F02-003 explicitly states in its Implementation Plan: "Ensure `RegisterRoutes` registers routes on the provided mux under the given prefix (T-E27-F02-004 will call this from `cmd/server/services.go`)." T-E27-F02-004 ("Wire ViewerService into ServiceContainer") lists T-E27-F02-003 as a dependency. The unregistered handler is not dead code — it is properly sequenced work.

### Interface Contract

`ViewerServicer` interface in `service.go` matches `*services.ViewerService` method signatures exactly. The compile-time check `var _ ViewerServicer = (*services.ViewerService)(nil)` at `service.go:26` catches any drift at build time. Verified: `make build` passes.

### CORS Middleware

All 5 behavioral cases from the task spec are correctly implemented:
- No Origin → calls next (no CORS headers): `cors.go:23-27`
- Local origin + non-OPTIONS → echoes Origin + `Vary: Origin`, calls next: `cors.go:31-44`
- Local origin + OPTIONS → 204 preflight, does NOT call next: `cors.go:36-43`
- Non-local origin → calls next without CORS headers: `cors.go:45`
- `url.Parse` error → treated as non-local (safe default): `cors.go:52-54`
- CORS is not applied globally; only viewer routes use `withLocalCORS` wrapper: `handler.go:48` — satisfies ADR-E27-007.

### Error Type Handling

- `SecurityError` → HTTP 403: `errors.As(err, &secErr)` pattern at `handler.go:125-128` — correct.
- `FileTooLargeError` → HTTP 413: `errors.As(err, &largeErr)` at `handler.go:129-132` — correct.
- Not-found → HTTP 404: `isNotFound` string match at `handler.go:333-339` — consistent with existing codebase convention in `internal/api/common.go`.

### RFC3339 Parse Order

`since` parsing in `RecentActivity` tries `time.RFC3339Nano` first (line 243), then falls back to `time.RFC3339` (line 246). Order is correct per spec.

### parseIntClamp Reverse-Validation (Non-blocking)

In `FeatureTasks` (lines 177-192), `parseIntClamp` is called before the non-integer validation check. Functionally safe: the 400 response fires and `return` is hit before `opts` is constructed and the service is called. The pre-computed `limit` value is discarded. The code review noted this correctly. No functional bug.

### types.go

The file contains only a comment explaining that DTO types live in `internal/services/`. This deviates from the task spec's prescribed layout (which described `types.go` as owning all DTO declarations) but is architecturally sound — avoids a duplicate source of truth. The compile-time interface check in `service.go` provides the contract guarantee the spec was seeking.

### Security

- Path traversal via `SecurityError` → 403 with safe user message (does not expose path): `handler.go:127`
- File size limit via `FileTooLargeError` → 413: `handler.go:131`
- Internal errors logged via `slog.Error` with structured `entity`/`endpoint`/`error` keys: verified across all 7 handler methods
- User-facing error messages do not expose SQL or filesystem internals: verified

### Tests Deferred (Expected)

`handler_test.go` does not exist yet — tests are scoped to T-E27-F02-006 per the task spec. This is documented and by design.
