- Joins `entity_history` to the parent table via `INNER JOIN` on `e.id = eh.entity_id AND eh.entity_type = 'epic'` — the entity_type guard in the JOIN condition is correct; it prevents cross-type collisions where an epic row and a task row happen to share the same `entity_id` value.

- Orphan omission via INNER JOIN (not LEFT JOIN) — satisfies task requirement and TC-R-004.

### FromStatus NullString Handling

```go
var fromStatus sql.NullString
err := rows.Scan(
    &row.EntityType, &row.Key, &row.Title,
    &fromStatus, &row.ToStatus, &row.ChangedAt,
)
if fromStatus.Valid {
    row.FromStatus = fromStatus.String
}
```

Correct: `from_status` is nullable in the schema (initial-creation rows have no prior status). Using `sql.NullString` prevents scan errors on NULL values. When invalid (NULL), `FromStatus` stays as its zero value `""`, which is the documented behavior.
