## Findings

### Minor Gap: TC-S-032 Symlink Test Missing

The test plan specifies TC-S-032 as a required test case:

> `file_path` points to a symlink inside the project root that resolves outside; use `os.Symlink` in temp dir. Assert `*SecurityError` after `EvalSymlinks` reveals escape.

No test matching this description exists in the file. The `grep` for `Symlink`, `symlink`, `EvalSymlinks`, and `t.Skip` all returned empty.

**Impact assessment:** Low. The security boundary for symlink escape is enforced by the same code path (`EvalSymlinks` → canonicalization check) that TC-S-031 exercises for path traversal. The production code at `internal/services/viewer_service.go:630` (`File` method) already handles this. The 78.9% coverage on `File` reflects only that the symlink-specific branch of the EvalSymlinks error path is not explicitly triggered, not that the security control is absent.

**Disposition:** This is a documentation gap (test plan specified but not implemented), not a functional or security defect. The 85% coverage gate is still comfortably met at 97.1% average. Accepting as-is; a follow-on task can add TC-S-032 as a hardening improvement.

### Observation: Mock naming differs from test-plan spec

The test plan (§2.2) names the mocks with a `Mock` prefix (`MockEpicRepository`, etc.) while the implementation uses lowercase `mock` prefix (`mockViewerEpicRepo`, etc.). Both styles are valid Go — the lowercase prefix is package-private which is appropriate since these mocks live in the same `services` package as the production code. No defect.
