# Task: Wire ViewerService into ServiceContainer in cmd/server/services.go

## Goal

Integrate `ViewerService` and `ViewerHandler` into the HTTP server entry point. Modify `cmd/server/services.go` to add `ViewerService` to `ServiceContainer`, wire all its dependencies inside `WireServices`, and call `viewer.RegisterRoutes` so the 7 endpoints are reachable at runtime.

## Requirements

### Functional Requirements

- [ ] Add `ViewerService *services.ViewerService` field to the `ServiceContainer` struct in `cmd/server/services.go`
- [ ] In `WireServices`, construct `ViewerService` using `services.NewViewerService(...)` with all required repository and service dependencies already available in the wiring function
- [ ] Pass `projectRoot` string to `NewViewerService` — determine how the server obtains project root (check `cmd/server/main.go`; it is typically derived from the config file path or passed as a flag)
- [ ] Create a `viewer.ViewerHandler` with the `ViewerService` and call `viewer.RegisterRoutes(mux, "/api/v1/viewer/")` in the server's route registration block
- [ ] Confirm the `withLocalCORS` middleware is applied by `RegisterRoutes` (not by the server's global middleware — CORS is viewer-scoped per ADR-E27-007)
- [ ] Ensure the existing server startup sequence is not disrupted — all existing endpoints continue to work

### Non-Functional Requirements

- [ ] `WireServices` remains the single place where all services are constructed (no service construction in `main.go` or handlers)
- [ ] `ViewerService` is a long-lived singleton constructed once at startup (matches HTTP service wiring pattern in architecture.md)

## Implementation Plan

### Steps

1. [ ] Read `cmd/server/services.go` and `cmd/server/main.go` to understand the existing `ServiceContainer` and `WireServices` pattern
2. [ ] Add `ViewerService *services.ViewerService` to `ServiceContainer`
3. [ ] In `WireServices`, instantiate repositories needed by `ViewerService` that are not already constructed (check which repos exist: `epicRepo`, `featureRepo`, `taskRepo` should already exist; verify `bugRepo`, `changeCardRepo`, `historyRepo` are available or create them)
4. [ ] Call `services.NewViewerService(epicRepo, featureRepo, taskRepo, bugRepo, changeCardRepo, historyRepo, workflowSvc, statusCalc, projectRoot)` and assign to `ServiceContainer.ViewerService`
5. [ ] In route registration: `viewerHandler := viewer.NewViewerHandler(services.ViewerService)` (or equivalent); call `viewer.RegisterRoutes(mux, "/api/v1/viewer/")`
6. [ ] Import `internal/api/viewer` and `internal/services` packages correctly

### Technical Approach

- Keep changes minimal and localized to `cmd/server/services.go` and the route registration section of `cmd/server/main.go` (or wherever routes are registered).
- If `statusCalc` (`*status.CalculationService`) is not yet instantiated in `WireServices`, construct it here following the pattern used elsewhere in the codebase.

## Deliverables

- [ ] `cmd/server/services.go` updated with `ViewerService` field and wiring
- [ ] Route registration updated to mount `/api/v1/viewer/` routes

## Acceptance Criteria

- [ ] `make build` passes
- [ ] `curl http://localhost:<port>/api/v1/viewer/summary` returns HTTP 200 (manual smoke test)
- [ ] `make test` passes with no regressions to existing server tests
- [ ] `make lint` passes

## Testing Strategy

The integration smoke test in T-E27-F02-006 (`cmd/server/viewer_integration_test.go`) covers the full wired-up server. This task does not require its own dedicated tests — the build succeeding and existing tests passing is the primary gate.
