# Task: Write ViewerService unit tests (mock repositories, all 7 methods)

## Goal

Create `internal/services/viewer_service_test.go` with full unit test coverage for all 7 `ViewerService` methods using function-field mock repository structs. No real database. Targets ≥ 85% service coverage per the test plan.

## Requirements

### Functional Requirements

- [ ] Create `internal/services/viewer_service_test.go` (or add to existing `mocks_test.go` for mocks)
- [ ] Declare function-field mock structs per `services/testing.md` pattern: `MockEpicRepository`, `MockFeatureRepository`, `MockTaskRepository`, `MockBugRepository`, `MockChangeCardRepository`, `MockEntityHistoryRepository`, `MockWorkflowService` — each with `Func` fields for every method called by `ViewerService`
- [ ] Each mock method delegates to its `Func` field if non-nil, else returns a descriptive error like `"XFunc not set"`
- [ ] Write TC-S-001 through TC-S-004 (`Summary` method tests) — see test-plan.md §4.1
- [ ] Write TC-S-010 through TC-S-013 (`Hierarchy` method tests) — see test-plan.md §4.2
- [ ] Write TC-S-020 through TC-S-023 (`History` method tests) — see test-plan.md §4.3
- [ ] Write TC-S-030 through TC-S-036 (`File` method tests — use `t.TempDir()` for temp project root; create/omit files as needed) — see test-plan.md §4.4
- [ ] Write TC-S-040 through TC-S-046 (`FeatureTasks` method tests) — see test-plan.md §4.5
- [ ] Write TC-S-050 through TC-S-055 (`RecentActivity` method tests) — see test-plan.md §4.6
- [ ] Write TC-S-060 through TC-S-063 (`WorkflowMeta` method tests) — see test-plan.md §4.7
- [ ] Use table-driven test pattern where multiple cases share setup shape

### Non-Functional Requirements

- [ ] No real database in any test in this file
- [ ] File system tests use `t.TempDir()` — no hard-coded paths
- [ ] TC-S-032 (symlink escape) uses `os.Symlink` inside a temp dir; skip if OS does not support symlinks (use `t.Skip`)
- [ ] Coverage target ≥ 85% for `internal/services/viewer_service.go`

## Implementation Plan

### Steps

1. [ ] Set up mock structs in `viewer_service_test.go` or a shared `mocks_test.go` in `internal/services/`
2. [ ] Write `Summary` tests first (simplest — pure count aggregation)
3. [ ] Write `Hierarchy` tests — verify sort order by providing scrambled mock data
4. [ ] Write `History` tests — verify entity type detection by key format (epic/feature/task/bug/change_card keys all tested)
5. [ ] Write `File` tests — requires `t.TempDir()` for project root; test path traversal (inject `../../etc/passwd` as `file_path` in mock return), missing file, symlink (skip if unsupported), oversized file (write exactly 2 MiB+1 bytes to temp file), exactly 2 MiB (should succeed)
6. [ ] Write `FeatureTasks` tests — provide mock tasks in scrambled execution_order/priority/created_at and assert sort; verify filter and pagination; verify limit clamping
7. [ ] Write `RecentActivity` tests — verify limit clamping (0→50, 9999→200); verify orphan omission logic
8. [ ] Write `WorkflowMeta` tests — verify direction computation (forward/backward/lateral) with controlled ordinal lists; verify missing level emits empty object

### Technical Approach

- For TC-S-031 (path traversal): mock `EpicRepo.GetByKey` to return an epic with `file_path = "../../etc/passwd"`. The service should detect the escape during canonicalization without reading the file.
- For TC-S-032 (symlink): create `<tmpdir>/projectroot/` and `<tmpdir>/outside/secret.txt`; create symlink `<tmpdir>/projectroot/link.md -> <tmpdir>/outside/secret.txt`; set `file_path = "link.md"` in mock return. Service must detect escape after `EvalSymlinks`.
- For TC-S-034 (2 MiB+1): write `(2*1024*1024)+1` bytes to a temp file. Use `os.WriteFile` with a pre-allocated slice. Assert `FileTooLargeError`.
- For TC-S-061 direction test: inject workflow mock returning status list `["draft","active","completed"]` and transitions `[{draft,active},{active,draft},{active,completed}]`. Assert directions are `forward`, `backward`, `forward`.
- All `Func` fields in mocks capture their arguments using local variables in the test body and assert them with `require.Equal` or `assert.Equal`.
