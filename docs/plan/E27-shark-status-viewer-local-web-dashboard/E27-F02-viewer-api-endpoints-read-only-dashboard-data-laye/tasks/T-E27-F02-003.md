# Task: Implement viewer API handler, types, CORS middleware, and route registration

## Goal

Create the `internal/api/viewer/` package: the `ViewerServicer` interface, all response DTO types, the `ViewerHandler` with 7 endpoint methods, localhost-only CORS middleware, and `RegisterRoutes`. This is the HTTP delivery layer for E27-F02.

## Requirements

### Functional Requirements

- [ ] Create `internal/api/viewer/service.go` — declare `ViewerServicer` interface with methods: `Summary`, `Hierarchy`, `History`, `File`, `FeatureTasks`, `RecentActivity`, `WorkflowMeta` (exact signatures per spec §4.2); also declare `FeatureTaskOptions` and `RecentActivityOptions` structs in this file
- [ ] Create `internal/api/viewer/types.go` — declare all response DTOs: `SummaryResponse`, `EpicSummary`, `StatusCount`, `TaskSummary`, `BugSummary`, `ChangeCardSummary`, `HierarchyResponse`, `EpicNode`, `FeatureNode`, `HistoryResponse`, `HistoryEntry`, `FileResponse`, `FeatureTasksResponse`, `TaskItem`, `RecentActivityResponse`, `ActivityEntry`, `WorkflowMetaResponse`, `LevelMeta`, `StatusMeta`, `TransitionMeta` — JSON tags must match the shapes in spec §3
- [ ] Create `internal/api/viewer/cors.go` — implement `withLocalCORS(next http.Handler) http.Handler` that: (a) parses `Origin` header; (b) checks host is `localhost` or `127.0.0.1` (any port); (c) if local, echoes `Origin` as `Access-Control-Allow-Origin` and sets `Vary: Origin`; (d) if OPTIONS, responds 204 with `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, `Access-Control-Max-Age` and returns without calling next; (e) if non-local origin, does not set CORS headers and calls next normally; (f) if no Origin header, calls next normally
- [ ] Create `internal/api/viewer/handler.go` — implement `ViewerHandler` struct with `ViewerServicer` field; implement `RegisterRoutes(mux *http.ServeMux, prefix string)` that mounts all 7 routes under `prefix` (e.g., `/api/v1/viewer/`) wrapped with `withLocalCORS`
- [ ] Each handler method follows the three-step pattern: (1) parse/validate path params and query params, (2) call service, (3) format JSON response
- [ ] Key path params are normalized to uppercase before service call
- [ ] `{key}` params validated with `internal/models/validation.go` regexes before any service call; invalid → 400
- [ ] `blocked` query param accepts only `"true"` or `"false"`; anything else → 400
- [ ] `entity_type` query param validated against allowlist `{"epic","feature","task","bug","change_card"}`; invalid → 400
- [ ] `since` query param parsed with `time.Parse(time.RFC3339, ...)` or `time.RFC3339Nano`; malformed → 400
- [ ] `limit` and `offset` are parsed as integers; non-integer values → 400; out-of-range values are clamped (not errored)
- [ ] Error responses use the existing `api.ErrorResponse` struct from `internal/api/` (check the existing `common.go` or similar file); handlers call `respondError(w, status, err)` helper
- [ ] `SecurityError` from `ViewerService.File` → HTTP 403; `FileTooLargeError` → HTTP 413; `NotFoundError` → HTTP 404; other errors → HTTP 500 with `slog.Error` log
- [ ] Internal errors logged via `slog.Error` with `"entity"`, `"endpoint"`, `"error"` keys; user-facing messages must not expose SQL or file system details

### Non-Functional Requirements

- [ ] CORS middleware applied only to viewer routes — not globally (ADR-E27-007)
- [ ] No business logic in handler methods — all computation in service
- [ ] `withLocalCORS` correctly handles `OPTIONS` preflight without calling downstream handler

## Implementation Plan

### Steps

1. [ ] Read existing `internal/api/` files (`common.go`, `task_handler.go`) to understand `ErrorResponse`, `respondJSON`, `respondError` helpers and the handler pattern in use
2. [ ] Create `internal/api/viewer/` directory
3. [ ] Write `service.go` — `ViewerServicer` interface and option types
4. [ ] Write `types.go` — all response DTOs with JSON tags matching spec §3 shapes exactly
5. [ ] Write `cors.go` — `withLocalCORS` middleware; parse `Origin` host using `net/url.Parse`
6. [ ] Write `handler.go` — `ViewerHandler`, `RegisterRoutes`, one method per endpoint
7. [ ] For each handler: parse params → validate → call service method → switch on error type → write JSON response
8. [ ] Ensure `RegisterRoutes` registers routes on the provided mux under the given prefix (T-E27-F02-004 will call this from `cmd/server/services.go`)

### Technical Approach

- Study `internal/api/task_handler.go` as the reference pattern for handler structure, error handling, and JSON output helpers.
- For CORS: use `net/url.Parse(origin).Hostname()` to extract host, then check `host == "localhost" || host == "127.0.0.1"`. The port is irrelevant per ADR-E27-007.
- Route mounting: if the server uses `http.ServeMux`, use pattern `/api/v1/viewer/{key}` (Go 1.22+ pattern syntax). If it uses a third-party mux (chi, gorilla), adapt accordingly — check `cmd/server/main.go` for the mux type in use.
- Key validation helper: write `validateAndNormalizeKey(key string) (string, string, error)` that tries each validation regex in order (epic → feature → task → bug → change_card) and returns the normalized uppercase key and detected entity type.
