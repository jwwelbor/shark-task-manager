## 4. Red-Team Findings

### RT-001: `file://localhost` and `//localhost` origins accepted [LOW — not a security issue]

**Finding:** `isLocalOrigin("file://localhost/anything")` returns `true`, and
`isLocalOrigin("//localhost")` returns `true`. These are accepted as local origins.

**Assessment:** Non-issue for this use case.
- Browsers do not send `file://localhost` as an `Origin` header for network XHR/fetch requests.
  The CORS spec defines the `Origin` for `file://` pages as either `"null"` or absent — neither
  of which would match `"localhost"` or `"127.0.0.1"` via `u.Hostname()`. An `Origin: null`
  request would have `origin == ""` and fall through the empty-origin path (no ACAO set).
- `//localhost` (protocol-relative) is not a valid value browsers send in the `Origin` header.
  If a non-browser client sends it deliberately, the worst outcome is that the CORS response
  headers are echoed — this endpoint is a read-only local dev tool serving no sensitive write
  operations.
- ADR-E27-007 explicitly scopes this to a developer tooling context where server is always
  bound to localhost. The attack surface is zero-exposure.

This is a theoretical curiosity worth a code comment, not a blocking defect.

### RT-002: IPv6 loopback `::1` not accepted [INFORMATIONAL — by design]

**Finding:** `isLocalOrigin("http://[::1]:3000")` returns `false`. A developer running a
browser on `::1` would not get CORS headers.

**Assessment:** Non-blocking. The task spec and ADR-E27-007 explicitly scope to `localhost`
and `127.0.0.1` only. IPv6 loopback support is not a requirement. Documented in code comment
on the `isLocalOrigin` function.

### RT-003: Case-sensitivity — `LOCALHOST` not accepted [INFORMATIONAL — by design]

**Finding:** `isLocalOrigin("http://LOCALHOST:3000")` returns `false` (`url.Hostname()`
returns lowercase `"localhost"` from the parsed URL for standard input... actually checking
this more carefully: `url.Parse` preserves the case of the hostname in the raw URL).

Wait — re-checking: `url.Parse("http://LOCALHOST:3000").Hostname()` returns `"LOCALHOST"` (Go
does not lowercase hostnames on parse). However, real browsers normalize `Origin` headers to
lowercase hostnames per RFC 6454 §7 and the URL standard. So `LOCALHOST` would never be sent
by a compliant browser. Non-issue.

### RT-004: Wiring confirmed

`handler.go:48`: `wrap := WithLocalCORS` — all viewer route registrations use this wrapper.
The middleware is live for all viewer routes and only viewer routes (confirming ADR-E27-007
scope compliance).
