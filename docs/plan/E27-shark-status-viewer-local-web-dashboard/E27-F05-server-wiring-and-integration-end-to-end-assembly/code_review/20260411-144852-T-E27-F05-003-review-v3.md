### Behavior verification (reading the implementation directly)

1. **All OPTIONS (any origin, including no Origin) → 204, do NOT call next:** Lines 28-41. Method check is first, unconditional `w.WriteHeader(http.StatusNoContent)` and `return` before any call to `next`. Confirmed correct.

2. **Local origin GET requests → ACAO + Vary + Allow-Methods + Allow-Headers:** Lines 49-58. All four headers set. Confirmed correct.

3. **Local origin OPTIONS → above headers + 204, no next:** Lines 28-40. `isLocalOrigin` check at line 29; if true, all 4 CORS headers set before the unconditional 204. Confirmed correct.

4. **Non-local origin, non-OPTIONS → call next, no CORS headers:** Lines 50-60. After OPTIONS branch and empty-origin branch, non-local origins fall through to `next.ServeHTTP(w, r)` at line 60 without setting any headers. Confirmed correct.

5. **`isLocalOrigin` with empty string:** `url.Parse("")` succeeds; `u.Hostname()` returns `""`, which is neither `"localhost"` nor `"127.0.0.1"`. Returns false. Correct.

6. **`Access-Control-Max-Age: 86400`** is set on OPTIONS preflight for local origins (line 35). Not required by the task spec but not prohibited either. This is a reasonable enhancement (reduces preflight frequency). No YAGNI concern for a value this small and standard.
