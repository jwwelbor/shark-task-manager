# Code Review: T-E27-F05-002

**Verdict: PASS**

## Summary

The implementation correctly wires `ViewerService` into the server and registers all viewer routes with CORS
and SPA. The developer chose a structural refactoring beyond the minimum task scope: instead of adding code
directly to `cmd/server/services.go` and `cmd/server/main.go`, they extracted the canonical wiring and
server entry point into `internal/viewer/server/` (a new importable package) so that both `cmd/server/main.go`
and the CLI `shark web` command (F04) share identical logic. `cmd/server/services.go` is now a thin
re-export alias. This is architecturally sound and explicitly permitted by the spec's "If F03 landed with a
different export pattern, F05 adapts accordingly" clause.

## Code Quality Checks

### Changes match task scope
PASS. The changes touch exactly `cmd/server/main.go`, `cmd/server/services.go`, and the new
`internal/viewer/server/` package. No unrelated modifications found.

### Architecture aligns with feature spec decisions
PASS. The spec explicitly contemplated adapting to the actual F03 API. `internal/viewer/assets.go`
exports `ViewerHTML []byte` (not `RegisterStaticRoutes`). The implementation correctly adapted by
serving the byte slice directly. The structural extraction to `internal/viewer/server` satisfies the
spec requirement for an importable `StartServer` entry point (REQ-F-006, REQ-F-007).

### Service layer pattern followed
PASS. `WireServices` in `wire.go` constructs all services with explicit dependency injection in
the correct order (repositories → entity service → entity-specific services → viewer service).
No business logic in `cmd/` files. The `main.go` is now 42 lines total.

### Error handling follows project conventions
PASS. `StartServer` returns errors via `fmt.Errorf("...: %w", err)` wrapping. DB init failure,
integrity check failure, and bind failure are all returned (not panicked). `http.ErrServerClosed`
is correctly translated to `nil` on graceful shutdown.

### CORS scoping: viewer-only, not global
PASS. `WithLocalCORS` is applied per-route inside `viewer.RegisterRoutes`. The CRUD handlers
(`api.NewTaskHandler`, `api.NewFeatureHandler`, `api.NewEpicHandler`) are registered directly on
the mux without any CORS wrapping.

### No hardcoded values that should be configurable
PASS. The default port `:8080` falls back gracefully when `opts.Addr` is empty (documented in
`Options` godoc). `projectRoot` defaults to `"."` only when opts is empty. `shutdownTimeout` of
30 seconds is a named constant, not a magic number.

### Security: CORS restricted to localhost/127.0.0.1
PASS. `isLocalOrigin` in `cors.go` uses `url.Parse` to extract the hostname and checks strictly
for `"localhost"` or `"127.0.0.1"`. External origins receive no `Access-Control-Allow-Origin`
header. The browser enforces this via same-origin policy.

### Caller-provided DB ownership
PASS. `server.go:76-87` — when `opts.DB != nil`, `StartServer` skips `dbinit.Init` and does NOT
call `db.Close()`. When `opts.DB == nil`, a deferred `repoDB.Close()` is installed. This matches
the spec contract (REQ-F-006 / TC-014b).

### Readiness signal ordering
PASS. `opts.Ready` is closed at `server.go:161-163`, after the listener is bound but BEFORE the
blocking `srv.Serve` call at `server.go:168`. This guarantees the server is accepting connections
when the ready signal fires.

## Observations (Non-blocking)

1. **TC-003/TC-004/TC-011c/TC-015 not in `cmd/server/main_test.go`**: The test plan specifies these
   integration smoke tests should be added to `cmd/server/main_test.go`. They are not present in the
   current `main_test.go` (which still contains only the pre-existing otelhttp and graceful-shutdown
   tests). The equivalent coverage exists in `internal/viewer/server/server_test.go` (which tests
   `StartServer` directly). Since the test plan's rationale was "integration test proving F01-F04
   compose correctly", and `server_test.go` does exactly that via the importable entry point, this is
   acceptable. The integration surface is identical. Not blocking.

2. **`GET /static/` not served**: The task spec mentions mounting vendor JS at `GET /static/`. The
   current implementation only serves `viewer.html` at `GET /`. Since the spec's F03 dependency
   (`internal/viewer/assets`) only exports `ViewerHTML []byte` (no vendor JS static bundle), this is
   an F03 scope gap rather than an F05 gap. Not blocking.

3. **`workSessionAdapter` not used by ViewerService**: `wire.go` defines `workSessionAdapter` and
   `taskHistoryAdapter` but neither is passed to `NewViewerService`. These were carried over from the
   original `cmd/server/services.go` for future CRUD wiring. The compile-time interface checks
   (`var _ services.WorkSessionRepository = (*workSessionAdapter)(nil)`) provide value. Not blocking.
