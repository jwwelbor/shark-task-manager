## 4. Red-Team Findings

### Finding 1: CORS per-route vs. sub-mux (implementation deviation from spec)

The task spec proposed mounting `viewer.WithLocalCORS(viewerMux)` as a single sub-mux at `/api/v1/viewer/`. The actual implementation applies `WithLocalCORS` per-route inside `RegisterRoutes`. This is a legitimate implementation difference with identical security properties — every viewer route is individually wrapped, so no viewer route lacks CORS coverage. The OPTIONS catch-all at `"OPTIONS "+prefix+"/"` ensures preflight requests are handled. Not a defect.

### Finding 2: GET /static/ not served (task spec gap, not implementation defect)

The task spec mentions `GET /static/` serving embedded vendor JS. `internal/viewer/assets.go` exports only `ViewerHTML []byte` — there is no vendor JS bundle. The viewer.html (77k) includes an inline script tag referencing CDN-hosted libraries. This is an F03 scope decision, not an F05 defect. The code review correctly classified this as non-blocking.

### Finding 3: Adversarial key input validation

`validateAndNormalizeAnyKey` on path values for `/history/{key}` and `/file/{key}` performs allowlist validation: only keys matching `IsShortTaskKey`, `IsTaskKey`, `IsFeatureKey`, `IsEpicKey`, `IsBugKey`, or `IsChangeCardKey` pass through. A path traversal attempt like `../../etc/passwd` will fail the pattern check and return HTTP 400. No injection risk identified.

### Finding 4: entity_type parameter allowlist in RecentActivity

`handler.go:223-229` uses `map[string]bool` allowlist for `entity_type`. Only `epic`, `feature`, `task`, `bug`, `change_card` are accepted. Other values return HTTP 400. Correct pattern per project input sanitization standards.

### Finding 5: DB ownership contract correctness

`server.go:76-87`: when `opts.DB != nil`, `callerOwnedDB = true` and the `defer repoDB.Close()` branch is skipped. When `opts.DB == nil`, `defer repoDB.Close()` is installed. TC-014b in `server_test.go` verifies this by confirming `repoDB.Ping()` succeeds after `StartServer` returns with a caller-provided DB. Correct.

### Finding 6: Readiness signal ordering

`server.go:161-163` closes `opts.Ready` AFTER the listener is bound but BEFORE the blocking `srv.Serve` call. TC-012 and TC-018 both verify the ready signal arrives within 500ms and that /health returns 200 immediately after. Correct.

### Finding 7: workSessionAdapter and taskHistoryAdapter unused by ViewerService

`wire.go` defines and compile-checks both adapters. Neither is passed to `NewViewerService`. They are present for future CRUD wiring. The compile-time interface checks (`var _ services.WorkSessionRepository = ...`) provide value by preventing silent drift. Non-blocking.
