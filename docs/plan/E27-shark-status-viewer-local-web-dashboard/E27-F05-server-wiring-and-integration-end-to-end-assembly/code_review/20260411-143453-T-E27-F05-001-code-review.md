## Implementation Quality

### cmd/server/main.go

The original 52-line main was reduced to 40 lines. It is now a correct thin wrapper:
1. Initializes observability.
2. Builds a signal-notified context.
3. Delegates to `viewerserver.StartServer(ctx, viewerserver.Options{Addr: ":8080"})`.
4. Logs error and exits non-zero on failure.

No hardcoded DB path. No direct repository calls. Follows the thin-wrapper pattern.

### internal/viewer/server/server.go

The extracted `StartServer` entry point is well-structured:

- **DB ownership contract:** `callerOwnedDB` flag correctly gates `defer repoDB.Close()`. When the caller passes `opts.DB`, the server does NOT close it (TC-014b verified).
- **Ready signal:** Closed after listener is bound but before `srv.Serve` blocks (Step 7), satisfying TC-012 and TC-018.
- **Graceful shutdown:** 30-second timeout preserved (`shutdownTimeout` constant). `http.ErrServerClosed` translated to `nil`. Goroutine drained after shutdown.
- **Error wrapping:** Uses `fmt.Errorf("...: %w", err)` at every error site. Follows project conventions.
- **No hardcoded paths:** `opts.ProjectRoot` defaults to `"."` when empty; delegated to `dbinit.Init`.
- **SPA route:** `GET /{$}` (Go 1.22 method-qualified pattern) serves embedded `viewer.html` correctly.
- **Health endpoint:** Pings DB on every request; returns 503 on failure; returns 200/"OK" on success. Matches original behavior.

One minor observation: the `srvErr` channel drain after shutdown (lines 196–198) re-checks `!errors.Is(err, http.ErrServerClosed)`. This is slightly defensive — `srv.Shutdown` waits for `srv.Serve` to return, so by the time we drain `srvErr`, the goroutine is done. This is harmless and actually guards against races in edge cases.

### cmd/server/services.go

Reduced from 341 lines to 26 lines. The canonical `WireServices` and `ServiceContainer` now live in `internal/viewer/server/wire.go` (importable by both `cmd/server` and `internal/cli/commands/web.go`). The `cmd/server` package retains thin type alias and delegation wrapper for backward compatibility. Clean and correct.

### internal/viewer/server/wire.go

`ViewerService` is properly wired into `ServiceContainer` (REQ-F-002). The service graph is complete and ordered (workflow → repos → entity service → domain services → viewer service). Compile-time interface checks are in place for adapters.

The `panic` calls in `NewNoteService`, `NewContextService`, and `NewResumeService` error paths are consistent with the existing CLI wiring pattern (fail-fast at startup if construction fails, not during request handling).

### Tests

`internal/viewer/server/server_test.go` covers TC-012, TC-013, TC-014b, and TC-018:
- Uses pre-bound `net.Listener` on port 0 (no port conflicts).
- Uses `db.InitDB(":memory:")` — isolated, no shared test DB pollution.

Test pattern is correct per test-plan §6 (real DB for integration tests in a tempdir/`:memory:` is explicitly permitted).
