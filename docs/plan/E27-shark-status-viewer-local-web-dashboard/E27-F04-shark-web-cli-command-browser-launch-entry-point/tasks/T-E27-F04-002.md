# Task: Add browser auto-open and CLI URL output formatting

## Goal

After the server starts and a port is resolved, print the viewer URL to stdout and automatically open the browser using the platform-appropriate command (`xdg-open` on Linux, `open` on macOS, `start` on Windows). Provide `--no-open` to skip browser launch. This task assumes T-E27-F04-001 has wired up the server; this task adds the UX layer on top.

## Requirements

### Functional Requirements

- [ ] Print `Shark viewer running at http://127.0.0.1:<port>` to stdout after server is ready
- [ ] Automatically invoke browser open command unless `--no-open` flag is set
- [ ] Detect OS at runtime: `runtime.GOOS == "linux"` → `xdg-open`, `"darwin"` → `open`, `"windows"` → `start`
- [ ] Browser open failure is non-fatal — print warning but continue serving
- [ ] Print `Press Ctrl+C to stop` hint after URL
- [ ] Handle SIGINT/SIGTERM for graceful shutdown: print `\nShutting down...` and exit cleanly

### Non-Functional Requirements

- [ ] No new Go module dependencies (use `os/exec` from stdlib)
- [ ] Output uses `cli.Info` / `cli.Success` helpers consistent with other commands
- [ ] Browser open is fire-and-forget (don't wait for browser to close)

## Implementation Plan

### Steps

1. [ ] Add `openBrowser(url string) error` helper function in `web.go`:
   - Switch on `runtime.GOOS`
   - `exec.Command("xdg-open", url).Start()` on Linux
   - `exec.Command("open", url).Start()` on macOS
   - `exec.Command("cmd", "/c", "start", url).Start()` on Windows
   - Return error for unsupported OS (non-fatal at call site)
2. [ ] In `runWeb`, after server is ready (listening):
   - Print URL with `fmt.Printf("Shark viewer running at http://127.0.0.1:%d\n", port)`
   - Print hint with `fmt.Println("Press Ctrl+C to stop")`
   - Unless `--no-open`, call `openBrowser(url)` and on error print warning via `cli.Warning`
3. [ ] Set up OS signal handler: `signal.NotifyContext(ctx, syscall.SIGINT, syscall.SIGTERM)`
4. [ ] Block on signal or server error; on signal print shutdown message and return nil

### Technical Approach

- `os/exec` `.Start()` (not `.Run()`) is essential — do NOT block waiting for browser to exit
- On CI/headless environments, `xdg-open` may fail; `--no-open` or graceful fallback required
- Windows `start` command requires shell invocation: `exec.Command("cmd", "/c", "start", url)`

## Deliverables

- [ ] `openBrowser(url string) error` helper in `internal/cli/commands/web.go`
- [ ] Signal handling in `runWeb` for graceful Ctrl+C shutdown
- [ ] URL output and user hint printed to stdout

## Acceptance Criteria

- [ ] Running `shark web` prints URL to stdout and opens default browser
- [ ] Running `shark web --no-open` prints URL but does NOT open browser
- [ ] On a Linux system, `xdg-open <url>` is invoked
- [ ] On macOS, `open <url>` is invoked
- [ ] Browser open error is logged as warning, not fatal
- [ ] Ctrl+C prints shutdown message and exits with code 0
- [ ] Output format is consistent with existing CLI command style

## Testing Strategy

Covered by T-E27-F04-003. The `openBrowser` function should be unit-testable by accepting an injectable exec command or by verifying the correct command string is constructed per OS.
