# Task: Write unit tests for shark web command

## Goal

Create `internal/cli/commands/web_test.go` covering `findFreePort` and `openBrowser` — the two pure-logic helpers that are unit-testable without a real server or database. CLI integration is light (thin wrapper), but the helpers have enough branching to merit explicit tests.

## Requirements

### Functional Requirements

- [ ] Test `findFreePort` happy path: when a port range has at least one free port, returns it
- [ ] Test `findFreePort` all-ports-busy: occupy all ports in range with listeners, expect error
- [ ] Test `findFreePort` boundary: `start > end` returns error immediately
- [ ] Test `openBrowser` constructs correct command per OS (mocked `runtime.GOOS` or via injectable executor)
- [ ] Test `openBrowser` non-fatal on unknown OS: returns error but does not panic

### Non-Functional Requirements

- [ ] Tests use no real database (CLI test pattern — mocked services)
- [ ] Tests run in <10ms each (no sleeping, no real network where avoidable)
- [ ] Follow existing test patterns in `internal/cli/commands/*_test.go`

## Implementation Plan

### Steps

1. [ ] Create `internal/cli/commands/web_test.go` with `package commands`
2. [ ] Write `TestFindFreePort_ReturnsFirstFreePort`:
   - Bind a listener to start port
   - Call `findFreePort(start, start+2)` — expect start+1 or start+2
   - Close listener in defer
3. [ ] Write `TestFindFreePort_AllBusy`:
   - Bind listeners to all ports in range (e.g., 3 ports)
   - Call `findFreePort` — expect error containing "no free port"
   - Close all listeners in defer
4. [ ] Write `TestFindFreePort_InvalidRange`:
   - Call `findFreePort(8080, 8079)` — expect error
5. [ ] Write `TestOpenBrowser_CorrectCommand` (if `openBrowser` is injectable):
   - If not injectable, verify the function exists and handles `runtime.GOOS` cases without panicking
   - At minimum, a smoke test that `openBrowser` on the current OS does not panic (may fail on CI without display — handle gracefully)

### Technical Approach

- `findFreePort` is pure Go (uses `net.Listen`) — testable by occupying ports with real listeners in the test
- `openBrowser` uses `os/exec` which is harder to unit test without injection. If the implementation does not support injection, write a compile-time existence test and a table-driven test that verifies the switch statement covers all expected OS strings
- Follow `internal/cli/commands/cloud_test.go` or `analytics_test.go` for file layout

## Deliverables

- [ ] `internal/cli/commands/web_test.go` with all test cases above

## Acceptance Criteria

- [ ] `go test ./internal/cli/commands/ -run TestFindFreePort` passes
- [ ] `go test ./internal/cli/commands/ -run TestOpenBrowser` passes (or is skipped on CI if display-dependent)
- [ ] `make test` passes with all new tests included
- [ ] `make lint` passes with no new warnings

## Testing Strategy

Unit tests only. No integration tests for this feature (the integration is tested when the full server stack is exercised in E27-F05 tests).

## Dependencies

- T-E27-F04-001 and T-E27-F04-002 must be complete (test file imports from `web.go`)

## Notes

- If `openBrowser` invokes `exec.Command(...).Start()`, the child process starts asynchronously — tests should NOT block waiting for browser to open
- Port-occupation tests must close listeners in `defer` to avoid port leaks across test cases
- Use `t.Parallel()` where safe to speed up the suite
