# Code Review: T-E27-F04-001 — Implement shark web command with port detection and server startup

## Summary

**Verdict: FAIL**

The implementation in `internal/cli/commands/web.go` is substantially correct and well-structured. Build compiles cleanly, lint passes, all tests pass. However, one Acceptance Criterion (AC #2) is not met: explicit `--port` flag does not fail fast; it falls back to auto-increment instead.

---

## Findings

### FAIL — AC #2: Explicit `--port` flag does not fail fast

**Location:** `internal/cli/commands/web.go`, line 87

**Current behavior:**
```go
port, err := findFreePort(webPort, webPort+13)
```
This always tries ports `webPort` through `webPort+13` regardless of whether the user explicitly passed `--port`.

**Required behavior (per task spec AC and Notes):**
- `shark web --port 8080` must use port 8080 specifically and fail fast if 8080 is busy.
- Auto-increment (try 8081, 8082, …) should only apply when the default port (7777) is used.

**Fix:**
```go
portChanged := cmd.Flags().Changed("port")
var port int
if portChanged {
    // User explicitly set a port — fail fast, do not auto-increment.
    port, err = findFreePort(webPort, webPort)
    if err != nil {
        return fmt.Errorf("port %d is already in use", webPort)
    }
} else {
    port, err = findFreePort(webPort, webPort+13)
    if err != nil {
        return fmt.Errorf("could not find a free port: %w", err)
    }
}
```
