## Outstanding Finding (Carried Forward from Review #1)

### FAIL -- AC#2: Explicit `--port` flag does not fail fast

**Location:** `internal/cli/commands/web.go`, line 94

**Task spec (AC#2):** "`shark web --port 8080` uses port 8080 specifically"

**Task spec (Notes):** "The `--port` flag: if user explicitly sets a port, skip auto-increment and fail fast if that port is busy"

**Current behavior:** Always auto-increments from `webPort` to `webPort+13`, even when the user explicitly sets `--port 8080`. This silently picks 8081 if 8080 is busy, violating the Principle of Least Surprise.

**Required fix:**

```go
var port int
var err error
if cmd.Flags().Changed("port") {
    // User explicitly set a port -- fail fast, do not auto-increment.
    port, err = findFreePort(webPort, webPort)
    if err != nil {
        return fmt.Errorf("port %d is already in use", webPort)
    }
} else {
    port, err = findFreePort(webPort, webPort+13)
    if err != nil {
        return fmt.Errorf("could not find a free port in range %d--%d: %w", webPort, webPort+13, err)
    }
}
```

Additionally, a test should be added to `web_test.go` verifying that when `start == end` and the port is busy, `findFreePort` returns an error (this case is already covered by `TestFindFreePort_AllBusy`, but a dedicated test for the explicit-port scenario would be ideal).
