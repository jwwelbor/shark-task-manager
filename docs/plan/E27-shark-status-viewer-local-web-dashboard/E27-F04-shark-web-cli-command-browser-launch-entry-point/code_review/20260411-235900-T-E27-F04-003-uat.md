## Red-Team Findings

### Finding 1: Error message content not asserted in TestFindFreePort_AllBusy (Minor, Non-Blocking)

**Observation:** The implementation plan (step 3) states: "expect error containing 'no free port'". The test at line 58 only checks `err == nil` — it does not assert the error message contains "no free port".

**Implementation returns:** `fmt.Errorf("no free port found in range %d–%d", start, end)` (web.go line 62)

**Assessment:** The functional requirement (requirement 2) states only "expect error" — no message content check is mandated. The implementation plan's mention of "no free port" is descriptive guidance, not a hard requirement. The test correctly verifies the behavioral contract (error returned when all ports busy). This is not a defect.

### Finding 2: t.Parallel() not used (Non-Issue)

**Observation:** The task notes "Use t.Parallel() where safe to speed up the suite." No test in `web_test.go` calls `t.Parallel()`.

**Assessment:** Zero of approximately 90 sibling test files in `internal/cli/commands/` use `t.Parallel()`. This is consistent with the package's established pattern. The note in the task spec is advisory ("where safe"), not mandatory. Non-blocking.

### Finding 3: TestFindFreePort_AllBusy uses 1 busy port instead of "e.g., 3 ports" (Non-Issue)

**Observation:** The spec says "Bind listeners to all ports in range (e.g., 3 ports)". The test binds 1 listener and restricts the range to that 1 port — functionally equivalent but simpler.

**Assessment:** "e.g., 3 ports" is an example, not a constraint. Single-port all-busy testing is cleaner and correctly covers the error path. Non-blocking.

### Finding 4: openBrowserForOS - exec injection via URL (Security, Informational)

**Observation:** `openBrowserForOS` passes `url` directly as a shell argument to `xdg-open`, `open`, or `cmd /c start`. The URL is always generated internally as `http://127.0.0.1:<port>` (web.go line 155) — never from user input. No injection risk exists in the current implementation.

**Assessment:** Not a defect. Documented for completeness.
