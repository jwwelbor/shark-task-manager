# Add edit/save UI to SPA viewer (edit button, textarea, save/cancel)

## Goal

Modify `internal/viewer/assets/viewer.html` to add an inline edit flow. An
Edit button appears in the toolbar when a file is loaded. Clicking it switches
the content pane to a full-width textarea. Save sends a PUT with JSON body
`{"path": editFilePath, "content": textarea.value}` and re-renders on success.
Cancel restores the previous rendered markdown with no write.

## Scope

- Files to modify: `internal/viewer/assets/viewer.html`

## Acceptance Criteria

See spec.md §1.3 AC-01, AC-02, AC-03, AC-04, AC-07.

- AC-T1: Edit button visible only when a file is loaded (Info tab active); hidden otherwise.
- AC-T2: Clicking Edit shows textarea pre-filled with raw content and Save/Cancel buttons.
- AC-T3: Save sends `PUT /api/v1/edit/file` with JSON body containing `path` (from `FileResponse`) and `content`.
- AC-T4: Successful save re-renders markdown from textarea content — no extra fetch.
- AC-T5: Cancel restores previous rendered view; no write issued; no confirmation dialog.
- AC-T6: Non-2xx save response shows inline error banner; textarea stays open with edits intact.
- AC-T7: Save button disabled during in-flight request.
- AC-T8: Edit works for both entity file view and standalone doc file view.

## Test Cases

and covered by epic UAT plan (not Go unit tests).
