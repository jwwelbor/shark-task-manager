# Add EditHandler with PUT /api/v1/edit/file endpoint

## Goal

Create `internal/api/viewer/edit_handler.go` with a thin HTTP handler that
parses a JSON body containing `path` and `content`, delegates to
`EditService.WriteFile`, and maps service errors to HTTP status codes. Also
create the corresponding test file with a mock.

## Scope

- Files to create:
  - `internal/api/viewer/edit_handler.go`
  - `internal/api/viewer/edit_handler_test.go`

## Acceptance Criteria

See spec.md §1.3 AC-02, AC-04, AC-05, AC-06, AC-08 and Architecture §2.3, §2.5.

- AC-T1: `EditServicer` interface defined in handler file for mock injection.
- AC-T2: `http.MaxBytesReader` (2 MiB) applied before JSON decode; oversized body → 413.
- AC-T3: Missing `path` or `content` field in JSON body → 400.
- AC-T4: `SecurityError` from service → 400 Bad Request.
- AC-T5: Other service errors → 500 Internal Server Error.
- AC-T6: Success → 200 with JSON body `{"path","bytes_written"}`.
- AC-T7: Handler reuses `respondJSON` / `respondError` helpers from `handler.go`.
