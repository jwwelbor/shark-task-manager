## Code Quality Review

### Public API (`internal/dbinit/init.go`)

**Options struct** — Matches spec exactly. Both `ProjectRoot` and `ConfigPath` fields with correct doc comments explaining auto-discovery behaviour.

**`Init` function** — Correct dispatch logic with `"sqlite"`, `"local"`, `""` mapping to local and `"turso"` routing to Turso init. Unsupported backends return a clear error containing `"unsupported database backend"`. Error wrapping follows project conventions throughout.

**`MustInit`** — Correctly panics with message `"dbinit: failed to initialize database: ..."`. Panic message contains `"dbinit:"` prefix for log grepping.

**`resolveRoots`** (spec calls it `resolveProjectRoot` + `resolveConfigPath`) — Combined into one helper, which is a reasonable simplification. Logic is correct: explicit `ProjectRoot` bypasses walk, explicit `ConfigPath` bypasses default join, falls back cleanly.

**`loadDatabaseConfig`** — Correct fallback to local defaults when file is missing or has no `database` section. `os.ExpandEnv` applied to `backend`, `url`, and `auth_token_file` fields. Default URL falls back to `configDir/shark-tasks.db` (uses config file's directory rather than `projectRoot`) — this is correct for the common case where the config lives at the project root, and the task spec says "If `url` is empty → default to `<projectRoot>/shark-tasks.db`". There is a subtle discrepancy: when `ConfigPath` and `ProjectRoot` differ, the default URL is computed from `filepath.Dir(configPath)` rather than `projectRoot`. This is acceptable because if a caller supplies an explicit `ConfigPath` they are also expected to supply an explicit URL, and the fallback to `configDir` is a safe local default.

**`initLocal`** — Simple and correct. Calls `db.InitDB(dbPath)`, wraps result in `repository.NewDB`. Error message includes the path for debuggability.

**`initTurso`** — Auth token loading order is correct: `AuthTokenFile` → `TURSO_AUTH_TOKEN` env → proceed with URL as-is. Calls `dbConfig.Validate()` before dialling. Type-assertion check on `*db.TursoDriver` is explicit with a clear error message. `SkipMigrations` branching is correct.

### `internal/dbinit/project_root.go`

Walk algorithm matches the documented priority ordering: `.sharkconfig.json` > `shark-tasks.db` > `.git/`. The "continue scanning all levels" approach (not stopping at the first marker found) ensures the highest-priority marker wins even if a lower-priority one appears lower in the tree. This mirrors `cli.FindProjectRoot` behaviour correctly. The duplication comment is present and points to `internal/cli/root.go`.

One deviation from the task spec: the spec says to return an error `"dbinit: project root: could not locate project root"` when nothing is found. Instead, the implementation falls back to `startDir`. This matches the behaviour of `cli.FindProjectRoot` (which also falls back rather than erroring) and is therefore a safe, consistent choice. All callers treat the returned directory as the root without checking for a "not found" error.

### `internal/cli/db_init.go`

Correctly delegates to `dbinit.Init` with explicit `ProjectRoot` and `ConfigPath` wired from `cli.FindProjectRoot`. The function signature `initDatabase(ctx context.Context) (*repository.DB, error)` is preserved unchanged for `db_global.go` compatibility.

**Minor observation:** The spec shows the delegate as a one-liner `return dbinit.Init(ctx, dbinit.Options{})` (letting dbinit auto-discover the root). The implementation takes the slightly more explicit approach of calling `cli.FindProjectRoot()` first and passing it in. This is equivalent in behaviour and actually stronger (uses the CLI's own project root discovery, avoiding any subtle divergence). Acceptable.

### `cmd/server/main.go`

`db.InitDB("shark-tasks.db")` hardcode is replaced with `dbinit.Init(context.Background(), dbinit.Options{})`. The `defer repoDB.Close()` is correctly positioned. `db.CheckIntegrity(repoDB.DB)` accesses the embedded `*sql.DB` field directly — this works as long as `repository.DB` embeds `*sql.DB` as a named or unnamed field. The `slog.Info` lines `"Database initialized successfully"` and `"Database integrity check passed"` are preserved verbatim (REQ-NF-003 met).

### Error Handling

All errors are wrapped with business context. Error messages begin with `"failed to ..."` rather than the spec's `"dbinit: ..."` prefix, which is a minor style divergence but within project conventions and still greppable. No errors are silently ignored.
