# Add epic-scoped dashboard pane and extend section renderers

## Goal

Extend `viewer.html` so that clicking an epic node shows a "Dashboard" tab
by default. Add `renderEpicDashboardPane` function and augment the five
existing section renderers with an optional `epicKey` parameter for
client-side filtering, reusing all existing card/badge templates.

## Scope

- Files to modify:
  - `internal/viewer/assets/viewer.html`

## Acceptance Criteria

See spec.md §1.1 REQ-F-001 (AC-001.1 through AC-001.9) and REQ-NF-001
(AC-NF-001.1, AC-NF-001.2). See spec.md §2.7 for line references.

- AC-T1: `navigateToEntity()` sets `entityViewTab = 'dashboard'` when entity
  type is epic; otherwise sets `'info'` (spec.md §2.2.1).
- AC-T2: Dashboard button (`id="ev-tab-dashboard"`) appears before Spec
  button (`id="ev-tab-info"`) in the toggle bar HTML string.
- AC-T3: Dashboard button only rendered when `isEpic === true`; features and
  tasks get no Dashboard tab.
- AC-T4: Guard in `renderEntityView()`: if `entityViewTab === 'dashboard'`
  and `!isEpic`, coerce to `'info'` before rendering.
- AC-T5: `renderEpicDashboardPane(epicKey, paneEl)` defined after
  `renderDashboard()`; renders all five section titles.
- AC-T6: All five section renderers accept optional `epicKey` param:
  `renderStatusBreakdown`, `renderFeatureProgress`, `renderActiveTransitions`,
  `renderStaleEntities`, `renderEntityCharts`.
- AC-T7: `renderEpicDashboardPane` wires `data-navigate-key` delegation via
  existing pattern (no new delegation logic).
- AC-T8: No new `fetch(` or `apiGet` calls introduced in the new function.
