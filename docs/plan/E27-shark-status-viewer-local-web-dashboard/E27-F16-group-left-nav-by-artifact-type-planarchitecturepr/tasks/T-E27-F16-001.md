# Add browsable-folder config and navigation-folder service

## Goal

Make configured and built-in navigation folders available through a secure, read-only service contract while preserving configuration compatibility.

## Scope

- Files to modify: `internal/config/config.go`, `internal/config/config_test.go`
- Files to modify: `internal/services/viewer_service.go`, `internal/services/viewer_service_test.go`

## Acceptance Criteria

Reference: `spec.md` REQ-F-005, REQ-F-006, REQ-NF-002 and §4.2–4.5.
- AC-T1: Produce the ordered built-in and valid configured folder response, including labels, stable ids, source, and availability.
- AC-T2: Omit empty, traversal, absolute, and symlink-escape entries with one warning per rejected entry while retaining valid entries.
- AC-T3: Preserve unknown configuration keys and keep absent or empty folder configuration a safe no-op.

## Test Cases

Reference: `test-plan.md` TC-018–TC-023, TC-026–TC-030, TC-035, TC-037 and §8 caller-path contracts.

### Cross-feature

None. `spec.md` §5 declares no I-## contracts.

### Cross-epic

None. `spec.md` §6 declares no X-## contracts.

## Design Reference

See `spec.md` §4.2, §4.4–4.5, ADR-F16-4, ADR-F16-7, and ADR-F16-8; reuse the research report Capability map's existing containment primitive.

## Brownfield Context

Extend `WebConfig`, `GetWebPort`'s nil-safe accessor pattern, `ViewerService` optional setters, and the established `FolderFiles` containment flow; do not add a second path-safety helper.

## Notes for Agent

Write failing service/config tests first. Keep all path validation in the service and leave database, repository, and migration surfaces unchanged.
