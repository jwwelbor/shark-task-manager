# Add tech-debt and ideas sections to sidebar hierarchy tree view

## Goal

Bugs, change cards, and ideas are already returned in the `HierarchyResponse` from
`ViewerService.Hierarchy()` and rendered via `buildFlatSectionHtml`. However the sidebar
comment at line ~4441 of `viewer.html` still references "Tech Debt" as a planned section
that does not exist. This task verifies that all four flat entity sections (Bugs, Change
Cards, Ideas, and any additional flat types) are rendered correctly in the sidebar and adds
a "Tech Debt" section if a backing entity type exists, or documents why it is out of scope.

## Scope

- Files to modify:
  - `internal/viewer/assets/viewer.html` — verify/extend `renderSidebar()` flat-section block
  - `internal/services/viewer_service.go` — extend `HierarchyResponse` if a tech-debt entity type exists
- Files to create: none

## Acceptance Criteria

See spec (epic.md Phase 2) and architecture.md §1.1 for flat-section design.

Additional task-specific criteria:
- AC-T1: Sidebar renders Bugs, Change Cards, and Ideas sections when data is non-empty.
- AC-T2: Each item in a flat section shows a status dot, entity key, and title.
- AC-T3: If a "tech debt" or equivalent entity type exists in the models, it appears as its own section; otherwise the comment is removed and the gap is documented as out-of-scope.
- AC-T4: Sections whose data arrays are empty or nil are not rendered (no empty headings).
- AC-T5: `showCompleted` filter applies to flat-section items the same as epic/feature items.

## Test Cases

Manual verification using `shark web`:
- Navigate to a project with bugs and change cards; confirm they appear in the sidebar.
- Toggle "Show completed" checkbox; confirm completed flat-section items appear/disappear.
- Project with no bugs: confirm Bugs section heading is absent.
