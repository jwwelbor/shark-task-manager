# Fix missing timestamps on transition history view rows

## Goal

The history table in the entity detail pane renders each row with a `date` field
populated via `formatDateTime(entry.changed_at || entry.created_at || entry.timestamp || '')`
(line ~4099 of `viewer.html`). In practice, `models.EntityHistory.ChangedAt` is serialized
as `"changed_at"` in JSON. If the server returns null or zero-value timestamps (e.g. the
`TaskHistory` model uses a `"timestamp"` field rather than `"changed_at"`), the date cell
renders as an empty string or "Invalid Date". This task audits the field names returned by
the `/api/v1/viewer/history/{key}` endpoint, aligns the JS field-access chain with the
actual JSON keys, and ensures the duration calculation between rows also uses the correct
field.

## Scope

- Files to modify:
  - `internal/viewer/assets/viewer.html` — history sort comparator (~line 4091), date
    extraction (~line 4099), duration `tThis`/`prevTs` chain (~lines 4111–4114)
  - `internal/services/viewer_service.go` — `History()` method: verify `HistoryResponse`
    populates `changed_at` consistently for all entity types (task, feature, epic, bug, etc.)

## Acceptance Criteria

Additional task-specific criteria:
- AC-T1: History rows always display a non-empty date string in the date column.
- AC-T2: Dates are displayed in the `formatDateTime` locale format (e.g. "Apr 13, 2026 10:30 AM").
- AC-T3: Duration column shows a valid interval ("for 2h 15m") or "—" when the interval cannot be computed; it never shows "for NaN" or similar.
- AC-T4: `HistoryResponse.Records` uses a consistent `changed_at` JSON field for all entity types surfaced by the viewer.
- AC-T5: If an entity type uses a different field name (e.g. `timestamp`), the JS field-access chain handles both.

## Test Cases

Manual verification:
- Open a task with at least two status transitions; confirm all rows in the history tab show dates.
- Open an epic or feature with history; confirm dates and durations render correctly.
- Open an entity with only a single history record; confirm duration is "—" for that row.
