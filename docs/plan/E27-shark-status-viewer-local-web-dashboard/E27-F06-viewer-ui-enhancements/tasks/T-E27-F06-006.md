# Fix copy-path button on entity files and add to non-entity file views

## Goal

The entity info panel already renders `copyBtn(entity.file_path)` next to the File Path
row (line ~3132 of `viewer.html`). The global copy-button delegation handler at line ~4606
writes the `data-copy-value` attribute to the clipboard. However, the folder-files pane
(`renderFolderFilesPane`) does not include a copy button next to individual file entries,
and the doc-view header path subtitle at line ~4196 includes a copy button but its
`data-copy-value` depends on `rawPath` which may be undefined when the doc key is a
synthetic key rather than a real file path. This task verifies the entity-file copy button
works for all entity types, adds a copy button to each file entry in the folder-files pane,
and ensures the doc-view path subtitle copy button always has a valid value.

## Scope

- Files to modify:
  - `internal/viewer/assets/viewer.html` — `renderFolderFilesPane()` (~line 4688): add
    `copyBtn` to each non-directory file entry; doc-view header path subtitle (~line 4196):
    guard `rawPath` against empty/undefined; entity info panel `copyBtn` call (~line 3132):
    verify `entity.file_path` is non-null before rendering.

## Acceptance Criteria

Additional task-specific criteria:
- AC-T1: Copy button appears next to the File Path row for all entity types that have a `file_path` (task, feature, epic, bug, change card).
- AC-T2: Clicking the copy button writes the full relative file path to the clipboard.
- AC-T3: Each non-directory file entry in the folder-files pane shows a copy button that copies the entry's `path` value.
- AC-T4: The doc-view header copy button is only rendered when `rawPath` is a non-empty string.
- AC-T5: No `data-copy-value` attribute is set to an empty string or "undefined".

## Test Cases

Manual verification:
- Select a task; confirm the File Path row shows a copy button; click it; paste into editor to verify.
- Open a folder via "Show all files" sidebar filter; click a file's copy button; verify path is correct.
- Select a doc node whose key contains no `/`; confirm no broken copy button appears.
