# Show only filename (not full path) for non-entity files in tree view

## Goal

`buildDocNodeHtml()` (line ~4322 of `viewer.html`) already strips the directory prefix
from path-like doc keys to show only the filename in the sidebar tree: if `key.includes('/')`
it takes `key.split('/').pop()`. However the flat-section items rendered by
`buildFlatSectionHtml()` and the folder-files items rendered by `renderFolderFilesPane()`
use `entry.name` (correct) but the sidebar doc nodes attached to epics and features may
still expose full relative paths in the key/title slots when the `HierarchyDoc` title is
absent. This task audits all sidebar node-rendering functions for non-entity files and
ensures they display only the filename portion, not the full relative path.

## Scope

- Files to modify:
  - `internal/viewer/assets/viewer.html` — `buildDocNodeHtml()` (~line 4320),
    `buildFlatSectionHtml()` (~line 4419), and the folder-file item rendering in
    `renderFolderFilesPane()` (~line 4688)

## Acceptance Criteria

Additional task-specific criteria:
- AC-T1: In the sidebar tree, doc nodes attached to epics and features display the basename (filename without path) in the key or title slot.
- AC-T2: `buildDocNodeHtml()` never renders a full path string visible to the user in the sidebar.
- AC-T3: Flat-section items (bugs, change cards, ideas) display their short entity key, not a file path.
- AC-T4: The full path is preserved as the `data-key` attribute for navigation (the path is not lost).
- AC-T5: When a `HierarchyDoc.title` is provided it takes precedence over the basename.

## Test Cases

Manual verification:
- Open a project with epic-level docs (e.g. `docs/plan/E27/architecture.md`); confirm
  the sidebar shows `architecture.md`, not the full path.
- Enable "Show all files" in sidebar filter; confirm folder-file entries show filenames.
