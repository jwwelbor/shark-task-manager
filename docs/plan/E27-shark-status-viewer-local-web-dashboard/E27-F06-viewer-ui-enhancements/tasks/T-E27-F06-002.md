# Collapse tree view by default (epics collapsed on page load)

## Goal

On initial page load the sidebar tree starts fully collapsed — `expandedEpics` and
`expandedFeatures` are both initialized to empty Sets (line ~1915 of `viewer.html`).
However, during a project reload (refresh interval or manual refresh) the current code
path reuses the existing expansion state. This task verifies the initial-load collapse
behavior works correctly and does not regress after a refresh, then wires a keyboard
shortcut or UI button to collapse all nodes on demand.

## Scope

- Files to modify:
  - `internal/viewer/assets/viewer.html` — `initApp()` expansion-state logic (~line 1907),
    optional "Collapse All" button in the sidebar filter bar

## Acceptance Criteria

See epic.md Phase 3 SPA features ("collapsible tree").

Additional task-specific criteria:
- AC-T1: On first page load, `expandedEpics` and `expandedFeatures` are both empty Sets.
- AC-T2: All epic nodes appear collapsed; no feature or task nodes are visible until the user clicks.
- AC-T3: After a background data refresh, previously-expanded nodes remain expanded.
- AC-T4: A "Collapse All" button or keyboard shortcut resets `expandedEpics` and `expandedFeatures` to empty Sets and re-renders the sidebar.
- AC-T5: Collapsing behavior is consistent in both the initial load and post-refresh paths.

## Test Cases

Manual verification:
- Load dashboard fresh; confirm sidebar shows only epic-level nodes.
- Expand epic E27, then manually trigger a data refresh; confirm E27 remains expanded.
- Click "Collapse All" (if added); confirm all nodes return to collapsed state.
