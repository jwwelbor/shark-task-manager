# Fix low-contrast status badge text (white on yellow/light backgrounds)

## Goal

The `.status-badge` CSS class has a hardcoded `color: #fff` (line ~370 of `viewer.html`).
When a status badge uses a light background such as yellow (`#e7b30e`) the white text
produces a contrast ratio below the WCAG 2.1 AA threshold (4.5:1 for small text).
The `getContrastColor()` function already exists and computes the correct foreground
(`#000` or `#fff`) from relative luminance, but it is only applied dynamically in some
badge sites. This task removes the hardcoded `#fff` from the CSS class so all badge
renders rely exclusively on the inline `color:` set by JS.

## Scope

- Files to modify:
  - `internal/viewer/assets/viewer.html` — remove `color: #fff` from `.status-badge` CSS rule
    (~line 370); audit all `<span class="status-badge"` template sites to ensure each one
    passes `color:${getContrastColor(color)}` as an inline style.

## Acceptance Criteria

Additional task-specific criteria:
- AC-T1: `.status-badge` CSS no longer contains `color: #fff`.
- AC-T2: Every template site that generates a `.status-badge` span also sets an inline `color:` via `getContrastColor()`.
- AC-T3: Yellow-background badges (`in_progress`, `open`, etc.) display black text.
- AC-T4: Dark-background badges (blocked, red) continue to display white text.
- AC-T5: No visual regression on status badges in the sidebar, history table, overview panel, or dashboard cards.

## Test Cases

Manual verification:
- Load dashboard; inspect `in_progress` task in sidebar — badge text must be dark (not white).
- Load history pane for any entity — from/to badges with yellow background show black text.
- Load dashboard summary cards — status badge pills use correct contrast.
