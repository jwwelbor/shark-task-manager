# Task: Add tab segment to breadcrumb and push browser history on tab switch

## Goal

Two related improvements to navigation:

1. **Breadcrumb shows current tab** — when viewing the "Spec" tab of `E27-F09`, the breadcrumb reads `E27 › E27-F09 › Spec` instead of stopping at the entity key. This gives users a full location indicator at all times.

2. **Browser back/forward works across tab switches** — each time the user clicks a tab (Overview, Spec, Files, History, Notes, etc.) the SPA pushes a history entry via `history.pushState`. When the user presses the browser back button they return to the previous tab, and eventually to the previous entity. The on-screen back button can then be removed.

## Requirements

### Breadcrumb

- [ ] Append the active tab name as the last breadcrumb segment after the entity key segment
- [ ] Tab segment is plain text (not a link), styled like existing breadcrumb segments
- [ ] Tab segment updates whenever `entityViewTab` changes (reactive to tab switches)
- [ ] When no entity is selected, the tab segment is absent

### Browser History

- [ ] On tab switch: call `history.pushState({ entityKey, tab }, '', url)` where `url` encodes both the entity key and tab (e.g. `?entity=E27-F09&tab=spec`)
- [ ] On entity navigation: call `history.pushState({ entityKey, tab: 'overview' }, '', url)` — existing navigation already may do this; extend to include tab
- [ ] On `popstate` event: restore both `selectedEntity` and `entityViewTab` from `event.state`; re-render detail pane without a full page reload
- [ ] Initial page load with `?entity=X&tab=Y` in URL: restore state on load (so bookmarks and refreshes work)
- [ ] Remove the on-screen back button (`←` / Back button in the header/toolbar) once browser history works; if no explicit back button exists currently, skip this step

### URL scheme

Use query params (not hash) for compatibility with the existing server:
- Entity only: `?entity=E27-F09`
- Entity + tab: `?entity=E27-F09&tab=spec`
- No selection: base URL with no params

## Implementation

All changes in `internal/viewer/assets/viewer.html`.

**Breadcrumb**: Find `renderBreadcrumb` (or wherever breadcrumb HTML is assembled). Add a final segment using the current `entityViewTab` value. Map internal tab IDs to display names (e.g. `overview` → `Overview`, `spec` → `Spec`, `files` → `Files`, `history` → `History`, `notes` → `Notes`, `related` → `Related Docs`).

**History push**: Find `entityViewTab = ...` assignment sites (tab click handlers). After each assignment, call:
```js
const url = new URL(window.location);
url.searchParams.set('entity', currentEntityKey);
url.searchParams.set('tab', entityViewTab);
history.pushState({ entityKey: currentEntityKey, tab: entityViewTab }, '', url);
```

**History pop**: Add a `window.addEventListener('popstate', e => { ... })` handler that reads `e.state` and restores `selectedEntity` + `entityViewTab`, then re-renders the detail pane.

**Initial load**: In the startup/init section, read `new URLSearchParams(location.search)` and if `entity` param is present, navigate to that entity and tab.

## Acceptance Criteria

- [ ] Breadcrumb shows `Parent › Entity › Tab` when an entity and tab are active
- [ ] Breadcrumb tab segment updates immediately on tab click
- [ ] Clicking a tab pushes a browser history entry
- [ ] Pressing browser back navigates to the previously selected tab (or entity)
- [ ] Pressing browser back after entity navigation returns to the previous entity
- [ ] Refreshing the page with `?entity=E27-F09&tab=spec` in the URL restores the correct entity and tab
- [ ] No regression in existing entity navigation (clicking sidebar items still works)
- [ ] `make test` passes
