# Task: Structured JSON Error Output

## Goal

When `--json` mode is active (including via `SHARK_OUTPUT=json` from T-002), all error output must be structured JSON on stdout rather than human-readable text on stderr. This allows AI agents to parse a single stream for both success responses and error data.

This task implements Phase 1 only: modifying `cli.Error()` and wiring up the Cobra error interception. All 60+ existing `cli.Error()` call sites automatically get basic structured errors with no per-command changes. Phase 2 (updating individual call sites with richer error codes) is explicitly out of scope for this task.

## Requirements

### Functional Requirements

- [ ] When `GlobalConfig.JSON == true`, `cli.Error(message)` outputs a JSON object to stdout instead of text to stderr
- [ ] The JSON error object contains fields: `"error": true`, `"code": "COMMAND_ERROR"`, `"message": "<message>"`
- [ ] A new `cli.ErrorJSON(CLIError)` function allows callers to emit errors with richer context (entity, entity_key, current_status, valid_transitions)
- [ ] When `GlobalConfig.JSON == false` (human mode), `cli.Error()` behaves identically to the current implementation (pterm or fmt.Fprintln to stderr)
- [ ] Errors returned from Cobra's `RunE` are intercepted in `main.go` and output as structured JSON when in JSON mode
- [ ] `RootCmd.SilenceErrors = true` prevents Cobra from printing duplicate error output to stderr
- [ ] `RootCmd.SilenceUsage = true` prevents Cobra from printing usage on every error
- [ ] Optional fields (`entity`, `entity_key`, `current_status`, `valid_transitions`) are omitted from JSON output when empty/nil (using `omitempty`)
- [ ] All error output in JSON mode goes to stdout, not stderr (single stream for agents)
- [ ] In human mode, error output continues to go to stderr (unchanged behavior)

### CLIError Struct

A new `CLIError` struct is defined in a new file `internal/cli/cli_error.go`:

```go
package cli

// CLIError is the structured error format emitted in JSON mode.
// The "error" field always being true allows agents to detect errors
// without relying on HTTP status codes or exit code checks.
type CLIError struct {
    Error            bool     `json:"error"`
    Code             string   `json:"code"`
    Message          string   `json:"message"`
    Entity           string   `json:"entity,omitempty"`
    EntityKey        string   `json:"entity_key,omitempty"`
    CurrentStatus    string   `json:"current_status,omitempty"`
    ValidTransitions []string `json:"valid_transitions,omitempty"`
}

// Error code constants
const (
    ErrCodeNotFound          = "NOT_FOUND"
    ErrCodeInvalidTransition = "INVALID_TRANSITION"
    ErrCodeValidationError   = "VALIDATION_ERROR"
    ErrCodeDatabaseError     = "DATABASE_ERROR"
    ErrCodeInvalidArgs       = "INVALID_ARGS"
    ErrCodeCommandError      = "COMMAND_ERROR"
)
```

- [ ] Phase 1 only -- do NOT update individual `cli.Error()` call sites

## Implementation Plan

### Step 1: Create `internal/cli/cli_error.go`

New file containing the `CLIError` struct and error code constants as specified above.

### Step 2: Modify `cli.Error()` in `internal/cli/root.go`

Replace the existing `Error()` function (approximately lines 325-330) with:

```go
// Error prints an error message. In JSON mode, outputs structured JSON to stdout.
// All errors go to stdout in JSON mode so agents parse a single stream.
func Error(message string) {
    if GlobalConfig.JSON {
        _ = OutputJSON(&CLIError{
            Error:   true,
            Code:    ErrCodeCommandError,
            Message: message,
        })
        return
    }
    if !GlobalConfig.NoColor {
        pterm.Error.Println(message)
    } else {
        fmt.Fprintln(os.Stderr, "✗", message)
    }
}
```

### Step 3: Add `ErrorJSON()` in `internal/cli/root.go`

Add alongside `Error()`:

```go
// ErrorJSON outputs a structured CLIError. Use this when richer error context
// (entity key, valid transitions) is available. Falls back to Error() in human mode.
func ErrorJSON(e CLIError) {
    e.Error = true // Ensure always set, even if caller forgot
    if GlobalConfig.JSON {
        _ = OutputJSON(&e)
        return
    }
    // Human-readable fallback
    Error(e.Message)
}
```

### Step 4: Set `SilenceErrors` and `SilenceUsage` in `init()` in `internal/cli/root.go`

In `root.go`'s `init()` function, add:
```go
RootCmd.SilenceErrors = true
// SilenceUsage prevents Cobra from printing usage on every error.
// Errors from RunE are semantic failures, not usage errors.
RootCmd.SilenceUsage = true
```

### Step 5: Handle errors from `Execute()` in `cmd/shark/main.go`

Update `main()` to handle the error returned by `cli.RootCmd.Execute()`:

```go
func main() {
    // ... existing version setup ...
    cli.SetVersion(version)

    if err := cli.RootCmd.Execute(); err != nil {
        // In JSON mode, output structured error to stdout
        if cli.GlobalConfig.JSON {
            _ = cli.OutputJSON(&cli.CLIError{
                Error:   true,
                Code:    cli.ErrCodeCommandError,
                Message: err.Error(),
            })
        } else {
            // Human mode: print to stderr (Cobra silenced its own output)
            fmt.Fprintln(os.Stderr, "Error:", err)
        }
        os.Exit(1)
    }
}
```

Ensure `fmt` and `os` are imported in `main.go`.

```go
func TestError_JSONMode(t *testing.T) {
    // Capture stdout
    old := os.Stdout
    r, w, _ := os.Pipe()
    os.Stdout = w

    GlobalConfig.JSON = true
    Error("something went wrong")

    w.Close()
    os.Stdout = old
    var buf bytes.Buffer
    buf.ReadFrom(r)

    var result CLIError
    err := json.Unmarshal(buf.Bytes(), &result)
    require.NoError(t, err)
    assert.True(t, result.Error)
    assert.Equal(t, "COMMAND_ERROR", result.Code)
    assert.Equal(t, "something went wrong", result.Message)
}
```

## Notes

- Phase 2 (updating individual `cli.Error()` call sites with richer `ErrorJSON()` calls) is explicitly out of scope. The modified `cli.Error()` handles all 60+ existing call sites automatically by emitting a generic `COMMAND_ERROR` JSON object.
- The `"error": true` field provides a reliable sentinel for agents: they can check `.error == true` regardless of which other fields are present, without relying on exit code interpretation.
- In JSON mode, ALL output goes to stdout (both success responses and error responses). This allows agents to parse a single stream. The `"error": true` field distinguishes errors from success.
- The edge case where `PersistentPreRunE` itself fails (before `GlobalConfig.JSON` is set) will output plain text. This is acceptable -- config-level failures are not expected to be parsed by agents.
- Estimated code change: ~50 lines across 3 files (plus the new `cli_error.go`).
