# Task: SHARK_OUTPUT Environment Variable

## Goal

Support `SHARK_OUTPUT=json` as a session-wide way to enable JSON output mode. AI agents can set this environment variable once in their environment rather than appending `--json` to every command invocation.

This is the smallest change in E17-F08: approximately 8 lines in a single file. It is implemented first because it enables easier testing of all subsequent F08 tasks without `--json` on every command.

## Requirements

### Functional Requirements

- [ ] `SHARK_OUTPUT=json` in the environment enables JSON output mode for all commands in that session
- [ ] When `SHARK_OUTPUT=json` is set, command output is identical to running with `--json` flag
- [ ] `--json` flag takes precedence over `SHARK_OUTPUT` (flag wins)
- [ ] `PM_JSON=true` environment variable takes precedence over `SHARK_OUTPUT` (existing Viper-based env var wins)
- [ ] `SHARK_OUTPUT=table` or any value other than `json` is silently ignored
- [ ] Empty `SHARK_OUTPUT=""` is silently ignored
- [ ] `SHARK_OUTPUT=JSON` (uppercase) is silently ignored (case-sensitive match)
- [ ] When `--json=false` is explicitly passed by the user, it overrides `SHARK_OUTPUT=json`

### Precedence Model

```
--json flag (highest)  -->  PM_JSON=true env var  -->  SHARK_OUTPUT=json  -->  default (false)
```

### Non-Functional Requirements

- [ ] Change is confined to `internal/cli/root.go`
- [ ] No behavior change for any command that does not use `SHARK_OUTPUT`
- [ ] `make fmt && make lint && make test` passes

### Implementation

**File**: `internal/cli/root.go`

Add after the Viper config update block (after `GlobalConfig.Verbose = viper.GetBool("verbose")`):

```go
// Check SHARK_OUTPUT environment variable.
// Only activates if --json flag and PM_JSON env var have not already enabled JSON mode.
// Precedence: --json flag > PM_JSON=true > SHARK_OUTPUT=json > default (false)
if !GlobalConfig.JSON {
    if sharkOutput := os.Getenv("SHARK_OUTPUT"); sharkOutput == "json" {
        GlobalConfig.JSON = true
    }
}
```

`os` is already imported in `root.go`. No additional imports needed.

### Why this ordering is correct

`initConfig()` is called in `PersistentPreRunE`, which runs after Cobra has already parsed all command-line flags. By the time this code runs:
- `GlobalConfig.JSON` already reflects the `--json` flag value (set by Cobra)
- The Viper block just above has already applied `PM_JSON=true` if set

So checking `!GlobalConfig.JSON` before applying `SHARK_OUTPUT` correctly implements the precedence model without any additional logic.

## Notes

- `SHARK_OUTPUT` is not handled by Viper because it is a string-to-boolean mapping (`"json"` value maps to a boolean flag). Viper's `AutomaticEnv()` handles the existing `PM_JSON=true` (boolean), but not `SHARK_OUTPUT=json` (string). Explicit `os.Getenv()` is the correct approach.
- Only the value `"json"` activates JSON mode. All other values (including `"JSON"`, `"table"`, empty string) are silently ignored. This design allows the variable to be extended with other values in the future without breaking existing behavior.
- Estimated code change: ~8 lines in one file.
