# Task: Implement status options subcommand

## Goal

Add the `shark status options <key>` command to `internal/cli/commands/status_group.go`. This is a read-only command that shows the current status and all valid transitions for any entity. It replaces the `--preview` pattern and helps AI agents discover valid next statuses before committing to a transition.

## Context

This task adds `statusOptionsCmd` and `runStatusOptions` to `status_group.go`. The file already has `dispatchNextStatus` (added in T-E17-F07-002) and `buildNextStatusResult` / `printEntityTransitions` are available from `epic_next_status.go` in the same package.

`runStatusOptions` is intentionally simple -- it is read-only. No flags beyond the inherited `--json`. The handler calls `dispatchNextStatus`, builds the result with `buildNextStatusResult`, and formats output. No `dispatchTransition` call is ever made.

## Requirements

### Functional Requirements

- [ ] Add `statusOptionsCmd` cobra.Command with `Use: "options <key>"`, `Args: cobra.ExactArgs(1)`, `RunE: runStatusOptions`
- [ ] Implement `runStatusOptions` handler:
  - Parse entity type and key via `ParseGetArgs(args)`
  - Call `dispatchNextStatus(ctx, entityType, key)` -- read-only, no state change
  - Build result via `buildNextStatusResult(entityType, info)` (from `epic_next_status.go`)
  - JSON output: `{"entity_type", "entity_key", "current_status", "current_phase", "is_terminal", "available_transitions"}`
  - Human output: entity header, current status + phase, transitions table, usage hints
  - If terminal: print info message "This is a terminal status -- no further transitions are available"
  - If no transitions (non-terminal): print warning "No valid transitions from 'X'"
  - Usage hints: `shark status advance <key>` and `shark status set <key> <status>`
- [ ] Add `statusCmd.AddCommand(statusOptionsCmd)` in `init()` -- no additional flags needed (read-only)
- [ ] Verify `dispatchTransition` is NEVER called in `runStatusOptions` (read-only guarantee)

### Non-Functional Requirements

- [ ] Strictly read-only: no service write calls, no state mutations
- [ ] JSON output includes `available_transitions` as an array (empty `[]` when no transitions, not `null`)
- [ ] Context timeout: 30 seconds

### Technical Approach

The handler is straightforward. The JSON output shape is:

```json
{
  "entity_type": "task",
  "entity_key": "E07-F01-001",
  "current_status": "in_development",
  "current_phase": "development",
  "is_terminal": false,
  "available_transitions": [
    {"target_status": "ready_for_code_review", "label": "..."},
    {"target_status": "blocked", "label": "..."}
  ]
}
```

Use `buildNextStatusResult(entityType, info)` to construct the `EntityNextStatusResult` struct and then serialize its `AvailableTransitions` field for the JSON output. The `result.CurrentPhase` comes from `info.CurrentPhase` via `buildNextStatusResult`.

For human output, use `fmt.Printf` for the entity/status header and call `printEntityTransitions(result.AvailableTransitions)` for the formatted transitions list.

## Notes

- `printEntityTransitions` is defined in `epic_next_status.go` in the same package. Verify the exact function signature before calling it.
- The JSON `available_transitions` field must be an empty array `[]` (not `null`) when there are no transitions. Ensure `buildNextStatusResult` returns an empty slice, not nil. If it returns nil, initialize `result.AvailableTransitions = []TransitionOption{}` before serializing.
- `current_phase` comes from the workflow config metadata. If `info.CurrentPhase` is empty, omit the phase line from human output but still include the field (as empty string) in JSON.
