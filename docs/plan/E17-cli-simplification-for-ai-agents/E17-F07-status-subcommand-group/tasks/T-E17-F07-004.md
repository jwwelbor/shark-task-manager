# Task: Implement status history subcommand

## Goal

Add the `shark status history <task-key>` command to `internal/cli/commands/status_group.go` and add `historyCmd.Hidden = true` to `internal/cli/commands/history.go`. The history subcommand shows the status change log for a task. It is task-only (feature and epic keys produce a clear error). The hidden alias on `shark history` is a one-line change tracked as part of this task.

## Context

This task completes the four subcommands in `status_group.go`. The file already has the full scaffolding from T-E17-F07-001 through T-E17-F07-003.

Note: The existing `shark history` command (`history.go`) is a project-wide history command with filter support (`--limit`, `--offset`, `--format=csv`). It is NOT equivalent to `shark status history` -- the latter is task-key-specific. Making `historyCmd.Hidden = true` only hides it from `--help` output; it remains fully functional. The feature spec states this is the intended "hidden alias" relationship.

## Requirements

### Functional Requirements

- [ ] Add `statusHistoryCmd` cobra.Command with `Use: "history <task-key>"`, `Args: cobra.ExactArgs(1)`, `RunE: runStatusHistory`
- [ ] Implement `runStatusHistory` handler:
  - Parse entity type and key via `ParseGetArgs(args)`
  - Reject non-task keys immediately (before any service call): return error "status history is only supported for tasks; got <entityType> key '<key>'"
  - Call `cli.GetTaskServiceWithHistory().GetTaskHistory(ctx, key)`
  - Handle not-found: `os.Exit(1)` with message containing the key
  - JSON output: serialize `[]*models.TaskHistory` array directly
  - Human output: table with headers "Timestamp", "Old Status", "New Status", "Agent", "Notes"
    - `nil` OldStatus -> display as "(initial)"
    - `nil` Agent -> display as ""
    - `nil` Notes -> display as ""
    - Timestamp: format as "2006-01-02 15:04:05"
  - Empty history (no records): exit 0 with info message "No history records found for task X"
  - Footer for non-empty: info message "Showing N history records for task X"
- [ ] Add `statusCmd.AddCommand(statusHistoryCmd)` in `init()` -- no additional flags needed
- [ ] In `internal/cli/commands/history.go`: add `historyCmd.Hidden = true` to the `init()` function

### Non-Functional Requirements

- [ ] The `shark history` command must remain fully functional after being hidden (hidden = not shown in --help, but still works if called directly)
- [ ] Task-only restriction must be enforced before any service call is made
- [ ] `cli.GetTaskServiceWithHistory()` (not `cli.GetTaskService()`) must be used because `GetTaskHistory` may require the history repository dependency

## Implementation Plan

### Steps

3. [ ] Add `statusCmd.AddCommand(statusHistoryCmd)` to `init()` (no new flags)
4. [ ] Open `internal/cli/commands/history.go`, find `init()`, add `historyCmd.Hidden = true`
5. [ ] Run `make fmt && make lint && make test` -- fix any failures

### Technical Approach

The non-task rejection must happen before any service call. Check `entityType != "task"` immediately after `ParseGetArgs` and return the error. Do not call `cli.GetTaskServiceWithHistory()` for non-task keys.

The table display uses `cli.OutputTable(headers, rows)`. The rows slice is built in a loop over `histories`, handling nil pointer fields with explicit nil checks.

For `history.go` modification: locate the `init()` function and add `historyCmd.Hidden = true` as the first line. This is the only change to `history.go`.

Verify `cli.GetTaskServiceWithHistory()` exists in `internal/cli/services_global.go` before using it. If it doesn't exist (unlikely per technical design), use `cli.GetTaskService()` as a fallback and document the assumption.
