# Task: Implement status set subcommand

## Goal

Create the `shark status set <key> <status>` command in `internal/cli/commands/status_group.go`. This is the first subcommand in the status group and must be idempotent: if the entity is already at the target status, return exit 0 with `"changed": false` in JSON output. Entity type (epic/feature/task) is auto-detected from the key format.

## Context

This task creates the new file `internal/cli/commands/status_group.go` and implements the first of four subcommands. The file will also include the shared scaffolding (package declaration, imports, init function, dispatch helpers, error handler) that the other three tasks (T-E17-F07-002 through T-E17-F07-004) will add to.

The technical design is fully specified in `docs/plan/E17-cli-simplification-for-ai-agents/E17-F07-status-subcommand-group/technical-design.md`. Follow it exactly.

## Requirements

### Functional Requirements

- [ ] Create `internal/cli/commands/status_group.go` with package declaration and imports
- [ ] Define `statusSetCmd` as a `*cobra.Command` with `Use: "set <key> <status>"`, `Args: cobra.ExactArgs(2)`, `RunE: runStatusSet`
- [ ] Implement `runStatusSet` handler following the three-step CLI pattern (parse, call service, format output)
- [ ] Auto-detect entity type via `ParseGetArgs(args[:1])` -- reuse from `get.go`
- [ ] Normalize target status: `strings.ToLower(strings.TrimSpace(args[1]))`
- [ ] Validate that status is not empty after trimming (return error before any service call)
- [ ] Route to correct service via `dispatchTransition(ctx, entityType, key, targetStatus, opts)`:
  - `"epic"` -> `cli.GetEpicService().TransitionStatus(...)`
  - `"feature"` -> `cli.GetFeatureService().TransitionStatus(...)`
  - `"task"` -> `cli.GetTaskService().TransitionStatus(...)`
- [ ] Implement idempotency: if `result.Transitioned == false`, return exit 0 with `"changed": false` JSON; human mode prints info message ("already in status")
- [ ] Implement `handleStatusTransitionError(err, key, entityType)` private helper that maps errors to exit codes (1 = not found, 3 = invalid transition / reason required)
- [ ] Implement `entityTransitionerFunc` adapter type (needed by T-E17-F07-002 for `performEntityTransition`)
- [ ] Register flags in `init()`: `--reason`, `--force`, `--agent`, `--notes`
- [ ] Add `statusCmd.AddCommand(statusSetCmd)` in `init()`
- [ ] Support `--json` output (inherit from root via `cli.GlobalConfig.JSON`)
- [ ] Print orchestrator action hint if `result.OrchestratorAction` is set
- [ ] Print child_count warning if `result.ChildCount > 0` in human mode
- [ ] Print `--force` bypass warning if `result.IsForced` is true in human mode

### Non-Functional Requirements

- [ ] No business logic in the command -- all transitions delegated to service layer
- [ ] No direct repository calls -- all via `cli.GetTaskService()`, `cli.GetFeatureService()`, `cli.GetEpicService()`
- [ ] Follow `os.Exit()` pattern for not-found (1) and invalid-state (3) errors, matching `epic_set_status.go`
- [ ] Context timeout: 30 seconds (matching `epic_set_status.go` pattern)

### Technical Approach

The `status_group.go` file is a new file in `package commands`. Because `statusCmd` is defined in `status.go` in the same package, it is accessible from `status_group.go` without any import or change to `status.go`.

Idempotency is implemented by checking `result.Transitioned` (Behaviour A per technical design Section 5.2). If the service returns `Transitioned: false` with no error, this is a no-op -- return success with `changed: false`. If the service returns an error containing "already", fall back to Behaviour B (treat as no-op). Verify which behaviour the existing `TaskService.executeStatusTransition()` actually uses before choosing the path.

The `dispatchTransition` and `handleStatusTransitionError` helpers are placed in this file (not a shared file) because they are used by all four subcommands in this file.
