# TechDebt Service, DTOs, and Repository Adapter

## Goal
Implement the business logic service for tech-debt entities, the input/output DTOs, and the
EntityRepository adapter that connects the tech-debt repository to the entity registry system.

## Scope
- Files to create: internal/services/tech_debt_service.go, internal/services/tech_debt_dto.go,
  internal/services/tech_debt_repo_adapter.go, internal/services/tech_debt_service_test.go

## Acceptance Criteria
Reference spec.md: "See spec.md Section 2.1 (service, dto, adapter) and Section 3.2 (Service Tests)"
- AC-T1: TechDebtService uses workflowSvc.ForLevel(workflow.LevelTechDebt) in constructor
- AC-T2: Create() validates input, generates key via repo, persists entity
- AC-T3: AdvanceStatus() delegates to workflow service for next-status resolution
- AC-T4: SetStatus() validates transition unless force=true
- AC-T5: Triage() advances to "triaged" only if current status is "identified"; otherwise updates fields only
- AC-T6: DTOs defined: CreateTechDebtInput, TechDebtUpdates (pointer fields), TechDebtFilters, TriageTechDebtInput
- AC-T7: TechDebtRepositoryAdapter implements EntityRepository interface (GetByKey + UpdateStatus)
- AC-T8: All 16 service test cases pass using mocked repositories (no real DB)
