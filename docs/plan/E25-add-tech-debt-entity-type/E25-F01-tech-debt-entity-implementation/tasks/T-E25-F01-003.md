# Workflow Configuration for Tech-Debt Lifecycle

## Goal
Register the tech-debt workflow level and define default statuses (identified, triaged, in_progress,
resolved, wont_fix, cancelled) with status metadata, flow, and transitions so the workflow system
can validate status changes for TD-### entities.

## Scope
- Files to modify: internal/workflow/levels.go, internal/config/workflow/multilevel.go,
  internal/config/workflow/defaults.go, internal/config/workflow/parser.go,
  internal/config/workflow/validator.go

## Acceptance Criteria
Reference spec.md: "See spec.md FR-03, Section 2.6 (Workflow Configuration)"
- AC-T1: LevelTechDebt = "tech_debt" constant added in levels.go
- AC-T2: TechDebt field added to MultiLevelWorkflow struct; GetWorkflowForLevel() returns it
- AC-T3: DefaultTechDebtWorkflow() defines 6 statuses with correct colors, phases, progress weights
- AC-T4: Status flow: identified->triaged->in_progress->resolved; triaged->wont_fix; triaged->cancelled; in_progress->cancelled
- AC-T5: Parser maps "tech_debt_workflow" key; validator includes tech_debt level
