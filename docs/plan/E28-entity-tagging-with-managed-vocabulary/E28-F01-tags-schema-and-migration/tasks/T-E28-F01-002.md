# Add Tag and EntityTagLink domain models and EntityTypeIdea enum

## Goal

Create `internal/models/tag.go` with `Tag` and `EntityTagLink` structs and a compiled tag-name regex validator. Extend `models.EntityType` in `internal/models/entity_type.go` by adding `EntityTypeIdea` and its `validEntityTypes` entry. These types are the compile-time contract consumed by the repository and service layers in later features.

## Scope

- Files to create: `internal/models/tag.go`, `internal/models/tag_test.go`
- Files to modify: `internal/models/entity_type.go`

## Acceptance Criteria

See architecture.md ADR-4 (tag name regex and lowercasing rule), ADR-10 (EntityTypeIdea enum addition), §1.1 (models layer).

Additional task-specific criteria:
- AC-T1: `Tag` struct exposes `ID`, `Name`, `CreatedAt`, `UpdatedAt` with JSON tags.
- AC-T2: `EntityTagLink` struct exposes `ID`, `EntityType`, `EntityID`, `TagID`, `CreatedAt`.
- AC-T3: `ValidateTagName` applies the compiled allowlist regex from ADR-4; lowercases input before validation; returns a descriptive error for non-matching input.
- AC-T4: `EntityTypeIdea` constant added; `validEntityTypes` map updated; existing entity-type tests pass unchanged.
- AC-T5: No hardcoded status values anywhere in `tag.go`.

## Test Cases

Unit tests in `tag_test.go`: valid lowercase slug passes; uppercase input passes after lowercasing; empty string fails; hyphen-leading string fails; 65-character string fails; string with spaces fails. EntityType extension verified by running existing `entity_type_test.go` without modification.

## Design Reference

See architecture.md ADR-4 for full regex and rationale, ADR-10 for EntityType extension. Input sanitization rules in `.claude/rules/go/input-sanitization.md` §Layer 1.
