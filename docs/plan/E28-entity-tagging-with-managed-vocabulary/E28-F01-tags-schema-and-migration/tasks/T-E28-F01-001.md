# Add tags and entity_tags migration to internal/db/db.go

## Goal

Introduce the `migrateAddTagsAndEntityTags` function in `internal/db/db.go`, add it to `runMigrations`, bump `CurrentSchemaVersion` from 13 to 14, and add the developer callout comment. This delivers the complete database foundation — tables, indexes, and cascade-delete triggers — that every other E28 feature depends on.

## Scope

- Files to modify: `internal/db/db.go`

## Acceptance Criteria

See architecture.md §3.1 (new tables + indexes), §3.2 (cascade-delete triggers), §3.5 (migration strategy).

Additional task-specific criteria:
- AC-T1: `tags` table, `entity_tags` table, and all three indexes created idempotently via `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`.
- AC-T2: Six `entity_tags_cascade_delete_<entity>` triggers created with `CREATE TRIGGER IF NOT EXISTS` matching the existing `entity_notes_cascade_delete_*` pattern.
- AC-T3: `CurrentSchemaVersion` incremented from 13 to 14.
- AC-T4: `migrateAddTagsAndEntityTags` registered in `runMigrations` in the correct sequential position.
- AC-T5: Developer callout comment present in the migration function documenting the `skip_migrations: false` toggle requirement.

## Test Cases

Manual verification: set `skip_migrations: false`, run any shark command, confirm `tags` and `entity_tags` tables exist via `sqlite3 shark-tasks.db .tables`. Schema version confirmed at 14 via `sqlite3 shark-tasks.db "SELECT * FROM schema_version"`. Re-running the migration on a v14 database is a no-op (idempotent check). Integration tests live in T-E28-F01-004.
