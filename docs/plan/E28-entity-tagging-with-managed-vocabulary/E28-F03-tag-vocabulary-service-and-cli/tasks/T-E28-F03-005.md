# Implement shark tags CLI (TDD: tests + impl + static import checks)

## Goal
Build the `shark tags` root command and its four subcommands (`list`, `add`,
`rm`, `rename`) using test-driven development: write the CLI tests in
`tags_test.go` from test-plan.md FIRST, confirm they fail, then implement the
thin wrappers in `tags.go` to make them pass. Each subcommand parses
args/flags, calls `cli.GetTagService()`, formats output, and maps typed errors
to exit codes. Static import checks for AC-19 and AC-20 live alongside the
CLI tests. A local `tagServiceIface` enables mock injection in tests.

## Scope
- Files to create:
  - `internal/cli/commands/tags_test.go` (write first, TDD)
  - `internal/cli/commands/tags.go` (written to pass the tests)

## Acceptance Criteria
See spec.md AC-13 through AC-20, REQ-F-009 through REQ-F-011, REQ-NF-001,
REQ-NF-003.

TDD ordering:
- AC-T0: Tests committed before implementation is merged; `go test` on
  `tags_test.go` demonstrably fails before `tags.go` is added (captured in the
  task log or the commit sequence).

Implementation criteria:
- AC-T1: `shark tags list --json` emits `[{"name":"..."}]` — no ID or timestamps.
- AC-T2: `shark tags add <name>` emits `{"name":"<name>"}` on `--json`; plain
  text `"Added tag <name>"` otherwise.
- AC-T3: `shark tags rm <name> --force` passes `force=true` to `RemoveTag`.
- AC-T4: `shark tags rename <old> <new> --json` emits `{"old":"...","new":"..."}`.
- AC-T5: Error JSON on stderr uses `{"error":"<code>","message":"<text>"}`
  format with code values from spec.md REQ-F-011.
- AC-T6: `*NotFoundError` (on rm/rename) triggers a second `ListTags` call to
  assemble the vocabulary snippet per REQ-F-008.
- AC-T7: `*UnauthorizedError` surfaces `UserHint()` on a second stderr line
  when hint is non-empty; omits the line when hint is empty.
- AC-T8: No import of `internal/repository/tag` or `database/sql` in
  `internal/cli/commands/`.
- AC-T9: Local `tagServiceIface` unexported; each subcommand built via a
  `newTagsXxxCmd(svc tagServiceIface)` helper per spec.md §2.4 and D4.
- AC-T10: Commands registered via `init()` to `cli.RootCmd`.

Test criteria:
- AC-T11: `buildTagsCmdWithMock(svc)` helper constructs a cobra root with
  injected mock — mirrors `buildSetPasswordCmdWithMock` in
  `admin_maintainer_test.go`.
- AC-T12: `mockTagService` struct uses function-field pattern; all four
  service methods covered.
- AC-T13: Table-driven test for INT-3 exercises all six error-to-exit-code
  rows with a single test function.
- AC-T14: AC-17 / INT-5 test verifies that on `*NotFoundError`, the CLI calls
  `ListTags` and puts the vocabulary snippet in stderr.
- AC-T15: Static check (AC-19): in-process `go list -f '{{.Imports}}'` run
  asserts `internal/services/` imports `internal/repository/tag` and
  `internal/auth/maintainer`, excludes `internal/cli` and `cobra`.
- AC-T16: Static check (AC-20): `go list` on `internal/cli/commands/` asserts
  `internal/repository/tag` and `database/sql` are absent.
- AC-T17: `go test ./internal/cli/commands/...` passes with no real DB.
