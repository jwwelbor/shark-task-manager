# Implement TagService core logic in tag_service.go

## Goal
Create `internal/services/tag_service.go` implementing the `TagService` struct
and its five public methods (`ValidateName`, `ListTags`, `AddTag`, `RemoveTag`,
`RenameTag`) with full gate invocation, name normalization, in-use policy, and
rename collision detection as specified.

## Scope
- Files to create:
  - `internal/services/tag_service.go`
- Files referenced (read-only, no edits):
  - `internal/repository/tag/` (F01 interfaces)
  - `internal/auth/maintainer/` (F02 Gate interface)
  - `internal/models/` (models.Tag, ValidateTagName)

## Acceptance Criteria
See spec.md AC-1 through AC-11, AC-19, AC-22.
See spec.md REQ-F-001 through REQ-F-008, REQ-NF-002, REQ-NF-003, REQ-NF-004.

Additional task-specific criteria:
- AC-T1: `NewTagService` panics on any nil dependency.
- AC-T2: All mutating methods invoke `gate.Authorize` before `ValidateName`.
- AC-T3: `RecordSuccess` errors are logged and swallowed (not returned).
- AC-T4: `RemoveTag` with `force=false` and count > 0 returns `*TagInUseError`
  without calling `Delete`.
- AC-T5: `RenameTag` does not call any `EntityTagRepository` method.
- AC-T6: Each public method emits one OTel span named `tag_service.<method>`.
- AC-T7: No span attribute contains `pass`, `password`, `hash`, or `maintainer.*`.
- AC-T8: `ValidateName` is the sole path by which raw input reaches
  `models.ValidateTagName`.
