# EntityTagRepository: FilterEntityIDs and ListTagNamesByEntities methods

## Goal
Add two new repository methods to `EntityTagRepository` that power the AND-intersection tag
query and batched tag-name lookup paths. These are pure data-access methods with no business
logic. Both follow the existing tracing/span patterns established in F01–F04.

## Scope
- Files to modify:
  - `internal/repository/tag/entity_tag_repository.go`
  - `internal/repository/tag/interfaces.go`
  - `internal/repository/tag/entity_tag_repository_test.go`
- Files to create:
  - `internal/repository/tag/errors.go` (add `ErrEmptyTagIDs` sentinel if not present)

## Acceptance Criteria
See spec.md §2.3.1 for `FilterEntityIDs` SQL shape, binding order, and N=1 optimization.
See spec.md §2.3.2 for `ListTagNamesByEntities` SQL, `EntityIDTagName` struct, and empty-input short-circuit.
See spec.md §2.3.3 for interface additions to `EntityTagRepositoryInterface`.
Additional task-specific criteria:
- AC-T1: Both methods are declared in `EntityTagRepositoryInterface` in `interfaces.go`.
- AC-T2: `FilterEntityIDs` with an empty `tagIDs` slice returns `ErrEmptyTagIDs` without a DB call.
- AC-T3: `ListTagNamesByEntities` with empty `entityIDs` returns non-nil empty slice without a DB call.
