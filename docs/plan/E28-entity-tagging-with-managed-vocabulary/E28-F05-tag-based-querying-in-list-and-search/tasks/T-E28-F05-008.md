# SearchService tag post-filter and CLI service wiring

## Goal
Update `SearchService.SearchAll` to accept a `tags []string` parameter and post-filter results
by calling `EntityIDsByTags` once per entity-type bucket in the raw search result (REQ-NF-002).
Also update `cli.GetSearchService()` and `cmd/server/services.go` to wire `TagService` as the
second argument, and update the existing call site in `search.go` to pass `searchTags`.

## Scope
- Files to modify:
  - `internal/services/search_service.go`
  - `internal/services/search_service_test.go`
  - `internal/cli/services_global.go` (GetSearchService passes GetTagService())
  - `internal/cli/commands/search.go` (pass searchTags to SearchAll; no --tag flag yet — T-009)
  - `cmd/server/services.go` (WireServices: SearchService construction passes TagService)
  - `cmd/server/services_test.go` (update if constructor call changes)

## Acceptance Criteria
See spec.md §2.6.1 for updated `SearchService` struct and `NewSearchService(repo, tagSvc)` signature.
See spec.md §2.6.2 for the five-step algorithm: bucket by type → call EntityIDsByTags per type → filter.
Additional task-specific criteria:
- AC-T1: `EntityIDsByTags` is called at most once per distinct entity type in the result set.
- AC-T2: When `tags` is nil/empty, `EntityIDsByTags` is never called; results are returned unchanged.
- AC-T3: `tagSvc==nil` and non-empty tags returns `*TagFilterUnavailableError`.
