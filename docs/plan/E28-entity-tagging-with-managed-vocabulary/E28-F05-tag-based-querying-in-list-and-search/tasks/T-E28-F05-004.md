# EntitySearchResult.ID field and search repository SQL update

## Goal
Add the `ID int64` field to `EntitySearchResult` and update all five UNION ALL branches of the
search SQL to populate it. This is a prerequisite for the search service's tag post-filter
(T-008), which needs entity IDs to perform set-membership checks against the tagged-ID set.

## Scope
- Files to modify:
  - `internal/repository/search/repository.go`
  - Any test files that compare `EntitySearchResult` by value (update struct literals to add `ID`)

## Acceptance Criteria
See spec.md §2.6.3 for the `ID int64` field declaration, `json:"id,omitempty"` tag, and the
updated SELECT column order (`entity_type, id, key, title, status, severity`) in each UNION branch.
Additional task-specific criteria:
- AC-T1: Every test that constructs an `EntitySearchResult` literal compiles and passes after adding `ID`.
- AC-T2: A real `SearchAll` query returns results where `ID` is non-zero for every row.

## Test Cases
See test-plan.md Section 1.5, `TestEntitySearchResult_IDFieldNonZero` and
`TestEntitySearchResult_IDFieldPresentInStruct`.

## Design Reference
See spec.md §2.6.3 for the five UNION branch SQL column additions.
See spec.md REQ-F-012 for the non-zero ID guarantee and `omitempty` rationale.
