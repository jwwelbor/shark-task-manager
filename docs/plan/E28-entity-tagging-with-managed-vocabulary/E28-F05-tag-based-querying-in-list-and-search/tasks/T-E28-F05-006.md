# Seven entity List service methods: tag filter integration

## Goal
Edit the seven entity List service methods to apply the tag pre-filter/post-filter pattern when
`filters.Tags` is non-empty. Uses `EntityIDsByTags` for ID resolution (Block 1) and
`filterByTagIDs` for in-memory set intersection (Block 2). Short-circuits when tagged-ID set is
empty (REQ-F-017). All seven methods follow the identical uniform pattern from spec.md §2.5.2.

## Scope
- Files to modify:
  - `internal/services/task_service.go` and `internal/services/task_service_test.go`
  - `internal/services/epic_service.go` and `internal/services/epic_service_test.go`
  - `internal/services/feature_service.go` and `internal/services/feature_service_test.go`
  - `internal/services/bug_service.go` and `internal/services/bug_service_test.go`
  - `internal/services/change_card_service.go` and `internal/services/change_card_service_test.go`
  - `internal/services/idea_service.go` and `internal/services/idea_service_test.go`

## Acceptance Criteria
See spec.md §2.5.2 for Block 1 (pre-filter) and Block 2 (post-filter) code shape.
See spec.md §2.5.1 table for which `models.EntityType` constant each service passes to `EntityIDsByTags`.
Additional task-specific criteria:
- AC-T1: Short-circuit: when `EntityIDsByTags` returns an empty slice, the base List repository is NOT called.
- AC-T2: Nil `filters.Tags` bypasses both blocks; `EntityIDsByTags` is never called.
- AC-T3: `UnregisteredTagError` from `EntityIDsByTags` propagates unchanged (no wrapping).
- AC-T4: `ChangeCardService` gains the `tagSvc TagAttacher` optional dependency if not already wired by F04.
