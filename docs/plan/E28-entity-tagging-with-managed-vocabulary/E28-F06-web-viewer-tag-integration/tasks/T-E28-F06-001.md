# Add TagReader interface and Tags method to ViewerService

## Goal
Define the `TagReader` consumer interface, add `TagsResponse`/`TagDTO` types,
add `HierarchyOptions` DTO, extend the four entity DTOs (`HierarchyEpic`,
`HierarchyFeature`, `ViewerTask`, `FlatEntity`) and `FeatureTaskOptions` with a
`Tags []string` field, add the `WithTagService` optional setter, and implement
`Tags(ctx)`. This establishes the data types and interface contracts required by
Tasks 2-6.

## Scope
- Files to modify:
  - `internal/services/viewer_service.go`
  - `internal/services/viewer_service_test.go`

## Acceptance Criteria
See spec.md REQ-F-001, REQ-F-003, REQ-F-014, REQ-F-015, REQ-NF-004,
REQ-NF-009, REQ-NF-011; ADR-F06-2, ADR-F06-3.

Additional task-specific criteria:
- AC-T1: `TagReader` defines exactly `ListTags`, `EntityIDsByTags`, and
  `AttachedTagNamesByIDs` with the signatures in spec.md §2.3.1.
- AC-T2: `Tags []string` on all four DTOs marshals as `[]` not `null`.
- AC-T3: `Tags()` with nil `tagSvc` returns `{Tags: []TagDTO{}}`, no error, no
  error-level log.
- AC-T4: OTel span `viewer_service.tags` set with `tag.count` attribute.
