# Add Tags handler route and tag error response helpers

## Goal
Implement the `ViewerHandler.Tags` method, register `GET /api/v1/viewer/tags`
in `RegisterRoutes` with `WithLocalCORS`, add `parseTagsQuery` helper, add
`tagErrorResponse` struct and `respondUnregisteredTagError` helper, and add
`TagsFunc` to `MockViewerServicer`. This task also adds the read-only security
regression tests for non-GET methods on the `/tags` route.

## Scope
- Files to modify:
  - `internal/api/viewer/handler.go`
  - `internal/api/viewer/handler_test.go`

## Acceptance Criteria
See spec.md REQ-F-002, REQ-F-013, REQ-NF-006, REQ-NF-009, REQ-NF-012;
AC-01, AC-02, AC-03; §2.3.4 (new HTTP endpoint), §2.3.6 (error shape).

Additional task-specific criteria:
- AC-T1: `GET /api/v1/viewer/tags` returns 200 with `{"tags":[...]}`.
- AC-T2: `POST /PUT /PATCH /DELETE` to `/api/v1/viewer/tags` return 404 or 405;
  `TagsFunc` call counter stays 0 for all mutation attempts.
- AC-T3: Service error produces `500` with `slog.Error` log; no panic.
- AC-T4: `parseTagsQuery` trims whitespace and drops empty-after-trim entries
  (verified in IS-3 cases).
- AC-T5: `respondUnregisteredTagError` emits `unregistered_tags` JSON array.

## UAT Rejection (2026-04-25)

**Classification:** AC Violation
**Unmet criteria:**
- AC-03 / REQ-NF-012 — "An automated test MUST assert that POST, PUT, PATCH,
  DELETE to `/api/v1/viewer/tags` and `/api/v1/viewer/tags/<name>` all produce
  404 Not Found or 405 Method Not Allowed — no write endpoint exists. This
  test is a regression tripwire for REQ-F-013."
- AC-T2 (this task) — same: "POST/PUT/PATCH/DELETE to `/api/v1/viewer/tags`
  return 404 or 405; `TagsFunc` call counter stays 0 for all mutation
  attempts."
- AC-T1 (this task) — happy-path GET test for `/api/v1/viewer/tags` is also
  missing.

**What happened:** The handler code is correct — `RegisterRoutes` only mounts
`GET /api/v1/viewer/tags` at `internal/api/viewer/handler.go:69`, so non-GET
methods naturally fall through to 404/405. The `MockViewerServicer.TagsFunc`
field was added at `internal/api/viewer/handler_test.go:40` and the `Tags`
method at `:120-125`, but **no test invokes the `/tags` route at all** —
neither the GET happy path nor the POST/PUT/PATCH/DELETE security tripwire.
Verified by grep: zero references to `/api/v1/viewer/tags`,
`UnregisteredTagError`, or `tagErrorResponse` in
`internal/api/viewer/*_test.go`.

**Fix required:**
1. Add `TestHandler_Tags_*` covering: GET happy path (200, `{"tags":[]}` and
   populated cases) and the GET 500-on-service-error path.
2. Add `TestHandler_Tags_NonGetMethods` (or equivalent) asserting that POST,
   PUT, PATCH, DELETE to `/api/v1/viewer/tags` return 404 or 405, and that
   the mock `TagsFunc` call counter remains 0.
3. Optionally add the `/api/v1/viewer/tags/<name>` non-GET coverage referenced
   in test-plan.md TC-AC03-1..5.
