# Wire tag filter params into Hierarchy and FeatureTasks handlers

## Goal
Update `ViewerHandler.Hierarchy` to parse `?tag=` query params via
`parseTagsQuery` and pass them as `HierarchyOptions{Tags: ...}` to the
service; update `ViewerHandler.FeatureTasks` to similarly parse `?tag=` into
`opts.Tags`; update both handlers to catch `*services.UnregisteredTagError`
via `errors.As` and call `respondUnregisteredTagError`. Update the mock
`HierarchyFunc` signature in handler tests and add all tag-filter handler tests.

## Scope
- Files to modify:
  - `internal/api/viewer/handler.go`
  - `internal/api/viewer/handler_test.go`

## Acceptance Criteria
See spec.md REQ-F-009, REQ-F-011, REQ-F-012, REQ-NF-005, REQ-NF-009;
AC-06 through AC-10.

Additional task-specific criteria:
- AC-T1: `?tag=voice` forwards `["voice"]` to service via `HierarchyOptions`.
- AC-T2: `?tag=&tag=voice&tag=%20%20` forwards `["voice"]` (blanks dropped,
  whitespace trimmed; normalization is service-side, NOT handler-side).
- AC-T3: Unregistered-tag error on `Hierarchy` produces 400 with
  `unregistered_tags` field; a generic error still produces 500.
- AC-T4: Feature-not-found produces 404 on `FeatureTasks`; feature-found +
  unregistered tag produces 400 (mutually exclusive, feature lookup first).
- AC-T5: `HierarchyFunc` mock signature updated to accept `HierarchyOptions`;
  all existing hierarchy tests updated to match.

response shape, or 400-vs-404 ordering on `FeatureTasks`. Verified by
