# Add tag decoration and filter to ViewerService.FeatureTasks

## Goal
Extend `ViewerService.FeatureTasks` to apply a tag pre-filter (via
`EntityIDsByTags`) before the existing status/agent/blocked filters and
pagination, so that `Total` reflects the tag-filtered count. Then decorate
the final page-scoped task slice with one `AttachedTagNamesByIDs` call. When
`tagSvc` is nil the filter is silently ignored and tasks carry `[]string{}`.

## Scope
- Files to modify:
  - `internal/services/viewer_service.go`
  - `internal/services/viewer_service_test.go`

## Acceptance Criteria
See spec.md REQ-F-005, REQ-F-008, REQ-F-015, REQ-NF-002, REQ-NF-009,
REQ-NF-011; ADR-F06-2.

Additional task-specific criteria:
- AC-T1: Tag filter runs before all existing filters and before pagination.
- AC-T2: `Total` in the response equals the post-tag-filter, pre-pagination
  count (not the raw feature-task count).
- AC-T3: `AttachedTagNamesByIDs` is called with only the IDs on the returned
  page, not the full pre-pagination ID list.
- AC-T4: Empty page after tag filter results in `Total == 0`, `Tasks == []`,
  and zero `AttachedTagNamesByIDs` calls.
- AC-T5: Nil `tagSvc` + non-empty `opts.Tags` produces no error and every task
  has `Tags == []string{}`.
