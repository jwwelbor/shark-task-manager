# Add tag decoration and filter to ViewerService.Hierarchy

## Goal
Extend `ViewerService.Hierarchy` to accept a `HierarchyOptions` parameter,
batch-fetch tag names for all entity types present in the tree (at most 6
`AttachedTagNamesByIDs` calls), populate the `Tags` field on every DTO, and
prune the response tree when `opts.Tags` is non-empty. When `tagSvc` is nil all
DTOs carry `[]string{}` and the filter is silently ignored.

## Scope
- Files to modify:
  - `internal/services/viewer_service.go`
  - `internal/services/viewer_service_test.go`

## Acceptance Criteria
See spec.md REQ-F-003, REQ-F-004, REQ-F-010, REQ-F-015, REQ-NF-001,
REQ-NF-009, REQ-NF-011; ADR-F06-1, ADR-F06-2, ADR-F06-4.

Additional task-specific criteria:
- AC-T1: Signature changes from `Hierarchy(ctx)` to `Hierarchy(ctx, HierarchyOptions)`.
- AC-T2: `AttachedTagNamesByIDs` called at most 6 times regardless of tree size.
- AC-T3: Pruning: epic with zero matching descendants and no direct tag is absent
  from the response; flat entity types are independently filtered.
- AC-T4: `*UnregisteredTagError` from `EntityIDsByTags` propagates unchanged.
- AC-T5: Nil `tagSvc` + non-empty `opts.Tags` produces no error or panic.
