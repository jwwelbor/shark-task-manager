# Maintainer Bootstrap Service

## Goal
Implement `internal/services/maintainer_bootstrap_service.go` — the thin service that
orchestrates "read config → compute SHA-256 hex digest → write `password_hash` back to
config." Keeps the CLI command a thin wrapper per the service-layer pattern. Includes
unit tests with mocked config reader/writer.

## Scope
- Files to create:
  - `internal/services/maintainer_bootstrap_service.go`
  - `internal/services/maintainer_bootstrap_service_test.go`

## Acceptance Criteria
See spec.md AC-11 (service half: written hash equals sha256hex of provided password;
all other config keys preserved).
See spec.md REQ-F-008.
- AC-T1: Service interface accepts a config reader/writer pair (interfaces, not concrete
  types) so tests can mock I/O without touching the filesystem.
- AC-T2: `SetPassword(ctx, plaintextPassword) error` computes SHA-256 hex digest and
  writes only the `password_hash` field; other existing config keys are preserved
  verbatim.
- AC-T3: If no config exists (reader returns "not found"), service creates a minimal
  config containing only `{maintainer: {password_hash: "<digest>"}}`.
- AC-T4: Plaintext password is not written to any field; only the digest is stored.
- AC-T5: Service returns a non-nil error on config write failure; error is wrapped
  with context per error-handling patterns.

## Test Cases
See test-plan.md Section 1 AC-11 note: service test asserts written hash equals
sha256hex("hunter2") and that all other JSON keys survive the round-trip.
See test-plan.md Section 3 INT-3 (end-to-end via CLI test in T-E28-F02-005).
