# CLI Command and Accessor Integration

## Goal
Wire all F02 pieces into the CLI: the `shark admin maintainer set-password` command
(thin wrapper over bootstrap service), the `GetMaintainerGate()` lazy accessor in
`internal/cli`, registration under `adminCmd`, and updates to CLI reference docs.
Delivers the full end-to-end bootstrap and gate-usage flow.

## Scope
- Files to create:
  - `internal/cli/commands/admin_maintainer.go`
  - `internal/cli/commands/admin_maintainer_test.go`
  - `internal/cli/maintainer_global.go`
  - `internal/cli/maintainer_global_test.go`
- Files to modify:
  - `internal/cli/commands/admin.go` — register `adminMaintainerCmd` under `adminCmd`
  - `docs/cli-reference/setup-commands.md` — add set-password section
  - `docs/cli-reference/configuration.md` — add maintainer object section

## Acceptance Criteria
See spec.md AC-11, AC-12, AC-13.
See spec.md REQ-F-008, REQ-F-009, REQ-F-010.
- AC-T1: `set-password` accepts `--password <value>` flag; also accepts `--password-stdin`
  for piped input. Interactive stdin prompt (echo-disabled) used when neither flag is set
  and stdin is a terminal.
- AC-T2: Command prints nothing resembling the plaintext or hash to stdout/stderr on
  success (AC-12 verified by captured output test).
- AC-T3: `GetMaintainerGate()` follows lazy-init pattern; panics on project-root or
  config-load failure; returns new instance per call; does not panic when
  `cfg.Maintainer` is nil (returns gate that always fails).
- AC-T4: `adminMaintainerCmd` is registered as child of `adminCmd` in `init()` in
  `admin_maintainer.go` (not in `admin.go`).
- AC-T5: CLI test for `set-password` mocks the bootstrap service interface; verifies
  correct password is passed and no secret appears in any output stream.
- AC-T6: Integration test for `GetMaintainerGate()` uses `t.TempDir()` project root
  with a written `.sharkconfig.json`; verifies end-to-end Authorize works.
