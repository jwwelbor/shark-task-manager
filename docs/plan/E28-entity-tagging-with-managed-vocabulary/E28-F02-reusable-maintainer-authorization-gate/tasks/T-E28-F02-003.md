# Config MaintainerConfig Wiring

## Goal
Add the `MaintainerConfig` struct to `internal/config` and wire it into `Config` as an
optional `maintainer` JSON object. A nil or absent `Maintainer` field must be
equivalent to "no password configured." Includes config round-trip tests to confirm
that adding the new field does not break existing config serialization.

## Scope
- Files to create:
  - `internal/config/maintainer.go`
  - `internal/config/maintainer_test.go`
- Files to modify:
  - `internal/config/config.go` — add `Maintainer *MaintainerConfig` field
  - `internal/config/config_test.go` — extend with round-trip test

## Acceptance Criteria
See spec.md AC-3, AC-7 (config nil → gate behavior), AC-11 (hash preserved on write).
See spec.md REQ-F-007.
- AC-T1: `MaintainerConfig` has `PasswordHash string` (json:"password_hash,omitempty")
  and `CacheWindowSeconds int` (json:"cache_window_seconds,omitempty").
- AC-T2: `CacheWindow()` method returns `60 * time.Second` when `CacheWindowSeconds`
  is 0 or when receiver is nil.
- AC-T3: `Config.Maintainer` field uses json tag `"maintainer,omitempty"`.
- AC-T4: JSON round-trip of a `Config` with populated `Maintainer` preserves all
  fields — other top-level keys (database, workflow_config) are unchanged.
- AC-T5: JSON round-trip of a `Config` without `Maintainer` does not add a
  `"maintainer"` key to the output (omitempty behavior verified).
