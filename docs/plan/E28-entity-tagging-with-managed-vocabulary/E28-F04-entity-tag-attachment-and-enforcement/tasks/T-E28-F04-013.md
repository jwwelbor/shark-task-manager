# Task: Render SC-2 vocabulary snippet on entity create/update --tag path

## Goal

Close the REQ-F-015 / SC-2 gap surfaced during T-E28-F04-012 UAT: when a user
supplies an unregistered tag via `--tag` on any entity `create` or `update`,
render the full SC-2 error shape (vocabulary snippet + exact remediation line)
that is already produced on the `shark <entity> tag add|rm` path. Currently
the `--tag` path returns a bare `Error: ...` line through `handleServiceError`
and exits 1, contradicting both the spec and the `tags.md` documentation that
had to be amended in T-012 to disclose the divergence as a tracked limitation.

## Context

- REQ-F-015 (spec.md:66) requires both attach-path surfaces (`--tag` and
  `<entity> tag add`) to produce the SC-2 shape.
- The shared helper `handleVocabularyErrorWithSnippet` already exists in
  `internal/cli/commands/tags_shared.go:39` and is correct; it is simply not
  wired into the six entity `runXCreate`/`runXUpdate` runners.
- `TagRequiredError` currently surfaces through the same bare path; the
  remediation should point the user at `shark tags add <name>` (or the
  `tag_required_for` config if no vocabulary names are registered yet).
- `cmd/shark/main.go:58` collapses all `RunE` errors to `os.Exit(1)`, which
  also defeats REQ-F-016's exit-code mapping (exit 3 for
  `unregistered_tag` / `tag_required`). This task fixes both in one pass
  because the typed-error routing and the exit-code plumbing share the same
  call sites.

## Requirements

### Functional Requirements

- FR-1: On `shark <entity> create --tag=<unregistered>` and
  `shark <entity> update --tag=<unregistered>` for all six entity families
  (task, feature, epic, bug, change, idea), stderr MUST contain:
    1. A single-line error message describing the failure.
    2. `Available tags:` followed by the first 10 registered tag names,
       two-space-indented and comma-separated.
    3. `…and N more` line when the vocabulary exceeds 10 tags.
    4. Exact remediation line as the LAST stderr line:
       `To add it: shark tags add <name>` — matching the exact-suffix
       assertion pattern from T-E28-F04-004 AC-T2.
- FR-2: On `shark <entity> create` without `--tag` where `tag_required_for`
  lists the entity type, stderr MUST contain the single-line
  `at least one tag is required for <entity>` message AND the `Available
  tags:` snippet when the vocabulary is non-empty. No remediation line is
  required for `TagRequiredError` because no single tag name is rejected
  (a different follow-up may add a hint; out of scope here).
- FR-3: Process exit status for `*UnregisteredTagError` and
  `*TagRequiredError` MUST be `3` (not `1`). All other service errors
  continue to exit per the existing `handleServiceError` mapping (1 for
  not-found, 2 for DB/system, 3 for validation/conflict).
- FR-4: `--json` mode MUST suppress the vocabulary snippet and remediation
  line (matching the Path A behavior in `handleVocabularyErrorWithSnippet`).
  The JSON envelope MUST carry the inner `code:"unregistered_tag"` or
  `code:"tag_required"` as well as the outer `COMMAND_ERROR` envelope.
- FR-5: Docs updated: `docs/cli-reference/tags.md` must fold Path A and
  Path B into a single rendering description; the REQ-F-015 limitation
  callout at `tags.md:510` must be removed.

### Non-Functional Requirements

- NFR-1: No new service-layer methods; reuse `handleVocabularyErrorWithSnippet`
  and `tagsErrorCode`.
- NFR-2: No regressions in existing T-005..T-012 tests.
- NFR-3: Quality gate clean: `make fmt && make lint && make test`.

## Implementation Plan

### Steps

1. **Route typed tag errors before `handleServiceError`.** Introduce a
   helper `handleEntityServiceError(cmd, tagSvc, err, entityType, key)` in
   `internal/cli/commands/helpers.go` (or a new sibling file) that:
    - Checks `errors.As(err, &*UnregisteredTagError)` and
      `errors.As(err, &*TagRequiredError)`. For a match, delegate to
      `handleVocabularyErrorWithSnippet(cmd, tagSvc, name, err)` — for
      `TagRequiredError` pass an empty `name` (the helper already tolerates
      this; confirm and adjust if needed).
    - Otherwise, fall through to the existing `handleServiceError`
      string-match logic.
    - Returns `error` instead of calling `os.Exit` so the cobra `RunE`
      chain can propagate the exit code.
2. **Fix exit-code propagation in `cmd/shark/main.go:58`.** Unwrap the
   `"exit code N:"` prefix produced by `handleVocabularyErrorWithSnippet`
   (and by the new helper for non-tag errors) to honor the embedded exit
   code; fall back to `1` when no code is encoded. This is the smallest
   change that honors REQ-F-016 without requiring every handler to stop
   calling `os.Exit` today.
3. **Wire the new helper into 12 call sites** across bug / task / feature /
   epic / change / idea runners — both `runXCreate` and `runXUpdate`. Each
   site becomes:

    ```go
    svc := cli.GetTaskService()
    result, err := svc.CreateTask(ctx, input)
    if err != nil {
        return handleEntityServiceError(cmd, cli.GetTagService(), err, "task", input.Title)
    }
    ```

4. **Add tests.** One table-driven test per layer:
    - `internal/cli/commands/entity_tag_error_path_test.go`:
      `TestEntityCreateUpdate_UnregisteredTag_RendersSnippet` — 24 subtests
      (6 entities × 2 verbs × 2 error types) using the shared
      `MockTagService` returning the typed errors. Assert:
        - stderr contains `Available tags:` when vocabulary non-empty
        - stderr has exact suffix `To add it: shark tags add <name>\n`
          for `UnregisteredTagError`
        - stderr contains `at least one tag is required for <entity>`
          for `TagRequiredError`
        - RunE returns an error that produces exit code 3
        - `--json` suppresses the snippet and emits the inner typed code
    - `cmd/shark/main_test.go` (new, small) — assert the exit-code unwrap
      translates `"exit code 3: ..."` to process exit 3.
5. **Update `docs/cli-reference/tags.md`** — collapse Path A/B sections,
   remove the tracked-limitation callout, update examples to show the
   unified rendering.
6. **Quality gate.** Run `make fmt && make lint && make test`.

### Technical Approach

- Consumer-side interface for `tagSvc` in the new helper: reuse the
  `tagServiceIface` already used by `handleVocabularyErrorWithSnippet` so
  the helper works for any entity service and remains easy to mock.
- Keep `handleServiceError` behavior unchanged for non-tag errors to avoid
  touching unrelated call sites. The new helper is a thin wrapper.
- No service-layer changes. All plumbing is CLI-layer + `main.go` exit
  handling.
