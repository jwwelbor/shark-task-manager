# Add UnregisteredTagError and TagRequiredError typed errors

## Goal
Append two new typed errors to the existing `tag_errors.go` pattern so the
service layer in T-003 and the CLI mappings in T-004/T-005+ can distinguish the
"tag not in vocabulary on attach" and "tag required by policy" cases from F03's
`NotFoundError` and `ValidationError`. Pure type addition.

## Scope
- Files to modify: `internal/services/tag_errors.go`
- Files to create: `internal/services/tag_errors_test.go` (if no per-error
  test file exists yet; otherwise append to the existing file)

## Acceptance Criteria
Reference spec.md AC-28, AC-28b.
Additional task-specific criteria:
- AC-T1: Both types are structs with the exact exported field names listed
  in spec.md Section 2.4 (`Name string`, `EntityType string`).
- AC-T2: Both `Error()` methods produce the literal formats specified in
  Section 2.4, verified by string-equality tests.

## Test Cases
See test-plan.md Section 1.1, AC-28 and AC-28b rows.

## Design Reference
See spec.md Section 2.4 for struct layouts, field names, and Error() format
strings. See Section 2.10 ADR-F04-3 for the rationale for keeping
`UnregisteredTagError` distinct from F03's `NotFoundError`.
