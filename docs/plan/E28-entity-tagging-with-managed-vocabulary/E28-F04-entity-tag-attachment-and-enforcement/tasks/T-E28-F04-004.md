# Update CLI TagService wiring and refactor vocabulary error helper

## Goal
Pass `cli.GetConfig()` as the new fourth argument to `services.NewTagService`
in `cli.GetTagService()`, extend `tagsErrorCode` with branches for
`UnregisteredTagError` and `TagRequiredError`, and rename/export
`handleTagsRmRenameError` into a reusable helper so T-005 (bug) and beyond can
render the SC-2 vocabulary-snippet stderr for attach errors.

## Scope
- Files to modify: `internal/cli/tag_global.go`, `internal/cli/commands/tags.go`,
  `internal/cli/commands/tags_test.go`
- Files to create: `internal/cli/commands/tags_shared.go` (optional — may be
  added instead of an in-place rename; either location is acceptable)

## Acceptance Criteria
Reference spec.md Section 2.7 error-code table and Section 2.8 wiring.
Additional task-specific criteria:
- AC-T1: `tagsErrorCode` returns `("unregistered_tag", 3)` for
  `*services.UnregisteredTagError` and `("tag_required", 3)` for
  `*services.TagRequiredError`.
- AC-T2: `handleVocabularyErrorWithSnippet` (or the existing
  `handleTagsRmRenameError`) recognises `*UnregisteredTagError` and produces
  stderr ending in the exact substring `To add it: shark tags add <name>`.
- AC-T3: Existing F03 `tags_test.go` cases still pass unchanged.
