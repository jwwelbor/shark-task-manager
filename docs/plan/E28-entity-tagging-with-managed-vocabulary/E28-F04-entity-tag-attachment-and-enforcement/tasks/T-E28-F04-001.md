# Add Config.TagRequiredFor field with JSON round-trip

## Goal
Add the `TagRequiredFor` configuration field to `*config.Config` with an exported
method satisfying the forthcoming `services.TagEnforcementConfig` interface. The
field is read-only from the service layer's perspective and powers the
`EnforceRequired` policy introduced in T-003. No other behavior changes.

## Scope
- Files to modify: `internal/config/config.go`, `internal/config/config_test.go`
- Files to create: none

## Acceptance Criteria
Reference spec.md AC-27, AC-27b, AC-27c, AC-27d.
Additional task-specific criteria:
- AC-T1: `cfg.TagRequiredFor()` on a nil receiver returns nil without panic.
- AC-T2: The JSON field name is exactly `tag_required_for` with `omitempty`.
- AC-T3: The method returns a defensive copy (mutations by callers do not
  affect subsequent calls).

## Test Cases
See test-plan.md Section 1.4, cases AC-27, AC-27b, AC-27c, AC-27d.

## Design Reference
See spec.md Section 2.3 for field naming, JSON tag, and defensive-copy rationale
(including the `TagRequiredForTypes` backing-field naming decision).
