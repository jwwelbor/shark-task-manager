# Update CLI reference docs

## Goal
Document the three new user-facing surfaces introduced by F04: the `--tag`
repeated flag on every entity create/update command, the per-entity
`shark <entity> tag add|rm` subcommand, and the new `tag_required_for`
configuration field. This is pure documentation; no code, no tests.

## Scope
- Files to modify: `docs/cli-reference/tags.md`,
  `docs/cli-reference/configuration.md`,
  `docs/cli-reference/task-commands.md`,
  `docs/cli-reference/feature-commands.md`,
  `docs/cli-reference/epic-commands.md`,
  `docs/cli-reference/bug-commands.md`,
  `docs/cli-reference/change-commands.md`,
  `docs/cli-reference/README.md`
- Files to create: none

## Acceptance Criteria
Reference spec.md Section 2.11 (documentation changes).
Additional task-specific criteria:
- AC-T1: `tags.md` gains "Applying tags during create/update" and
  "Retroactive tagging: `shark <entity> tag add|rm`" sections with worked
  examples drawn from AC-19, AC-20, AC-21, AC-23, AC-24, AC-25.
- AC-T2: `configuration.md` documents `tag_required_for`, lists the six
  allowed lowercase values, and includes a worked example matching UAT-6.
- AC-T3: Each per-entity command reference page describes the new `--tag`
  flag and the `tag add|rm` subcommand.
- AC-T4: `README.md` gains a one-line mention under **Advanced** or
  **Vocabulary** about retroactive tagging.

## Test Cases
No automated tests — documentation review only. The user-facing examples
must match the AC numbering in test-plan.md Section 1.3 so future
readers can trace doc snippets back to acceptance criteria.

## Design Reference
See spec.md Section 2.11 (Documentation Changes) for the per-file
breakdown and Section 2.10 ADR-F04-4 for the six allowed
`tag_required_for` values to enumerate in `configuration.md`.
