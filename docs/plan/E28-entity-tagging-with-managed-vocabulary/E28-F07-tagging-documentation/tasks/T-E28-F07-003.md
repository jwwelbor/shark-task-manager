# Add v13->v14 migration callout to initialization.md and configuration.md

## Goal
Document the schema bump from v13 to v14 introduced by E28 (tags + entity_tags tables) so existing users running with `skip_migrations: true` know they must temporarily flip the flag. Closes the assessment gap "initialization.md / configuration.md v13→v14 migration callout (skip_migrations: false toggle)".

## Scope
- Files to modify:
  - `docs/cli-reference/initialization.md` (add a "Migrating an existing project to v14 (E28 tagging)" section explaining the one-time `skip_migrations: false` toggle for users on Turso/cloud)
  - `docs/cli-reference/configuration.md` (extend the `database.skip_migrations` section, or add a brief note where the flag is described, with a pointer to the initialization.md section)

## Acceptance Criteria
- `initialization.md` has a clearly titled section explaining: the schema version moved 13 -> 14, the new tables are `tags` and `entity_tags`, and how to apply the migration when `skip_migrations: true` is set (set to `false`, run any shark command once, set back to `true`).
- The callout names the affected backend explicitly (Turso / `skip_migrations: true` users); local SQLite always runs migrations.
- `configuration.md` mentions the v14 migration where `skip_migrations` is documented and links back to the initialization.md section.
- Both pages cross-link via Markdown anchors (no relative-path typos).

## Test Cases
1. `grep -n "v14\|version 14\|13 -> 14\|13 → 14" docs/cli-reference/initialization.md docs/cli-reference/configuration.md` returns matches in both files.
2. `grep -n "skip_migrations" docs/cli-reference/configuration.md` shows the callout near the flag description.
3. Manual: navigate the link from `configuration.md` to the initialization.md section and confirm it resolves.
