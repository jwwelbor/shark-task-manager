# Cross-reference and consistency pass across all tagging docs

## Goal
After all tagging content has landed (T-001 through T-005), do a single editorial pass that verifies wording, terminology, link integrity, and example consistency across every doc page that mentions tags. Closes the assessment gap "Cross-reference / consistency pass across all touched pages" and the README/Vocabulary verification item.

## Scope
- Files to modify (likely small edits only):
  - `docs/cli-reference/README.md`
  - `docs/cli-reference/tags.md`
  - `docs/cli-reference/configuration.md`
  - `docs/cli-reference/initialization.md`
  - `docs/cli-reference/core-commands.md`
  - `docs/cli-reference/discovery-commands.md`
  - `docs/cli-reference/idea-commands.md`
  - `docs/cli-reference/task-commands.md`
  - `docs/cli-reference/feature-commands.md`
  - `docs/cli-reference/epic-commands.md`
  - `docs/cli-reference/bug-commands.md`
  - `docs/cli-reference/change-commands.md`

## Acceptance Criteria
- Terminology is uniform across pages: "registered tag", "vocabulary", "AND semantics", "retroactive tagging", "maintainer authorization" — all spelled and capitalized consistently.
- Every mention of a sister page uses a working relative link (no broken anchors). Verify by running a Markdown link checker or by `grep` + manual click.
- README.md "Command Groups -> Vocabulary" section lists `tags add/rm/rename/list` and at least one entity-level example, and links to `tags.md`.
- Each per-entity command page (task/feature/epic/bug/change/idea) has `--tag` documented on `create` and `update`, and a `tag add`/`tag rm` subsection — wording matches the template in tags.md.
- The unregistered-tag error remediation snippet (the "To add it: shark tags add <name>" line) is described identically wherever it appears.
- No page contradicts another on multi-tag semantics, slug rules, or `tag_required_for` behavior.

## Test Cases
1. `grep -rn "registered tag\|Registered tag" docs/cli-reference/` returns the same canonical phrasing on each page.
2. Manual link check: for each page in scope, every `](filename.md#anchor)` link resolves to an existing heading.
3. `grep -rn "shark tags add" docs/cli-reference/` shows the same remediation example on every page that documents the unregistered-tag error.
4. Sanity diff: render `tags.md` -> `README.md` -> per-entity pages and confirm a reader following the cross-references can answer "how do I tag a task?" end-to-end without contradictions.
