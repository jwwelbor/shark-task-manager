# Verify completeness of tags.md against E28 ACs and assessment note

## Goal
`docs/cli-reference/tags.md` is already drafted at ~734 lines but the assessment explicitly calls for a completeness verification pass. Walk every E28 acceptance criterion (AC-1 through AC-26 and SC-1 through SC-10) and confirm the canonical tags page covers it; fill remaining gaps. Closes the assessment gap "tags.md is already ~734 lines; verify completeness".

## Scope
- Files to modify:
  - `docs/cli-reference/tags.md` (additions only — do not restructure existing sections unless an AC is missing)

## Acceptance Criteria
- Every AC and SC referenced by E28-F01 through E28-F06 is either explicitly documented in `tags.md` or has a clear cross-reference to the page that documents it (configuration.md, viewer doc, per-entity command pages).
- The following are present and accurate: vocabulary semantics (closed list, lowercase ASCII slug rules), `shark tags add/rm/rename/list`, retroactive `<entity> tag add/rm`, applying tags during `create`/`update`, AND-semantic multi-tag filtering, unregistered tag error envelope, `tag_required_for` summary with a link out to configuration.md, viewer chip + filter behavior summary with a link to the viewer doc.
- A short "Coverage matrix" subsection at the end of tags.md maps each E28 AC/SC to the section that satisfies it (table form). This is the artifact the QA pass will check against.
- Total page length stays manageable (target < 900 lines after additions; if > 900, split into a subpage and link).

## Test Cases
1. `wc -l docs/cli-reference/tags.md` returns the new line count; record before/after in the PR description.
2. `grep -n "AC-\|SC-" docs/cli-reference/tags.md` shows the coverage matrix entries.
3. Manual cross-check: pick three random ACs from E28 features and confirm each appears in the coverage matrix and links to the doc that explains it.
