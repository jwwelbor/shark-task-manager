# Verify and complete maintainer + tag_required_for sections in configuration.md

## Goal
Audit the existing `maintainer` block and `tag_required_for` sections in `docs/cli-reference/configuration.md`, fill any gaps the assessment flagged, and confirm both are deep enough to fully describe E28 behavior. Closes the assessment gap "configuration.md documentation of tag_required_for and maintainer block depth/completeness".

## Scope
- Files to modify:
  - `docs/cli-reference/configuration.md` (extend the `maintainer` and `tag_required_for` sections; do not duplicate content already in `tags.md` — link to it instead)

## Acceptance Criteria
- The `maintainer` section documents every field shipped in E28-F02 (`password_hash`, any salt/algorithm note, behavior when absent vs configured) and the related CLI commands (`shark admin maintainer set-password`, any verify/clear commands that exist).
- The behavior of `gate.Authorize` and the `*UnauthorizedError` exit path is described once, with a link from configuration.md to tags.md (or vice versa) so the same fact is not maintained in two places.
- `tag_required_for` documents: (a) supported entity-type values, (b) creation-time vs update-time behavior, (c) exit code and message format, (d) how it interacts with `--tag` on the `create` commands.
- Both sections include at least one realistic JSON snippet and one CLI example each.
- No content drifts from what the F02/F03/F04 implementations actually do (verify by reading the relevant service code).

## Test Cases
1. Manual read: every `maintainer.*` field used by `internal/auth/maintainer` is documented.
2. `grep -n "tag_required_for" docs/cli-reference/configuration.md` shows a section with at least 4 distinct paragraphs/bullets.
3. Cross-reference links to `tags.md` resolve (no broken anchors).
4. JSON examples are syntactically valid (run through `jq`).
