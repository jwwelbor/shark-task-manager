# Task: EpicService backward transition support

## Goal

Extend `EpicService.TransitionStatus()` to detect backward transitions, enforce reason requirements, create rejection notes, and count child features. Update constructor and service accessors.

## Requirements

### Functional Requirements

- [ ] Change `TransitionStatus()` signature to accept `TransitionOptions` instead of `bool force`
- [ ] Detect backward transitions using `workflowSvc.IsBackwardTransition()`
- [ ] Enforce `--reason` for backward transitions when `RequireRejectionReason` is true
- [ ] Create rejection note via `EntityNoteRepository.CreateRejectionNote()` for backward + reason
- [ ] Count child features and populate `ChildCount` on `TransitionResult`
- [ ] Set `IsBackward` and `Reason` on `TransitionResult`
- [ ] Force bypasses workflow validation but still requires reason
- [ ] Force without reason returns clear error: "--force requires --reason"
- [ ] Graceful degradation when noteRepo or featureRepo is nil

### Non-Functional Requirements

- [ ] No new database tables or migrations
- [ ] All existing callers updated for new signature

## Implementation Plan

### Steps

1. [ ] Define `EpicNoteRepository` interface in `epic_service.go`
2. [ ] Define `EpicFeatureCounter` interface in `epic_service.go`
3. [ ] Add `noteRepo` and `featureRepo` fields to `EpicService` struct
4. [ ] Update `NewEpicService()` constructor signature
5. [ ] Change `TransitionStatus()` to accept `TransitionOptions`
6. [ ] Add backward detection logic after existing validation
7. [ ] Add rejection note creation after status update
8. [ ] Add child feature counting
9. [ ] Update `internal/cli/service_accessors.go` `GetEpicService()` to pass new deps
10. [ ] Update all callers of `TransitionStatus()` to use `TransitionOptions{Force: force}`
11. [ ] Update existing tests

### Technical Approach

**New interfaces** in `internal/services/epic_service.go`:
```go
type EpicNoteRepository interface {
    CreateRejectionNote(ctx context.Context, entityType models.EntityType, entityID int64,
        historyID int64, fromStatus, toStatus, reason, rejectedBy, documentPath string) error
}

type EpicFeatureCounter interface {
    ListByEpic(ctx context.Context, epicID int64) ([]*models.Feature, error)
}
```

**Key logic addition** (between validation and update):
1. If force && reason == "": return error "--force requires --reason"
2. `isBackward, _ := s.workflowSvc.IsBackwardTransition(currentStatus, targetStatus)`
3. If backward && !force: check `RequireRejectionReason` config, require reason
4. After update: if (backward || force) && reason != "" && noteRepo != nil: create rejection note
5. Count features: if featureRepo != nil: `len(featureRepo.ListByEpic(ctx, epicID))`

**Callers to update**:
- `internal/cli/commands/epic_next_status.go` - change `force` to `TransitionOptions{Force: force}`
- `internal/services/epic_service_test.go` - update all test calls
