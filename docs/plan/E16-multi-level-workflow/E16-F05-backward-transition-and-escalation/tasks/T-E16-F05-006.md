# Task: Epic set-status CLI command

## Goal

Create `shark epic set-status <key> <status>` command that allows setting any valid epic status with workflow validation and backward transition guards.

## Requirements

### Functional Requirements

- [ ] New file: `internal/cli/commands/epic_set_status.go`
- [ ] Command: `shark epic set-status <epic-key> <status>`
- [ ] Flags: `--reason`, `--force`, `--agent`
- [ ] Parse key and status from positional args
- [ ] Call `epicSvc.TransitionStatus()` with `TransitionOptions`
- [ ] Display success message with from/to status
- [ ] Display reason when backward transition
- [ ] Display child count warning when features exist
- [ ] JSON output support via `cli.GlobalConfig.JSON`
- [ ] Error handling: not found (exit 1), invalid state (exit 3)

### Non-Functional Requirements

- [ ] Thin wrapper pattern: parse args, call service, format output
- [ ] No business logic in command handler
- [ ] Case insensitive key handling

## Implementation Plan

### Steps

1. [ ] Create `internal/cli/commands/epic_set_status.go`
2. [ ] Define `epicSetStatusCmd` cobra command with `Use`, `Short`, `Long`, `Args`, `RunE`
3. [ ] Register flags in `init()`: `--reason`, `--force`, `--agent`
4. [ ] Register as subcommand of `epicCmd`
5. [ ] Implement `runEpicSetStatus()`:
   - Parse args[0] as epic key, args[1] as target status
   - Build `TransitionOptions` from flags
   - Call `cli.GetEpicService().TransitionStatus()`
   - Handle errors with appropriate exit codes
   - Format output (JSON or human-readable)
6. [ ] Create `internal/cli/commands/epic_set_status_test.go`

### Technical Approach

See architecture Section 3.1 for full command implementation. The command follows the same pattern as existing `shark task set-status` but uses the service layer (not legacy repo access).

**Error handling**:
- "requires --reason" -> `cli.Error()` + exit 3
- "not found" -> `cli.Error()` + exit 1
- Other errors -> return wrapped error

**Output format**:
```
Human: Epic E16: draft -> active
Human (backward): Epic E16: active -> draft
  Reason: Requirements changed
  Warning: 5 features remain in current states.
JSON: Full TransitionResult object
```

## Acceptance Criteria

- [ ] `shark epic set-status E16 active` performs forward transition
- [ ] `shark epic set-status E16 draft --reason "text"` performs backward transition
- [ ] `shark epic set-status E16 draft` without reason returns error for backward
- [ ] `shark epic set-status E16 draft --force --reason "text"` bypasses validation with reason
- [ ] `shark epic set-status E16 draft --force` without reason returns error
- [ ] `shark epic set-status E16 active --json` returns JSON TransitionResult
- [ ] `shark epic set-status INVALID active` returns "not found" exit 1
- [ ] Child count warning shown when features exist
- [ ] `make fmt && make lint && make test` passes

## Testing Strategy

- [ ] Test valid forward transition - success output
- [ ] Test backward with --reason - success + reason display
- [ ] Test backward without --reason - error message
- [ ] Test --force with --reason succeeds
- [ ] Test --force without --reason returns error
- [ ] Test JSON output format
- [ ] Test not found error
- [ ] Test invalid transition error
- Tests use mocked services
