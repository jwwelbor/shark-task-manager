# Task: TransitionOptions and Extended TransitionResult types

## Goal

Add the `TransitionOptions` struct and extend `TransitionResult` with backward transition fields in `internal/services/transition_types.go`. This is a pure type-addition task with no behavior changes.

## Requirements

### Functional Requirements

- [ ] Add `TransitionOptions` struct with `Force`, `Reason`, `DocumentPath`, `Agent` fields
- [ ] Add `IsBackward`, `IsForced`, `Reason`, `ChildCount` fields to existing `TransitionResult`
- [ ] All new fields use `omitempty` JSON tags for backward-compatible serialization

### Non-Functional Requirements

- [ ] No behavior changes in existing code
- [ ] JSON serialization of new fields works correctly (empty values omitted)

## Implementation Plan

### Steps

1. [ ] Open `internal/services/transition_types.go`
2. [ ] Add `TransitionOptions` struct after `TransitionResult`
3. [ ] Add three fields to `TransitionResult`: `IsBackward bool`, `Reason string`, `ChildCount int`
4. [ ] Verify the file compiles

### Technical Approach

**File**: `internal/services/transition_types.go`

Add `TransitionOptions`:
```go
type TransitionOptions struct {
    Force        bool   `json:"force,omitempty"`  // Bypasses workflow validation, still requires Reason
    Reason       string `json:"reason,omitempty"` // Required for backward and forced transitions
    DocumentPath string `json:"document_path,omitempty"`
    Agent        string `json:"agent,omitempty"`
}
```

Extend `TransitionResult` with:
```go
IsBackward bool   `json:"is_backward,omitempty"`
IsForced   bool   `json:"is_forced,omitempty"`
Reason     string `json:"reason,omitempty"`
ChildCount int    `json:"child_count,omitempty"`
```

### Dependencies

- None. This is the foundation task.
