# Task: CLI Commands - next-status, update refactor, service accessors

## Goal

Create `shark epic next-status` and `shark feature next-status` CLI commands, refactor `shark epic update --status` and `shark feature update --status` to use the new service layer, and add `GetEpicService()` / `GetFeatureService()` global accessors. This is the user-facing layer that connects the workflow engine to CLI interaction.

## Success Criteria

- [ ] `GetEpicService()` and `GetFeatureService()` factory functions created in CLI layer
- [ ] `shark epic next-status <key>` command works: advances epic to next workflow status
- [ ] `shark epic next-status <key> --preview` shows available transitions without making changes
- [ ] `shark epic next-status <key> --status=<target>` transitions directly to specified status
- [ ] `shark epic next-status <key> --force` bypasses workflow validation
- [ ] `shark epic next-status <key> --json` returns structured JSON response
- [ ] `shark feature next-status <key>` works identically for features
- [ ] `shark epic update <key> --status <new>` validates against epic workflow (not hardcoded list)
- [ ] `shark feature update <key> --status <new>` validates against feature workflow
- [ ] Invalid transitions show error with valid options and `--force` hint
- [ ] Terminal status entities show "no transitions available" message
- [ ] Not-found entities show "not found" error with exit code 1
- [ ] All new commands have unit tests with mocked services
