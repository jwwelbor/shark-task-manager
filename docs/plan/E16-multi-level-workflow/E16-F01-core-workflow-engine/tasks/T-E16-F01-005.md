# Task: Model and CLI Validation Refactoring

## Goal

Refactor `ValidateEpicStatus()` and `ValidateFeatureStatus()` in the model layer to accept any non-empty string (removing hardcoded status lists), update error message variables, and update CLI validators to delegate to the workflow service for workflow-aware validation. This unblocks configurable epic/feature statuses throughout the codebase.

## Success Criteria

- [ ] `models.ValidateEpicStatus()` checks only for non-empty string (no hardcoded status list)
- [ ] `models.ValidateFeatureStatus()` checks only for non-empty string
- [ ] `ErrInvalidEpicStatus` error message updated to generic "invalid epic status" (no hardcoded list)
- [ ] `ErrInvalidFeatureStatus` error message updated similarly
- [ ] Existing `EpicStatus` and `FeatureStatus` constants retained with deprecation comments
- [ ] CLI `ValidateStatus()` function in `validators.go` delegates to `workflow.Service.ForLevel()` for epic/feature
- [ ] `ParseEpicStatus()` and `ParseFeatureStatus()` (if they exist) become workflow-aware or are removed
- [ ] Custom statuses (e.g., `ready_for_research`) pass model validation
- [ ] Default statuses (`draft`, `active`, `completed`, `archived`) still pass validation
- [ ] All existing tests pass (update as needed for new validation behavior)

## Implementation Guidance

### Overview

This task covers architecture Wave 4 (items T-010, T-011). It's a targeted refactoring that makes the validation layer compatible with configurable workflows. The changes are primarily about removing restrictive validation, not adding new logic.

### Key Requirements

- **Model validation changes**: See [Architecture - Section 6.1](../architecture.md#61-model-layer-remove-hardcoded-status-validation) for exact new implementations of `ValidateEpicStatus()` and `ValidateFeatureStatus()`
- **Error variable updates**: See [Architecture - Section 6.1](../architecture.md#61-model-layer-remove-hardcoded-status-validation) for before/after error messages
- **Status constant deprecation**: See [Architecture - Section 6.2](../architecture.md#62-model-layer-remove-hardcoded-status-constants) for how to add deprecation comments while keeping constants
- **CLI validator update**: See [Architecture - Section 6.3](../architecture.md#63-cli-layer-update-validatestatus-function) for the new `ValidateStatus()` implementation
- **BA Review Risk**: `ValidateEpicStatus`/`ValidateFeatureStatus` are hardcoded to 4 statuses - this must change
