# Task: Config Schema and Default Workflows

## Goal

Add new `StatusMetadata` fields (`IsPlanning`, `AggregatesFrom`) and `AggregationStatusKey` constant to the workflow config schema, then create `DefaultEpicWorkflow()` and `DefaultFeatureWorkflow()` functions and a `MultiLevelWorkflow` container struct. This establishes the config data model foundation that all subsequent tasks depend on.

## Success Criteria

- [ ] `IsPlanning` (bool) and `AggregatesFrom` (string) fields added to `config.StatusMetadata` struct
- [ ] `AggregationStatusKey` constant (`_aggregation_`) defined alongside existing `StartStatusKey` and `CompleteStatusKey`
- [ ] `DefaultEpicWorkflow()` returns a valid `*WorkflowConfig` with 4 statuses: draft, active, completed, archived
- [ ] `DefaultFeatureWorkflow()` returns a valid `*WorkflowConfig` with same 4 statuses
- [ ] Both default workflows pass existing `ValidateWorkflow()` validation
- [ ] `MultiLevelWorkflow` struct created with `Epic`, `Feature`, `Task` fields (all `*WorkflowConfig`)
- [ ] `GetWorkflowForLevel(level string)` method returns appropriate workflow, falling back to defaults for nil
- [ ] Existing task workflow behavior completely unchanged
- [ ] All new code has unit tests
