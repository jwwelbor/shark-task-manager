# Task: Implement multi-level workflow list display

## Goal

Rewrite `runWorkflowList()` in `internal/cli/commands/workflow.go` to display all three workflow levels (epic, feature, task) with planning vs aggregation visual markers, custom/default labels, and a legend footer.

## Requirements

### Functional Requirements

- [ ] REQ-F-001: Show epic workflow statuses and transitions
- [ ] REQ-F-002: Show feature workflow statuses and transitions
- [ ] REQ-F-003: Visual markers for planning (`[planning]`) and aggregation (`[status]`, `[aggregates: X]`)
- [ ] REQ-F-004: Source labels - "(custom)" or "(default)" per level
- [ ] REQ-F-005: Legend footer explaining markers
- [ ] REQ-F-006: JSON output with `epic_workflow`, `feature_workflow`, `task_workflow` keys

## Implementation Plan

### Steps

1. [ ] Add display structs: `MultiLevelWorkflowDisplay`, `LevelWorkflowDisplay`, `StatusDisplay`
2. [ ] Add `buildMultiLevelWorkflowDisplay()` and `buildLevelWorkflowDisplay()` builder functions
3. [ ] Rewrite `runWorkflowList()` to use `config.LoadMultiLevelWorkflow()` and builder functions
4. [ ] Add `displayMultiLevelWorkflowHumanReadable()` rendering function
5. [ ] Add `displayWorkflowLevelSection()` for per-level rendering with markers
6. [ ] Add `displaySpecialStatuses()` and `displayStatusWithMarkers()` helpers
7. [ ] Remove old `displayWorkflowHumanReadable()` function
8. [ ] Run `make fmt && make lint && make test`

### Files Changed

- `internal/cli/commands/workflow.go` - Main implementation

### Technical Approach

- Follow the multi-level pattern from `workflow show-actions` (same file pattern)
- Reuse `config.LoadMultiLevelWorkflow()` for custom-vs-default detection
- Reuse `config.MultiLevelWorkflow.GetWorkflowForLevel()` for resolved workflows
- Use `cases.Title(language.English)` for level name formatting (already imported)

## Acceptance Criteria

- [ ] `shark workflow list` shows 3 levels with section headers
- [ ] Default workflows show "(default)", custom workflows show "(custom)"
- [ ] Aggregation statuses displayed with `[brackets]`
- [ ] Planning statuses marked with `[planning]`
- [ ] Legend present at bottom
- [ ] `shark workflow list --json` returns `MultiLevelWorkflowDisplay` structure
- [ ] `make fmt && make lint && make test` passes
