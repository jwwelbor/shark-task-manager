### Low Priority Issues / Minor Findings

#### Finding #1: Case-Insensitive Key Lookup Not Consistent
**Severity:** Low
**Type:** Enhancement
**Affected Commands:** `epic note`, `epic context`, `feature note`, `feature context`

**Description:**
Task commands properly handle case-insensitive keys (e.g., `e16-f04-004`), but epic and feature commands require exact case (E16, not e16).

**Evidence:**
```bash
shark task get e16-f04-004     # ✅ Works
shark epic note add e16 ...    # ❌ Error: epic not found
```

**Impact:**
Minor usability issue. Users must remember correct case for epic/feature keys. Does not affect functionality when correct case is used.

**Recommendation:**
Update `EpicRepository` and `FeatureRepository` `GetByKey` methods to use case-insensitive lookups (similar to `TaskRepository`). This can be addressed in a future polish task.

**Workaround:**
Use correct case (uppercase) for epic and feature keys.
