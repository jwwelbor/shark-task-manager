# Task: EntityNote Model and EntityNoteRepository

## Goal

Replace the task-only `TaskNote` model and `TaskNoteRepository` with a polymorphic `EntityNote` model and `EntityNoteRepository` that supports epic, feature, and task entities. Update all existing code that references the old types to use the new ones.

## Requirements

### Functional Requirements

- [ ] Create `EntityNote` model with `EntityType` + `EntityID` fields
- [ ] Create `EntityType` enum: `epic`, `feature`, `task`
- [ ] Move `NoteType` constants from `task_note.go` to `entity_note.go` (unchanged values)
- [ ] Delete `internal/models/task_note.go`
- [ ] Create `EntityNoteRepository` with all CRUD methods
- [ ] Implement entity existence validation before note creation
- [ ] Delete `internal/repository/task_note_repository.go`
- [ ] Update all ~17 files referencing `TaskNote` / `TaskNoteRepository` to use new types
- [ ] Existing task note commands continue to work (passing `entity_type = 'task'`)

### Non-Functional Requirements

- [ ] All queries use parameterized statements
- [ ] Entity existence validation uses COUNT query (not full entity load)
- [ ] Repository tests use real database with proper cleanup

### Technical Approach

- The `EntityNoteRepository` queries `entity_notes` table (created in T-E16-F04-004)
- Entity existence validation queries the appropriate table based on `entity_type`:
  - `epic` -> `SELECT COUNT(*) FROM epics WHERE id = ?`
  - `feature` -> `SELECT COUNT(*) FROM features WHERE id = ?`
  - `task` -> `SELECT COUNT(*) FROM tasks WHERE id = ?`
- Search methods join across entity tables to resolve keys/titles for display
- `NoteSearchResult` is updated to be entity-generic (not task-specific)
