# Task: Enhance Epic Get and Feature Get with Notes and Context

## Goal

Modify the existing `shark epic get` and `shark feature get` commands to include notes and context data in their output. Currently these commands show entity details and child summary but no notes or context.

## Requirements

### Functional Requirements

- [ ] `shark epic get <key>` human-readable output includes a "Notes" section and "Context" section
- [ ] `shark epic get <key> --json` JSON output includes `notes` and `context_data` fields
- [ ] `shark feature get <key>` human-readable output includes "Notes" and "Context" sections
- [ ] `shark feature get <key> --json` JSON output includes `notes` and `context_data` fields
- [ ] Notes section shows most recent 10 notes (with count if more exist)
- [ ] Context section shows non-nil fields only
- [ ] If no notes/context exist, sections are omitted (not shown as empty)

### Non-Functional Requirements

- [ ] Additional queries (notes + context) only add 2 queries per command
- [ ] Existing output format and fields are preserved (additive change only)

## Implementation Plan

### Steps

1. [ ] Modify `internal/cli/commands/epic.go` - `runEpicGet` function:
   - After fetching epic, also fetch notes via `NoteService.ListNotes(ctx, "epic", key, nil)`
   - Also fetch context via `ContextService.GetContext(ctx, "epic", key)`
   - JSON output: add `notes` and `context_data` fields to response struct
   - Human-readable: add "Notes" and "Context" sections after existing output
2. [ ] Modify `internal/cli/commands/feature.go` - `runFeatureGet` function:
   - Same pattern: fetch notes and context alongside feature data
   - JSON: add fields to response
   - Human-readable: add sections
3. [ ] Write/update CLI tests

### JSON Output Enhancement

**Epic get JSON** (new fields):
```json
{
  "key": "E16",
  "title": "Multi-Level Workflow System",
  "status": "active",
  "features": [...],
  "notes": [
    {"id": 1, "note_type": "decision", "content": "...", "created_at": "..."}
  ],
  "context_data": {
    "progress": {"current_step": "Feature implementation"},
    "open_questions": ["Should completion be auto-detected?"]
  }
}
```

### Human-Readable Enhancement

Append after existing output:
```
--- Notes ---
  [decision] 2026-02-09  Chose config-driven approach
  [comment]  2026-02-09  Research phase complete
  (showing 2 of 2 notes)

--- Context ---
  Current Step: Feature implementation
  Open Questions:
    - Should completion be auto-detected?
```

## Notes

- The existing `epic.go` and `feature.go` use the legacy "fat controller" pattern (direct repo access). For the notes/context addition, use the service layer (NoteService, ContextService) to avoid adding more direct repo calls.
- Be careful not to break the existing JSON output contract - the new fields are additive only.
- Consider using the `smart get` dispatcher in `internal/cli/commands/smart_dispatchers.go` as well, since `shark get E16` routes through there.
