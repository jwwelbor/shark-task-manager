# Task: NoteService and ContextService

## Goal

Create service layer abstractions for note and context operations that work across all entity types. These services encapsulate entity key resolution (converting user-provided keys like "E16" or "E16-F01" to entity IDs) and business logic, enabling thin CLI command wrappers.

## Requirements

### Functional Requirements

- [ ] `NoteService.AddNote(ctx, entityType, entityKey, noteType, content, createdBy)` resolves key to ID and creates note
- [ ] `NoteService.ListNotes(ctx, entityType, entityKey, noteTypes)` returns notes for entity
- [ ] `NoteService.SearchNotes(ctx, query, noteTypes, entityType, epicKey, featureKey)` searches across notes
- [ ] `ContextService.GetContext(ctx, entityType, entityKey)` returns context data for any entity
- [ ] `ContextService.SetContextField(ctx, entityType, entityKey, field, value)` sets a single field (merge semantics)
- [ ] `ContextService.ClearContext(ctx, entityType, entityKey)` clears all context data
- [ ] Entity key resolution works for all key formats (E16, E16-F01, E16-F01-001, slugged variants)

### Non-Functional Requirements

- [ ] Services use constructor injection for all dependencies
- [ ] Services are testable with mocked repositories
- [ ] Entity key resolution reuses existing repository lookup patterns

## Implementation Plan

### Steps

1. [ ] Create `internal/services/note_service.go`:
   - Constructor: `NewNoteService(entityNoteRepo, epicRepo, featureRepo, taskRepo)`
   - `AddNote` method: resolve entity key -> get entity ID -> create note via repo
   - `ListNotes` method: resolve entity key -> query notes via repo
   - `SearchNotes` method: delegate to repo search
   - Private `resolveEntityID(ctx, entityType, key)` method that uses appropriate repo's GetByKey
2. [ ] Create `internal/services/context_service.go`:
   - Constructor: `NewContextService(epicRepo, featureRepo, taskRepo)`
   - `GetContext` method: resolve key -> get context from appropriate repo
   - `SetContextField` method: resolve key -> get current context -> merge field -> update
   - `ClearContext` method: resolve key -> set context to nil
3. [ ] Create `internal/services/note_service_test.go` with mocked repositories
4. [ ] Create `internal/services/context_service_test.go` with mocked repositories

### Technical Approach

**Entity Key Resolution**:
The `resolveEntityID` method switches on `entityType` and calls the appropriate repository:
```
epic    -> epicRepo.GetByKey(ctx, key)    -> return epic.ID
feature -> featureRepo.GetByKey(ctx, key) -> return feature.ID
task    -> taskRepo.GetByKey(ctx, key)    -> return task.ID
```

**Context Field Merge**:
`SetContextField` implements the same merge logic as the existing `updateContextField` function in `task_context.go`:
1. Get current context data (or create empty if nil)
2. Parse the field name and update the corresponding struct field
3. Write back the full context data

**Supported context fields** (same as task context):
- `current_step`, `completed_steps`, `remaining_steps`
- `implementation_decisions`, `open_questions`
- `blockers`, `acceptance_criteria_status`, `related_tasks`

### Service Wiring

Add service constructors to `internal/cli/db_global.go` or a new `internal/cli/services_global.go`:
```go
func GetNoteService(ctx context.Context) (*services.NoteService, error)
func GetContextService(ctx context.Context) (*services.ContextService, error)
```
