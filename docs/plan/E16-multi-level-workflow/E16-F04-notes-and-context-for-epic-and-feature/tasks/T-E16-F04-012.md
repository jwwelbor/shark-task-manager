# Task: Integration Testing and Edge Cases

## Goal

Comprehensive integration testing of the full E16-F04 feature: notes, context, resume, and get commands across all entity types. Verify backward compatibility with existing task note/context commands. Test edge cases and error paths.

## Requirements

### Functional Requirements

- [ ] Full lifecycle test: add note -> list notes -> set context -> get context -> resume -> get (with notes/context)
- [ ] Cross-entity type tests: same operations work for epic, feature, and task
- [ ] Backward compatibility: existing `shark task note add`, `shark task note list`, `shark task context`, `shark task resume` commands work unchanged
- [ ] Edge cases: empty notes, empty context, null fields, very long content
- [ ] Error paths: invalid keys, missing entities, invalid note types, invalid context fields
- [ ] JSON output validation for all commands

### Non-Functional Requirements

- [ ] Tests are deterministic and repeatable
- [ ] Tests clean up after themselves
- [ ] Tests can run in CI environment

## Implementation Plan

### Steps

1. [ ] Create integration test file(s) that exercise the full command lifecycle:
   - Create an epic -> add notes -> set context -> resume -> verify
   - Create a feature -> add notes -> set context -> resume -> verify
   - Verify `shark get` includes notes/context
2. [ ] Test backward compatibility:
   - Run existing task note commands -> verify they still work
   - Verify task notes migrated from `task_notes` to `entity_notes` are accessible
   - Verify `shark task resume` still works
3. [ ] Test edge cases:
   - Add note with empty content (should error)
   - Add note with invalid type (should error)
   - Get context on entity with no context (should return null/empty)
   - Resume on entity with no notes or context (should still work)
   - Set context field with JSON value (complex types)
   - Very long note content (> 10KB)
4. [ ] Test JSON output consistency:
   - Verify all JSON responses are valid JSON
   - Verify response schemas match architecture doc specifications
   - Verify `--json` flag produces machine-readable output
5. [ ] Test notes search with entity type filter:
   - `shark notes search "keyword" --entity-type epic` (if T-E16-F04-003 is complete)
   - `shark notes search "keyword"` returns results across all entity types

### Test Scenarios

| Scenario | Commands | Expected |
|----------|----------|----------|
| Epic note lifecycle | `epic note add` -> `epic note list` -> `epic resume` | Notes visible in all |
| Feature note lifecycle | `feature note add` -> `feature note list` -> `feature resume` | Notes visible in all |
| Task note backward compat | `task note add` -> `task note list` -> `task resume` | All work unchanged |
| Epic context lifecycle | `epic context set` -> `epic context get` -> `epic resume` | Context visible in all |
| Get command enhancement | `epic get --json` | Includes notes and context_data |
| Empty entity | `epic resume <new-epic>` | Succeeds with empty notes/context |
| Invalid key | `epic note add INVALID --type comment "test"` | Error: epic not found |
| Invalid note type | `epic note add E16 --type invalid "test"` | Error: invalid note type |
