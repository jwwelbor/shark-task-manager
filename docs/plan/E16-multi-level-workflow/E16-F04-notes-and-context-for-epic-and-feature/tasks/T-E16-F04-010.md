# Task: ResumeService and Resume CLI Commands

## Goal

Create a `ResumeService` and CLI commands for `shark epic resume <key>` and `shark feature resume <key>`. These aggregate entity details, notes, context data, child entities, and workflow position into a single comprehensive context dump for agents resuming work.

## Requirements

### Functional Requirements

- [ ] `shark epic resume <key> [--json]` shows full context for resuming epic-level work
- [ ] `shark feature resume <key> [--json]` shows full context for resuming feature-level work
- [ ] Epic resume includes: epic details, context data, notes, features list, workflow phase
- [ ] Feature resume includes: feature details, context data, notes, tasks list, parent epic, workflow phase
- [ ] JSON output matches the schema defined in the architecture doc
- [ ] Human-readable output shows organized sections

### Non-Functional Requirements

- [ ] Epic resume: max 3 queries (epic + notes + features)
- [ ] Feature resume: max 4 queries (feature + notes + tasks + parent epic)
- [ ] Service is testable with mocked repositories

## Implementation Plan

### Steps

1. [ ] Create `internal/services/resume_service.go`:
   - Define `EpicResumeContext` struct:
     ```go
     type EpicResumeContext struct {
         Epic          *models.Epic         `json:"epic"`
         ContextData   *models.ContextData  `json:"context_data,omitempty"`
         Notes         []*models.EntityNote `json:"notes,omitempty"`
         Features      []*models.Feature    `json:"features,omitempty"`
         WorkflowPhase *string              `json:"workflow_phase,omitempty"`
     }
     ```
   - Define `FeatureResumeContext` struct:
     ```go
     type FeatureResumeContext struct {
         Feature       *models.Feature      `json:"feature"`
         ContextData   *models.ContextData  `json:"context_data,omitempty"`
         Notes         []*models.EntityNote `json:"notes,omitempty"`
         Tasks         []*models.Task       `json:"tasks,omitempty"`
         Epic          *models.Epic         `json:"epic,omitempty"`
         WorkflowPhase *string              `json:"workflow_phase,omitempty"`
     }
     ```
   - Constructor: `NewResumeService(noteSvc, contextSvc, epicRepo, featureRepo, taskRepo, workflowSvc)`
   - `GetEpicResumeContext(ctx, epicKey)` method:
     1. Resolve epic by key
     2. Get context data via ContextService
     3. Get notes via NoteService
     4. Get features for this epic
     5. Get workflow phase from status metadata (if E16-F01 available, otherwise derive from status)
   - `GetFeatureResumeContext(ctx, featureKey)` method:
     1. Resolve feature by key
     2. Get context data
     3. Get notes
     4. Get tasks for this feature
     5. Get parent epic
     6. Get workflow phase
2. [ ] Create `internal/cli/commands/epic_resume.go`:
   - Command: `shark epic resume <key> [--json]`
   - Handler: call `ResumeService.GetEpicResumeContext` -> format output
   - JSON mode: output full `EpicResumeContext` as JSON
   - Human-readable mode: organized sections (Status, Context, Notes, Features)
3. [ ] Create `internal/cli/commands/feature_resume.go`:
   - Command: `shark feature resume <key> [--json]`
   - Handler: call `ResumeService.GetFeatureResumeContext` -> format output
   - JSON mode: output full `FeatureResumeContext` as JSON
   - Human-readable mode: organized sections (Status, Context, Notes, Tasks, Epic)
4. [ ] Write service tests and CLI tests

## Notes

- The `WorkflowPhase` field is populated from status metadata if the multi-level workflow engine (E16-F01) is available. If not, derive a basic phase from the entity status (e.g., "draft" -> "planning", "active" -> "execution", "completed" -> "done").
- Consider referencing the existing `task_resume.go` `ResumeContext` struct for patterns, but don't inherit work session fields (work sessions are task-only and may be deprecated).
- The resume commands are the primary tool agents use to recover context when starting a new session.
