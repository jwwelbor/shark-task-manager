# Task: Update Status Command with Planning Awareness

## Goal

Update the `shark status` command to show planning-aware information for epics and features. When an entity is in planning mode, the status dashboard should show workflow position rather than child progress aggregation.

## Requirements

### Functional Requirements

- [ ] Modify status command for epics to use `DisplayService` and respect planning/aggregation mode
- [ ] Modify status command for features to use `DisplayService` and respect planning/aggregation mode
- [ ] Planning mode status shows: current status, phase, workflow position (next steps), no child rollups
- [ ] Aggregation mode status shows: current behavior (progress, rollups, action items)
- [ ] Add `DisplayMode`, `Phase`, and `IsPlanning` fields to `EpicSummary` model (or equivalent status output type)
- [ ] JSON output includes planning metadata in status response

### Non-Functional Requirements

- [ ] Status command remains thin wrapper calling service layer
- [ ] Backward compatible for projects without epic/feature workflows

## Implementation Plan

### Steps

1. [ ] Update `runStatusCommand` in `internal/cli/commands/status.go` to use `DisplayService`
2. [ ] For epic status: call `GetEpicDisplayInfo` and route to planning or aggregation status renderer
3. [ ] For feature status: call `GetFeatureDisplayInfo` and route to planning or aggregation status renderer
4. [ ] Implement planning-mode status renderers for both entity types
5. [ ] Update JSON output to include `display_mode`, `is_planning`, `phase`
6. [ ] Add tests

### Technical Approach

- Status command already detects entity type from key format
- After detecting epic/feature, call DisplayService instead of directly querying repos
- Planning status is simpler to render: just entity name, status, phase, and next available transitions
- Aggregation status uses existing logic (progress, rollups, action items)

## Deliverables

- [ ] Modified `internal/cli/commands/status.go` with DisplayService integration
- [ ] Planning-mode status renderers for epic and feature
- [ ] Updated JSON output with planning metadata

## Acceptance Criteria

- [ ] `shark status E16` (when E16 is in planning state) shows workflow position, no feature rollups
- [ ] `shark status E16-F03` (when F03 is in planning state) shows workflow position, no task rollups
- [ ] `shark status E07` (existing epic, no epic workflow) shows current behavior unchanged
- [ ] `shark status E07-F01` (existing feature, no feature workflow) shows current behavior unchanged
- [ ] JSON output includes `display_mode`, `is_planning`, `phase` fields

## Testing Strategy

- [ ] Test epic status in planning mode
- [ ] Test epic status in aggregation mode (existing behavior)
- [ ] Test feature status in planning mode
- [ ] Test feature status in aggregation mode (existing behavior)
- [ ] Test backward compatibility with no workflow configured
- [ ] Test JSON output for both modes
