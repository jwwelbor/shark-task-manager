# Task: Add Planning Feature Labels in Epic Aggregation View

## Goal

When an epic is in aggregation mode (showing child features), features that are still in planning states should display a `(planning)` label instead of a progress bar. This provides visual distinction between features being planned and features being built.

## Requirements

### Functional Requirements

- [ ] In `EpicDisplayInfo.Features` list items, include a `IsPlanning` boolean field
- [ ] When rendering epic aggregation view, features with `IsPlanning: true` show `(planning)` label instead of progress percentage
- [ ] Features with `IsPlanning: false` show progress bars as they do today
- [ ] JSON output for features in epic get includes `is_planning` field per feature
- [ ] The `FeatureDisplayItem` type (used in EpicDisplayInfo) includes display mode information

### Non-Functional Requirements

- [ ] Minimal change to existing aggregation renderer
- [ ] No additional database queries beyond what's already fetched

## Implementation Plan

### Steps

1. [ ] Add `IsPlanning` field to `FeatureDisplayItem` struct in DisplayService types
2. [ ] In `GetEpicDisplayInfo` aggregation path, determine each feature's display mode
3. [ ] Update epic aggregation renderer to check `IsPlanning` and render `(planning)` label
4. [ ] Update JSON output to include `is_planning` per feature item
5. [ ] Add tests

### Technical Approach

- When assembling `EpicDisplayInfo` in aggregation mode, iterate features and call `determineFeatureDisplayMode()` for each
- Set `FeatureDisplayItem.IsPlanning = true` for features in planning states
- In renderer: `if item.IsPlanning { print "(planning)" } else { print progressBar }`
- This is a small incremental change on top of T-E16-F03-002's renderer

## Deliverables

- [ ] Updated `FeatureDisplayItem` type with `IsPlanning` field
- [ ] Updated epic aggregation renderer with `(planning)` label logic
- [ ] Updated JSON output

## Acceptance Criteria

- [ ] `shark get E16` (when E16 is active with some features in planning) shows `(planning)` next to planning features and progress bars next to active features
- [ ] `shark get E16 --json` includes `is_planning` field for each feature in the features array
- [ ] Existing epics with no feature workflow show all features with progress bars (no change)

## Testing Strategy

- [ ] Test epic with mix of planning and aggregation features
- [ ] Test epic where all features are in planning
- [ ] Test epic where all features are in aggregation (existing behavior)
- [ ] Test JSON output structure

## Dependencies

- **T-E16-F03-002**: Epic get renderer (modifies the aggregation renderer)
