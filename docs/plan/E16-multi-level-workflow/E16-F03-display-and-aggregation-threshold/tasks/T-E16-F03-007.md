# Task: Integration Testing and Edge Cases

## Goal

Comprehensive integration testing of the display and aggregation threshold feature, covering cross-cutting scenarios, backward compatibility, edge cases, and the interaction between planning and aggregation modes.

## Requirements

### Functional Requirements

- [ ] Integration tests covering full stack: CLI command -> DisplayService -> Repository -> Database
- [ ] Backward compatibility tests: projects with no epic/feature workflow see zero behavior change
- [ ] Edge case tests for mode transitions (entity crosses aggregation threshold)
- [ ] Mixed mode tests: epic in aggregation with some features in planning, some in aggregation
- [ ] Empty state tests: epic/feature with no children in both modes
- [ ] JSON output validation for all scenarios

### Non-Functional Requirements

- [ ] Tests cover both basic and advanced workflow profiles
- [ ] Tests are deterministic and parallel-safe
- [ ] Integration tests use real database (per testing architecture rules)

## Implementation Plan

### Steps

1. [ ] Create integration test file `internal/services/display_service_integration_test.go`
2. [ ] Write backward compatibility tests (no workflow configured)
3. [ ] Write planning mode integration tests (epic and feature)
4. [ ] Write aggregation mode integration tests (verify no regression)
5. [ ] Write mixed mode tests (epic aggregating, features mixed planning/aggregation)
6. [ ] Write aggregation threshold crossing tests
7. [ ] Write JSON output validation tests
8. [ ] Write CLI output format tests for both modes
9. [ ] Document test coverage results

### Test Scenarios

**Backward Compatibility:**
- Existing project with no epic/feature workflow config
- All epics show aggregation mode (current behavior)
- All features show aggregation mode (current behavior)
- Status command shows current behavior

**Planning Mode:**
- Epic in `draft` status (is_planning: true) -> planning mode display
- Feature in `in_refinement_ba` status (is_planning: true) -> planning mode display
- No progress bars or child counts shown
- Correct workflow position displayed

**Aggregation Mode:**
- Epic in `active` status (is_planning: false) -> aggregation mode display
- Feature in `active` status (is_planning: false) -> aggregation mode display
- Progress bars and child counts shown (identical to current)

**Mixed Mode:**
- Epic in `active` with features: F01 (active, shows progress), F02 (draft, shows "(planning)")
- Verify `(planning)` label appears correctly

**Threshold Crossing:**
- Feature transitions from `ready_for_development` (planning) to `in_development` (aggregation)
- Verify display mode changes accordingly
- Verify CalculationService begins aggregating after threshold crossed

**Edge Cases:**
- Epic with zero features in planning mode
- Feature with zero tasks in planning mode
- Entity at exact threshold status (`_aggregation_` status)
- Invalid/unknown status falls back to aggregation mode
