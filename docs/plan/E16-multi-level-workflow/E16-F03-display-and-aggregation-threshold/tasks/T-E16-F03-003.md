# Task: Implement Feature Get Planning Mode Renderer

## Goal

Update the `feature get` command to use `DisplayService` and render planning mode output when a feature is in a planning state. When in planning mode, show workflow position instead of task progress bars.

## Requirements

### Functional Requirements

- [ ] Modify `runFeatureGet` in `internal/cli/commands/feature.go` to call `DisplayService.GetFeatureDisplayInfo()`
- [ ] Create `renderFeaturePlanning(info *FeatureDisplayInfo)` function for planning mode display
- [ ] Planning mode output shows: feature title, current status with phase label, workflow position
- [ ] Planning mode shows message: "No tasks yet (feature is still being refined)" when appropriate
- [ ] No progress bars, task counts, or work breakdown shown in planning mode
- [ ] JSON output includes `display_mode: "planning"`, `is_planning: true`, `phase`, `workflow_position`
- [ ] Existing aggregation mode rendering is preserved unchanged

### Non-Functional Requirements

- [ ] Command remains a thin wrapper: parse args, call service, format output
- [ ] No business logic in the command layer

## Implementation Plan

### Steps

1. [ ] Update `runFeatureGet` to instantiate `DisplayService` and call `GetFeatureDisplayInfo`
2. [ ] Add routing: `switch info.Mode` to planning or aggregation renderer
3. [ ] Implement `renderFeaturePlanning()` with workflow position display
4. [ ] Update JSON output path to include planning metadata fields
5. [ ] Verify existing aggregation rendering is untouched
6. [ ] Add tests with mocked DisplayService

### Technical Approach

- Same pattern as T-E16-F03-002 (epic get) but for features
- Feature planning renderer shows: title, status, phase, workflow position
- Feature aggregation renderer is existing behavior (task progress, work breakdown, action items)

## Deliverables

- [ ] Modified `internal/cli/commands/feature.go` - Updated `runFeatureGet` with DisplayService integration
- [ ] New renderer function `renderFeaturePlanning()` in feature.go
- [ ] Updated JSON output with planning metadata

## Acceptance Criteria

- [ ] `shark get E16-F03` (when F03 is in planning state) shows workflow position, no task progress
- [ ] `shark get E16-F03 --json` includes `display_mode`, `is_planning`, `phase`, `workflow_position`
- [ ] `shark get E07-F01` (existing feature with no feature workflow) shows current aggregation behavior unchanged
- [ ] Planning mode message displayed when feature has no tasks yet

## Testing Strategy

- [ ] Test with mocked DisplayService returning planning mode FeatureDisplayInfo
- [ ] Test with mocked DisplayService returning aggregation mode FeatureDisplayInfo
- [ ] Test JSON output includes correct fields for both modes
- [ ] Verify no regression in existing aggregation output format

## Dependencies

- **T-E16-F03-001**: DisplayService core with `GetFeatureDisplayInfo` and type definitions

- User Story 4: "Feature in active state shows task progress (unchanged behavior)"
