# Task: Implement Epic Get Planning Mode Renderer

## Goal

Update the `epic get` command to use `DisplayService` and render planning mode output when an epic is in a planning state. When in planning mode, show workflow position instead of progress bars and task counts.

## Requirements

### Functional Requirements

- [ ] Modify `runEpicGet` in `internal/cli/commands/epic.go` to call `DisplayService.GetEpicDisplayInfo()`
- [ ] Create `renderEpicPlanning(info *EpicDisplayInfo)` function for planning mode display
- [ ] Planning mode output shows: epic title, current status with phase label, workflow position (next/previous statuses)
- [ ] Planning mode shows message: "No features yet (epic is still being refined)" when appropriate
- [ ] No progress bars, task counts, or feature rollups shown in planning mode
- [ ] JSON output includes `display_mode: "planning"`, `is_planning: true`, `phase`, `workflow_position`
- [ ] Existing aggregation mode rendering is preserved unchanged

### Non-Functional Requirements

- [ ] Command remains a thin wrapper: parse args, call service, format output
- [ ] No business logic in the command layer

## Implementation Plan

### Steps

1. [ ] Update `runEpicGet` to instantiate `DisplayService` and call `GetEpicDisplayInfo`
2. [ ] Add routing: `switch info.Mode` to planning or aggregation renderer
3. [ ] Implement `renderEpicPlanning()` with workflow position display
4. [ ] Update JSON output path to include planning metadata fields
5. [ ] Verify existing aggregation rendering is untouched
6. [ ] Add tests with mocked DisplayService

### Technical Approach

- Command calls `DisplayService.GetEpicDisplayInfo(ctx, epicKey)` which returns `EpicDisplayInfo` with mode already determined
- Route to `renderEpicPlanning()` or existing aggregation renderer based on `info.Mode`
- Planning renderer uses `cli.Info()` and `cli.Success()` for formatted output
- JSON mode serializes the full `EpicDisplayInfo` struct

## Deliverables

- [ ] Modified `internal/cli/commands/epic.go` - Updated `runEpicGet` with DisplayService integration
- [ ] New renderer function `renderEpicPlanning()` in epic.go
- [ ] Updated JSON output with planning metadata

## Acceptance Criteria

- [ ] `shark get E16` (when E16 is in planning state) shows workflow position, no progress bars
- [ ] `shark get E16 --json` includes `display_mode`, `is_planning`, `phase`, `workflow_position`
- [ ] `shark get E07` (existing epic with no epic workflow) shows current aggregation behavior unchanged
- [ ] Planning mode message displayed when epic has no features yet

## Testing Strategy

- [ ] Test with mocked DisplayService returning planning mode EpicDisplayInfo
- [ ] Test with mocked DisplayService returning aggregation mode EpicDisplayInfo
- [ ] Test JSON output includes correct fields for both modes
- [ ] Verify no regression in existing aggregation output format

## Dependencies

- **T-E16-F03-001**: DisplayService core with `GetEpicDisplayInfo` and type definitions

## Notes

- User Story 1 from PRD: "Epic in planning state shows workflow position, not empty progress bars"
- The existing rendering code for aggregation mode should be extracted into a `renderEpicAggregation()` function for symmetry, but the behavior must remain identical
