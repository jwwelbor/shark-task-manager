# Task: Add resolveAction to EpicService and integrate into transitions

## Goal

Add orchestrator action resolution to `EpicService` so that when an epic transitions status via `TransitionStatus` or queries available transitions via `GetNextStatus`, the response includes the orchestrator action (if any) defined in the workflow config for the target status. This follows the same pattern already established by `TaskRepository.getOrchestratorAction()` (lines 1029-1059 of `internal/repository/task_repository.go`) but places the logic in the service layer where it belongs.

## Requirements

### Functional Requirements

- [ ] Add a private `resolveAction(entityKey, status string) *config.PopulatedAction` helper method to `EpicService`
- [ ] Integrate `resolveAction` into `TransitionStatus` -- attach the resolved action to the returned `TransitionResult`
- [ ] Integrate `resolveAction` into `GetNextStatus` -- enrich each available transition with its orchestrator action
- [ ] `resolveAction` returns `nil` (not an error) when no action is defined for a status
- [ ] `resolveAction` returns `nil` (not an error) when the workflow config is nil or has no `StatusMetadata`
- [ ] Template placeholder `{id}` in `instruction_template` is replaced with the epic key (e.g., "E16")

- [ ] All existing `EpicService` tests continue to pass without modification

### Technical Approach

#### resolveAction Implementation

Add the following private method to `EpicService` in `internal/services/epic_service.go`:

```go
// resolveAction looks up and populates the orchestrator action for a status.
// Returns nil if no action is defined (not an error).
func (s *EpicService) resolveAction(entityKey string, status string) *config.PopulatedAction {
    wf := s.workflowSvc.GetWorkflow()
    if wf == nil || wf.StatusMetadata == nil {
        return nil
    }

    meta, exists := wf.StatusMetadata[status]
    if !exists || meta.OrchestratorAction == nil {
        return nil
    }

    return &config.PopulatedAction{
        Action:      meta.OrchestratorAction.Action,
        AgentType:   meta.OrchestratorAction.AgentType,
        Skills:      meta.OrchestratorAction.Skills,
        Instruction: meta.OrchestratorAction.PopulateTemplate(entityKey),
    }
}
```

This method:
- Calls `s.workflowSvc.GetWorkflow()` to get the underlying `*config.WorkflowConfig` (the `GetWorkflow()` method already exists on `workflow.Service` at line 52 of `internal/workflow/service.go`)
- Performs nil checks at every level to prevent panics
- Looks up `StatusMetadata[status]` (a map access, O(1))
- Calls `PopulateTemplate(entityKey)` to replace `{id}` (and other placeholders) with the epic key
- Returns a `*config.PopulatedAction` struct (already defined in `internal/config/action_service.go` at line 32)

#### GetNextStatus Integration

Modify `GetNextStatus` (currently lines 83-104 of `epic_service.go`) to enrich transitions:

```go
func (s *EpicService) GetNextStatus(ctx context.Context, epicKey string) (*NextStatusInfo, error) {
    epic, err := s.repo.GetByKey(ctx, epicKey)
    if err != nil {
        return nil, fmt.Errorf("failed to get epic: %w", err)
    }
    if epic == nil {
        return nil, fmt.Errorf("epic not found: %s", epicKey)
    }

    currentStatus := string(epic.Status)
    transitions := s.workflowSvc.GetTransitionInfo(currentStatus)
    currentMeta := s.workflowSvc.GetStatusMetadata(currentStatus)

    // Enrich transitions with orchestrator actions
    enrichedTransitions := make([]TransitionInfoWithAction, 0, len(transitions))
    for _, t := range transitions {
        enriched := TransitionInfoWithAction{
            TransitionInfo:     t,
            OrchestratorAction: s.resolveAction(epicKey, t.TargetStatus),
        }
        enrichedTransitions = append(enrichedTransitions, enriched)
    }

    return &NextStatusInfo{
        EntityType:           "epic",
        EntityKey:            epicKey,
        CurrentStatus:        currentStatus,
        CurrentPhase:         currentMeta.Phase,
        AvailableTransitions: enrichedTransitions,
        IsTerminal:           s.workflowSvc.IsTerminalStatus(currentStatus),
    }, nil
}
```

This requires T-E16-F02-002 to have already:
- Defined `TransitionInfoWithAction` type in `transition_types.go`
- Changed `NextStatusInfo.AvailableTransitions` from `[]workflow.TransitionInfo` to `[]TransitionInfoWithAction`

### Mock Strategy

The tests need a mock `workflow.Service` that returns a controlled `*config.WorkflowConfig` from `GetWorkflow()`. There are two approaches:

**Option A (Preferred)**: Create a real `workflow.Service` from a test config file with known status metadata including orchestrator actions. Use `workflow.NewService()` pointed at a temp directory with a `.sharkconfig.json` containing the test workflow.

**Option B**: If `workflow.Service` methods cannot be easily mocked (since it is a struct, not an interface), create a minimal `.sharkconfig.json` in a temp directory and construct a real `workflow.Service` that loads it. This is the approach used by existing tests.

The `EpicRepository` interface is already defined in `epic_service.go` (lines 13-16) and is straightforward to mock:
```go
type MockEpicRepository struct {

    UpdateFunc   func(ctx context.Context, epic *models.Epic) error
}
```
