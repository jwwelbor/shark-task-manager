# Task: Expand PopulateTemplate to support entity field placeholders via map-based replacer

## Goal

Replace the hardcoded `strings.Replace` chain in `PopulateTemplate` with a map-based replacer that can substitute any entity field into instruction templates. This allows templates in `.sharkconfig.json` to reference fields like `{title}`, `{file_path}`, `{status}`, `{agent_type}`, etc. -- anything available from `shark task get`. The `{field}` syntax is preserved (no breaking change to template format).

## Requirements

### Functional Requirements

- [ ] FR-1: `PopulateTemplate` accepts a `map[string]string` of placeholder values instead of a single string
- [ ] FR-2: All keys in the map are available as `{key}` placeholders in templates
- [ ] FR-3: Backward compatibility: `{id}`, `{task_id}`, `{epic_id}`, `{feature_id}` continue to work and resolve to the entity key
- [ ] FR-4: New placeholders available for all entity types: `{title}`, `{slug}`, `{status}`, `{file_path}`, `{created_at}`, `{updated_at}`
- [ ] FR-5: Task-specific placeholders: `{agent_type}`, `{priority}`, `{description}`, `{execution_order}`, `{blocked_reason}`, `{depends_on}`, `{completion_notes}`, `{files_changed}`
- [ ] FR-6: Feature-specific placeholders: `{description}`, `{execution_order}`
- [ ] FR-7: Epic-specific placeholders: `{description}`, `{priority}`, `{business_value}`
- [ ] FR-8: Unknown placeholders (not in map) are left as-is in the output (not replaced, not errored)
- [ ] FR-9: `validateTemplateSyntax` updated to accept any `{word}` placeholder without warning (since the known set is now dynamic)
- [ ] FR-10: Provide helper functions to build the placeholder map from each entity type: `TaskPlaceholders(*models.Task) map[string]string`, `FeaturePlaceholders(*models.Feature) map[string]string`, `EpicPlaceholders(*models.Epic) map[string]string`

### Non-Functional Requirements

- [ ] NFR-1: All existing tests continue to pass (with call-site signature updates)
- [ ] NFR-2: No new external dependencies (stdlib `strings` package only)
- [ ] NFR-3: Template resolution remains sub-millisecond for templates up to 2000 chars
- [ ] NFR-4: Zero allocation path for templates with no placeholders

### Technical Approach

**Change 1: New signature**

```go
// Before
func (oa *OrchestratorAction) PopulateTemplate(entityID string) string

// After
func (oa *OrchestratorAction) PopulateTemplate(vars map[string]string) string
```

**Change 2: Map-based replacement loop**

```go
func (oa *OrchestratorAction) PopulateTemplate(vars map[string]string) string {
    result := oa.InstructionTemplate
    for key, value := range vars {
        placeholder := "{" + key + "}"
        result = strings.Replace(result, placeholder, value, -1)
    }
    return result
}
```

**Change 3: Helper functions**

```go
func TaskPlaceholders(task *models.Task) map[string]string {
    m := map[string]string{
        "id":              task.Key,
        "task_id":         task.Key,
        "epic_id":         task.Key,  // backward compat alias
        "feature_id":      task.Key,  // backward compat alias
        "title":           task.Title,
        "slug":            task.Slug,
        "status":          string(task.Status),
        "file_path":       task.FilePath,
        "agent_type":      task.AgentType,
        "priority":        fmt.Sprintf("%d", task.Priority),
        "execution_order":  fmt.Sprintf("%d", task.ExecutionOrder),
        "description":     task.Description,
        "created_at":      task.CreatedAt.Format(time.RFC3339),
        "updated_at":      task.UpdatedAt.Format(time.RFC3339),
    }
    if task.BlockedReason != "" {
        m["blocked_reason"] = task.BlockedReason
    }
    if task.DependsOn != "" {
        m["depends_on"] = task.DependsOn
    }
    if task.CompletionNotes != "" {
        m["completion_notes"] = task.CompletionNotes
    }
    if task.FilesChanged != "" {
        m["files_changed"] = task.FilesChanged
    }
    return m
}
```

Similar patterns for `FeaturePlaceholders` and `EpicPlaceholders`.

**Change 4: Call site updates**

```go
// task_repository.go (has full task object)
instruction := metadata.OrchestratorAction.PopulateTemplate(config.TaskPlaceholders(task))

// epic_service.go (needs epic object -- resolveAction already called with entityKey,
// but the caller has the epic; pass it through or change resolveAction signature)
instruction := meta.OrchestratorAction.PopulateTemplate(config.EpicPlaceholders(epic))

// feature_service.go (same pattern)
instruction := meta.OrchestratorAction.PopulateTemplate(config.FeaturePlaceholders(feature))
```

The `resolveAction` methods in epic_service.go and feature_service.go currently only receive `entityKey string`. They'll need to receive the full entity object (or the pre-built map) so the template can access all fields. This is a minor refactor of the `resolveAction` signature.

**Change 5: Validation update**

`validateTemplateSyntax` should stop warning about "unknown" placeholders since the known set is now dynamic. It should only warn about:
- Malformed placeholders (unclosed braces)
- Templates exceeding 2000 char limit
- Templates with no `{...}` placeholder at all

## Notes

- Approach 1 (map-based replacer) chosen over Go `text/template` to preserve the existing `{field}` syntax and avoid a breaking change to `.sharkconfig.json` template format.
- Unknown placeholders are left as-is rather than errored, so templates can contain literal `{text}` if needed.
- The iteration order of Go maps is random, but this doesn't matter since no placeholder is a substring of another when wrapped in braces.
- Task-sized M due to the call-site refactoring needed in epic_service and feature_service.
