# Task: Add resolveAction to FeatureService and integrate into transitions

## Goal

Add orchestrator action resolution to `FeatureService` so that when a feature transitions status, the response includes the orchestrator action defined for the new status. This is the feature-level counterpart of T-E16-F02-003 (EpicService) and follows the identical pattern.

After this task, calling `featureSvc.TransitionStatus(ctx, "E16-F01", "ready_for_refinement_tech", false)` returns a `TransitionResult` that includes the populated `OrchestratorAction` (if one is configured for `ready_for_refinement_tech` in the feature workflow). Calling `featureSvc.GetNextStatus(ctx, "E16-F01")` returns available transitions enriched with per-status orchestrator actions.

## Requirements

### Functional Requirements

### Technical Approach

**`resolveAction` method** (identical pattern to `EpicService.resolveAction` from T-E16-F02-003):

```go
// resolveAction looks up and populates the orchestrator action for a status.
// Returns nil if no action is defined (not an error).
func (s *FeatureService) resolveAction(entityKey string, status string) *config.PopulatedAction {
    wf := s.workflowSvc.GetWorkflow()
    if wf == nil || wf.StatusMetadata == nil {
        return nil
    }

    meta, exists := wf.StatusMetadata[status]
    if !exists || meta.OrchestratorAction == nil {
        return nil
    }

    return &config.PopulatedAction{
        Action:      meta.OrchestratorAction.Action,
        AgentType:   meta.OrchestratorAction.AgentType,
        Skills:      meta.OrchestratorAction.Skills,
        Instruction: meta.OrchestratorAction.PopulateTemplate(entityKey),
    }
}
```

**`TransitionStatus` modification** -- add two lines before the return:

```go
// After: feature.Status = models.FeatureStatus(targetStatus) and s.repo.Update(...)

// Resolve orchestrator action for the new status
action := s.resolveAction(featureKey, targetStatus)

return &TransitionResult{
    EntityType:         "feature",
    EntityKey:          featureKey,
    FromStatus:         currentStatus,
    ToStatus:           targetStatus,
    Transitioned:       true,
    OrchestratorAction: action,
}, nil
```

**`GetNextStatus` modification** -- replace direct `transitions` usage with enriched slice:

```go
transitions := s.workflowSvc.GetTransitionInfo(currentStatus)

// Enrich transitions with orchestrator actions
enrichedTransitions := make([]TransitionInfoWithAction, 0, len(transitions))
for _, t := range transitions {
    enriched := TransitionInfoWithAction{
        TransitionInfo:     t,
        OrchestratorAction: s.resolveAction(featureKey, t.TargetStatus),
    }
    enrichedTransitions = append(enrichedTransitions, enriched)
}

return &NextStatusInfo{
    EntityType:           "feature",
    EntityKey:            featureKey,
    CurrentStatus:        currentStatus,
    CurrentPhase:         currentMeta.Phase,
    AvailableTransitions: enrichedTransitions,
    IsTerminal:           s.workflowSvc.IsTerminalStatus(currentStatus),
}, nil
```

**Key design decisions:**
- The `resolveAction` method is private because it is an internal implementation detail
- The method mirrors `EpicService.resolveAction` exactly -- if future refactoring extracts it to a shared helper, the signatures are already identical
- Nil safety is handled at every level: nil workflow, nil `StatusMetadata` map, missing status key, nil `OrchestratorAction` pointer

## Notes

- This task is intentionally identical in structure to T-E16-F02-003 (EpicService). The only differences are: entity type is "feature" instead of "epic", the service is `FeatureService` instead of `EpicService`, and the repository interface is `FeatureRepository` instead of `EpicRepository`. If both tasks are completed, a future refactoring could extract a shared `resolveAction` function.
- The `PopulateTemplate` call passes the feature key (e.g., "E16-F01") which replaces `{id}`, `{feature_id}`, `{task_id}`, and `{epic_id}` uniformly. Since this is a feature-level workflow, `{id}` and `{feature_id}` are the semantically correct placeholders for template authors.
- The `GetNextStatus` change requires updating the return type of `AvailableTransitions` from `[]workflow.TransitionInfo` to `[]TransitionInfoWithAction`. This type change is made in T-E16-F02-002 (the `NextStatusInfo` struct update). This task only uses the new type.
