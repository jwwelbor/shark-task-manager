# TD-132 research report

## Scope

Verify whether the live lifecycle producer still omits the content-root
identity needed by the evaluator's independent content-digest crosscheck.

- [x] `affected_implementation_or_contract` — Evidence: bench/scripts/run-lifecycle.sh
- [x] `pattern_contract` — Evidence: bench/scripts/evaluate-lifecycle.sh; bench/scripts/tests/tc116_content_identity_crosscheck_test.sh
- [x] `dependency_impact` — Evidence: docs/plan/E40-shark-bench-workflow-benchmarking-harness/E40-F12-live-i-05-evidence-bundle-producer-for-lifecycle-v/spec.md

## Findings

T-E40-F12-005 has already remediated the reported producer gap.
`scenario_identity()` in `run-lifecycle.sh` declares the installed
scratch-project `shark-data` directory as `content_root`, marks the scheme as
`walk_v1`, and computes `shark_content_digest` using the same deterministic
walk algorithm as `evaluate-lifecycle.sh`.

The evaluator independently derives the digest when a content root is
declared and records an identity mismatch if it differs. TC-116 drives a
live lifecycle dispatch against a copied canonical content tree. It verifies
the matching case, a legacy-shaped record with both `content_root` and
`content_digest_scheme` absent, and a post-run byte corruption that must
trigger the mismatch. The absent content root prevents the legacy record's
crosscheck; the scheme marker records provenance but is not itself evaluated
as a compatibility gate.

TC-116 requires the scenario's admitted `fixture.base_sha`. This review ran
the test at that detached fixture revision (`964fa68e`), where all cases
passed, then restored the worktree's older repository-pinned submodule
revision. Running it at the repository pin correctly fails the runner's
fixture-root verification before dispatch rather than weakening that
provenance gate.

The remaining documented limitation is operational: a scratch project that
does not contain installed Shark data has an empty-tree digest. Provisioning
that scratch-project prerequisite is outside TD-132's resolved producer and
evaluator contract.

| Live end-to-end regression coverage | REUSE | `tc116_content_identity_crosscheck_test.sh` |

## Decisions

No implementation change is required. TD-132 is resolved by the existing
T-E40-F12-005 implementation and TC-116 regression coverage. Preserve the
`walk_v1` marker as producer provenance; legacy-shaped records do not enter
the crosscheck because they lack a declared content root.
