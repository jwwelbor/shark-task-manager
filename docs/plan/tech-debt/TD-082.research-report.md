# TD-082 research report

## Scope

TD-082 concerns interpreter-specific bytecode generated beside the E40-F03
fixture helper, `bench/scripts/testdata/aggregate/gen_fixtures.py`. The debt
record says that the first E40-F03 commit tracked
`__pycache__/gen_fixtures.cpython-312.pyc` and requires Git to stop tracking
that generated file while ignoring future Python caches and `.pyc` files.

The affected capability is test-fixture generation for the E40-F03 aggregate
and replay tests. The generator must remain committed and runnable; only its
generated Python bytecode is out of scope. This is a repository-hygiene repair,
not a change to the generator's fixture contract or test behavior.

The authoritative entity has `docs/plan/tech-debt/TD-082.md` as its stored file
path, but that file is absent in this worktree. The entity description returned
by `shark get TD-082 --json` supplies the original finding and acceptance
criteria.

## Findings

1. **The original defect was real.** Commit `efd16c8b` added both the Python
   generator and `bench/scripts/testdata/aggregate/__pycache__/gen_fixtures.cpython-312.pyc`.
   The latter is generated, interpreter-specific output and does not belong in
   the source contract.

2. **The required remediation already exists on the current branch.** Commit
   `54529025` adds the repository-specific Python cache rules to `.gitignore`.
   `git check-ignore -v` resolves both a nested `__pycache__` bytecode path and
   a `.pyc` file to those rules. `git ls-files --error-unmatch
   bench/scripts/testdata/aggregate/__pycache__/gen_fixtures.cpython-312.pyc`
   exits with status 1, proving Git no longer tracks the reported file.

3. **The remediation preserves the E40-F03 capability.** The same current
   commit contains `gen_fixtures.py`, while the E40-F03 task and test plan bind
   its generated records to the `tc018` and `tc019` suites. Ignoring bytecode
   does not change the script, its golden-derived inputs, or those consumers.

4. **No replacement implementation is needed.** The existing `.gitignore`
   rules cover the exact required paths throughout the repository. Adding a
   generator-local ignore file or changing Python invocation would duplicate
   established repository behavior without improving the contract.

5. **Related-document registration is not supported for tech-debt entities.**
   `shark related-docs add --help` exposes epic, feature, task, bug, change,
   and question flags, but no tech-debt flag. Registering this sidecar would
   require unrelated CLI capability work, so the report remains discoverable
   through the entity's standard sidecar path.

## Decisions

1. Treat TD-082 as already remediated by commit `54529025`; do not make a
   duplicate `.gitignore` change or alter `gen_fixtures.py`.
2. Retain both `.gitignore` rules: `__pycache__/` prevents cache-directory
   churn and `*.pyc` covers standalone bytecode files.
3. Use the two Git checks in Finding 2 as the completion evidence: the paths
   must be ignored and the reported bytecode file must not be tracked.
4. Do not register a fake related-document link. Extending `related-docs` to
   tech-debt entities is outside TD-082.

**Recommended outcome: pass.** The requested source-control state already
exists and has been verified against the current worktree.
