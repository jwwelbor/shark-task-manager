# TD-215 research report — synced temporary candidate files

## Scope

TD-215 removes the duplicated write, sync, close, and cleanup sequence used
for candidate publication and archived candidate heads. It leaves CAS,
archiving order, and publish behavior unchanged.

## Research checklist

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-215.md`
- [x] `affected_implementation_or_contract` — Evidence: `internal/integration/candidate.go:203-277,335-374`
- [x] `pattern_contract` — Evidence: `internal/integration/candidate_test.go`; `internal/integration/publish.go`

## Findings

`attemptUpdateCandidate` and `archiveCandidateHead` repeat the same
crash-safety sequence. Their callers own different publish semantics, but
temporary-file durability and cleanup are identical.

### Capability map

| Capability | Decision | TD-215 action |
|---|---|---|
| Synced private-file write | EXTEND | Share one helper that removes partial files on failure. |
| Candidate CAS and archive ordering | REUSE | Retain in existing callers. |

## Decisions

1. Extract `writeTempFileSynced(path, data)` with cleanup on every failure.
2. Keep caller-level error context and all post-write link/rename behavior.
