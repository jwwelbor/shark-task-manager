# Consolidate .sharkconfig.json read/write via config.Manager.SaveRaw

## Description

internal/cli/commands/sharkdata_cmd.go:177-204 (ensureWorkflowConfigField) does os.ReadFile -> json.Unmarshal into map[string]interface{} -> json.MarshalIndent -> os.WriteFile for .sharkconfig.json. This duplicates the round-trip pattern already implemented in internal/config/manager.go, where Manager.Load() preserves a RawData map[string]interface{} for unknown keys.

Fix: extend config.Manager with a SaveRaw() method (or expose RawData mutation + a Save call), then route all .sharkconfig.json read-modify-write through the single helper. Surfaced during simplify review of commit 6492e45.

## Impact

Two independent code paths now read/modify/write `.sharkconfig.json`. They can diverge on indentation, key ordering, or handling of unknown fields. The bespoke path in `sharkdata_cmd.go` re-implements behavior `config.Manager` already provides, so future changes to round-trip semantics must be made in two places.

## Resolution Plan

- Add `Manager.SaveRaw(path string) error` (or `Manager.WithRawMutation(fn func(map[string]interface{})) error`) in `internal/config/manager.go`.
- Refactor `ensureWorkflowConfigField` in `internal/cli/commands/sharkdata_cmd.go` to call the new helper.
- Grep for other call sites doing direct `os.ReadFile` / `json.Marshal` on `.sharkconfig.json` and route them through `Manager` as well.
