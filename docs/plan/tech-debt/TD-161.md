# Sprint admission mutation methods bypass compile-time repository interface, plus untested override/goal-review branches

## Description

AddAssignmentTx, CreateAdmissionOverrideTx, CreateGoalReviewTx, and GetLatestGoalReviewTx are only reachable via local runtime type assertions (sprintAdmissionMutationRepository, sprintGoalReviewRepository in internal/services/sprint_service.go) instead of being declared on the primary SprintRepository interface like the other new methods added in the same change (GetEpicIDByKey, GetFeatureIDByKey, ListActiveAdmissionOverrides). Promote all four to SprintRepository for compile-time safety and drop the local type-assertion interfaces and their "not configured" runtime error branches (which can never legitimately trigger against the shipped repository).

While closing the deep-review blocker for the override transaction path, MockSprintRepository gained AddAssignmentTx/CreateAdmissionOverrideTx test doubles and one AddEntityToSprint override-path test, but the following remain untested:
- BulkAddToSprint's per-candidate blocked/override handling (skip without override reason; delegate-to-AddEntityToSprint with a valid reason)
- SubmitSprintGoalReview's field/outcome validation error branches
- filterSprintPlanAdmission's override-application branch (PlanSprint) specifically, vs. the structurally identical branch already covered elsewhere

Found by /shark-rider deep-review high on E19 (angles B and E, non-blocker).
