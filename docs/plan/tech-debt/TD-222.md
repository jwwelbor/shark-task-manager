# Gate ingestion kickback cannot reopen a task already at a terminal status

## Description

gatepersist.applyKickback (internal/gatepersist/coordinator.go) builds TransitionOptions without Force:true. Task workflow routes a 'pass' outcome from development straight to the terminal 'completed' status. A feature-level gate step whose fail outcome has role kickback_rework (e.g. code_review) can target such an already-completed task with a kickback, but the ingestion's own Transition call then fails with 'cannot transition from completed (terminal status)', because gatepersist never passes --force. Worked around manually during E40-F12's code_review kickback to T-E40-F12-006 via 'shark status set <key> <status> --force' before retrying --apply-result with the same run_id. gatepersist should probably force kickback transitions targeting a terminal status (or provide an explicit override path) rather than requiring a manual pre-step outside the ingestion boundary.
