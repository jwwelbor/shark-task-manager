# plan.go duplicates three next.go resolvers and has already drifted

## Description

internal/cli/commands/plan.go:596,831,867 — resolvePlanEntity, autoAdvancePlanCascadeParent and applyPlanWireAction are near-verbatim copies of resolveNext, autoAdvanceCascadeParent and applyWireAction in next.go, differing only in recursion target and cache type. planAdapterCache embeds nextAdapterCache, so the type is not a barrier.

Already drifted on day one: next.go:422 emits the B022 unknown-status warning to stderr; plan.go:645 sets the same resp.Error with no warning, so 'shark plan' silently swallows a diagnostic that 'shark next' surfaces.

gocyclo: resolveNext 20, resolvePlanEntity 19. Bodies differ by ~3 lines out of ~80.

Fix: parameterize one resolver with a cascade strategy (a cascadeFn parameter or an enum on the shared cache), deleting both copies and the drift class with them.

Source: /shark-rider deep-review high on PR #139 (finding N3).
