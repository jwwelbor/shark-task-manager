# TD-055 research report

## Scope

Replace the HTTP Question error-message substring classifier with typed business-rule errors while retaining the existing 400/409 response contract.

## Findings

`questionErrorStatus` currently maps ten conflict and nine validation fragments after `err.Error()` rendering. The originating errors are concentrated in Question workflow operations: configuration, response recording, resolution destination validation, and terminal operations. Their existing contextual `%w` wrapping is compatible with `errors.Is`/`errors.As` once the leaf business errors are typed.

The present test constructs arbitrary messages, so it proves phrase matching rather than the service/API contract. The replacement must create real typed errors at each classified rejection and assert the same HTTP status through wrapped errors.

## Decisions

Introduce a small typed Question rule-error contract carrying HTTP class (conflict or bad request), replace every currently classified leaf error with it, and have `questionErrorStatus` inspect the typed contract with `errors.As`. Preserve the generic not-found and unexpected-error handling outside this scope.
