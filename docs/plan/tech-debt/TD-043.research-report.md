# Research report — Portfolio Advise has two implementations and the dead one owns the tests

## Scope

This report covers the construction and execution paths of
`PortfolioAdviceService.Advise`, their production callers, and the tests that
claim the portfolio-advice service contract. The affected capability is the
read-only portfolio evidence assembly used by bare `shark plan`: it loads one
portfolio snapshot, applies the configured active-claim policy, classifies
workflow state, and returns a deterministic advice envelope.

The proposed remediation replaces the legacy multi-reader service path with the
already-shipped `PortfolioSnapshotSource` path. It does not replace the advice
envelope, graph analysis, workflow classification, claim-expiry policy, or
portfolio repository.

Shared vocabulary:

- **Legacy path**: `NewPortfolioAdviceService` plus the `Advise` branch that
  calls `listPortfolioEpics` and `readPortfolioAdviceEvidence`.
- **Production path**: `NewPortfolioAdviceServiceFromSnapshot` plus
  `adviseFromSnapshot`, as wired by `cli.GetPortfolioAdviceService`.
- **Snapshot source**: the single dependency that returns epics, descendants,
  relationships, and claims as `portfolio.Snapshot`.
- **Claim filter**: the no-I/O expiry policy applied to claims already present
  in the snapshot.
- **Shipped path**: the constructor and `Advise` branch reached from bare
  `shark plan`, not merely a path available to tests.

## Findings

1. **Production has already selected one implementation, but the service still
   carries two dependency graphs.** `cli.GetPortfolioAdviceService` constructs
   only `NewPortfolioAdviceServiceFromSnapshot`, and bare `shark plan` calls
   that service through `portfolioAdvisor.Advise`. The legacy constructor has
   no non-test caller. The six service fields are split by mode: the legacy
   constructor leaves `snapshotSource` and `claimFilter` nil, while the
   production constructor leaves `epics`, `snapshot`, and `claims` nil. Five
   fields are therefore mode-specific, and the nil check in `Advise` chooses
   behavior.

2. **The service unit suite exercises the unshipped branch.** All ten
   `NewPortfolioAdviceService` construction sites in
   `internal/services/portfolio_advice_service_test.go` use separate epic,
   child/relationship, and claim fakes. None reaches
   `PortfolioSnapshotSource.ReadSnapshot` or the production
   `PortfolioClaimFilter.FilterActiveReadOnly` call. Production-constructor
   coverage currently lives in the repository integration fixture and the CLI
   global-wiring smoke test, so detailed envelope behavior and failure cases are
   asserted against a different ingestion path from the one shipped.

3. **The two paths expose different failure contracts, not merely different
   query counts.** The legacy path can preserve partial evidence because
   `portfolioAdviceReads` records independent child, relationship, and claim
   errors. The production snapshot source returns one `Snapshot` or one error,
   so a snapshot read failure is fatal and the partial-evidence fields are never
   populated on the shipped path. In particular,
   `TestPortfolioAdviceServicePartialEvidenceDecisionTable` protects behavior
   that production cannot produce. Repointing tests therefore requires an
   explicit choice to align them to the shipped all-or-nothing snapshot
   contract; mechanically wrapping the old fakes would retain a false contract.

4. **The escaped claim-heartbeat blocker now has production-path remediation.**
   The fix originally recorded as commit `e4e29432` is present in the current
   PR #139 squash (`2a5719e0`): `portfolio.Repository.listSnapshotClaims`
   normalizes persisted SQLite timestamps to RFC 3339 UTC.
   `TestReadSnapshot_DecodesClaimWrittenByProductionClaimPath` seeds a claim
   through the real claim repository, and
   `TestReadSnapshot_ReturnsPortfolioWideRowsWithoutEpics` also covers the
   normalized claim read after the portfolio-wide queries were separated.
   These repository tests are the correct boundary for the storage-format
   defect and must remain.

5. **The original E36-F04 specification now contradicts the shipped service
   dependency contract.** Its service table names
   `NewPortfolioAdviceService(epics, snapshot, claims, workflows)` and describes
   independent partial reads. PR #139 introduced the production snapshot source
   and claim filter without replacing that text. Deleting the legacy
   implementation makes the code honest but leaves the accepted design
   misleading unless the constructor and failure semantics are updated there
   too.

6. **The remediation can stay bounded.** The shared
   `assemblePortfolioAdvice` and all graph, classification, sanitization, and
   prompt behavior are already downstream of both paths. The change only needs
   to remove the legacy service interfaces, constructor, mode-specific fields,
   branch, and read helpers; make the snapshot path unconditional; and move the
   detailed unit fixtures to a fake `PortfolioSnapshotSource` plus a claim
   filter. `ClaimService.ListActiveReadOnly` has its own tests and need not be
   removed merely because portfolio advice stops calling it.

## Decisions

1. Delete `NewPortfolioAdviceService` and retain
   `NewPortfolioAdviceServiceFromSnapshot` as the sole constructor. Do not add a
   compatibility wrapper: the only callers of the old constructor are the tests
   that caused this debt.
2. Reduce `PortfolioAdviceService` to `snapshotSource`, `claimFilter`, and
   `workflows`; remove `PortfolioAdviceEpicReader`,
   `PortfolioAdviceSnapshotReader`, `PortfolioAdviceClaimReader`,
   `listPortfolioEpics`, `readPortfolioAdviceEvidence`, and the
   `snapshotSource != nil` mode switch.
3. Make `Advise` execute the snapshot path unconditionally. Keep
   `assemblePortfolioAdvice` and the existing workflow/context checks as the
   shared behavioral core.
4. Replace the three service fakes with a fake `PortfolioSnapshotSource` that
   returns a complete `portfolio.Snapshot` or an error. Use a real or focused
   fake `PortfolioClaimFilter` so service tests assert the production filtering
   seam.
5. Retire the legacy per-component partial-read cases rather than encoding
   unreachable production behavior. Replace them with snapshot-read error,
   context cancellation, missing-workflow, active/expired-claim, and complete
   snapshot cases through the sole constructor.
6. Preserve the repository integration tests for production-written claim
   timestamps, portfolio-wide rows without epics, deterministic snapshots, and
   target-scale reads. They complement rather than duplicate service-unit
   coverage.
7. Update the E36-F04 service-contract text in the implementation change so it
   no longer advertises the removed constructor or independent partial-read
   semantics.
