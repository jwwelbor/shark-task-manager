# TD-123 research report — F06 evidence-root scan hardening

## Scope

Confirm whether the frozen F06 evidence-root verifier still has the reported
`.git` traversal and scan-error gaps. Identify the smallest proven repair
without changing F06's root vocabulary or match-priority contract.

## Findings

TD-123 remains relevant. F06 still excludes every `.git` directory in
`walk_files`, so a reachable disclosure copy below that directory is not
examined. `check_root` also catches `OSError` while opening a file and
continues, which can return `CLEAN` after an incomplete scan.

F07 already implements the required fail-closed design. Its iterative walker
does not treat `.git` as a trust boundary, tracks resolved directory inode
pairs to prevent symlink cycles, and raises `ScriptError` when it cannot stat,
list, or read a scan path. TC-056 proves `.git` disclosure detection and
unreadable directory/file failures.

### Capability map

| Capability | Decision | TD-123 action |
|---|---|---|
| F06 root vocabulary and target matching | REUSE | Preserve the existing F06 root names and match ordering. |
| F07 iterative fail-closed walker | EXTEND | Port the bounded walker and error behavior to F06 without coupling the scripts. |
| F07 disclosure tests | EXTEND | Add equivalent F06 fixtures for `.git` copies and unreadable paths. |

## Decisions

1. Keep TD-123 active; the affected F06 code is still present on current `main`.
2. Implement the proven F07 walk/error pattern in F06 as a separate hardening
   change. Do not change F06's package parsing, root vocabulary, or target
   priority while doing so.
3. Add F06 regression coverage before closing the debt. The expected result
   for an unreadable scan path is a fail-closed script error, never `CLEAN`.
