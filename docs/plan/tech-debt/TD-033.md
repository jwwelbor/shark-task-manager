# Collapse duplicate workflow-source resolution in defaultWorkflowDataLoader

## Description

defaultWorkflowDataLoader (internal/config/aliases.go) duplicates the index/directory/JSON/inline source resolution already performed by LoadMultiLevelWorkflowFromBytes (internal/config/workflow/parser.go). Its Pass 1 (LoadMultiLevelWorkflowFromYAMLDir) and the master-index detection block both re-implement resolution that Pass 2 (LoadMultiLevelWorkflowOrDefaultFromBytes) already does. This shotgun-surgery split caused a real bug: the E35-F04 master-index (entities:) feature was wired into the parser path with tests but silently missed in the ActionService loader, so workflow_config pointing at a master index file (e.g. route/workflow.yaml) was rejected as 'Shark 1.x JSON'. Fixed for now by patching index handling into the second loader too — which deepens the duplication. Proper fix: collapse defaultWorkflowDataLoader to call the strict parser variant (LoadMultiLevelWorkflowFromBytes) as the single source of truth for source resolution, project the resulting MultiLevelWorkflow into the status->orchestrator-action map, and fill empty entity slots with defaults. Keep ONLY the loud legacy-JSON rejection policy (B020) that the parser's swallow-errors OrDefault variants do not provide. Removes Pass 1 and the new index block. Hot path with dense regression history (B020 silent-misroute, B026 partial-YAML-failure, TD-023 single-read, TD-024 debug logging) — needs careful re-validation against all of those. Related to E35 route-based workflow. New test added in this session: internal/config/workflow_index_loader_test.go.
