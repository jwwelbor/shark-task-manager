# evaluate-lifecycle.sh leaves stale oracle.json on disk after JSON-decode failure

## Description

On json.JSONDecodeError reading back the oracle subprocess's own output file (evaluate-lifecycle.sh:723-733), a synthetic not_run result is built in memory but persist_synthetic_oracle() is never called on this path (the malformed file still passes isfile()). The stale/corrupt oracle.json is left on disk and copied verbatim into retained evidence by retain_pair, disagreeing with the not_run verdict actually recorded in evaluation.jsonl. Fix: call persist_synthetic_oracle unconditionally on the except branch. Found in code review of PR #219 (B064).
