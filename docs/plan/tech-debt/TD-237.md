# Document or guard shark next stream separation when stderr merged with JSON stdout

## Description

Unresolved placeholder warnings ([shark-stats] WARN: ... has N unresolved placeholders) are emitted to stderr by next.go:1509 per E32-F07 REQ-F-003. When harnesses, subshells, or pipes merge stderr (2>&1) into stdout, strict JSON parsers fail. Needs documented guidance or resilient JSON extraction support.

## Impact

`shark next <key> --json` is the sole canonical keyed dispatch API in Shark 2.x. While JSON is emitted strictly on stdout and `[shark-stats] WARN:` warnings are emitted on stderr (`internal/cli/commands/next.go:1509`), automated runners, test harnesses, or subshells that combine stdout and stderr (`2>&1`) suffer parse errors when piping directly into strict JSON decoders (e.g. `python3 -c "import sys, json; json.load(sys.stdin)"`).

## Resolution Plan

1. Document the stream contract in `docs/architecture/shark-rider-dispatch-prompt-assembly.md` and CLI references: callers must keep stderr and stdout separated, or extract JSON beginning at the first `{`.
2. Consider adding an optional flag (or verifying global `--quiet`) to suppress diagnostic stderr logging during automated harness execution when stderr cannot be easily redirected.
