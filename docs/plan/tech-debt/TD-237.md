# Document or guard shark next stream separation when stderr merged with JSON stdout

## Description

Unresolved placeholder warnings ([shark-stats] WARN: ... has N unresolved placeholders) are emitted to stderr by `internal/cli/commands/next.go:1511` per E32-F07 REQ-F-003. When harnesses, subshells, or pipes merge stderr (`2>&1`) into stdout, strict JSON parsers fail. Needs documented guidance or resilient JSON extraction support.

## Impact

`shark next <key> --json` is the sole canonical keyed dispatch API in Shark 2.x. While JSON is emitted strictly on stdout and `[shark-stats] WARN:` warnings are emitted on stderr (`internal/cli/commands/next.go:1511`), automated runners, test harnesses, or subshells that combine stdout and stderr (`2>&1`) suffer parse errors when piping directly into strict JSON decoders (e.g. `python3 -c "import sys, json; json.load(sys.stdin)"`).

## Resolution Plan

1. Document the stream contract in `docs/architecture/shark-dispatch-prompt-assembly.md` and the CLI JSON-output reference: `shark next <key> --json` writes the complete response to stdout and warnings or diagnostics to stderr. Automation must keep the streams separate, parse stdout, and avoid merging them with `2>&1`.
2. Preserve the E32-F07 stderr warning and the structured `unresolved_placeholders` JSON field. Do not suppress the warning without revising that requirement.

## Resolution Notes
