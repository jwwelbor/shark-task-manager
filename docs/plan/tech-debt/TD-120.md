# UAT prompt template requests a qa-*.md artifact that STANDARD/SIMPLE-tier features never produce

## Description

The approval/UAT dispatch prompt's READ step always instructs the reviewer to read docs/review/.../qa-*-<feature>.md, but the code-review workflow's own phase contract states there is no separate QA pass for SIMPLE/STANDARD tier -- code review performs Parts 1-4 as the single same-model gate, and the qa feature-status transition is COMPLEX-tier only. This caused UAT (codex) to flag 'missing required QA artifact' as a blocking HIGH finding across 3 rounds of E40-F06's UAT, even after an explicit inline correction in round 3's prompt was ignored. Fix: make the UAT prompt template's READ step conditional on complexity_tier, or drop the qa-*.md reference entirely for SIMPLE/STANDARD tier features.

## Impact

Every future SIMPLE/STANDARD-tier feature's UAT gate will spuriously flag a missing QA artifact, costing an unnecessary rejection round each time unless manually caught.

## Resolution Plan

Locate the embedded UAT/approval prompt template (internal/sharkdata/default_data/...); gate the qa-*.md READ instruction on complexity_tier == COMPLEX, or move it into a COMPLEX-only variant of the prompt.
