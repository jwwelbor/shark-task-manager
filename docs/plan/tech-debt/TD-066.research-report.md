# TD-066 research report

## Scope

Keep an explicit task dependency clear synchronized across the legacy `tasks.depends_on` column and task-to-task `entity_relationships` dependency gates.

- [x] `dependency_impact` — Evidence: `internal/repository/task/dependency.go:607-665` reads both stores before unblocking; stale relationship rows remain a live gate.

## Capability map

| Capability | Decision |
| --- | --- |
| Explicit `ClearDependsOn` | EXTEND with a transactional relationship cleanup path. |

## Findings

Task updates preserve the loaded legacy dependency JSON for ordinary edits, so repository code cannot infer that a nil value means a user requested clearing. Clearing every relationship on a nil model would destroy independently created links during unrelated title/status updates. The service already carries this intent in `TaskUpdates.ClearDependsOn`.

## Decisions

Route only explicit clears through `UpdateClearingDependencies`, which updates the task and deletes outgoing task-to-task `depends_on` rows in one transaction. Preserve ordinary update behavior. Add service routing and database regression coverage for a link-created dependency.
