# epic/integration_review.md prompt step 5 points at an always-empty-in-steady-state event field instead of the populated candidate-level digests

## Description

Step 5 of the new final-integration-review prompt (internal/sharkdata/default_data/prompts/epic/integration_review.md:16) tells the reviewing agent to compute diff evidence from 'every untracked path recorded across the candidate's events' -- but IntegrationEvent.TrackedPaths/UntrackedPaths (event.go) is nil at feature_service.go's steady-state call site (integration.RecordEvent(run.EpicRunID, featureKey, commit, nil, nil), the call that fires on every ordinary feature completion). The data that's actually populated lives one level up on IntegrationCandidate.TrackedPathDigests/UntrackedPathDigests (candidate.go), which step 2 of the same prompt already tells the reviewer to read but step 5 never names. Not literally always nil: backfill.go passes through caller-supplied backfill events' TrackedPaths/UntrackedPaths, so a backfill-seeded run's events can carry this data -- but the claim holds for the steady-state (non-backfill) path this gate reviews during ordinary epic execution. Fix: reword step 5 to reference the candidate's own tracked_path_digests/untracked_path_digests fields in addition to any event-level paths where present (backfill-seeded runs), not instead of. From code-review of the E34 (F06-F11) integration diff, finding F8 (non-blocker: low-frequency, AI-agent-executed review-gate instruction gap, potentially silent).
