# Sprint admission override has correctness gaps: lost update-timestamp divergence and no removal lifecycle

## Description

Two related gaps found in the roadmap admission override path (internal/repository/sprint/repository.go, internal/services/sprint_service.go):

1. AddAssignment always sets assigned_at=time.Now().UTC(); AddAssignmentTx uses the caller-supplied assignment.AssignedAt instead. AddEntityToSprint's override branch calls AddAssignmentTx, so overridden vs non-overridden admission for otherwise-identical inputs can get different assigned_at semantics. Pick one policy and apply it in both paths.

2. sprint_admission_overrides has a UNIQUE(sprint_id, entity_type, entity_id) constraint with no removed_at/soft-delete column, and RemoveAssignment never touches it. Overriding a blocked entity, removing it from the sprint, then re-adding it while still blocked will hit the UNIQUE constraint on CreateAdmissionOverrideTx instead of succeeding. Either void the prior override row on assignment removal, or make CreateAdmissionOverrideTx an upsert.

Found by /shark-rider deep-review high on E19 (angle B, non-blocker).
