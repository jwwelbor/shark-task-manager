# TD-080 research report

## Scope

Prevent a rerun from mixing a prior crashed attempt's artifacts with a new record.

## Research checklist

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-080.md`; `bench/scripts/run-one.sh:190-200`.
- [x] `affected_implementation_or_contract` — Evidence: `bench/README.md:279-320` documents one record per deterministic run directory.
- [x] `pattern_contract` — Evidence: `bench/scripts/tests/tc014_run_one_smoke_test.sh:72-150` already rejects an existing final record.

## Findings

The old guard looked only for `record.jsonl`; stale `run/` or `post/` outputs from a failed attempt were silently reused.

## Decisions

Reject every non-empty deterministic run directory before provisioning. An empty directory remains usable; destructive replacement is deliberately not implicit.
