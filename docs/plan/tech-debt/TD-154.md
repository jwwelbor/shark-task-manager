# B054 .git validation: type-check HEAD/objects, add cross-copy parity guard

## Description

From B054 code review, second pass (docs/review/bugs/b054/code-review-20260828-0144-B054.md), non-blocking findings on the .git marker validation fix (commits 6542b9a2, 447261f4):

O1: HEAD/objects/ are existence-checked but not type-checked, so a directory named "HEAD" inside .git (or a file named "objects") would still be accepted as valid -- a contrived edge case, identical in both the internal/cli and internal/dbinit copies, not a regression from B058's fix class but worth a follow-up stat-type check.

O2: There is no cross-copy parity guard between internal/cli/root.go's findProjectRootFrom and internal/dbinit/project_root.go's findProjectRoot -- exactly the gap that let the first B054 pass fix only one of the two independent .git-detection copies silently, requiring a second review round to catch. Recommend either extracting a genuinely shared helper (if package boundaries allow), or a test that asserts the two implementations produce identical results for a matrix of fixture cases, so future changes to one can't silently diverge from the other again.

O3: trailing whitespace in docs/plan/bugs/B054.research-report.md -- cosmetic, worth a lint pass on next touch.
