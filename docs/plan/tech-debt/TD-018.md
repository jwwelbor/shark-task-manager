# Extract shared validateEntityMap helper to dedupe action/service.go ValidateActions

## Description

internal/config/action/service.go has near-identical validation logic in two places:

- service.go:266-298 — ValidateActions (root)
- service.go:367-396 — entityActionView.ValidateActions

The view variant just drops the 'entityType:' prefix from error-key strings; the per-status / per-action validation loop body is otherwise identical.

Fix: extract a shared validateEntityMap(entityType string, entityMap map[string]Action, qualifyKeys bool) helper. Both callers reduce to one line.

Surfaced during simplify review of commit 6492e45.

## Impact

Two parallel validators must stay in sync. A future check added to one (e.g., a new required field, a deprecation warning) is easy to forget to mirror, and the error-key qualification rules can silently diverge.

## Resolution Plan

- Add a private `validateEntityMap(entityType string, entityMap map[string]Action, qualifyKeys bool) []ValidationError` in `internal/config/action/service.go`.
- `ValidateActions` (root) calls it once per entity type with `qualifyKeys=true`.
- `entityActionView.ValidateActions` calls it once with `qualifyKeys=false`.
- Both legacy method bodies collapse to a single call + result aggregation.

## Resolution Notes

Extracted `validateEntityMap(entityType string, entityMap map[string]StatusActionData, qualifyKeys bool, result *ValidationResult)` in `internal/config/action/service.go`. The helper centralizes the per-status / per-action validation loop (missing `ready_for_*` actions, invalid `OrchestratorAction` payloads, warning text, and result mutation).

- `DefaultActionService.ValidateActions` calls the helper once per entity type with `qualifyKeys=true`, preserving the `<entityType>:<status>` key qualification for non-default entity types (the default entity, `task`, stays unqualified for back-compat).
- `entityActionView.ValidateActions` calls the helper once for its bound entity type with `qualifyKeys=false`, emitting raw status names as before.

Added `internal/config/action/service_validate_test.go` with two tests: `TestValidateEntityMap_QualifyKeys` (direct helper coverage, table-driven across both `qualifyKeys` modes plus the default-entity exception) and `TestValidateActions_BothCallersConsistent` (end-to-end coverage proving both the root service and `ForEntity` view exercise the helper correctly).
