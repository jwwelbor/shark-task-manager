# TD-233 Research Report

## Scope

Consolidate the triage-routing prose (the contract that says non-blocker review findings
must route through the triage skill's decision tree — fix-now gate, duplicate search,
type classification — rather than mapping severity straight to tech-debt) into a single
shared reference per deployable tree, without weakening the B066/B067 regression gates
that assert the literal phrase and forbid the direct-mapping phrases.

## Research checklist

- [x] `scope_vocabulary` — Evidence: skills/shark-rider/skills/deep-review/references/consolidator.md
- [x] `affected_implementation_or_contract` — Evidence: internal/sharkdata/default_data/skills/quality/workflows/review-code.md
- [x] `pattern_contract` — Evidence: internal/cli/commands/review_output_policy_test.go

## Findings

- Grepping for `triage skill`, `decision tree`, `fix-now`, `duplicate search`, and `type
  classification` across the repo turned up four live prose instances outside historical
  plan/report documents: `skills/shark-rider/skills/deep-review/references/consolidator.md`,
  `skills/shark-rider/skills/deep-review/SKILL.md`, `internal/sharkdata/default_data/skills/quality/workflows/review-code.md`,
  and `internal/sharkdata/default_data/agents/tech-lead.md`. The fifth known instance,
  the user-global `~/.claude/skills/finish-feature/SKILL.md`, was fixed separately under
  TD-232 and is out of scope here.
- `internal/sharkdata/default_data/` is the embedded canonical bundle (extracted to
  `shark-data/` on `install-shark-data`); `skills/shark-rider/` is repo-tracked Rider
  skill content deployed a different way. The two trees do not resolve file references
  into each other at runtime, so one physical shared document cannot serve both —
  confirmed by the existing codebase precedent of `consolidator.md`'s pre-existing prose
  pointer to `review-code.md` Step 12, which is a cross-tree citation for a human/agent
  reader, not a resolvable path.
- `internal/cli/commands/review_output_policy_test.go`'s
  `TestConsolidatorRoutesNonBlockersThroughTriage` and
  `internal/sharkdata/embed_test.go`'s `TestEmbedded_ReviewFindingsRouteThroughTriage`
  both independently assert the literal phrase `triage skill's decision tree` is present
  in their respective tree's files and that none of `host triages as tech-debt`, `host
  files as tech-debt`, `host files these as tech-debt`, `File as tech-debt only if`
  appear. This dual, per-tree gate is itself evidence the repo's own test authors already
  treat the two trees as non-resolvable — reinforcing that a single physical anchor for
  both is not the right target.
- `skills/shark-rider/skills/triage/SKILL.md` already implements the decision tree
  structurally: Step 0 is the fix-now gate, Step 3 is the existing-entity (duplicate)
  search, and Step 4 is the classification table. No canonical statement of the *contract
  as seen from a producer's side* existed there before this change — only the skill's own
  procedure.
- `internal/sharkdata/default_data/skills/quality/workflows/review-code.md` Step 12
  ("Triage labeling") was already the fullest statement of the contract within the
  embedded bundle, including the negative guarantee ("never tech-debt by default") and
  the fallback-to-note behavior on a failed triage attempt.

## Capability map

The triage-routing contract already existed in several places; this work chose
one canonical statement per deployment tree and reduced the rest to pointers.

| Capability | Where | Decision | Why |
| --- | --- | --- | --- |
| Triage decision tree (fix-now gate, duplicate search, type classification) | `skills/shark-rider/skills/triage/SKILL.md` | **EXTEND** | The skill already owned the decision tree as procedure; a "Routing contract" section was added so other Rider finding-producers can point at it instead of restating the step list. |
| Rider-tree restatements | `skills/shark-rider/skills/deep-review/references/consolidator.md`, `.../deep-review/SKILL.md` | **REUSE** | Reduced to pointers at the triage skill, keeping the load-bearing phrase and the "never tech-debt by default" guarantee so the B066/B067 regression gates stay true. |
| Embedded-bundle canonical statement | `internal/sharkdata/default_data/skills/quality/workflows/review-code.md` Step 12 | **EXTEND** | Already the fullest statement in that tree; designated canonical and left intact, with the same file's earlier restatements trimmed to pointers. |
| Embedded-bundle restatement | `internal/sharkdata/default_data/agents/tech-lead.md` | **REUSE** | Now points at review-code.md Step 12 rather than restating the mechanism list. |
| Single cross-tree shared reference | — | **CONTRADICTS** | TD-233's original Resolution Plan called for one document under `skills/shark-rider/skills/triage/` that the embedded-bundle files point at. `internal/sharkdata/default_data/` and `skills/shark-rider/` deploy through different paths and do not resolve file references into each other, so that pointer would not resolve at runtime. One canonical statement per tree was adopted instead. |

## Decisions

- Chose two per-tree canonical anchors instead of one cross-tree document, because a
  single physical file cannot be read by both `internal/sharkdata/default_data/` and
  `skills/shark-rider/` at runtime. This deviates from the Resolution Plan's original
  suggestion (one doc under `skills/shark-rider/skills/triage/`, with `review-code.md`
  and `tech-lead.md` pointing at it) for that reason — the cross-tree pointer would not
  resolve.
- Canonical statement for the Rider tree: a new "Routing contract (for review and other
  finding-producer skills)" section in `skills/shark-rider/skills/triage/SKILL.md`.
  `consolidator.md` and `deep-review/SKILL.md` were trimmed to point at it while
  retaining the load-bearing literal phrase and the "never a default" guarantee.
- Canonical statement for the embedded bundle tree: `review-code.md` Step 12, left intact.
  The schema-comment and phase-contract restatements earlier in the same file were
  trimmed to short "(see Step 12)" / "(full contract in Step 12)" pointers.
  `review-code.md`'s Section I and "Do NOT block for" mentions were left alone — they
  describe report-output format and a scoping rule for a specific finding class,
  respectively, not restatements of the contract's mechanism list.
  `tech-lead.md` was trimmed to point at `review-code.md` Step 12 instead of restating
  the fix-now/duplicate-search/classification list.
- Verified no guarantee was weakened by running the exact regression tests named in the
  B066/B067 gates: `go test ./internal/cli/commands/ -run
  'Consolidator|ReviewPrompts|DeepReview'` and `go test ./internal/sharkdata/`. Both
  passed after the edits.
