# TD-030 research report

## Scope

Remove the task repository's assumption that a blocked task is stored with the literal status `blocked` while preserving blocked-task display and epic analytics behavior.

## Research checklist

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-030.md:1-15`; `internal/repository/task/repository.go:653-673`.
- [x] `affected_implementation_or_contract` — Evidence: `internal/services/display_service.go:30-35,559-565`; `internal/services/epic_analytics_service.go:29-33,184-190`.
- [x] `pattern_contract` — Evidence: `internal/workflow/service.go:364-367` exposes phase-derived statuses; `internal/services/sprint_service.go:1412-1416` passes a workflow-derived blocked vocabulary to a repository query.
- [x] `dependency_impact` — Evidence: `internal/services/epic_service.go:49-57,208-210` constructs `EpicAnalyticsService`; constructor wiring must carry task workflow context without changing unrelated callers.

## Capability map

| Capability | Source | Decision |

| Blocked-task query | `TaskRepository.ListBlockedTasksByEpic` | EXTEND — accept caller-supplied blocked statuses. |
| Workflow status vocabulary | `workflow.Service.ForLevel(...).GetStatusesByPhase` | REUSE — derive task blocked statuses at service boundaries. |
| Sprint blocked-status propagation | `sprint_service.go:1412-1416` | REUSE — follow the existing repository-query pattern. |

## Findings

The repository currently binds `models.TaskStatus("blocked")` directly. DisplayService already owns `workflowSvc`, but EpicAnalyticsService does not; its construction through EpicService is the required dependency seam. A variadic or slice parameter must build an `IN` predicate and should return an empty result for no supplied blocked statuses rather than silently restoring a hardcoded default.

## Decisions

Change the repository and all narrow interfaces to accept the workflow-derived task blocked-status vocabulary. Pass it from DisplayService and inject the workflow service into EpicAnalyticsService through EpicService. Preserve ordering and degrade gracefully when no statuses are configured.
