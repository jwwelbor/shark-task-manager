# TD-036 research report

## Scope

TD-036 removes the unused `DefaultTransition` selector and its workflow-service
wrapper. The production transition consumers already read `NextStatusInfo`
and deliberately use its documented pass-first first transition. This change
does not alter that runtime contract or introduce a second selection path.

## Findings

1. Neither selector has a non-test production caller.
2. The runtime already selects the pass-first target from the richer
   `NextStatusInfo` boundary, where orchestration metadata is available.
3. The selector's case-insensitive map scan is not the production contract;
   retaining it creates a plausible but unexercised alternate path.

## Decisions

1. Remove the config selector, its wrapper, and unit tests.
2. Remove it from the architecture selector catalog while retaining the
   pass-first ordering documentation.
3. Do not migrate a production caller merely to preserve an abstraction that
   offers less context than the existing transition DTO.
