## Context

Deep-review finding N5 on PR #126 (see docs/review/fix-positional-selection-class/code_review/2026-07-11-fix-positional-selection-class-overall-review.md).

`validatePrimaryDesignations` (internal/config/workflow/validator.go) enforces the primary-tag designation rule for the sprint lifecycle phases on EVERY route-based workflow, at every entity level. Runtime phase selection (`StatusForPhase`) is only consumed by SprintService, so a custom task/feature/epic workflow with two review-phase steps is rejected at validate time even though runtime never selects by phase there.

## Fix

Scope the phase-designation check to the sprint workflow level (ValidateWorkflowFiles knows the level; ValidateWorkflow currently does not — needs level plumbing or a per-level rule set), or downgrade the finding to a warning for non-sprint levels.
