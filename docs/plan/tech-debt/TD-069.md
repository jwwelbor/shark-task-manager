# shark task list silently drops results for single combined E##-F## positional arg

## Description

'shark task list <epic>-<feature>' (a single positional arg, e.g. 'shark task list E38-F09') silently returns zero results instead of listing that feature's tasks, because runTaskList (internal/cli/commands/task.go:103-111) only treats args[0] as epicKey and never splits a combined key into epic+feature -- unlike shark get/shark feature get/etc, which auto-detect the E##-F## format per the project's documented Key Format Flexibility convention. The two-positional-arg form ('shark task list E38 F09') and the flag form ('shark task list --feature=E38-F09') both work correctly. Found while driving E38-F09 through shark-rider run: the task_generation workflow prompt literally instructs the agent to run 'shark list E38-F09 --json' to check for existing tasks, and that command returns null even when tasks exist, which could mislead an agent into re-creating tasks or missing existing coverage. Fix: split args[0] on a combined E##-F## pattern the same way other single-key commands do, or accept a single combined positional the same way normalizeFeatureKey already handles the two-arg case.

## Impact

Silent empty results are the worst failure mode for a CLI a workflow prompt tells
an agent to run for a readiness check: `shark task list E38-F09 --json` returns
`null` even when tasks exist, so an agent following the literal instruction
concludes "no tasks yet" and may re-generate a task DAG that duplicates existing
(possibly completed) work, or skip a coverage check it should have run. Any
human or script using the single combined-key positional form hits the same
silent gap — there's no error, just an empty/`null` result, so it looks like an
empty feature rather than a bug.

## Resolution Plan

In `runTaskList` (internal/cli/commands/task.go), when `len(args) == 1` and
`args[0]` matches the combined `E##-F##` feature-key pattern, treat it as
`featureKey` (and derive `epicKey` from it) instead of assigning it to
`epicKey` alone — mirroring how `normalizeFeatureKey` already handles the
two-positional-arg case. Add a unit test covering `shark task list E38-F09`
against a feature with existing tasks.
