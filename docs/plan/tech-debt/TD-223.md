# provider_active_claims does not dedupe self-overlapping envelope windows

## Description

run-lifecycle.sh's provider_active_claims() (E40-F12) subtracts each raw worker-envelope provider_active interval against a fixed claimed_union built once from driver-observed categories, but never against pieces already accepted earlier in the same call. Two overlapping self-reported provider_active windows in one envelope would both survive un-deduplicated into the emitted time_ledger, which would fail verify-stage-evidence.sh's pairwise cross-category overlap check. Currently dormant: no shipped adapter populates time_ledger.provider_active yet (per the function's own docstring), so this is a latent gap in forthcoming-facing code, not an active production failure. Found during E40-F12 deep-review (angle-A).

## Impact

None today: no shipped adapter writes `time_ledger.provider_active`, so `claims.extend(_subtract_claimed(...))`'s narrow union base is never exercised with real overlapping data. If a future adapter starts emitting `provider_active`, an envelope reporting overlapping windows would flow unmerged into `reconcile_time_ledger()` and `verify-stage-evidence.sh` would reject the bundle with a `ledger_overlap` violation at replay/verify time, not at production time.

## Resolution Plan

In `provider_active_claims()` (bench/scripts/run-lifecycle.sh), fold each accepted piece into `claimed_union` as it is produced inside the loop, or re-run the same union-merge used to build `claimed_union` from `claimed_so_far` over the final `claims` list before returning — so a later raw pair in the same call is also checked against earlier-accepted `provider_active` pieces from this call.
