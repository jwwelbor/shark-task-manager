# Backfill retry re-folds already-applied events, wedging on next event

## Description

internal/integration/backfill.go's per-event loop (lines ~207-218) unconditionally re-folds every input event via RecordEvent+UpdateCandidate with no presence check. A retry of a crashed Backfill re-folds already-applied event A (a no-op digest-wise), spending the claim slot for the unchanged digest, so the next genuinely-new event B then collides and fails with a permanent spurious CandidateConflictError. foldIntegrationEventIfMissing (feature_service.go) already has the presence-check guard this loop lacks. Fix: mirror that presence check inside Backfill's loop, skipping UpdateCandidate for events already present in the current on-disk candidate. From code-review of the E34 (F06-F11) integration diff, finding F1 (non-blocker: Backfill is a one-time, human-operated bootstrap tool with a documented manual workaround).
