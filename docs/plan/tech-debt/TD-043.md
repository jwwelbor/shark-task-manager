# Portfolio Advise has two implementations and the dead one owns the tests

## Description

internal/services/portfolio_advice_service.go:90 selects between two Advise implementations on s.snapshotSource != nil. Only production wiring (services_global.go:753) takes the snapshot path, yet 10 of 11 unit tests construct the legacy NewPortfolioAdviceService, so the shipped path is exercised by a single integration test. Four of six struct fields are always nil depending on which constructor ran.

This is the direct root cause of a shipped blocker escaping the suite: bare 'shark plan' hard-failed whenever any claim row existed (fixed in commit e4e29432), and the unit tests could not have caught it because they never ran the code path that broke.

Fix: delete the legacy constructor plus listPortfolioEpics/readPortfolioAdviceEvidence, and repoint the unit tests at a fake PortfolioSnapshotSource. Advise then has one body.

Source: /shark-rider deep-review high on PR #139 (finding N2). Full report was written to docs/review/feat-shark-plan-command/code_review/ which is gitignored and not committed.
