# Replace template/helpers.go custom key parsers with keys.KeyService.Parse

## Description

internal/config/template/helpers.go:17-83 reimplements key parsing with its own regex patterns and helper functions:

- epicKeyPattern, featureKeyPattern (compiled regexes)
- ParseEpicKeyFromEntityKey(entityKey string) string
- ParseFeatureKeyFromTaskKey(taskKey string) string

These duplicate functionality that internal/keys.KeyService.Parse() already exposes via the ParsedKey struct (EpicNum, FeatureNum, slug-stripping, T- prefix handling, case-insensitive matching, etc.).

The same duplicate alias chain appears in internal/config/aliases.go:166-170.

Fix: replace both helpers with KeyService.Parse() calls. Delete the redundant regex vars and the alias chain in aliases.go. KeyService is the single source of truth for shark key parsing — bypassing it risks subtle divergence (slug rules, case rules, T- prefix rules) that has already bitten this codebase.

Surfaced during simplify review of commit 6492e45.

## Impact

Two key-parsing implementations can drift. `KeyService` already handles slugs, T- prefix, case-insensitivity, and the various legacy formats. The custom regexes in `template/helpers.go` cover only a narrow happy path — they will misbehave on slugged keys (`E07-F01-user-management`) and case-variant input (`e07`, `t-e07-f01-001`) once those start flowing into the template layer. Drift between key parsers has bitten this codebase before.

## Resolution Plan

- Replace `ParseEpicKeyFromEntityKey` and `ParseFeatureKeyFromTaskKey` in `internal/config/template/helpers.go` with calls to `keys.NewKeyService().Parse(entityKey)`, reading `EpicNum` / `FeatureNum` off the resulting `ParsedKey`.
- Delete `epicKeyPattern` and `featureKeyPattern` and any test fixtures that exercise only the regex variant.
- Remove the duplicate alias chain at `internal/config/aliases.go:166-170`, routing through `KeyService` instead.
- Add a test that exercises the template layer with slugged + mixed-case keys to lock in the behavior.

## Resolution Notes

  `keys.NewKeyService().Parse(...)`, reading `EpicNum` / `FeatureNum` off the
  returned `ParsedKey`. Deleted the local `epicKeyPattern` /
