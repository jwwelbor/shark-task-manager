# dispatcher.go: unbounded stdout/stderr capture before gate-envelope size limit evaluated

## Description

internal/runner/dispatcher.go:185 and :189 use io.ReadAll on the worker process's stdout/stderr pipes with no size bound, before any gate_result_v1 envelope size limit (workercontrol.MaxEnvelopeBytes, 256KiB) is evaluated downstream. An adversarial or misbehaving worker process can exhaust memory via unbounded output. Pre-existing (last touched by E22/E38 work, not in E34-F05's diff: git log shows no E34-F05 commit touching dispatcher.go) -- not introduced by E34-F05, but shares the same unbounded-ingestion defect class as run_apply_result.go's os.ReadFile gap (fixed as part of this feature's T-E34-F05-004 kickback). Found by Codex red-team during E34-F05 UAT round 2.
