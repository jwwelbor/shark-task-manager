# TD-070 research report

## Scope

TD-070 tracked a task-update command that accepted `--depends-on` but discarded
it before the service layer. The current lineage contains the B048 remediation:
task and unified update commands now preserve the flag's set, clear, and absent
semantics through parsing, `TaskUpdates`, the service, and repository validation.
This report verifies that existing remediation rather than changing the contract.

## Findings

1. The reported silent no-op is no longer present. `parseTaskUpdates` calls
   `parseDependsOnUpdateFlag` only when the flag is supplied, then propagates
   the result through `TaskUpdates`.
2. The public contract is three-way: a list JSON-encodes and replaces the
   legacy dependency list, an explicitly empty value clears it, and an absent
   flag leaves it unchanged. `ClearDependsOn` has explicit service precedence.
3. Focused tests cover task and unified command parsing plus the no-resequence
   repository path, so a future dropped parser or unsafe `--parallel` write
   fails before persistence.
4. TD-061's current cleanup only removes duplicate validation control flow; it
   preserves this B048/TD-070 safety contract.

## Decisions

1. Recommend resolution with no further code change: the shipped B048
   remediation satisfies TD-070's root cause and regression boundary.
2. Retain the focused parser and repository tests; do not conflate legacy JSON
   dependency updates with `task link` relationship edges.
3. Tech-debt related-document registration is unsupported by the live CLI, so
   this adjacent report is the durable evidence.
