# TD-014 research report

## Scope

TD-014 concerns the dormant bug prompt-partial path only. It must not force
bugs onto the partial renderer before the E32-F02 migration that owns that
runtime change.

## Findings

The current bug `next` flow reaches the post-render guard through the
orchestrator-action fallback, not a bug partial. Existing helper-level
coverage proves `review_base` derivation but cannot prove a production
partial-loading path that does not exist. A standalone test would need to
invent that path and would not protect the runtime migration.

## Decisions

Defer implementation and the end-to-end regression test to E32-F02. Its
acceptance test must transition a bug through `ready_for_code_review` via the
actual partial renderer and assert that the rendered action contains the
configured `review_base`. No production behavior changes in TD-014.

**Recommended outcome: wont_fix as standalone work; retain the E32-F02
dependency.**
