# TD-029 research report

## Scope

Make task timestamp writes classify configured task workflow phases and terminal states, while retaining the existing timestamp columns and migration compatibility.

## Research checklist

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-029.md:1-15`; `internal/repository/task/repository.go:1382-1392,1498-1508`.
- [x] `affected_implementation_or_contract` — Evidence: `internal/repository/task/repository.go:1360-1510`; `internal/services/task_service.go:1558-1759`.
- [x] `pattern_contract` — Evidence: `internal/workflow/service.go:364-367`; `internal/services/task_service.go:1751-1759` derives task terminal statuses.
- [x] `dependency_impact` — Evidence: `StatusUpdateRawParams` paths share the same timestamp update logic and dependency cascade consequences.
- [x] `cross_boundary_risks` — Evidence: existing column names are historical API/database fields; renaming requires migration and downstream compatibility review.
- [x] `alternatives` — Evidence: a phase-aware mutation policy fixes configured workflow behavior now; an event-log/schema redesign remains a later migration decision.

## Capability map

| Capability | Source | Decision |
| --- | --- | --- |
| Timestamp persistence | task repository status updates | EXTEND — accept phase/terminal status policy from TaskService. |
| Workflow vocabulary | `TaskService.taskTerminalStatuses` | REUSE — derive configured classifications before repository writes. |

## Findings

`started_at`, `completed_at`, and `blocked_at` are legacy column names, but their write trigger can be made status-agnostic without a migration: first execution-phase entry, first terminal entry, and first blocked-phase entry. This preserves stored data and API fields while eliminating literal coupling.

## Decisions

Use the same caller-supplied task status policy as TD-028 to control timestamp writes. Defer column renaming or event-log redesign because neither is necessary to make configured workflows correct.
