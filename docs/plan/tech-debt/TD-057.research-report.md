# TD-057 research report

## Scope

TD-057 adds regression coverage for three target guards owned by
`QuestionService.Supersede`: a Question cannot supersede itself, the
superseding key must use the strict uppercase `Q001` through `Q999` grammar,
and the distinct superseding Question must exist. These checks occur before
`closeWithReason`, the method that writes terminal provenance and status.

The work adds focused mocked-service tests only. It does not alter the
supersede workflow, key grammar, CLI/API transport validation, repository
transaction, or terminal-provenance shape.

## Findings

1. **The three guards are present but untested at their service seam.**
   `Supersede` rejects an equal `Key` and `SupersededBy`, validates the target
   with `models.ValidateQuestionKey`, then loads the distinct target. Existing
   TC-107 tests always provide valid, distinct, resolvable `Q002`, so none of
   those paths is exercised.

2. **The validation order is an important part of the contract.** A
   self-supersede rejection occurs before any repository read. A malformed key
   occurs before target lookup. A well-formed missing key performs only the
   target lookup and must not load or write the Question being closed. All
   three failures must occur before `closeWithReason` calls `Withdraw` for its
   atomic status/context update.

3. **The smallest adequate test boundary is `QuestionService`.** Cobra and
   HTTP only require a supplied target field and delegate the semantic checks
   to `Supersede`. A service test with `mockQuestionRepository` can prove the
   production policy and absence of a write without a database or duplicate
   transport tests.

4. **Existing test style already supplies the correct no-write oracle.**
   `TestQuestionServiceWithdrawAndSupersedeRejectGuardViolations_TC107` uses
   a `withdrawFn` that records invocation and asserts it remains false after
   rejected close conditions. TD-057 should add a sibling Supersede-only table
   rather than alter the successful-close test.

5. **No related-document registration is available for tech-debt entities.**
   `related-docs` supports epic, feature, task, bug, change-card, and Question
   parents, but no tech-debt parent. The adjacent sidecar report is the
   supported durable artifact.

## Decisions

1. **Add one TC-107 table-driven service test with three subtests.** Place it
   beside the existing terminal-provenance guard tests in
   `internal/services/question_service_test.go`.

2. **Use these exact cases:**

   - `self`: `Key: "Q001"`, `SupersededBy: "Q001"`; expect an error, zero
     target lookups, and no `Withdraw` call.
   - `malformed`: `SupersededBy: "Q000"` (or another strict-grammar failure);
     expect `models.ErrInvalidQuestionKey`, zero target lookups, and no
     `Withdraw` call.
   - `missing`: `SupersededBy: "Q002"` whose `GetByKey` returns a not-found
     error; expect the wrapped target-load error, one target lookup, and no
     `Withdraw` call.

3. **Make the mock fail loudly if the wrong read occurs.** In the self and
   malformed cases, a `GetByKey` call is a regression. In the missing case,
   accept exactly one lookup for `Q002`; the target Question `Q001` must not be
   loaded because the failure happens before `closeWithReason`.

4. **Do not add duplicate CLI or HTTP cases.** Their required-field tests and
   pass-through behavior are already separate. The service test protects the
   semantic policy shared by every transport.

**Recommended outcome: implement.** Add the three focused no-write service
subtests. The guards are production-correct, but their regression boundary is
currently unprotected.
