# TD-224 research report — I-05 writer seams

## Scope

Reduce duplicated I-05 writer loading and persistence mechanics without
changing the bundle schema, reset ownership, or lifecycle CLI behavior.

## Research checklist

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-224.md`
- [x] `affected_implementation_or_contract` — Evidence: `bench/scripts/run-lifecycle.sh:730-889,1032-1331`
- [x] `pattern_contract` — Evidence: `bench/scripts/verify-retention-manifest.sh`; `bench/scripts/tests/tc115_i05_producer_test.sh`

## Findings

The YAML-table loaders and stage persistence concerns are duplicated inside
one monolithic shell-embedded Python subsystem. The smallest safe change is
local helper extraction; cross-script module relocation would mix a larger
distribution boundary with the correctness work in this branch.

### Capability map

| Capability | Decision | TD-224 action |
|---|---|---|
| I-05 bundle format | REUSE | Preserve schema and paths. |
| YAML loading | EXTEND | Use one local loader helper. |
| Cross-script sharing | EXTEND LATER | Do not introduce a new module boundary here. |

## Decisions

1. Extract only local helpers that retain existing caller contracts.
2. Keep `run-lifecycle.sh` as the production entrypoint for this group.
