# Isolate subprocess test logs and run artifacts from repository root

## Description

Contract/integration tests use temporary databases but run from the repository root, so test shark.log and .shark/runs/ artifacts accumulate with development/production-style logs. Observed 716 E01/E01-F01 run records in the repository .shark/runs/ tree. E40-F04 correctly defines per-run logs and most unit tests use t.TempDir(), but subprocess contract tests still need an isolated project/log root. Related to completed E40-F04; distinct from TD-121, which concerns a shared temporary database.

## Impact

Test-generated `shark run` records are mixed into the repository's normal
`shark.log` and `.shark/runs/` tree. This makes historical run diagnosis
ambiguous and can leave test artifacts in the same location used for local
development evidence.

## Resolution Plan

Run subprocess contract/integration tests from an isolated temporary project
root that contains the required config/workflow inputs, or provide an explicit
test artifact root. Ensure `shark.log`, `.shark/runs/`, transcripts, and related
run artifacts resolve beneath that root while preserving the production default.
Add a regression assertion that test runs do not create or append to the
repository-root log/artifact paths. Re-check the existing E40-F04 liveness and
stdout-purity contracts after the isolation change.
