# tc014_run_one_smoke_test.sh's scratch bootstrap hits a shared /tmp/shark-tasks.db, clobbered by concurrent sessions

## Description

bench/scripts/tests/tc014_run_one_smoke_test.sh's provisioning phase creates/uses /tmp/shark-tasks.db as a fixed shared path rather than a per-invocation isolated scratch DB. On this shared machine with multiple concurrent agent sessions, another session's project-initialization step can overwrite this file mid-run with a different (older) schema, causing intermittent 'sqlite3.OperationalError: no such table: bugs' failures in collect-run.sh -- unrelated to any specific feature's code. Discovered during E40-F06 UAT while diagnosing bench/scripts/tests/run-all.sh flakiness (tc014 failing, not any F06 guard test). Fix: make tc014's scratch bootstrap use a per-invocation isolated DB path (mktemp-based), consistent with scripts/shark-scratch-env.sh's isolation pattern used elsewhere in this test suite.

## Impact

Any bench test suite run (locally or via automated dispatch) on this shared machine can intermittently fail at tc014 for reasons unrelated to the feature under test, costing wasted investigation time and false rejection signals in review gates.

## Resolution Plan

Update tc014_run_one_smoke_test.sh's provisioning phase to create its scratch shark-tasks.db under a per-invocation mktemp directory rather than the fixed /tmp/shark-tasks.db path, matching scripts/shark-scratch-env.sh's isolation pattern.
