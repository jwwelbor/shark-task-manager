# architecture.md: adoption-matrix doc doesn't note epic.integration_review deferral

## Description

The canonical gate_result_v1 adoption matrix covers 12 of architecture.md's stated 13 entries; epic integration_review is deliberately deferred to E34-F08 in a code comment, but architecture.md's adoption-matrix table was never updated to say so. Fix: add a one-line 'deferred to E34-F08' note. From E34-F05 code-review round 1, finding F7.

## Impact

This record's original premise was stale by the time it was worked: `epic/integration_review` now exists in the shipped workflow (`internal/sharkdata/default_data/workflow/epic.yaml`, added by E34-F08), so the "does not exist yet" framing in the code comment (`internal/config/workflow/result_contract_adoption_matrix_test.go`) no longer matches reality. But the step still carries no `result_contract` field (defaults to `legacy`) and no `outcome_roles`. Meanwhile architecture.md's "Compatibility and migration" adoption-matrix sentence had drifted the other way: it listed epic `integration_review` alongside `feature_review` as opting into `gate_result_v1`, which was never true and is not true now. A reader trusting the doc would wrongly expect `integration_review` results to follow the `gate_result_v1` envelope.

## Resolution Plan

Correct the adoption-matrix sentence in `docs/plan/E34-prompt-and-skill-improvements/architecture.md` (Compatibility and migration section) to list only the 12 steps that actually carry `result_contract: gate_result_v1` in the shipped workflow YAML, and add a short clause stating epic `integration_review` remains `legacy`. Checked the E34-F08 feature docs (spec.md, tasks/T-E34-F08-009.md) for a recorded intent to later migrate `integration_review` to `gate_result_v1`: none exists — F08 only wires `outcomes` (pass/fail/blocked/on_hold), not `result_contract`/`outcome_roles`. So the correct wording is "remains legacy," not "deferred to E34-F08" (E34-F08 is what added the step, not what promises to migrate it).

## Resolution Notes

Verified against HEAD: `internal/sharkdata/default_data/workflow/epic.yaml` — `feature_review` (line 144) has `result_contract: gate_result_v1`; `integration_review` (lines 155-170) has neither `result_contract` nor `outcome_roles`. `internal/config/workflow/result_contract_adoption_matrix_test.go`'s `canonicalAdoptionMatrix` also confirms only `epic: {"feature_review"}` is expected to resolve `gate_result_v1`, with a comment explaining `integration_review` was excluded because it didn't exist in the workflow yet when the matrix was fixed at T-E34-F05-005. Cross-checked the rest of the sentence's list (feature `specification`/`test_planning`/`task_review`/`code_review`/`qa`/`approval`; tech-debt `triaged`/`in_progress`; change-card `development`/`code_review`/`qa`) against `internal/sharkdata/default_data/workflow/{feature,tech-debt,change}.yaml`: all 11 of those entries correctly carry `result_contract: gate_result_v1`.
