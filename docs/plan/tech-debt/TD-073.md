# ValidateQuestionBoundedText denylist misses whitespace-permuted variants (BEARER:, password =, Authorization :)

## Description

internal/models/question.go:190 ValidateQuestionBoundedText lowercases the value before checking strings.Contains against exact literal markers ("bearer ", "password=", "authorization:"), so it normalizes case but not whitespace/punctuation. A marker with an inserted/removed space or colon slips through undetected -- e.g. "BEARER:" (colon immediately after, no space) and "password =" (space before the equals) are both currently ACCEPTED, not rejected. Found and pinned as a characterization test (known_gap sub-table) by T-E38-F09-021's TC-SEC-01-02 in tests/contracts/e38_f09_interactions_test.go. REQ-NF-004 commits F09 to relying on this existing E39 denylist rather than adding a second validator, so F09 cannot fix this in its own scope; E39/the denylist owner should normalize whitespace before the substring check (e.g. collapse runs of whitespace, or match a lenient regex per marker) and then update T-021's known_gap sub-table.
