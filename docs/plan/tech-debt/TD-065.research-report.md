# TD-065 research report

## Scope

TD-065 was filed after B048 to document and restore the three-way
`shark task update --depends-on` contract. The current checked-out lineage
already contains that remediation: task and unified task updates distinguish
an absent flag (no-op), explicit empty input (clear), and a list (replace),
and the fast `--parallel` path validates dependency changes before writing.
This report verifies the existing result and keeps the documentation scope
separate from relationship-edge dependencies.

## Findings

1. The historical B048 silent no-op has been remediated. `parseTaskUpdates`
   delegates changed input to `parseDependsOnUpdateFlag`, and `TaskUpdates`
   transports its explicit set/clear intent to `TaskService.UpdateTask`.
2. The documented behavior is present: a list JSON-encodes and replaces the
   legacy field, blank or comma-only input clears it, and an absent flag makes
   no dependency mutation.
3. `UpdateNoResequence` validates dependencies before its direct write, so
   combining `--depends-on` with `--parallel` cannot bypass validation. TD-061
   removes duplicated control flow without changing that invariant.
4. Clearing the legacy JSON field does not delete an outgoing `task link`
   relationship; both stores remain independently visible to status gating.

## Decisions

1. Resolve without further implementation: the live B048 behavior and focused
   regression tests meet the TD-065 contract.
2. Retain the CLI, service, and repository tests as the counterfactual guard;
   removing parser, DTO, service, or fast-path validation behavior fails its
   respective focused test.
3. Keep this adjacent report as the durable record because tech-debt entities
   cannot be parents of `shark related-docs add`.
