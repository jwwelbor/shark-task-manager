# evaluate-lifecycle.sh and compare-lifecycle-evaluations.sh still use the stale 6-field identity formula

## Description

B057 fixed `verify-lifecycle-run.sh`'s candidate `identity_digest` check to use
the named 7-field formula (`base_commit`, `tree_digest`, `binary_diff_digest`,
`changed_path_digest`, `dirty_untracked_manifest`, `test_suite_digest`,
`scratch_content_digest`) that `run-lifecycle.sh`'s `refresh_candidate()`
actually produces. `bench/scripts/evaluate-lifecycle.sh` (`CANDIDATE_FIELDS`,
~line 261) and `bench/scripts/compare-lifecycle-evaluations.sh`
(`candidate_fields`, ~lines 20 and 64) still hardcode the old 6-field tuple
and independently recompute `expected_identity` from it.

## Impact

A real 7-field candidate that now passes `verify-lifecycle-run.sh` will still
be rejected one hop downstream with `identity_mismatch` when it reaches F09
evaluation or comparison — reproducing B057's exact symptom in a different
script. Flagged by B057's own research report (dependency_impact module) but
left unaddressed in that fix's scope, since `smoke-lifecycle.sh` only calls
`verify-lifecycle-run.sh`, not these two scripts.

## Resolution Plan

Apply the same named-field fix (a `CANDIDATE_IDENTITY_FIELDS` constant
matching `run-lifecycle.sh`'s actual output) to `evaluate-lifecycle.sh` and
`compare-lifecycle-evaluations.sh`, and add contract-test coverage before F09
or F10 are exercised against real dry-run output.

Also fold `scratch_content_digest` into `bench/runs/i07-schema.yaml`'s
`required_fields` (and `properties` digest typing), and derive each script's
identity-field list from that schema instead of maintaining three private
copies — the schema's own header already claims to be "the single
machine-readable owner ... rather than maintaining private copies," which
`verify-lifecycle-run.sh`'s B057 fix does not yet honor.
