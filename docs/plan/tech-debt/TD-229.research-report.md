# TD-229 research report

## Scope

Investigate the missing regression for `retain_pair` refusing a required
source after the destination directory has been created. The affected
capability is byte-preserving lifecycle-pair retention: a refusal must leave
the pair destination empty and reclaimable. The repair extends the existing
TC-011 negative case in `tc115_i05_producer_test.sh`; it does not change

## Findings

`retain_pair` enumerates all seven required inputs before copying any
artifact. If the late-listed `transcripts` directory is absent, the preflight
calls `refuse_missing_source()` before `copy_artifact()` or
`copy_dir_artifact()` runs. Its stated contract is therefore stronger than
the current test: the already-created destination must remain empty and can
be safely reclaimed.

TC-115's TC-011 negative case builds a real bundle, removes only
`transcripts/`, invokes the real `retain_pair`, and asserts a nonzero result
plus absent `manifest.json`. Those assertions prove refusal but would also
pass under the previous copy-as-you-go order if earlier artifacts had already
been written. No existing assertion checks the destination contents.

The batch and review-comparison drivers both create the destination before
calling the same shared script. A direct assertion in TC-115 is the narrow
remediation because it exercises the producer contract without duplicating
driver-level behavior.

## Decisions

1. Extend the existing TC-011 negative case immediately after the
   `manifest.json` assertion. Assert that `RETAIN_DEST_NEG` contains no
   entries, including hidden entries, after the missing-`transcripts/`
   refusal.
2. Keep the fixture shape: remove the late-listed `transcripts/` directory
   from an otherwise valid I-05 bundle. This proves the upfront ordering; a
   first-listed missing source would not distinguish the new preflight from
   the old order.
3. Do not modify `retain_pair` or either caller. The implementation already
   provides the required behavior; TD-229 closes the coverage gap only.
4. Register this report through the `related-docs` front matter in
   `TD-229.md`, matching the current tech-debt sidecar convention.

**Recommended outcome: pass.** The implementation and its caller contracts
are already correct; one focused assertion is the remaining planned work.
