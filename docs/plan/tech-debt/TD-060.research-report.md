# TD-060 research report

## Scope

TD-060 addresses repeated parsing of update-command `--depends-on` values. A
comma-separated string is normalized by trimming whitespace and dropping empty
members before it is stored as JSON. Task update additionally needs a
three-way result: flag absent means no change, a normalized empty list means
clear the legacy task JSON field, and a non-empty list means replace it. Idea
update serializes the normalized list, including an explicit empty list, for
its own dependencies field.

Current main contains TD-065's `parseDependsOnUpdateFlag`. The original
TD-060 wording is still directionally correct, but the duplication is now
partial rather than exact: task update owns three-way intent and JSON
encoding, while `readStringSliceFromFlag` owns flag-kind normalization for
idea's entity-first `StringSlice` and unified string registrations. The
minimal safe change is to share only the identical normalization step, not to
merge task and idea update semantics.

Out of scope: task creation parsing, `task link`/`unlink` relationship-edge
parsing, the legacy task-vs-relationship dependency split, or a new generic
flag framework.

## Findings

1. **There is one real duplicated algorithm.** For string-typed flags,
   `readStringSliceFromFlag` trims the raw input, splits on commas, trims each
   member, and drops empty members. `parseDependsOnUpdateFlag` repeats those
   same steps before deciding clear versus set. On current task commands both
   entity-first and unified registrations are strings, so delegating this
   normalization preserves their observable list result.

2. **The helpers are not interchangeable as whole functions.** The shared
   reader accepts `StringSlice` for entity-first idea update; task update must
   return `DependsOn *string` plus `ClearDependsOn bool` and must distinguish
   an absent flag before reading it. Moving task's three-way decision into the
   generic reader would either erase intent or make idea inherit the legacy
   task storage model.

3. **JSON encoding should remain task-owned.** A non-empty normalized task
   list is encoded for `TaskUpdates.DependsOn`; an empty normalized task list
   means a nil field plus `ClearDependsOn=true`. Idea update always encodes its
   resulting slice for `UpdateIdeaInput.Dependencies`, where empty is `[]`.
   Sharing JSON output would conflate these different persistence contracts.

4. **The existing TD-065 tests pin behavior but not the shared normalization
   seam.** `task_update_depends_on_test.go` covers task set, explicit empty,
   absent, and unified string behavior. `idea.go` consumes the reader, but
   the focused tests found do not table-test the reader across both flag kinds
   and whitespace/comma-only values. A small direct helper table test makes
   the refactor's behavioral boundary explicit.

5. **No related-document registration is available for tech-debt entities.**
   This report is the durable related-work record; do not add unsupported
   registration work.

## Decisions

1. **Recommend IMPLEMENT as a small behavior-preserving refactor.** TD-060 is
   neither fully superseded nor a reason to redesign CLI parsing: it should
   remove only the repeated comma-string normalization now that TD-065 has
   made that logic security- and workflow-relevant.

2. **Have `parseDependsOnUpdateFlag` call
   `readStringSliceFromFlag(cmd, "depends-on")` after its `Changed` guard.**
   Retain the task helper's error wrapping, clear-on-empty branch, JSON
   encoding, and `*string` result. Do not change `readStringSliceFromFlag`'s
   current `StringSlice` behavior as part of this ticket; task commands do not
   use that type and idea behavior is outside this refactor.

3. **Add focused normalization and contract tests.** Table-test the shared
   reader for a string flag with ordinary, whitespace-padded, comma-only, and
   empty input; separately pin `StringSlice` input to its existing output.
   Retain TD-065 task set/clear/absent tests, adding a whitespace-padded
   task-list assertion if not already present. Retain or add an idea unified
   empty-list assertion. The counterfactual is that changing splitting,
   trimming, empty-member treatment, or task's clear distinction fails the
   focused test rather than silently changing either command.

4. **Verify narrowly.** Run the dependency-update command tests and any new
   helper/idea tests with `go test ./internal/cli/commands -run
   'DependsOn|StringSliceFromFlag' -count=1`, then `git diff --check`. No
   service, repository, schema, or documentation change is required for this
   refactor.
