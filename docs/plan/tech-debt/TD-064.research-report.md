# TD-064 research report

## Scope

Make documented short dependency keys such as `E07-F01-001` usable wherever the task update/create parser accepts dependency input.

## Research checklist

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-064.md:1-15`; `docs/cli-reference/task-commands.md:170`; `docs/cli-reference/core-commands.md:244`.
- [x] `affected_implementation_or_contract` — Evidence: `internal/cli/commands/parse_create_task_input_test.go:131-149`; `internal/repository/task/dependency.go:22-91`.
- [x] `pattern_contract` — Evidence: `internal/cli/commands/update_dispatch.go:101-171` accepts comma-separated task keys; dependency persistence uses canonical task keys.
- [x] `dependency_impact` — Evidence: `internal/repository/task/repository.go:979-990` validates parsed dependencies before either update write path.

## Capability map

| Capability | Source | Decision |
| --- | --- | --- |
| Dependency parsing | task input helpers and parser tests | EXTEND — normalize short input before validation. |
| Repository validation | `dependency.go:22-91` | REUSE — retain canonical-key validation. |

## Findings

Documentation promises short form but validation receives it unchanged. The normalization must be at the CLI parsing boundary, before JSON construction, so repository callers and stored `depends_on` values remain canonical. This is the same boundary that already accepts comma-separated input.

## Decisions

Normalize each accepted short dependency key to its canonical `T-` form in the shared input parser, retain canonical input unchanged, and cover create/update parsing plus validation. Do not relax `ValidateTaskKey` globally.
