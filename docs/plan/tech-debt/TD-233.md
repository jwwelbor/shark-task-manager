# Consolidate triage-routing prose into a single shared contract reference

## Description

B066's research report (Decision #3) called for a shared contract document describing how non-blocker findings route through the triage skill's decision tree. The actual fix instead inlines near-duplicate prose independently across `review-code.md` (multiple call sites), `tech-lead.md`, and `consolidator.md`. Found during B066 code review (finding F6/F7).

## Impact

The next time this contract changes (e.g. triage gains a new step, or the outcome vocabulary changes), a maintainer must find and edit every independent prose copy by hand across these files. Missing one silently reproduces B066's original symptom (a review-finding producer that no longer routes findings correctly).

## Resolution Plan

Extract the triage-routing contract into one canonical reference doc (e.g. under `skills/shark-rider/skills/triage/` or a shared `context/` doc) and have `review-code.md`, `tech-lead.md`, and `consolidator.md` reference it instead of repeating the prose.

## Resolution Notes

Full instance inventory (grep for "triage skill's decision tree" plus its supporting
phrases — `decision tree`, `fix-now`, `duplicate search`, `type classification`):

- `skills/shark-rider/skills/deep-review/references/consolidator.md` (3 mentions)
- `skills/shark-rider/skills/deep-review/SKILL.md` (1 mention; added after the original
  B066 fix, per B067)
- `internal/sharkdata/default_data/skills/quality/workflows/review-code.md` (5 mentions)
- `internal/sharkdata/default_data/agents/tech-lead.md` (1 mention)
- User-global `~/.claude/skills/finish-feature/SKILL.md` — out of scope, fixed under
  TD-232.

`internal/sharkdata/default_data/` (the embedded canonical bundle) and
`skills/shark-rider/` (repo-tracked Rider skill content) deploy through different paths
at runtime and are not mutually resolvable file references, so a single physical
document cannot serve both trees. The Resolution Plan's original suggestion — one doc
under `skills/shark-rider/skills/triage/`, with `review-code.md`/`tech-lead.md` pointing
at it — was not used for that reason; a cross-tree pointer from the embedded bundle to a
Rider-tree file would not resolve.

Instead, one authoritative statement per tree, with everything else reduced to a pointer
that keeps the load-bearing anti-regression guarantee (the literal phrase "triage skill's
decision tree" plus "tech-debt is only one possible outcome, never a default"):

- **Rider tree**: `skills/shark-rider/skills/triage/SKILL.md` gained a "Routing contract
  (for review and other finding-producer skills)" section naming the fix-now gate
  (Step 0), duplicate search (Step 3), and classification (Step 4) as the decision tree.
  `consolidator.md` and `deep-review/SKILL.md` now point at that section instead of
  restating the step list inline.
- **Embedded bundle tree**: `review-code.md` Step 12 ("Triage labeling") was already the
  fullest statement of the contract and is now the canonical one; the schema and
  phase-contract mentions earlier in the same file were trimmed to "(see Step 12)" /
  "(full contract in Step 12)" pointers, and `tech-lead.md` now points at
  `skills/quality/workflows/review-code.md` Step 12 instead of restating the mechanism
  list.

Verified against `TestConsolidatorRoutesNonBlockersThroughTriage` (in
`internal/cli/commands/review_output_policy_test.go`) and
`TestEmbedded_ReviewFindingsRouteThroughTriage` (in `internal/sharkdata/embed_test.go`) —
both still pass; no existing guarantee was weakened.
