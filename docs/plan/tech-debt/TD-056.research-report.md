## Findings

The local and Turso SQLite drivers surface constraint errors as different unexported types, so no shared `errors.As` target is available. The prior Question code retried any error containing `unique`, which could consume unrelated failures. The Claim repository already establishes the intended portability exception: recognize only the observed SQLite UNIQUE message forms and explain why typed inspection is unavailable.

## Decisions

Add `repoerr.IsSQLiteUniqueViolation`, constrain it to observed modernc/libsql messages, and use it from Question key allocation. Test both driver forms and reject unrelated prose containing `unique`.
