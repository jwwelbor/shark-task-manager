# ValidateQuestionBoundedText forbidden-marker allowlist tested for only 1 of 7 markers

## Description

internal/models/question.go's ValidateQuestionBoundedText implements 7 credential/prompt-injection forbidden markers (api_key, password=, authorization:, bearer , system prompt, user prompt, assistant:) plus UTF-8 validity and min/max byte-length boundary checks, but internal/models/question_test.go only exercises 1 marker (api_key=secret) -- zero coverage on the other six markers, invalid UTF-8, and length boundaries. Fix: add a table-driven test covering each untested marker, an untrimmed value, invalid UTF-8, and boundary lengths (one under/over, and exactly at, min/max). Surfaced by round-5 /shark-rider deep-review of E39 (finding F11), 2026-08-01.

## Impact

Six of seven credential/prompt-injection forbidden markers (`password=`, `authorization:`, `bearer `, `system prompt`, `user prompt`, `assistant:`) plus UTF-8 validity and min/max byte-length boundary checks could regress or be silently removed without any test failing -- only the `api_key` marker has coverage today.

## Resolution Plan

Add a table-driven test to `internal/models/question_test.go` covering each of the six untested markers, an untrimmed value, invalid UTF-8, and boundary lengths (one byte under min, exactly at min, exactly at max, one byte over max).
