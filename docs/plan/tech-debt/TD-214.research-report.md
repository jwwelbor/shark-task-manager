# TD-214 research report — atomic integration publishing

## Scope

TD-214 consolidates the create-if-absent hard-link operation shared by
integration event, run, and replacement-record publishing. It preserves each
record type's marshaling, directory, read-back, and error contract.

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-214.md`

- [x] `pattern_contract` — Evidence: `internal/integration/candidate.go:235-305`; `docs/architecture/coding-standards.md:70-82`

## Findings

Three immutable record writers independently hard-link a complete private
temporary file, then read the typed winner when another writer won the race.
The atomic link is the shared correctness primitive; the typed read-back is
not interchangeable.

### Capability map

| Capability | Decision | TD-214 action |
|---|---|---|
| Atomic create-if-absent | EXTEND | Centralize `os.Link` and EEXIST handling. |
| Typed record recovery | REUSE | Leave each caller's reader and diagnostics local. |

## Decisions

1. Extract a narrow `atomicLinkPublish` helper returning won/not-won.
2. Preserve per-record serialization, directory creation, and winner
   validation in their existing owners.
