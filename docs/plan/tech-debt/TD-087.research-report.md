# TD-087 research report

## Scope

TD-087 concerns admission evidence for lifecycle scenario packages. The affected
capability is `bench/scripts/admit-scenario.sh`'s construction of the test
document passed to `eval-predicate.sh`: it combines the shared
`p2p_selection` result with a separate `--only-id` result for predicate-owned
test IDs. This report covers duplicate normalized IDs across those two adapter
responses, not duplicate YAML keys, scenario IDs, or duplicate entries inside
one adapter response.

The existing remediation is the two-query design in `capture_predicate_state`:
it makes named predicate operands available even when they are excluded from
the shared P2P clause. TD-087 extends that remediation with a consistency
check; it does not replace the separate-query design, the P2P admission check,
or predicate evaluation.

## Findings

1. **The merge masks conflicting evidence.** `merge_entries` records an ID in
   `seen` and discards each later entry. When the P2P query reports `pass` and
   the named-ID query reports `fail` for the same normalized ID, the merged
   document retains `pass`. `eval-predicate.sh` then builds its ID lookup from
   that retained entry, so checks (d) and (e) can receive a result that does
   not represent all adapter evidence.

2. **Overlap is intentional; contradiction is not.** The admission script
   explicitly runs named IDs separately so they remain visible when the P2P
   selection excludes them. A named ID can also overlap the P2P selection.
   Therefore rejecting every duplicate would break a valid overlap. The
   required distinction is equal outcomes (safe to collapse) versus differing
   outcomes (an adapter-contract or evidence-consistency failure).

3. **The failure must be loud rather than an ordinary admission rejection.**
   A contradictory result describes an inconsistent tool result, not a
   candidate failing one of checks (a) through (f). The script already uses
   `ScriptError` and exit status 2 for prerequisites and invalid tool output;
   use that path so it cannot be recorded as a normal candidate verdict.

4. **Current caller-path coverage does not protect this boundary.** TC-032
   exercises real admitted packages, and TC-033 exercises each named rejection
   branch through the real entry point. Neither provides overlapping adapter
   documents with different outcomes or asserts that the gate stops before
   `eval-predicate.sh` consumes them. The scenario contract specifies
   normalized `{id, outcome}` adapter entries but does not make the merge
   responsible for arbitrating contradictions.

5. **The relevant existing work is E40-F05 and E40-F11.** E40-F05 established
   execution-based admission, the adapter test-output shape, and the
   separate schema/admission ownership boundary. E40-F11 extended named-ID
   selection to task and epic predicate kinds while retaining the same merge
   helper. TD-087 is a narrow correctness extension of that delivered
   capability.

## Decisions

1. **Preserve the two-query design.** Continue to merge P2P and `--only-id`
   outputs before invoking `eval-predicate.sh`; it is needed to evaluate all
   predicate operands from adapter output.

2. **Reject only contradictory duplicate IDs.** Change `merge_entries` to
   retain the first entry's outcome by normalized ID, accept a later entry
   only when its outcome is identical, and raise `ScriptError` when outcomes
   differ. Include the ID and both outcomes in the error without embedding
   unrelated adapter output.

3. **Treat a contradiction as a script error.** Let the existing top-level
   `ScriptError` handler return exit status 2 and no normal admission verdict.
   Do not map it to check (b) or invent a seventh admission check.

4. **Add a focused caller-path regression test.** Drive the real
   `admit-scenario.sh` entry point with an adapter seam that returns an
   overlapping ID with `pass` from the P2P query and `fail` from the named-ID
   query. Assert exit 2, diagnostic ID/outcomes, and no JSON verdict. Include
   a same-outcome overlap control to prove valid overlap remains admissible.
