# TestUpdateCandidate_DirtyPathDigests lacks cardinality, rename, delete, and clean-tree fixtures

## Description

internal/integration/candidate_test.go's TestUpdateCandidate_DirtyPathDigests only asserts two specific map keys are present, never map cardinality -- so it cannot catch a regression in computeDirtyPathDigests' .shark/-exclusion branch (candidate.go, which exists specifically so the candidate's own on-disk files never leak into its own digest map) or its rename/copy-entry-skip branch. A deleted-tracked-file case and a fully-clean-tree case are also untested. Confirmed both subtests use presence checks (got, ok := candidate.XPathDigests[...]) with no len(...) assertion anywhere, while RecordEvent/UpdateCandidate actively write files under .shark/ as untracked entries during this very test run -- meaning deleting the exclusion would leave this test green. Fix: add exact-cardinality assertions (len(candidate.TrackedPathDigests)/len(candidate.UntrackedPathDigests)), a git mv rename fixture, a deleted-tracked-file fixture, and a clean-tree fixture. From code-review of the E34 (F06-F11) integration diff, finding F11 (non-blocker).
