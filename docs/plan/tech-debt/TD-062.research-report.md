# TD-062 research report

## Scope

Restore the no-dependency `--parallel` update fast path without weakening the B048 rule that a supplied `--depends-on` value is validated before persistence.

## Findings

The TD-061 hoist makes every update call `ValidateTaskDependencies`; that is correct for changed dependencies but makes an order-only `--parallel` update read dependencies for legacy-invalid rows. The validator is a no-op only after its caller has entered it, so the guard belongs at the common update seam. A nil, empty, or `[]` dependency field needs no validation; a supplied value must continue to reject invalid keys before `updateRowDirect`.

## Decisions

Implement a narrow presence guard around dependency validation and add a test that proves an order-only no-resequence update succeeds for a persisted legacy-invalid value while an explicit invalid dependency still fails. Do not change dependency rules or the normal resequencing path.
