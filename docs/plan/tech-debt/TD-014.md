# Prove partial-based rendering path is exercised end-to-end for bug entities

## Description

The B025 fix added a server-computed `review_base` placeholder and switched the `_code_review_process.md`, `_qa_process.md`, and `_uat_redteam_review.md` partials from agent-body kebab tokens (`<review-base>`) to Go-template directives (`{{.review_base}}`). The fix is correct and forward-compatible.

However, during the B025 tech-lead code review it was observed that `./bin/shark next B020 --json` (B020 is the canonical test bug at `ready_for_code_review`) reaches the post-render guard without going through the partial-based path at all — it succeeds via the **orchestrator-action fallback** code path in `internal/cli/commands/next.go`. Meaning: bug entities currently don't load `_code_review_process.md` / `_qa_process.md` / `_uat_redteam_review.md` at runtime.

So while the regression test (`TestDeriveReviewBase`, `TestEntityPlaceholders_PopulatesReviewBase`) covers the helper logic, there is no end-to-end test that exercises the partial-rendering path for bugs. The fix is dormant: when bugs adopt partial-based rendering (probably under E32 / shark 2.0 consolidation), the `review_base` plumbing will be there — but its first live exercise will be unsupervised.

## Impact

- Low today: the fix is correct, regression tests cover the helper, no user-visible problem.
- Latent risk: when bugs migrate to partial-based rendering, an integration-level mistake (e.g., the bug workflow never actually loads `_code_review_process.md`) would surface only at that migration, not now.
- Audit-trail risk: the B025 code review claimed end-to-end verification of the partial path, but the verification was actually of the helper + the orchestrator-action fallback path. A future regression that breaks partial-loading for bugs would not be caught by current tests.

## Resolution Plan

One of the following:

1. **Add an integration test** that loads a bug's `ready_for_code_review` action via the partial path and asserts the rendered prompt contains the expected `review_base` substitution. This requires either (a) bugs actually adopting the partial-based rendering, or (b) a test harness that forces the partial path for an entity that doesn't use it in production.

2. **Document explicitly** in `internal/cli/commands/next.go` (or wherever the path divergence lives) that bugs currently go through the orchestrator-action fallback, with a TODO citing this tech-debt as the resolution gate when bugs migrate.

3. **Migrate bugs to the partial path** as part of E32-F02 (engine) work — at which point this tech-debt becomes the regression-test deliverable for that migration.

Option 3 is most likely the right path since it converges with the E32 shark-2.0 consolidation. Resolve via the E32-F02 migration work rather than as a standalone task.
