# I-02/I-03 schema has no dedicated field for recurrence classification

## Description

REQ-F-005 (E34-F06) requires classifying a matched defect-class instance as recurrence vs normal finding, but neither I-02 GateResult.Finding.disposition (open|fixed|already_dispositioned|severity_conflict|not_reproducible) nor I-03 DefectClassSweep.instances[].disposition (fixed|dispositioned|open) has a value for it. E34-F06's defect-class-sweep.md workflow works around this by requiring the recurrence classification to be stated explicitly inside the existing instance evidence string rather than as a structured field, to avoid a single feature unilaterally widening a shared cross-feature contract. Epic owner should decide whether I-02/I-03 warrant an explicit recurrence field/pointer in a future revision, weighed against the churn of updating every consumer (E34-F07, E34-F08).

## Impact

Recurrence is currently only discoverable by reading free-text `evidence`
strings rather than filtering/querying a structured field — acceptable for
now but not machine-queryable across many instances/features.

## Resolution Plan

If cross-feature demand for querying recurrence emerges (e.g. E34-F08
analytics), add a `recurrence: bool` (or richer pointer) field to I-03
`instances[]` and thread it through every consumer's contract test in one
coordinated change, not piecemeal per-feature.
