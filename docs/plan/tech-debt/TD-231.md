# Improve failure diagnostics for TestConsolidatorRoutesNonBlockersThroughTriage

## Description

require.Contains on the ~9KB consolidator.md content dumps the whole file into the test failure message on mismatch, burying the diagnosis. Use a targeted assert (e.g. check substring presence via a boolean + t.Errorf with just the missing phrase) instead. Found during B066 code review (docs/review/bugs/b066/code-review-20260916T040348Z-B066.md, finding F4).

## Impact

Medium. On assertion failure the whole ~9KB `consolidator.md` body was
interpolated into the test output, so the actual diagnosis — which phrase was
missing, or which forbidden phrase was present — was buried in a wall of
unrelated text. The same pattern applied to two sibling tests in the same file
that assert over rendered templates and file contents.

## Resolution Plan

Replace `require.Contains`/`require.NotContains` over large content with
`strings.Contains` + `t.Errorf` that reports only the phrase, never the
haystack, matching the idiom already used in
`internal/cli/commands/controller_stage_error_rework_test.go`. Keep
`require.NoError` on the file reads and template renders — a missing file should
abort, since every later assertion would be meaningless.
