# TD-211 research report

## Scope

Assess whether the proposed `TC-I-02-GATERESULT-PARITY` test can exercise the
three named downstream consumers through real GateResult construction paths.

## Research checklist

- [x] `scope_vocabulary` — Evidence: docs/plan/E34-prompt-and-skill-improvements/architecture.md
- [x] `affected_implementation_or_contract` — Evidence: internal/gateresult/gateresult.go
- [x] `pattern_contract` — Evidence: docs/plan/E34-prompt-and-skill-improvements/E34-interaction-map.md
- [x] `dependency_impact` — Evidence: docs/plan/E34-prompt-and-skill-improvements/E34-F06-defect-class-completeness-and-recurrence-routing/spec.md; docs/plan/E34-prompt-and-skill-improvements/E34-F07-state-space-planning-and-decision-propagation/spec.md; docs/plan/E34-prompt-and-skill-improvements/E34-F08-tier-consistent-gates-and-final-integration-review/spec.md

## Findings

`architecture.md#i-02-gateresult-v1` defines I-02 with the optional
`remediation_sweeps` and `change_impacts` arrays. `internal/gateresult`
implements and validates those fields.

E34-F06 documents `remediation_sweeps` as its I-02 extension, and E34-F07
documents `change_impacts` as its I-02 extension. E34-F08 instead documents
`adoption_manifest` as an I-05 prompt-level sibling in an integration-review
GateResult example. The I-02 architecture table and `internal/gateresult` do
not declare or construct an `adoption_manifest` field.

Therefore, no three-consumer runtime construction path exists. A test that
claims to round-trip F08 through the I-02 model would test an invented contract
and would mask the boundary between I-02 and I-05.

## Capability map

| Capability | Existing evidence | Decision |
| --- | --- | --- |
| I-02 GateResult validation | `internal/gateresult/gateresult.go` and `internal/gateresult/gateresult_test.go` | REUSE |
| I-03 remediation-sweep extension | E34-F06 specification and I-02 model | EXTEND |
| I-04 change-impact extension | E34-F07 specification and I-02 model | EXTEND |
| I-05 adoption manifest | E34-F08 integration-review prompt and architecture I-05 section | CONTRADICTS the TD-211 three-consumer premise |

## Decisions

Do not implement the proposed `TC-I-02-GATERESULT-PARITY` as written. The
test's required F08 construction path is absent by design, and the test would
misrepresent I-05 as an I-02 schema field.

The existing I-02 parser and validation tests remain the authoritative model
coverage. If a future requirement promotes `adoption_manifest` into the
executable I-02 model, create a coordinated schema revision and a new
cross-consumer contract test for that revised schema.
