# Replace hardcoded status strings in service layer with workflow.Service calls

## Description

Five service files hardcode workflow status strings instead of deriving them from workflow.Service. Affects: feature_progress_service.go (lines 317, 399, 454 — 'blocked'), epic_analytics_service.go (line 82 — 'completed'/'archived'), display_service.go (lines 289, 505, 561, 572 — 'blocked'/'completed'/'archived'/'ready_for_review'), sprint_analytics_service.go (lines 141, 283, 524-531 — multiple sprint+entity statuses), viewer_service.go (lines 662, 702 — 'active'/'planning'/'completed'/'archived'). Fix: use workflowSvc.ForLevel(level).GetTerminalStatuses(), GetStatusesByPhase('blocked'), IsTerminalStatus() as appropriate per entity level.
