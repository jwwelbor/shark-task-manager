# Dead PortfolioWarning constants + stale spec.md failure-modes rows after TD-043 single-snapshot collapse

## Description

PortfolioWarningChildStateUnavailable (CHILD_STATE_UNAVAILABLE) and PortfolioWarningRelationshipStateUnavailable (RELATIONSHIP_STATE_UNAVAILABLE) in internal/models/portfolio_advice.go are dead production constants: TD-043 deleted their only producers when it collapsed PortfolioAdviceService.Advise onto a single-snapshot read. docs/plan/E36-project-layer-and-consult-bridge/E36-F04-portfolio-aware-next-action-advisor/spec.md's Failure-modes table (rows ~367-368) still documents the removed two-query failure mechanism. Fix: remove the two dead constants and the corresponding stale spec.md rows, or mark them explicitly reserved/deprecated. See code review finding F4.

## Impact

Low. Purely accuracy debt: a future maintainer grepping for `CHILD_STATE_UNAVAILABLE`/`RELATIONSHIP_STATE_UNAVAILABLE` in `spec.md`'s Failure-modes table would assume a live emission path exists when it does not. The underlying `evidence_complete=false` contract these codes gestured at remains fully live via other producers (`portfolio_child_evidence.go`, `portfolio_relationship_evidence.go`, `portfolio_advice_finalize.go`), so no consumer-facing behavior is affected.

## Resolution Plan

Remove `PortfolioWarningChildStateUnavailable` and `PortfolioWarningRelationshipStateUnavailable` from `internal/models/portfolio_advice.go` (verify no remaining references outside the pure string-identity test at `internal/models/portfolio_advice_test.go:209-210`, and update that test), and remove or rewrite the corresponding "Descendant-state query fails" / "Relationship query fails" rows in `docs/plan/E36-project-layer-and-consult-bridge/E36-F04-portfolio-aware-next-action-advisor/spec.md`'s Failure-modes table (~lines 367-368) to reflect the single-snapshot fail-fast model.
