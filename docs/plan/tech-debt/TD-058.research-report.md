# TD-058 research report

## Scope

TD-058 concerns regression coverage for the seven forbidden markers enforced
by `models.ValidateQuestionBoundedText`: `api_key`, `password=`,
`authorization:`, `bearer `, `system prompt`, `user prompt`, and `assistant:`.
The original finding correctly identified that `internal/models/question_test.go`
covered only an `api_key`-shaped value when the debt was recorded.

The affected capability is bounded Question content before it can be persisted,
routed, or used as terminal provenance. This report determines whether current
coverage now protects all seven markers. It does not reopen the separately
recorded TD-073 delimiter-variant work, alter the validator, or expand TD-058
into a general rewrite of every UTF-8 and byte-boundary test.

## Findings

1. **The original unit-test gap existed, but the marker coverage has since
   been remediated.** The original E39 model test contains only the
   `api_key=secret` state fixture. Commit `9eb07d63` added E38-F09's
   `TC-SEC-01-01`, which calls the real shared validator for every one of the
   seven literal marker classes across both persisted free-text fields:
   `responses.summary` and `responses.evidence_pointer`. That gives fourteen
   direct policy cases rather than one indirect state fixture.

2. **The remediation protects the correct capability boundary.** The
   contract deliberately redeclares the expected seven literals instead of
   importing production data. If a future edit removes or changes a marker in
   `ValidateQuestionBoundedText` without updating the contract intentionally,
   the direct validation subtest fails. The test also asserts the stable
   forbidden-material error class.

3. **The write boundary has separate evidence.** `TC-SEC-01-01` uses a real
   database and the real `shark question respond` command to prove forbidden
   values fail before a Question's status or `context_data` changes. It uses
   one marker per response field at that sink, while the direct table supplies
   exhaustive all-marker coverage. This division is appropriate: it avoids a
   redundant fourteen-command integration matrix while proving both policy and
   persistence behavior.

4. **This is an extension of coverage, not a replacement validator.** The
   shared implementation remains the sole policy seam for Question-state
   content, terminal reasons, and focused read identities. The E38-F09 test
   adds cross-component coverage around that seam; it neither replaces the
   E39 model test nor introduces a second allowlist.

5. **The original record also mentioned generic input validation, but that
   is not evidence that the marker debt remains open.** Existing tests cover
   terminal-reason byte boundaries and an untrimmed Question-read actor. They
   do not form a single exhaustive direct-validator matrix for invalid UTF-8
   and every min/max input shape. Treat any desired expansion of that generic
   validation coverage as separate follow-up work, rather than holding the
   specific seven-marker debt open after its stated impact is fixed.

6. **Related-document registration is unsupported for TD-058.** The current
   command accepts epic, feature, task, bug, change-card, and Question parents
   only. Registering this sidecar would require unrelated CLI and service work.
   The adjacent report path is the supported durable record.

## Decisions

1. **Close TD-058 as already remediated.** `TC-SEC-01-01` protects all seven
   forbidden marker classes directly and proves the public response write path
   rejects forbidden content before persistence.

2. **Retain the literal contract table.** Do not derive its marker set from
   `ValidateQuestionBoundedText`; independent literals are the regression
   guard TD-058 needs.

3. **Keep TD-073 separate.** Its whitespace and punctuation permutations
   address a different failure mode from TD-058's missing all-marker coverage.

4. **Do not add a related-document link.** Tech-debt entities are not a
   supported `related-docs` parent. Extending that capability is outside this
   debt item.

**Recommended outcome: pass.** The reported seven-marker coverage gap has
already been closed by the E38-F09 contract suite and verified in the current
worktree. No duplicate test or implementation change is required for TD-058.
