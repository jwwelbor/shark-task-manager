# TD-223 research report — deduplicated provider-active windows

## Scope

Make `provider_active_claims` subtract windows accepted earlier in the same
worker envelope as well as driver-observed categories, preserving the existing
time-ledger interval format and verifier contract.

## Research checklist

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-223.md`
- [x] `affected_implementation_or_contract` — Evidence: `bench/scripts/run-lifecycle.sh:916-1028,1770`
- [x] `pattern_contract` — Evidence: `bench/scripts/verify-stage-evidence.sh:148-177`; `bench/scripts/tests/tc115_i05_producer_test.sh`

## Findings

The reducer uses a fixed `claimed_so_far` input while accepting multiple
provider windows. Overlapping windows from one envelope can therefore be
emitted twice even though the verifier requires pairwise non-overlap.

### Capability map

| Capability | Decision | TD-223 action |
|---|---|---|
| Existing interval subtraction | EXTEND | Add each accepted fragment to the local claimed union. |
| Ledger verifier | REUSE | Keep its non-overlap contract unchanged. |

## Decisions

1. Maintain a local normalized claimed union initialized from caller claims.
2. Add accepted fragments before processing the next raw provider interval.
