# internal/integration package: no context.Context, git subprocesses can hang hot dispatch loop

## Description

Every exported entrypoint in internal/integration (CaptureBase, GetRun, CurrentCommit, UpdateCandidate, GetCandidate, VerifyBaseReachable, AnalyzeHistory, AcquireRegistrationLock) and all 9 of the package's git subprocess calls omit context.Context, using exec.Command instead of exec.CommandContext, contrary to docs/architecture/coding-standards.md's Context section. FeatureService.recordIntegrationEventForTerminalTransition calls CurrentCommit/RecordEvent/UpdateCandidate synchronously on every terminal feature transition -- a stuck git subprocess (e.g. contended .git/index.lock from concurrent Claude/Codex sessions sharing one checkout, a documented real pattern in this repo) would hang shark next/shark run/shark status advance with no recourse but killing the process. Fix: thread ctx through the package's exported functions and git-shelling helpers, switching exec.Command to exec.CommandContext. From code-review of the E34 (F06-F11) integration diff, finding F3 (non-blocker: continues an existing weaker codebase norm, e.g. internal/fileops has the same shape; strongest convergent signal, flagged by 3 of 6 review angles).
