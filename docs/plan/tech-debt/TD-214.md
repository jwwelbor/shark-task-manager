# internal/integration: atomic publish-via-temp-file protocol duplicated 3x

## Description

The 'marshal -> mkdir -> write temp file -> os.Link onto shared path -> on EEXIST read back winner' crash-safe publish protocol is implemented independently in publishEvent (event.go), publishRun (run.go), and persistReplacementRecord (history.go) -- nearly line-for-line, differing only in marshaled type and error text. persistReplacementRecord's own doc comment names this as mirroring the other two, meaning the duplication was seen and hand-copied a third time rather than factored out. Fix: extract one shared helper, e.g. publishOnce[T any](path, tmpPath string, value *T, readBack func(string) (*T, error)) (*T, error), or a narrower atomicLinkPublish(tmpPath, path string) (won bool, err error) each caller wraps. From code-review of the E34 (F06-F11) integration diff, finding F4 (non-blocker per the repo's formal sibling-check threshold of >=3 implementors of a shared interface, which doesn't apply here -- but three independently-maintained copies of a correctness-sensitive crash-safety protocol is real maintainability debt).
