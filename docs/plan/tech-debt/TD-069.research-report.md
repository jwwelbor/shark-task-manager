# TD-069 research report

## Scope

Make `shark task list E38-F09` apply both its epic and feature filters, matching the documented combined feature-key form.

## Research checklist

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-069.md:1-21`; `internal/cli/commands/task.go:103-115`.
- [x] `affected_implementation_or_contract` — Evidence: `internal/cli/commands/task.go:103-146`; `internal/services/task_service.go` task filter contract.
- [x] `pattern_contract` — Evidence: `internal/cli/commands/helpers.go:146-195` already parses combined feature keys.
- [x] `dependency_impact` — Evidence: `internal/cli/commands/list.go:176-184` delegates the two-positional filtering path to `runTaskList`.

## Capability map

| Capability | Source | Decision |
| --- | --- | --- |
| Combined feature-key parsing | `ParseTaskListArgs` and `ParseFeatureKey` | REUSE — derive canonical epic and feature components. |
| Task list filter dispatch | `runTaskList` | EXTEND — apply parsed components for a single combined positional key. |

## Findings

The command already normalizes a two-argument feature suffix, but a single combined key is assigned only to `EpicKey`, producing an empty result set. Existing key helpers validate and split the required format.

## Decisions

Recognize a valid combined positional feature key before task service dispatch, derive its epic component, and pass the canonical full feature key as `FeatureKey`. Retain flag behavior and existing one-epic/two-positional forms.
