# run-lifecycle.sh I-05 writer: length/DRY/altitude cleanup

## Description

E40-F12 deep-review (angle-D) flagged three related maintainability items in bench/scripts/run-lifecycle.sh's I05BundleWriter subsystem, all non-blocking: (1) record_stage() is ~94 lines mixing four jobs (snapshot assembly, stage-snapshot write, transcript write, index/bundle rewrite) -- extract _write_stage_snapshot()/_write_transcript() helpers. (2) stage_category_map(), usage_mapping_providers(), and i05_schema_version() are three near-identical cached-YAML-loader functions differing only in filename/key/error text -- extract a shared _load_yaml_table() helper. (3) The diff nearly doubled run-lifecycle.sh (905->1656 lines) by inlining the whole I-05 subsystem rather than reusing the importlib.util.spec_from_file_location cross-script-sharing pattern bench/scripts/verify-retention-manifest.sh already demonstrates; canonical_digest/content_digest-style helpers are now hand-duplicated across 5+ files. Consider extracting I05BundleWriter + its digest/YAML-table helpers into bench/scripts/lib/i05_bundle_writer.py.

## Impact

Low today: control flow stays shallow and each duplicated loader is independently correct. The cost compounds as future T-E40-F12-* (or sibling E40-F*) work keeps adding fields to `run-lifecycle.sh`, and as `evaluate-lifecycle.sh` keeps hand-copying the same digest helpers instead of sharing them — the file is already the largest bash-wrapped script in `bench/scripts/`.

## Resolution Plan

1. Extract `_write_stage_snapshot(snapshot, ordinal, stage_key) -> digest` and `_write_transcript(worker_envelope, ordinal, stage_key)` out of `I05BundleWriter.record_stage()`.
2. Extract a shared `_load_yaml_table(relative_path, key=None, error_label=...)` helper used by `stage_category_map()`, `usage_mapping_providers()`, and `i05_schema_version()`.
3. Evaluate extracting `I05BundleWriter` and its digest/YAML-table helpers into `bench/scripts/lib/i05_bundle_writer.py`, loaded via the same `importlib.util.spec_from_file_location` pattern `bench/scripts/verify-retention-manifest.sh` already uses, so `evaluate-lifecycle.sh` can import the same `content_digest`/`canonical_digest` instead of re-copying them.
