# shark task create --depends-on silently fails to persist dependency relationships

## Description

Reported independently by two task-generation dispatches (E34-F07): 'shark task create ... --depends-on=<key>' is accepted with no error but does not create a depends_on relationship row — 'shark task deps <key>' shows nothing until 'shark task link <a> <b> --type=depends_on' is run manually afterward. This is a silent data-loss bug: a task-generation agent that doesn't independently verify via 'shark task deps' would ship a feature with an unenforced dependency graph. Reproduce with 'shark task create <epic> <feature> "title" --depends-on=<other-task-key>' then 'shark task deps <key>' showing no relationship; compare against 'shark task link' which works correctly.
