# Workstream 2 items 3-5 (consolidator disposition fixtures, fingerprint rerun dedup) need an LLM eval harness, not Go tests

## Description

dev-artifacts/2026-09-15-review-triage-and-agent-attention-plan/plan.md Workstream 2 asks for: (3) consolidator fixtures covering 5 disposition scenarios (bug, task/fix-now, duplicate-link, tech-debt, no-action nit); (4) finish-feature tests proving unresolved findings stop progression; (5) a rerun test proving stable fingerprints dedupe. Items 1/2/6 are done: TestEmbedded_ReviewFindingsRouteThroughTriage and TestConsolidatorRoutesNonBlockersThroughTriage (policy-phrase rejection), the rendered-prompt goldens (regenerated, in sync across review/tech-lead paths), and TestEmbedded_NonBlockersCarryStableFingerprint/TestConsolidatorNonBlockersCarryStableFingerprint (fingerprint field presence) plus a verified diff -r showing the installed skill bundle matches the repo byte-for-byte (deployment verification). Items 3 and 5 cannot be Go unit tests: consolidator.md and triage/SKILL.md's Step 3 dedup search are prompts followed by an LLM at review time, not executable code with a callable entrypoint -- classifying a scenario into one of 5 dispositions, or proving a fingerprint search actually dedupes across two review runs, requires running a real model against fixture scenarios and grading its output (an eval), not asserting on file content the way the existing regression gates do. Item 4 (finish-feature) is a user-global skill outside this repository (already established by TD-232) and cannot be gated from a shark-task-manager commit. Introducing an LLM eval harness is a new testing-platform capability (CLAUDE.md Rule 16 territory) requiring owner ratification, not something to build unilaterally to close out a checklist item.

## Impact

Without these, the plan's Workstream 2 acceptance evidence for
disposition-classification correctness and cross-run fingerprint dedup
rests on the prose in review-code.md/consolidator.md/triage/SKILL.md
being followed correctly by whichever model runs a review, with no
automated check catching a regression in classification behavior itself
(as opposed to the presence of the right words in the prompt, which the
existing regression gates do check).

## Resolution Plan

Requires an owner decision (CLAUDE.md Rule 16: new testing-platform
capability) on whether to build an LLM eval harness for shark's prompt
skills before this can be scoped further. If ratified: define the 5
consolidator disposition fixtures as scenario+expected-classification
pairs, run them against a pinned model, and grade the classification
output; define a two-run fingerprint scenario (same defect, two separate
triage invocations) and assert the second invocation links rather than
duplicates. Until that decision is made, this stays a named, tracked gap
rather than a silent one.
