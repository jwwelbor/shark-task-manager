# Research report: TD-228

## Scope

TD-228 closes one regression-coverage gap in the shared I-05 Go contract test. The affected vocabulary is an artifact's optional `consumers` array and its typed consumer edge: exactly `consuming_stage`, `edge_kind`, and `observed_at`. The work must prove that an otherwise valid consumer carrying an additional field is rejected. It does not change the I-05 schema, permitted consumer fields, or production validator behavior.

## Findings

PR #219 (B064) added the Go contract-test rejection loop that reports an unexpected key on a consumer edge. Its only direct consumer fixture omits `observed_at`, so it proves required-field rejection but never reaches the loop's unexpected-field branch. Removing that loop would leave the current contract test green.

The production-side remediation already centralizes typed-consumer validation in `bench/scripts/lib/i05_validation.py`. It rejects any consumer whose key set differs from the three required fields, and its callers use the result to reject malformed evidence. `tc046_artifact_record_test.sh` covers the missing-`observed_at` case, which confirms the existing required-field behavior but not this Go contract-test branch.

The affected capability is the shared `TestTC042_I05StageEvidenceContract` contract used across E40 consumers. TD-228 extends its fixture coverage only; it neither replaces B064's single-owner production validation nor changes the schema contract.

## Decisions

Use the existing `artifact_consumer_edge_fields_required` subtest and add an otherwise valid typed consumer with `observed_at` plus one extra key such as `unexpected_field`. Assert that `e40I05ValidateArtifacts` returns an error naming that key or the unexpected-field condition. Keep the existing missing-`observed_at` assertion because it protects a separate required-field branch.

Do not add a new validator, schema field, fixture hierarchy, or duplicate production-script test. The smallest durable change is a second negative fixture in the shared Go contract test, aligned with the closed-field-set rule already enforced by B064's reused validator.
