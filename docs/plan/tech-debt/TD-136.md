# E40-F10: install_atomic_file duplicated verbatim between lib/retain_pair and run-lifecycle-batch.sh's own inline copy

## Description

bench/scripts/lib/retain_pair's install_atomic_file(target: Path, data: bytes) and run-lifecycle-batch.sh's own inline install_atomic_file(target_path: str, data: bytes) (added in the round-4 audit-sweep commit 3bb7688b for batch.json/invalid/index.jsonl) are logically identical (tempfile.mkstemp + fsync + os.replace, same exception handling), just with a Path vs str signature difference. Same DRY family as the already-tracked digest_of_path duplication (4 independent implementations, carried as non-blocker tech-debt since round 2/3). A future edit to one atomic-install primitive without mirroring the other risks silent divergence, matching this feature's own established risk pattern (digest_of_path's round-2 divergence WAS a real blocker). Recommend extracting a shared python helper module both drivers can source/import, or accept as intentional duplication given each is invoked via a separate python3 heredoc subprocess with no existing shared-module precedent in bench/scripts/. Found during E40-F10 round-5 code review (tech-lead).
