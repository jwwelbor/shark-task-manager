# ErrInvalidNoteType sentinel message string is stale (omits review, drifts from validator allowlist)

## Description

The ErrInvalidNoteType sentinel at internal/models/validation.go:29 lists an outdated set of valid note types ('comment, decision, blocker, solution, reference, implementation, testing, future, question, rejection, or requirement') and omits 'review'. The validator function (ValidateNoteType) itself accepts 'review' correctly — only the human-readable error message string is stale. Surfaced during B027 round-2 QA. Fix: regenerate the error message from the validTypes allowlist (or a shared constant) so the message can never drift from the validator again.

## Impact

Low. Only surfaces when a user supplies an invalid `--type` value to `shark create note`. The error still correctly identifies the input as invalid; the listed alternatives are just incomplete. Discoverability of valid types from the error message is the only practical impact.

Drift risk is the larger concern: the message is now decoupled from the `validTypes` allowlist, so any future addition to the allowlist will silently make the message more stale.

## Resolution Plan

Generate the message from the allowlist instead of hardcoding it. Either:
- Build the list dynamically in `ValidateNoteType` when constructing the error (sort keys of `validTypes` map), or
- Extract the allowed types into a shared `[]string` constant that both `validTypes` and the error message consume.

The second is simpler if the order of types in the message matters for readability.
