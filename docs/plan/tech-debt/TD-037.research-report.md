# TD-037 research report

## Scope

Reduce the complexity of sprint close without changing its transaction ownership or carryover behavior.

## Research checklist

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-037.md`; `internal/services/sprint_service.go:2216-2450`.
- [x] `affected_implementation_or_contract` — Evidence: `internal/services/sprint_close_test.go:116-500` covers completion, carryover, defaults, and rollback.
- [x] `pattern_contract` — Evidence: `internal/services/sprint_service.go:2282-2445` keeps assignment changes, terminal status, completion insert, and commit transaction-owned.

## Capability map

| Capability | Decision |
| --- | --- |
| Next planning sprint selection | EXTEND with a dedicated helper preserving create-or-reuse behavior. |
| Completion write | EXTEND with one transaction-owned status-and-completion helper. |

## Findings

`CloseSprintWithCarryover` mixed orchestration, planning-sprint selection, reassignment, and final transaction writes. The existing tests establish that selection failures occur before assignment mutation and that status/completion failure rolls back the transaction.

## Decisions

Extract `nextPlanningSprint` and `recordSprintCloseTx`; retain the public close orchestration, carryover switch, and transaction boundary unchanged.
