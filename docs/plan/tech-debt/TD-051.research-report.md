# TD-051 research report

## Scope

TD-051 corrects remnants of the former multi-read portfolio-advice path after
TD-043 made `PortfolioAdviceService.Advise` depend on one complete snapshot.
The two affected warning codes are `CHILD_STATE_UNAVAILABLE` and
`RELATIONSHIP_STATE_UNAVAILABLE`. They remain declared and identity-tested, but
no current producer can emit them. The E36-F04 failure-modes table still
describes separate descendant-state and relationship queries that the current
service no longer performs.

This repair removes dead public model constants and aligns the documented
failure model with the single-snapshot contract. It preserves live
`evidence_complete=false` warnings for invalid workflow status, dangling
relationships, and invalid active-claim progress. It does not change portfolio
selection, ordering, snapshot contents, or runtime error handling.

## Findings

1. **TD-043 already removed both production paths.** Commit `06e65f94`
   deleted `readPortfolioAdviceEvidence` and its separate child and
   relationship error values. `Advise` now calls `ReadSnapshot` once. A
   snapshot-read error returns a wrapped error and no advice envelope before
   child, relationship, or claim evidence is assembled.

2. **The two named constants are dead.** Their only current references are
   their declarations in `portfolio_advice.go` and string-identity entries in
   `portfolio_advice_test.go`. No service, CLI, API, or consumer emits either
   warning code. Keeping the test entries only proves the obsolete strings
   remain public; it does not protect live behavior.

3. **Incomplete evidence remains a live, narrower contract.** Unknown
   workflow statuses, dangling relationship endpoints, and invalid claim
   progress still set `EvidenceComplete` to false and emit respectively
   `UNKNOWN_WORKFLOW_STATUS`, `DANGLING_RELATIONSHIP`, or
   `CLAIM_STATE_UNAVAILABLE`. `PortfolioPlanningService.Plan` pauses when
   `EvidenceComplete` is false. Removing the two dead codes must not remove or
   weaken these producers.

4. **Three spec rows, not only two, need single-snapshot alignment.** The
   descendant-state and relationship-query rows are stale as TD-051 states.
   The adjacent active-claim-read row is stale for the same reason: claims now
   arrive in the snapshot and `FilterActiveReadOnly` has no error return. Keep
   the live `CLAIM_STATE_UNAVAILABLE` documentation, but rewrite it to the
   actual invalid-claim-progress condition. Replace all three independent-read
   rows with one snapshot-read failure row plus the existing per-record
   degradation rows.

5. **Remove rather than reserve the two codes.** There is no wire consumer or
   documented compatibility commitment that needs the strings preserved, and
   reserving them would continue to imply a possible runtime emission. Removal
   matches the single-snapshot implementation and keeps the warning vocabulary
   truthful.

6. **A related-document link cannot be registered.** The current
   `related-docs` command accepts epic, feature, task, bug, change-card, and
   Question parents only. The standard adjacent report is the supported
   durable artifact for a tech-debt entity.

## Decisions

1. **Remove `PortfolioWarningChildStateUnavailable` and
   `PortfolioWarningRelationshipStateUnavailable`.** Remove their two
   corresponding rows from the warning-code identity test. Do not mark them
   reserved or deprecated.

2. **Rewrite the failure-modes table around `ReadSnapshot`.** State that an
   unavailable snapshot or cancelled context returns a wrapped error with no
   envelope. Remove the two obsolete per-query failure rows.

3. **Correct the adjacent active-claim row.** Do not document a separate
   claim-read failure. Describe the live invalid active-claim-progress case as
   incomplete evidence with `CLAIM_STATE_UNAVAILABLE`, while preserving its
   no-sensitive-claim-data guarantee.

4. **Preserve all remaining incomplete-evidence producers and planning
   pause behavior.** Focused service tests should continue to prove snapshot
   failure is fatal and malformed in-snapshot evidence pauses portfolio
   planning without exposing secrets.

5. **Do not register a related document.** Tech-debt entities remain
   unsupported parents for `related-docs`; adding that transport is outside
   TD-051.

**Recommended outcome: implement.** Make the narrow constant/test/spec
cleanup, including the stale adjacent claim-read documentation row. The change
extends TD-043's completed single-snapshot remediation; it does not replace
the live partial-evidence contract.
