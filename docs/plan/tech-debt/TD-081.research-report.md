# TD-081 research report

## Scope

Distinguish an executed-and-failed quality gate from a gate whose command could not execute.

- [x] `scope_vocabulary` — Evidence: `docs/plan/tech-debt/TD-081.md`; `docs/plan/E40-shark-bench-workflow-benchmarking-harness/E40-F02-bench-harness-run-driver-and-metric-collection/spec.md:84`.
- [x] `affected_implementation_or_contract` — Evidence: `bench/scripts/run-one.sh:642-700`; `bench/scripts/collect-run.sh:838-875`.
- [x] `dependency_impact` — Evidence: `bench/scripts/aggregate-runs.sh:755-770` excludes null gate values rather than treating them as failures.

## Capability map

| Capability | Decision |
| --- | --- |
| Quality-gate null value | EXTEND with a retained per-gate reason. |

## Findings

The sidecar contract named a reason for null status but the driver only wrote pass/fail, and the collector discarded the reason. Exit statuses 126/127 were therefore indistinguishable from a real test failure.

## Decisions

Map 126/127 to null with a command-specific reason, require that reason at collection, and retain it in `quality.gate_reasons` alongside the null metric.
