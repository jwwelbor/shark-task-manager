# TD-131 research report — held-back source digest handoff

## Scope

Assess whether the E40-F09 held-back oracle's path handoff to the I-05 broker
can execute bytes other than the evaluator sources the oracle identified. The
question is limited to benchmark evidence integrity: it does not claim a
worker-to-host escape or broaden the I-05 authorization boundary.

## Findings

`resolve_oracle_sources()` calculates a digest for the resolved source set, but
`grant_and_validate_access()` passes only paths to the broker. The broker and
registered adapters reopen and copy those paths, then record the destination
digest in `access.jsonl`. The oracle validates requested paths, cardinality,
and destination containment but does not compare the recorded copied-byte
digest to the earlier source digest.

An evaluator-root writer can therefore replace a source after resolution and
before the adapter copy. The predicate can run the replacement while the
reported `test_digest` identifies the old source. Existing TC-048 and TC-068
coverage proves ordering, isolation, adapter invocation, and normal-copy
digest recording, but not a disagreement between the pinned and copied bytes.
The practical impact is benchmark-integrity corruption under a concurrent
writer, not a privilege-boundary escape.

Current verification ran TC-048 successfully. TC-068 reaches its
adapter-destination-collision partition but fails before later partitions:
the test expects `cleanup_failure`, while the real adapter refuses the
pre-existing destination before injection and the oracle maps that broker
failure to `isolation_violation`. That stale expectation is a separate test
contract defect, not evidence against the source-digest finding; it must be
triaged separately rather than silently changing this research-only branch.

## Decisions

Implement a scoped, oracle-local remediation: preserve a per-source SHA-256
at resolution, join each returned access event to its expected source, and
fail closed with a named `source_changed` or `isolation_violation` result when
the copied digest differs. Restore the checkout before exit and add a
deterministic source-swap regression that changes a held-back source between
resolution and adapter copy.

Do not change the broker interface first. An additive broker manifest could
be a future systemic hardening, but the existing access-event digest supplies
the required evidence for this bounded fix. Commit `2ed6f3f7` explains why the
subprocess handoff was outside the original change; it is not a current
correctness exception.
