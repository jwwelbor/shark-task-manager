# task update --depends-on flag is a silent no-op

## Description

`internal/cli/commands/task_helpers.go:384` registers a `--depends-on` flag on
`shark task update` ("New comma-separated dependency task keys"), but
`parseTaskUpdates` (`task_helpers.go:272-312`) never reads it, and
`services.TaskUpdates` (`internal/services/task_dto.go:44-69`) has no
`DependsOn` field to carry the value even if it were read. `shark task update
<key> --depends-on <keys>` exits 0 with no warning and leaves the task's
`depends_on` completely unchanged. Found while resolving TD-063.

## Impact

Users/agents attempting to change a task's dependencies via `shark task
update` get silent no-op behavior with no error — the command appears to
succeed but the update never happens. The only currently-working way to
change `depends_on` after creation is `shark task link --depends-on` (which
writes to the separate `entity_relationships` table, not the `depends_on`
JSON field) or direct database/file edits. Low severity because
`--depends-on` on create still works, and `task link` is a working
alternative for adding dependencies, but the dead flag is misleading and
should either be wired up or removed.

## Resolution Plan

Pick one:
1. Wire it up: add a `DependsOn *[]string` (or similar) field to
   `services.TaskUpdates`, read `--depends-on` in `parseTaskUpdates`, and
   apply it in `TaskService.UpdateTask` before calling `repo.Update`
   (`ValidateTaskDependencies` will validate it same as create/other update
   paths, in-feature scoped per the TD-063 fix). Add a test that exercises
   the production CLI-to-service call path.
2. Remove it: delete the flag registration and its help text if
   `depends_on` updates should only happen via `shark task link`.
