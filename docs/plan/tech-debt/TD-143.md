# Arm OPERATOR_LIMITS_FILE cleanup trap immediately after mktemp to close early-exit leak window

## Description

Round 9 code review (UAT-R2-01 fix): in both run-lifecycle-batch.sh:273 and run-review-comparison.sh:228, OPERATOR_LIMITS_FILE is created via mktemp several statements before the EXIT trap that removes it is registered (cleanup_matrix / cleanup_candidate, set up only after out_root_canon=$(realpath ...), sourcing lib/path-safety.sh, and mkdir -p on out_root_canon). Under set -euo pipefail, a failure in any of those intervening statements exits the script before the trap exists, leaking the temp file. Severity is low: the file holds only three numeric YAML lines (no secrets, no path-safety-relevant content) and OS temp cleanup eventually reclaims it. Fix: register a minimal 'trap the file exists, rm -f $OPERATOR_LIMITS_FILE on EXIT' immediately after the successful mktemp, then let the later cleanup_matrix/cleanup_candidate trap supersede it. Independently identified by tech-lead review and by codex red-team (finding 2) as a non-blocker.
