# Duplicate linkable-entity enumeration in task_display_data view (B049 follow-up)

## Description

internal/db/db.go's taskDisplayRelationshipEntities (~line 2813) is a second independent enumeration of the linkable-entity set already listed in internal/cli/commands/link.go:113 (mapDetectedTypeToEntityType), with no test tying them together. Adding an 8th linkable entity type to one list without the other would silently reintroduce B049's exact bug (a relationship type/entity type silently dropped from shark get --json output). Suggested guard: add a test in internal/db asserting taskDisplayRelationshipEntities against models.ValidEntityTypes minus {idea, sprint} (no import cycle). Flagged as a non-blocker in code review for B049: docs/review/bugs/b049/code-review-20260802T135918Z-B049.md.

## Impact

Low likelihood, high blast radius: nothing breaks today because the two lists happen to agree. If a future entity type (or a change to `mapDetectedTypeToEntityType`) is added to one list but not the other, `shark get --json` / `shark task get --json` will silently drop relationships to that entity type again — the exact class of bug B049 fixed — with no test failure to catch it.

## Resolution Plan

Add a test in `internal/db` (or `internal/cli/commands`) that asserts `taskDisplayRelationshipEntities` (internal/db/db.go ~line 2813) matches the linkable entity set used by `mapDetectedTypeToEntityType` (internal/cli/commands/link.go:113), e.g. against `models.ValidEntityTypes` minus `{idea, sprint}`. Keeping both lists but wiring a cross-check test converts a silent drift into a build failure.
