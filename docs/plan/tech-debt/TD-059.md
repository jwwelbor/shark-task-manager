# fakeQuestionAdapterRepository.Update no-op can't detect a dropped write

## Description

internal/services/question_repo_adapter_test.go:26 fakeQuestionAdapterRepository.Update is a no-op returning nil, and GetByID always returns the same shared struct pointer already mutated in place by SetContextData -- so the test cannot detect a dropped repo.Update() call in entityAdapter's emulated UpdateContextData path, the one thing the test exists to protect. Fix: give the fake repo an updateFunc hook / capturedContextData field and assert it was invoked exactly once with the expected value. Surfaced by round-5 /shark-rider deep-review of E39 (finding F12, nit), 2026-08-01.

## Impact

The test that exercises `entityAdapter`'s emulated `UpdateContextData` path for Question (via `fakeQuestionAdapterRepository`) can pass even if a future refactor accidentally drops the `repo.Update()` call it's supposed to protect, because the fake's `Update` is a no-op and `GetByID` returns the same shared, already-mutated pointer regardless of whether `Update` ran.

## Resolution Plan

Give `fakeQuestionAdapterRepository` an `updateFunc` hook or a `capturedContextData` field, and assert in the relevant test that it was invoked exactly once with the expected merged value -- mirroring the pattern `entity_adapter_test.go`'s `TestEpicAdapter_UpdateContextData` already uses.
