# Push --tag filter into search FTS UNION SQL instead of post-load Go filter

## Description

internal/repository/search/repository.go added an id column to EntitySearchResult so the service layer can call EntityIDsByTags then filter in-memory. At scale this loads FTS rows that get discarded by the Go-side filter. Should push the tag filter into the FTS UNION via INNER JOIN entity_tags + WHERE tag_id IN (...) so SQLite skips non-matching rows entirely. Discovered during /simplify review of E28 entity-tagging branch on 2026-04-25. Architectural change — not a one-line fix; FTS UNION already spans multiple entity tables, each would need the same join shape.
