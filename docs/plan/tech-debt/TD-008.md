# Skip transaction and dependency validation in --parallel repo update path

## Description

When forceSkipCascade=true (the --parallel update path) in internal/repository/task/repository.go and internal/repository/feature/repository.go updateInternal, two pieces of work run unnecessarily:

1. updateInternal still opens a transaction (BEGIN/UPDATE/COMMIT) for what is now a single non-cascading row update. Could short-circuit to a plain db.ExecContext. Magnitude: ~2 fewer round-trips per --parallel update; meaningful only on Turso (network-bound), negligible on local SQLite.

2. ValidateTaskDependencies (around task/repository.go:885) issues SELECTs against tasks even when the user is just renumbering one task into a parallel group. Saves 1 query per parallel update if guarded.

Both apply to the same code path; one fix touches both repos. Source: PR #79 (output-sizing branch) — efficiency review of the new --parallel flag.
