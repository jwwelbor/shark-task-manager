# Clarify folder listing metadata errors

## Description

CR-004 in E27-F16 review: internal/services/viewer_service.go folderFileEntries returns size zero when DirEntry.Info fails. Behavior predates E27-F16; decide and document an explicit best-effort response policy or propagate errors. Linked review: code-review-20260811T035830Z-E27-F16.md.

## Impact

Folder listings previously represented both unavailable file metadata and an
actual zero-byte file as `"size": 0`. Consumers could not distinguish a
transient `DirEntry.Info()` race from a known empty file.

## Resolution Plan

Keep folder listings best-effort: retain an entry when its metadata cannot be
read, but omit its optional `size` field. Emit `"size": 0` only when metadata
was successfully read for a real zero-byte file. Do not expose per-entry
filesystem errors or fail the whole listing for a transient child-entry race.

## Resolution Notes

`FolderFileEntry.Size` is now an optional `*int64` with `omitempty`. The
service sets it only after a successful `DirEntry.Info()` call for a
non-directory entry, preserving navigation when metadata is unavailable. Focused
service and HTTP tests cover omitted unavailable metadata and preserved known
sizes, including zero.
