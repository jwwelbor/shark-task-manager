# Supersede self-supersede/malformed-key/nonexistent-key guards are untested

## Description

internal/services/question_workflow_service.go's Supersede has three self-contained guards (self-supersede where SupersededBy == Key, malformed SupersededBy format, nonexistent SupersededBy) with zero test coverage -- grep confirms every Supersede call in question_service_test.go uses a valid, distinct, resolvable key. Fix: add three subtests, each asserting the repo write was never called. Surfaced by round-5 /shark-rider deep-review of E39 (finding F10), 2026-08-01.

## Impact

A regression in any of Supersede's three self-contained guards (self-supersede, malformed `SupersededBy`, nonexistent `SupersededBy`) would ship undetected -- the same class of risk that let the round-5 `TransitionStatus` bypass (E39's most severe finding) go unnoticed for two prior review rounds.

## Resolution Plan

Add three rejection subtests to the `Supersede` test coverage in `question_service_test.go`: `SupersededBy == Key` (self-supersede), a malformed `SupersededBy` key format, and a well-formed but non-existent `SupersededBy` key -- each asserting the repository write was never called.
