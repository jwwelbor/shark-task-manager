# E34-F01: shark run harness wiring verified only by source-text scan, not execution

## Description

internal/cli/commands/run_harness_flags_test.go:68-88 — wiring for shark run's HarnessResolver is verified by scanning source text rather than a mocked runRun execution. Pre-existing architectural gap (shark run lacks the test seams shark next has), not introduced by this feature. From E34-F01 code-review non-blocker #4.

## Impact

Low. The property at stake is syntactic: whether `runRun` forwards its parsed
`--harness`/`--harness-version`/`--harness-model` override into
`acquireRunLeaseForRunnableAction`. If that forwarding were dropped, a claim
would persist with empty harness fields and the run would silently degrade to
env-only harness resolution. The source-scan guard
(`TestRunRun_WiresHarnessOverrideAndResolver`) covers the wiring's presence but
not its argument value, so a mutation at run.go:289 alone is not caught by any
test.

## Resolution Plan

Closed `wont_fix`. The requested remedy — an execution-level test of `runRun`'s
own wiring — is not reachable within the project's accepted design:

- `buildTransitioner` (run.go:245) runs unconditionally on every entity-type
  branch and calls `cli.GetTaskService()`/`cli.GetFeatureService()`/etc., all of
  which require a real database. `.claude/rules/testing/cli-tests.md` forbids a
  real database in a CLI-command test.
- `internal/cli/commands/run_test.go:633-639` records that `test-plan.md`'s
  "Considered and rejected" section already evaluated extending
  `runClaimSvcOverride`-style injection to `buildTransitioner` /
  `cli.Get*Service` and rejected it as disproportionate for a STANDARD-scored
  feature (six-plus call sites), and that **decision D7 sanctions `go/parser`
  source-invariant checks for exactly this class of syntactic wiring property**.

So the source-scan test this record calls a gap is the project's deliberate,
documented convention for this property. Reopen only if D7 is revisited, or if
`buildTransitioner` gains injectable seams for an unrelated reason.

## Resolution Notes

Closed `wont_fix` on 2026-09-18 (row 3 of `docs/plan/tech-debt/2026-09-17-collection-plan.md`).

An execution-level test was attempted and then **withdrawn**. The candidate
(`TestRunLeaseForRunnableAction_FlagOverrideReachesClaim`) called
`acquireRunLeaseForRunnableAction` directly, passing its own `override` as an
argument, so it never exercised run.go:289 — mutating that call site to pass a
zero `services.HarnessIdentity{}` left the whole package green. Mutating the
wrapper's *inner* forwarding to `acquireRunLease` did turn it red, but that
same mutation already fails the pre-existing
`TestCascadeChildLease_InheritsParentHarnessOverride`, so the candidate's
mutation-detection delta over the existing suite was zero. It was dropped
rather than shipped as redundant maintenance surface.

The residual gap — no test fails if run.go:289 stops forwarding
`harnessOverride` — is real and remains open by the D7 decision above, not by
oversight.
