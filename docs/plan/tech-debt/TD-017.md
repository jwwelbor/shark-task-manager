# Split resolveNext (next.go) into tryCascade / applyWireAction / attachAgentBody helpers

## Description

internal/cli/commands/next.go:144-329 — resolveNext is 200+ lines that mix: argument parsing, transitioner construction, action service lookup, status reading, terminal/archived detection, placeholder generation, populated-action retrieval, cascade recursion with children iteration and child-response dispatch, internal-verb to wire-verb normalization, auto-advance recursion, and agent-body inlining with frontmatter strip.

Refactor pipeline:
1. tryCascade(ctx, entityType, key, depth) — owns the cascade verb's children-loop and resolved_via threading
2. applyWireAction(internalAction, agentType, nextInfo) — already exists as normalizeWireAction; pull the post-switch advance_and_recurse / error branches into a sibling helper
3. attachAgentBody(resp, agentType, vars) — owns the LoadAgentBodyForInline + RenderAgentBody + concatenation block

resolveNext should then read as: parse -> read status -> terminal/archive guard -> generate placeholders -> populate action -> tryCascade if cascade verb -> applyWireAction -> attachAgentBody -> return.

Closely related to the cascade.go fat-controller bug (B029). Surfaced during simplify review of commit 6492e45.

## Impact

A single function carries the entire dispatch pipeline (parse, resolve, recurse, normalize, inline, guard). Each new feature touching `shark next` adds another branch and grows the same handler. The cascade vs auto-advance vs normal-dispatch paths share so much surrounding state that test setup is heavy. The fat-controller bug in `cascade.go` (B029) is in part a consequence — the cascade branch is too entangled with the rest of `resolveNext` to be cleanly delegated.

## Resolution Plan

After extraction, `resolveNext` reads top-to-bottom as: parse → status → terminal/archive guard → placeholders → populate action → `tryCascade` → `applyWireAction` → `attachAgentBody` → return. Each helper has a narrow signature, owns one decision, and can be unit-tested with stub inputs instead of a fully-wired transitioner.

## Resolution Notes

Extracted three helpers from `resolveNext` in `internal/cli/commands/next.go`:

- `tryCascade(ctx, cache, entityType, key, depth, resp) (NextResponse, error)` — owns the children-loop and resolved_via threading for the cascade verb.
- `applyWireAction(ctx, cache, entityType, key, depth, internalAction, populated, nextInfo, transitioner, resp) (NextResponse, handled bool, error)` — wraps `normalizeWireAction` and handles the `advance_and_recurse` / `error` branches; `handled=false` means the caller should continue (simple wire action filled in resp).
- `attachAgentBody(prompt, agentType, vars) string` — pure helper for `LoadAgentBodyForInline` + `RenderAgentBody` + concatenation with graceful degradation.

`resolveNext` now reads top-to-bottom as: parse → status → terminal/archive guard → placeholders → populate action → tryCascade (cascade verb) → applyWireAction → attachAgentBody → return. Behavior is preserved — no existing tests required modification. A light-touch test (`next_helpers_test.go`) asserts the three helpers remain in scope and exercises the graceful-degradation path of `attachAgentBody`.
