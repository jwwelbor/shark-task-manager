# Path-derived values in verify-stage-evidence.sh and replay-stage-evidence.sh lack containment checks in 3 sites

## Description

During E40-F06 T-003 round-2 rework, a defect-class sweep for package.yaml/bundle-derived values reaching os.path.join or subprocess argv without a registry lookup or containment check found 3 sites outside T-003's own file scope that are inconsistent with sibling guards' handling of the identical field shape: (1) verify-stage-evidence.sh:449 destination_abs -- destination_rel comes from the trusted, frozen adapter's own stdout, no containment check. (2) replay-stage-evidence.sh:234 rel_path -- from the bundle's own recorded manifest, no explicit containment check (only reached after digest verification passes, lower risk). (3) replay-stage-evidence.sh:304 snapshot_full_path -- snapshot_path from bundle.json's own stages[], no containment check, inconsistent with verify-stage-evidence.sh's own guarded handling of the identical field shape (this is the most significant of the three). None are currently exploitable via any committed fixture; all are hardening gaps for future untrusted bundle content. Fix: add explicit resolve-and-contain checks (mirroring resolve_in_evaluator_root's pattern) at all 3 sites.

## Impact

Low today (no committed fixture exploits these paths), but the same class of gap that caused T-003's round-3 code-review blocker 1 -- if left unaddressed, a future feature building on these bundle/manifest-derived paths without re-auditing them could introduce a real path-escape vulnerability.

## Resolution Plan

Add explicit resolve-and-contain checks at verify-stage-evidence.sh:449 (destination_abs), replay-stage-evidence.sh:234 (rel_path), and replay-stage-evidence.sh:304 (snapshot_full_path), mirroring resolve_in_evaluator_root's pattern in verify-evidence-roots.sh.
