# TC-030 has no corpus-wide scenario_id uniqueness check

## Description

tests/contracts/e40_i04_scenario_contract_test.go:167,484 checks each package's scenario_id independently against a kebab-case regex but never accumulates seen ids across the corpus to reject a duplicate, despite REQ-F-002 requiring scenario_id uniqueness. Today's four seed packages have distinct ids so nothing is currently masked, but the invariant is not mechanically enforced. Fix: track a set of seen scenario_id values while iterating index.Scenarios and fail naming both the duplicate id and the two colliding package paths if a repeat is found.
