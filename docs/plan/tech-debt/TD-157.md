# task_generation's 50-line cap has no self-check step, so violations are only caught (expensively) at task_review

## Description

`internal/sharkdata/default_data/prompts/feature/task_generation.md:137,160` and
`internal/sharkdata/default_data/prompts/feature/task_review.md:29` both state
the identical rule — "Each task file is 50 lines or less (not counting
frontmatter)" — once as a CRITICAL RULE/exit-gate item in the generation
prompt, and again as a checklist item in the review prompt. The rule is
stated twice, but only *enforced* once: `task_generation.md` never instructs
the generating agent to count its own output's lines before returning, so
the only place a violation is actually caught is the separate `task_review`
gate, one full workflow step later.

Observed in production (not hypothetical): in project `wwgm`
(`~/projects/wwgm`), Shark epic E20-F07's task_generation step (2026-08-23)
produced 10 task specs at 66-94 lines each — 30-90% over budget — which
passed whatever self-review that step ran. A `task_review` pass on
2026-08-29 correctly caught this and returned FAIL, kicking the feature back
to `task_generation`. The fix required in the second pass was to re-read all
10 files, diagnose which lines were narrative padding vs required content,
and rewrite each to fit the cap while preserving every AC/TC/
Integration-Contract line verbatim (wwgm commit `61c4fbe`). That is a full
second read-and-rewrite pass over content that could have been generated
correctly the first time — roughly double the token cost of the step, plus
one extra `task_generation` <-> `task_review` round trip, for a defect class
the generation prompt already names as a CRITICAL RULE.

## Impact

- Wasted generation cost: an over-budget task_generation pass isn't caught
  until task_review, so fixing it means a second full read+diagnose+rewrite
  pass instead of getting it right once.
- Wasted workflow cost: one extra task_generation <-> task_review round trip
  per violation, plus the review agent's time spent finding line-count
  violations that a mechanical self-check would catch for free.
- The failure mode compounds when task specs are reused from an earlier,
  pre-cap-aware session (as in the wwgm case) rather than freshly generated
  under the current prompt — nothing in task_generation.md tells the
  dispatched agent to re-validate *existing* task files it decides not to
  regenerate, so stale over-budget files can silently pass through if the
  agent's own judgment call is "tasks already exist, advance."

## Evidence: what the redo actually cost and bought (wwgm commit `61c4fbe`)

Diffed `T-E20-F07-001.md`'s before/after directly (not just the fixing
agent's self-report) to check whether the two-pass redo was actually
necessary or just expensive. Findings:

- **No AC/TC/integration-contract fact was dropped.** Every file path, line
  range, AC/TC ID, and contract detail (port scope, forbidden type-naming,
  I-01/I-06 shape sources) survived the trim.
- **What got cut was narrative elaboration**, e.g. this line:
  > `backend/app/api/character_creation.py:39-320` — the five routes,
  > `CreationRunAuthorityRequest`, `_FAILURE_STATUS`, and the module's
  > "HTTP mapping only" docstring contract this task must preserve.

  became:
  > `character_creation.py:39-320 (routes, _FAILURE_STATUS)`

  — the pointer survived, the *rationale* ("this task must preserve the
  docstring contract") did not. Structural subheadings ("### Existing Files
  to Read Before Implementing", "### Patterns to Follow", "### Scope
  Boundary") were also flattened into denser paragraphs.
- **Net verdict: the trimmed version is arguably the *better* artifact**,
  not just a shorter one — `task_generation.md`'s own stated intent is that
  task files are thin pointers into spec.md/test-plan.md, not restatements
  or explanations of them. The pre-redo 66-94 line versions were doing more
  narrating than the prompt's own design wants.

That's precisely what makes the two-pass path wasteful rather than
necessary: nothing about writing tersely and by-reference *from the start*
would have required more information than writing narratively first and
compressing later — same content, written once, at the target length,
instead of drafted long and then re-read/diagnosed/rewritten. The fix
below should make the terse-first draft the default, not something a
review gate has to force after the fact.

## Resolution Plan

Add an explicit self-check step to `task_generation.md`'s exit gate,
sequenced before the agent returns its outcome: for every task file
written (fresh or reused/pre-existing), run a mechanical line count
(excluding frontmatter) and confirm <= 50 before reporting the
`task_generation` step complete. If a file is over budget, the agent fixes
it in the same pass rather than deferring to task_review. This turns the
50-line rule from "stated in two places, enforced in one" into "stated
once, self-verified at the point of creation, and re-verified at review as
a backstop" — task_review remains a legitimate independent check, but stops
being the *first* place violations are ever caught.

Suggested concrete change: in `task_generation.md`, right before the
existing "EXIT GATE" block, add something like:

```
Before returning, run a line count on every task file you wrote or are
reusing (excluding frontmatter): `wc -l <file>` minus frontmatter lines.
Any file over 50 lines must be trimmed now, in this pass -- do not rely on
task_review to catch it.
```

Second, cheaper hint worth pairing with the mechanical check: the evidence
above shows the overage wasn't from missing information, it was from
writing narratively (explanatory sentences, rationale clauses, full
subheadings) instead of by-reference from the first draft. A short framing
line near the top of `task_generation.md`'s CRITICAL RULES —
e.g. "Draft each task file by reference from the start: cite `spec.md`/
`test-plan.md` sections and file:line locations, don't narrate them. A
task file that needs trimming after a first draft was written the wrong
way, not just too long." — targets the actual habit that produces
oversized drafts, so the mechanical line-count check becomes a rare
backstop instead of a routine second pass.
