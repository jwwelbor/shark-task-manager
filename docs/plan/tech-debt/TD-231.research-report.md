# TD-231 Research Report: Improve Failure Diagnostics for TestConsolidatorRoutesNonBlockersThroughTriage

## Scope

Test file: `internal/cli/commands/review_output_policy_test.go`

Target test: `TestConsolidatorRoutesNonBlockersThroughTriage` (lines 191-213)

The test reads a ~9KB markdown file and asserts on its content using `require.Contains` and `require.NotContains`. When assertions fail, the entire file content is dumped into test output, making it difficult to identify the specific missing or unwanted phrase.

## Findings

### Current Assertions (Lines 191-213)

The test currently uses:

**Positive assertion (line 200-201):**
```go
const triageReference = "triage skill's decision tree"
require.Contains(t, content, triageReference,
    "consolidator.md must route non-blockers through the triage skill's decision tree")
```

**Negative assertions loop (lines 209-211):**
```go
for _, phrase := range directMapping {
    require.NotContains(t, content, phrase,
        "consolidator.md must not map finding severity directly to tech-debt")
}
```

On failure, `require.Contains` and `require.NotContains` dump the full `content` string (~9KB) into the test failure message, making it difficult to quickly identify which substring was missing or unexpectedly present.

### Sibling Tests with Same Issue

Two other tests in the same file read file/template content and use `require.Contains`, creating the same diagnostic problem:

1. **Line 94** — `TestReviewPromptsUseCompactSuccessAndDetailedFindingsPolicy`:
   - Loops over multiple phrases and calls `require.Contains(t, rendered, want)` for each
   - If assertion fails, dumps full rendered template content

2. **Line 174** — `TestDeepReviewUsesCompactPassAndDetailedFindingsPolicy`:
   - Reads multiple files and loops over phrases calling `require.Contains(t, content, want)`
   - If assertion fails, dumps entire file content for each phrase

### Idiomatic Pattern in Codebase

The codebase already uses a cleaner pattern for substring assertions elsewhere (`internal/runner/controller_stage_error_rework_test.go`):

```go
if !strings.Contains(result.Error, "dry-run-post-dispatch-ns-failed") {
    t.Errorf("result.Error = %q, want substring %q", result.Error, "dry-run-post-dispatch-ns-failed")
}
```

This pattern:
- Uses `strings.Contains` for the condition check
- Reports the actual content and the wanted substring, not forcing full dump
- Allows caller to see the missing phrase immediately

### require vs assert

**Recommendation: Use `assert` for multi-phrase checks.**

In `TestConsolidatorRoutesNonBlockersThroughTriage`, there are multiple forbidden phrases. Using `require.NotContains` (which fails fast on first violation) means only the first unwanted phrase is reported. Using `assert.NotContains` (which continues) reports all violations in a single test run, accelerating diagnosis when multiple phrases need fixing.

Pattern:
```go
// Use assert (continues) for multi-check loops, require (aborts) for single critical assertions
for _, phrase := range directMapping {
    assert.False(t, strings.Contains(content, phrase),
        "consolidator.md must not contain %q", phrase)
}
```

## Decisions

1. **Replace `require.Contains` with targeted boolean check + `t.Errorf`** for file content assertions
2. **Replace loop of `require.NotContains` with `assert.False` + `strings.Contains`** to report all violations
3. **Apply fix consistently across all three tests** that read content and assert on substrings (lines 94, 174, 200-211)
