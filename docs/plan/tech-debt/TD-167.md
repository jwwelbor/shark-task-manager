# E34-F01: shark next/run --harness override flags bypass trim and 100-char sanitization cap

## Description

internal/cli/commands/next.go:345-363 (harnessOverrideFromFlags, shared by next.go and run.go) reads --harness/--harness-version/--harness-model verbatim with no trim and no length cap, unlike shark claim's handling (claim.go:149-154) and the REQ-NF-004 cap enforced in models.EntityClaim.Validate(). Not an injection risk (Go text/template does not re-evaluate interpolated values), but is a real REQ-NF-004 deviation: an oversized or newline-bearing value flows straight into the rendered prompt and the omitempty NextResponse JSON. Fix: apply the same trim(+lowercase for type)/length-cap normalization used at claim time to the next/run override flags before merging into the resolver.
