### 6. `specification-writing` — FAIL

**SKILL.md:** Present  

**Findings:**

#### Finding S6-1 — TRUE VIOLATION (Status Transition Ownership)
- **File:** `shark-data/skills/specification-writing/context/naming-conventions.md`
- **Line:** 114
- **Content:** `` - `shark status advance E01-F01-001` - Advance task to next workflow status ``
- **Rule violated:** Status transition ownership — `status advance` in canonical skill file
- **Classification:** TRUE VIOLATION
- **Analysis:** The `naming-conventions.md` context file includes a "Status Management" section with four literal CLI commands including `shark status advance` and `shark status set`. These are status-transition commands. Per the layer rules, status movement belongs to `shark-data/prompts/` and `shark-data/workflow/`, not to a skill context file. The naming-conventions document is a craft-layer reference for how files are named — it should not own or document status management commands.
- **Recommendation:** Remove the "Status Management" block (lines 112-117) from `naming-conventions.md`. If this information is useful for orientation, it belongs in a prompt's instructions or in general project documentation, not in a skill context file. This is a migration to prompts/workflow layer.

- **Rule violated:** Status transition ownership — `status set` in canonical skill file
- **Classification:** TRUE VIOLATION

#### Finding S6-3 — ILLUSTRATIVE CONTEXT
