# Task: End-to-end fresh init → validate → create epic → shark next

## Context

Feature spec acceptance criteria 1-2 require the full bootstrap sequence to
work on a fresh project. This task exercises the complete flow against the built
binary, not just unit tests: `shark init` → `shark validate` → `shark create
epic` → `shark next <key>`. Covers E6+E8+E9 integration (E7 upgrade is covered
by T-E32-F03-002). All three earlier verification tasks must be green first.

## Requirements

- Full bootstrap sequence succeeds on a temp directory (no pre-existing DB)
- `shark validate` passes immediately after init (AC1)
- After `shark create epic "test"`, `shark next <epic-key>` works and returns
  a non-empty dispatch (AC2)
- No panics, no missing-config errors, no "workflow_config not found" messages

## Implementation Plan

1. Build binary: `make shark`
2. In a fresh temp dir, run: `shark init` → exit 0 and shark-data/ present
3. Run `shark validate` → exit 0
4. Run `shark create epic "test"` → capture key from output
5. Run `shark next <key>` → exit 0 with dispatch content
6. If any step fails, identify the broken integration point (likely config
   resolution of shark-data/workflow/) and fix in config or CLI handler
7. Run full test suite: `make test` to confirm no regressions

## Acceptance Criteria

- [ ] `shark init && shark validate` exits 0 on fresh temp dir (AC1)
- [ ] `shark create epic "test" && shark next <key>` exits 0 (AC2)
- [ ] `make test` passes with no regressions after any fixes
- [ ] No config or workflow resolution errors in stdout/stderr
