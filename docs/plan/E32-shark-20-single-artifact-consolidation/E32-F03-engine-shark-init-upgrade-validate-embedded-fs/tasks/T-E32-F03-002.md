# Task: Verify shark upgrade dry-run mode and overrides/ preservation

## Context

E7 is implemented in internal/sharkdata/embed.go (Upgrade()). Tests exist in
embed_test.go (TestUpgrade_RequiresExistingTree, TestUpgrade_PreservesOverrides,
TestUpgrade_DryRunWritesNothing, TestUpgrade_ApplyRestoresCanonical). The CLI
flag --dry-run is wired in sharkdata_cmd.go. Feature spec §E7 requires overrides/
to be byte-identical before and after upgrade (acceptance criterion 4).

## Requirements

- All TestUpgrade_* tests pass
- --dry-run flag writes no files and exits 0
- After upgrade, shark-data/overrides/ content is byte-identical to pre-upgrade
- Upgrade on a missing tree returns a clear error (not panic)

## Implementation Plan

1. Run `make test ./internal/sharkdata/...` — confirm all TestUpgrade_* pass
2. Smoke: init a temp dir, add sentinel file to shark-data/overrides/custom.md,
   run `./bin/shark upgrade --dry-run`, confirm custom.md unchanged and no
   new files written
3. Run `./bin/shark upgrade` (no dry-run), confirm custom.md is still present
   and byte-identical
4. Run upgrade on a dir without shark-data/ — confirm error exit and clear message
5. Fix any gaps found in Upgrade() or the CLI handler

## Acceptance Criteria

- [ ] `make test ./internal/sharkdata/...` passes (all TestUpgrade_* green)
- [ ] `./bin/shark upgrade --dry-run` exits 0, writes no files
- [ ] overrides/ sentinel file is unchanged after `./bin/shark upgrade`
- [ ] `./bin/shark upgrade` on missing tree exits non-zero with clear message
- [ ] make lint passes on sharkdata package
