# Task: Verify E4/E5 — .md prompt support and shark-data/ resolution

## Context

`internal/templates/orchestrator_renderer.go` implements both E4 (`.md` prompt file
support with frontmatter strip) and E5 (`shark-data/` resolution with `shark-templates/`
fallback via `findTemplateDir()`). Tests exist in `orchestrator_renderer_test.go`
and `shark_data_renderer_test.go`.

Reference: feature spec §E4, §E5, research.md §1 (E4, E5), architecture.md ADR-5.

## Requirements

- `OrchestratorRenderer` globs both `.tmpl` and `.md` files in the template dir.
- `stripFrontmatter()` correctly removes a leading `---`-delimited YAML block.
- `findTemplateDir()` Pass 1 resolves `shark-data/prompts/` when present.
- `findTemplateDir()` Pass 2 falls back to `shark-templates/` when `shark-data/` absent.
- `.md` files render via the same Go template engine and `orchestratorFuncs()` as `.tmpl`.

## Implementation Plan

1. Run `go test ./internal/templates/ -run Orchestrator -v` and confirm existing tests pass.
2. Confirm `stripFrontmatter` test cases cover: no frontmatter, with frontmatter, malformed.
3. Confirm `findTemplateDir` test cases cover: shark-data present, shark-data absent (fallback).
4. Add any missing test cases; the bar is that all five requirements above have coverage.

## Acceptance Criteria

- `go test ./internal/templates/` passes with zero failures.
- `stripFrontmatter` tested for no-frontmatter, valid-frontmatter, and edge cases.
- `findTemplateDir` tested for both Pass 1 (shark-data) and Pass 2 (fallback) branches.
- `make fmt && make lint` clean.

## Dependencies

- None; runs in parallel with T-E32-F02-001 and T-E32-F02-002.
