# Task: Verify E2 — YAML workflow loader round-trip

## Context

`internal/config/workflow/yaml_loader.go` implements `LoadMultiLevelWorkflowFromYAML` (E2).
Tests exist in `yaml_loader_test.go`. This task verifies the YAML loader produces
semantically identical workflow configs to the legacy `.sharkworkflow.json` for the
`task` entity — the required proof entity per feature spec §E2.

Reference: feature spec §E2, research.md §1 (E2), architecture.md §4.2.

## Requirements

- `shark-data/workflow/task.yaml` loads without error via `LoadMultiLevelWorkflowFromYAML`.
- All statuses, transitions (`status_flow`), and `status_metadata` fields present in
  the YAML match semantics of the legacy JSON for the task entity.
- Per-file error accumulation: missing optional entity files do not abort load.
- Override precedence: `<dataDir>/overrides/workflow/task.yaml` supersedes `<dataDir>/workflow/task.yaml`.

## Implementation Plan

1. Run `go test ./internal/config/workflow/ -v` and confirm all existing tests pass.
2. Load `shark-data/workflow/task.yaml` via the public loader API; compare status keys
   against legacy `.sharkworkflow.json` task statuses.
3. Document the round-trip result as a note in the test or here.
4. Add a test for override precedence if not already covered.

## Acceptance Criteria

- `go test ./internal/config/workflow/` passes with zero failures.
- `task.yaml` loads cleanly; all task statuses present and semantically equivalent.
- Per-file error accumulation confirmed: removing a non-required entity file does not panic.
- `make fmt && make lint` clean.
