# Task: Verify E3 — shark next command end-to-end

## Context

`internal/cli/commands/next.go` (658 lines) implements `shark next` (E3). Tests
exist across `next_test.go`, `next_golden_test.go`, `next_helpers_test.go`,
`next_normalize_test.go`, `next_cache_test.go`. This task verifies the full
`NextResponse` contract and that the command works against a `shark-data/`
workflow config.

Reference: feature spec §E3, research.md §1 (E3), architecture.md §4.3, ADR-2.

## Requirements

- `shark next <entity>` returns valid JSON with all `NextResponse` fields populated.
- `prompt` field is non-empty when `action = spawn_agent`.
- `agent_type`, `provider`, `model`, `action`, `resolved_via` present in response.
- `attachAgentBody()` inlines agent persona from `shark-data/agents/<type>.md`.
- Cascade resolution (`tryCascade`) iterates dispatchable children; `maxCascadeDepth` guard fires on runaway.
- `normalizeWireAction()` maps internal YAML verbs to wire vocabulary correctly.

## Implementation Plan

1. Run `go test ./internal/cli/commands/ -run Next -v` and confirm all existing tests pass.
2. Review `next_golden_test.go` — confirm golden test fixtures cover a `spawn_agent` scenario
   where `prompt` includes inlined skill content.
3. If `shark-data/` workflow config path is not yet tested (config currently points to
   `shark-templates/`), add a test fixture that uses `shark-data/workflow/task.yaml`.
4. Verify `maxCascadeDepth` guard has a test case.
5. Verify `normalizeWireAction` covers all five wire verbs.

## Acceptance Criteria

- `go test ./internal/cli/commands/ -run Next` passes with zero failures.
- Golden test or integration test exercises full `spawn_agent` response with non-empty `prompt`.
- All five wire verb normalizations have coverage (`spawn_agent`, `check_or_resume`,
  `advance_status`, `pause`, `archive`).
- `make fmt && make lint` clean.
