## Summary

T-E18-F05-002 implements the CRUD commands for change-cards. The create, get, update, and delete handlers are correctly implemented as thin wrappers. However, the `list` command has two defects: the table output is missing the required "Linked Entity" column, and the `--link` filter only maps to `EpicKey` rather than a general linked-entity key field.

## Findings

### DEFECT 1 (Required Fix): List table missing "Linked Entity" column

The PRD (feature.md Story 3, AC3.1) specifies that the list table must have these columns:

```
Key | Title | Status | Linked Entity | Created At
```

The current implementation in `printChangeCardList` uses:

```go
headers := []string{"Key", "Title", "Status", "Priority", "Created"}
```

"Priority" replaces "Linked Entity" - this does not match the spec. The linked entity (e.g., `E07` or `E07-F01`) is the primary contextual field for a change-card. Priority is not listed in the spec as a list column. The `Priority` field on `ChangeCard` is not even confirmed to exist in the model; the spec focuses on the linked entity relationship.

**Required fix:** Change headers to `["Key", "Title", "Status", "Linked Entity", "Created"]` and populate the "Linked Entity" column from the change-card's linked entity key field.

### DEFECT 2 (Required Fix): `--link` filter only maps to `EpicKey`

The PRD (Story 3, AC3.2) specifies:

> "Filter by linked entity: `--link=E07` (epic) or `--link=E07-F01` (feature)"

The current implementation:

```go
filters.EpicKey = changeLinkFilter
```

This incorrectly assigns the `--link` value to `filters.EpicKey` only. A feature key like `E07-F01` passed via `--link` would be ignored or misrouted. The filter struct should use a general `LinkedEntityKey` field (or equivalent) that the service layer uses to match against the change-card's linked entity regardless of whether it is an epic or feature.

**Required fix:** Use the appropriate field on the `ListChangeCardsFilters` struct - e.g., `filters.LinkedEntityKey = changeLinkFilter` - and ensure the `ChangeCardService.ListChangeCards` implementation handles both epic-level and feature-level key matching.
