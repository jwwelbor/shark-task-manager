## Findings

### DEFECT 1 (Required Fix): `runChangeContextClear` ignores `--field` flag

The `--field` flag is declared on `changeContextClearCmd`:

```go
changeContextClearCmd.Flags().StringVar(&changeCtxField, "field", "", "Specific context field to clear")
```

However, in the handler `runChangeContextClear`, the `changeCtxField` variable is never read:

```go
func runChangeContextClear(cmd *cobra.Command, args []string) error {
    key := args[0]
    ctxSvc := cli.GetContextService()

    if err := ctxSvc.ClearContext(cmd.Context(), models.EntityTypeChange, key); err != nil {
        return fmt.Errorf("failed to clear context for change-card %s: %w", key, err)
    }

    cli.Success(fmt.Sprintf("Context cleared for change-card %s", key))
    return nil
}
```

This means `shark change context clear C001 --field effort` clears ALL context fields on C001, not just `effort`. The `--field` flag is silently ignored.

The PRD (AC8.3) specifies:

> "Clear specific context field: `shark change context clear C001 --field effort`"

The bug.go implementation (canonical F04 pattern) also supports field-level clearing. The correct implementation should be:

```go
func runChangeContextClear(cmd *cobra.Command, args []string) error {
    key := args[0]
    ctxSvc := cli.GetContextService()

    if changeCtxField != "" {
        // Clear a single specific field
        if err := ctxSvc.ClearContextField(cmd.Context(), models.EntityTypeChange, key, changeCtxField); err != nil {
            return fmt.Errorf("failed to clear context field '%s' for change-card %s: %w", changeCtxField, key, err)
        }
        cli.Success(fmt.Sprintf("Context field '%s' cleared for change-card %s", changeCtxField, key))
    } else {
        // Clear all context
        if err := ctxSvc.ClearContext(cmd.Context(), models.EntityTypeChange, key); err != nil {
            return fmt.Errorf("failed to clear context for change-card %s: %w", key, err)
        }
        cli.Success(fmt.Sprintf("Context cleared for change-card %s", key))
    }
    return nil
}
```

If `ContextService` uses a different method name for field-level clearing, check the `ContextService` interface and use the appropriate method. Reference `internal/cli/commands/bug.go` for the canonical pattern.

## Principle of Least Surprise

A user running `shark change context clear C001 --field effort` reasonably expects only the `effort` field to be removed. Silently clearing ALL context when a specific field was requested would cause data loss that the user did not intend. This is a correctness bug with real user impact.
