**Status: FAIL - CRITICAL DEFECT**


The error message is self-contradictory: C001 IS the expected C### format, yet it is rejected. The `ParseScope` function does not handle `IsChangeKey` (C### format). See BUG-001 below for full details.

## Defects Found

### BUG-001: C### key dispatch broken in ParseScope and runGet

**Severity:** Critical
**Priority:** Critical
**Status:** New
**Found In:** Development (smoke testing)
**Story:** T-E18-F06-002 AC-2

**Description:**
`shark get C001` (and any C### format change key) fails with a misleading error instead of routing to the change entity handler. The acceptance criterion "shark get C001 dispatches to runChangeGet() handler" is NOT met.

**Steps to Reproduce:**
1. Build the binary: `make shark`
2. Run: `./bin/shark get C001`
3. Observe error output

**Expected Result:**
Command dispatches to `runChangeGet()` and returns something like "change not found with key C001"

**Actual Result:**
```
Error: invalid change card key format "C001" - expected C### (e.g., C001)
```

**Root Cause Analysis:**

Two issues in the codebase:

**Issue 1: `ParseScope` in `internal/cli/commands/helpers.go` does not check `IsChangeKey()`**

The function checks `IsBugKey` and `IsChangeCardKey` but has no corresponding check for `IsChangeKey`. When a C### key is passed, it starts with "C" but does not match the CC-### pattern, so it falls through to:

```go
if len(normalized) > 0 && normalized[0] == 'C' {
    return nil, InvalidPositionalArgsError("get",
        fmt.Sprintf("invalid change card key format %q - expected C### (e.g., C001)", args[0]),
        ...)
}
```

This code path should instead check `IsChangeKey` first and return a `scopeChange` scope type.

**Issue 2: `runGet()` in `internal/cli/commands/get.go` lacks `case "change"`**

Even if `ParseScope` were fixed to return a `scopeChange` type, `runGet()` would need a `case "change": return runChangeGet(cmd, []string{key})` to route to the correct handler.

**Fix Required:**

1. In `helpers.go`, add `IsChangeKey` check in `ParseScope()` before the C-prefix error handler:
   ```go
   if keys.IsChangeKey(normalized) {
       return &parsedScope{Type: scopeChange, Key: normalized}, nil
   }
   ```
   Also add `scopeChange` constant if not already defined.

2. In `get.go`, add `case "change"` to the dispatch switch:
   ```go
   case "change": return runChangeGet(cmd, []string{key})
   ```

3. Verify similar fixes may be needed in `delete_dispatch.go` and `status_group.go` for C### delete/status commands.

**Impact:**
All C### (change entity) key operations fail at the dispatch layer. The change entity implementation from F05 is unreachable via the unified CLI commands. This blocks the user story completely for change entities.

**Workaround:**
None available via unified commands. Users cannot get, delete, or advance status of change entities using C### keys.
